RoboDesign1M: A Large-scale Dataset for Robot Design Understanding ​

项内容
arXiv2503.06796
提交日期2025-03-09
作者Tri Le, Toan Nguyen, Quang Tran, Quang Nguyen, Baoru Huang, Hoan Nguyen, Minh Nhat Vu, Tung D. Ta, Anh Nguyen
分类cs.RO
一句话从上百万篇机器人相关科学文献里半自动抽取设计插图与其配文，构成约 100 万图文对与 130 万问答对，把「读懂机器人设计图」变成一个可训练、可评测的多模态任务。

所属教程：通用具身智能

版本与命名说明

abs 页元数据标题写作 RoboDesign1M，而 v2 全文（含摘要、表格、结论）一律写作 RobotDesign1M，项目页也是 robotdesign1m。frontmatter 按 本站体例 用 abs 页标题，正文按全文写法。本文按 v2（2026-07-13 修订，8 页，IROS 2026 接收）撰写。

§ 1 — 研究问题与重要性 ​

机器人设计目前仍是一件高度依赖个人经验的手艺活：从功能需求到机构选型、到具体尺寸与传动方案，中间没有可检索的知识库，只有分散在几十年论文里的图纸和文字。基础模型理论上能改变这一点——自动生成候选设计、按自然语言检索相似方案、给出改进建议、当教学助手——但前提是要有一个规模足够大的机器人设计语料，而这个语料不存在。

已有的工程设计数据集要么是通用物体的 CAD 模型（ABC、DeepCAD、Text2CAD），要么是机械领域的小规模集合（Ghezelbash 等的 9K 齿轮/机构图），要么是仿真参数化配置。机器人设计的特殊之处在于，它不只关心单个零件的几何，还关心零部件的属性与相互关系——哪一段是连杆、哪个关节是驱动的、传动比怎么排布。本文的贡献是给出第一个专门面向机器人设计的百万级多模态数据集，并把它作为三类任务（设计问答、文搜图、文生设计图）的基准。

§ 2 — 前人工作与不足 ​

Table I 的对比很清楚地划出了空缺。ABC（1M）、DeepCAD（178K）、Omni-CAD（453K）、Text2CAD（170K）这一支都是 CAD 模型，覆盖的是通用物体；SketchGraph 有 15M 但是 CAD 草图；LINKS 有 100M 但只有参数、且是仿真合成的；工程领域的 Ghezelbash（9K）与 Lee 等（715K）局限于机械件。真正稀缺的是三样东西同时具备的语料：真实设计、跨机器人子领域、且带自然语言描述。

作者对「为什么之前没人做」的解释也是有说服力的。第一，机器人设计数据在工业界通常是专有资产，不可能规模化开放；第二，它不像抓取位姿那样能靠生成模型合成——现有文生图模型压根画不出可用的技术图纸；第三，标注需要专业知识，纯人工不可扩展。所以本文选择的路径是绕开「设计源文件」，转而去挖已发表科学文献里的插图：这些图天然带有作者写的图注与正文解释，可靠性由同行评议兜底，且覆盖了社区几十年的探索。

§ 3 — 重建作者的思考路径 ​

倒推一下，这条路径几乎是被约束条件逼出来的。既然专有 CAD 拿不到、合成数据不可信、人工标注不可扩展，那么唯一剩下的高质量、大规模、带文本的机器人设计来源就是论文 PDF。一旦锁定这个来源，剩下的问题就全部变成数据工程：怎么把图从 PDF 里抠出来（PDFFigures）、怎么把不相关的图（曲线图、表格、实验照片）滤掉（训一个分类器）、怎么去重（CLIP 嵌入 + 近似 kNN）、怎么把简短图注扩成可用的监督信号（用 LLM 造问答对）。

造问答对这一步有一个值得注意的设计取舍。最直接的做法是把整篇论文喂给 LLM 让它围绕图提问，但那样幻觉率高。作者的做法是先用 LLM 从正文里抽出显式提到该图编号的段落作为 reference text，再交叉核验其确实出现在原文中，最后只把「图注 + 已核验的 reference text」这段短文本喂给 LLM 生成问答。这是拿覆盖率换可靠性，作者在 Limitations 里也承认这会漏掉隐式描述该图的文字。

§ 4 — 核心 Intuition ​

两句话。机器人设计的知识本来就已经被写下来了，只是被封在几十万篇 PDF 的插图和图注里；只要有一条足够干净的抽取-过滤-扩写流水线，就能把它变成多模态模型能吃的训练信号。而扩写这一步的关键在于限制 LLM 的输入范围：只给它图注和明确引用了该图的段落，宁可信息少一点，也不让它在整篇论文的上下文里编造。

§ 5 — 具体方法与完整 Pipeline ​

以一张双足机器人腿部传动结构图为例走一遍。

采集。先从 IEEE RA-L 的关键词表出发，用 ChatGPT 扩展语义相近词，人工筛选后定下 1K 个查询词，再去 Google Search、OpenAlex、IEEE Xplore 开放获取部分检索。除机器人外还纳入机械工程与电气工程的文献。最终得到 100 万篇以上文档，含会议论文、期刊、学位论文。用 PDFFigures 抽图、图注与全文，得到 500 万图文对。

过滤。第一步滤掉非设计图。训练一个集成分类器：OpenCLIP（选在 ImageNet-Sketch 上表现最好的预训练权重，因为素描风格与技术图纸视觉概念最接近）+ EfficientNetV2，用人工标注的 32,000 张图训练，在留出集上准确率超过 95%。第二步去重：用 OpenCLIP 嵌入 + Faiss 近似 kNN 找相似图，但不直接删——很多机器人设计视觉上相近而实质不同，因此还要比对配文，只有图与文都近乎相同才删。过滤后剩约 100 万图文对。

扩写。对每张图，LLM 抽出引用它的段落 → 与全文交叉核验 → 基于「图注 + reference text」生成问答对。三个候选（GPT-4o、LLaMa 3.3 70B、Qwen2.5 72B）中选 LLaMa 3.3 70B，理由是成本与质量的平衡。5 位机器人工程师人工核验了其中 100 条生成结果后再批量处理，最终得到约 130 万问答对。

统计。平均图注 15.14 词；去停用词与数字后词表 113K，约为 Ghezelbash 与 Text2CAD 的 16–78 倍；图覆盖 OpenAlex 分类下 1K 个主题、12K 个关键词。

§ 7 — 实验设计与结论 ​

三类任务，统一套路是「在 A 数据集上微调、在 B 数据集上评」，用交叉表把「难」和「脏」区分开。全部实验在 4×A100-80GB 上做。

设计问答。微调 LLaVA-1.5 与 Qwen2-VL，指标 BLEU/METEOR/L3Score（L3Score 用 GPT-4o 当评审）。域内结果（Table II）：Qwen2-VL 在 RobotDesign1M 上微调后是 1.32 / 12.33 / 0.31，而在 Text2CAD 上微调后是 6.94 / 32.64 / 0.94，在 Ghezelbash 上是 3.62 / 18.50 / 0.52。作者据此论证自家数据集「更具挑战性」。跨数据集（Table III）：在 Text2CAD 测试列上，Ghezelbash 训练的模型是 2.63 / 15.93 / 0.34，RobotDesign1M 训练的是 3.03 / 17.42 / 0.47；在 Ghezelbash 测试列上，Text2CAD 训练的是 1.32 / 8.84 / 0.12，RobotDesign1M 训练的是 2.12 / 12.93 / 0.33。这是全文最核心的证据。

文搜图。微调 BLIP-2，报 R@1/5/10（Table IV）。域内：Text2CAD 16.21 / 40.92 / 53.45，Ghezelbash 22.11 / 49.44 / 63.00，RobotDesign1M 12.9 / 27.46 / 36.28。跨数据集：RobotDesign1M 训练的模型在两个外域列上都优于另一个外域模型（Text2CAD 列 1.68 vs 1.01，Ghezelbash 列 8.77 vs 6.44）。

文生设计图。微调 SDXL，指标 FID：未微调 45.83，微调后 39.42（Table V，全表只有这两行）。另有 12 名机器人工程师、1200 次评估的 5 分 Likert 用户研究，结果只在 Fig. 9 的柱状图里，无数值。

需要如实指出的问题。第一，Table II 里 LLaVA-1.5 与 Qwen2-VL 在 Text2CAD 上微调后的 METEOR 与 L3Score 逐位相同（32.64 / 0.94），两个不同模型给出完全相同的两位小数，几乎可以确定是复制错误。第二，一个被论文回避的事实：GPT-4o 零样本在 RobotDesign1M 上是 2.51 / 20.83 / 0.30，而任何一个在 RobotDesign1M 上微调后的模型（最好 1.32 / 12.33 / 0.31）在 BLEU 与 METEOR 上都比它更低——也就是说「微调提升性能」只在同一模型与其自身零样本相比时成立。第三，正文写「在 Text2CAD 上微调的 Qwen2-VL 在 Ghezelbash 上 BLEU 为 0.013」，而表中该格是 1.32，是百分制与小数制的混用。第四，Table V 只有两行，没有「在其他数据集上微调」的对照行，而 FID 的参考分布正是 RobotDesign1M 的真值图像——在目标分布上微调必然降低对该分布的 FID，这个数不构成数据集质量的证据。第五，Table IV 的 R@k 强依赖检索库大小，而三个测试集的库大小全文未给，「我们的更难」这一结论有相当部分可能是库更大的产物。

§ 8 — Take-aways ​

五句话版：RoboDesign1M 用「文献插图 + 图注 + 显式引用段落」这条路径，绕开了机器人设计数据专有、不可合成、不可人工标注的三重封锁，构建了约 100 万图文对与 130 万问答对。流水线的核心是一个 32K 人工标注训出的相关性分类器，和一个「只喂短上下文以抑制幻觉」的 LLM 扩写策略。三类任务的实验设计是对的：用跨数据集交叉表把「基准更难」与「数据更脏」区分开。但三个训练集的规模相差两个数量级且从未被控制，跨数据集增益无法与纯粹的数据量效应分离。生成任务的 FID 对照缺失关键行，问答任务的真值本身由 LLM 生成、评审又是 GPT-4o，存在循环性。

三句话版：这是一个数据工程做得扎实、评测设计有想法的数据集论文。它最有价值的方法论贡献是那张「训练集 × 测试集」的交叉表，因为它是区分「难」与「脏」的唯一合法手段。但该表没有做数据量对齐，因此它证明的可能只是「大数据集泛化更好」这一平凡结论。

一句话版：把机器人设计知识从 PDF 插图里挖出来是对的，但要证明挖出来的是「质量」而不是「数量」，还差一次子采样对照。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：Table III 与 Table IV 的跨数据集优势，可以归因于 RobotDesign1M 的多样性与质量。

这个归因要成立，需要三个训练集在规模上大致可比。而事实是 RobotDesign1M 约 100 万样本，Text2CAD 约 17 万，Ghezelbash 约 9 千——最大与最小相差两个数量级。多模态模型的跨域迁移能力对训练数据量高度敏感，这是文献里反复观察到的结论。因此「在 Text2CAD 上评时，我们训的模型 BLEU 3.03 > Ghezelbash 训的 2.63」这一条，完全可以由「我们的训练集大 100 倍」解释，与图文质量无关。

论文对此没有任何控制：既没有把 RobotDesign1M 子采样到 9K/170K 再比，也没有报告任何随数据量变化的曲线。这一点尤其关键，因为它是全文唯一用来反驳「我们的低分只是数据噪声」的证据——§IV-A 明确写道「模型在我们数据集上分数低，但既不是过拟合也不是数据噪声所致，证据是 Table III 的跨数据集表现」。如果这条证据被数据量效应吃掉，那么「更具挑战性的基准」与「标注更嘈杂的基准」在现有实验下就无法区分，而分类器 >95% 的准确率只在那 32K 人工标注的留出集上测过，最终 100 万条的真实噪声率从未在独立样本上估计。

§ 10 — 最小复现实验 ​

一周内可做，只需要重跑问答任务的一格。

  • 数据：RobotDesign1M（发布后）、Text2CAD、Ghezelbash 三者的公开划分。
  • 实现：把 RobotDesign1M 训练集随机子采样成三档：9K（对齐 Ghezelbash）、170K（对齐 Text2CAD）、全量。三档各用同一超参微调 Qwen2-VL。
  • 测量：重画 Table III 的两个跨数据集列（Text2CAD 列与 Ghezelbash 列）的 BLEU/METEOR/L3Score，作为训练集规模的函数。
  • 判据：若 9K 档仍然在 Text2CAD 列上超过 Ghezelbash 训练的 2.63 / 15.93 / 0.34，则「质量与多样性」的归因成立，且能给出一个量化的等效换算（多少条我们的数据 ≈ 多少条别人的数据）。若三档呈明显单调、且 9K 档退回到与基线持平，则跨数据集优势主要是规模效应，论文的核心论证需要改写。这个实验的成本主要是三次微调，单卡数天即可完成。

§ 11 — 最强反例设计 ​

站在反对者立场，最有杀伤力的是一个盲视觉对照：把微调好的 Qwen2-VL 在评测时喂入全黑图像（或与问题不匹配的随机图像），其余不变，重跑 Table II 与 Table III。

这个攻击之所以有力，是因为本数据集的问答对由「图注 + 引用段落」生成，而图注和正文往往会直接写出图中内容的名称（"Fig. 3 shows the four-bar linkage of the knee joint"）。这意味着大量问题很可能仅凭问题文本的措辞、加上机器人领域的通用先验就能答对，根本不需要看图。如果盲视觉基线只掉一两个 BLEU 点，那么这个基准度量的就不是「设计图理解」，而是「机器人领域文本先验」——而后者恰恰是通用 LLM 已经具备的能力，也能解释为什么 GPT-4o 零样本的 METEOR（20.83）反而高于所有微调模型。

第二条替代解释针对检索任务。Table IV 的三个测试集检索库大小未报告，而 R@k 随库大小近似按 1/N 衰减。一个干净的做法是把三个测试集的候选库都截成同样大小（例如各 5,000 张），重跑 BLIP-2。若截齐之后 RobotDesign1M 的域内 R@1 从 12.9 大幅上升、与 Text2CAD 的 16.21 拉平，那么「我们的基准更难」这一表述就主要是库规模的记账方式问题。

第三条针对生成任务。FID 的参考分布就是本数据集，所以微调必然赢。要真正说明数据集有用，应当补一行「在 Text2CAD 上微调的 SDXL，在 RobotDesign1M 上算 FID」，以及一行「在 RobotDesign1M 上微调、在 Text2CAD 上算 FID」，构成与 Table III 同构的交叉表。

§ 12 — Follow-up Research Idea ​

本数据集当前的任务定义全部停留在描述层面：图上有什么、哪张图匹配这句话、按这句话画一张图。但设计的本质不是描述，而是功能到形式的映射——一个设计之所以长成这样，是因为它要满足某个负载、行程、带宽或自由度要求。现有三个任务里没有任何一个碰到这层。

新的 framing：把数据集从「设计图理解」重定义为「设计-指标联合建模」。同一篇论文里既有设计图，也有作者报告的定量指标（自由度、负载、峰值扭矩、重复定位精度、驱动方式、材料）。把这些指标从正文和表格里抽出来，与图配对，就得到一个 design → spec 的预测任务，以及反过来的 spec → design 检索/生成任务。这不是「扩展到新领域」，而是把监督信号从「图注怎么说」换成「这个设计实际能做到什么」，从根本上避开了 §11 指出的「答案藏在问题里」的漏洞——性能指标不会出现在图注里。

(a) 驱动它的局限：现有三个任务的真值全部由图注派生，因此模型的上限是「复述图注」，而这既不检验几何理解也不检验功能理解。(b) 可借鉴的相邻领域工具：分子性质预测里成熟的做法——结构编码器 + 多任务性质回归 + 按论文（而非按样本）划分的留出集以防泄漏；以及程序合成里的「规格-实现」配对训练。(c) 第一个实验长什么样：先在 1K 篇文献上人工抽取（图, 自由度, 驱动类型, 报告负载）四元组，训一个从图预测自由度与驱动类型的分类器，按论文级划分留出集。如果它在留出论文上显著超过「只看图注文本」的基线，说明设计图里确实存在可被学习的功能信息，这个方向才值得扩到全量 100 万条。
