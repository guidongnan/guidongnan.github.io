WorldMem: Long-term Consistent World Simulation with Memory ​

项内容
arXiv2504.12369
提交日期2025-04-16
作者Zeqi Xiao, Yushi Lan, Yifan Zhou, Wenqi Ouyang, Shuai Yang, Yanhong Zeng, Xingang Pan
分类cs.CV
一句话把历史帧连同它的位姿和时间戳一起存进 memory bank，用带状态嵌入的 cross-attention 按视野重叠度检索并读回，让世界模型在离开视野 600 帧后回头仍能重建同一个场景。

所属教程：世界模型

§ 1 — 研究问题与重要性 ​

世界模拟器的失败模式非常好复现：让 agent 在场景里转个身再转回来，原来那栋房子变了。论文把根因说得很干脆——视频生成模型受计算和显存约束，只能在一个固定的 temporal context window 内工作，窗口之外的内容被直接丢弃。丢弃即遗忘，遗忘即世界不一致。

为什么这不是一个可以靠加算力绕过的问题：注意力开销随窗口平方增长，而 world simulation 的目标是无限长的交互。任何固定窗口的方案都只是把断点往后推。要真正解决，必须把历史移到生成循环之外，做成可检索的外部存储。这就是 WorldMem 要建立的东西：一个能让"世界"在时间上真正持久的机制。

§ 2 — 前人工作与不足 ​

论文把已有的一致性方案分成两类，分别指出边界。

几何式：ReconX、CAT3D、Gen3C、WonderJourney、WonderWorld、Wonderland 显式把生成内容重建成 3D/4D 表示。这类方法能可靠地维持一致性，但代价是灵活性——世界一旦被重建成显式几何，修改它、与它交互就变得困难；而且大范围无边界场景下细节容易丢失（引 GenFusion）。

几何无关式：GameNGen、DIAMOND 这一系通过在特定场景（某张 CS:GO 或 DOOM 地图）上过拟合来保证一致性，代价是无法扩展。StreamingT2V 靠全局 + 局部视觉上下文延续，SlowFast-VGen 渐进训练 LoRA 模块做记忆召回。论文对后两者的批评很精确：它们依赖抽象表征（LoRA 权重、压缩特征），压缩率高但丢掉了空间特异性和视觉保真度，无法做到"精确重建当初看到的那个场景"。另有一支（Scene Representation Transformer、RayZer）把场景表示成固定数量的离散 token，受限于 token 预算，难以覆盖多样且不断演化的环境。

为什么这个缺口当时没被填上：因为长时世界模拟需要的记忆推理与视频生成里常见的记忆机制目标不同。MEMO 那类工作用记忆做局部时序平滑，Corgi、Make-a-Story 用记忆做语义连贯——两者都不要求像素级重建。而世界模拟要求在大幅视角变化和长时间跨度下把原场景一模一样地还原回来。这是一个更强的要求，需要显式的空间—时间对齐信息，而不只是"更多上下文"。

§ 3 — 重建作者的思考路径 ​

不引用本文贡献，只从当时的既有事实出发：

第一，Diffusion Forcing 提供了 per-frame noise level，使自回归 rollout 在扩散框架下成为可能，Oasis 已经验证了它在 Minecraft 上的可用性。这给了一个可以往上加东西的稳固底座。

第二，显式 3D 重建对动态、演化的世界不友好（放个南瓜灯、雪会化、麦子会长），所以几何路线走不通。但几何无关路线的已知问题是保真度不够。

第三，一个关键观察：生成下一帧时，历史里真正相关的只是很小一部分。绝大多数历史帧与当前视角毫无重叠。既然如此，就不该压缩全部历史（那是 LoRA 和固定 token 的做法），而应该全部存下来、按需检索少量。这直接给出 token 级 memory bank 的设计。

第四，检索到帧之后怎么用？如果只给视觉 token，模型面对"这块像素来自哪个视角、什么时候"是完全歧义的。而这些信息在 Minecraft 里是现成的：位姿 (x,y,z,pitch,yaw) 和时间戳。把它们作为状态附在每个记忆单元上，并嵌进 query-key 的注意力计算里，模型就有了做空间—时间推理的锚点。这一步是把"更多上下文"变成"可推理的记忆"的关键。

第五，怎么找相关记忆？视角是否相关，最直接的物理量是视锥重叠比例。这个量可以用蒙特卡洛采样廉价估计，不需要学习。

§ 4 — 核心 Intuition ​

模型忘掉世界，不是因为容量不够，而是因为历史被丢在了上下文窗口外面。把所有历史帧连同「它是从哪个位姿、什么时候拍的」一起存起来，生成新帧时按视锥重叠度捞回最相关的 8 帧，然后让当前帧的 token 去 attend 这些记忆——但注意力的 query 和 key 都要先加上位姿与时间的嵌入，否则模型不知道该把记忆里的哪块像素搬到当前视角的哪个位置。再把所有位姿都表示成相对于当前帧的量，学习目标就从"记住绝对坐标"退化成"做一次相对视角变换"，难度大幅下降。

§ 5 — 具体方法与完整 Pipeline ​

一个真实样例：agent 在雪地里放下一个南瓜灯，走开探索一阵，再走回来——期望看到灯还在，而且周围的雪已经被烤化了。

  • 底座：条件 Diffusion Transformer + Diffusion Forcing，Minecraft 上以 Oasis 为 base model，RealEstate10K 上以 DFoT 为 base model。动作（Minecraft 里 25 维，含移动、视角、事件触发）经 MLP 嵌入后加到去噪时间步嵌入上，通过 AdaLN 注入 temporal block。
  • 写入：每生成一帧，把它的 latent token、位姿 p∈R5、时间戳 t 打包成一个 memory unit 存进 memory bank。存的是 token 级（VAE 压缩后），不是像素。
  • 检索：对当前目标位姿，用蒙特卡洛法（默认 10000 个采样点、半径 30m 的球）估计每个历史位姿与它的 FOV 重叠比 o，结合时间差 d 算置信度 α=o⋅wo​−d⋅wt​（实现中 wo​=1，wt​=0.2/tc​），贪心取 top-8，再用相似度阈值 tr=0.9 过滤掉冗余的近重复帧。
  • 读取：memory attention。query 是正在生成的 latent token，key/value 是记忆 token。query 和 key 都加上状态嵌入后做 cross-attention。
  • 噪声安排：训练时记忆帧给最低噪声 kmin​=15，上下文窗口帧从 [kmin​,kmax​] 独立采样（kmax​=1000）；推理时记忆帧和上下文帧都设为 kmin​，待生成帧设为 kmax​。
  • 训练配置：MineDojo 生成约 12K 条长视频，每条 1500 帧；分辨率 640×360，VAE 编到 32×18 再 patchify 到 16×9；8 帧上下文 + 8 帧记忆；4 卡、每卡 batch 4、约 500K 步、Adam lr 2×10−5。

§ 6 — 核心数学推导 ​

状态嵌入。位姿用 Plücker 嵌入转成稠密的逐像素特征。给定像素 (u,v)，先反投影到相机坐标 πuv​=K−1[u,v,1]T，转到世界方向 duv​=Rc​πuv​+c，则该像素对应的光线用 Plücker 坐标表示为：

luv​=(c×duv​, duv​)∈R6

为什么用 Plücker 而不是直接编码 5 维位姿？因为一个 5 维向量对整帧是一个数，模型必须自己推断"这个位姿如何影响每个像素"；而 Plücker 给出的是 H×W×6 的稠密场，每个像素直接携带自己那条光线的空间信息。消融证实了这一点：稀疏位姿嵌入 PSNR 20.67，稠密（Plücker）23.63。

时间用正弦嵌入过 MLP，与位姿嵌入相加：

E=Gp​(PE(p))+Gt​(SE(t))

状态感知记忆注意力。设 Xq​ 为当前帧展平特征，Xk​ 为拼接的记忆特征，先各自注入状态：

X~q​=Xq​+Eq​,X~k​=Xk​+Ek​

X′=CrossAttn(Q=pq​(X~q​), K=pk​(X~k​), V=pv​(Xk​))

注意 value 用的是 Xk​ 而不是 X~k​——状态只参与"找哪块记忆"（相似度计算），不参与"搬什么内容"。这是一个干净的职责分离：位姿是索引，像素是内容。

相对状态。query 帧的状态被置零（位姿设为单位、时间戳设为 0），key 帧的状态归一化成相对值。这把学习目标从"在绝对世界坐标系里做推理"变成"做一次相对视角变换"——后者与训练时见过的位姿分布无关，因此能外推。消融显示这一步主要改善的是 LPIPS 和 rFID：绝对编码 0.1830 / 29.34，相对编码 0.1429 / 15.37，rFID 几乎减半。

时序 attention mask：

Amask​(i,j)=⎩⎨⎧​1,1,0,​i≤LM​ 且 j=ii>LM​ 且 j≤i否则​

LM​ 是记忆帧数。第一行保证记忆帧之间互不影响（每个只能看自己），第二行保证上下文帧的因果性。这条约束是必要的：记忆帧来自任意时刻，若允许它们互相 attend，时间顺序就被破坏了。

§ 7 — 实验设计与结论 ​

问题一：窗口内的一致性就已经坏了吗？ 是。上下文窗口 16、记忆窗口 8，在"左转再右转"这类自返回运动上测：Full Sequence 基线 PSNR 20.14 / LPIPS 0.0691，Diffusion Forcing 24.11 / 0.0094，WorldMem 25.98 / 0.0072。全序列训练的模型在自己的窗口内都做不到自洽，DF 靠帧间信息交换改善，记忆机制再进一步。

问题二：窗口外呢？ 这才是真正的考验。上下文窗口压到 8，先建 600 帧的 memory bank，再生成 100 帧，与 600 帧之后的真值比。Full Seq 根本 roll 不了这么长（表中为空）；DF 崩溃：PSNR 17.32、LPIPS 0.4376、rFID 51.28；WorldMem 23.98 / 0.1429 / 15.37。rFID 从 51 降到 15 说明的不只是"更接近真值"，而是"画质本身没有退化"——DF 的低 rFID 反映了长程 rollout 的质量崩塌。

问题三：真实场景管用吗？ RealEstate10K 上设计 5 条首尾同位姿的闭环轨迹、100 个场景，轨迹长 37–60 帧，超过所有基线的训练长度（最长 25 帧）。CameraCtrl 13.19 / 0.3328 / 133.81，TrajAttn 14.22 / 0.3698 / 128.36，DFoT 16.42 / 0.2933 / 110.34，ViewCrafter（显式 3D 重建）21.72 / 0.1729 / 58.43，WorldMem 23.34 / 0.1672 / 43.14。ViewCrafter 排第二这件事本身有信息量：显式几何确实有效，只是受重建和渲染的后处理误差拖累。论文同时承认 RealEstate 限制了方法的发挥，因为它是短的、非交互的片段。

问题四：各个设计各值多少？ 检索策略：随机采样 18.32 / 0.3224 / 47.35 → 加置信度过滤 23.12 / 0.1863 / 24.33 → 再加相似度去冗余 23.98 / 0.1429 / 15.37。训练采样策略：小范围（2m 内）19.23、大范围（8m）21.11、渐进式（先小后大）23.98——课程式的难度递增是必需的。时间条件：无 23.17 / 0.1989 / 23.89，有 25.12 / 0.1613 / 16.53。记忆长度：1 帧 22.18，8 帧 25.32（最优），16 帧反而掉到 23.14，说明记忆过多会引入噪声、降低检索精度。

问题五：不给真值位姿还能用吗？ 训了一个轻量位姿预测器（输入前一帧、前一位姿、下一动作）。GT 位姿 25.32 / 0.1429 / 15.37，预测位姿 23.13 / 0.1786 / 20.36——有下降但可接受。

问题六：代价多大？ 600 个视觉记忆 token（形状 [600,16,18,32]，float32）约 21MB。检索延迟：10 个候选 0.04s、600 个 0.10s、1000 个 0.16s，而单帧生成（20 步去噪）约 0.9s，检索只占 10–20%。训练显存 33GB → 51GB，速度 3.19 → 1.76 it/s；推理显存 9GB → 11GB，速度 1.03 → 0.89 it/s。训练开销显著，推理开销很小。

§ 8 — Take-aways ​

5 句话：固定上下文窗口是世界模型不一致的结构性根源，加窗口只能推迟问题。WorldMem 把全部历史帧以 token 形式存进外部 memory bank，每个单元附带位姿和时间戳，用视锥重叠度 + 时间邻近度做置信度检索，取 top-8。读取时用 state-aware cross-attention：query 和 key 都注入 Plücker 位姿嵌入与时间嵌入，value 保持纯视觉，实现"位姿当索引、像素当内容"的职责分离。位姿一律用相对表示，把绝对定位问题化归为相对视角变换，这是长程外推的关键（rFID 29.34 → 15.37）。600 帧之后回望，PSNR 从 Diffusion Forcing 的 17.32 提到 23.98，且推理开销仅增加约 2GB 显存与 14% 时间。

3 句话：记忆不该被压缩成抽象特征，该被全量保留、按需检索。检索到的帧必须带空间—时间状态，否则模型无法把它对齐到当前视角。相对位姿把外推问题变成插值问题。

1 句话：给每一帧记忆贴上「从哪儿看、什么时候看的」标签，世界才能被找回来。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：视锥重叠度足以判定一帧记忆是否与当前生成相关。整个检索环节——也就是把 O(N) 的历史压到 8 帧的那一步——完全依赖它，而消融显示随机检索会让 PSNR 从 23.98 掉到 18.32，即检索质量几乎决定了方法的全部收益。

它在实践中为什么可能不成立：FOV 重叠是一个纯几何的、不考虑遮挡的判据。蒙特卡洛采样只检查空间点是否同时落在两个视锥内，不检查这些点是否真的被看见。在有遮挡的场景里——站在墙的两侧、洞穴里、密林中——两个位姿可以有极高的 FOV 重叠却观测到完全不同的内容。此时检索会自信地返回一批无关记忆，而模型被训练成信任检索结果。论文自己在 limitations 里点名了这一点："when views are blocked by obstacles, relying solely on view overlap may be insufficient"。

论文提供了什么证据：它给出的是"模型对不完美检索有一定鲁棒性"的定性说法（"the model's reasoning over memory helps maintain performance even when the retrieved content is imperfect"），以及随机检索 vs 置信度检索的消融。缺什么证据：没有按遮挡程度分层的评测。Minecraft 恰恰是一个遮挡极其常见的环境（方块地形、洞穴、建筑内部），而所有报告的数字都是在混合场景上的平均值。一个遮挡重的子集上的单独评测，会直接暴露这条假设的边界。

§ 10 — 最小复现实验 ​

一周内可做，不需要训练任何生成模型：

  • 只实现检索模块——蒙特卡洛 FOV 重叠估计（10000 点、30m 半径），这是纯几何计算，几百行代码。
  • 用 MineDojo 采集 200 条轨迹，每条 600 帧，记录每帧的 RGB、深度和位姿。
  • 对每条轨迹的最后一帧作为 query，用 FOV 重叠度检索 top-8 历史帧。同时用深度图计算真实的像素级可见性重叠（把 query 帧的像素反投影到 3D，检查它在每个历史帧里是否可见且未被遮挡），作为 ground truth 相关性。
  • 度量：FOV 检索的 top-8 与真实可见性 top-8 的重合率（Recall@8），并按场景类型分层——开阔平原、建筑内部、洞穴、密林。
  • 判据：若开阔场景 Recall@8 > 0.8 而洞穴/室内场景 < 0.4，则遮挡确实是 WorldMem 的系统性失效条件，且该失效被平均指标掩盖了。这直接量化了 §9 的假设，成本远低于复现整个模型。

§ 11 — 最强反例设计 ​

站在反对者立场，最有力的攻击是给"WorldMem 学会了记忆与推理"一个替代解释：它可能只学会了一个条件很强的图像 warping 操作——给定一张记忆帧和它相对当前视角的位姿差，做几何变换后贴过来。如果是这样，那么它的"记忆"能力实质上等价于一个可微的重投影模块，并不涉及任何世界状态的理解。

设计一个能区分两者的实验：构造记忆帧与目标帧之间不存在有效几何变换的场景。例如，agent 从正面观察一个房子，走到房子背面。此时正面的记忆帧与背面视角 FOV 重叠可能很低（会被检索过滤掉），但更尖锐的设定是：给一个部分遮挡的物体——记忆帧里只能看到桌子的左半边，目标视角要求生成整张桌子。纯 warping 只能把左半边搬过去，右半边必须靠对"这是一张桌子"的理解来补全，且要与左半边风格一致。

度量方式：把生成的右半边与真值比 PSNR，同时与"把左半边镜像过去"的朴素基线比。如果 WorldMem 显著优于镜像基线，说明它确实在做超越几何变换的推理；如果两者相当，则"记忆推理"这个说法应弱化为"位姿条件的重投影"。

第二条攻击：论文所有 Minecraft 实验都使用游戏引擎给出的真值位姿（推理时可换成预测位姿，但预测器也是在有真值监督下训练的）。在真实世界里位姿本身就需要从视频里估计，误差会与记忆检索误差耦合。设计实验：给真值位姿注入递增的高斯噪声（模拟 SLAM 误差量级，例如平移 0.1m/0.5m/1m，角度 1°/5°/10°），观察 PSNR 曲线。若在 SLAM 的典型误差量级下性能就已明显下降，那么这套方法对真实场景的适用性远比 RealEstate10K 上的结果所暗示的窄。

§ 12 — Follow-up Research Idea ​

驱动局限：WorldMem 的记忆是只写不改的——每一帧存进去就再不更新。但真实世界是会变的，论文自己用时间戳部分处理了这件事（雪化了、麦子长了）。问题在于时间戳只是一个标签，模型必须自己从"同一位置、不同时刻"的多份记忆里推断出变化规律。当交互次数上升，同一个地点会积累几十份互相矛盾的快照，检索必须在其中选，而选错就等于回退到过去的世界状态。同时 memory bank 线性增长，论文把这列为 limitation。

新 framing：把记忆从"帧的日志"改成"世界状态的信念（belief）"。不再存所有历史快照，而是维护一个按空间索引的、可被观测更新的信念集合：每次生成新帧后，不是追加一条记录，而是用新观测去修正该区域的信念（连同一个不确定度）。检索时返回的不是历史帧，而是当前信念的渲染。这把无界增长的日志变成有界的状态表示，同时天然解决了"矛盾快照"的选择问题——矛盾在写入时就被消解了。

可借鉴的邻域工具：（a）SLAM 里的占据栅格与子图（submap）管理，几十年来就在处理"如何用有界内存维护一个可更新的空间表示"；（b）贝叶斯滤波的观测更新，给出了"新观测如何修正旧信念"的原则性形式；（c）LLM agent 领域的记忆整合（memory consolidation）——从 episodic 日志中周期性蒸馏出 semantic 摘要，与这里的需求同构；（d）神经辐射场的增量式更新方法，提供了在连续表示上做局部修正的工程手段。

第一个实验：先不改架构，只改写入策略，做一个可证伪的对照。在 WorldMem 的 memory bank 上加一个空间体素索引：把世界离散成体素，每个体素最多保留 K 条记忆（K=1,2,4 三档），新观测进来时按"时间更新 + 视角更正交"的准则替换旧条目。对照组是原版的无界追加。在 MineDojo 上跑 3000 帧的长交互（远超论文的 600 帧），比较：（a）峰值内存；（b）1000 / 2000 / 3000 帧处回望同一地点的 PSNR；（c）检索延迟。判据：若 K=2 的体素方案在内存恒定的情况下 PSNR 不劣于无界追加，说明记忆的价值在于空间覆盖而非时间完整性，那么"记忆即信念"的路线就有了第一块实证基础；若 PSNR 明显下降，则说明模型确实在利用多时刻快照做时序推理，此时应该转向显式建模变化过程而不是压缩快照——两种结果都直接指导下一步。
