ProtoKV: Streaming Video Understanding under Delayed Query with Summary-State Memory ​

项内容
arXiv2606.26762
提交日期2026-06-25
作者Le Tu Ngoc Minh, Jinyeong Lim, Dongsu Han
分类cs.CV, cs.LG
comments20 pages, 4 figures, Accepted to ICML 2026
一句话近窗保留精确 KV、远期历史不再保留 token 实例而是聚合成定容的 object-centric prototype bank（中心 + PQ 残差统计 + 质量计数），查询时把每个 prototype 解码成固定数目的 pseudo-token 直接拼进标准 attention，使远期证据在长延迟查询下不被淘汰稀释。

所属教程：长视频理解

本页依据 arxiv.org/html/2606.26762v1 全文与 arxiv.org/e-print/2606.26762 的 TeX 源码撰写。

§ 1 — 研究问题与重要性 ​

流式视频理解通常被表述成"显存有界下如何压 KV cache"。本文把问题往前推了一步：真正决定系统好坏的不是压缩率，而是查询延迟（delayed query）。决定性线索可能只出现几秒，而用户的问题在几十分钟后才异步到达；在这段时间里记忆已经被成千上万次更新覆写过。作者把这个量重新定义为 "post-evidence update pressure"——延迟不只是时间差，更是证据出现之后累积的更新压力。

这个重述有实际后果。它意味着评测流式记忆时，把所有查询混在一起报一个平均准确率是没有意义的，因为长延迟与短延迟的样本考察的是完全不同的机制：短延迟只考近窗，长延迟才考远期记忆。论文因此设计了一个按延迟分桶的评测协议，这一点比它的方法本身更值得关注。

有界记忆的设计空间此前占据两个极端。滑窗（SWA）保证常数显存但一旦过期就永久丢失；offloading / retrieval 系统（如 ReKV）能找回细节但把开销推到查询时，带来时延与方差。中间那个"始终在线、query-agnostic 维护、固定占用、查询时可直接使用"的工作点，正是交互式系统真正需要的，也是本文的目标区间。

§ 2 — 前人工作与不足 ​

滑窗 KV cache 是最朴素的有界基线，常数显存，但它对远期证据的处理方式是直接截断。

在线 token 保留 / 压缩（InfiniPot-V 是本文的主要对照）在硬上限下对 token 实例做选择、合并、淘汰。它比滑窗温和，但作者的批评切中要害：只要远期历史还被表示成 token 实例的子集，一个 token 被丢掉，它携带的细粒度线索就彻底没了。选择性保留在证据稀疏且延迟很长时是脆弱的——每一次淘汰都是一次不可逆的赌注，而赌注要下几万次。

ReKV 走 offloading / 选择性召回路线，代价是需要相当大的显存预算才能维持精度，且召回发生在查询时，直接抬高时延。ProVideLLM 用 verbalized text token 表示远期历史，但需要专门训练做视觉-文本对齐。VideoLLM-MoD 优化的是层级计算跳过，与 cache 无关。

作者据此圈定了对照准入条件：有界 KV 显存、免训练、query-agnostic 在线更新。满足这三条的只剩 SWA 与 InfiniPot-V，这也是表 1 的对照集合。这个准入条件是合理的，但它同时意味着对照集非常小，后面会提到这带来的问题。

§ 3 — 重建作者的思考路径 ​

第一步是接受一个观察：token 淘汰的失败模式是"全有或全无"。一个 token 被淘汰后，与它相关的所有信息都归零。而摘要式表示的失败模式是"逐渐模糊"——信息会被平均掉，但不会突然消失。在长延迟场景下，缓慢退化显然优于阶跃丢失。这一步把设计目标从"选对 token"改成了"造一个不会突然丢东西的摘要"。

第二步是问摘要该以什么为单位。按时间分块摘要是最自然的想法，但视频里同一个物体会在不同时间反复出现，按时间切会把同一实体的证据打散。按内容聚类更合适：把 key 空间相近的 token 归到同一个 prototype，等于做在线的 object-centric 聚合。

第三步是发现"只存中心"不够。prototype 吸收的 token 越多，中心就越是均值，独特线索被平均掉的风险越大——而这恰恰是长延迟场景最关键的地方。所以中心之外还得留一点表示簇内多样性的东西，但又不能存 per-token 的编码（那就退回 token 保留了）。Product Quantization 的流式直方图统计正好符合：定容、可在线更新、能刻画中心周围的多峰残差结构。

第四步是接口问题。摘要再好，如果需要改模型结构就没法即插即用。把每个 prototype 解码成 S 个合成的 KV 条目（pseudo-token），和近窗的真实 KV 拼在一起送进标准 attention，是唯一不动模型的做法。而一旦这么做，就必须补一个 mass-aware 的修正——否则一个吸收了一万个 token 的 prototype 和一个只吸收了三个的，在 attention 里权重是一样的。

§ 4 — 核心 Intuition ​

token 保留式的有界记忆，其失效方式是不可逆的阶跃丢失；摘要式的有界记忆，其失效方式是可控的逐渐模糊。当查询延迟很长、证据必须熬过成千上万次更新时，后者更优。把远期历史聚合成定容的 object-centric prototype，用残差统计防止过度平均、用 log-mass bias 恢复被折叠掉的多重度，就能在常数占用下让远期证据保持可用；再用 pseudo-token 把它伪装成普通 KV，标准 attention 不需要任何改动。

§ 5 — 具体方法与完整 Pipeline ​

两层状态。 近窗 Bnear​ 保留最近若干帧的精确 KV；被挤出近窗的 token 进入远期记忆，被吸收进一个定容的 prototype bank。

在线分配。 对每个被淘汰的 token i，在 prototype 中选一个 k⋆ 最小化三项组合目标：

  • key 空间相似度 −cos(Ki​,ck​)。作者只用 key 不用 value 做分配，理由是 dot-product attention 里检索权重取决于 q⊤k，而 value 只影响加权之后的内容；value 内容变化更剧烈，用来做在线分组不稳定。
  • 空间连续性 λsp​dMah​(si​;μk​,Σk​)，即在 prototype 自身的位置分布上做马氏距离门控，抑制多个相似物体共现时的 prototype 跳变。
  • 陈旧度控制 λidle​1[t−τk​>Tidle​]，压制长期未更新的 prototype 被匹配。

prototype 更新。 分配后更新中心 (ck​,pk​)（EMA）、质量计数 nk​、残差统计 Rk​、空间状态 (μk​,Σk​) 与最近使用时间 τk​。

容量维护。 陈旧 prototype 做 mass decay；中心足够接近的做 merge；质量衰减到 0 的槽位从近窗的一个 token 重新初始化回收。

残差统计。 对分配到 k 的 token 记 riK​=Ki​−ck​、riV​=Vi​−pk​，用基于 PQ 的流式直方图统计定容地保存这些残差的分布结构，目的不是重建单个 token，而是保住簇内多样性。

pseudo-token 接口。 查询时把每个 prototype 的中心与残差统计蕴含的代表性残差模式组合，解码出 S 个合成 KV 条目，与近窗真实 KV 拼接成定长上下文。位置编码上，同一 prototype 的 S 个 pseudo-token 共享同一个 rotary 位置 τk​（最近被吸收的源 token 的原始流位置），近窗 token 保留原位置。

mass-aware bias。 对每个 prototype 在 softmax 之前加 bk​=lognk​ 到 attention logit 上（见 §6）。

一个具体例子：一段 40 分钟的第一人称录像，第 6 分钟主人把钥匙放进抽屉。这几帧的 token 先在近窗被精确保留，随后被吸收进"抽屉 / 钥匙"这个 prototype；接下来 34 分钟里发生了大量无关活动，但由于连续性分配把后续同类观测继续喂给同一个 prototype，它的 nk​ 不断累积、不会被回收。第 40 分钟用户问"钥匙在哪"，该 prototype 被解码成 S 个 pseudo-token，凭 lognk​ 的加成在 attention 里拿到与其证据量匹配的权重。

§ 6 — 核心数学推导 ​

关键推导是 mass-aware bias 的合理性。设 prototype k 吸收了 nk​ 个 token。若把它们真的实例化，softmax 分母里这一簇贡献的是 ∑j=1nk​​exp(q⊤kj​/d​)；若这些 token 的 key 都接近中心 ck​，该和约等于 nk​exp(q⊤ck​/d​)。而

nk​exp(d​q⊤ck​​)=exp(d​q⊤ck​​+lognk​).

于是把 bk​=lognk​ 直接加到 logit 上，就在不实例化这 nk​ 个 token 的前提下复现了它们的聚合效果。论文给出的形式是

ℓk,s​=d​q⊤k~k,s​​+bk​,

bk​ 在该 prototype 的全部 S 个 pseudo-token 间共享，且在 softmax 之前施加。作者把它类比为 softmax 归一化下的先验 logit 调整（long-tail 分类里的 logit adjustment）。

需要看清这个近似的适用边界：它只在簇内 key 相对中心的离散度足够小时才成立。簇越大越杂，∑j​exp(⋅) 与 nk​exp(⋅) 的差距越大——由 Jensen 不等式，前者恒不小于后者，所以 lognk​ 是下估。残差统计的存在部分补偿了这一点（S 个 pseudo-token 覆盖了中心之外的模式），但论文没有给出误差界。这属于工程上可用、理论上未闭合的近似。

§ 7 — 实验设计与结论 ​

问题一：常规基准上是否有优势。 表 1（token 预算 ∣M∣ = 24k 用于 RVS-Ego / RVS-Movie，4k 用于 OVO-Bench / StreamingBench）。LLaVA-OV-7B 上，RVS-Ego 准确率 SWA 55.7 / InfiniPot-V 57.8 / ProtoKV 58.6；RVS-Movie 50.8 / 51.4 / 52.1；OVO-Bench 53.5 / 54.2 / 54.8；StreamingBench 72.9 / 75.2 / 76.3。Qwen2.5-VL-7B 上四项分别是 58.4→58.9→59.4、52.0→52.3→53.1、53.2→53.6→54.4、75.9→76.4→77.3。相对 InfiniPot-V 的增益普遍在 0.5–1.1 点之间，这一点必须说清楚：主表上的差距很小。

问题二：按查询延迟分桶后差距如何变化。 这是本文真正的实验主张。作者把查询时间设为 tq​=t0​+Δ（分钟），只保留答案不随 tq​ 变化的 retrospective 问题类型，并只在对所有 Δ 都有效的交集子集上评测。图 3 的结论：SWA 在延迟超过近窗时出现断崖式下跌；InfiniPot-V 平缓下降但持续下降；ProtoKV 的退化斜率明显更平。文中给出的最大延迟点数字是在两个基座上 RVS-Movie 相对 SWA 最多 +20.4pp、相对 token retention 最多 +12.5pp。摘要里那个 12.5 点，出处就是这里，不是主表。

问题三：这种鲁棒性来自哪个部件。 表 2 在 ∣M∣=24k、LLaVA-OV-7B、RVS-Ego、与图 3 相同交集子集上做消融，两列分别是 Δ=0 与 Δ=30 的准确率（括号是相对 Δ=0 的跌幅）：完整方法 59.0 → 54.3（-4.7）；只有近窗 57.5 → 40.5（-17.0）；只有远期 prototype 54.5 → 49.2（-5.3）；去掉残差统计 58.5 → 51.0（-7.5）；去掉 mass bias 58.3 → 51.0（-7.3）；去掉连续性分配 56.2 → 47.5（-8.7）。这张表读起来很干净：远期摘要负责长延迟不崩，近窗负责短延迟不虚，残差统计与 mass bias 各自贡献约 3 点的长延迟稳定性。

问题四：离线设定下还成立吗。 表 3 用 Qwen2-VL-7B 对齐既有 OVU 基线。VideoMME：DyCoke 3K 55.3 / 6K 59.7，InfiniPot-V 3K 61.2 / 6K 62.8，ProtoKV 3K 62.1 / 6K 63.7；MLVU：57.5 / 60.5、67.2 / 68.4、67.0 / 68.9。MLVU 3K 上 ProtoKV（67.0）低于 InfiniPot-V（67.2），作者如实写成"remains competitive"。

问题五：代价。 表 4 在匹配峰值显存（23.0 GB）下对比 ReKV：准确率 58.8 vs 58.0（ProtoKV 略低），TTFT 1.43s vs 1.06s，端到端时延 3.92s vs 2.90s，两项时延各降约 26%。在线更新开销单独测了：Qwen2.5-VL-7B、RVS-Ego、RTX 5090，每帧 33.8 ms，占单帧总处理时间的 30.8%，发生在摄入阶段而非查询时。硬件型号写明了，这一点合规。

问题六：什么时候会失败。 4.6 节按 MLVU 任务类型拆解，作者主动指出最明显的弱点是需要区分或计数大量视觉上高度相似的重复事件的任务：在固定 prototype 容量下这些事件会被吸收进同一个 prototype，边界被压糊。这是摘要式表示的机制性代价，作者没有回避。

§ 8 — Take-aways ​

5 句版：流式记忆的核心变量不是压缩率而是查询延迟，延迟应被理解为证据之后累积的更新压力。token 保留式记忆的失效是不可逆的阶跃丢失，摘要式记忆的失效是可控的逐渐模糊，长延迟下后者占优。ProtoKV 用近窗精确 KV + 定容 object-centric prototype bank（中心 + PQ 残差统计 + 质量计数）实现常数占用，用 pseudo-token 与 lognk​ 的 logit bias 把它接进未经修改的 attention。主基准上相对 token retention 只有 0.5–1.1 点的优势，但按延迟分桶后在最大延迟点上可达 +12.5pp，消融显示远期摘要与近窗各自负责长短延迟的一端。方法的机制性弱点是无法区分大量视觉相似的重复事件，作者自己也承认。

3 句版：把远期历史从"保留哪些 token"改成"维护一个定容摘要状态"，并用 pseudo-token 保持与标准 attention 的兼容。主表上的差距很小（0.5–1.1 点），真正的差距在长延迟桶里（最大 +12.5pp）。代价是重复相似事件的边界被压糊，以及每帧 33.8 ms 的摄入开销。

1 句版：评估流式记忆必须按查询延迟分桶报数，混在一起的平均准确率会把摘要式与保留式记忆的本质差别抹平。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是评测协议本身：延迟查询是通过把查询时间戳人为后移 $\Delta$ 分钟来模拟的，并假定被保留的 retrospective 问题的答案不随 $t_q$ 改变。作者自己在 4.1 节坦白了原因——所评基准没有提供"最后一次证据出现时间" te​，所以只能拿数据集自带的查询时间 t0​ 当参照往后推。整个 12.5 点的头条结论完全建立在这个代理量上。

它可能不成立的方式有三种。其一，Δ 度量的是"从 t0​ 起的时间"，而不是"从证据起的时间"；不同样本的 t0​ 与真实 te​ 之间的间隔千差万别，因此同一个 Δ 桶里混着实际延迟差别巨大的样本。其二，为了让所有 Δ 可比，评测被限制在"对每个 Δ 都满足 t0​+Δ≤L"的交集子集上，这会系统性地筛掉短视频，使大延迟桶偏向长视频——而长视频本来就更难，方法间的差距也更容易被放大。其三，规则式的 retrospective 过滤是否真的保证了答案不变，论文只给了附录里的正反例，没有给人工核验的一致率。

论文为这条假设提供的证据是间接的：表 2 的消融在同一交集子集上做，内部一致性很好；但没有任何独立于该协议的长延迟证据。这属于缺失证据——如果有一个原生标注了 te​ 的基准，哪怕只在上面复现一个点，说服力都会完全不同。

§ 10 — 最小复现实验 ​

一周内可做的最小验证，目标是把"摘要状态优于 token 保留"从人造延迟协议里解耦出来。

  1. 取 LLaVA-OV-7B 与一个自带证据时间标注的数据集（例如从带 temporal grounding 标注的长视频 QA 里取子集，用标注的证据区间末端当 te​）。
  2. 按真实延迟 Δe​=tq​−te​ 分桶，而不是按 t0​+Δ。
  3. 在匹配的 24k 预算下实现三个变体：SWA、一个简单的 token 保留（按 attention 分数在线淘汰即可，不必复现 InfiniPot-V 全部细节）、以及一个简化版 ProtoKV——只做 key 空间 EMA 聚类 + lognk​ bias，不实现 PQ 残差统计与空间连续性。
  4. 判据：若简化版 ProtoKV 在大 Δe​ 桶上相对 token 保留仍有两位数增益，则"摘要 vs 保留"这条主张独立于人造协议成立；若增益缩到 2–3 点，则原文的 12.5 需要归因到协议或到残差统计这些附加部件上。表 2 显示去掉残差统计会让 Δ=30 的分数从 54.3 掉到 51.0，所以这个拆分是有意义的。

§ 11 — 最强反例设计 ​

最强的攻击针对缺失的平凡基线。论文的对照集只有 SWA（纯近期）与 token retention（选择性保留）。有一个同样满足"有界、免训练、query-agnostic"三条准入、却没有被评测的基线：均匀时间下采样——把固定预算按时间均匀铺满已观测的整条流，新帧到达时对全体重采样。这个基线的性质恰好与 SWA 互补：它在长延迟下几乎不退化（因为远期证据始终以固定密度保留），代价是近期细节变粗。按论文自己对 Δ 的解释，均匀下采样在大 Δ 桶上应当表现得相当好。如果它能拿到接近 ProtoKV 的长延迟分数，那么"必须用 object-centric 摘要"这个结论就被大幅削弱——真正起作用的可能只是"别把预算全押在近期"。这个对照极其便宜，论文里却没有。

第二重攻击针对表 1 与表 3 的统计显著性。主表上 ProtoKV 相对 InfiniPot-V 的差距是 0.5–1.1 点，RVS 系列的 Score 还是用 gpt-3.5-turbo-0125 打的 0–5 分。论文全篇没有报告任何置信区间、标准差或多次运行；LLM 评分本身有采样噪声，题量也有限。构造反例的方法是：固定所有设置，只改评分模型的随机种子或换一个评分模型，重跑三次表 1。若 ProtoKV 与 InfiniPot-V 的排序在三次里发生翻转，主表就不能支撑"consistently outperforming"这一措辞。真正稳的是图 3 与表 2 的长延迟结论，那里的差距有 7–17 点，噪声吃不掉。

第三重是一个可预测的失败构造，直接把作者在 4.6 节承认的弱点做成攻击：录制一段包含 N 次高度相似重复动作（例如反复开关同一个抽屉）的长视频，问"第几次开抽屉时里面是空的"。ProtoKV 会把这 N 次全部吸收进同一个 prototype，lognk​ 只会让它更响亮而不会让它更可分；token 保留式方法至少还可能保住其中某一次的实例。预测 ProtoKV 在这类题上低于 InfiniPot-V。这不是外部批评，是把作者的自陈弱点量化。

§ 12 — Follow-up Research Idea ​

驱动局限：prototype 是内容驱动的聚类，时间只以 τk​（最近一次吸收的位置）和 mass decay 的形式弱参与。这直接导致 4.6 节承认的失败：同一物体的 N 次出现被折叠成一个不可分的簇，"第几次"这类问题在原理上无法回答。而第一人称长时程记忆里，"第几次 / 上一次 / 通常"恰恰是最高频的问题类型。

新 framing：把 prototype 从"一个中心 + 残差分布"升级成"一个中心 + 一段发生时间的分布"，即让每个 prototype 携带一个定容的时间直方图（在时间轴上做 PQ 式的流式分桶），并在 pseudo-token 解码时把不同时间峰值解码成不同位置编码的 pseudo-token，而不是像现在这样全部共享 τk​。这样一个反复出现的物体会展开成若干个时间上分离的 pseudo-token，attention 就有机会区分"第一次"与"最后一次"。这个想法的工具可以直接从流式数据库的分位数草图（t-digest、KLL sketch）和事件序列建模里借，它们本来就是为"定容近似一个时间分布"设计的。

第一个实验：不必改训练，只需在现有 ProtoKV 上加一个每 prototype 的 16 桶时间直方图，把 S 个 pseudo-token 的位置编码从"共享 τk​"改成"按直方图质量分位取 S 个时间点"，然后在两个数据集上对比：一是论文用的 RVS-Ego 长延迟桶（验证不掉分），二是自建的 N 次重复事件计数 / 序数题集（验证涨分）。论文的附录 D.1 已经比较过三种 RoPE 位置锚点选择，说明这个接口是可插拔的，改动量很小。若序数题上的增益显著而长延迟分数不降，就说明"定容摘要"这条路线还欠一个时间维度，而不是已经到顶。
