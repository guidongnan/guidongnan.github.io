SimWAM: A Simple World Action Model for End-to-End Autonomous Driving ​

项内容
arXiv2608.07468
提交日期2026-08-07（v3: 2026-08-17）
作者Zongchuang Zhao, Xin Zhou, Tianyang Xu, Zhengyang Sun, Kaixuan Zhou, Honglin Li, Dingkang Liang, Xiang Bai
分类cs.CV
一句话让视频专家和轨迹专家共用一条 attention 流联合做 flow matching，但用一张隔离掩码让动作 token 永远看不见未来帧 token，于是未来视频只在训练期起监督作用，推理期整条视频生成通路可以直接扔掉；再把确定性 ODE 换成保持边缘分布的 SDE，用 Flow-GRPO 直接优化 NAVSIM 的 PDM 复合奖励。

所属教程：从视频生成到世界动作模型

§ 1 — 研究问题与重要性 ​

驾驶 WAM 目前普遍采用 imagine-then-act 的分解：

pθ​(at+1:t+H​∣ot​,st​,l)=∫pθ​(zt+1:t+N​∣ot​,st​,l)pθ​(at+1:t+H​∣ot​,st​,l,zt+1:t+N​)dzt+1:t+N​

先合成未来场景 latent，再据此生成轨迹。论文指出这个分解的代价很直接：它把昂贵的视频合成放进了实时规划回路。SimWAM 主张退回最朴素的策略接口 pθ​(at+1:t+H​∣z(ot​),st​,l)，只用当前观测的表示，而把交通动力学先验完全交给训练期的未来视频监督去注入。

论文自己把定位说得很克制：不主张算法优越性，只想立一个「简单且扎实的 WAM 基线」，用来考察通用视频模型在自动驾驶里的潜力。

§ 2 — 前人工作与不足 ​

论文把对手分三类。传统端到端规划器（UniAD、VAD、DiffusionDrive、WoTE、SeerDrive）本质是模仿策略，交通语义、用户意图与场景动态只被隐式捕获。驾驶 VLA（ORION、AutoVLA、ReCogDrive、SGDrive、FutureSightDrive、ExploreVLA）引入了语义知识与显式推理，其中一部分也加了未来场景生成或 latent reasoning，但论文批评这些组件「与动作预测耦合松散，且常需要额外训练阶段或串行推理」。

真正的靶子是驾驶 WAM：Epona 用自回归扩散联合预测未来视频与轨迹，DriveLaW 把扩散规划器条件在视频生成器产出的 latent 上，DriveWAM 联合训练视频预测器与规划器。这些方法的共性是推理期轨迹规划仍与未来视觉生成绑定。

论文明确承认自己的出发点来自 Fast-WAM 的一个结论：视频 co-training 的收益主要来自训练期的表征学习，而非测试期的未来想象。SimWAM 做的是把这个结论在驾驶域推到极致——既然测试期不需要想象，那就用一张掩码在结构上保证它不可能被需要。

§ 3 — 重建作者的思考路径 ​

只用已有背景推。rectified flow 给了一个统一的生成接口，轨迹和视频可以用同一个损失形式训练。Fast-WAM 已经说明未来想象在推理期是可省的。Flow-GRPO 已经给出了把确定性 flow ODE 改成保持边缘分布的 SDE、从而获得可解析的转移密度用于策略梯度的做法。NAVSIM 提供了一个可微分之外仍可计算的复合驾驶奖励 PDMS。

于是三步几乎是拼出来的。第一步：既然两个模态可以用同一个 flow matching 目标，就让它们共享一条 attention 流而不共享任何参数——这样视频骨干可以随时替换。第二步：既然推理期不想要未来帧，就必须保证动作分支在训练时也没有依赖它，否则推理期删掉它会造成 train/test 不匹配；最省事的实现就是一张注意力掩码。第三步：既然模仿学习的上限被演示数据锁死，而 PDMS 本身可算，就把 ODE 换成 SDE 采一组候选轨迹，用组内相对优势做 GRPO 更新。

§ 4 — 核心 Intuition ​

未来视频对规划的作用是塑造当前观测的表示，而不是提供一份可供查阅的未来。既然如此，就不要让动作 token 有机会去查阅它——用一张掩码把这条捷径堵死，动作分支被迫把所有交通动力学信息内化进对当前帧的理解。堵死之后，推理期删掉整条视频通路不改变任何东西。

§ 5 — 具体方法与完整 Pipeline ​

输入是单目前视图像 ot​、含速度加速度与横摆角速度的自车状态 st​、导航指令 l；输出是自车坐标系下 8 个 waypoint ai​=(xi​,yi​,θi​)，覆盖 4 秒、频率 2 Hz。

  1. 视频专家。从 Wan2.2-5B 初始化的视频 DiT，连同它的视频 VAE 与 T5 文本编码器一起用。VAE 把每帧编成 latent token，导航指令经 T5 走 cross-attention 进来。当前帧作为干净条件，N=8 个未来帧加噪并用 flow matching 重建。这是一个标准视频生成目标，不引入任何驾驶专用的预测模块。
  2. 动作专家。一个隐藏维 1024 的轻量 DiT，条件为 c={z(ot​),st​,l}，自车状态经一个小 MLP 嵌入，预测轨迹速度场 vθa​。
  3. 隔离注意力掩码。共享 attention 流里有三种 token：当前观测 latent z(ot​)、未来帧 latent、动作 token。未来帧 token 与动作 token 都看得见 z(ot​)，但彼此互不可见。论文强调这是隔离动作 token 所需的唯一结构改动。因为动作分支从未依赖未来帧 token，训练完之后未来帧的 VAE 解码器可以直接丢弃。
  4. 联合训练。L=LFMact​+λLFMvid​，取 λ=1，AdamW + cosine，初始学习率 10−4，训练 100 个 epoch，分辨率 384×672。
  5. 强化学习。把确定性 ODE 换成保持边缘分布的 SDE，每个场景采 G=8 条候选轨迹，用 NAVSIM 的复合 PDM 奖励算组内相对优势做 clipped 更新。只更新动作专家 attention 投影上的 LoRA（rank 32，α=16，学习率 5×10−5），以保住蒸出来的运动先验。RL 只在模仿学习后 PDMS 低于 90 的困难 navtrain 场景上做，评测始终覆盖完整 navtest。

§ 6 — 核心数学推导 ​

flow matching 部分是标准的：给定干净目标 x 与噪声 ϵ，线性插值 xτ​=(1−τ)x+τϵ 的速度是常数 ϵ−x，网络回归它，LFM​=E∥vθ​(xτ​,τ,c)−(ϵ−x)∥22​；采样即从 τ=1 积分 dxτ​=vθ​dτ 到 τ=0。

真正需要解释的是 ODE 到 SDE 的改写。确定性 ODE 有两个对 RL 致命的缺陷：它对每个初始噪声只给一条轨迹，探索不了别的机动；它没有可解析的转移密度，因而没法算重要性采样比。论文沿用 Flow-GRPO 的构造：

dxτ​=[vθ​(xτ​,τ)+2τστ2​​(xτ​+(1−τ)vθ​(xτ​,τ))]dτ+στ​dw,στ​=a1−ττ​​

这个 SDE 的关键性质是保持与原 ODE 相同的边缘分布 pτ​(xτ​)——也就是说加进去的随机性不改变模型学到的轨迹分布，只是把「一条确定路径」变成「同一分布下的多次抽样」。每一步 Euler-Maruyama 于是给出各向同性高斯转移 πθ​(xτ−Δτ​∣xτ​)=N(μθ​,στ2​ΔτI)，对数似然可算，策略梯度就成立了。

评测指标本身也是一个乘法与加权的复合式：

PDMS=m∈{NC,DAC}∏​rm​×∑m∈{EP,TTC,C}​wm​∑m∈{EP,TTC,C}​wm​rm​​

无碰撞与可行驶区域合规是乘性惩罚因子，任一为零则总分归零；Ego Progress、TTC、Comfort 构成加权质量项。这个结构决定了策略的最优行为：先保证不撞不越界，然后在此约束下尽量多走。

§ 7 — 实验设计与结论 ​

主结果（NAVSIM navtest，12146 个场景，SimWAM 只用单目前视）：NC 98.4 / DAC 98.7 / EP 86.4 / TTC 95.5 / C 100.0 / PDMS 91.5。对照最强 VLM 规划器 SGDrive 91.1、ReCogDrive 90.8、ExploreVLA 90.4；世界模型一档 DriveWAM 90.1、DriveVLA-W0 90.2、DriveLaW 89.1、PWM 88.1、Epona 86.2；传统端到端 DiffusionDrive 88.1、UniAD 83.4。人类驾驶员的 PDMS 是 94.8。

分阶段贡献：action-only 86.6 → 加视频联合训练 90.3 → 加 RL 91.5。视频那一步的增益分布在所有子指标上（NC 97.6→98.7、DAC 95.7→98.0、TTC 92.6→95.9）；RL 那一步则几乎全部来自 EP（83.9→86.4），NC 与 TTC 反而各降了 0.3 与 0.4。

注意力掩码对比（这是全文最值得注意的一张表）：双向 90.2、动作看未来 90.1、隔离 90.3。三者差 0.2 分。论文的表述很克制：「在我们的设定下，把动作分支暴露给未来视频 token 没有可测量的收益」。

视频骨干可替换性：LTX-Video 88.7、Wan2.1-1.3B 90.2、Wan2.2-5B 90.3、Cosmos-Predict2.5 90.4（后者在驾驶视频上预训练过）。动作专家缩放：0.21B → 89.9，1.02B → 90.3。

未来视频目标的时间配置：4 帧覆盖 2 秒 → 89.9；4 帧覆盖 4 秒 → 90.2；8 帧覆盖 4 秒 → 90.3。论文的读法是时间跨度比帧密度重要。

采样步数与分辨率（A100 单卡实测延迟）：1 步 68.9 PDMS / 115 ms，5 步 90.1 / 297 ms，10 步 90.3 / 518 ms，20 步 90.2 / 968 ms；分辨率 192×352 为 88.9 / 509 ms，384×672 为 90.3 / 518 ms，768×1344 为 90.6 / 573 ms。

RL 的探索采样器：朴素随机扰动拿到 91.3 PDMS，其中 EP 高达 88.0 却把 NC 压到 97.7、TTC 压到 94.1；保边缘的 SDE 为 91.5，EP 86.4 但 NC/TTC 更好。RL 曲线在 15k 步达峰后两条都略微下降。

跨域：NAVSIM 训练的模型零样本上 nuScenes，平均碰撞率 0.04% 为全表最低，平均 L2 为 0.96 m（与 DriveWAM 持平，略逊于 DriveVA 的 0.84 m）。在 NVIDIA 的 PhysicalAI-Autonomous-Vehicles 上只用 65K 训练样本，3 秒 ADE/FDE 为 0.40 / 1.08，4 秒为 0.69 / 1.96，优于 DriveWAM（5B+8B）的 0.47 / 1.35 / 0.83 / 2.47 与 10B 的 Alpamayo-1.5。NAVSIM-v2 上 navhard EPDMS 37.6（Metis 32.2），navtest EPDMS 90.2——论文明确写明所有 NAVSIM-v2 实验都不含 RL。

§ 8 — Take-aways ​

5 句版：驾驶 WAM 的 imagine-then-act 把视频合成塞进了实时回路，而 SimWAM 用一张隔离注意力掩码在结构上保证动作分支从不依赖未来帧，于是推理期可以整条删掉；两个专家不共享任何参数、只经统一 attention 接口交互，因此视频骨干可换、动作专家可独立缩放；单目前视在 NAVSIM 上拿到 91.5 PDMS，视频联合训练贡献 +3.7，RL 再贡献 +1.2；掩码消融显示双向、单向、隔离三种连接方式的 PDMS 只差 0.2 分，说明让动作看见未来 token 本身没有收益；RL 的收益几乎全部来自 Ego Progress，而 NC 与 TTC 略有回落。

3 句版：Fast-WAM 说未来想象在推理期可省，SimWAM 用一张掩码把这件事变成结构保证而非经验观察。代价是训练期要多跑一个 5B 视频专家，收益是推理期零额外开销外加可替换的骨干。RL 阶段把 PDMS 本身当奖励，涨的是进度分。

1 句版：把未来关在训练期，用一张掩码上锁。

§ 9 — 最脆弱的假设 ​

RL 阶段的奖励函数与最终评测指标是同一个 PDMS，而 NAVSIM 是一个非反应式基准——周围交通参与者回放日志轨迹，不会对自车行为作出反应。

这个组合让 EP 这一项变得危险。PDMS 的结构是「不撞不越界」乘以「包含进度的加权项」，在非反应式世界里，多往前走一点几乎不会招致任何后果，因为对面的车不会因为你抢了半个车身而变线或急刹。于是策略梯度会稳定地把质量项往 EP 方向推，而论文的数据正好显示了这一点：RL 阶段 EP 从 83.9 涨到 86.4，NC 从 98.7 降到 98.4，TTC 从 95.9 降到 95.5。定性图也印证：作者说模仿模型「保守，在路口和窄街只前进一小段」，强化后「更果断地沿路线推进」。在非反应式评测里这叫改进，在真实交通里它叫什么取决于对方是否会让。

论文其实拥有验证这件事的工具——NAVSIM-v2 的 navhard 有带反应式交通体的第二阶段——但明确声明所有 NAVSIM-v2 实验都不含 RL。也就是说，唯一能检验「RL 学到的是驾驶质量还是指标形状」的场地，恰好被排除在 RL 的评测之外。这是一个可精确定位、且用现成资产就能补上的证据缺口，不是模糊的 limitation。

§ 10 — 最小复现实验 ​

验证视频联合训练的 +3.7 分究竟来自「交通动力学先验」还是来自「多一个辅助损失的正则效应」。代码与权重已开源（github.com/H-EmbodVis/SimWAM），navtrain 也是公开数据。

  • 数据：NAVSIM navtrain 的一个子集（不必全量 103288 个场景，取十分之一即可看出方向），评测用完整 navtest。
  • 实现：保持架构、掩码、λ、优化器全部不变，只替换 LFMvid​ 的目标。三个变体：(a) 原版真实未来帧；(b) 错配未来——用同 batch 内另一场景的未来帧；(c) 静止未来——把当前帧复制 8 份当目标。
  • 测量：navtest 的 PDMS 及五个子指标。
  • 判据：若 (b)(c) 仍能到 89.5 以上，那么增益主要来自「共享表示上多了一个重建型辅助任务」这一正则效应，「交通动力学先验迁移」这个解释就被削弱；若两者掉回 87 附近，论文的归因成立。顺带解决一个歧义——论文的 action-only 基线没写清是完全不含 Wan2.2 骨干，还是含骨干但不含视频损失；如果是前者，那 +3.7 分里混进了「换了个更强的预训练视觉编码器」这一项，必须先拆开。

§ 11 — 最强反例设计 ​

反例一：把 RL 模型丢进反应式评测。 这是成本最低、杀伤力最大的一击，因为两个 checkpoint（IL 与 IL+RL）和评测协议都现成。在 NAVSIM-v2 navhard 的两阶段协议上同时跑两个模型，重点看 Stage 2（周围车辆会响应自车）的 NC、TTC、DAC 与总 EPDMS。可预测的结果：RL 模型在 Stage 1 的 EP 更高，但 Stage 2 的 NC 与 TTC 相对 IL 模型下降，总 EPDMS 持平或更低。若真是这样，"RL 直接优化驾驶质量" 这句话就要改写成 "RL 直接优化的是非反应式假设下的 PDMS 形状"。论文当前给出的 navhard 37.6 不构成反驳，因为那是不含 RL 的模型。

反例二：削弱「world model」这个定位本身。 三条独立证据指向同一个方向：掩码消融里双向 90.2 与隔离 90.3 几乎无差；把视频骨干从 5B 的 Wan2.2 换成 1.3B 的 Wan2.1 只掉 0.1 分；未来目标从 8 帧减到 4 帧只掉 0.1 分。这些合起来支持一个替代解释——起作用的可能不是"世界模型"，而是"一个在大规模视频上预训练过的视觉骨干 + 一个多任务重建正则"。决定性的对照实验很简单：冻结 Wan2.2 只当特征提取器、完全不加视频损失，看 PDMS 落在 86.6 与 90.3 之间的哪个位置。论文没有报这一格，而它恰好是拆分「预训练权重的功劳」与「未来预测目标的功劳」的唯一位置。

一个尺度上的提醒：91.5 与 91.1（SGDrive）差 0.4 分，而论文未报多 seed 或置信区间；同时 1 步采样的 PDMS 是 68.9、10 步是 90.3、20 步是 90.2，说明推理超参对结果的影响远大于方法间差距，不同工作若采样预算不同则排序本身就不可比。

§ 12 — Follow-up Research Idea ​

驱动局限：LFMvid​ 对 8 个未来帧的每一个 latent token 一视同仁。但一段行车视频里绝大部分 latent 是静止的路面纹理、建筑和天空，与规划无关；真正携带交通动力学的是少数几个动态 agent 所在的区域。论文的表 8 已经隐约撞上这件事——时间跨度比帧密度重要，说明"监督什么"比"监督多少"更关键——但它止步于调时间配置。

新 framing：把未来视频损失从一个固定的重建目标，改造成一个被下游规划损失反向选择出来的目标。具体说，为每个未来 latent token 学一个监督权重，其学习信号不是重建误差，而是该 token 的视频梯度与动作梯度的对齐程度。等价的表述是：世界模型不该去预测整个未来，而该去预测那些改变规划决策的未来。这把「WAM 里的视频分支该学什么」从人工设计的问题变成一个可优化的问题，也顺带给出了 §11 里那个疑问的正面答案——如果学出来的权重确实集中在动态 agent 上，就说明起作用的是动力学而非泛泛的正则。

可借鉴的邻域工具：辅助任务权重的元学习（用梯度余弦相似度决定辅助损失的取舍，这一套在多任务学习里已经成熟）；influence function 用来估计单个训练信号对最终指标的贡献；以及同期 WAM 工作里手工版的先例——按 latent 距离分位数算出「发生变化」的掩码再加权，可以当作这个学习式权重的强基线与初始化。

第一个实验：先不改训练，只做诊断。在现成的 SimWAM checkpoint 上，逐 future latent token 计算 ∇ϕ​Lvid 与 ∇ϕ​Lact 在共享观测表示参数 ϕ 上的余弦相似度，把这个标量画回图像平面。关键判据是它是否与场景里的运动 agent 空间重合——若重合，第二步再把这个相似度作为权重回填进 LFMvid​ 重训，与均匀权重比 PDMS；若不重合而是均匀弥散，那么表 3 与表 4 暗示的"这只是个正则项"就得到了正面证实，这同样是一个值得写出来的结论。
