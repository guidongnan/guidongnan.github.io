RLinf-VLA: A Unified and Efficient Framework for Reinforcement Learning of Vision-Language-Action Models ​

项内容
arXiv2510.06710
提交日期2025-10-08
作者Hongzhi Zang, Mingjie Wei, Si Xu, Yongji Wu, Zhen Guo, Yuanqing Wang, Hao Lin, Peihong Wang, Liangzhi Shi, et al.
分类cs.RO
一句话把仿真器、VLA 架构与 RL 算法统一到一套接口下，用"混合 GPU 分配 + 细粒度流水线"消掉 rollout 阶段的 GPU 气泡，并在同一平台上给出 PPO/GRPO 在 VLA 上的一组可复用实操结论。

所属教程：通用具身智能

版本说明

arXiv abs 页给出的 HTML 版本是 v2（v1 提交于 2025-10-08，v2 修订于 2026-02-07），本文按 v2 全文撰写。论文 comments 注明这是 RLinf 团队报告的算法侧，系统层设计另见 arXiv:2509.15965。

§ 1 — 研究问题与重要性 ​

VLA 的 RL 后训练在 2025 年下半年集中爆发，但每篇论文都自带一套代码：不同的骨干、不同的算法、不同的仿真器、不同的评测协议。结果是没人能回答"PPO 和 GRPO 在 VLA 上到底谁更好""动作分块该怎么算优势"这类基础问题——因为任意两篇论文的数字都不可比。

第二个问题更工程但同样卡脖子。LLM 的 RL 里，rollout 只需要模型推理；VLA 的 rollout 里，仿真器和模型抢同一批 GPU。渲染、推理、训练三者交替，任何朴素的资源分配都会留下大量 GPU 空转。SimpleVLA-RL 直接沿用为 LLM 设计的 VeRL，缺的正是这一层针对具身场景的系统优化。

RLinf-VLA 同时做这两件事：给出统一接口（ManiSkill / LIBERO / RoboTwin × OpenVLA / OpenVLA-OFT × PPO / GRPO），以及一套 GPU 分配策略。它的价值不在于提出新算法，而在于第一次让"同一批消融在同一平台上跑完"成为可能。

§ 2 — 前人工作与不足 ​

算法侧。 GRAPE 用 DPO 对齐偏好；VLA-RL（2505.18719）用 PPO；SimpleVLA-RL（2509.09674）与 RIPT-VLA（2505.17016）用 GRPO 族的二值成功奖励；πRL​（2510.25889）首次把策略梯度用到流匹配模型上；π0.6∗​ 的 RECAP（2511.14759）训了一个二值价值函数。这些工作各自成立，但结论互相冲突：RL4VLA（2505.19789）的系统实验支持 PPO 而否定 GRPO，RIPT-VLA 却用 GRPO 同族的 RLOO 拿到很好的结果。没有统一平台，这类冲突无法被裁决。

系统侧。 SimpleVLA-RL 建立在 VeRL 之上，遵循的是 LLM 的 RL 范式：所有组件共享 GPU，靠 offload/onload 切换。这在 LLM 上合理（rollout 与训练交替发生，各自独占一段时间），在具身场景里却灾难——生成与仿真必须逐步交互，每一步都 offload/onload 的开销不可接受。

仿真器接口。 ManiSkill 是 GPU 并行的（仿真、渲染、推理全在 GPU），LIBERO 与 RoboTwin 是 CPU 并行的（GPU 只做渲染与推理）。二者的资源瓶颈完全不同，用同一套分配策略必然有一边吃亏。

§ 3 — 重建作者的思考路径 ​

把 VLA 的 RL pipeline 拆开看，只有三个组件：Generation（模型出动作）、Simulator（环境走一步）、Training（更新参数）。GPU 资源在 rollout 阶段（前两者）与优化阶段（后者）之间分配。

朴素方案有两种。Collocated：三者共享全部 GPU，靠 offload 切换——但 Generation 与 Simulator 必须逐步交互，频繁 offload 的代价不可接受，于是只能退化成"只在 rollout 首尾各切一次"，代价是两者互相等待时都占着显存不干活。Disaggregated：每个组件独占一块分区——但组件间有依赖，rollout 阶段训练分区完全空转。

两条路都不行，那就混合：让 Generation 与 Simulator 各占一部分 GPU，Training 用全部 GPU。这样至少 rollout 阶段两者能并行。但仍有气泡——Simulator 必须等 Generation 给出动作。解法是把一个仿真器实例切成 k 个子仿真器，做成流水线：S(1) 出观测送给 Generation 时，S(2) 同时在跑；a(1) 回到 S(1) 的同时，Generation 处理 o(2)。这就是 hybrid + fine-grained pipelining。

算法侧的设计选择也是从具身场景的特性推出来的。VLA 的动作是分块的，于是出现 LLM RL 里不存在的三级结构：Chunk → Atomic Action → Token。优势与对数似然各自可以在哪一级算？这直接派生出一组必须扫的消融。

§ 4 — 核心 Intuition ​

VLA 的 RL 和 LLM 的 RL 有一个结构性差异：仿真器要和模型抢 GPU，而且两者必须逐步交替。既然逐步交替，就把仿真器切成多个子实例做成流水线，让一个子实例算物理的时候另一个子实例的观测正在被模型推理，气泡就被填上了。算法侧同样受动作分块支配：优势和对数似然算在 chunk、atomic action 还是 token 这三级上，会给出不同的信用分配，而这个选择此前从未被系统地扫过。

§ 5 — 具体方法与完整 Pipeline ​

以 LIBERO 上用 OpenVLA-OFT 跑 GRPO 为例：

  1. 统一接口。仿真器侧屏蔽 ManiSkill（GPU 并行）与 LIBERO/RoboTwin（CPU 并行）的差异；模型侧支持单步动作（OpenVLA）与动作分块（OpenVLA-OFT），把单步视为块大小为 1；算法侧只需指定优势函数与损失函数两个函数即可换算法。微调用 LoRA。
  2. GPU 分配。三种模式可配：collocated（共享，仅 rollout 首尾 offload）、disaggregated（各占分区）、hybrid + 细粒度流水线（Generation 与 Simulator 分区，Training 用全部 GPU，仿真器切成 k 个子实例流水化）。
  3. 多粒度计算。优势可按 chunk 级（整块共享一个优势）或 action 级（块内每个原子动作各有优势）；对数似然可按 chunk / action / token 三级。表 II 给出支持的组合：chunk 级优势兼容三种对数似然，action 级优势不兼容 chunk 级对数似然。
  4. PPO 侧设计。Actor 与 Critic 共享参数，在语言模型部分挂一个轻量价值头；partial reset（子环境一终止立即重置）vs fixed episode length；chunk 级价值（标量）vs action 级价值（C 维向量）。
  5. GRPO 侧设计。Valid Action Mask（只用任务完成前的时间步）；按有效步数归一化损失，Tisucc​1​∑t​；success rate filter（丢弃全成功或全失败的组，借自 DAPO 的动态采样）。
  6. 训练与评测。LIBERO 上把 130 个任务合成一个统一模型训练（而非按套件各训一个），每任务 50 episode、三个随机种子；ManiSkill 25 个 pick-and-place 任务，OOD 协议沿用 RL4VLA，每子设定 256 episode；RoboTwin 6 个任务，训练用 1000 个固定随机场景种子，评测用 128 个未见种子。

§ 6 — 核心数学推导 ​

二值奖励下 GRPO 优势的闭式解。 设组大小 G、其中 k 条成功，奖励取 {0,1}。组均值 Rˉ=k/G，标准差 σ=k(G−k)​/G。于是

A^succ​=σ1−k/G​=kG−k​​,A^fail​=−G−kk​​.

优势只依赖成功计数 k，组内严格零和，且 1/σ 自动给稀有事件加权。k∈{0,G} 时 σ=0、优势无定义——这正是 success rate filter 存在的数学必要性，而不是一条工程经验。

轨迹长度归一化为什么有效。 论文的 GRPO 目标（式 12）在每条轨迹上乘 1/Tisucc​。把它和不归一化的版本对比：不归一化时，第 i 条轨迹对梯度的总权重是 Ti​A^i​；由于成功轨迹在首次成功处被 Valid Action Mask 截断、失败轨迹跑满时限，必有 Tfail​>Tsucc​，于是 ∑i​Ti​A^i​=0，系统性地偏向压低失败而非抬高成功。加上 1/Ti​ 之后每条轨迹的总权重恰好是 A^i​，零和性质被恢复。

这条推导有独立价值：RL4VLA（2505.19789）正是用这个机制解释它观察到的 GRPO 在 VLA 上失败，而 RLinf-VLA 的"w/ Norm"消融（图 11 显示归一化后成绩显著更高）在本质上就是该偏置的修正。它还给出一个可证伪的预言：在成功与失败轨迹长度分布相近的环境里，归一化应当无效——论文在 ManiSkill 上恰恰"没有观察到明确收益"，与预言一致。

动作分块带来的三级结构。 chunk 级对数似然 π(ct​∣ot​)=∏i=1C​π(at,i​∣ot​,at,:i−1​) 是 C 个原子动作条件概率之积，而每个原子动作又是 M 个维度 token 之积。取哪一级做重要性比值，直接决定比值的方差量级：token 级最细、方差最小但与优势的粒度最不匹配；chunk 级方差被 C×M 个因子放大。这是 LLM RL 里不存在的自由度。

§ 7 — 实验设计与结论 ​

性能。 ManiSkill（表 I(a)）：OpenVLA 基座 53.91（分布内）/39.10（OOD 均值）→ GRPO 84.38/75.15 → PPO 96.09/81.93；OpenVLA-OFT 基座 28.13/18.29 → GRPO 94.14/60.64 → PPO 97.66/77.05。PPO 在两个骨干上都稳定优于 GRPO，且训练更稳，这与 RL4VLA 的结论一致、与 SimpleVLA-RL 的选择相反。

LIBERO（表 I(b)，130 任务统一模型）：基座 50.20/51.61/49.40/11.90/42.67，Avg 42.09；RLinf-GRPO 99.67/98.93/98.32/93.55/98.12，Avg 98.11。可自行验算：基座的 Avg 恰好等于按任务数 (10,10,10,10,90) 加权的均值 42.088，而 RLinf-GRPO 行同口径算出 97.97、算术均值 97.72，两者都对不上表中的 98.11；不过 98.11−42.09=56.02 与正文的"平均提升 56.02%"完全吻合。另需注意，图 7(c) 描述 LIBERO 训练曲线"从约 73% 升到 98%、提升约 30%"，与表 I(b) 的基座 42.09 相差三十多个百分点，两处口径不一致。

RoboTwin（表 I(c)）：基座 75.78/10.15/20.31/9.37/3.13/28.13（均值 24.48）→ RLinf-GRPO 94.53/96.09/92.96/83.59/70.31/70.31（均值 84.63），差 60.15 个百分点；引言写的"平均提升 63.75%"无法从该表复原。摘要的"20–85%"实为逐任务的绝对百分点差（最小 Cup 的 18.75，最大 Hammer 的 85.94），不是相对提升。

效率。 ManiSkill 上 OpenVLA 用 hybrid(pipe=2) 在 8 卡上相对 disaggregated 基线快 1.88×，扩到更多卡仍保持 1.61–1.69×。但 LIBERO/RoboTwin 上流水线收益消失：OpenVLA-OFT 一次生成 15 步动作块，生成与执行的比例从 1:1 变成约 1:15，而 LIBERO 的 CPU 并行仿真器才是瓶颈，此时 collocated 与 hybrid(pipe=1) 反而更优。相对 SimpleVLA-RL 的 collocated 实现是 1.34–2.27×，作者归因于向量化环境替代多进程 worker、以及去掉冗余的 log-prob 重算。

算法实操结论。 (1) PPO 下 action 级价值估计一致优于 chunk 级（成功率更高、价值损失更低，ManiSkill 与 LIBERO-Goal 上一致）。(2) partial reset 显著优于固定回合长度——因为优化目标是 "success_once"。(3) GRPO 下轨迹长度归一化、valid action mask 在 LIBERO 上都有效且可叠加，但在 ManiSkill 上都看不到明确收益。(4) success rate filter 只在 OpenVLA + ManiSkill 上救回了 step 400 附近的崩塌，在另外两个设定上效果不明显。

全文没有真机实验。

§ 8 — Take-aways ​

5 句话版。 RLinf-VLA 把三个仿真器、两种 VLA 架构与两种 RL 算法统一到一套接口下，使 VLA 的 RL 消融第一次可以在同一平台上做。系统侧的核心是 hybrid GPU 分配 + 把仿真器切成子实例做细粒度流水线，在 GPU 并行的 ManiSkill 上带来 1.61–1.88× 加速，相对 SimpleVLA-RL 是 1.34–2.27×；但在 CPU 并行的 LIBERO 上流水线收益消失，说明"没有普适最优分配"本身就是结论。算法侧给出四条实操结论：action 级价值优于 chunk 级、partial reset 优于固定长度、轨迹长度归一化与 valid mask 在 LIBERO 有效但在 ManiSkill 无效、success filter 只在特定设定救崩塌。性能上 LIBERO 130 任务单一模型达 98.11%、RoboTwin 六任务 84.63%，且 PPO 在 ManiSkill 上一致优于 GRPO。全部结果在仿真中，无真机。

3 句话版。 VLA 的 RL 与 LLM 的 RL 的真正差别是"仿真器要和模型抢 GPU 且必须逐步交互"，这决定了资源分配策略必须随仿真器类型改变。统一平台的价值体现在它能同时给出 PPO>GRPO 和一组分块相关的实操结论。代价是所有 RL 增益都相对一个明显偏弱的 SFT 基座测得。

1 句话版。 这是一篇把 VLA 的 RL 从"每人一套脚本"推向"可比较的实验平台"的系统论文，其最有价值的产出是那四条互相冲突的消融结论，而非榜单数字。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：表 I 里的 "Base" 行可以代表 SFT 的合理水平，因此 RL 的增益就是 RL 的贡献。

LIBERO 上 OpenVLA-OFT 的基座平均只有 42.09，Long 一栏低至 11.90。作为参照，OpenVLA-OFT 原文在四套件上的平均约 97，Cross-Platform Scaling（2509.11480）实测复现为 95.3，VLA-Adapter（2509.09372）报 97.3。也就是说，RL 后的 98.11 与文献中只做 SFT 的成绩基本持平，而 56.02 个百分点的"提升"几乎全部来自基座异常低这一事实。论文给出的解释是它训练的是覆盖 130 个任务的单一统一模型（而非每套件一个），这确实会拉低基座——但正因如此，"RL 把 LIBERO 推到 98.11" 这句话不能与逐套件训练的文献数字并列。ManiSkill 的 OpenVLA-OFT 基座 28.13 同样远低于该模型的常规水平。

如果这条假设不成立，论文的算法结论（PPO vs GRPO、四条实操建议）仍然成立——它们都是同一基座下的内部比较，这是统一平台最扎实的部分。受影响的只是"20–85% 提升"这类跨文献的性能主张。

第二条脆弱性在系统侧：1.88× 的分母是作者自己构造的 naive disaggregated 基线，而不是任何外部框架。与外部框架（SimpleVLA-RL）的对比是 1.34–2.27×，且在 collocated 模式下测得。两个数字的参照系不同，摘要把它们并列容易被误读。

§ 10 — 最小复现实验 ​

一周内可做、且能直接检验 §9 的实验：把基座补齐，重跑同一套 RL。

  • 数据与模型：LIBERO-Long（当前基座最弱的一档，11.90）。按 OpenVLA-OFT 原文配方在该套件上单独 SFT 一个模型（公开配方，单机可跑），再用 RLinf-VLA 的 GRPO 配置做 RL。
  • 对照三条：(i) 130 任务统一 SFT 基座 + RL（论文设定，93.55）；(ii) 单套件 SFT 基座（预期 90+）不做 RL；(iii) 单套件 SFT 基座 + 同样的 RL。
  • 测量：三档的成功率，以及 RL 消耗的 GPU 小时。
  • 判据：若 (ii) 已接近 (i)，说明 LIBERO 上的 RL 增益主要是在补统一训练造成的欠拟合；若 (iii) 明显高于 (ii)，则 RL 在充分 SFT 之上仍有独立价值。这条实验只需一个套件，成本远低于复现全表，却能把"RL 的贡献"与"基座的欠训练"彻底分开。

同一周内可顺带做的第二个检查：在 ManiSkill 上统计成功轨迹与失败轨迹的长度分布。若二者接近，就验证了 §6 关于"轨迹长度归一化在 ManiSkill 无效"的机制解释。

§ 11 — 最强反例设计 ​

站在反对者立场，最有力的攻击是：这篇论文自称提供"公平比较的统一平台"，但它从未把自己的实现与外部实现在同一任务上做质量对比。

框架与 SimpleVLA-RL 的比较只出现在吞吐量上（1.34–2.27×），没有任何一张表回答"用 RLinf-VLA 训出来的策略是否与 SimpleVLA-RL 训出来的一样好"。这很重要，因为吞吐提升如果伴随实现差异（向量化环境、去掉 log-prob 重算、LoRA 配置），完全可能同时改变最终策略质量。一个统一平台若不能复现被它替代的那些实现的结果，"统一"就只是接口层面的。

同样的问题出现在算法结论上。"PPO 优于 GRPO"这一条只在 ManiSkill 上验证（LIBERO 与 RoboTwin 都只跑了 GRPO）。而 RL4VLA 给出的 GRPO 失败机制（截断导致的 ∑i​Ti​A^i​=0）恰好被本文的轨迹长度归一化修正了——那么在加了归一化的 GRPO 与 PPO 之间重比一次，结论是否还成立？表 I(a) 的 GRPO 行是否用了归一化，论文没有说明。这是一个成本很低、却可能翻转核心结论的对照。

判决性实验：在 ManiSkill 上跑 2×2——{PPO, GRPO} × {有/无轨迹长度归一化}，其余全部相同，三个种子。如果 GRPO+Norm 追平 PPO，那么"PPO 更适合 VLA"应改写为"GRPO 需要正确的长度归一化"，这对整个领域的意义远大于一个榜单数字。

§ 12 — Follow-up Research Idea ​

(a) 驱动它的局限：本文最有价值的发现其实是四条互相冲突的消融结论——同一个技巧在 LIBERO 上有效、在 ManiSkill 上无效。论文把它们并列成"实操建议"，但没有解释冲突从何而来。这意味着从业者仍然只能靠试。而这些冲突在 §6 里其实是可预测的：轨迹长度归一化的收益应当正比于成功/失败轨迹的长度差异；success filter 的收益应当正比于组内成功率落在 {0,1} 端点的频率；action 级 vs chunk 级价值的收益应当正比于块内奖励的时间异质性。

(b) 可借鉴的相邻工具：把 framing 从"给出实操建议"换成"给出可测的环境统计量 → 技巧收益的预测函数"。这在 AutoML 与算法选择（algorithm selection）领域是成熟范式：先定义一组廉价可测的 meta-feature，再学一个从 meta-feature 到"该用哪个配置"的映射。这里的 meta-feature 全部可以在第一轮 rollout 里免费算出：成功率分布的端点质量、成功/失败轨迹长度比、块内奖励方差、生成与仿真的耗时比。

(c) 第一个实验：在 RLinf-VLA 已支持的三个仿真器上，各取 3–4 个任务，先各跑 100 步 rollout 收集 meta-feature，再把 24=16 种技巧组合各跑一个短训练（比如 300 步）。用这批数据拟合"meta-feature → 各技巧的边际收益"的线性模型，并在留出的任务上检验它的预测。第一个要验证的具体预言就是 §6 给出的那条：ΔNorm​ 与 E[Tfail​]/E[Tsucc​]−1 正相关。如果这条关系在留出任务上成立，那么框架就可以从"三种模式随你配"进化到"看一眼你的环境统计量，自动配好"——这才是统一平台真正的杠杆点，也同样适用于 GPU 分配策略的自动选择。
