Loong: Generating Minute-level Long Videos with Autoregressive Language Models ​

项内容
arXiv2410.02757
提交日期2024-10-03（v2 修订于 2025-04-02）
作者Yuqing Wang, Tianwei Xiong, Daquan Zhou, Zhijie Lin, Yang Zhao, Bingyi Kang, Jiashi Feng, Xihui Liu
分类cs.CV
一句话把文本 token 与离散视频 token 拼成一条单向序列从零训 LLaMA 结构的解码器，用渐进短到长训练 + 早期帧损失加权解决长视频训练的损失失衡，再用「解码回像素再重新编码」消除因果 tokenizer 造成的续写分布漂移，从 10 秒外推到分钟级。

所属教程：自回归视频生成

§ 1 — 研究问题与重要性 ​

2024 年前后的视频生成基本停在几秒钟。要讲一个有内容的故事，需要的是分钟级、且在这一分钟里允许场景切换与大幅运动的视频。扩散路线当时的长视频方案（Gen-L-Video 的重叠片段聚合、FreeNoise 的噪声重排、StreamingT2V 的记忆块）都是在短片段生成器外面套一层拼接逻辑，长程一致性靠工程手段维持。

自回归 LLM 在文本上早就证明了长序列建模能力，也能训练在短序列上再外推到更长。把这套能力直接搬到视频上看起来顺理成章，但当时最好的 LLM 路线视频生成器（VideoPoet）也只能生成 2 秒高质量片段并迭代延展到 10 秒。本文要回答的问题很直接：到底是什么在拦着自回归语言模型生成长视频。这个问题重要，因为如果障碍只是工程细节，那么视频生成就能直接继承 LLM 这十年积累的长上下文、scaling、多模态统一等全部红利。

§ 2 — 前人工作与不足 ​

VideoPoet 是最接近的对照。它用预训练 T5 编码文本、对条件 token 用双向 attention、对视频 token 用因果 attention，能出 2 秒高质量片段并延展到 10 秒。这个设计的代价是它与 GPT 式的纯因果序列建模范式不一致，条件部分双向、生成部分单向的混合结构不便于把文本、视频、其他模态统一进同一条序列。

Phenaki 用 masked video transformer 生成可变长视频，走的是并行解码而非严格 next-token，长程一致性依赖 mask 调度。

LongVideoGAN / NUWA-XL / GAIA-1 分别用 GAN、diffusion-over-diffusion、世界模型做长视频，但都限定在特定域（人体、卡通、驾驶），开放域不适用。

StreamingT2V 是当时最强的开源长视频基线，建立在 Stable Video Diffusion 上，用记忆块维持外观。它的问题与所有「短片段 + 拼接」方案相同：模型本身从未在长序列上学过依赖关系。

论文没有把这些方法批评成「思路错了」，而是指出一个更朴素的事实：LLM 路线之所以没人做长视频，是因为直接在长视频上训根本训不出来，而这个失败原因此前没有被诊断清楚。

§ 3 — 重建作者的思考路径 ​

第一步是承认失败并去测量它。作者在 65 帧（10 秒，约 4356 token）视频上直接训练，然后按帧段画损失曲线，看到一个很干净的结构：第 1–17 帧的 token 损失明显高于第 18–65 帧，而第 50–65 帧的平均损失最小。这个现象有一个不需要新理论就能给出的解释——next-token prediction 训练时后面的帧能看到前面真值帧的 token，视频帧间冗余极大，于是预测后面帧几乎是抄写任务；预测第一帧却只能靠文本。

第二步是从这个观察推出后果。序列越长，容易 token 的数量增长越快，它们累加起来的损失压过少数难 token，梯度方向被简单任务主导，结果是早期帧质量崩坏——而早期帧崩了，整段视频就没救了。

第三步是想对策。既然问题是「难易 token 数量失衡」，就有两个正交的杠杆：让模型先在短序列上把难的部分学会（渐进短到长），以及在长序列阶段直接给难 token 加权（损失重加权）。

第四步是推理侧。训练只到 10 秒，要到 60 秒必须迭代续写。作者试了最自然的做法——直接拿上一段的 token 当条件——结果画质在训练长度之外急剧退化。诊断出来的原因是因果 tokenizer 的 token 错位：一段视频末尾 n 帧的 token 是在「前面所有帧都在」的上下文里编出来的，而新一段开头 n 帧的 token 在训练时是没有前文的，两者分布不同。于是解法就浮现了：把生成的 token 解码回像素，再重新编码一次，让条件 token 回到训练时的分布。

§ 4 — 核心 Intuition ​

长视频自回归训练的真正敌人是帧间冗余：它让后面的帧变成抄写题，海量简单 token 的损失淹没了少数真正困难的早期帧 token。先在短视频上把难题学会、再在长视频阶段给早期帧加权，就把梯度重新分配回该学的地方。推理侧的对应问题是因果 tokenizer 让「有前文的 token」和「无前文的 token」分布不同，把生成结果解码回像素再重编码一次即可把条件拉回训练分布。

§ 5 — 具体方法与完整 Pipeline ​

Tokenizer。复现 MAGVIT2 式的因果 3D CNN（单独处理首帧），空间下采样 8 倍、时间下采样 4 倍，总压缩率约 256；量化用 Clustering Vector Quantization（CVQ），比原始 VQ 的码本利用率更高，码本大小 8192，参数量 246M。一段 10 秒视频（65 帧，每帧 128×128）被压成 17×16×16 个离散 token。分辨率压到 128 是刻意的：用空间换时间跨度，高分辨率留给后处理。

序列格式。文本 token 与视频 token 拼成统一序列 s=[t;v]，全部使用因果 attention，不用预训练文本编码器。词表 = 32000 文本 + 8192 视频 + 10 特殊 token = 40202。

主干。LLaMA 架构，700M / 3B / 7B 三档，从零训练，不加载任何文本预训练权重。

三阶段训练。stage-1 在 100M 文本-图像对（从 CC12M 与 LAION-2B 过滤）上做文生图预训练 200k 步；stage-2 图像与 17 帧视频片段联合训练 200k 步，batch 512，视频数据来自 WebVid-10M 与从 HDVG 过滤的 5.5M 片段；stage-3 帧数提到 65（10 秒）继续联合训练 100k 步，batch 256，并在此阶段开启早期帧损失加权（λ=1.0）。三阶段都用 AdamW、基础学习率 1.0e-4、前 10000 步线性 warmup 后余弦退火。tokenizer 本身也按 1 → 17 → 65 帧渐进训练，分辨率固定 128，batch 64，400k 步。

推理，走一遍完整例子：给定一条文本 prompt，模型先自回归生成 65 帧的视频 token（图 4 中的 v1​–v9​）；取最后 5 帧解码回像素，再用 tokenizer 重新编码得到干净的条件 token（v7​–v9​）；把这些重编码 token 与文本 token 一起作为条件生成下一段（v10​–v13​）；重复直到目标长度。采样用 top-k，k=50；classifier-free guidance 比例 7.5。一分钟视频在这套设置下约 26112 个视频 token。最后用现成的超分与 refinement 模型做后处理，只提分辨率与细节，不改内容与运动。

§ 6 — 核心数学推导 ​

基础目标是视频 token 上的 next-token prediction 负对数似然

L=−i=1∑L​logp(vi​∣v<i​,t)

这里的关键不在公式本身，而在于 L 变大时各项的难度分布。因为相邻帧高度冗余，i 越靠后，v<i​ 中可直接复制的信息越多，−logp(vi​∣v<i​,t) 越小。总损失是这些项的和，于是 L 从 17 帧涨到 65 帧时，新增的几乎全是小项，但它们的数量足以让梯度方向被它们支配。

损失重加权就是对这个求和做分段处理：

Lweighted​=−(1+λ)i=1∑K​logp(vi​∣v<i​,t)−i=K+1∑L​logp(vi​∣v<i​,t)

K 是前 17 帧对应的 token 数，λ>0。这个式子朴素到几乎不像一个方法，但它正对着诊断出来的病因：既然早期 token 少而难，就把它们在梯度里的份额乘上 (1+λ)。论文取 λ=1.0，即早期帧权重翻倍。

§ 7 — 实验设计与结论 ​

模型规模是否 scaling？ 因为缺少通用的长视频 benchmark，作者自建了一个：从 WebVid 验证集取最长的 1000 段，各截成 27 秒（其中最短者的时长），指标用 FVD 与 CLIP(ViT-L/14) 算的 Video-Text Matching。在相同迭代数下，700M / 3B / 7B 的 FVD 为 633 / 572 / 432，VTM 为 21.5 / 22.8 / 24.1，两个指标都随规模单调改善。

短视频上是否有竞争力？ MSR-VTT 零样本、16 帧评测：Loong 的 FVD 是 274，仅次于 VideoPoet 的 213，好于 Show-1(538)、ModelScopeT2V(550)、MagicVideo(998)、CogVideo(1294)。CLIPSIM 方面 Loong 是 0.2903，低于 Show-1(0.3072) 与 VideoPoet(0.3049)。作者把 CLIPSIM 的劣势归因于从零训练、没有借用 T5 或 CLIP 的文本表示，这个解释合理但没有做消融验证。

训练策略的两项设计有用吗？ 这里的证据是定性的。图 5 对比直接长视频训练与渐进+加权训练在前 17 帧的生成结果，前者物体外观明显退化、结构信息大量丢失，后者保持完好。图 6 对比有无 token 重编码的续写，无重编码时续写段出现外观与内容的突变。这两项消融没有给出 FVD 或 VTM 数字，是本文实验部分最明显的缺口。

采样策略。 贪心解码（k=1）稳定但几乎静止，全词表多项式采样动态但质量差，k=50 折中。作者明确写出 k 越小运动越少。

长视频上是否赢过基线？ 用户研究：50 条 prompt 生成 1 分钟视频，与 StreamingT2V 双盲对比，收集 440 份回答，内容一致性胜率 0.83 对 0.125，图文匹配胜率 0.65 对 0.19。

§ 8 — Take-aways ​

5 句话版：直接在 65 帧视频上做 next-token prediction 训练会失败，原因是帧间冗余让后段 token 变成抄写题，其累加损失压过少数困难的早期帧 token 并主导梯度。对策是把训练拆成图像 → 17 帧 → 65 帧三阶段，并在最后阶段给前 17 帧的 token 损失乘上 (1+λ)，λ=1。推理侧的对应障碍是因果 tokenizer 使「带前文编码」与「无前文编码」的 token 分布不一致，解法是把生成结果解码回像素后重新编码再作为条件。整套系统在 128×128 上运行、由 LLaMA 结构从零训练、词表 40202、tokenizer 压缩率约 256，最终从 10 秒外推到分钟级。模型规模从 700M 到 7B，自建 27 秒 benchmark 上 FVD 从 633 降到 432，MSR-VTT 短视频 FVD 274 仅次于 VideoPoet。

3 句话版：长视频自回归训练的瓶颈是损失失衡而不是模型容量，渐进短到长加早期帧加权就能解决。续写时的画质崩坏源于因果 tokenizer 的分布错位，解码-重编码即可修复。两项修复合起来让一个从零训练的 LLaMA 式解码器生成出分钟级视频。

1 句话版：把长视频训练的难点定位成 token 难度分布失衡，并用两个极简的修正（损失加权 + token 重编码）把纯自回归路线推到分钟级。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：用户研究里的「content consistency」能代表长视频质量。论文自己在采样策略一节写明，k 越小生成越稳定、运动越少，k=1 时视频几乎静止。这意味着「一致性」这个维度存在一个平凡解——少动就赢。而 Loong 的对照方 StreamingT2V 建立在 SVD 上，两个系统的运动幅度先验并不相同。0.83 对 0.125 的胜率因此无法区分「Loong 的长程建模更好」与「Loong 在 k=50 下的运动幅度恰好更保守」。

论文为这条假设提供的证据是：图文匹配这一维 Loong 也赢（0.65 对 0.19），而静止视频通常拿不到高图文匹配。这个反驳有一定力量，但图文匹配由人评、prompt 只有 50 条、且两项评分来自同一批评测员的同一次对比，无法排除光环效应。真正缺的证据是一个运动幅度的客观测量（光流幅值、帧间差分能量之类）与一条平凡基线（把第一帧复制 60 秒）的得分。少了这两样，一致性优势的归因就是开放的。

§ 10 — 最小复现实验 ​

一周的版本不必复现 7B，也不必碰长视频训练。只验证论文的核心诊断：

  1. 拿任意开源离散视频 tokenizer（或自己训一个小的因果 3D VAE），把一批 65 帧、128×128 的视频编码成 token。
  2. 训一个 300M 级别的因果 Transformer 做 next-token prediction，按帧段记录平均损失（帧 1、帧 2–17、帧 18–49、帧 50–65 分别统计）。若复现出「早期帧损失显著高于末段」的结构，第一条诊断成立。
  3. 同一份数据、同一算力预算下跑两组：直接 65 帧训练 vs 先 17 帧再 65 帧 + 早期帧加权 λ=1。测两个量：前 17 帧的重建质量（对固定 prompt 生成后算 FVD 或 LPIPS），以及整段的 FVD。
  4. 必须加的对照：λ=0 但同样做渐进训练。论文把渐进训练与损失加权作为一个整体消融，没有拆开，所以「加权到底贡献了多少」目前是未知的。这一格恰好是最省事又最有信息量的实验。

判据：若 (3) 中改进主要来自渐进训练而 (4) 显示 λ 无差异，那么论文强调的损失重加权就是可有可无的，这个阴性结果本身值得报告。

§ 11 — 最强反例设计 ​

针对 token 重编码这一条设计攻击。论文对续写退化的诊断是「因果 tokenizer 造成条件 token 分布错位」，解法是解码后重编码。但同一现象还有一个更平凡的替代解释：重编码经过了一次有损的 decode-encode 往返，相当于对生成的 token 做了一次去噪投影，把累积的、离开真实 token 流形的误差拍回码本上的合法组合。若这个解释成立，那么重编码的收益与 tokenizer 的因果性无关，任何有损重量化都能达到同样效果。

具体反例实验：训练一个非因果（双向 3D 卷积、无因果 padding）的视频 tokenizer，其余设置照搬 Loong，再做续写。按论文的诊断，非因果 tokenizer 不存在「首 n 帧无前文」的问题，直接用上一段 token 续写应该不退化，重编码应当带来接近零的增益。若实测发现非因果 tokenizer 下重编码依然显著改善续写质量，那么原诊断被推翻，真正起作用的是量化投影而非分布对齐。

第二个可预测的失败条件：重编码只保留最后 5 帧作为条件，即条件窗口约 1.5 帧 token 深度。任何跨度超过这个窗口的语义（一个角色在第 10 秒出现、第 40 秒再出现）在结构上无法被传递。构造一批「实体反复出现」的 prompt（论文的 50 条 prompt 未针对这一点设计），Loong 应当可预测地失败，且失败与模型规模无关。

§ 12 — Follow-up Research Idea ​

驱动这个想法的局限：Loong 的续写记忆是一个固定长度的像素窗口（最后 5 帧），信息量恒定且与内容无关。无论这 5 帧里是一段静止的天空还是一个刚出场的角色，传给下一段的 token 预算完全一样。这与文本 LLM 形成鲜明反差——文本的上下文里，一个专有名词只占几个 token 却能携带跨越万字的约束。

新的 framing：把长视频自回归的上下文分成两条不同码率的通道，而不是一条统一的视频 token 流。低码率通道存「持久量」（实体身份、场景布局、光照方向），用极少的 token 表示、永不滑出窗口；高码率通道存「瞬时量」（当前运动状态），只保留最近若干帧并随时丢弃。这样长程一致性由低码率通道负责，而它的成本不随视频长度增长。

可借鉴的相邻领域工具：视频编码里的 I 帧/P 帧与 GOP 结构，本质上就是按持久性分配码率；以及语音领域的 residual vector quantization，天然给出分层码率的 token 流。

第一个实验：在 Loong 的 tokenizer 上加一路极窄的「场景码本」（比如每段视频 16 个 token，码本 1024），训练时用一个辅助目标强制它可预测同一视频后续片段的实体身份（用现成的检测/ReID 模型给伪标签）。推理时这 16 个 token 与文本 token 一起常驻上下文，永不被滑出。评测就用 §11 里那批「实体反复出现」的 prompt，测第 40 秒时角色与第 10 秒的身份相似度。若这条窄通道能在几乎不增加 token 预算的前提下显著提升跨段身份保持，就说明长视频的上下文应当按持久性分层，而不是按时间均匀截断。
