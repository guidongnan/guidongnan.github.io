A Survey on Vision-Language-Action Models: An Action Tokenization Perspective ​

项内容
arXiv2507.01925
提交日期2025-07-02
作者Yifan Zhong, Fengshuo Bai, Shaofei Cai, Xuchuan Huang, Zhang Chen, Xiaowei Zhang, Yuanfei Wang, Shaoyang Guo, Tianrui Guan, et al.（共 14 位，通讯 Yuanpei Chen / Yaodong Yang）
分类cs.RO
一句话把所有 VLA 统一成"一串 VLA 模块逐步生成 action token、信息逐级变得更可执行"的链式框架，并按 token 形态划出语言描述/代码/affordance/轨迹/目标状态/隐表征/原始动作/推理八类，逐类给出优劣、经验成果与趋势判断。

所属教程：通用具身智能

论文性质

这是一篇 70 页的综述（arXiv v1，5 张图、10 张汇编表），没有原创实验，也没有形式化数学。全文的贡献是一个统一框架 + 一套分类学 + 逐类的文献梳理与趋势判断。

§ 1 — 研究问题与重要性 ​

VLA 这个领域在两年内长出了形态极不一致的一堆系统：有的让 LLM 写 Python 调 API（Code as Policies），有的让 VLM 吐关键点（ReKep），有的生成一段未来视频再抽动作（UniPi），有的直接把 7 维动作离散成 token 接进语言模型（RT-2、OpenVLA），有的用流匹配头连续输出（π0​）。这些工作互相之间几乎无法比较：基准不同、本体不同、数据不同，连"输入输出接口"都不同。结果是新入场的人很难判断某个设计到底新在哪里，也很难判断某条路线的天花板在哪。

本文要解决的正是这个"缺少共同坐标系"的问题。作者的观察是：抛开表面差异，几乎所有 VLA 都可以写成同一件事——视觉与语言输入被一串模块反复处理，每个模块吐出一段"逐渐更接地、更可执行"的中间产物，直到最后一段可以直接送给控制器。他们把这些中间产物统一叫作 action token，并明确类比 LLM 里的 language token。有了这个坐标系，"VLA 的主要设计选择是什么"就有了一个具体答案：action token 的形态。这件事的价值不在于任何一个新数字，而在于它把一个靠直觉分类的领域变成了一个可以逐维度对照的领域。

§ 2 — 前人工作与不足 ​

已有的 VLA / 具身智能综述通常按两条轴组织：一条是应用域（操作、导航、驾驶），一条是模块功能（感知、规划、控制）。前者的问题是把技术上同构的工作切开——RT-Trajectory（操作）与 DriveVLM（驾驶）都在生成轨迹当中间量，却被分到互不相干的章节。后者的问题是端到端模型无法被安置：π0​ 里没有一个可以被叫作"规划器"的部件。

还有一类按训练范式分（模仿学习 / 强化学习 / 分层），这在动作表示已经统一的领域是合理的，但 VLA 恰恰是动作表示还没有收敛的阶段——同样是模仿学习，输出关键点和输出关节角是完全不同的两件事。

本文的定位就是补上这条缺失的轴。它没有否定已有综述的价值，而是指出：在动作表示尚未收敛之前，表示本身才是最有区分度的分类维度。这个判断本身是可以争论的（见 §11），但它至少是一个可证伪的立场。

§ 3 — 重建作者的思考路径 ​

不使用本文自身的结论，重建路径大致如下。第一步来自一个已有的经验事实：LLM 的成功很大程度上是"把一切转成 token 然后做 next-token 预测"这个统一接口带来的。第二步是观察 VLA 的现状——它已经在大量借用 LLM/VLM 的骨干，但动作侧的接口五花八门。于是自然会问：VLA 里有没有一个东西扮演了 language token 的角色？

第三步是关键的一跳：如果把"关键点""目标图像""子任务描述"这些看似异质的中间产物都视为 token，那它们的共同点是什么？答案是它们都是某个模块的输出、都携带动作相关信息、都会被下一个模块消费。这个抽象层次一旦定下来，就能观察到一个规律：这些 token 沿链条排列时，信息是单调地"变得更接地、更可执行"的——从"把茶泡好"到"拿起水壶"到"壶柄上的抓取点"到关节角。第四步是把这条链上的 token 按形态归类，八类就是这样归出来的。第五步是给每一类找出它成立的理由（哪个基础模型支持它）与失效的理由（表达力/延迟/数据），这直接产出了 Table 1。

§ 4 — 核心 Intuition ​

VLA 里真正被设计的东西不是网络结构，而是中间产物的形态。你选择让模型吐一句话、一段代码、一个像素坐标、一段轨迹、一张未来图，还是 7 个浮点数，就同时决定了三件事：哪个基础模型能帮你生成它、需要什么标注才能训它、以及它能表达多细的动作。这就是为什么 action token 是 VLA 的核心设计变量——它是"基础模型能力"与"物理可执行性"之间的那个接口，而不同 token 类型只是在这条接口上取了不同的折中点。

§ 5 — 具体方法与完整 Pipeline ​

用文中给的例子"泡茶"走一遍这个框架如何应用。

  • 识别 VLA 模块：作者的定义是"最大的可微子网络"与"不可微的功能单元"。以 VoxPoser 为例，LLM 是一个模块，VLM 是一个模块，运动规划算法也是一个模块（不可微，但仍算）。以 Hi Robot 为例，微调过的 PaliGemma 是一个模块，仿 π0​ 训练的低层 VLA 是另一个模块。
  • 识别 action token：模块之间传递的东西就是 token。VoxPoser 链条是"语言计划 → affordance map → 原始动作"；Hi Robot 链条是"语言计划 → 原始动作"。此外，模块内部语义上有意义的中间生成也算 token，这条扩展让端到端模型也能被纳入框架。
  • 按形态归类：八类的定义分别是——语言描述（从高层 language plan 到低层 language motion）、代码（可执行片段或伪代码）、affordance（关键点 / 包围盒 / 分割掩码 / 稠密 affordance map 四个子类）、轨迹（末端、物体或场景的时序空间状态序列）、目标状态（预测的未来图像 / 点云 / 视频片段）、隐表征（在大规模数据上专门预训练的动作相关潜向量序列）、原始动作（可直接执行的低层控制指令）、推理（显式描述决策过程的自然语言，作为元 token 增强其他任何 token 的生成）。
  • 逐类填表：每一章都有一张汇编表，除了常规的方法/年份/基准外，还有两列很有信息量的自定义维度——previous module 与 next module，即"这个 token 由什么生成、被什么消费"。这两列实际上把每篇工作在链条上的位置显式化了，是本文最实用的组织手段。
  • 汇总判断：Table 1 给出每类的优势、局限与"值得一提的经验成果"（例如 language plan 对应 π0.5​ 铺床、Hi Robot 做三明治；affordance-keypoint 对应 ReKep 倒茶；轨迹对应 RT-Trajectory 擦桌；目标状态对应 VPP 用移液管转移液体；隐表征对应 GO-1 叠短裤与 OmniJARVIS 在 Minecraft 挖钻石；原始动作对应 π0​ 叠衣服）。

§ 6 — 核心数学推导 ​

本文无形式化数学推导，跳过。全文没有出现过一个编号公式，所有判断以文字与汇编表形式给出。

§ 7 — 实验设计与结论 ​

综述没有原创实验，能被当作"证据"的是三样东西，逐一评估其强度。

汇编表（Tables 2–9）。 每类 token 一张，字段包含 previous/next module、数据来源、基准。这是全文最扎实的部分，因为它把"某个 token 由谁生成、被谁消费"这一维度显式列了出来，读者可以据此判断两篇工作是否真的同构。缺点是表里不含可比的性能数字——这是诚实的选择（跨基准数字本来就不可比），但也意味着分类学的判别力从未被定量检验。

Table 1 的"值得一提的经验成果"列。 作者用的是"做成了什么任务"而非"拿了多少分"，例如 language plan 对应"铺床""做三明治"。这是一种规避跨论文数字不可比的做法，代价是这一列几乎不可证伪：任务难度没有共同刻度，"铺床"与"倒茶"孰难无法判定。

趋势判断（§13）。 作者给出的核心结论是：未来不属于任何单一 token，而属于分层组合——顶层用 language plan 与 code 做长时程规划与逻辑控制，中层用 3D affordance + 轨迹建模 + 目标视频预测组成中间运动表示，底层用策略模块映射到原始动作；推理作为元 token 贯穿各层。同时明确把隐表征排除在推荐架构之外，理由是粒度、语义完备性与任务对齐三方面的训练难题尚未解决，而显式 token 更易训练、可检视、可控。这是全文最有立场的一段，也是最容易被后续工作证伪或证实的一段。

另外几条判断值得单独记下：语言 motion 因表达力不足不太可能成为主流，但 language plan 在任务分解上不可替代；代码的潜力取决于能否建成融合感知与动作原语的完整函数库；affordance（做什么）与轨迹（怎么做）之间正在形成互补，并可由世界模型预测的目标状态共同支撑；原始动作是端到端的理想形态但被数据量卡住——作者给了一个很具体的量级估计：OXE 数据集的 token 总量约为大规模语言语料的 1/200,000。

§ 8 — Take-aways ​

五句话版：这篇综述提出把所有 VLA 视为"一串模块产生一串 action token，信息逐级更可执行"的统一链条，并按 token 形态分为八类。核心论点是 VLA 之间的主要设计差异就在于 token 形态，因为它同时决定了哪个基础模型可用、需要什么标注、以及能表达多细的动作。作者逐类给出优劣（例如轨迹可从域外人类视频训练但 3D 表达力差；目标状态数据可扩展性强但生成质量与延迟是瓶颈；原始动作最少人工先验但被数据稀缺卡死），并判断未来是分层组合而非单一赢家。他们把隐表征排除在推荐架构外，理由是粒度与任务对齐的训练难题。全篇没有实验、没有公式，价值在于坐标系而非结论。

三句话版：VLA 的核心设计变量是中间表示的形态，不是网络结构。八类 token 各有明确的能力边界，未来大概率是顶层语言/代码、中层 affordance+轨迹+目标状态、底层原始动作的分层组合。全文最硬的一个数字是"机器人数据比语言语料少约五个数量级"，它解释了为什么端到端路线短期内走不通。

一句话版：把 VLA 当成 "action token 的自回归链"来看，整个领域的设计空间就塌成了一个可比较的坐标轴。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是框架层面的："VLA 模块与 action token 交替排列成一条链"这个抽象具有判别力。如果它不成立，那么八分类就不是对设计空间的划分，而只是对术语的重新命名，全文的组织价值随之坍塌。

它很可能不成立，有三条理由。第一，作者自己在 §13.2 明确写道，未来的 VLA agent"不应被线性架构所限制"，模块与 token 应当被自适应地调用与管理，形成双向、图结构的拓扑。也就是说，作者一边用链式抽象组织全文，一边预告这个抽象即将过期。第二，token 的定义被显式放宽到"模块内部语义上有意义的中间生成也算 action token"。这条扩展是为了容纳端到端模型，但它使定义几乎不可证伪——一个端到端网络的任何一层激活都可以被事后声称"语义上有意义"。第三，八类的容量极不均衡：原始动作这一类实际上吞掉了 π0​、RDT、GR00T N1、OpenVLA 等近两年绝大多数受关注的工作，而这些工作彼此的差异（动作头形态、预训练数据、跨本体对齐方式）远大于它们与"轨迹类"工作的差异。当一个分类轴上的某一格装下了半个领域时，这个轴的分辨率就已经不够用了。

论文为该假设提供的证据是 Figure 1 的两个案例（Hi Robot 与 VoxPoser）加上后续章节的文献覆盖度。这属于"存在性证明"——能找到很多例子被框架容纳，但从未检验框架排除了什么。缺的是一个反向测试：找出无法被自然地写成链式 token 序列的 VLA（例如带在线重规划的闭环系统、或动作与感知交织的隐式模型），并说明框架如何处理它们。

§ 10 — 最小复现实验 ​

综述无法"复现"，但它的核心 claim（token 形态是主要设计变量）是可以在一周内做一次最小检验的。

  • 设定：固定 LIBERO（四个套件）与一个固定的 VLM 骨干（例如 Qwen2.5-VL-3B）、固定演示数据与训练预算（相同 GPU 小时、相同步数）。
  • 实现三种 token 形态，其余全部相同：(a) 原始动作 chunk（离散化后 next-token 预测）；(b) 轨迹 token（预测末端在图像平面上的 2D 路径，再由一个固定的控制器跟随）；(c) 目标状态 token（预测 k 步后的目标图像，再由一个固定的逆动力学模型出动作）。
  • 测量：四个套件的成功率、每步延迟、以及在演示数量减半时的成功率降幅（数据效率）。
  • 判据：若三者的排序在四个套件上一致，且差距明显大于随机种子波动，则"token 形态是主要设计变量"在这一受控设定下成立；若排序随套件翻转、或差距落在种子噪声内，则说明在同骨干同数据条件下 token 形态并非主导因素，主导因素更可能是数据与本体匹配。这个实验的价值在于，它是把一个分类学主张转成实验主张的最小代价方案，而目前整个领域都没有做过。

§ 11 — 最强反例设计 ​

站在反对者立场，最有力的攻击是提出一条竞争的分类轴并论证它的预测力更强：监督信号的来源与规模（该 token 的训练标注从哪来、能扩到多大），而非 token 的形态。

论证如下。在"原始动作"这一格内部，π0​ 与 OpenVLA 的性能差距，主要由预训练数据量、本体覆盖与动作头形态决定，与"它们都用原始动作"这一共同点无关。跨格来看，VoxPoser（affordance）与 Code as Policies（代码）的真正差异是前者链条末端接了一个运动规划器、后者接了一组人工 API——即"下游消费者"决定了系统能力，而不是"token 长什么样"。作者自己设计的 previous/next module 两列恰恰指向这一点，却没有把它提升为分类轴。

更强的是本文自身的证据结构：Table 1 的局限列里，"数据稀缺""标注成本""延迟"这三条反复出现在不同 token 类型下——语言描述是延迟高、代码是依赖预定义 API、轨迹是缺 VLM 支持与语义、目标状态是生成质量与延迟、原始动作是数据稀缺。这说明约束更多来自监督与算力，而非表示形态本身。

可执行的反例实验：取 30 篇有公开数字的 VLA 工作，为每篇标注 (i) token 类型、(ii) 训练数据量级、(iii) 评测本体是否与训练本体同形、(iv) 是否使用了不可微的外部模块（规划器、抓取器、分割器）。用这四个变量分别拟合"相对同期基线的提升幅度"，比较各自的解释力。如果 (ii)+(iii) 的解释力显著高于 (i)，那么 token 分类学就是一个描述性而非预测性的框架——这不否定它的组织价值，但会推翻"token 形态是主要设计选择"这一核心断言。

§ 12 — Follow-up Research Idea ​

一个非增量的方向：把 action token 从分类学对象变成率失真意义下的可测量对象。

(a) 驱动它的局限：本文最大的遗憾是八类之间无法定量比较——Table 1 只能用"做成了什么任务"当经验成果，因为跨基准数字不可比。只要缺少一个共同刻度，"哪类 token 更好"就永远只能靠立场表态。而作者自己在类比 language token 时其实已经暗示了刻度的存在：语言 tokenizer 是可以按压缩率评价的。

(b) 可借鉴的相邻领域工具：信息论里的率失真理论与神经压缩里的任务导向编码。把每一类 action token 视为在观测-动作通道上的一个有损编码：码率 R = 该 token 每决策步携带的比特数（语言 plan 是几十比特、关键点是几十比特、目标图像是几千比特、原始动作 chunk 是几百比特），失真 D = 用一个固定的下游控制器消费该 token 时的闭环任务代价。这样八类 token 就落在同一张 R–D 平面上，"分层组合"的主张变成一个可验证的命题：不同层是否确实落在这条曲线的不同区段。

(c) 第一个实验长什么样：选一个有真值动作的多任务数据集（LIBERO 或 DROID 的子集），把同一批演示分别编码成五种 token（language motion、关键点、末端 2D 轨迹、目标图像、动作 chunk），用同一个小型解码控制器把每种 token 映射回动作，测量"每步比特数 vs 动作重建误差 vs 闭环成功率"三元组。第一步可以完全离线（只测重建误差），成本极低。如果不同 token 类型的点确实构成一条清晰的凸包络，那么就有了一个真正的坐标；如果它们散成一团，说明 token 形态与信息量并不对应，本文的分类轴就需要被更细的维度替代。这个方向的好处是：无论结论如何，它都把"该用哪种中间表示"从口味之争变成了可测量的工程选择。
