Routing Before Looking: Query-Adaptive Evidence Acquisition for Long-form Video Understanding ​

项内容
arXiv2608.20805
提交日期2026-08-21
作者Tianyue Wang, Xuying Wu, Yuxiang Ma, Ruiming Liang, Jiaxuan Kang, Yanchao Hao, Zheng Wei, Leigang Qu, Haiyun Guo, Jinqiao Wang
分类cs.CV
会议EMNLP 2026
一句话让同一批查询分别跑生成式与检索式两条轨迹，用胜负对比蒸馏出一份人类可读的路由 skill 文档，推理时不动模型参数、只靠这份 skill 加硬规则在 Global Browse / Temporal Ground / Semantic Retrieve 三个工具之间选路。

所属教程：长视频理解

本页依据 arxiv.org/e-print/2608.20805 取回的 LaTeX 源码撰写（acl_latex.tex 含全部正文、附录与表格）。方法在正文中名为 Route2Look，与标题的 "Routing Before Looking" 对应。

§ 1 — 研究问题与重要性 ​

长视频智能体的失配点在于：查询要什么证据，和系统怎么去取证据，这两件事没有对齐。作者按真实场景把查询分成三类：全局理解类（摘要、主题、片类）、显式时序类（问句里直接带时间戳或时间范围）、隐式时序类（相关证据的位置完全没有在问句里给出）。前两类的取证方式几乎是确定的；难的是第三类，模型得先推断"去哪儿找"，才谈得上"发生了什么"。

这个问题的重要性由一个 oracle 实验直接量化。在 LVBench 的一个子集上，如果能对每条查询完美地在"生成式"与"检索式"两种策略之间选择，准确率从 68.5%（最优单策略）升到 81.5%，绝对提升 13.0 个百分点。这不是渐进式的余量，而是说明策略选择本身就是一个和感知能力同量级的自由度。

§ 2 — 前人工作与不足 ​

查询无关的流水线是第一条线。一类做法是先全局扫描再逐步放大（VCA、VideoLucy、LongVT、FrameThinker、VideoARM 等）；另一类是预计算文本表示（稠密 caption、ASR、OCR）存进外部记忆再检索推理（VideoAgent、VideoTree、DrVideo、Mr.Video、DVD 等）。它们对所有查询套同一套流程，既可能在无关内容上白烧算力，也可能漏掉当前查询要的证据。

查询条件化的规划是第二条线（LVAgent、VideoExplorer、VideoSeek、LensWalk、EVA 等）。它们先根据查询做规划再感知，适应性明显更好。但作者指出它们仍然依赖单一主导策略：生成式路线自顶向下，根据查询与已有观测逐步生成候选时间区间，擅长从全局脉络或叙事逻辑推断，但对突发的、高度局部的事件不敏感；检索式路线自底向上，用 clip 级 embedding 并行召回语义相关区间，擅长抓局部显著证据，但处理长程因果链或需要整体叙事的问题时吃力。

技能自演化是本文借用的第三条线（Voyager、Reflexion、ExpeL、SkillWeaver、AutoSkill、EvoSkill、Trace2Skill）。这条线已经证明可以从轨迹中抽出可复用的技能，本文把它搬到长视频取证的路由决策上。

§ 3 — 重建作者的思考路径 ​

第一个观察是：如果两种策略真的互补，那么它们的成功集合应该有相当大的非重叠部分。作者用 oracle 分析把这个直觉钉死了——50.5% 的样本两种策略都能答对，13.0% 只有生成式能答对，18.0% 只有检索式能答对，18.5% 两种都答不对。18.5% 的双失败率说明单靠路由不可能解决全部问题，但 31% 的单边成功率说明路由确实有大空间。

第二个观察是：既然要在两个策略间选，最直接的监督信号不是"这条轨迹好不好"，而是"这两条轨迹里哪条更好"。单独总结一条轨迹得到的是描述，成对比较得到的才是偏好。这直接导出了 differential contrastive analysis 的设计。

第三个观察是关于载体。如果把路由学成一组网络权重，就需要训练、需要为每个底座重训。如果把它写成一份人类可读的 skill 文档，就能直接注入 prompt、跨底座复用、并且可以被人检查。代价是它不能被梯度优化，只能靠"提取 patch — 分层合并"这种符号化流程演化。

§ 4 — 核心 Intuition ​

隐式时序查询没有唯一正确的取证方式，但每一条查询都有一个更划算的取证方式，而这个偏好是可以从"同题双跑、比出胜负"里抽出来的、且能被写成自然语言规则的。既然如此，路由就不必是一个训练出来的分类器，它可以是一份文档。

§ 5 — 具体方法与完整 Pipeline ​

Route-Look-Memorize 循环。给定查询 Q 与时长 l 的视频 V，智能体 πθ​（全程冻结）迭代取证直到证据足够。每轮：Route 阶段产生路由推理 rt​ 并选工具 ut​；Look 阶段工具返回帧 Ft​，交由 VLM 做视觉检查、生成描述并判断是否构成有用证据，过滤无关片段后留下 Et​；Memorize 阶段维护两份记忆——context memory Mc​ 存完整交互历史 {(ri​,ui​,Ei​)}，working memory Mw​ 存当轮子任务的局部上下文，只有经过验证的证据才回写 Mc​。

三个工具。Global Browse 在全片均匀采帧提供整体脉络；Temporal Ground 在问句给定的时间区间内均匀采帧；Semantic Retrieve 对全片做查询感知的语义检索。

检索机制的四步。查询扩散：把 Qt​ 扩成一组子查询（改写、上层语义抽象、换视角、并入选项信息）以提高召回。多模态检索：视频切成 Nc​ 个不重叠 clip，si​[j]=cos(Φ(Qti​),Φ(cj​))。时序证据聚合：对所有子查询的相关性曲线逐元素取最大，sfused​[j]=maxi​si​[j]。自适应片段抽取：动态阈值 γret​=μ(sfused​)+α⋅σ(sfused​)，超阈的峰向两侧扩展成完整事件，按平均融合分排序取 top-K。

两阶段路由技能。Stage 1 在演化集 Devolve​ 上对每条隐式时序查询独立跑生成式轨迹 τgen（走 Global Browse）与检索式轨迹 τret（走 Semantic Retrieve）；按"准确优先、效率其次"的判据组成偏好对 (τ+,τ−)——答对的胜过答错的，同样答对则看帧数；对每个偏好对蒸馏出一个 skill patch pi​=(Triggeri​,Strategyi​,Lessoni​)；再做分层合并，按批送给 LLM 去重、以支持度高者化解冲突、把实例观察抽象成通则，直到 patch 数少于批大小。Stage 2 把最终 skill S∗ 注入三层路由策略：Layer 1 硬规则（显式时序走 Temporal Ground，全局理解走 Global Browse），Layer 2 用 skill 指导隐式时序查询选路，Layer 3 是 continue-or-stop 判据。

配置。默认 GPT-5 当智能体底座，LanguageBind 作多模态检索器、10 秒一个 clip，top-K=5，α=0.5，最大迭代 H=10；每次工具调用按 2 FPS 采样、单次最多 50 帧（API 限制）。演化集是从 CG-Bench 分层采样的 500 条，合并批大小 B=32。

一个具体例子。附录的技能可视化给了边界情形：在稳定的大远景里数人数，路由到生成式（粗略全局浏览即可）；数全片重复出现的相似动作，路由到检索式（需要高召回的候选搜索再局部核验）。同样是"计数"，取证方式相反。

§ 6 — 核心数学推导 ​

本文的形式化很轻，主要是把技能演化写成一个带优先级的选择准则。给定 skill S，准确率与帧效率分别为

P(S;πθ​,D)=∣D∣1​(Q,V,y∗)∈D∑​1[πθ​(Q,V;S)=y∗],C(S;πθ​,D)=∣D∣1​∑c(Q,V;S).

演化的目标是找到 S∗ 使 P(S∗)>P(S0​)，或在准确率持平时 C(S∗)<C(S0​)。这里 S0​ 代表单一固定策略。这条准则的实际含义是：帧数只在准确率打平时才起作用，因此整个系统在设计上就允许用更多帧换更高准确率——这一点在读表 tab:ablations 的帧数列时必须记住。

检索侧唯一的自由参数是阈值系数 α：γret​=μ+ασ 是一个随分数分布自适应的阈值，α 越大候选越少。取 max 而非取平均来融合子查询曲线，意味着只要任何一个改写命中，该时间位置就会被点亮，这是一个偏召回的设计。

§ 7 — 实验设计与结论 ​

第一个问题：端到端效果。 表 tab:main 覆盖三个基准，每个基准报 #Frames 与 Acc。LVBench（1,549 题 / 103 段小时级视频）：GPT-5 384 帧 60.1，DVD 8,074 帧 74.2，VideoSeek 92.3 帧 68.4，Route2Look 202.3 帧 75.4。VideoMME 长子集（900 题，平均 2,466 秒）：GPT-5 384 帧 67.9，VideoSeek 60.9 帧 70.1，Route2Look 126.6 帧 76.1。LongVideoBench 长切分（564 题 / 188 段，900–3,600 秒）：DVD 2,816 帧 68.6，VideoSeek 29.6 帧 73.5，Route2Look 168.7 帧 77.8。

第二个问题：收益集中在哪类查询。 按查询类型拆分（LVBench 上三类占比 1.6% / 16.0% / 82.4%），DVD 与 VideoSeek 都用 GPT-5 复现以对齐底座。全局理解类 Route2Look 92.0%，与 VideoSeek 持平、比 DVD 高 8.0；显式时序类从 VideoSeek 的 77.4% 升到 82.7%，平均只用 66.0 帧；隐式时序类 73.7%，比 VideoSeek 高 10.5、比 DVD 高 15.4。隐式时序既是最大类也是最难类。

第三个问题：路由本身值多少。 表 tab:ablations 在 LVBench 的 200 条分层子集上做（Acc / #Frames）：Generation-only 63.5 / 107.5；Retrieval-only 68.5 / 290.7；Random routing 65.8 / 196.8；Learned routing 但去掉差分对比 61.5 / 238.6；完整 Learned + Diff. Con. 70.0 / 244.9；Oracle 81.5 / 131.8。

这张表信息量很大。检索式比生成式高 5.0 点但多用 2.7 倍帧；随机路由落在两者之间，说明单纯混合无效；去掉差分对比后掉到 61.5，低于任何一种单策略，说明不做胜负对比而只做轨迹总结蒸馏出的 skill 会把智能体带偏；oracle 81.5 只用 131.8 帧，是学到的路由（244.9 帧）的一半多一点。

第四个问题：换底座还成立吗。 表 tab:backbone（LVBench）：固定 GPT-5 当 LLM 换 VLM，Qwen2.5-VL 41.0 / 317.7、Qwen3-VL 47.5 / 116.8、Qwen3.5-VL 54.5 / 156.2；固定 GPT-5 当 VLM 换 LLM，GPT-4o 45.5 / 300.8、GPT-4.1 58.0 / 282.1、GPT-5 70.0 / 244.9。推理更强的 LLM 同时提高准确率并降低帧数。

第五个问题：超参与成本。 表 tab:hyperparameter：演化集从 200 条扩到 500 条，准确率 67.0 → 70.0；合并批大小 B=32 最佳，200 条下 B=10 掉到 63.5、B=200 为 66.5，500 条下 B=200 掉到 64.0；K 从 5 降到 3 帧数从 249.5 降到 171.7 但准确率从 67.0 掉到 61.5。表 tab:tokens 报成本：GPT-5 基线 384 帧 / 83K token / 60.1，Route2Look 202.3 帧 / 72K token / 75.4，帧数降 47.3%。

§ 8 — Take-aways ​

5 句版：长视频取证不存在一种普适策略，oracle 分析显示生成式与检索式的成功集合有 31% 的非重叠部分，完美路由可以从 68.5% 拉到 81.5%。把路由技能写成人类可读的文档而非网络权重，使它可以跨底座复用并被人检查，代价是只能靠符号化的 patch 蒸馏与分层合并来演化。差分对比是这条路线的关键：去掉它之后蒸馏出的 skill 比不路由还差（61.5 对 68.5）。学到的路由拿到了 oracle 13.0 点空间里的 1.5 点（68.5 → 70.0），且是用更多帧换来的（290.7 → 244.9 只是相对检索式省，绝对帧数仍高于生成式的 107.5）。三个基准上的帧数（202.3 / 126.6 / 168.7）都明显高于 VideoSeek（92.3 / 60.9 / 29.6），"帧效率"这个措辞需要对照具体基线读。

3 句版：Route-Look-Memorize 三工具循环，路由技能从生成式与检索式轨迹的胜负对比中蒸馏，推理时冻结底座。LVBench 75.4 / VideoMME-Long 76.1 / LongVideoBench-Long 77.8，均为表内最优。但学到的路由与 oracle 之间仍有 11.5 点差距，且消融是在 200 条子集上做的，1.5 点差异约合 3 道题。

1 句版：把"用哪种方式去看"变成一个可学习、可读、可复用的决策，收益真实但目前只兑现了理论空间的一小部分。

§ 9 — 最脆弱的假设 ​

失败代价最大的一条是：从少量轨迹对里蒸馏出的自然语言 skill，能够稳定地把新查询映射到更优策略上。 这条假设撑起了整个 Stage 2，而论文自己的数字对它并不友好。

第一，收益的绝对幅度很小。表 tab:ablations 里学到的路由 70.0 对最优单策略 68.5，差 1.5 点；这张表跑在 200 条分层子集上，1.5 点约合 3 道题。论文全篇没有给出任何置信区间或多次运行的方差，而底座是 GPT-5 这样带采样随机性的模型。

第二，蒸馏过程本身是脆的。去掉差分对比后成绩掉到 61.5，比不做任何路由的生成式（63.5）和检索式（68.5）都低。这说明 skill 文档不是一个"锦上添花"的先验：只要蒸馏方式稍有偏差，它就会主动把智能体导向错误策略。一个只在正确配置下才有正收益、在近邻配置下就变成负收益的机制，其稳健性需要更强的证据。

第三，超参敏感度不小。合并批大小从 32 改成 200，在 500 条演化集下准确率从 70.0 掉到 64.0——比路由带来的全部收益还大。演化集从 200 扩到 500 带来 3.0 点，也大于路由相对最优单策略的 1.5 点。这些数字合起来说明：目前测到的"路由收益"与"蒸馏流程的超参噪声"处在同一量级。

论文缺失的证据是：同一份 skill 在多个随机种子下重复蒸馏后的方差，以及在完整 1,549 题 LVBench 上（而非 200 条子集上）的路由消融。

§ 10 — 最小复现实验 ​

一周内可做，不需要复现完整智能体：

  1. 取 LVBench 的 200 条分层子集与一个可用的强 LLM 底座，实现三个工具的最简版本（Global Browse 用均匀采样、Temporal Ground 用区间均匀采样、Semantic Retrieve 用 LanguageBind + 10 秒 clip + 论文的 γret​ 公式）。
  2. 对每条隐式时序查询各跑一次生成式与检索式轨迹，用 5 个不同随机种子重复，记录每条查询在每个种子下的对错。
  3. 计算两个量：单条查询的策略偏好在种子间的一致率（同一条查询是否稳定地偏向同一策略）；以及 oracle 准确率在种子间的方差。
  4. 判据：若偏好一致率低于 70%，那么"每条查询有一个可学的更优策略"这个前提在实例级就不成立，81.5% 的 oracle 上界主要是在噪声上取上包络，13.0 点的空间被高估。若一致率高于 85%，则本文的立论稳固，剩下的问题只是蒸馏方式不够好。

§ 11 — 最强反例设计 ​

第一重攻击针对 oracle 上界的定义方式。 论文的 oracle 是"对每条样本用真值选更优策略"，其结果 81.5% 恰好等于两个单策略成功集合的并集大小。当底座是采样式 LLM 时，一次运行的"成功"里包含相当比例的运气成分：一条题目在生成式下答对可能只是这一次采样恰好蒙对。把两个单策略各跑一次再取并集，会把双方的运气都算进上界。反驳实验很直接：每个策略各跑 5 次，把"成功"重新定义为多数次答对，再算并集。如果 oracle 从 81.5% 明显回落，而两个单策略的多数投票成绩上升，那么 13.0 点的"路由空间"里有一大块其实是采样方差，而不是策略互补性。论文没有做任何重复运行，这一格是缺失的。

第二重攻击针对"帧效率"的措辞。 正文写"achieves state-of-the-art performance while maintaining strong frame efficiency"，并强调在 LVBench 上只用了 DVD 的 2.5% 帧预算。但表 tab:main 同时显示 Route2Look 在三个基准上分别用了 202.3 / 126.6 / 168.7 帧，而 VideoSeek 只用 92.3 / 60.9 / 29.6 帧——在 LongVideoBench 上是 5.7 倍的差距。作者挑了帧数最夸张的 DVD（8,074 帧）作参照，对帧数最少的强基线避而不谈。最有力的反例是画一张 Accuracy-vs-#Frames 的 Pareto 图，把 VideoSeek 的帧预算逐步放大到 168.7 帧再测 LongVideoBench。若 VideoSeek 在同等帧预算下逼近 77.8，那么本文的增益应归因于"看得更多"而非"看得更准"。这一实验论文的 Limitations 里其实已经承认了动机（"Route2Look still requires moderate frame verification"），但没有做。

第三重攻击针对消融样本量。 全部核心消融（含 oracle、随机路由、去差分对比）都跑在 200 条子集上。1.5 点约合 3 道题，5.0 点约合 10 道题。任何结论若要成立，至少需要在完整 1,549 题上重跑 Learned 与 Retrieval-only 两行，并给出二项分布下的置信区间。若 70.0 与 68.5 的区间重叠，则"学到的路由优于最优单策略"这一核心主张在统计上未被证实，本文剩下的可靠贡献就只有 oracle 分析所揭示的问题空间。

§ 12 — Follow-up Research Idea ​

驱动它的局限：本文把路由建成"每条查询选一个主导策略"，而 oracle 分析里 18.5% 的样本两种策略都失败。作者在正文中也承认真实情况下同一条查询可能需要混合策略，所以 81.5% 只是一个"近似上界"。换句话说，二选一的动作空间本身就是天花板的一部分。

换一个 framing：把取证从"选策略"改写成"在证据不确定性下的序贯实验设计"。每一步不问"该用哪个工具"，而问"哪一次观测最能降低当前答案分布的熵"。三个工具就是三种代价不同、信息特性不同的观测算子：Global Browse 覆盖广但每处稀疏，Semantic Retrieve 精准但依赖 embedding 召回，Temporal Ground 只在有先验区间时可用。选择准则变成期望信息增益除以帧代价，停止准则变成边际增益低于阈值——这同时替换掉了 Layer 2 的 skill 和 Layer 3 的 continue-or-stop 启发式。

可借鉴的相邻领域工具：贝叶斯实验设计里的 expected information gain 估计，以及信息检索里的 anytime ranking——后者提供了在预算耗尽前随时给出当前最优答案的机制，正好对应 Layer 3 想做但用启发式做的事。

第一个实验长什么样：在完整 LVBench 上先做纯测量。对每条隐式时序查询，在每一轮工具调用前后记录底座对选项的概率分布，计算该次观测带来的实际熵下降，除以该次调用的帧数，得到"每帧信息增益"。先验证两件事：(a) 三个工具的每帧信息增益分布是否显著不同（若不同，说明信息论准则有可用信号）；(b) 用这个后验量做事后最优选路，准确率能否接近 81.5% 的 oracle。若能接近，则可以进一步训练一个只看查询与已有观测的轻量代理来预测每帧信息增益，把事后量变成事前量，从而绕开 skill 文档这条符号化蒸馏链。
