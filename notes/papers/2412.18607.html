DrivingGPT: Unifying Driving World Modeling and Planning with Multi-modal Autoregressive Transformers ​

项内容
arXiv2412.18607
提交日期2024-12-24
作者Yuntao Chen, Yuqi Wang, Zhaoxiang Zhang
分类cs.CV
一句话把前视图像的 VQ token 与逐帧相对位姿的分箱 token 交错成一门「驾驶语言」，用单个 Llama 式自回归 transformer 以 next-token prediction 同时学世界模型与端到端规划。

所属教程：世界模型

§ 1 — 研究问题与重要性 ​

驾驶世界模型和端到端规划这两件事，在 2024 年底基本是两条互不相通的技术路线。世界模型这边几乎全是 video diffusion：DriveDreamer、Drive-WM、Vista 都是在 Stable Video Diffusion 之类的底座上 fine-tune，把控制信号通过 cross-attention 或 AdaLN/FiLM 打进去。规划那边是 BEV 特征加轨迹解码头，UniAD、VAD、SparseDrive 都是这个范式。

问题在于：model-based planning 的完整闭环需要「用世界模型推演候选动作的后果，再挑一个动作」，而 diffusion 架构天生只擅长生成像素，不擅长同时吐出动作序列这类异构模态。作者的判断是，只要生成和规划分属两个模型、两套目标函数，可微分的 model-based planning 就永远拼不起来。这篇论文要回答的是：能不能把「预测未来观测」和「预测未来动作」写成同一个序列建模问题，用一个模型、一个损失训完。

§ 2 — 前人工作与不足 ​

GAIA-1 是最接近的先例，它已经用自回归 next-token predictor 建模驾驶视频，但外挂了一个 diffusion image decoder，且动作 token 用的是零位置编码，本质上把动作当作弱条件而非可预测的输出。其余主流工作如 DriveDreamer、Drive-WM、GenAD 都建立在 diffusion 上，视觉质量确实更好，但长视频的时序一致性一直不稳。作者在实验里给出了具体失败模式：SVD 在 navtrain 上 fine-tune 后生成长视频会「卡在红灯前反复重复历史内容」，还会出现物体突然凭空出现（红框）和逐渐消失（绿框）的 object hallucination——因为 diffusion 每个窗口的生成缺乏对更早历史的显式条件。

规划一侧的问题是另一个方向的。开环 benchmark 上的端到端规划已经被指出严重依赖 ego status 这类特权信息（Li et al. 2024），而 nuScenes 的驾驶动作分布过于平缓，模型只要复制历史动作就能拿到不错分数。这两件事叠加，使得「规划模型到底学没学会开车」难以判断。

§ 3 — 重建作者的思考路径 ​

把已有线索排一下：其一，LlamaGen、VAR、VideoPoet、Chameleon、Emu3 这批工作已经证明，把图像离散化成 VQ token 之后，标准语言模型架构 + next-token prediction 能做出高质量的图像与视频生成；其二，Decision Transformer 和 RT-1/RT-2 已经证明，把动作离散化成 token 塞进同一个序列，transformer 能学会决策；其三，POMDP 的形式化里，策略 π(at​∣ot​) 与观测转移 P(ot+1​∣ot​,at​) 本来就是同一条观测-动作交替序列上的两个条件分布。

三条线索交汇处只剩一个操作：把图像 token 和动作 token 按帧交错拼成一条序列，让 causal transformer 去预测下一个 token。这时世界建模是「给定历史预测图像 token」，规划是「给定当前及历史预测动作 token」，两者自动成为同一个交叉熵损失的子任务。真正需要解决的只剩工程细节——动作怎么量化、位置编码怎么给、上下文长度够不够。

§ 4 — 核心 Intuition ​

驾驶序列本来就是「看一眼、动一下、再看一眼」的交替结构，这和语言的 token 流同构。只要把观测和动作都变成 token 并共享同一个词表，世界模型与规划器就是同一个模型在不同位置上的两种预测行为，不需要额外的接口设计。让 diffusion 做不到这一点的，是它的输出空间被绑死在连续像素张量上；让自回归奏效的，是它对模态无差别——只要能离散化，就能进同一条序列。

§ 5 — 具体方法与完整 Pipeline ​

以 NAVSIM 上一个变道场景为例走一遍：

  • 输入：前视相机图像序列（原始 900×1600，resize 到 288×512）与自车轨迹。NAVSIM 用 12 帧（4 帧历史 + 8 帧未来）@2Hz，nuPlan 用 16 帧 @10Hz。
  • 观测 tokenization：VQ-VAE 把每帧压成 H/S×W/S 的离散 token，下采样率 8 或 16 分别对应每帧 2304 或 576 个 token，词表大小 16384。消融比较了 LlamaGen、OpenMAGVIT2、Cosmos Tokenizer 三个离散 tokenizer 后，选定 LlamaGen 的 VQ-VAE。
  • 动作 tokenization：关键设计是不预测绝对轨迹。若用 (Tt+1→t​,Tt+2→t​,…) 这种以 t 为原点的长时域轨迹，历史动作里已经包含了几乎全部未来信息，模型只需复制即可，学不到驾驶。因此改为逐帧相对位姿 (Tt+1→t​,Tt+2→t+1​,…)，每个动作分量 {x,y,θ} 先按 1st/99th 百分位截断再均匀分 128 箱，三个分量各用独立词表。
  • 序列与模型：序列形如 z1​,q1​,z2​,q2​,…，总词表 16384+3×128=16768。模型沿用 LlamaGen 结构（SwishGLU、Llama 的 FFN 维度），图像与动作 token 都加逐帧 1D rotary embedding。AdamW，lr 10−4，weight decay 5×10−2，梯度裁剪 1.0，token-level dropout 0.1，100k 迭代，总 batch 16。
  • 推理与解码：温度 1.0、top-k 2000 采样，并做 guided sampling——采样图像 token 时把动作词表的 logits 屏蔽掉，反之亦然，避免高温下串模态。长视频每次生成 16 帧、条件于前 8 帧。附录里再用一个 fine-tune 过的 SVD decoder 把 288×512 的 token 精修到 1024×576，做出 64 帧 / 32 秒的样例。
  • 输出：图像 token 经 VQ-VAE decoder 还原成视频；动作 token 反量化成 (xt​,yt​,θt​)，再连乘还原成绝对轨迹。

§ 6 — 核心数学推导 ​

问题被形式化为 POMDP：状态空间 S、动作空间 A、转移 P(st+1​∣st​,at​)、观测函数 Z(ot​∣st​)。目标是把策略 π(at​∣ot​) 与观测层转移 P(ot+1​∣ot​,at​) 统一。

动作量化：先截断 aˉt​=min(max(at​,a1st​),a99th​)，再分箱

qt​=⌊a99th​−a1st​aˉt​−a1st​​(M−1)⌋.

截断到百分位是为了让分箱分辨率不被极端值稀释；三个分量各自量化是因为 x,y,θ 的量纲和幅度完全不同。

训练目标就是标准交叉熵：

t∑​−logpθ​(xt​∣x<t​),x∈{z∪q}.

这一个式子里同时含有世界建模项 pθ​(zt​∣z<t​,q<t​) 与端到端驾驶项 pθ​(qt​∣z≤t​,q<t​)——两个任务不是被人为加权组合的，而是被序列的 causal 结构自动切分出来的。

轨迹还原用位姿连乘。单步相对位姿写成齐次矩阵

Tt+1→t​=​cosθt​sinθt​0​−sinθt​cosθt​0​xt​yt​1​​,

绝对位姿 Tt+k→t​=∏i=1k​Tt+i→t+i−1​。用相对量做 token、用连乘还原绝对量，是为了让每个 token 的数值范围随序列增长保持稳定。

§ 7 — 实验设计与结论 ​

问题一：自回归生成的驾驶视频能打过 diffusion 吗？ 在 navtest 上，未微调的 SVD（FVD 483.76 / FID 27.80）和 CogVideoX（848.87 / 31.78）都倾向于生成几乎静止的画面；在 navtrain 上微调过的 SVD 降到 227.54 / 24.03；从零训练的 DrivingGPT 达到 142.61 / 12.78。

问题二：长视频谁更稳？ 选 512 段超过 64 帧的 navtest 片段，SVD 的 FID 从 30.48 涨到 46.45、FVD 从 418.93 涨到 1079.28；DrivingGPT 是 15.04→20.45 与 278.11→506.95。退化幅度的差距比绝对值更能说明问题：自回归显式条件于历史 token，因此不会「忘掉」几秒前的场景。

问题三：规划够不够强？ NAVSIM 上刻意不使用 ego status。DrivingGPT PDMS 82.4（NC 98.9 / DAC 90.7 / TTC 94.9 / Comf. 95.6 / EP 79.7），高于同样只用前视图像、同样不用 ego status 的 ResNet-50 + MLP 基线的 77.8，以及 constant velocity 的 24.2。

问题四：它是真在开车还是在抄历史动作？ 把预测的动作分量逐个替换成「复制上一帧历史动作」：复制纵向 x 掉到 53.5，复制横向 y 掉到 79.4，复制航向 θ 掉到 73.1，全预测是 82.4。作者指出复制 x 掉得最狠是因为 NAVSIM 里有大量起步加速场景。这个消融是全文最有说服力的部分。

两个反直觉的结论。 其一，数据质量压过数量：NAVSIM 的 104k 条序列训出 82.4，nuPlan 均匀采样的 651k 条只有 74.6；作者的假设是常规驾驶里大量轨迹几乎没有动作变化、信息增益极低。其二，动作 token 必须加位置编码：只给图像 token 加 rotary embedding 时 PDMS 仅 65.3，两者都加是 82.4——这一项直接指出了 GAIA-1 式「动作零位置编码」的代价。

§ 8 — Take-aways ​

5 句话版。 论文把驾驶视频帧的 VQ token 与逐帧相对位姿的分箱 token 按帧交错，构造出一门统一词表 16768 的「多模态驾驶语言」。用 Llama 式 causal transformer 做标准 next-token prediction，世界建模与端到端规划自动成为同一个交叉熵的两个子任务。视频侧在 navtest 上 FVD 142.61 / FID 12.78 超过微调后的 SVD，且长视频退化明显更慢、无 object hallucination。规划侧在不用 ego status 的 NAVSIM 上 PDMS 82.4，超过 ResNet-50+MLP 基线的 77.8。消融显示动作 token 必须加 rotary 位置编码（65.3→82.4），且数据质量比数量更重要（104k 的 NAVSIM 打赢 651k 的 nuPlan）。

3 句话版。 用交错的图像/动作 token 把驾驶世界模型和规划统一成一个 next-token prediction 问题。单模型在视频生成和开环规划两侧都打过各自的强基线。逐帧相对位姿与动作位置编码是让这套方案真正跑起来的两个关键工程决策。

1 句话版。 驾驶可以当成一门语言来学，只要动作被正确地离散化并被当成一等公民放进序列。

§ 9 — 最脆弱的假设 ​

最致命的假设是：逐帧相对位姿的离散 token 足以承载规划所需的全部动作信息，且 8 帧未来动作的逐步自回归不会累积成灾难性误差。

论文自己承认，之所以不用长时域绝对轨迹，是因为那样会泄露特权信息让模型退化成复制。但换成逐帧相对量后，4 秒轨迹要靠 8 步连乘还原，每一步的量化误差（128 个箱）和采样随机性都会被乘进去。论文给出的证据是终点指标（PDMS 82.4）好，缺的证据是误差随预测步数的增长曲线——没有任何一张图展示第 1 步和第 8 步的位姿误差差异，也没有对比「一次性预测整条轨迹」的回归式 head。一旦这个假设在更长时域（比如 8 秒）或更激进的机动上失效，「统一序列建模」的卖点就只剩视频生成那一半。

另外，PDMS 只在 navmini 的 396 个场景上测，navtest 只有 136 个场景，样本量对于安全类指标偏小。

§ 10 — 最小复现实验 ​

一周内可做、不需要复现整套系统的验证：

  1. 拿现成的 LlamaGen VQ-VAE（不训 tokenizer），只在 NAVSIM navtrain 的 1,192 条序列上训一个小号（约 100M 参数）DrivingGPT，序列长度压到每帧 576 token（下采样率 16）。
  2. 测量对象只有一个：开环轨迹误差随预测步数 k=1..8 的变化。同时训一个结构完全相同、但把动作头换成「一次性回归 8 步绝对轨迹」的对照模型（图像部分保持自回归 token 预测不变）。
  3. 判据：如果自回归动作在 k≤3 上不劣于回归头、而在 k=8 上误差显著更大（比如 ADE 高出 30% 以上），说明误差累积确实是主要瓶颈，论文的终点指标掩盖了这一点；如果两者在 k=8 仍然接近，则支持论文的设计选择。
  4. 附加低成本对照：把动作词表从 128 箱降到 32 箱，看 PDMS 掉多少，直接量化「离散化损失」在总误差里的占比。

§ 11 — 最强反例设计 ​

最有力的攻击是给出一个替代解释：DrivingGPT 在 NAVSIM 上赢过 ResNet-50+MLP，可能主要来自 VQ-token 重建这个辅助任务提供的表征监督，而不是「世界建模与规划的联合学习」。

设计：训三个模型，(a) 完整 DrivingGPT；(b) 只预测动作 token、图像 token 只作为输入不计损失（即去掉世界建模目标，但保留完全相同的 transformer 与 token 化）；(c) 图像损失权重设为 0.1 的中间档。如果 (b) 的 PDMS 与 (a) 相差不大，那么「联合学习世界模型与规划」这一 claim 就失去了实验支撑——真正起作用的是把图像离散化后送进大 transformer 这件事本身。论文目前没有做这个消融。

另一类可预测失败的场景：夜间、雨雪、强逆光。VQ-VAE 在低信噪比图像上的重建质量会显著下降，而 DrivingGPT 的表征完全建立在「重建高度压缩的图像 token」之上（作者自己在正文中提到了这一点）。可以预期它在这些条件下相对 BEV 类规划器的优势会消失甚至反转。nuPlan 与 NAVSIM 的数据分布并不足以检验这一点。

§ 12 — Follow-up Research Idea ​

驱动局限。 这篇论文把世界模型和规划放进了同一个模型，但推理时仍然是「一路采样到底」——它从未真正使用世界模型去搜索。作者在结论里说这是「differentiable model-based planning 的垫脚石」，可垫脚石之上的那一步没人走。

新的 framing。 不要把动作 token 当成要被预测的东西，而把它当成要被搜索的东西：既然模型给出了 pθ​(qt​∣z≤t​) 和 pθ​(zt+1​∣z≤t​,qt​)，这正好是一棵可展开的树。可借鉴的相邻领域工具是 LLM 推理里的 speculative decoding 与 process reward model：用小模型快速展开多条动作分支，用一个在生成的未来 token 上打分的 critic（比如预测碰撞/越界概率的轻量 head）做剪枝，把 next-token sampling 换成 token 级的 beam search。这与「扩展到多相机」或「加一个 LiDAR 模块」这类增量改法不同，它改变的是模型被使用的方式。

第一个实验。 在 NAVSIM 上，固定训练好的 DrivingGPT 不动，仅在推理时对动作 token 做 beam width = 8 的搜索，评分函数用「模型对后续 2 帧图像 token 的平均 log-likelihood」这一零额外训练的代理奖励。如果 PDMS 从 82.4 有可测提升（尤其是 NC 与 DAC 两项），就证明这个模型的世界建模能力确实携带了规划可用的信息，而单纯的自回归采样在浪费它；如果没有提升，则说明图像 token 的似然与驾驶安全性几乎无关，这本身也是一个值得报告的负结果，会直接质疑「联合建模有益于规划」的整条叙事。
