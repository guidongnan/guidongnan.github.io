Think, then Score: Decoupled Reasoning and Scoring for Video Reward Modeling ​

项内容
arXiv2605.05922
提交日期2026-05-07（v2: 2026-05-12）
作者Yuan Wang, Ouxiang Li, Yulong Xu, Borui Liao, Jiajun Liang, Jinghan Li, Meng Wang, Xintao Wang, Pengfei Wan, Kuien Liu, Xiang Wang（中科大 / 快手可灵团队 / 中科院软件所）
分类cs.CV
一句话让 MLLM 先自由生成 CoT，再在其后追加一个可学习的 [Reward] token 由回归头输出标量分；推理用 GRPO 优化、打分用 BT loss 优化，把两者的梯度彻底分开。

所属教程：智能体视频生成

§ 1 — 研究问题与重要性 ​

视频生成的 post-training 与 test-time scaling 都以奖励模型为地基，奖励模型的质量直接决定优化的天花板。论文要解决的是奖励模型自身的两难：判别式模型直接从 MLLM 特征回归标量，用 BT 或 MSE 损失，梯度稳定，但没有显式推理，只能从粗粒度偏好标签反推细粒度语义差异，容易学到捷径特征，要靠堆数据才能泛化；生成式模型先写 CoT 再给分，语义监督细、可解释、泛化潜力更好，但推理与打分被绑在同一条自回归采样链上，优化极不稳定。

这个问题重要，是因为奖励模型的失效模式与生成模型不同：生成模型出错人眼能看见，奖励模型出错会被后训练悄悄放大成系统性偏差。而且分布外泛化在这里是刚需——今天训练用某几个 T2V 模型的产物，明天要评的是下一代模型。

§ 2 — 前人工作与不足 ​

判别式一侧是 VideoScore（MSE）与 VideoAlign（BT）。训练信号稳定，但缺少显式理由会让模型去拟合排序而不是学"为什么好"，补救办法只有扩数据，代价高且对 OOD 场景适应差。

生成式一侧，早期的 VisionReward、UnifiedReward 直接生成分数 token，仍缺推理；后来 UnifiedReward-Thinking、VideoScore2 引入 CoT，走 SFT 加 GRPO 两段式。RewardDance 一类用 token 概率当奖励，但依赖参考视频或成对比较，实用性受限。

作者对生成式路线的批评拆得很细并在附录给了论证。其一，缺少对奖励值的直接优化：把分数当离散 token，交叉熵把不同分数视为正交类别，把 5 预测成 4 与预测成 1 受到的惩罚相近，完全忽略序数距离；到了 RL 阶段策略梯度只压低次优 token 的概率质量，不指示误差的符号，模型不知道该往上调还是往下调。其二，信度分配困难：整条序列共享一个 rollout 奖励，无法区分是中间推理差还是最终分数错。其三，策略梯度方差高，直接导致训练震荡。

§ 3 — 重建作者的思考路径 ​

出发点是两个可观测现象。图 1(b)：加了 CoT 的生成式模型偏好准确率高于判别式模型，说明显式思考对泛化确实必要。图 1(c)：用 BT loss 的判别式训练曲线平滑收敛，而把最终分数交给 GRPO 优化的曲线明显震荡。

并排放在一起，问题变成一个清楚的设计题：能不能保留 CoT 带来的语义监督，同时让最终那个标量不经过采样链？ 答案几乎是被逼出来的——既然标量分不必是 token，那就别让它是 token。让 MLLM 照常生成 CoT，然后在序列末尾挂一个可学习的查询 token，用它的隐状态过回归头出分。CoT 仍然进入上下文并影响打分，但打分本身可以用 BT loss 直接监督，梯度不再穿过离散采样。

再往下一步，新的风险是打分模块可能只读 CoT 不看画面——如果 CoT 说"主体正确、动作合理"，回归头完全可以照抄结论。于是需要在训练时随机把 CoT 抹掉，逼它同时依赖原始输入。

§ 4 — 核心 Intuition ​

奖励模型需要 CoT 来获得细粒度语义监督，但不需要让最终分数从 CoT 的 token 空间里长出来。把标量分从采样链上摘下来挂到独立回归头上，就能同时拿到 CoT 的泛化性与 BT loss 那种带方向、带自适应步长的确定性梯度。剩下的唯一风险是回归头偷懒只读文字，用随机丢弃 CoT 来堵。

§ 5 — 具体方法与完整 Pipeline ​

数据。 先给真实视频写 caption，再拿这些 caption 当 prompt 驱动 Gen-2、Pika 1.0、PixVerse v1/v2、Dreamina、Luma、Gen-3、Kling 生成视频对。人工标注者沿主体、动态、环境、风格、镜头运动五个维度比较，得到 2.2 万训练对与 1469 对同分布评测对。两阶段的 CoT 来源不同：冷启动用 Qwen3-VL-8B 生成（这一阶段只求激活打分模块），RL 阶段用 Gemini-2.5-Pro 生成带子维度分数的高质量 CoT。两阶段都做一致性过滤，只保留 CoT 隐含偏好与人工标签一致的样本。

推理流程。 给定视频 v 与 prompt c，Qwen3-VL-8B 先生成 CoT o。按附录里的指令，模型要先从 prompt 推出金标准视觉预期（抽象词如"孤独""电影感"要转成暗光、浅景深这类可验证指标），再客观描述实际看到的内容，最后在五个子维度上给 0、1、2 分。然后拼成 X=(v,c,o,[Reward])，取 [Reward] 的末层隐状态过回归头得标量分。

训练两阶段。 阶段一判别式冷启动：在预收集的 CoT 数据上用 BT loss 联合微调骨干与打分模块（LoRA rank 64、AdamW、学习率 2e-6、2 个 epoch、batch 32），训练时以概率 p 遮蔽整段 CoT，此时分数只能来自原始输入。阶段二双目标 RL：GRPO 提升 CoT 质量，辅助 BT loss 持续校准打分模块，总损失 Ltotal​=LGRPO​+αLBTaux​，α=0.005。RL 跑 65 步，组大小 G=8，rollout batch 128，视频统一 2 fps，8 张 A800。

§ 6 — 核心数学推导 ​

BT loss 为什么好用。 目标为 LBT​=−E[logσ(sw​−sl​)]，对两个分数求导得

∂sw​∂LBT​​=−(1−σ(sw​−sl​)),∂sl​∂LBT​​=1−σ(sw​−sl​)

这是一对方向确定的推拉力，力度正比于当前 margin 误差：难样本（sw​≈sl​）梯度大，易样本（sw​≫sl​）梯度自动衰减，等于自带课程学习。对比之下，把分数当 token 时策略梯度形如 g^​∝A⋅∇θ​logπθ​(s∣q^​,o)，只压概率不给方向，模型只能在离散 token 空间盲搜。

GRPO 方差随长度线性增长。 令 st​=∇θ​logπθ​(ot​∣q^​,o<t​)，由 score function 恒等式 E[st​∣Ht−1​]=∇θ​1=0 知 {st​} 是鞅差序列，交叉协方差恒为零，于是

Var[S]=t=1∑T​Var[st​]≥T⋅G0​,G0​≜tmin​E[∥st​∥2]>0

再由组内 z-score 归一化有 E[A^2]=1，得 Var[g^​GRPO​]∝Var[S]=Ω(T)。结论是 CoT 越长梯度方差越大；作者指出 clipping 只是拿偏差换方差，不解决 Ω(T) 的增长。这条定理正是"最终分数不该活在采样链里"的理论依据。

GRPO 的复合奖励 R=λ1​Rfmt​+λ2​Rqual​+λ3​Rlen​：格式奖励要求严格遵守 <think></think> 结构并输出 JSON 子维度分，质量奖励是子维度分正确率 Ncorrect​/Ntotal​，长度奖励为

Rlen​(ℓ)=⎩⎨⎧​0,0.2⌊ℓ/500⌋,1,​ℓ<500500≤ℓ<2000ℓ≥2000​

它单调不减，只惩罚过短不惩罚过长（正文说要抑制冗长，公式并没做到），而更长的 CoT 恰恰意味着更大的 Var[g^​]。这是我从公式与定理并读得出的推断，论文未讨论。

§ 7 — 实验设计与结论 ​

解耦是否带来更好的泛化？ 同分布的 1469 对上 DeScore 拿到 0.734，高于最强判别式 VideoAlign 的 0.642 与最强生成式 VideoScore2 的 0.617。两个 OOD 集：GenAI（1.9k 对早期 T2V，约 320×512、2 到 2.5 秒）的 Acc w/o Tie 为 0.765；VideoGen-Bench（26.5k 对、12 个模型、至 576×1024、4 到 6 秒）为 0.768，显著高于 VideoAlign 的 0.722 与最好的生成式基线 0.582。唯一被超过的是 GenAI 的 Acc w/ Tie，UnifiedReward-Thinking 0.548 对 DeScore 0.504，作者已承认。数据效率上作者称超过 SOTA 的同时训练数据减少 76%。

两阶段组件各贡献多少？ 阶段一很干净：不加 CoT 的纯判别版本同分布 0.588；加 CoT 到 0.615（GenAI w/o Tie 0.585 到 0.636，VideoGen 0.589 到 0.654）；再加随机遮蔽到 0.656（0.685 与 0.672）。阶段二更有意思：只用 GRPO、不加辅助 BT loss 时 VideoGen-Bench 的 Acc w/o Tie 从 0.768 崩到 0.648，作者归因为奖励漂移——GRPO 只管推理质量，打分模块失去校准；反过来，不做冷启动只用双目标 RL 也能拿 0.741。

能否真的改善生成？ 接进 Longcat-GRPO 与 Flow-DPO 两套后训练框架，基座 Wan-2.1-1.3B，在 VBench 上评。相对基线（SC 0.951 / BC 0.961 / AQ 0.547 / IQ 0.669 / DD 0.527），Longcat-GRPO 版本到 0.969 / 0.973 / 0.645 / 0.706 / 0.541，Flow-DPO 版本到 0.969 / 0.972 / 0.615 / 0.700 / 0.542，五项全涨。需要指出表 3 的标题写的是"不同奖励模型的比较"，但表内只有基线与两个装配 DeScore 的版本，没有任何一个替换成其他奖励模型的对照，因此只能支持"用了比不用好"。作者在附录 I 承认 DeScore 主要评估文本忠实度，对运动不合理与视觉伪影可能不敏感。

§ 8 — Take-aways ​

五句话版。 DeScore 指出生成式视频奖励模型的根本问题是推理与打分被绑在同一条自回归链上，并给出三条后果：分数作为离散 token 缺少序数方向、整条序列共享奖励导致信度分配困难、GRPO 梯度方差随序列长度 Ω(T) 增长（论文给了证明）。解法是结构性解耦：照常生成 CoT，末尾挂一个可学习的 [Reward] token 由回归头输出标量分，因而可用 BT loss 直接监督。训练分两阶段，冷启动用 BT loss 并随机遮蔽 CoT 以防打分模块只读文字，RL 阶段用 GRPO 优化推理、辅助 BT loss 校准分数。在同分布与两个 OOD 榜上全面领先（0.734、0.765、0.768），训练数据减少 76%，去掉辅助 BT loss 后 VideoGen-Bench 从 0.768 掉到 0.648。接入两套后训练框架后 VBench 五项全涨，但该实验缺少其他奖励模型的对照。

三句话版。 最终奖励不该活在采样链里：把标量分摘出来用 BT loss 直接优化，就同时拿到了 CoT 的泛化与判别式的稳定。随机遮蔽 CoT 是关键细节，它逼打分模块看画面而不是抄推理结论。理论侧给出 GRPO 梯度方差 Ω(T) 的证明，为整个设计提供依据。

一句话版。 让模型先想再打分，但打分那一步不走 token 生成，而走一个用 BT loss 直接监督的回归头。

§ 9 — 最脆弱的假设 ​

最脆弱的是：推理阶段生成的 CoT 真的为最终标量分提供了增量信息。全篇的 framing 是保留 CoT 的泛化收益，如果 CoT 在推理时其实可有可无，DeScore 就退化成一个被 CoT 数据正则化过的判别式奖励模型，think-then-score 这个范式主张失去大半。

为什么可能不成立？随机遮蔽机制明确地训练打分模块在没有 CoT 时也能给分，即模型被要求学会一条不依赖 CoT 的通路。一旦这条通路足够强，CoT 在推理时的边际贡献就可能很小。

证据两头都有。支持的一侧：阶段一加 CoT 使同分布准确率从 0.588 升到 0.615，OOD 涨 5 到 6 个点。指向相反方向的：再加随机遮蔽（也就是主动降低对 CoT 的依赖）又涨了 4.1 个点到 0.656，涨幅大于加 CoT 本身的 2.7 个点；附录 H.1 的注意力可视化也显示遮蔽让 [Reward] token 把注意力从纯推理 token 分散到多模态输入上，而这被作者认定为性能更好的原因。换句话说模型越少依赖 CoT，分数越准。缺的关键证据是一个很容易做的对照：推理时把 CoT 去掉，看准确率掉多少，论文没有报告这个数字。

§ 10 — 最小复现实验 ​

只需复现阶段一，不必碰 RL。

  • 数据：从公开偏好数据或作者释出的数据取 5000 对训练、1000 对评测。
  • 实现：Qwen3-VL-8B 加 [Reward] token 加回归头，LoRA rank 64，按阶段一配置训三个版本：无 CoT；有 CoT 且遮蔽概率 p=0；有 CoT 且 p=0.5。
  • 测量：对后两个版本各做三种推理——正常 CoT、空 CoT、以及从另一段视频错配过来的 CoT，分别报偏好准确率。
  • 判据：若 p=0.5 的版本在空 CoT 下与正常 CoT 相差不到一个百分点，说明推理阶段的 CoT 基本是装饰性的，范式主张需弱化为"CoT 是有效的训练期正则"；若错配 CoT 显著掉分而空 CoT 只小幅下降，说明 CoT 提供的是真实但可替代的信息；若空 CoT 大幅掉分，则论文假设成立。

§ 11 — 最强反例设计 ​

最有力的攻击是质疑"OOD 泛化"这个标签的成色。DeScore 的训练视频来自 Gen-2、Pika 1.0、PixVerse、Dreamina、Luma、Gen-3、Kling，而 GenAI 被描述为 10 个早期 T2V 模型生成的低分辨率短视频，两个集合在生成器家族上大概率高度重叠，那么 GenAI 更像换了一批 prompt 而非换了一个分布。更关键的是评测口径：VideoGen-Bench 上报告的是 Text Alignment 子分，而 DeScore 的训练标签本身就完全建立在对文本 prompt 的语义忠实度上，这是在它的主场比赛；VideoAlign 这类多头模型的 TA 子分只是其整体能力的一个切片。

具体实验：构造一个真正的分布外集合，视频全部来自训练集中不含的新一代生成器，且偏好标签不以文本对齐为主而以运动合理性与视觉伪影为主（作者在附录 I 已承认这是盲区），同时把所有基线换成综合分而非 TA 子分。预测是 DeScore 相对 VideoAlign 的优势大幅缩水甚至反转，结论应改写为"在文本对齐维度上解耦范式带来了更好的样本效率"，而非笼统的更强 OOD 泛化。

第二个可预测的失败条件来自长度奖励：Rlen​ 在 ℓ≥2000 处饱和且单调不减，训练会把 CoT 推向 2000 token 以上，而作者自己的定理说方差正比于 T。把 RL 步数从 65 步显著拉长，可预测训练会在某点开始震荡——65 步这个数字本身就值得追问是不是"在崩之前停住"。

§ 12 — Follow-up Research Idea ​

驱动它的局限：DeScore 训完之后是一个固定的标量函数。但它的结构创造了一个此前不存在的对象——一个以自然语言理由为输入之一的打分头，即 s=Φ(Θ(v,c,o)) 中的 o 是可以被替换的。论文只把它当作模型自己生成的中间产物，从未当作可控输入。

新的 framing：把 CoT 当作奖励模型的控制面，研究可条件化的评审员。不同产品需求（偏好大幅运动还是画面稳定、写实还是风格化、不同的安全红线）目前只能各训一个奖励模型；如果在推理时把人写的评审准则当作 o 注入，就能不重训地平移奖励函数，进而调节生成模型的取向。这同时给出一条可解释性路径：固定视频、系统性改写 CoT 里的某句判断，观察分数变化，就能反事实地测出模型到底信了什么。

可借鉴的相邻工具：一是 LLM 里的可控解码与 system prompt 条件化研究，那里已有方法衡量指令对输出的实际控制强度；二是因果推断里的干预式探针，把"改写 CoT 到分数变化"的关系从相关性提升为可验证的敏感度度量。

第一个实验：固定 500 对视频，为每对生成 K 份 CoT，其中一份是模型自己的，其余按不同侧重（强调动态、强调美学、强调物理合理性）改写，测量分数的可控范围与偏好翻转率。核心检验的是分数对 CoT 内容的敏感度是否足以支撑条件化控制。若敏感度接近零，说明 § 9 的担忧成立、CoT 确为装饰；若敏感度足够大且方向可预测，则做第二步——在 Flow-DPO 后训练里用两套不同的注入准则，检验能否得到一条动态度与美学质量的可控帕累托前沿，把奖励模型从固定函数变成可调旋钮。
