VideoPoet: A Large Language Model for Zero-Shot Video Generation ​

项内容
arXiv2312.14125
提交日期2023-12-21（v4 修订于 2024-06-04；abs 页 Comments 写 ICML 2024）
作者Dan Kondratyuk, Lijun Yu, Xiuye Gu, José Lezama, Jonathan Huang, Grant Schindler, Rachel Hornung, Vighnesh Birodkar, Jimmy Yan, Ming-Chang Chiu, et al.（Google 等，共约 30 位）
分类cs.CV, cs.AI
一句话把图像、视频、音频全部量化进同一张约 30 万条目的词表，用一个 decoder-only prefix LM 在九种生成任务的混合目标上预训练，得到一个能零样本做 T2V / I2V / 补全 / 风格化 / 视频配音并可任务串联的视频基座。

所属教程：自回归视频生成

§ 1 — 研究问题与重要性 ​

2023 年底的视频生成几乎被扩散模型垄断，典型做法是拿一个预训练的文生图模型（Stable Diffusion 一类），再微调出时间一致性。这条路线在单任务上效果好，但每加一个能力就要改架构或挂 adapter：ControlNet 做结构控制、AnimateDiff 做运动、latent blending 做编辑。能力之间是拼装关系，不是同一个模型的自然涌现。

语言领域早就走完了另一条路：一个 decoder-only transformer，一次预训练，靠 prompt 切换任务。这条路径在文本、代码、音频、语音、机器人上都已经跑通，唯独视频生成上，语言模型的质量一直被认为追不上扩散。VideoPoet 要回答的问题是：如果严格按照 LLM 的训练协议（大规模多任务预训练 + 任务适配微调）来做视频生成，语言模型这条路能不能追平扩散。这个问题的价值不在于名次，而在于如果答案为是，视频生成就能直接接管 LLM 社区多年积累的 scaling recipe、训练与推理基础设施、硬件优化。

§ 2 — 前人工作与不足 ​

视频扩散路线（Imagen Video、Align-your-Latents、Show-1、ModelScopeT2V、VideoCrafter、Stable Video Diffusion）当时质量最好。论文的批评很具体：这些模型是「训练后可组合」而非「端到端统一训练」，新任务靠推理技巧（SDEdit 式的 latent 混合）、架构改动或 adapter 层实现，多任务之间无法互相促进。

图像/视频语言模型路线（DALL-E、Parti、CogVideo、Phenaki、MaskGIT、Muse、MAGVIT）已经证明离散 token + transformer 可行，但先前工作大多只用成对的视频-文本数据训练单一任务。这有两个后果：受限于成对数据量，规模上不去；同一段视频只被用于一种任务，数据效率低。

MAGVIT-v2（Language Model Beats Diffusion）在同一时期证明了 tokenizer 质量才是视觉生成的上限所在，这是 VideoPoet 直接站上去的肩膀。

多模态生成的组合式方案（CoDi 一类）用多个生成模型加文本控制来实现 any-to-any，代价是多个模型间的接口需要外部协调。

VideoPoet 的定位是把上述缺口一次补齐：单模型、单词表、无成对文本也能参与训练（自监督任务用同一段视频反复构造），任务由 <task> token 指定。

§ 3 — 重建作者的思考路径 ​

第一步是承认瓶颈在 tokenizer 而不是 transformer。当时的判断是「视觉 tokenizer 的重建上限决定生成上限」，而 MAGVIT-v2 恰好把这个上限抬到了可用的位置：17 帧、2.125 秒、128×128、8 fps 的视频被压成 (5,16,16) 共 1280 个 token。1280 这个数字很关键——它落在 LLM 序列长度的舒适区里。

第二步是解决数据问题。视频-文本成对数据远少于图文对，如果只训 T2V，规模天花板很低。但语言模型的经验是任务越多样零样本能力越强，而视频天然支持一大堆不需要文本的自监督任务：帧预测、图生视频、中心补全、外扩、音视频续写。同一段无文本视频可以同时服务于多个任务，成对数据的需求量随之下降。

第三步是把所有模态塞进一张词表。图像被当成 1 帧视频，用同一个 tokenizer 编成 (1,16,16)；音频用 SoundStream 编成离散码；文本用冻结的 T5 XL 嵌入直接插进序列的保留位置。这样 transformer 侧不需要任何模态专用结构。

第四步是分辨率的取舍。自回归采样的开销随序列长度增长，17×896×512 的视频要 35840 个 token，完全不现实。于是把语言模型钉在低分辨率上，另外训一个非自回归的 token 空间超分模型。

§ 4 — 核心 Intuition ​

只要把视频、图像、音频都压成同一张词表里的整数，视频生成就退化成一个纯粹的序列建模问题，可以直接套用 LLM 的全部做法。真正让这件事有效的是任务设计而非架构：把同一段无文本视频同时用作帧预测、补全、外扩、音视频续写的训练样本，稀缺的视频-文本对就不再是规模瓶颈，而多任务预训练带来的零样本泛化让模型能做没被显式训练过的事（比如把图生视频与风格化串起来做视频编辑）。

§ 5 — 具体方法与完整 Pipeline ​

词表构造。前 256 个码位留给特殊 token 与任务 prompt；接下来 262144（218）个码位给图像与视频；再接 4096 个音频码（SoundStream 的 RVQ 四层，每层 1024 个码，各层码本不相交）；最后附一小段英文词表。总规模约 30 万。

tokenizer。视觉侧用 MAGVIT-v2，强制因果时间依赖以便续写；128×128 的 17 帧视频编成 (5,16,16)=1280 token，竖屏 128×224 编成 (5,28,16)=2240 token，单张图像编成 (1,16,16)=256 token。因为图像只要 256 个 token，同一 batch 里能装下约 5 倍于视频的图像样本。补全/外扩任务用 COMMIT 编码。音频侧 2.125 秒切成 106 个 latent 帧，实验发现按 RVQ 层级由低到高顺序预测略优于同时预测各层。文本侧用冻结的 T5 XL 编码，经线性层投影进 transformer 嵌入空间，最多 64 个文本 token。

主干。decoder-only 的 prefix LM：序列左半部分（文本嵌入、条件视觉/音频 token）用双向 attention，右半部分（待生成的视觉/音频 token）用因果 attention，损失只加在输出部分。任务由 <task> token 指定，且共享同一输出类型的任务可以复用同一个 <task>（T2V、I2V、无条件生成三者共用）。

预训练任务九种：无条件生成、T2V、帧预测、I2V、补全/外扩、风格化、音频到视频、视频到音频、音视频续写。风格化的训练形式是从光流（RAFT）加深度（MIDAS）加文本重建真值视频；把光流与深度归一化后沿通道维拼接，通道数恰好与 RGB 相同，因此可以直接用同一个 MAGVIT-v2 tokenizer 编码，不必重训 tokenizer。推理时对输入视频估光流与深度，只改文本即可换风格。

训练策略。多任务用 Alternating Gradient Descent：按序列长度把任务分组，每次迭代交替采一组，padding 比例接近 0%。采样权重分两段：前 25% 的迭代按图像 90% / 视频 10%，之后翻转为视频 90% / 图像 10%。预训练后在约 5000 万条更高质量的视频-文本子集上微调，这一步同时修好了「解码坍缩」（反复预测同一 token）并允许更大的 classifier-free guidance。

超分。非自回归的窗口注意力 transformer，每个 block 三层，分别在空间垂直、空间水平、时间三个轴上做局部窗口自注意力；cross-attention 一路看低分辨率 token 序列（窗口与自注意力同构），一路看 T5 XL 文本嵌入。为应对 262144 的词表，用 k=2 的 token factorization 把一个 262144 类分类拆成两个 512 类分类。训练用 64M 高质量视频-文本对，低分辨率条件由真值视频 bicubic 下采样后 tokenize 并在离散 latent 空间做噪声增广（随机重采样一部分 LR token，并以 10% 概率独立丢弃 LR 条件与文本嵌入）。两级 2× 级联，从 224×128 升到 896×512，第一级 1B、第二级 500M，各 24 步采样。

走一遍完整例子（文生 10 秒视频）：T5 XL 编码 prompt → 插入序列前缀 → <task> 指定视频输出、<res> 指定分辨率 → LM 自回归吐出 1280 个视觉 token → 取最后 1 秒作为条件继续预测下一段，迭代到 10 秒 → detokenizer 还原到 224×128 像素 → 两级超分升到 896×512。在 TPUv5p 4 芯片、batch 4 的设置下，基座 34 秒、detokenizer 1.3 秒、超分 6.8 秒，摊到每秒输出视频约 5 秒。

§ 6 — 核心数学推导 ​

论文没有给出新的形式化推导，方法层面的数学只有 prefix LM 的标准条件似然：模型在前缀 c（文本嵌入、条件 token）上做双向 attention，对输出段 y=(y1​,…,yM​) 做因果分解并只在这一段计损失

L=−m=1∑M​logpθ​(ym​∣y<m​,c)

唯一值得单独说明的是超分模块用的 token factorization：MAGVIT-v2 的码本大小 218=262144，直接做 softmax 分类的输出层与计算量都不可接受。把码位索引分解成 k=2 个因子，每个因子取值 29=512，于是一次 262144 类分类变成两次 512 类分类，输出层规模从 218 降到 2×29。这是把大词表问题转成乘积码的经典手法，代价是假设两个因子在给定上下文时条件独立。

§ 7 — 实验设计与结论 ​

问题一：多任务预训练真的比单任务好吗？ 用 300M 模型在相同 300k 步、batch 1024、学习率 10−3 下扫任务组合，零样本评测四件事：MSR-VTT 的 CLIPSIM、UCF-101 的 FVD、K600 帧预测的 FVD（给 5 帧预测 11 帧）、SSv2 的中心补全与外扩 FVD。结果（依次为这五个数）：只训 T2V 得到 0.244 / 822 / 759 / 2333 / 2310；加上 T2I 变成 0.247 / 1025 / 794 / 2118 / 1916；只训四个自监督任务（SSL）是 0.226 / 1742 / 700 / 1093 / 1500；去掉 T2I 的全任务是 0.235 / 1008 / 755 / 95 / 389；全任务是 0.240 / 1085 / 729 / 127 / 636。结论有两层：纯自监督在 T2V 上明显吃亏（CLIPSIM 0.226、UCF-101 FVD 1742），说明文本配对数据无法用自监督任务替代；全任务在平均意义上最好，但在单项上未必赢——比如 UCF-101 的 FVD 反而是只训 T2V 最低。作者把这个下降归因于同等步数下每个任务训练不足，这个解释合理但未做补充实验验证。

问题二：规模有用吗？ 300M / 1B / 8B 分别用 100 亿、370 亿、580 亿视觉与音频 token 训练，FVD 与 FAD 在 log-log 图上随规模与数据量持续改善。同一张表 1 的最后一行是 8B 全任务模型：0.305 / 355 / 687 / 4.7 / 13.76，相对 300M 档是整体的、大幅度的跃升，其中 SSv2 补全的 FVD 从 127 降到 4.7。附录的定性对比进一步指出 8B 相对 1B 多出的能力：时间一致性、prompt 遵循、运动幅度，以及有限的文字渲染、空间关系与计数。

问题三：与扩散 SOTA 相比如何？ 自动指标方面，表 2 报告了 MSR-VTT 与 UCF-101 上的零样本 CLIPSIM / FVD / IS，VideoPoet 处于领先梯队（该表在 arXiv HTML 版被渲染成一行、数字粘连，本页不逐个转引其中的具体数值，改以表 1 中 8B 模型的零样本结果为准）。评测协议本身写得非常细：生成 16 帧、256×256（先出 128×128 再 bicubic 上采样），MSR-VTT 的 CLIP 分用全部 59794 条 caption 与 ViT-B/16，FVD 在 2048 段视频上重复 20 次。

人评方面，作者建了约 250 条 prompt 的评测集，用 7 名评测员在文本忠实度、视频质量、运动有趣度、运动真实度、时间一致性五个维度上做双盲两两对比，对手包括 Show-1、VideoCrafter、Phenaki、Pika、Gen2、WALT、Lumiere（Pika 与 Gen2 因需手工提交只跑了 50 条子集）。结论是 VideoPoet 在多数维度上胜出，运动有趣度与运动真实度上优势显著，只有并行工作 Lumiere 在视频质量一项上超过它。

问题四：涌现出了哪些没训过的能力？ 任务串联是最有说服力的一条：先做文本条件的图生视频，再做视频到视频风格化，每一级的输出质量都足以留在下一级的分布内（相当于 teacher forcing），因此可以链式组合出训练时不存在的编辑任务。风格化的定量结果在附录：DAVIS 2016 选 20 段视频、每段 2 条风格 prompt，CLIPSIM 上 VideoPoet 0.3417 对 Control-A-Video（depth）0.3246，人评在文本忠实度与视频质量上也占优。此外模型能绕物体旋转并给出物体背面的合理外观，尽管训练中没有任何 3D 一致性的数据或损失。

§ 8 — Take-aways ​

5 句话版：VideoPoet 把 MAGVIT-v2 的视觉码、SoundStream 的音频码与冻结 T5 XL 的文本嵌入拼进一张约 30 万条目的统一词表，用一个 decoder-only prefix LM 在九种生成任务的混合目标上预训练，再在约 5000 万条高质量视频-文本对上做任务适配微调。关键设计是让同一段无文本视频同时充当帧预测、补全、外扩、音视频续写的训练样本，从而把稀缺的视频-文本对从规模瓶颈的位置上挪开。自回归成本靠分辨率取舍解决：LM 只在 128×224 上生成，再由一个窗口注意力的非自回归 transformer 分两级超分到 896×512，并用 k=2 的 token factorization 把 262144 类分类拆成两个 512 类。300M 的任务组合消融显示纯自监督在 T2V 上明显吃亏而全任务平均最优，8B 模型在零样本 UCF-101 FVD 355、SSv2 补全 FVD 4.7 上大幅优于 300M 档。人评中 VideoPoet 在运动有趣度与运动真实度上显著胜过同期扩散模型，只有 Lumiere 在视频质量上超过它。

3 句话版：只要 tokenizer 够好，视频生成可以完全变成 LLM 的序列建模问题，从而继承 LLM 的多任务预训练与基础设施。多任务混合目标让无文本视频也能贡献训练信号，并涌现出可串联的零样本编辑能力。这条路线在运动质量上首次与同期扩散 SOTA 正面抗衡。

1 句话版：用统一离散词表与多任务预训练，把视频生成做成一个真正的语言模型问题。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：人评中「VideoPoet 的运动质量胜过扩散模型」这一结论，反映的是模型能力而非评测协议的不对称。论文自己披露了三处会系统性偏向 VideoPoet 的设置：其一，prompt 集在筛选时优先选取显式包含运动的 prompt，理由是避免偏袒那些生成近乎静止的高画质视频；其二，VideoPoet 的推理使用了固定负向 prompt（"a still shot of an ugly cartoon, slideshow of an empty scene, low resolution, distorted and disfigured"）与轻量 prompt 改写（在原 prompt 后追加 "highly detailed, cinematic, arc shot, high contrast, soft lighting, 8k"）；其三，评测用的是任务适配微调后的版本。这三项里，负向 prompt 直接把「静止/幻灯片感」这一失败模式从 VideoPoet 的输出分布里压掉，而对手模型是否获得等价处理，论文没有说明。运动有趣度与运动真实度恰好是这套 prompt 工程最直接影响的两个维度，也恰好是论文宣称优势最大的两个维度。

论文为这条假设提供的间接证据是自动指标（零样本 FVD / CLIPSIM）也处于领先梯队，而自动指标不受负向 prompt 影响。这有一定说服力，但 FVD 对运动质量的敏感度本身就有争议，且自动指标评的是 16 帧短片段，与人评的运动维度不是同一件事。真正缺的证据是一次对称实验：给所有对手模型同样的负向 prompt 与 prompt 改写预算，或者干脆把 VideoPoet 的这层包装去掉再评一次。

§ 10 — 最小复现实验 ​

不要复现 8B，改去测量这套方法的上限，一周足够：

  1. 取一个公开的 MAGVIT-v2 风格离散视频 tokenizer（或 LlamaGen / OmniTokenizer 一类替代），把 200 段真实视频按 17 帧、128×128、8 fps 编码再解码。
  2. 计算 FVD(重建, 真实)、LPIPS 与 PSNR。这组数就是任何以该 tokenizer 为基础的生成模型在这些指标上的地板。
  3. 把地板与论文报告的生成 FVD 放在一起看。若生成 FVD 已经接近地板，说明继续加大 LM 规模收益有限，瓶颈在 tokenizer；若两者差距仍很大，说明 LM 侧还有空间。
  4. 补一条更便宜的诊断：把重建视频与原视频做一次人评两两对比，问「哪个视频质量更好」。论文在 limitation 里承认量化会封顶视觉保真度，但没有量化这个封顶有多低。如果人评在重建 vs 原视频上就有明显偏好，那么论文中「Lumiere 在视频质量上胜出」这一条就有了一个与模型能力无关的解释。

判据：地板 FVD 若与论文的生成 FVD 同量级，第 4 步的人评偏好差距若与 Lumiere 对 VideoPoet 的优势幅度可比，则「画质劣势来自 tokenizer 而非 LM」成立。

§ 11 — 最强反例设计 ​

最有力的攻击针对人评结论，分两步。

第一步，制造对称。 重跑人评，但给每个对手模型也配一条等价的负向 prompt 与同样的 prompt 改写后缀（扩散模型普遍支持负向 prompt，Show-1、VideoCrafter、SVD 都可以）。同时把 prompt 集换成一个未按运动筛选的中性集合。如果 VideoPoet 在运动有趣度与运动真实度上的优势在对称条件下缩小到统计不显著，那么原结论的归因就要从「LLM 路线更擅长运动」改成「这套 prompt 工程更擅长压制静止失败模式」。

第二步，加平凡基线做刻度。 在人评中混入两个平凡条目：把首帧复制 17 帧得到的静止视频，以及把真实视频直接 tokenize-detokenize 后的重建视频。前者给出「运动」维度的下界刻度——若静止视频在运动真实度上拿到的分数并不低，说明该维度的评分标准本身没有区分度；后者给出「视频质量」维度的上界刻度。论文的五个维度全部是相对比较、没有绝对锚点，加入这两个锚点后，各模型之间零点几个百分点的胜率差异才有可解释的量纲。

可预测的失败条件：论文在 limitation 里已经点明，小物体与细节在大幅运动下难以保持。据此可以构造一批必然失败的 prompt（手部特写做精细操作、文字招牌在镜头快速平移中保持可读、多个同类小物体各自独立运动）。这类 prompt 在当前约 250 条的评测集中占比很低，而它们恰好是「视频作为世界模型」下游应用最关心的情形。

§ 12 — Follow-up Research Idea ​

驱动这个想法的局限：VideoPoet 的 tokenizer 与 LM 是串行训练的——MAGVIT-v2 先按重建误差训好，冻结，然后 LM 在它产生的 token 上学。重建误差这个目标会把码本容量按「像素上难以还原」来分配，而 LM 真正在意的是「在给定上下文时难以预测」。这两件事并不重合：一片随机纹理的草地重建误差高但对下文毫无预测价值，一个正在运动的小物体重建误差低却携带几乎全部的动力学信息。论文自己的 limitation（小物体与细节在大幅运动下丢失）正是这种错配的表现。

新的 framing：把 tokenizer 的码率分配目标从「重建保真」换成「边际预测价值」——一个 token 值不值得占用码本容量，取决于保留它能让下游 LM 的条件似然提高多少，而不是取决于它对像素 MSE 的贡献。这不是给现有系统加模块，而是换掉压缩器的目标函数，把视觉压缩从信号处理问题重新定义成一个与序列建模耦合的信息分配问题。

可借鉴的相邻领域工具：率失真理论中的「面向任务的压缩」（task-aware compression）已经有成熟表述；语音领域的神经编解码器与 LM 联合训练（AudioLM 一系）提供了工程范式；LLM 数据归因里的 influence function 提供了估计「某个输入成分对下游损失的边际贡献」的手段。

第一个实验（纯诊断，不需要重训任何大模型）：在已有的冻结 tokenizer 与一个小 LM 上，对每个视频 token 位置同时测两个量——(a) 该位置在 detokenizer 中对重建误差的贡献（遮蔽该 token 后的像素误差增量），(b) 该位置的 LM 条件负对数似然。把两者画成散点图。如果两者接近正交甚至反相关，就直接证明了当前码率分配与预测价值脱钩，这个阴性/正交结果本身足以支撑后续换目标函数的工作；如果两者高度相关，说明这条路线不值得走，也是一个干净的结论。第二步才是按 (b) 重新加权 tokenizer 的训练损失，在同等码率下比较 LM 的困惑度与生成 FVD。
