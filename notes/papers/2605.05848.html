VideoRouter: Query-Adaptive Dual Routing for Efficient Long-Video Understanding ​

项内容
arXiv2605.05848
提交日期2026-05-07
作者Kuanwei Lin, Wenhao Zhang, Ge Li
分类cs.AI, cs.CV
一句话把长视频压缩重写成"预算下的证据分配"：Semantic Router 只看问题文本就决定该铺开覆盖还是集中高清，Image Router 借 InternVL3 前四层语言层给每帧打相关性分，再按优先级把 token 预算发下去。

所属教程：长视频理解

本页依据 arxiv.org/e-print/2605.05848 取回的 LaTeX 源码撰写（正文、附录与全部表格）。

§ 1 — 研究问题与重要性 ​

长视频进入多模态大模型时，瓶颈不在模型会不会看，而在 token 预算根本装不下。一小时视频按帧展开的视觉 token 序列会把显存和首 token 延迟同时打爆。已有的压缩方法确实能把数字压下来，但它们大多在两件事上偷懒：要么完全不看用户问了什么，要么对所有帧套同一套压缩比例。

这两种偷懒在长视频上代价特别大，因为证据在时间轴上分布极不均匀。"这段视频讲了什么主题"需要的是全时段的粗粒度覆盖；"那个人手里拿的牌子上写了什么"需要的是某一两帧的高分辨率细节；更麻烦的是很多真实问题同时要这两样。用一套固定策略去服务这三类需求，必然在其中至少两类上做亏本买卖。

作者把问题重新表述成 budgeted evidence allocation：给定一个硬的视觉 token 预算 Bimg​，模型应该自己决定把这些 token 铺薄还是堆厚。这个表述的价值在于它把"压缩率"这个工程参数变成了一个可以被监督、被学习的决策变量。

§ 2 — 前人工作与不足 ​

LLM 之前的压缩（PruMerge、VisionZip 等）继承自 ViT 时代的 token dropping / merging（ToMe、EViT、DynamicViT、TokenLearner）。它们在视觉编码器出口处就把 token 砍掉，此时模型还没有看到问题，砍什么完全由视觉冗余度决定。

LLM 内部的剪枝（FastV、DyToK、PyramidDrop、SparseVLM、HiDrop）等到 LLM 跑了几层、有了一点跨模态推理之后再剪。这条路线比前一条更有信息，但它们的决策粒度是 token 或帧，没有一个贯穿整段视频的、以查询为条件的预算策略。

查询感知的选帧（CROP、LGTTP、PruneVid、QTSplus、GenS、VideoTree）已经证明"少数帧决定答案"这件事成立。它们的问题在于把决策做成了单层：选出关键帧，其余丢掉。本文的批评是这一层不够——先要决定"这个问题到底吃不吃关键帧策略"，再决定"哪些帧是关键帧"。

§ 3 — 重建作者的思考路径 ​

先接受一个已有观察：LLM 的前几层已经完成了相当程度的跨模态融合。既然如此，帧-查询相关性这种判断不必再造一个外挂模型，直接复用前几层的隐状态就够，而且这些层本来就要算。这是 Image Router 的来源。

第二个观察来自失败模式。如果只有帧级相关性打分，那么对"总结全片主旨"这类问题，打分器会被迫在无差别的帧里挑出几帧标成"相关"，然后把其余帧压到极致——这恰好破坏了这类问题唯一需要的东西，即时间覆盖。所以必须在帧级决策之上再加一层"这个问题该用哪种分配策略"的判断。这是 Semantic Router 的来源。

第三个观察是监督信号从哪来。帧级相关性没有现成标注，作者用了一个反演思路：先让 VLM 对均匀采样帧写稠密 caption，再让 LLM 从 caption 反向生成依赖特定视觉线索的 QA，最后逐帧测试"去掉这一帧还能不能答对"，能答对的就不是必要帧。策略级标签则靠 A/B 探针：在同一底座上强制跑 Global 和 Fragment 两种策略，按题目类别比准确率差。三条线合起来，方法的形状就定了。

§ 4 — 核心 Intuition ​

一个问题需要多少视觉带宽，在看视频之前就已经由问题本身决定了大半；而带宽该花在哪几帧，只有把问题和帧放在一起过一遍才知道。前者交给一个纯文本分类器，后者交给复用 LLM 前四层的轻量打分头，两者串起来就得到了一条从"问题语义"直达"每帧 token 数"的通路。

§ 5 — 具体方法与完整 Pipeline ​

底座与 shadow stack。基座是 InternVL3-8B，输入帧统一缩放到 448×448。为避免引入大量新参数，作者把 LLM 的前四层解码器复制成一份 shadow stack E1:4​，路由特征为 Hq​=E1:4​(Emb(q)) 与 Hv,q(t)​=E1:4​([Zt​;Emb(q)])。

Semantic Router。对 Hq​ 做带掩码的 Pooling，再过一个带 LayerNorm 与 GELU 的 Strategy MLP，输出二分类：ys​=0 为 Global（全帧统一池化尺度 sg​=2），ys​=1 为 Fragment（走自适应分配）。注意它只看问题文本，不看任何视觉输入。

Image Router。每帧的视觉 token 与问题拼接后过 shadow stack，再经一个带可学习 [CLS] 的轻量 Transformer Block 和 Frame Score MLP，输出 pt​，以 0.5 为阈值二值化。

预算与优先级池化。可用视觉预算按 Bimg​=Lmax​−Ltext​−Lgen​−ϵ 动态算出，安全余量 ϵ=100。Fragment 路径采用两档分辨率：关键帧 s1​=1，无关帧 s0​=4。分配遵循三级优先级：先保证所有关键帧按 s1​ 全留；剩余预算给无关帧按 s0​ 铺背景；极端紧张时先丢低优先级帧，若连关键帧都装不下就在关键帧集合里均匀采样，保证证据仍横跨时间轴。

训练三阶段。Stage 1 只训 Image Router，在 Video-FLR-200K 上 5 epoch、lr 5×10−5；Stage 2 只训 Semantic Router，在 Video-QTR-10K 上 2 epoch、lr 1×10−5；Stage 3 解冻 LLM 做 1 epoch 联合微调，lr 5×10−6，总损失 L=LLM​+λs​Lsem​+λv​Limg​，λs​=λv​=0.01。硬件为 4 张 NVIDIA H20 加 DeepSpeed ZeRO-2。

数据。Video-FLR-200K 含 200,664 条带帧级相关性标注的 QA，Video-QTR-10K 含 10,000 条带策略标签的视频-查询对，原始素材从 LLaVA-178K 训练集采样以避免评测集泄漏。所有样本过一致性、逻辑连贯性、反事实必要性三道过滤。附录报告了 500 条留出样本的人工审计：策略标签一致率 94.0%，帧相关性标签一致率 88.4%。

一个具体例子。问"讲者在白板上写的第二个公式是什么"，Semantic Router 从问句里的"第二个公式"判定为 Fragment；Image Router 在 64 帧里把白板特写的那几帧打成 1，其余打成 0；分配算法把这几帧按 s1​=1 全分辨率留下，其余帧按 s0​=4 压到 1/16，总量卡在 12,288 以内。

§ 6 — 核心数学推导 ​

策略标签的构造用了一条显式判据：对问题类别 C，当

Accfragment​(C)−Accglobal​(C)>τ

时赋予 Fragment 标签，否则赋 Global。这条式子值得单独看，因为它说明"策略标签"不是语义分类，而是在固定预算下哪种分配更划算的经验结论。换句话说，标签本身依赖于当时用的底座、预算与池化尺度，τ 一改、预算一改，同一类问题的标签就可能翻转。

分配算法的边界条件也是纯算术的。记每帧原始 token 数为 N，关键帧集合 F1​、无关帧集合 F0​，则 C1​=∣F1​∣⋅(N/s12​)、C0​=∣F0​∣⋅(N/s02​)。当 C1​+C0​≤Bimg​ 时全留；当只有 C1​≤Bimg​ 时，无关帧可留数量为 k=⌊(Bimg​−C1​)/(N/s02​)⌋；再紧张就退化为在关键帧里留 k=⌊Bimg​/(N/s12​)⌋ 帧。整个过程没有优化求解，是一条确定性的规则链。

两个路由头的损失分别是标准的逐帧二元交叉熵与二分类交叉熵：

Limg​=−T1​t=1∑T​[yt​logpt​+(1−yt​)log(1−pt​)],Lsem​=−c∈{0,1}∑​ys,c​logps​(c).

§ 7 — 实验设计与结论 ​

第一个问题：收益来自路由本身还是来自多喂的数据。 表 tab:fair_comparison 是本文最关键的一张表，因为它把帧数与最大预算全部对齐（同样 64 帧、同样 Bimg​=12,288），并报告实际压缩后的 token 数。第 3–6 列依次是 Video-MME / LongVideoBench / MLVU：Uniform Pooling（8,192 token）65.4 / 58.9 / 70.6；CLIP Relevance Pooling（7,936）65.8 / 59.7 / 71.0；Data FT + Uniform Pooling（8,192）65.2 / 58.1 / 70.7；VideoRouter（7,748）66.5 / 61.9 / 72.1。参照行是不压缩的 InternVL3 Dense（16,384 token）66.3 / 58.8 / 71.4。

这张表说了三件事。第一，只喂同样的路由监督数据而不装路由模块（Data FT 行）在三个基准上都没有超过 Uniform Pooling，收益确实来自分配机制而非数据曝光。第二，训练无关的 CLIP 相关性打分已经能吃到一部分收益（LongVideoBench 58.9 → 59.7），VideoRouter 相对它的净增量是 2.2 点。第三，相对均匀池化这条平凡基线的绝对增益分别是 1.1 / 3.0 / 1.5 点，长视频基准上最明显。

第二个问题：路由的开销吃不吃得回来。 表 tab:latency_breakdown 在 64 帧下拆开延迟：InternVL3 Dense 16,384 token、TTFT 8.4 s、峰值显存 36.5 GB；Uniform Pooling 8,192、4.8 s、24.6 GB；VideoRouter(s=2,4) 7,748 token，其中 router 0.5 s、prefill 3.0 s、TTFT 4.7 s、23.9 GB；VideoRouter(s=4,8) 5,262 token、TTFT 4.2 s、22.4 GB。shadow stack 的 0.5 s 被 prefill 的缩短抵消有余。

摘要里的"最多减少 67.9% token"正是 (16,384−5,262)/16,384。这个数字来自 s=4,8 那一档，而准确率数字（66.5 / 61.9 / 72.1）来自 s=2,4 那一档；论文没有报告 s=4,8 档的任何准确率。

第三个问题：两个路由头各自贡献多少。 表 tab:ablation_combined(a) 在统一预算下给出 MME-Long / MME-Overall / LVB / MLVU：InternVL3* 54.7 / 64.3 / 56.9 / 70.2；w/o Image Router 55.1 / 65.4 / 58.9 / 70.6；w/o Semantic Router 55.5 / 65.6 / 61.2 / 69.8；完整模型 56.0 / 66.5 / 61.9 / 72.1。值得注意的是去掉 Semantic Router 后 LongVideoBench 只掉 0.7 点，而 MLVU 掉到 69.8，反而低于未加任何模块的 InternVL3* 基线（70.2）。表 (b) 的训练策略消融显示跳过 Stage 3 联合微调最伤（LVB 只有 57.1）。

第四个问题：路由头本身准不准。 正文报告 Semantic Router 在 2,350 条测试样本上达到 98.2% 准确率，Image Router 在 2,500 条样本上随抽取深度变化：k=2 时 78.5%，k=4 时 83.4%，k=6 或 8 时收敛到 84.5%，而路由延迟开销从 5.1% 线性升到 10.4% 以上，因此默认取 k=4。

第五个问题：预算与帧数怎么配。 附录的 LongVideoBench 预算扫描给出完整曲线：4K 预算下 VideoRouter(64f) 58.4 而 VideoRouter(128f) 只有 54.9；到 12K 以上反转，128f 依次为 62.4 / 63.4 / 63.8，超过 64f 的 61.9 / 62.6 / 62.6。作者的解释是 128 帧在紧预算下会触发 s0​≥8 的超激进压缩并丢关键帧。

§ 8 — Take-aways ​

5 句版：长视频压缩的真问题是在硬预算下把带宽分给谁，而不是把压缩率调到多少。分配决策可以拆成两层：问题级的策略选择只需要文本，帧级的证据定位需要跨模态，后者复用 LLM 前四层就够。这两层都没有现成监督，作者用"反演生成 + 反事实必要性检验"造了 200K 帧级标签和 10K 策略标签，并做了 500 条人工审计。在帧数与预算完全对齐的受控对比里，相对均匀池化的增益是 1.1–3.0 点，长视频基准最明显。头条的 67.9% token 缩减来自比准确率表更激进的那一档配置，两者不能直接拼在一句话里读。

3 句版：Semantic Router 从问题文本预测全局覆盖还是局部高清，Image Router 用 shadow stack 给每帧打相关性，二者驱动一条确定性的优先级分配规则。受控对比显示收益来自分配机制而非数据曝光，且 shadow stack 的 0.5 s 开销被 prefill 缩短抵消。策略标签是按问题类别用 A/B 探针赋的，这是整套方法最脆的一环。

1 句版：在固定 token 预算下，先用问题文本选分配策略、再用早期 LLM 层选帧，能在同等或更低预算下超过均匀池化与训练无关的 CLIP 打分。

§ 9 — 最脆弱的假设 ​

失败代价最大的一条是：分配策略可以按问题类别整体赋标，且这个标签只凭问题文本就能可靠预测。 Video-QTR-10K 的构造方式是对每个问题类别 C 跑 A/B 探针，比较 Fragment 与 Global 的类别平均准确率，差值超过 τ 就把整个类别标成 Fragment。这等于假设同一类别内部的样本对带宽的需求是同质的。

论文自己提供了这条假设不成立的证据。附录的标签审计写明，标注者的分歧"集中在同时需要广覆盖与局部证据的混合查询上"；正文也主动声明这些标签"不应被理解为用户意图的刚性分类法"。而 Semantic Router 报出的 98.2% 准确率恰恰是这条假设的副产品：如果标签本来就是类别级的、且类别可以从问句措辞读出来，那么这个分类任务近乎退化，98.2% 不能被当作"路由决策做得好"的证据，只能说明"分类器学会了类别"。

真正缺失的证据是：论文没有报告在同一类别内部、按样本真实最优策略评估的路由准确率，也没有报告 oracle 路由（每条样本选真正更优的策略）能达到多少，因此我们无从判断类别级近似损失了多少上限。表 (a) 里 w/o Semantic Router 在 LongVideoBench 上只掉 0.7 点，与这条假设的脆弱性是相容的：如果类别划分本来就粗，去掉这层的损失自然小。

§ 10 — 最小复现实验 ​

不必复现三阶段训练。一周内可做的最小验证聚焦在"类别级策略标签是否够用"：

  1. 取 InternVL3-8B 与 LongVideoBench 验证子集（约 500 题），实现论文的两档池化（sg​=2；s1​=1,s0​=4）与预算 Bimg​=12,288。
  2. 对每道题分别强制跑 Global 与 Fragment 两条路径（Fragment 路径的帧相关性可先用训练无关的 CLIP 打分代替 Image Router），记录逐题对错。
  3. 统计三个量：oracle 路由准确率（逐题取更优）、类别级路由准确率（按论文口径给整类赋标后再执行）、以及"类别内策略翻转率"，即同一类别中真实最优策略与类别标签相反的样本占比。
  4. 判据：若 oracle 与类别级路由之间的差距明显大于表 (a) 里 Semantic Router 贡献的 0.7 点，则类别级近似是主要瓶颈，本文的路由上限被自己的标注粒度锁死；若翻转率低于 10%，则这条假设在该基准上成立，我的质疑不成立。

§ 11 — 最强反例设计 ​

第一重攻击针对头条数字的拼接。 论文的宣传句是"在同等或更低预算下持续超过 InternVL3 基线，token 最多减少 67.9%"。但 67.9% 对应的是 s=4,8、5,262 token 那一行，它在延迟表里出现，在准确率表里不出现；准确率表里的 7,748 token 对应的缩减是 52.7%。最有力的反驳实验只需要补一格：在 s=4,8 配置下跑 Video-MME / LongVideoBench / MLVU。如果这一档的准确率跌到 Uniform Pooling 之下，那么"67.9% 缩减"与"维持或提升准确率"就不能共存于同一个配置，本文的效率-精度 Pareto 前沿要整体左移。论文没有报这一格，这属于缺失证据。

第二重攻击针对帧级相关性的语言先验旁路。 Semantic Router 完全不看视频，Image Router 的输入是"帧 + 问题"。构造一批语言先验可解的问题（答案能从选项措辞、常识或问题本身推出），在这批样本上比较三个条件：完整 VideoRouter、把所有帧替换成黑帧、把帧顺序随机打乱。论文没有报告任何一种平凡基线（黑屏 / 打乱帧序 / 随机剪枝）。如果黑帧条件下 Video-MME 仍能拿到接近 60 的分数，那么表 tab:fair_comparison 里 1.1 点的 Video-MME 增益就落在语言先验的噪声带里，只有 LongVideoBench 的 3.0 点还站得住。这个实验的成本极低，却能把"1.1 点算不算证据"这件事一次性说清。

第三重攻击针对关键帧的均匀采样退路。 算法在极端预算下会对关键帧集合做 UniformSample。构造一批证据高度集中在连续几帧的问题（例如一闪而过的屏幕文字），把预算压到 4K。此时均匀采样会等概率地丢掉相邻的关键帧。若在这批样本上 VideoRouter 相对 CLIP Relevance Pooling 的优势消失，说明"自适应分配"的收益在最需要它的极端预算区反而不成立——而附录的预算扫描恰好显示 4K 处 VideoRouter(128f) 只有 54.9，低于 Uniform Pooling(64f) 的 55.8，这一格已经给了这条攻击一个落点。

§ 12 — Follow-up Research Idea ​

驱动它的局限：本文的两个路由头都在预测一个离散且预先定义好的策略空间（Global/Fragment、相关/不相关），而这个空间的边界是作者用 A/B 探针和阈值 τ 画出来的。一旦底座、预算或池化尺度改变，标签就要重造。这是一条不可迁移的监督链。

换一个 framing：把分配问题从"分类"改写成"在预算约束下最大化答案可恢复性"的信息论目标。对每帧定义一个条件互信息代理量 I(A;Zt​∣q,Z∖t​)，即在已有其余帧的条件下这一帧还能为答案带来多少增量信息；分配就变成在 ∑t​c(kt​)≤B 下最大化 ∑t​It​ 的背包问题，不再需要任何人造的策略类别。

可借鉴的相邻领域工具：稀疏自编码器与特征归因领域里成熟的 leave-one-out 增量估计，以及主动学习里的 expected information gain 近似——它们都在解决"逐元素边际价值估计"这个同构问题，且都有免于重新训练的一次前向近似。

第一个实验长什么样：在 LongVideoBench 上，用 InternVL3-8B 对 64 帧逐帧做 leave-one-out，测量去掉该帧后正确答案 token 的对数似然下降量，作为 It​ 的经验代理。先验证两件事：(a) 这个量与 Video-FLR-200K 的人工二值标签一致性有多高（如果显著高于 88.4% 的标注一致率，说明连续量比二值标签更可信）；(b) 直接用这个量做背包分配，在 4K/8K/12K 预算下能否超过本文的两档规则。若能，下一步才是把它蒸馏进 shadow stack，得到一个不依赖类别标签的连续路由器。
