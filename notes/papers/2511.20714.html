Inferix: A Block-Diffusion based Next-Generation Inference Engine for World Simulation ​

项内容
arXiv2511.20714
提交日期2025-11-25（v1；本文依据 2026-04-28 的 v2 全文）
作者Inferix Team（浙江大学 / 香港科技大学 / 阿里达摩院 / 阿里 TRE 联合团队）：Tianyu Feng, Yizeng Han, Jiahao He, Yuanyu He, Xi Lin, Teng Liu, Hanfeng Lu, Jiasheng Tang, Wei Wang, Zhiyuan Wang, Jichao Wu, Mingyang Yang, Yinghao Yu, Zeyu Zhang, Bohan Zhuang
分类cs.CV, cs.AI
一句话把 block-diffusion（半自回归）视频生成当作一类独立的推理负载，用块级 KV Cache 管理 + 序列并行 + 量化 + 实时流式输出做成专用推理引擎，并配套一个分钟级长视频的漂移评测集。

所属教程：物理感知视频生成

版本说明

只有 v2 的 HTML 全文可用。abs 页摘要里把配套 benchmark 称为 LV-Bench，v2 正文统一改称 InterVBench，本文以正文为准。

§ 1 — 研究问题与重要性 ​

这篇论文不是提出新模型，而是提出一个基础设施主张：世界模型的推理是一类新的负载，现有推理引擎都不对口。

论证从解码范式出发。主流视频扩散模型建在 DiT 上，用双向 attention，没有 KV Cache，好处是块内高度并行、可控性强，代价是长度固定、解码低效。AR 路线（如 Loong）支持变长生成和 KV Cache 管理，但生成质量落后于扩散，且解码不可并行。block diffusion（论文引 Self Forcing、MAGI-1）在两者之间插值：视频 token 按 block 生成，block 内做扩散去噪，block 间以前序 block 的 KV Cache 为 context。这个 generate-and-cache 循环让任意长度生成成为可能，同时把 LLM 世界里成熟的 KV Cache 机制重新引进了视频生成。

一旦解码范式变了，推理系统的瓶颈结构就跟着变。论文明确了两个压力点。存储侧：为了缓解长序列上的 drift 与 forgetting，前序 block 的 KV Cache 必须留着，而这些 cache 会吃掉大量显存。计算侧：模型大、序列长，论文给出一个具体数字，用 Wan2.1 14B 在单张 NVIDIA H20 上生成 5 秒视频约需 6800 秒；世界模拟的 context 更长，代价只会更高。

作者的类比很直白：LLM 时代催生了 vLLM 和 SGLang，视觉扩散时代催生了 xDiT 和 FastVideo，post-training 时代催生了 OpenRLHF 和 verl，那么世界模型时代也该有自己的引擎。Inferix 的定位与 vLLM/SGLang（面向高并发）和 xDiT（面向经典视频扩散）都不同，它面向的是单会话、超长上下文、需要实时交互的世界模拟。

§ 2 — 前人工作与不足 ​

vLLM 与 SGLang 已经把 PagedAttention、连续批处理、前缀共享做到成熟，但它们的优化目标是"多请求高吞吐"。世界模拟通常是一个用户、一条极长的视频流，吞吐不是瓶颈，单序列的显存曲线和交互延迟才是，这套抽象对不上。

xDiT 与 FastVideo 面向经典视频扩散，把并行做在"固定长度、全 attention、无 cache"的假设上：整段视频一次性去噪，序列并行切的是这一整段。block diffusion 的负载形态是"一段一段增量生成 + 一个持续增长的全局 KV Cache"，前者的调度器里根本没有 cache 这个对象。

模型侧的工作各自为政。CausVid 和 Self Forcing 建在 Wan2.1 这个 5 秒全 attention 基座上，MAGI-1 则是从零训练、自带一套 infra。三者的 KV 访问模式、block 划分、prompt 注入方式都不一样，社区想做对比实验就得各自跑各自的代码库。评测侧同样有缺口：VBench 这类指标在几秒钟的片段上工作良好，但它衡量的是整体质量，不是"质量随时间衰减多快"，而后者恰恰是长视频的核心失败模式。

§ 3 — 重建作者的思考路径 ​

假设时间回到 block diffusion 刚被证明可行的那一刻。一个做系统的人会先问：这个范式跟前面两代到底差在哪？答案是它同时具备 AR 的"增量 + KV Cache"和扩散的"块内多步迭代"。这个组合很特殊——LLM 推理是每步产出一个 token，block diffusion 是每个 block 内跑几十步去噪才产出一个 block，于是"一次前向"的粒度和成本都跟 LLM 完全不同，PagedAttention 那套按 token 分页的假设需要重新审视。

接着问：最先撑不住的是什么？把 5 秒扩散推到分钟级，KV Cache 随时间线性增长，而它又不能丢——丢了就 drift。所以显存是第一约束，offload、压缩、分块管理是必须提前留出的接口。

再问：做出来怎么证明有用？如果只报 FPS，社区会怀疑质量被牺牲了；如果用 VBench 报整体分数，又看不出长程漂移。于是需要一个专门衡量"相对于开头，后面退化了多少"的指标。把预测误差领域的 MAPE 搬过来衡量时间轴上的相对变化，是一个自然的迁移。

最后问：怎么让人真的用起来？答案落到工程细节上——统一不同模型的推理接口、内置低开销 profiler、把生成结果直接推成 RTMP/WebRTC 流，这样"世界模拟"才不只是离线跑一段 mp4。

§ 4 — 核心 Intuition ​

block diffusion 把视频生成从"一次性解一整段"变成了"带持久状态的增量解码"，而这个持久状态就是 KV Cache。一旦承认这一点，长视频生成的系统问题就跟 LLM serving 同构了：显存管理、上下文调度、增量输出。Inferix 做的事情就是把这个同构关系落成一个引擎，并顺手补上一个能看见"时间轴上退化多少"的尺子。

§ 5 — 具体方法与完整 Pipeline ​

以"用 CausVid 生成一段分钟级、中途换 prompt 的视频并直播出去"为例走一遍：

  1. 模型接入。Inferix 先把 MAGI-1、CausVid、Self Forcing 的共同计算模式抽象成一条通用 inference pipeline，用户自定义模型按同一组接口接入。这三个模型基座不同（CausVid/Self Forcing 基于 Wan2.1，MAGI-1 从零训练），抽象层要吸收这种差异。
  2. 并行策略选择。引擎根据模型结构、网络拓扑与通信开销，在 Ulysses 式序列并行（按 attention head 切分到多卡）和 Ring Attention（环形拓扑上分布 attention 计算，可选择传 query 或传 KV，性能画像不同）之间做选择。
  3. 块级去噪 + KV 写回。当前 block 从噪声出发迭代去噪，每步 attention 都读全局 KV Cache 取得前序 context；block 出来后把它的 KV 写回 cache，供后续 block 使用。
  4. KV 管理。统一 KV 管理接口之上是块级 KV 内存管理，同时保留 range-based 分块访问与 index-based 选择性取用两条路径，以适配未来"滑动窗口 + 选择性全局依赖"的混合访问模式；支持 MLA 的 latent store，以及把 cache offload 到主存以省显存。
  5. 换 prompt。用户在新 chunk 给出不同 prompt 时，Inferix 清空 cross-attention cache，切断前一个 prompt 的影响，从而实现"分段叙事控制"。
  6. 输出与观测。生成结果经 RTMP 或 WebRTC 推流；全程可开 profiler，作者称完整 profile 的额外开销小于 5%，并提供 Python 装饰器（函数级）和 context manager（代码块级）两种用法，以及自定义指标 hook。框架还集成了 DAX 量化。
  7. 评测。跑完接 InterVBench 出分。

InterVBench 的构建：从 DanceTrack、GOT-10k、HD-VILA-100M、ShareGPT4V 里挑长于 50 秒的高分辨率视频，共 1000 条（人类 671 条占 67%，动物 171 条占 17%，环境 158 条占 16%）；用 GPT-4o 作为数据引擎每 2–3 秒生成一段详细 caption，prompt 模板要求参考上一帧描述以保证时间连贯；数据来源筛选、chunk 切分、caption 校验三个阶段都有人工介入，每阶段至少两名独立审核员；最后按 80/20 划分训练与评测集。

指标方面，作者提出 Video Drift Error（VDE），衡量质量沿时间轴的相对变化，并派生五个维度：VDE-Clarity（清晰度漂移）、VDE-Motion（运动平滑性）、VDE-Aesthetic（美学一致性）、VDE-Background（场景布局稳定性）、VDE-Subject（主体身份漂移），均为越低越好；同时并列报告 VBench 的五个维度（主体一致性、背景一致性、运动平滑度、美学质量、图像质量，越高越好）。

§ 6 — 核心数学推导 ​

论文的形式化成分集中在 VDE 上，作者说明它受 MAPE 与加权 MAPE 启发。需要说明：v2 的 HTML 里 VDE 的具体公式没有渲染出来，所以这里只补它所依据的背景，不代入论文未给出的具体形式。

MAPE 衡量预测值相对真实值的百分比偏差：

MAPE=T1​t=1∑T​​yt​yt​−y^​t​​​

它的关键性质是无量纲——分母把尺度除掉了，所以不同单位的量可以放在一起比较。加权版本给不同样本不同权重：WMAPE=∑t​wt​∣yt​−y^​t​∣/∑t​wt​∣yt​∣。

把这套东西搬到长视频上，直觉是：清晰度、美学分、主体一致性这些指标各有各的量纲和取值范围，绝对差值不可比；但"相对于视频开头，第 t 段退化了百分之多少"是可比的。可以推断（论文未逐条展开）VDE 就是把 yt​ 换成某个参考时刻的质量分、y^​t​ 换成第 t 段的质量分，沿时间轴取相对偏差的聚合。这解释了为什么五个 VDE 变体能共用一个"越低越好"的量纲。

§ 7 — 实验设计与结论 ​

这里必须说清楚：这是一篇工程报告，v2 全文没有实验章节，也没有任何性能对比表或 benchmark 排行。论文给出的量化陈述只有两条——Wan2.1 14B 在单张 H20 上生成 5 秒视频约 6800 秒（作为动机而非结果），以及 profiler 完整开启时开销小于 5%。InterVBench 部分给出的是数据集组成表（表 1，各来源的视频条数与对象类别分布），不是模型得分表。

所以论文提出的问题其实是"世界模型时代需要什么样的推理基础设施"，它的回答方式是交付代码（github.com/alibaba-damo-academy/Inferix）、接口抽象和一个评测集，而不是实验证据。加速比、显存占用曲线、InterVBench 上各模型的 VDE 分数，这些在 v2 里都没有。作者在 roadmap 里列出的下一步包括：更复杂的 KV 管理与 block-sparse attention、把预训练全 attention 扩散模型微调成半自回归形态并做少步蒸馏、高并发部署、更复杂的分布式推理、更强的实时交互流式能力。

§ 8 — Take-aways ​

5 句话版：block diffusion 把视频生成变成了"带持久 KV Cache 的增量解码"，其推理负载与 LLM serving 和经典视频扩散都不同。Inferix 面向这个负载提供块级 KV 管理（分块访问 + 选择性取用 + 主存 offload + MLA latent store）、Ulysses/Ring 两类序列并行、DAX 量化、低开销 profiler 和 RTMP/WebRTC 流式输出。它统一了 MAGI-1、CausVid、Self Forcing 的推理接口，让不同 block diffusion 模型可以在同一套抽象下比较。配套的 InterVBench 收了 1000 条 50 秒以上的长视频，用 GPT-4o 每 2–3 秒生成 caption 并经三轮人工校验。它提出 VDE 系列指标专门度量质量沿时间轴的相对退化，补上了 VBench 只看整体质量的缺口。

3 句话版：世界模型的推理是"长上下文 + 持久 KV Cache + 实时交互"的新负载，vLLM 和 xDiT 都不对口。Inferix 用块级 KV 管理、序列并行、量化和流式输出把这个负载做成专用引擎，并统一了三个代表性 block diffusion 模型的接口。配套 InterVBench 用 VDE 指标衡量分钟级视频的时间漂移。

1 句话版：这是 block-diffusion 世界模拟的"vLLM 提案"，代码和评测集先落地，性能证据留待后续。

§ 9 — 最脆弱的假设 ​

最要命的假设是：block diffusion 会成为世界模拟的主流解码范式。Inferix 的每一个设计——块级 KV 管理、cross-attention cache 的按 chunk 清空、按 block 边界切分的流式输出——都直接绑在这个假设上。

它可能不成立的理由是具体的。第一，block 边界本身会引入伪影和运动不连续，这是半自回归范式的固有代价，如果社区通过"全 attention + 滑窗 + 少步蒸馏"把长视频做到同等长度且质量更好，block diffusion 的优势就被抹掉了。第二，KV Cache 单调增长这件事本身有上限，真正的分钟级到小时级模拟迟早需要显式记忆压缩或场景级重建，那时的状态对象未必还是 KV。第三，论文自己的 roadmap 里就写着"支持把预训练扩散模型微调成半自回归"，说明当下真正强的基座仍然是全 attention 扩散模型，半自回归更多是改造而非原生。

论文为这个假设提供的证据是范式层面的论证（图 1 的三种架构对比）和三个已有模型的存在性，没有提供"block diffusion 在同等算力下质量或速度更优"的实测。这个缺口在一篇纯工程报告里可以理解，但它确实让核心押注悬空。

§ 10 — 最小复现实验 ​

一周内可做且不需要复现整个引擎：

  • 数据：取 InterVBench 的评测切分，或自己从 HD-VILA-100M 里挑 30 条 50 秒以上的视频。
  • 实现：不碰 Inferix 的并行与量化，只跑一个开源 block diffusion 模型（Self Forcing 最轻），生成 30 条 60 秒视频。然后自己实现 VDE 的一个变体：把视频按 5 秒切段，逐段用现成打分器（如 LAION 美学分、CLIP 主体一致性）算分，以第一段为参考计算相对偏差并沿时间聚合。
  • 测量：VDE-Aesthetic 与 VDE-Subject 随时长的曲线；同时记录 KV Cache 显存占用随时长的增长曲线。
  • 判据：如果 VDE 曲线在 20–30 秒后明显上翘，而 VBench 整体分只轻微下降，就支持论文"VBench 看不见漂移"的主张；如果两条曲线走势基本一致，说明 VDE 只是 VBench 的换算，新指标价值有限。
  • 加做：把 KV Cache 强行截断成滑动窗口（只保留最近 N 个 block），看 VDE 恶化多少。这直接检验论文"KV Cache 必须留着才能缓解 drift"的前提。

§ 11 — 最强反例设计 ​

站在反对者立场，最有力的攻击是构造一个KV Cache 增长不是瓶颈的场景，从而证明 Inferix 优化的是错误的对象。

具体做法：取一个做过少步蒸馏的全 attention 视频扩散模型，用"重叠窗口 + 首帧条件"的朴素方式拼接生成 60 秒视频，不维护任何跨窗口 KV Cache。然后在同一张卡上与 block diffusion + 全量 KV Cache 的方案对比三项：端到端时延、峰值显存、VDE 五维得分。

如果朴素拼接方案在 VDE 上只差一点点，而时延和显存都明显更优，那么"必须维护持久 KV Cache"这个前提就被削弱了——drift 的主因可能是模型本身缺乏长程一致性建模，而不是 context 不够长，而给一个漂移的模型喂更多历史 KV 只会更贵不会更准。这提供了对"block diffusion 更连贯"这一结论的替代解释：它的连贯性可能来自训练时的 causal 约束，而非推理时的 cache。

另一类可预测失败：论文说换 prompt 时清空 cross-attention cache。在需要"前后两段共享同一角色但描述不同"的场景里，这个粗暴清空会直接导致角色跳变，而这恰恰是叙事型世界模拟的常见需求。

§ 12 — Follow-up Research Idea ​

局限：Inferix 把 KV Cache 当成一个只增不减、语义不透明的字节缓冲区来管理，管理策略是"分块 + 选择性取用 + offload"，全都是存储层的手段。但世界模拟里，历史的重要性是极度不均衡的——房间的几何结构应该永久保留，某片飘过的云不该占任何配额。

新 framing：把 KV Cache 管理重新表述为场景状态的有损压缩问题，而不是内存分页问题。引擎不再问"哪些 block 的 KV 该 offload"，而是问"这段历史里哪些信息对未来 block 的预测有增益"。

可借鉴的相邻工具：一是 3D 场景重建里的持久表示（把已观测的静态几何固化成显式结构，从 KV 里彻底移除，需要时以条件信号重新注入）；二是信息论里的率失真理论——给定显存预算 R，最小化未来预测误差 D，可以直接用生成模型自身的 log-likelihood 作为失真度量来给每个 KV 块估价；三是 LLM 侧的 KV 压缩工作（如 SnapKV、KIVI），但要把"attention score 高"这个代理换成"对未来帧预测的边际贡献"。

第一个实验：在 Self Forcing 上做离线的 KV 价值归因——生成一段 60 秒视频，事后逐块 mask 掉某个历史 block 的 KV 并重新生成后续，测量 VDE 的变化，得到每个块的"边际贡献分"。如果这个分数分布高度长尾（少数块贡献绝大部分），就说明率失真式的选择性保留有巨大空间；如果分布接近均匀，那么按时间衰减的滑动窗口已经接近最优，这条路就该放弃。
