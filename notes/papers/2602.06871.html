RFDM: Residual Flow Diffusion Model for Efficient Causal Video Editing ​

项内容
arXiv2602.06871
提交日期2026-02-06
作者Mohammadreza Salehi, Mehdi Noroozi, Luca Morreale, Ruchika Chavhan, Malcolm Chadwick, Alberto Gil Ramos, Abhinav Mehrotra
分类cs.CV
一句话把图生图扩散模型的前向加噪均值从零平移到「上一帧的预测」，使当前帧的去噪目标退化为帧间残差，从而用纯 2D 骨干逐帧因果地编辑任意长度视频。

所属教程：自回归视频生成

版本说明

本文基于 arXiv v2（2026-02-28 修订）全文撰写；v1 提交于 2026-02-06，CVPR 2026 接收。作者单位为 Samsung AI Center Cambridge，项目页 smsd75.github.io/RFDM_page。本站论文索引里该条目写作「变长、逐帧」，是中文描述而非编号错误。

§ 1 — 研究问题与重要性 ​

指令式视频编辑只给一句话（「把物体去掉」「把它变红」），不给 mask、不给光流。这个设定本身很好用，但现有方法几乎都建立在非因果的时序机制上：要么把整段视频塞进 3D 时空注意力，要么在所有帧之间做特征对齐或 token 合并。两个后果直接跟着来——输入长度必须固定，算力随视频长度增长。这就把两类真实场景排除在外：视频流式编辑，以及手机等资源受限设备上的部署。

自回归视频生成本来就是为变长输入设计的，因果注意力也天然高效，但这条路在编辑任务上几乎没人走。本文要回答的就是：能不能把一个纯 2D 的图生图（I2I）模型改造成逐帧因果的视频编辑器，且不增加任何相对图像模型的额外算力。这个约束很硬——它排除了所有靠加时序模块解决问题的方案。

§ 2 — 前人工作与不足 ​

零样本/少样本一派复用预训练的 T2I/I2I/T2V 模型：VideoDirector 在 T2V 上引导 DDIM 反演，FateZero 与 VideoGrain 改造 T2I，VidToMe 靠跨帧特征合并、Fairy 靠时空交叉注意力来强行拉齐帧间一致性，Tune-A-Video 则对每段视频微调骨干。论文对这一派的批评有两条且都成立：它们要么需要在推理时访问整段视频（因此无法自回归），要么需要逐视频微调，要么因为跨全部帧 token 的重时空注意力而算力高企。

训练一派依赖大规模数据与视频骨干（VACE、StyleMaster、EVE），可复现性差；InsV2V 用合成数据把图像模型适配到视频，代价是引入非自回归的时空注意力，算力随长度增长且在真实视频上表现更弱。

第三条批评落在评测上，这是本文相对独立的一击：现有 benchmark（TGVE、TGVE+）用编辑视频与文本 prompt 的 CLIP 相似度打分，这类指标既测不出「编辑是否在时间上被稳定保持」，也测不出faithfulness——即无关区域是否被保持不变。CLIP 文本相似度对「把整段视频都涂成粉色」和「只把液体涂成粉色」几乎无法区分，因此排序会失真。

§ 3 — 重建作者的思考路径 ​

约束先行：不能增加任何相对 I2I 的算力。这一条立刻排除了所有形式的跨帧注意力，剩下的唯一自由度是——改变模型的输入。

最朴素的做法是把上一帧的预测 y^​t−1​ 拼进输入通道。这确实零开销（只是多几个 channel），也确实能提升一致性，但监督信号没有变：网络仍然被要求从纯高斯噪声出发生成一整帧。视频的时间冗余在这里完全没被利用——相邻帧 90% 的内容是一样的，让模型每帧都从零重画一遍，既浪费又不稳定。

第二步的灵感来自图像逆问题里的 ResShift：与其从纯噪声出发，不如把前向过程的噪声均值平移到一个已有的、接近答案的估计上。在视频编辑里这个估计现成——就是上一帧的编辑结果。一旦这么做，采样的起点不再是白噪声，而是「带噪的上一帧预测」，模型要学的东西自动变成了两帧之差。这就给了一个很干净的分工：已经在 y^​t−1​ 里编辑好的区域（背景、两帧都出现的物体）只需平移过去；只有新出现的区域才需要真正依据 xt​ 与 prompt 做编辑。

第三步是自回归模型的老问题：训练时用什么作 y^​t−1​。用真值就是 teacher forcing，推理时会因分布错配而快速退化。Diffusion Forcing 给了现成答案——给不同帧采不同噪声水平，用模型自己在 t−1 的预测作条件，历史依然干净但来自模型自身的分布。

最后，做完实验会发现现有 benchmark 排不出真正想要的顺序（一个把整段视频都染色的方法可能拿到很高的 CLIP 文本分），于是顺手补了一套有真值参照的评测。

§ 4 — 核心 Intuition ​

逐帧独立跑 I2I 模型之所以闪烁，是因为每一帧都从一份独立的白噪声重新想象整个画面。把前向扩散的噪声均值从 0 平移到上一帧的预测，采样起点就变成「已经对了 90% 的图」，模型只需要补上那 10% 的差——一致性不是靠额外的注意力约束出来的，而是因为问题本身被换成了残差预测。整套改动只发生在噪声怎么加，网络结构与每帧算力一字未动。

§ 5 — 具体方法与完整 Pipeline ​

以「把一段 DAVIS 视频转成某种画风」为例，骨干是 SD1.5 或 SD3.5-Medium。

  1. 首帧：y^​−1​=0，退化为标准 I2I，从纯噪声用 DDIM 采样，条件是输入帧 x0​ 与 prompt p，走 CFG。
  2. 后续帧的加噪：不再是 yts​=αs​yt0​+σs​ϵ，而是把噪声均值移到 y^​t−1​，即 ϵ 从 N(0,I) 换成 N(y^​t−1​,I)。
  3. 额外条件：除了这个带偏移的噪声输入，还把当前输入帧 xt​ 与干净的 y^​t−1​ 沿通道拼进去，prompt 走 cross-attention。消融显示这个「再拼一次」的冗余输入很重要。
  4. 训练时的历史来源：采用 Diffusion Forcing——各帧独立采样噪声水平，y^​t−1​ 取自模型在 t−1 的去噪预测而非真值；自回归损失跨 5 帧展开，且梯度在整条链上回传（unrolling）。
  5. 推理时的关键帧刷新：y^​t−1​ 不是每帧都更新，而是每 Δ=3 帧刷新一次，用来抑制误差累积。
  6. 训练配置：Señorita-2M（首个大规模真实视频编辑数据集，含全局风格迁移、局部风格迁移、物体移除、物体添加、物体替换五类），按 80%/15%/5% 划分（正文两句对 validation 与 test 的比例写反，属笔误）。8 张 A100、45k 步、batch 8、梯度累积 2、lr 1×10−4。

§ 6 — 核心数学推导 ​

标准图像编辑扩散的前向过程是 q(ys∣y0)=N(αs​y0,(σs​)2I)，训练目标是让去噪网络预测 y0。把它直接搬到视频上，只是把去噪网络多条件化在 y^​t−1​ 上，前向过程不变——论文称之为 frame prediction 基线。

RFDM 改的是前向过程本身。定义帧间残差 mt0​=y^​t−1​−yt0​，则

q(yts​∣yt0​,y^​t−1​)=N(αs​yt0​+σs​y^​t−1​,(σs​)2I)=N(γs​yt0​+σs​mt0​,(σs​)2I)

写成采样形式更直观：

yts​=αs​yt0​+σs​y^​t−1​+σs​ϵ=αs​yt0​+σs​ϵ^,ϵ^∼N(y^​t−1​,I)

也就是说，全部改动可以概括成一句话：把采样噪声的均值从 0 换成上一帧的预测。这带来一个重要性质——当 s→1（噪声最大）时，yts​ 趋近于「加了噪的 y^​t−1​」而不是纯白噪声，因此去噪轨迹的起点天然落在上一帧附近，网络只需要沿着残差方向走。目标函数 argminθ​∥y^​θ​(yts​,y^​t−1​,xt​,p,λs​)−yt0​∥ 与基线完全相同，改变的只是输入分布。这是本方法零额外算力的根本原因。

需要指出中间那一步的系数：把 y^​t−1​=mt0​+yt0​ 代入可直接得到 γs​=αs​+σs​，而论文写的是 γs​=1−(σs​)2+σs​。两者相等当且仅当 αs​=1−(σs​)2，这既不是方差保持约定（αs2​+σs2​=1）也不是 rectified flow 约定（αs​+σs​=1）。论文未声明所用的噪声调度约定，此处判为排版或约定未说明（基于证据的推断，不影响方法本身）。

新引入的两个指标定义如下：

ViDreamSim=T1​t=1∑T​d(yˉ​t0​,yt0​),ErrAccu=T−11​t=1∑T​d(yˉ​t0​,yˉ​00​)

d 取 DreamSim 感知距离，yˉ​ 是输出、y 是真值。前者度量与真值的逐帧偏离（faithfulness），后者度量输出自身随时间偏离首帧的程度（drift）。ErrAccu 的求和范围 t=1..T 与分母 T−1 不匹配，属笔误。

§ 7 — 实验设计与结论 ​

问题一：换掉前向过程真的有用吗？ 消融在 SD1.5 骨干、Señorita 全局风格迁移验证集上做，报 warping error（时序一致性，越低越好）与 ErrAccu。核心一格是 (f)：frame prediction 得 0.009 / 0.09，residual-flow 得 0.009 / 0.07。时序一致性完全相同，只有误差累积改善 0.02。 相比之下，(a) 自回归损失覆盖帧数从 0 到 5 把 warping error 从 0.068 压到 0.007（近 10 倍）、ErrAccu 从 0.21 压到 0.07；(b) 额外拼入干净的 y^​t−1​ 把 0.027/0.14 改善到 0.009/0.07。也就是说，方法名里的那个组件在这两项指标上贡献最小。

作者为 residual-flow 补了一个更有说服力的证据 (g)：从 DAVIS 取 10 段视频，用 Qwen-Image-Edit 编辑首帧后交给两个模型往后传播，测分割跟踪指标。frame prediction 得 33.3 / 24.9 / 29.1，residual-flow 得 50.6 / 36.4 / 43.6（三列由前两列均值可验证为 J / F / J&F）。这条说明残差形式确实带来了更强的编辑传播能力，只是这种能力没有被 warping error 捕捉到。

其余消融：(c) teacher forcing 的 ErrAccu 反而更低（0.06 vs 0.07），但第三项（faithfulness）更差（0.38 vs 0.35），作者据此选 Diffusion Forcing——这个取舍被如实报告了。(d) 关键帧刷新间隔 Δ=0（永远用首帧输出作条件）拿到最低的 ErrAccu 0.04，但 warping error 最差 0.018；Δ=1 时 warping 最好（0.008）而 ErrAccu 最差（0.16）；折中取 Δ=3。(e) 打开梯度 unrolling 从 0.011/0.10 改善到 0.009/0.07。

问题二：与现有方法比如何？ TGVE 与 TGVE+ 上 RFDM3.5 的 CLIPFrame 两个 benchmark 上都是最高（0.965 / 0.970），TGVE 的 ViCLIP$_{out}$ 0.284 也最高（EVE 与 InsV2V 并列 0.262）；但两个 benchmark 的 PickScore 都不占优（TGVE 20.66 对 EVE/InsV2V 的 20.76，TGVE+ 20.52 对 EVE 20.88、STDF 20.60），TGVE+ 的 ViCLIP 0.250 与 RAVE 持平、略低于 EVE 的 0.251。正文写「6 项指标里领先 4 项」，按上述逐项对照我数到 3 项明确领先、1 项持平、2 项落后。作者对 PickScore 的落后给了解释：EVE 是 4.4B 3D 骨干且用 34M 视频训练，而 SD3.5 只有 2.5B、Señorita 只有 2M。

问题三：新 benchmark 排出了什么不同的顺序？ Señorita benchmark 上（三任务平均）RFDM1.5 得 DVS 0.43 / MLLM-Judge 6.60 / ViDreamSim 0.23 / warping 0.010，RFDM3.5 得 0.48 / 7.37 / 0.20 / 0.009，两者在 DVS、MLLM-Judge、ViDreamSim 三项上全面领先 Fairy（0.32/2.87/0.63/0.043）与 VidToMe（0.32/3.10/0.46/0.007）。但 warping error 上 VidToMe 的 0.007 优于 RFDM，作者的解释是 VidToMe 输出更平滑但更偏离真值——这个解释与它的 ViDreamSim 0.46 一致。

这里有一处需要如实指出的量级问题。当把 Fairy 换成本文预训练 UNet（Fairy*）后，它从 0.32/2.87/0.63 变成 0.40/3.98/0.29——DVS 与 RFDM1.5 的差距从 0.11 缩到 0.03，ViDreamSim 从 0.40 缩到 0.06。换句话说，Señorita 上大部分的领先来自骨干与训练数据，真正稳定拉开的只有 GPT-4o 打的 MLLM-Judge（6.60 对 3.98）。另一方面 VidToMe* 反而全面变差（MLLM 3.10→1.77、ViDreamSim 0.46→0.59），说明 * 变体并非干净的对照——那个 UNet 是配合 RFDM 的条件方案训出来的。

问题四：效率如何？ A100 上生成 16 帧，RFDM1.5 延迟 8、显存 2 GB；RFDM3.5 延迟 13、显存 6 GB。Fairy 是 13 / 77 GB，TokenFlow 128 / 11，RAVE 92 / 9，VidToMe 86 / 9，STDF 300 / 20。即 RFDM3.5 与 Fairy 同延迟但省约 13 倍显存，相对其余基线延迟低约 4 倍；RFDM1.5 相对 TokenFlow/RAVE 快约 12–16 倍、省 4–5 倍显存。这是全文最扎实的一组数字。

作者自陈的局限也很具体：时序记忆太短，对「改变视频中的动作」这类受运动约束的编辑无能为力，建议的补救是加 KV cache。

§ 8 — Take-aways ​

5 句话版：指令式视频编辑普遍依赖非因果时序机制，输入长度固定且算力随长度增长，堵死了流式与端侧场景；RFDM 的做法是把 I2I 扩散的前向加噪均值从 0 平移到上一帧的编辑结果，使去噪目标自动退化为帧间残差，网络结构与每帧算力完全不变；训练用 Diffusion Forcing 消除暴露偏差、跨 5 帧展开并回传梯度，推理时每 3 帧刷新一次条件帧以平衡一致性与漂移；在 A100 上编辑 16 帧只需 2–6 GB 显存，比同类方法快 4–16 倍，TGVE/TGVE+ 的帧间一致性指标最高、CLIP 类语义指标与闭源 3D 模型 EVE 互有胜负；作者另建了带真值参照的 Señorita benchmark 并引入 ViDreamSim 与 ErrAccu，但消融显示 residual-flow 本身对 warping error 零贡献、对 ErrAccu 只值 0.02，主要增益来自「拼入上一帧预测 + 多帧自回归损失」。

3 句话版：把噪声均值平移到上一帧的预测，就把逐帧重画变成了逐帧补差，零额外算力地把图像编辑模型变成因果视频编辑模型。效率优势是数量级的（显存降 13 倍、延迟降 4–16 倍），质量上与需要全视频访问的方法可比。residual-flow 的独立贡献主要体现在编辑传播/跟踪能力上，而非常规的时序一致性指标。

1 句话版：从上一帧的答案开始加噪，模型就只需要学两帧之差。

§ 9 — 最脆弱的假设 ​

最脆弱的是：Señorita 的真值可以作为衡量 faithfulness 的可靠参照。本文在 Señorita benchmark 上的三项主力指标——ViDreamSim（到真值的感知距离）、DVS（输入→输出与输入→真值的方向相似度）、MLLM-Judge（GPT-4o 对照真值打分，prompt 里明写「10 分表示比真值更好」）——全部锚定在同一份真值上。而这份真值不是人工标注，是 Señorita 用分割 + 修补 + 跟踪的多阶段流水线自动生成的。

论文自己在补充材料 §7.2 里承认了这一点：Señorita 的真值「偶尔含有伪影、闪烁或不干净的边界」，RFDM 的输出「常常比真值看起来更自然」。这句自述直接动摇了三项指标的效度——如果输出比参照更好，那么「到参照的距离更小」就不再等价于「更好」。

叠加的问题是训练-测试的分布优势：RFDM 在 Señorita 的 80% 训练划分上微调过 45k 步，而 Fairy、VidToMe 是零样本方法。作者已经意识到并给出了 * 变体作为部分控制，而这个控制恰恰给出了最有信息量的读数——Fairy 换上本文 UNet 后，DVS 与 ViDreamSim 的差距各缩水到原来的四分之一左右。缺失的证据是人类评测：全文没有任何人工偏好实验，MLLM-Judge 与人类判断的相关性也未被验证，而它正是 * 控制之后唯一还保持大幅领先的指标。

如果这条假设不成立，本文的第三项贡献（「新 benchmark 能更好地按 faithfulness 排序方法」）直接失效，前两项贡献的证据强度也会大幅下降——虽然效率数字不受影响。

§ 10 — 最小复现实验 ​

一周可做，不需要 45k 步训练。目标是把「residual-flow 前向过程」与「拼入上一帧预测」这两个纠缠在一起的因素分开。

  • 取 SD1.5 的 InstructPix2Pix 权重，在 Señorita 训练划分里抽 5 万对样本，训四个变体各 5k 步（8 卡 A100 约一天）：(A) 逐帧独立 I2I；(B) 只把 y^​t−1​ 拼入通道，前向过程不变；(C) 只做噪声均值平移，不拼通道；(D) 两者都做（= RFDM）。四者的自回归损失帧数统一固定为 3，排除消融 (a) 的干扰。
  • 在 Señorita 测试划分与 DAVIS 上各评一次，测四样：warping error、ErrAccu、ViDreamSim、以及消融 (g) 的 DAVIS 跟踪 J&F。
  • 判据：论文的消融 (b) 与 (f) 分别只做了「去掉通道拼接」和「换回 frame prediction」两个单点，无法确定 (C) 单独是否有效。若 (C) 相对 (A) 在跟踪指标上已有大幅提升而 (B) 没有，则残差形式的价值确实在编辑传播上；若 (B) 与 (D) 接近而 (C) 明显更差，则噪声平移只是在通道拼接之上的一个小修正，方法的实际核心是「把上一帧的答案喂回去」这件更朴素的事。

§ 11 — 最强反例设计 ​

反对者最有力的攻击是给出替代解释：RFDM 在一致性类指标上的领先，来自它在结构上更难产生帧间变化，而非它更好地理解了编辑该如何跨帧传播。三条证据支持这个读法。

其一，TGVE/TGVE+ 上 RFDM 唯一稳定夺冠的指标是 CLIPFrame——相邻帧的 CLIP 特征相似度。而 RFDM 的采样起点就是「加了噪的上一帧输出」，训练目标就是预测两帧之差。一个从上一帧出发、只学小增量的模型在「相邻帧有多像」这个指标上占优，几乎是构造性的，不构成独立证据。

其二，论文自己引入的 ErrAccu 度量的是「第 t 帧输出与第 0 帧输出的感知距离」。这个量在完全静止的视频上取 0，因此它同时惩罚漂移与合法的场景变化。消融 (d) 把这一点暴露得很清楚：Δ=0（永远拿首帧输出当条件）拿到全表最低的 ErrAccu 0.04，而它恰恰是时序一致性最差、显然也是最不该被推荐的配置。作者选 Δ=3 正是因为知道这个指标不能单独用，但主表里 ErrAccu 仍以「越低越好」呈现。

其三，也是最直接的一条：消融 (f) 显示 residual-flow 与 frame prediction 的 warping error 逐位相同（0.009），ErrAccu 只差 0.02。方法名字里的组件在两个主消融指标上几乎不可区分。作者用 DAVIS 跟踪实验（29.1 → 43.6）挽回了这一点，但那个实验只有 10 段视频、首帧编辑由第三方模型 Qwen-Image-Edit 提供，且没有报方差。

可预测会失败的场景由作者自己点明并可以进一步锐化：所有需要改变运动本身的编辑（改变动作、加速/减速、改变轨迹）。因为 RFDM 的条件只有前一帧（且每 3 帧才刷新一次），它没有任何机制表征「这段视频正在做什么动作」。设计一个决定性实验很直接：在 Señorita 的 object swap 与 object addition 两类（论文训练了数据集但评测中排除了这两类）上评一次，特别是被替换物体与原物体运动学不同的样本。若性能相对 Fairy/VidToMe 明显反转，就说明当前的强项严格局限于「外观级、逐帧局部」的编辑。

§ 12 — Follow-up Research Idea ​

驱动局限：RFDM 的记忆只有一帧，且这一帧还每 3 步才刷新。Δ 这个超参把「一致性」与「不漂移」变成了一个必须手工权衡的标量旋钮——消融 (d) 的四行数据里，两个目标在 Δ 上的最优点完全相反（Δ=1 时 warping 最优、ErrAccu 最差；Δ=0 时反之）。作者提出的补救是加 KV cache，但那只是把「一帧」换成「若干帧」，权衡的结构没变。

新 framing：把条件帧的选择从固定间隔改成由内容驱动的锚点重定位——不是问「隔几帧刷新一次」，而是问「当前帧的哪些区域应当从哪一个历史锚点继承」。这实际上把视频编辑重述为一个稠密对应（dense correspondence）问题：编辑结果的传播沿着像素的运动轨迹进行，而不是沿着时间轴均匀滑动。这个重述的价值在于它给了 Δ 一个原则性替代：被遮挡后重新出现的区域应当回溯到它最后一次可见的那个锚点，而不是从 3 帧前的模糊结果里长出来——后者正是论文限制在「外观级编辑」的根本原因。

可借鉴的相邻工具：点跟踪与长期对应（CoTracker/TAP 一系）已经能给出跨遮挡的稠密轨迹，而消融 (g) 恰好用 DAVIS 分割跟踪证明了 residual-flow 本身就带有跟踪能力——说明模型内部已经隐含了这类对应，只是没有被显式利用。另一侧，视频编解码里的运动补偿预测（motion-compensated prediction）几十年来解决的就是同一个问题：以运动场对齐参考帧、只编码残差。RFDM 目前做的是「不做运动补偿的残差编码」，而编解码领域早已知道这在有运动时效率会崩。

第一个实验：保持 RFDM 的一切不变，只把条件输入从 y^​t−1​ 换成 W(y^​t−δ​)——用一个现成的光流/点跟踪模型把某个更早的锚点 warp 到当前帧坐标系，并给出可见性掩码；被遮挡区域的噪声均值退回 0（即在那里做纯 I2I）。评测分两组 prompt：低运动组与高运动组（可用光流幅值自动划分 Señorita 测试集）。若运动补偿版本在高运动组上把 warping error 与 ErrAccu 同时改善——而不是像 Δ 那样只能二选一——就证明当前方法的权衡不是本质的，而是「用时间邻近代替空间对应」这一近似的产物。若两组都无改善，那也是有价值的负结果：说明 SD 骨干在小残差上的鲁棒性已经足以吸收未补偿的运动，从而解释了为什么如此简单的均值平移就能奏效。
