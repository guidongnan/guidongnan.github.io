Cosmos 3: Omnimodal World Models for Physical AI ​

项内容
arXiv2606.02800
提交日期2026-06-01（v4 修订于 2026-06-23）
作者NVIDIA: Aditi, Niket Agarwal, Arslan Ali, Jon Allen, Martin Antolini, Adeline Aubame, Alisson Azzolini, Junjie Bai, et al.
分类cs.CV, cs.AI, cs.LG, cs.MM, cs.RO
一句话把一个因果自注意力的 AR 推理塔与一个全注意力的扩散生成塔做成同一 transformer 每层的两套参数，只在共享 self-attention 处相遇（扩散 token 单向读取 AR 上下文，AR 永不被扩散 token 更新），再用带绝对时间调制的 3D MRoPE 把语言、图像、视频、音频、动作钉在同一物理时间轴上。

§ 1 — 研究问题与重要性 ​

Physical AI 的技术栈目前是碎片化的：视觉语言模型负责理解、视频生成模型负责合成、世界模拟器负责推演未来、世界-动作模型负责输出策略。这四类模型各自有独立的架构、独立的预训练、独立的评测，彼此之间只能通过外部胶水代码串起来。对机器人、自动驾驶、智能空间这类应用来说，这种碎片化的代价很直接——同一段视频要被不同的编码器编码好几遍，理解到的东西无法直接被生成模块使用，生成出的未来也无法直接反馈给推理模块。

Cosmos 3 的 claim 是这四类能力可以被一个模型吸收。论文摘要的措辞是 "effectively subsuming vision-language models, video generators, world simulators, and world-action models into a single framework"。这个 claim 之所以重要，不只是省参数，而在于它假设理解与生成共享同一套关于物理世界的表示——如果成立，那么用视频数据学到的动力学知识就应该能直接改善推理，反之亦然。这是一个可以被证伪的架构假设，而不是一个纯粹的工程整合。

§ 2 — 前人工作与不足 ​

Cosmos 家族本身是最直接的前作。Cosmos（2501.03575）确立了「用世界基座模型服务 Physical AI」的框架，Cosmos-Predict2.5（2511.00062）仍然是生成与推理分属不同模型的设计——Cosmos-Reason1 负责理解，Predict 模型负责生成，两者通过接口耦合。这正是 Cosmos 3 要合并掉的边界。

论文的 §7 把相关工作分成六束，其中与它自己的架构最直接对话的是最后一束 omnimodel。它先把世界模型分成两类：以 PlaNet、Dreamer、JEPA 为代表的预测性潜世界模型学紧凑隐状态以降低规划成本，以 Sora、Cosmos 系列为代表的生成式世界模型把预测出的未来直接暴露为可检验的多模态仿真。论文对前者的批评是它们为紧凑预测或下游控制而优化，而不是高保真多模态仿真；对后者的批评是它们主要把视频当输出模态，而世界仿真需要更强的契约：保持物体同一性与恒存性、尊重时间因果、暴露可控的干预因子，并在同一场景受到不同干预时保持一致。

在统一架构这一束上，论文点名的是 Unified-IO 2、Chameleon、Qwen-Omni、Transfusion（单 transformer 上混模态序列，文本用下一 token 预测、图像用扩散）、Mixture-of-Transformers（把模态专属参数这个模式显式化）与 BAGEL（decoder-only 的统一多模态预训练）。论文在 §2.3 直接承认自己的 decoder-layer 结构与 BAGEL 相似，并把差异定位在训练策略、位置编码与能力覆盖三处。它对整束工作的批评很窄也很具体：现有 omnimodel 仍以文本-图像建模或通用媒体生成为主，对物理世界动力学、动作条件生成、逆动力学与具身控制的投入很少。

§ 3 — 重建作者的思考路径 ​

下面的重建部分基于论文明写的设计理由，部分是推断，已分别标注。

先看一个在 Cosmos 3 之前就已成立的经验事实：自回归 transformer 在语言与视觉理解上是压倒性的选择（因果注意力、下一 token 预测、可变长度输出），而扩散 transformer 在高保真视觉生成上是压倒性的选择（全注意力、迭代去噪、连续 latent）。任何试图用其中一种统一另一种的做法都要付出可以预见的代价。

第二个事实是：两种范式真正冲突的地方其实很局部——注意力掩码（因果对全）与训练目标（下一 token 对去噪）。论文的 Fig. 5 把这一点画得很直白：同一层里 AR token 与 DM token 走各自独立的 LayerNorm 与 MLP，只在共享的 self-attention 算子处相遇。这直接指向 MoT。

第三个事实是位置编码的角色被低估了，而论文在这里做了一个比"用 3D MRoPE"更细的动作。Qwen3-VL 那套原始 3D MRoPE 的时间分量记录的是离散 token 索引，这对纯理解任务够用；但当视频、音频、动作在同一次前向里以不同采样率同时生成时，token 索引与物理时间就脱钩了。于是必须把时间轴换成绝对时间。这是一条只有在真的把四种模态塞进同一序列后才会撞上的工程细节。

最后是 Physical AI 场景本身给出的约束：机器人需要边缘实时推理，数据中心需要最高质量的合成数据生成。这直接导向一个规模阶梯而非单一模型。

§ 4 — 核心 Intuition ​

理解和生成之所以要用不同的架构，冲突只发生在两处——注意力能不能看未来、目标是预测下一个 token 还是去噪。把这两处做成同一骨干每层的两套参数，只在共享注意力处相遇，一个模型就能同时是 VLM、视频生成器、世界模拟器和策略模型，而共享的绝对时间 3D MRoPE 保证它们谈论的是同一个时空。

§ 5 — 具体方法与完整 Pipeline ​

编码器。 视觉走两条独立通路：理解用一个经过视觉-语言对齐预训练的 ViT（16×16 patch，再用两层 MLP 把 2×2 个 token 合并并投到 transformer 的 latent 空间），并按 Qwen3-VL 的做法用 DeepStack 聚合多层 ViT 特征、在视频帧之间插入文本时间戳；生成用 Wan2.2-TI2V-5B 的视频 VAE，时间 4× 压缩、空间 32×32 压缩（先 16×16 再 2×2 patch merge）。ViT 与骨干联合训练，VAE 全程冻结。音频用 48 kHz 立体声 VAE，hop size 1920，即每秒 25 个 token，同样冻结。

动作作为一等模态。 论文把动作定义为「导致世界状态改变的因果变量」，动作 token at​ 表示从 vt−1​ 到 vt​ 的转移。为了避开各家控制器的 PID 参数与底层执行接口，ego pose 与 effector pose 都表示成状态差分导出的伪动作：对相邻的两个 SE(3) 位姿取相对变换 ΔTt​=Tt−1−1​Tt​，旋转用 6D 表示。grasp state 例外，它直接编码当前时刻的操作状态（机械手的指尖位置、夹爪的开合值）而不是差分。不同 embodiment 的动作向量长度不同，用按域分开的输入/输出投影矩阵 z=Win(k)​x+bin(k)​ 映射到统一的 dmodel​，骨干共享。解码时把预测的 6D 旋转经 SVD 投回 SO(3)。

token 排布。 序列固定为「AR 子序列在前、扩散子序列在后」。AR 子序列装语言 token 与 ViT 编码的图文 token，扩散子序列装 VAE 编码的图像/视频 token 以及音频、动作 token；扩散子序列内部，干净的条件 token 排在带噪的目标 token 之前，并按视觉、音频、动作的顺序排列。所有任务共用这一种排布，任务差异只体现在哪些 token 是干净的、哪些是带噪的。例如文生视频加音频是 ST2V+Audio​=[SAR​,v~1:N​,s~]，而 SV2V​=[SAR​,v1:P​,v~P+1:N​] 在 P=1 时是 image-to-video、P>1 时是 video-to-video。动作的三种模式也是同一套排布的不同「干净/带噪」组合：正动力学给干净动作、去噪视觉；逆动力学给干净视觉、去噪动作；policy 模式两者同时去噪。

MoT 双塔。 每个 decoder layer 有两套参数：reasoner 塔处理 AR 子序列，generator 塔处理扩散子序列。两塔各有自己的 LayerNorm、attention 投影矩阵与 FFN，都从同一个预训练 VLM 的权重初始化。它们只在共享的 self-attention 处相遇，而且是不对称的：AR 的 query 只对 AR 的 key/value 做因果注意力，扩散的 query 对两段拼接后的 key/value 做双向注意力。论文明确指出 AR token 永远不会被扩散 token 更新。

规模。 Edge 4B 建在一个 28 层、hidden 2048、16 注意力头 8 KV 头、FFN 9216 的 2B dense transformer 上，从零训练（大体沿用 Qwen3-1.7B 架构，但去掉 QK normalization、FFN 激活换成 ReLU-squared）；Nano 16B 建在 Qwen3-VL 8B 上（36 层、hidden 4096、FFN 12288）；Super 64B 建在 Qwen3-VL 32B 上（64 层、hidden 5120、64 头、FFN 25600）。本文只发布 Nano 与 Super，Edge 留待后续 release。

训练。 Reasoner 先单独训：2200 万预训练样本加 220 万 SFT 样本的图文 / 视频文本 / 纯文本混合。然后训 Generator，而且只更新生成侧参数，reasoner 塔全程冻结，以保住语言与视觉理解能力。生成器预训练的规模是 Nano 31.05 T token（1024 张 GB200）、Super 17.86 T token（2048 张 GB200）；mid-training 阶段 Nano 2.4 T、Super 1.9 T，此时引入动作与 video transfer 两类新监督，混合比例是 T2I 10%、视频 32%、视频加音频 8%、动作 25%、通用 transfer 20%、驾驶 transfer 5%。所有生成模态共用 rectified flow 目标，动作的 loss 额外乘 10×，因为归一化动作向量的逐元素 MSE 太小。

一个具体的端到端例子。 用户给一句短指令，Reasoner 先当 prompt upsampler：它接收四段标签化的输入（instructions / description / task_constraints / output_json_template），输出一份 schema 受限的 JSON 场景程序，里面写明主体、空间布局、光照、镜头行为、时间顺序、音频线索，以及分辨率、宽高比、时长、帧率这些生成控制项。这份 JSON 再送进 Generator 渲染。论文强调这一步的价值在于把生成器必须条件化的隐变量显式暴露成可检查的字段，而不只是把 prompt 写长。推理时 upsampler 可以由 Claude Opus 4.6 或 Cosmos 3 Reasoner 自己担任。

§ 6 — 核心数学推导 ​

两塔的注意力。 论文把统一的关键写成两个式子。AR 子序列内部是标准的因果自注意力

OAR​=Attncausal​(QAR​, KAR​, VAR​),

扩散子序列则是双向的，但 key/value 是两段的拼接

ODM​=Attnfull​(QDM​, [KAR​;KDM​], [VAR​;VDM​]).

这个非对称设计是整篇最值得注意的一处工程判断。它保证信息只能从 AR 流向 DM：生成可以任意读取推理产生的上下文，而推理的自回归性质完全不受污染，因此预训练 VLM 的文本生成能力可以原样保留。代价也很明确：在同一次前向里，生成结果无法反过来影响推理。§9 会回到这一点。

生成目标。 所有非语言模态共用 rectified flow matching，预测速度场而非噪声；语言侧仍是标准的因果语言建模 LAR​=−∑t​logpθ​(xt​∣x<t​)。总损失是各模态速度 MSE 的加权和。

3D MRoPE 与绝对时间调制。 每个 token 拿一个 (t,h,w) 三元组：语言 token 令 t=h=w 同步递增，退化成 1D RoPE；视频 token 在三个轴上都变化；音频与动作 token 只带时间坐标，h=w=0。问题在于一个时间单位在不同模态、不同采样率下代表的物理时长不同。论文定义每秒时间步数 TPS：视频的 TPS 是帧率除以 VAE 的时间压缩率 4，音频是 48000/1920≈25，动作就是它自己的采样频率。取 24 FPS 作基准，TPSbase​=24/4=6，于是每个时间单位的实际增量是

δt=TPSTPSbase​​.

这样等长的真实时间就占据等长的位置区间，一个动作 token 与它对应时刻的视频 token 自然落在同一个 t 上。这正是论文相对 Qwen3-VL 原始 MRoPE（时间分量只记录离散 token 索引）的实质改动。

还有一个不体面但很实用的细节：直接让扩散 token 从最后一个 AR token 的时间偏移开始，会让前几帧出现过饱和与棋盘格伪影，在 Super 上尤其明显。论文的假设是最后一个语言 token 与第一帧的视觉 token 拿到了几乎相同的时间嵌入。解法是在 AR 与 DM 之间插一个固定的时间间隙，把后续所有视觉、音频、动作 token 的时间索引整体平移，间隙取 15000。不改架构也不加可学习嵌入，纯靠位置空间制造分隔信号。

§ 7 — 实验设计与结论 ​

问题一：统一骨干能不能在理解侧打过专用 VLM？ Table 1 的汇总里，Cosmos3-Super 的 general 分是 73.7、robotics 57.8、smart infra 62.6、driving 79.3。对照组里 Qwen3-VL-32B 是 72.8 / 52.6 / 56.1 / 40.7，闭源的 Gemini 3.1 Pro 是 77.5 / 58.2 / 58.6 / 47.2。通用维度上 Cosmos 3 输给 Gemini，但在 driving 上以 79.3 对 47.2 拉开三十多分。这个分布很能说明问题：收益集中在 Physical AI 专有领域，而非通用多模态理解。

问题二：生成侧的物理合理性如何？ Physics-IQ 把物理一致性单独拎出来当唯一评测轴，用真实起始上下文条件化并与真实物理续接对比。Cosmos3-Super 的 I2V 直接分是 43.8，配 WMReward 的 best-of-N 重排后到 48.9；对照的 Sora2 是 42.3 / 46.4、Wan2.2-A14B 是 38.3 / 44.4。V2V 上 Cosmos3-Super 是 59.7 / 63.4，Magi-1 是 56.0 / 62.6。

问题三：自动指标够不够？ 论文自己给了否定答案，而且给得很实在。它指出同一批 prompt 上 T2V 生成器在人评上跨度约 10 分，在可比的 PAIBench-G 总分上只有约 4 分；还直接写明公开的 PAIBench-G 图生视频榜单结果不可复现，因此自己重跑。于是它另建了 Cosmos HUE：每段视频由 VLM 生成至多 16 条原子二元问题，每个（视频，问题）对由两名标注者独立评判，分歧交第三名 QC 仲裁，Unclear 一律计为 No，得分是 Yes 的比例。T2V 榜上 Veo-3.1 领先（91.3），Seedance-1.5-Pro 90.0，Cosmos3-Super 是最好的开源生成器（89.3），Wan2.2-A14B 88.2，Cosmos3-Nano 87.6，而真实视频只有 93.6。作者把 GT 到 100 的差距明确当作题库仍需打磨的信号，而不是假装满分。I2V 上 Veo-3.1 89.7、Cosmos3-Super 89.6，差 0.1。

问题四：能不能后训练成机器人策略？ 这是最硬的一条。Cosmos3-Nano-Policy-DROID 在 RoboLab-120 上，specific 指令档的平均成功率是 39.7%（每任务 10 次 rollout），对比 π0.5​ 的 28.1% 与 DreamZero 的 25.2%；vague 档 20.6% 对 15.2% / 14.9%。同一个模型与同一组超参提交到 RoboArena（真实机器人、众包双盲 A/B）在 2026-05-30 排第一，提交到 MolmoSpaces 在 2026-06-20 以 39.0% oracle 成功率排第一，未做任何针对性调参。正动力学侧，从 mid-training 检查点后训练得到 25.52 dB（Nano）与 26.04 dB（Super），对比 Ctrl-World 的 22.99 dB。

问题五：mid-training 到底买到了什么？ LIBERO-10 上的对照很干净：从 mid-training 检查点起步（MT-init）在 500 步就到 24.6% 成功率，而从 pre-training 检查点起步（PT-init）此时仍是 0.0%；2000 步时两者分别是 97.4% 与 95.2%。统一动作 mid-training 买到的主要是收敛速度，终点差距不大。

外部榜单。 摘要里那三条定位在正文里有了日期：Artificial Analysis 文生图榜 2026-05-28 快照，Cosmos3-Super-Text2Image 在开源权重里第一、含闭源第四；同日的图生视频榜（无音频），Cosmos3-Super-Image2Video 开源第一、总榜第 22，论文称其与 Veo 3.1、Wan 2.5 这类闭源产品持平。带日期的快照比摘要里那句「在撰写技术报告时」要可引用得多，但这类持续更新的众包榜单仍然无法被后来的读者复现。

§ 8 — Take-aways ​

五句话版。 Cosmos 3 把一个推理塔与一个生成塔做成同一 transformer 每层的两套参数，两塔都从 Qwen3-VL 初始化，只在共享 self-attention 处相遇，且信息只允许从 AR 流向扩散。带绝对时间调制的 3D MRoPE 把视频、音频、动作按 δt=TPSbase​/TPS 钉在同一物理时间轴上，动作则统一成相对位姿伪动作加 grasp state、用按域分开的投影接入共享骨干。实验上它在 Physics-IQ、PAIBench-G、RoboLab、RoboArena、MolmoSpaces 上都取得开源最优或总体最优，其中 RoboLab specific 档 39.7% 对 π0.5​ 的 28.1% 是最硬的一条。但它自己的人评榜显示 T2V 仍落后 Veo-3.1（89.3 对 91.3，真实视频 93.6），而唯一一个直接验证「统一」的消融只测出 1 到 2 分的增益。

三句话版。 理解与生成的架构冲突只发生在注意力掩码与训练目标两处，把它们做成同一骨干的两塔即可共存。共享的绝对时间 3D MRoPE 让文本、图像、视频、音频、动作落在同一时空坐标系里，一个模型因此可以同时做 VLM、视频音频生成、正逆动力学与机器人策略。代价是推理塔在生成训练中全程冻结，“互相增益”在结构上只能是单向的。

一句话版。 把 Physical AI 需要的四类模型压进一个 MoT 骨干的两套塔参数里，用绝对时间位置编码把它们对齐。

§ 9 — 最脆弱的假设 ​

最脆弱的假设仍然是：理解与生成共享骨干会互相增益。区别在于现在可以拿论文自己的数据来称量它，而称出来的结果对这条叙事不太有利。

第一，方向是单向的，而且是设计使然。生成器预训练时只更新生成侧参数，reasoner 塔全程冻结，论文给的理由是冻结才能保住预训练 VLM 的语言与视觉理解能力。§6 那个非对称注意力做了同一件事的架构版：AR token 永远不被 DM token 更新。两条设计叠在一起，意味着「用视频数据学到的动力学知识反过来改善推理」这条路在 Cosmos 3 里是被结构性关闭的。全文也没有任何一个实验测量生成训练对理解分数的影响。

第二，保留下来的那个方向，增益是一位数。附录 E.1 做了唯一一个直接的对照：同样的 Cosmos3-Nano 架构、生成器塔都从零训练、都跑 90K 步 256 卡，只改理解塔的初始化——一边用 Qwen3-VL-8B，一边用 Cosmos3-Nano Reasoner。结果是 T2V 的 Domain 分从 73.7 升到 75.7（Overall 73.3 → 74.3），I2V 的 Domain 分从 80.0 升到 80.8（Overall 79.0 → 79.4）。收益确实集中在 Physical AI 类别（Robot +4.8、AV +2.3、Industry +1.0），而 Quality 分两者基本相同。

把这两条放在一起，「统一」的实际含义就收缩了：它是一个更懂物理世界的文本与视觉编码器给生成器当条件通路，收益在专有领域约 1 到 2 分。这仍然是一个真实的、被测量过的收益，但与「四类模型合并成一个模型因而互相增益」这个 framing 之间有明显落差。

公平地说，论文在同族模态之间给出了更强的共享证据。附录 E.4 在 PushT 上比较三个单模式检查点（各 2K 步）与一个联合 FD/ID/policy 检查点（6K 步，每模式预算相同）：逆动力学 MSE 从 1.11×10−3 降到 3.09×10−4（相对降 72%），policy 覆盖率从 74.1% 升到 77.3%，代价是正动力学 PSNR 从 27.13 掉到 26.22。E.3 也显示加入音频联合预训练不但不损害视频指标，T2V 与 I2V 总分反而各升 0.5。这些是「联合训练有协同」的实证，但它们都发生在生成塔内部，不涉及理解与生成之间的那条边。

§ 10 — 最小复现实验 ​

论文已经用附录 E.1 回答了「Reasoner 是否帮到 Generator」，缺的是反方向。所以值得做的最小实验是检验生成训练能否改善理解——这正是 §9 指出的结构性缺口，而且不需要复现 64B 训练。

  • 数据与模型：公开的 Cosmos3-Nano（16B，单机 8 卡可做 LoRA），加上仓库里已有的 VideoPhy-2 物理合理性子集与 PAIBench 打分脚本。
  • 三个配置：① 原始 checkpoint 直接评测；② 只对 Reasoner 塔做 VideoPhy-2 SFT；③ 解冻 reasoner 塔，只用生成任务（image-to-video）继续训练同样步数。配置 ③ 是关键，因为官方配方里 reasoner 在生成训练时是冻结的，这个消融必须自己改。
  • 交叉测量：配置 ③ 训完后测它的 Reasoner 物理合理性判断准确率与通用 VLM 分数；配置 ② 训完后测它的 I2V 生成在物理类 prompt 上的表现。
  • 判据：如果 ③ 让理解侧的物理判断显著上升而通用分不塌，说明生成确实往共享参数里写进了关于物理世界的知识，冻结 reasoner 是一个保守到浪费了收益的选择；如果 ③ 让理解侧退化（这正是论文冻结它的理由），那么「统一」在架构层面就只能是单向的条件通路，叙事应当据此收缩。任一结果都比现状信息量大，因为论文根本没测。

§ 11 — 最强反例设计 ​

攻击一：初始化混淆了「统一」与「Qwen3-VL 很强」。 两个塔都从同一个预训练 VLM 初始化，Nano 用 Qwen3-VL 8B、Super 用 Qwen3-VL 32B。任何「统一带来的收益」都可能只是「从一个强 VLM 初始化生成塔带来的收益」。附录 E.1 已经部分控制了这一点（对照组正是 Qwen3-VL-8B），差距落在 1 到 2 分，这恰恰说明混淆项很大而净效应很小。缺的对照是第三组：生成塔从随机初始化或从一个纯视觉预训练模型初始化。没有这一组，就无法判断双塔从同一 VLM 初始化究竟是「共享表示」还是「两次用了同一个好起点」。

攻击二：训练预算的分配与 scaling 叙事对不上。 Nano 的生成器预训练吃了 31.05 T token，Super 只吃了 17.86 T，小模型拿到的 token 反而多出七成。Table 1 里的结果也随之变得不易解读：音频分上 Nano 7.34 高于 Super 7.31，机器人策略的 SOTA 也出自 Nano 而非 Super。如果规模阶梯的意义在于「Super 是老师、Nano 是学生」，那么老师训练得比学生少这件事需要解释；如果两者只是不同预算下的独立产品，那么把它们并列成一个 family 并从中读出 scaling 结论就不成立。论文没有等 token 的规模对照。

攻击三：时序对齐是统一架构最该赢的地方，也最该被单独测。 3D MRoPE 的绝对时间调制是这篇论文在位置编码上最实质的贡献，它的直接推论是音频帧与视频帧、动作步与观测帧被钉在同一时间轴上。但论文没有报告任何时序对齐误差：没有测撞击瞬间的音频峰值与视觉事件帧的偏移分布，也没有在时间轴上单独消融掉绝对时间调制（附录 E.2 消融的是 FPS 控制机制对运动保真度的影响，量的是 DOVER 视频质量与动态度，不是对齐）。一个便宜且尖锐的探测实验是构造一批有明确物理事件时刻的 prompt（球落地、剪刀合拢、门关上），测生成音频峰值时刻与视觉事件帧之间的偏移标准差；若达到数帧量级，统一时空编码的实际耦合强度就远弱于架构叙事。

攻击四：部署侧的价值可能在数据而不在架构。 Edge 4B 被定位成边缘实时机器人策略与实时视觉推理，但它在这篇论文里并未发布，论文明写 Edge 留待后续 release，Table 1 也没有 Edge 行。同时最强的策略结果来自 Nano 而非 Super，而 Super 的定位是高质量合成数据生成与蒸馏教师。合起来看，一个合理的怀疑是：真正的价值链是「用大模型造数据、把小模型训好」，而「全模态统一骨干」是这条链上游的一个实现选择。若如此，核心贡献应当被重新表述为一条从数据合成到边缘策略的流水线。

§ 12 — Follow-up Research Idea ​

把「同一骨干的两种模式」从一个架构事实，变成一个可以在推理时自由交替的联合推断过程。

(a) 驱动它的局限：目前 Reasoner 与 Generator 是两个顺序调用的运行面。论文 §6.3.2 把这一点写得很明白：Reasoner 的职责是 prompt upsampling，先把用户意图展开成一份结构化 JSON 场景程序，然后才交给 Generator 一次性渲染。加上 §6 那个非对称注意力（AR 永不被 DM 更新），意味着生成过程中模型不能再推理，推理过程中也看不到自己会生成什么。而这恰好浪费了统一架构最独特的能力：两塔住在同一个前向里，理论上可以交错。长时程一致性、动作-状态一致性这类需要「边生成边核查」的问题，目前只能靠更大的模型硬扛。

(b) 可借鉴的相邻领域工具：一是 LLM 推理里的推测解码——用一个快的过程提出候选、用一个慢而准的过程验证；二是扩散采样中的分类器引导，把一个判别式信号变成采样过程中的梯度；三是模型预测控制的滚动时域框架，每步只执行一小段、然后重新规划。

(c) 第一个实验长什么样：实现一个「生成-自省交替」的采样器。把视频生成切成若干 chunk，每生成一个 chunk 后切换到 Reasoner Mode，让同一个模型对刚生成的这一段做物理合理性判断（这正是 VideoPhy-2 SFT 训练过的能力），并输出一条自然语言的纠正指令；把这条指令作为下一个 chunk 的额外条件，或者更强地，把 Reasoner 输出的合理性 logit 作为梯度引导注入下一个 chunk 的去噪过程。核心测量有三个：① 自省频率与最终物理合理性分数的关系曲线（每 1 个 chunk 一次 vs 每 4 个 vs 从不）；② 自省是否能在生成中途捕获那些最终会导致失败的错误（用人工标注的失败时刻做定位精度评估）；③ 关键的对照——用一个外部的同等能力 VLM 做同样的自省，与用模型自身的 Reasoner Mode 做对比。第三点是整个实验的价值所在：如果自省用同一骨干显著优于外部 VLM，那就第一次给出了「统一架构不只是打包」的因果证据，因为只有共享参数才能让 Reasoner 直接读到 Generator 的中间 latent 而不必经过像素解码。这会把 MoT 从一个省显存的工程选择，变成一个能力上不可替代的设计。
