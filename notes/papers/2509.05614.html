SpecPrune-VLA: Accelerating Vision-Language-Action Models via Action-Aware Self-Speculative Pruning ​

项内容
arXiv2509.05614
提交日期2025-09-06
作者Hanzhen Wang, Jiaming Xu, Yushun Xiang, Jiayi Pan, Yongkang Zhou, Yong-Lu Li, Guohao Dai
分类cs.CV, cs.AI, cs.RO
一句话复用上一动作步深层注意力选出的「全局重要 token」，再用本步前两层做自推测的局部筛选加帧间变化补充，配一个按末端速度区分粗/细粒度动作的控制器动态调节剪枝力度。

版本说明

本页依据 abs 页「HTML (experimental)」指向的 v3（2026-05-24 修订，comments 注明 Accepted to ICML 2026）全文撰写；v1 提交于 2025-09-06，v2 修订于 2026-02-09。

§ 1 — 研究问题与重要性 ​

最新一代 VLA（OpenVLA-OFT、Dexbotic-OFT）已经放弃了逐 token 自回归解码，改成单次前向直接吐出整段动作。这个改变把推理的性质彻底变了：没有 decode 阶段，只有 prefill，几百个多模态 token 一次性过网络。在 roofline 图上它落在计算受限区，延迟主要由计算量而非访存决定，而 LLM 主干占端到端延迟的 70% 以上。

计算受限意味着剪枝是对症的。但把通用 VLM 的 token 剪枝方法（FastV、SparseVLM、DivPrune）直接搬过来会出问题：它们的重要性判据来自当前这一次前向的浅层注意力或视觉编码器显著性，而作者的观察是这类局部信号在 VLA 上不可靠，激进剪枝会带来超过 20% 的成功率下降，或者为了保精度只能剪很少、加速有限。这件事的实际后果很直接——机械臂的控制频率上不去，接触阶段的反应延迟就下不来。

§ 2 — 前人工作与不足 ​

VLA-Cache 用图像相似度跨时间步复用不重要 token 的 KV，只减少 17–25% 的 FLOPs，且引入额外的显存访问开销。EfficientVLA 用单层注意力启发式剪视觉 token 并补充多样化 patch，作者批评它可能引入任务无关内容且缺乏全局上下文感知。SP-VLA 按视觉编码器显著性保留 token 以保住空间语义结构，但过滤不掉语义冗余。

三者的共同缺口是信息来源的层次：都只用了「当前步的浅层/编码器信号」。这不是疏忽，而是一个真实的因果困境——真正能判断 token 是否重要的是深层注意力，可深层注意力只有在整次前向跑完之后才拿得到，那时剪枝已经没有意义了。自推测解码（LayerSkip 用浅层起草、深层验证）与轻量预测器（SpecEE、SpeContext）提供了绕开这个困境的模板：用便宜的信号预测昂贵的信号。

§ 3 — 重建作者的思考路径 ​

第一步是搞清楚「什么才叫重要」。作者做了一个后验剪枝实验：先正常生成动作但不执行，再按各层的图像→文本注意力分数剪 token，用压缩后的输入重新生成并执行。结论是分层的——浅层注意力铺得很散，覆盖桌面纹理这类无关区域，反而漏掉碗和盘子；中层聚焦于任务相关物体（哪怕不直接参与动作）；深层聚焦于真正被操作的物体。用浅层引导剪枝在高稀疏下掉超过 10 个点，而中层加深层的组合在 86% 剪枝率下几乎不掉分。随机剪枝只在 12.5% 稀疏度以内安全。

第二步是解决时序困境。既然深层信号必须等前向跑完，那就别等这一次——用上一步的。VLA 的动作步之间时间间隔极短，画面高度重叠，任务目标恒定，因此上一步被判为全局重要的 token 大概率这一步仍然重要。作者用「重要 token 召回率」量化这一点，在不同视角下平均 75%–88%。

第三步是补漏。全局复用会漏掉两类 token：帧间发生显著变化的（动态内容），以及本步子目标改变带来的新的任务相关 token。前者用帧间 patch 余弦相似度找，后者用本步前两层的注意力做自推测——作者测得第一二层 top-k 里有 80%–90% 会出现在最后一层 top-k，第一层单独命中率低，加第三层收益边际但增加延迟。

§ 4 — 核心 Intuition ​

判断视觉 token 重不重要，需要深层注意力，而深层注意力只有前向跑完才有——这在单步里是死循环。但机器人的相邻两次推理看到的几乎是同一幅画面，所以把上一步算出来的深层判断直接搬到这一步用，循环就解开了。剩下的两类漏网之鱼各有便宜的探测器：变了的东西用帧间像素相似度找，新变重要的东西用本步最浅两层的注意力猜。至于剪多狠，看末端速度——机器人在自由移动时可以剪得很凶，一旦慢下来准备接触就必须保守。

§ 5 — 具体方法与完整 Pipeline ​

以 LIBERO 的「把碗放到盘子上」为例，一次推理分两级。

动作级静态剪枝（在 LLM 前向的入口执行）。三个集合取并集：Vglobal​ 是上一步在第 15 层与第 32 层按图像→文本注意力分数选出的 top-Kglobal​；Vdynamic​ 是把当前帧与一个历史参考帧按 token 尺寸切成 N×N patch 后，先滤掉相似度高于阈值 τ 的、再取剩余中相似度最低的 Kdynamic​ 个；Vlocal​ 是本步第 1、2 层各自的 top-Klocal​ 的并集。参考帧不取相邻帧（真机上相机噪声与光照变化会污染比较），而是取当前帧之前 T=⌊b+k⋅v⌋+4 帧，其中 k=−1、b=7，速度越快取得越近。基线取值 Kglobal​=30、Klocal​=24、Kdynamic​=20，由最大化召回率选出；整体用剪枝比 α=0.8 缩放。这一级砍掉 60%–70% 的视觉 token。

层级动态剪枝。给静态剪枝后剩下的 token 维护一个重要性分数 si(l)​=ωrank,i(l)​×ωconf(l)​，前者是按注意力排名经 sigmoid 归一得到的权重，后者是层置信度。分数沿层以 EMA 更新（β=0.2），在指定的更新层上剪掉分数最低的 10% token，额外省约 20% 计算。

动作感知控制器。由于训练数据已归一化，模型输出的位移天然处于一致量程，可直接算平移速度 vt​=Δx2+Δy2+Δz2​ 与旋转速度 vr​=Δα2+Δβ2+Δγ2​。轨迹数据呈双峰分布：粗粒度阶段速度高，细粒度阶段平移与旋转都慢且 Δz 非正。据此设阈值切换保守/激进两档。

§ 6 — 核心数学推导 ​

重要性判据本身是一个简单但需要看清方向的量。设第 l 层第 h 头的注意力矩阵为 Alh​，视觉 token Vi​ 的任务相关度定义为它分配给所有指令 token 的平均注意力：

Scorel​(Vi​)=H⋅m1​h=1∑H​j=1∑m​Alh​(Vi​,tj​)

注意这里 Vi​ 是 query、tj​ 是 key，即「这个图像块有多主动地去看指令」，而不是「指令有多关注这个图像块」。两者不是同一个量，softmax 的归一化方向也不同——前者对每个视觉 token 的全部 key 归一，因此得分高只说明该 token 的注意力质量里文本占比高，未必说明它对最终动作的贡献大（基于证据的推断）。

层置信度用注意力熵的倒数：

Hˉ(l)=−N1​i=1∑N​j=1∑M​Aij(l)​logAij(l)​,ωconf(l)​=Hˉ(l)+ϵ1​

这里的 Aij(l)​ 是文本 query 到图像 key的方向，与式中定义 Score 时的方向相反；论文没有说明为何两处取不同方向。另外该置信度只在第一次推理时计算、之后全程复用，理由是步间相似度高。

时序一致性的度量是

Recall(Vt−1​,Vt​)=∣Vt​∣∣Vt−1​∩Vt​∣​

实测 75%–88%。反过来读，这意味着每一步都有 12%–25% 的当前重要 token 不在上一步的集合里，全靠 Vdynamic​ 与 Vlocal​ 去捞——而这两者都是启发式，没有覆盖率保证。这正是方法在接触阶段掉分的结构性来源，也是动作感知控制器要去补的洞。

§ 7 — 实验设计与结论 ​

问题一：在两类主流架构上能否同时保精度与提速？ 表 1（A800）给出 LIBERO 四套件：OpenVLA-OFT 基线平均 96.6%，SpecPrune-VLA 96.1%（−0.5），加速 1.46×，FLOPs 降到 43%。对照组里 FastV 93.3% / 1.44× / 57%，DivPrune 89.4% / 1.46× / 54%，SparseVLM 95.6% / 1.28× / 77%，VLA-Cache 96.9% / 1.07× / 83%，EfficientVLA 88.9% / 1.52× / 35%。SimplerEnv 上以 DB-OFT 为底座：基线 70.4%，本方法 70.1%、1.44×、42% FLOPs。

这里有两处需要如实指出。其一，SpecPrune-VLA 在任何一个 LIBERO 子套件上都不是最好的剪枝方法：Spatial 97.4 低于 VLA-Cache 的 99.0，Object 95.8 低于 97.7，Long 93.4 低于 VLA-Cache 与 SparseVLM 的 93.6；它的卖点是「同等精度下更快」而非「同等速度下更准」。其二，VLA-Cache 在 Spatial 上拿到 99.0，高于未剪枝基线的 97.6——剪枝反超原模型，这通常是评测噪声或正则化效应的信号，值得在解读任何 0.5 个点的差距时保持警惕。

问题二：FLOPs 的节省有没有兑现成延迟？ 没有完全兑现，而且转化率并不占优。本方法 43% FLOPs 对应的理论上界是 2.33×，实测 1.46×，转化率 63%；FastV 57% FLOPs 理论上界 1.75×，实测 1.44×，转化率 82%；EfficientVLA 35% FLOPs 理论 2.86×，实测 1.52×，转化率 53%。也就是说 SpecPrune-VLA 比 FastV 多砍了 14 个百分点的 FLOPs，墙钟却只快了 0.02×，多出来的计算量被自推测的两层前向、逐层重排序与帧间比较吃掉了。

问题三：口径是否一致？ 摘要写「LIBERO 仿真最高 1.57×」，但表 1 的 LIBERO 平均是 1.46×、§7.5.1 的 LIBERO-Spatial 是 1.51×，1.57× 实际出自 §7.6 的 RTX 3090 端到端实验（同一实验里 LLM 部分是 2.09×）。另外 §7.4 正文写 SimplerEnv 平均加速 1.34×，而表 1 该列是 1.44×，两处对不上。

问题四：三个组件各值多少？ 图 8（LIBERO-Spatial）：完整模型 97.4% SR、72.3 ms、相对基线 109 ms 的 1.51×；只做静态 + 层级剪枝是 96.8% SR、70.8 ms。所以动作感知控制器花 1.5 ms 换 0.6 个点。表 3 显示去掉全局注意力复用（为公平把 Klocal​ 提到 54）后召回率 92%→84%、SR 96.1%→93.4%；表 4 显示把熵加权换成平均加权后召回率 88%→66%、SR 96.1%→92.0%。注意 §7.5.2 正文把表 3 引用成了 Table 4。

问题五：真机。 Flexiv Rizon4 三相机、按 OpenVLA-OFT 配置 LoRA 微调，四个任务：基线 96.7 / 85.0 / 91.7 / 95.0，本方法 96.7 / 82.0 / 90.0 / 95.0，延迟 187.7 ms → 110.2 ms（1.70×）。四个任务里有两个成功率下降（TransferTube −3.0、PickUpCup −1.7），平均从 92.1% 掉到 90.9%，正文的「maintaining the success rate」需要按这个幅度理解；正文未给出每个任务的试验次数。

§ 8 — Take-aways ​

五句话版：单步 prefill 形态的新一代 VLA 是计算受限的，因此 token 剪枝对症，而 LLM 占端到端延迟 70% 以上。本文的关键观察是重要性判据必须来自中深层注意力，但深层信号在本步不可得——解法是复用上一动作步的深层判断，因为相邻步画面高度重叠，重要 token 召回率有 75%–88%。剩下的漏网之鱼由帧间相似度（动态 token）与本步前两层的自推测（局部 token）补齐，再用末端速度区分粗/细粒度动作调节剪枝力度。LIBERO 上以 0.5 个点的代价换 1.46× 加速、FLOPs 降到 43%，真机 1.70×。但它在任何单个子套件上都不是最准的剪枝方法，FLOPs 到墙钟的转化率（63%）低于 FastV（82%），且真机四任务里两个成功率下降。

三句话版：把「哪些 token 重要」这个必须等深层才知道的判断，跨时间步搬到下一次推理，绕开了单步内的因果死锁。剩余误差集中在接触阶段，因此需要一个按速度切换保守/激进的控制器来兜底。加速比受限于自推测与逐层重排序的固定开销，FLOPs 的节省只兑现了六成多。

一句话版：机器人相邻两帧几乎一样，这既是加速的机会，也是这套判据唯一的立足点。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：图像→文本注意力的 top-K 就是动作真正需要的 token。整套方法——全局复用、局部自推测、层级重排序、召回率消融——全部建立在这个代理指标上，如果它与「对最终动作的因果贡献」不一致，那么召回率 92% 也只是把一个错误判据复现得更忠实。

论文为它提供的证据是图 3(e) 的后验剪枝实验：中层加深层引导在 86% 剪枝率下几乎不掉分，而随机剪枝在 12.5% 以上就崩。这是必要性证据（好的判据确实比随机强），不是充分性证据（不能排除还有更好的、与注意力不相关的判据）。而全文最直接的反证来自方法自己的设计动机：作者在 §6.1 明确观察到失败集中在接触阶段。接触阶段恰恰是全局画面变化最小的时候（只有夹爪附近的几个 patch 在动），因此召回率会保持很高，而真正新变得关键的那几个 token 数量极少、极容易被 top-K 的排名机制淹没——高召回率与接触阶段掉分可以同时成立。作者的补救（动作感知控制器）是在症状层面加保险，而不是修判据本身。

另外还有一层轻微的循环性：Kglobal​、Klocal​、Kdynamic​ 三个超参是按召回率最大化选出来的（图 7a/b），而召回率随后又被当作表 3、表 4 中支持设计有效性的证据。

§ 10 — 最小复现实验 ​

一周可做，不需要训练：在 LIBERO-Spatial 上冻结 OpenVLA-OFT，只替换静态剪枝的 token 选择策略，跑四档——(A) 本文方法；(B) episode 级固定掩码：只在第 0 步算一次全局重要 token，整条 rollout 都用它，不做任何跨步更新；(C) 随机保留同等数量 token；(D) 只保留 Vlocal​（本步前两层自推测），不做全局复用。四者报成功率、召回率与端到端延迟。

判据：如果 (B) 与 (A) 的成功率差距在 1 个点以内，那么「跨步复用」这个机制就是多余的——真正起作用的只是「有一张任务相关的静态掩码」，而 (B) 的开销为零、还能省掉存储上一步注意力的显存。考虑到 VLA 场景里相机固定、任务恒定、背景基本不动，这个结果并非不可能。

§ 11 — 最强反例设计 ​

最强的攻击是效率侧的替代解释：这套方法的复杂度没有换来相称的墙钟收益。表 1 已经把弹药摆出来了——本方法 43% FLOPs / 1.46×，FastV 57% FLOPs / 1.44×。一个只用第 2 层注意力、零跨步状态、零帧间比较的方法，用多 14 个百分点的计算量拿到了几乎相同的延迟。这说明自推测的两层前向、逐层 EMA 重排序、patch 级余弦相似度这三项固定开销吃掉了大部分理论收益。

判决实验：把三者的每步分解延迟报出来（视觉编码 / 前两层自推测 / 主干剩余层 / 剪枝逻辑本身），并在同一 FLOPs 预算下（比如都压到 43%）比较三种方法的墙钟与成功率。若 FastV 压到 43% 后墙钟明显优于本方法而成功率只低若干点，则「更聪明的判据」这条路在当前实现下不划算，论文的定位应改为「同精度下更省 FLOPs」而非「更快」。

第二条攻击针对基线的公平性。K 值是在本文自己的召回率指标上调出来的，而 FastV / DivPrune / SparseVLM 全部沿用其原论文的通用 VLM 配置，没有在 VLA 上做同等预算的超参搜索。至少应该给每个基线扫一遍剪枝率，画出「FLOPs–成功率」的完整帕累托前沿再作比较；表 1 现在只给了每个方法的一个点。

第三条是可预测的失败条件：全局复用假设相机与场景相对静止。在移动操作（底盘运动导致全画面平移）、或需要中途切换任务指令的场景下，Vt−1​ 与 Vt​ 的重叠会急剧下降，方法退化为只剩 Vlocal​∪Vdynamic​。论文的全部实验都在固定相机、单指令设定下完成，这一条从未被检验。

§ 12 — Follow-up Research Idea ​

本文把「剪多少」交给一个按速度切换的两档启发式，把「剪哪些」交给一个跨步复用的启发式；两者都是开环的，出错了也没人知道。一个非增量的 reframing 是：把 token 剪枝变成一个带风险控制的在线决策问题——不是猜哪些 token 重要，而是给每一步的剪枝决策一个可验证的偏差上界。

(a) 驱动它的局限：现在没有任何机制能在运行时告知「这一步剪错了」；失败只在接触阶段事后暴露，而那时已经不可逆。召回率 75%–88% 这个数字本身就是一个被平均掉的风险，它不告诉你风险在哪一步集中。(b) 可借鉴的相邻工具：conformal prediction 能给「剪枝后动作与不剪枝动作的偏差」一个有覆盖率保证的区间，且只需要一次离线校准；投机解码里的「起草—验证—回退」结构提供了现成的执行框架——用剪枝版当 draft，偶尔跑一次稠密前向做 verify，偏差超界就回退并重新校准。这与 FPC-VLA 2509.04018 在关键帧唤醒重模型的思路同构，只是那里验证的是任务语义、这里验证的是数值偏差。(c) 第一个实验：在 LIBERO 上离线采一批 (剪枝动作, 稠密动作) 配对，用 conformal 校准出「给定当前速度与召回率估计，动作偏差 ≤ϵ 的置信区间」；部署时按该区间决定是否触发一次稠密回退，把回退频率作为可调预算。判据是：在与本文相同的平均延迟下，接触阶段的成功率能否补回真机上那 3 个点，同时给出偏差超界的实测频率——后者是现有方法完全无法提供的一项保证。
