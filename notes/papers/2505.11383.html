Dynam3D: Dynamic Layered 3D Tokens Empower VLM for Vision-and-Language Navigation ​

项内容
arXiv2505.11383
提交日期2025-05-16
作者Zihan Wang, Seungjun Lee, Gim Hee Lee
分类cs.CV, cs.RO
一句话把单目 RGB-D 在线投影成 patch-instance-zone 三层、可增量更新也可删除的 3D token，喂给 3.8B 的 3D-VLM 直接预测原子导航动作，从而同时获得空间几何理解、长期记忆与动态环境适应。

所属教程：通用具身智能

§ 1 — 研究问题与重要性 ​

单目视觉语言导航（VLN）最近的主流做法是把视频大模型（NaVid、Uni-NaVid、NaVILA）搬过来：机器人只有一个前向相机，把历史帧当视频喂给 Video-VLM，让它输出下一个动作。这条路的吸引力在于能直接继承互联网预训练带来的语言理解与常识。但把「场景」编码成「一串帧」会同时丢掉三样东西：一是大尺度 3D 几何与空间语义（模型不知道刚才那个房间在自己身后三米处），二是结构化的场景记忆（无法利用预先探索的知识，也无法跨 episode 累积），三是对变化的适应能力（历史帧里那把椅子已经被搬走了，但表示里它还在）。这三点在真实部署里都不是边角问题——家用机器人反复在同一套房子里工作，物体和人会移动，而重复探索的代价直接体现为 SPL。

§ 2 — 前人工作与不足 ​

导航侧，早期工作在离散仿真器上做（走预定义连通图 + 全景 RGB-D），近期转向连续环境与真实可部署的单目系统。NaVid / Uni-NaVid / NaVILA 用视频大模型取得了强的真实世界适用性，但作者的诊断很具体：视频表示难以捕捉细粒度几何语义、也无法理解大尺度空间布局，因此在物体定位与路径规划上受限。

3D-VLM 侧，LL3DA 直接编码整场点云，LEO / Chat-Scene 把场景切成物体级片段，3D-LLM / Scene-LLM 从多视角图出发做 2D 分割再聚合 CLIP 特征到 3D 点，LLaVA-3D 把 2D patch 嵌进 3D voxel。这些方法的共同前提是场景已经完整给定——全场点云或多视角图像事先存在。放到导航上就失效：未见环境里没有完整点云，而且它们统统缺少增量更新机制，无法撤销或丢弃过时的场景信息。另一个未被解决的权衡是计算：patch 级特征量太大不能直接喂进 LLM，voxel 池化又会抹掉物体身份，而导航指令恰恰是按物体实例来描述目标的。前人不是没想到要做 3D，而是他们的 3D 表示是为「静态、已知、离线」的场景问答设计的。

§ 3 — 重建作者的思考路径 ​

三条已有线索摆在那里。第一，g3D-LF / HNR 这一系的可泛化特征场已经证明：把 CLIP 的 2D patch 特征按深度投影到 3D、再渲染回一个以智能体为中心的全景，可以给出比原始视频更好的局部几何语义。第二，导航指令里的目标几乎总是以物体实例描述的（"走到沙发旁边的那扇门"），所以表示的自然粒度是实例而不是体素。第三，一旦有了深度与位姿，「哪些历史特征点现在应该被删掉」是一个可以纯几何判定的问题——把旧特征点投回当前深度图，如果它落在视锥内却比当前深度更远，说明那个位置现在是空的，原来的物体已经不在了。

把三条线索拼起来就得到本文的结构：patch 层负责细粒度几何、instance 层负责目标定位、再往上补一个 zone 层负责「这是厨房还是卧室」这类实例级特征给不出的布局理解；而删除机制（视锥剔除）让整套表示天然支持动态环境与终身记忆。剩下的工程问题是如何把 2D 实例跨视角合并成一致的 3D 实例——这需要一个判别器，而它的监督可以从现成的 3D 实例分割标注（ScanNet / HM3D / MP3D / 3RScan）里免费得到。

§ 4 — 核心 Intuition ​

视频表示只能「追加」，不能「删除」，也没有物体身份；而导航既需要知道目标物体在哪、也需要知道刚才看到的东西现在还在不在。把观测投影成带 3D 坐标的实例级 token，删除就变成一次纯几何的视锥剔除，物体身份就变成一次跨视角特征匹配。让 VLM 读这样一组可增删的 3D token 而不是一串帧，长期记忆与动态适应就不再需要额外机制。

§ 5 — 具体方法与完整 Pipeline ​

以机器人在一间没见过的公寓里执行「走到厨房，停在冰箱前」为例：

  • Patch 层：每帧 RGB 过 CLIP-ViT-L/14@336px 得到 24×24 个 patch 特征，按深度与内外参投影到世界坐标，同时存下观测方位角 θ 与区域尺寸 s，并入特征点集合 M。
  • 删除：新帧到达时做视锥剔除——把 M 中每个点变换到相机系再投到像素坐标，若落在图像范围内且其深度明显小于当前深度图对应值（即"本该挡住视线却没挡"），就判定该点已过时并移除。这是与前人（只增不删）最本质的差别。
  • Instance 层：FastSAM 在当前帧上快速切出 2D 实例掩膜，掩膜内的 patch 特征加位置编码后过一个以可学 query 为输入的 transformer 编码器，聚合成 2D 实例表示。对每个新 2D 实例检索最近的 Top-K 个已有 3D 实例，Merging Discriminator（一个吃 2D 特征、3D 特征与欧氏距离的 MLP）判断是否同一物体：匹配则把 patch 拼进去重新编码，不匹配则新建。当某个 3D 实例的 patch 被剔除干净，实例本身也被丢弃。
  • Zone 层：把世界坐标切成若干立方米的方格，用 zone 编码器把格内实例特征聚合成 zone 表示，提供"这一片是厨房"这种布局级语义。
  • 送进 VLM：用 g3D-LF 的可泛化特征场，在智能体周围沿 12×48 条射线（垂直 90°、水平 360°）渲染出全景 patch token；instance 与 zone token 按到智能体的欧氏距离从近到远排序；每个 token 附带 [xc​,yc​,zc​,Dc​,cosθc​,sinθc​] 经 MLP 得到的位置编码。3.8B 的 LLaVA-Phi-3-mini 读入 {patch}{instance}{zone}{instruction}{最近四步历史动作}，输出原子动作：左转 θ 度 / 右转 θ 度 / 前进 d 厘米 / 停止。
  • 训练：表示模型在 ScanNet、HM3D、MP3D、3RScan、ARKitScenes、Structured3D 的 5K+ 场景 / 2M 语言标注上预训练 100K episode（4× RTX 6000 Ada，约 8 天）。3D-VLM 用 ScaleVLN 与 NavRAG 迁移到连续环境后得到的 4M+ 指令-轨迹对，与 R2R-CE / REVERIE-CE 的 20K+ 人工标注按 1:1 采样，分两阶段训练：先模仿学习严格跟真值路径，再用 waypoint predictor + DAgger 故意把智能体带偏再拉回来，训练纠错能力（100K episode，2× RTX 6000 Ada，约 9 天）。

§ 6 — 核心数学推导 ​

最值得展开的是子空间对比学习。3D 实例的语言对齐用标准 InfoNCE，把实例特征 Oi​ 与其语言描述的 CLIP 文本特征 Ti​ 拉近。但 3D-语言数据只有百万量级，而图文数据是十亿量级，所以还要从 CLIP 蒸馏视觉知识：用 FastSAM 掩膜做 Masked Average Pooling 得到「真值」实例特征 Ojgt​，再做对比蒸馏

Linst-distill​=I1​i∑​CE({cos(Oi​,Ojgt​)/τ}j=1J​, i).

问题在于：同一个 3D 实例从不同视角算出来的 Ogt 差别很大，因为掩膜内平均池化会把整幅图的背景语义也吸进去。写成加性模型就一目了然——设第 j 个视角的真值特征 Ojgt​≈oj​+Vj​，其中 Vj​ 是该视角全部 patch 特征的均值（视角的语义中心），oj​ 才是物体本身的分量。当 ∥Vj​∥ 与 ∥oj​∥ 可比时，cos(Oi​,Ojgt​) 里同视角的所有实例都共享 Vj​ 这一项，对比学习的负样本因此变得难以区分，梯度大量花在拟合视角偏置上。作者的做法是把对比的锚点从原点换成 Vj​：

Lsub-distill​=I1​i∑​CE({cos(Oi​−Vj​, Ojgt​−Vj​)/τ}j=1J​, i).

减去共享分量后，相似度只由物体分量决定，等价于在每个视角的局部子空间里做对比——这也解释了消融里去掉它为什么会掉 2.2 个 SR 点（52.9→50.7）。

Merging Discriminator 的监督是二分类交叉熵：把标注点云的实例 ID 按最近邻赋给 patch，2D/3D 实例各取其 patch 的多数 ID，同 ID 为正、异 ID 为负。

§ 7 — 实验设计与结论 ​

问题一：3D token 比视频表示强吗？ R2R-CE val 上 Dynam3D 的 NE/OSR/SR/SPL 是 5.34 / 62.1 / 52.9 / 45.7，test 上 5.53 / 60.4 / 51.4 / 44.8；对照 g3D-LF（47.2 / 34.6）、Uni-NaVid（47.0 / 42.7）、NaVid（37.4 / 35.9）。SR 比前两者高约 5.7 与 5.9 点，SPL 高 11.1 与 3.0 点，且参数量 3.8B < Uni-NaVid 的 7B。在更依赖目标定位的 REVERIE-CE 与需要理解复杂用户需求的 NavRAG-CE 上（NaVid 与 g3D-LF 由作者在同一训练集上重训），SR 分别是 40.1（NaVid 26.6）与 24.7（NaVid 19.4）。

问题二：结构化记忆真的能被复用吗？ 表 3 是本文最有说服力的一组：预探索（用 MP3D 标注的可导航视点的全景图预先建好整场表示）让 R2R-CE SR 从 52.9 升到 57.1、REVERIE-CE 从 40.1 升到 48.1；终身记忆（同场景 episode 连续评测、沿用上一 episode 的表示）分别到 55.6 与 45.0；两者叠加 58.4 与 49.5。作为对照，g3D-LF 开两项只从 47.2 升到 51.8。不过叠加并非严格最优：R2R-CE 的 SPL 在「仅预探索」时是 52.7，两项全开反而降到 50.4；REVERIE-CE 的 OSR 也是仅预探索时更高（56.8 vs 56.4）。

问题三：能对付动态环境和真机吗？ Hello Robot Stretch 3 + RealSense D435i，静态与动态各 20 个测试用例，停在目标 1 米内算成功。静态：Dynam3D 55%（NaVid 35%、g3D-LF 30%），加预探索 70%。动态（机器人接近到两米时人为把目标搬走）：Dynam3D 45%，NaVid 20%、g3D-LF 10%；加预探索后 SR 仍是 45%（只有 NE 与 OSR 改善）。20 次的样本量意味着 5% = 1 次，这些差距需要谨慎解读。

问题四：三层各值多少？ 表 6（R2R-CE val unseen / REVERIE-CE val）：只用 patch（去掉 instance 与 zone）是 45.7 / 25.7；加 instance + 子空间对齐但不加 zone 是 52.4 / 39.3；加 instance + zone 但不做子空间对齐是 50.7 / 38.4；全开 52.9 / 40.1。可以直接读出：zone 层在 R2R-CE 上几乎不值钱（SR +0.5，SPL 45.7 与 45.7 逐位相同），只在需要粗粒度高层指令的 REVERIE-CE 上值 0.8 点；真正的主力是 instance 层（+7.2 / +13.6）与子空间对齐（+2.2 / +1.7）。

效率上，单步推理 649 ms（3D 表示更新 83 ms、LLM 540 ms、其余 26 ms），训练时单步 455 ms，跑在单张 RTX 4090 上；多数 episode 20–40 步。

§ 8 — Take-aways ​

5 句话版：Dynam3D 把单目 posed RGB-D 在线编码成 patch-instance-zone 三层 3D token，用视锥剔除做删除、用 Merging Discriminator 做跨视角实例合并，从而让表示可增可删。这些 token 加上可泛化特征场渲染的全景 patch，喂给 3.8B 的 LLaVA-Phi-3-mini 直接输出原子动作。R2R-CE val 上 SR 52.9 / SPL 45.7，比 Uni-NaVid（7B）高 5.9 / 3.0 点，REVERIE-CE 与 NavRAG-CE 上同样领先。结构化记忆是最独特的收益：预探索 + 终身记忆把 R2R-CE 推到 58.4、REVERIE-CE 推到 49.5，这是视频表示做不到的。消融显示 instance 层贡献最大，zone 层在 R2R-CE 上几乎无效。

3 句话版：导航需要的不是"更长的历史帧序列"，而是一个可以删除过时信息、并按物体实例组织的空间表示。把它做成三层 3D token 后，长期记忆与动态适应变成表示的自然属性而不是额外模块。代价是整条链路依赖准确的深度与相机位姿。

1 句话版：让 VLM 读可增删的实例级 3D token，而不是一串永不遗忘的历史帧。

§ 9 — 最脆弱的假设 ​

整套方法的地基是位姿与深度足够准。投影、视锥剔除、跨视角实例合并、zone 划分，四个环节全部以相机外参为前提，而它们之间是串联的：位姿一漂，剔除的是错的点、合并的是错的实例、zone 归属也跟着错，误差没有任何一处被纠正回来。更麻烦的是这个假设与本文最独特的卖点直接冲突——终身记忆与预探索恰恰要求位姿在跨 episode、跨时间的尺度上保持一致，而这正是里程计漂移最严重的尺度。

论文为该假设提供的证据是间接的：真机用 Hello Robot Stretch 3，明确说明是"利用其实时定位与位姿估计能力"，实验框架改自 DynaMem。缺的证据很具体：没有任何位姿噪声或深度噪声的消融，没有报告真机上的定位误差量级，也没有给出终身记忆在多长时间尺度后开始失效。仿真中的位姿是 oracle，因此表 1–3 的全部数字都不能用来评估这个风险。

一个次级但同类的隐患：3D 表示预训练用了 Matterport3D 与 HM3D，而 R2R-CE / REVERIE-CE 的场景正来自 Matterport3D。论文没有说明表示模型的预训练是否排除了评测用的 val-unseen 场景。这属于「论文未说明」而非「已证实的泄漏」，但它是复现时必须首先确认的一项。

§ 10 — 最小复现实验 ​

一周可做且不需要重训任何模型的实验：拿作者发布的 checkpoint，在 R2R-CE val unseen 上只改推理端——给每一步的相机位姿注入零均值高斯噪声，平移标准差扫 {0,2,5,10} cm、偏航角扫 {0,1,2,5} 度（覆盖典型室内里程计的漂移量级），深度另做一组乘性噪声。测三个量：SR、被视锥剔除的特征点数量的变化、以及 3D 实例总数的变化（合并失败会让实例数暴涨）。判据：如果 SR 在 5 cm / 2° 处就掉到 patch-only 消融的 45.7 附近，说明三层结构的收益在真实位姿噪声下不成立；如果掉幅平缓且实例数稳定，则该假设是稳健的。同一组噪声也应该施加给 g3D-LF 基线（它同样依赖位姿），以区分「本方法特有的脆弱」与「这一整类方法共有的脆弱」。

§ 11 — 最强反例设计 ​

最有力的攻击是：instance / zone token 的收益可能主要来自「多了一批带位置编码的 token」，而不是它们携带的语义。设计一个语义置换对照——保持 token 的数量、3D 坐标与位置编码完全不变，但把每个 instance token 的特征向量在同一 episode 内随机置换（或替换成从训练集实例特征分布中采的随机向量）。如果 SR 只从 52.9 掉一两点、仍明显高于 patch-only 的 45.7，那么「语言对齐的 3D 实例表示」这一核心叙事就被证伪，真正起作用的是给 LLM 提供了一组稀疏的空间锚点。

有两条旁证让这个反例值得认真对待。其一，zone 层的消融显示它在 R2R-CE 上 SR 只值 0.5 点、SPL 逐位相同（45.7 vs 45.7）——如果 zone 真的提供了"这是厨房"这类布局语义，很难解释它对逐步导航毫无影响。其二，patch-only 那一行的 45.7 低于 g3D-LF 自己报告的 47.2，而 patch 分支正是从 g3D-LF 继承来的；也就是说消融的参照系比公开基线更低，所有"instance 贡献 +7.2"的读数都建立在这个偏低的起点上。作者未解释这一差异。

另一类可预测的失败：视锥剔除的判据是几何的，它只能删除"本该遮挡视线却没遮挡"的点，因此对被移走的物体有效，对换了位置但仍在视野外或外观改变而几何不变（换了床单、开关了灯）的情况完全无能为力。动态真机实验恰好只测了前一种（把目标搬到别处），后两种未被覆盖。

§ 12 — Follow-up Research Idea ​

驱动的局限：作者在 Limitations 里承认，Dynam3D 只输出原子动作，不显式输出目标实例的坐标，因此无法用于移动操作，也无法问答与对话。这背后是一个更深的方法论问题——表示质量与策略质量被端到端地捆在一起，一次失败无法归因：是实例没定位到，还是定位到了但动作选错了？

新的 framing：把导航重构成「持续输出并维护一个可检验的空间假设」，而不是「输出下一个动作」。具体地，让模型在每一步显式输出目标实例的 3D 位置及其置信度，把动作交给一个经典的规划器；模型的训练信号则来自这个假设的可证伪性——当机器人走到假设位置附近并观测到目标不在那里，就产生一个明确的负样本。这样表示与策略被解耦，且指令理解的错误可以在执行之前被检测出来（对应用侧就是「我认为冰箱在那边，置信度 0.4，要不要我先去看一眼」）。

可借鉴的相邻领域：主动 SLAM 与贝叶斯实验设计里的信息增益准则——它们正是为「维护一个关于世界的分布式假设，并选择最能降低其熵的动作」而生；以及 conformal prediction 提供的、可校准的置信区间构造方法。

第一个实验：在现有 3D-VLM 上加一个轻量回归头，输出目标实例的 3D 坐标与不确定度，用 REVERIE-CE 的目标物体标注做监督（不改动作头）。测量三件事：坐标误差与最终 SR 的相关性、置信度的校准曲线、以及「按置信度提前终止并请求澄清」能挽回多少失败 episode。若坐标误差与 SR 高度相关，则表示质量确实是瓶颈，本文的三层结构应当直接以定位精度为优化目标；若相关性很弱，则说明失败主要发生在动作层，3D 表示的进一步改进收益有限。
