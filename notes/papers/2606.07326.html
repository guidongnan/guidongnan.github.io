AnchorWorld: Embodied Egocentric World Simulation with View-based Evolution Customization ​

项内容
arXiv2606.07326
提交日期2026-06-05
作者Yu Li, Menghan Xia, Gongye Liu, Xintao Wang, Conglang Zhang, Lei Ke, Yuxuan Lin, Ruihang Chu, Pengfei Wan, Kun Gai, Yujiu Yang
分类cs.CV
一句话用第三人称视频补上第一人称看不见的全身动作监督，再用带 3D 位姿和演化 prompt 的 anchor view 指定"世界里某处该长什么样、该怎么变"。

所属教程：世界模型

§ 1 — 研究问题与重要性 ​

第一人称世界模拟器要同时满足两件事，而现有方法各自只做到一半。

第一件是具身动作控制。VR 与具身 AI 场景里，用户的响应不只是"画面继续下去看着合理"：头部运动决定相机看向哪里，身体运动驱动导航，手脚的协调动作决定与周围物体如何交互。用键盘、相机轨迹或文本 prompt 当控制信号很方便，但那不是人从第一人称视角行动的方式。

第二件是局部世界状态定制。现有方法通过初始帧、全局 prompt 或历史上下文隐式地决定环境，因此新观测到的区域几乎不受约束——用户没法指定"那个位置应该有什么"，更没法指定"那里的东西应该怎么随时间变化"。

把这两件事合起来，论文定义了一个新任务：world-customizable embodied egocentric simulation。它的实际价值在于把第一人称世界模型从"能走"推进到"能按剧本走"——这是 VR 内容创作与具身仿真真正需要的接口。

§ 2 — 前人工作与不足 ​

动作控制这条线。 早期交互式世界模型用键鼠控制视角（Genie、RELIC、WorldPlay、LingBot-World、Yan、Astra）；另一条线用文本触发世界事件（Cosmos、WoW、Yume、Hunyuan-GameCraft-2、PAN）。更细粒度的一支引入手部姿态（LOME、EgoSim、Hand2World、Generated Reality 等），但通常限制在相机运动受限的第一人称场景。最接近的两个是 PlayerOne 与 PEVA：PlayerOne 用全身运动做第一人称世界模拟，设计了部位解耦的运动注入；PEVA 用人体运动做条件、不用文本输入，鼓励模型从第一人称视频与运动线索里推断意图。

它们不够用的原因很具体，而且是结构性的而非工程性的：运动条件描述的是 3D 空间里的身体，但要预测的第一人称画面里，身体的绝大部分是看不见的。模型只能间接地、通过画面变化去观察身体运动的后果。监督因此既稀疏又对齐不良——这不是多标注一些数据能解决的，第一人称相机在物理上就拍不到自己的躯干和腿。

场景一致性这条线。 ReCamMaster 用源视频条件化做新相机轨迹合成；CineScene 用密集的等角度间隔图像序列表示场景，配合隐式 3D 特征；SWM 在导航时检索邻近街景图像做几何与语义参照；Context-as-Memory 检索视野相关的历史帧。这些方法能维持一致性，但它们的"世界"是被给定的（源视频、街景库、历史帧），用户无法在某个 3D 位置上写入自己想要的内容，更无法规定它如何演化。

§ 3 — 重建作者的思考路径 ​

不用本文贡献做前提。研究者从 PlayerOne 的失败模式出发：全身运动条件学不准。为什么？因为训练信号是"给定运动，预测第一人称画面"，而画面里看不到运动本身。

顺着这个诊断往下问：第一人称视频缺的监督，哪里有？第三人称视频里有——身体和它与场景的交互都完整可见。但两种视频的相机语义完全不同，不能直接混训。除非……把动作条件写成投影形式：动作 = 全身运动序列 + 相机轨迹。这样第三人称视频里相机参数取外部观察视点，第一人称视频里相机参数取头部位姿，同一套参数化统一了两种数据。先在大规模第三人称视频上预训练获得"3D 运动如何投影成 2D 观测"的知识，再迁移到第一人称。

第二条线索来自"世界该怎么被指定"。初始帧只能约束正前方；全局 prompt 只能约束整体风格。要约束"某个 3D 位置有什么"，最自然的表示就是一张图 + 它的 6-DoF 位姿。再加一句描述它怎么变的文本，就同时有了静态定制和动态定制。

第三步是训练顺序。这四件能力（第三人称动作、第一人称动作、静态 anchor、动态演化）互相依赖，同时上必然打架。所以拆成四个渐进阶段。

§ 4 — 核心 Intuition ​

第一人称视频学不会全身动作控制，是因为身体不在画面里；而第三人称视频恰好把这份监督完整地摆着。只要把动作条件写成"3D 运动 + 相机视点"的投影形式，两种视频就能用同一个模型训练。世界定制同理：不要靠初始帧或全局 prompt 隐式约束，直接在指定 3D 位姿上钉一张图，再配一句"它该怎么变"。

§ 5 — 具体方法与完整 Pipeline ​

基座是 Wan2.2 TI2V 5B，图生视频形式，77 帧 480p。以"用户在客厅里走向沙发，同时沙发上的人站起来"为例：

  • 输入。人体运动 M∈Rf×k×6 来自 SMPL-X（22 个主要关节，每个关节 3D 位置 + 3D 轴角旋转；因为第一人称数据里手部估计不可靠，排除手部）；初始第一人称帧 I0​；anchor view 集合 S={(Ii​,ci​,ti​)}i=1n​，每个包含 RGB 图、6-DoF 位姿、演化 prompt。
  • 动作注入（Spatial Pose Attention）。运动编码器把 M 映射成 zm​，相机编码器把位姿序列映射成 zc​，时间维下采样对齐到 VAE latent 的 f′。三者沿空间维拼接后过空间自注意力，输出时用 Truncate 丢掉辅助 pose token 只留视频特征。丢弃这一步很关键——pose 特征与 VAE latent 之间存在分布 gap，留着会污染后续层。
  • anchor view 注入。anchor 图编码成 latent token zs​，沿帧维与视频 latent 拼接（in-context 条件化，不改架构）；用 3D RoPE 给不同 anchor 分配不同的帧轴位置以区分它们；相机位姿编码后空间广播、在自注意力前加到视觉 token 上。
  • 演化 prompt 注入。每个 anchor 配一句描述其时序变化的文本，通过 cross-attention 注入，并用注意力掩码限制局部性：prompt tj​ 的 key 只对生成视频 token 和对应的 anchor token zs(j)​ 可见。
  • 四阶段渐进训练。Stage I 第三人称动作（20 万条内部单人动作视频 + 10.1 万条 MultiCamVideo 的 UE 合成视频，3 万迭代）；Stage II 第一人称动作（Ego-Exo4D + LEMMA，10 万样本，1.5 万迭代）；Stage III 静态 anchor 定制（2.5 万条大视角变化样本，1 万迭代）；Stage IV 动态演化（2.5 万静态 + 1 万动态，1 万迭代）。全程 16 卡、batch 16、lr 1×10−4，pose 与 anchor 条件各以 5% 概率独立丢弃。运动与 anchor 位姿都用 GVHMR 估计并统一到同一全局坐标系；演化 prompt 由 Qwen3-VL-32B-Instruct 按模板标注。

§ 6 — 核心数学推导 ​

投影式动作条件的 Spatial Pose Attention。 把视频 token、运动 token、相机 token 沿空间维拼成统一序列

T=[zv(t)​; zm​; zc​]∈Rf′×(h⋅w+k+1)×d,

zv(t)​←zv(t)​+Truncate(Attn(WQ​T, WK​T, WV​T)).

为什么这样设计比常见做法好？拼接发生在空间维意味着每一帧的视频 token 只和同一帧的 pose token 交互，模型被显式告知了帧级对齐关系；而 Truncate 在注意力之后丢弃 pose token，避免把分布不同的 pose 特征混进 latent 流。论文的第三人称消融（Table 4）量化了这个选择的价值：本方法 WA-MPJPE 74.57 / PA-MPJPE 28.01，而 3D Pose Attention 是 188.17 / 82.37，Cross-Attention Fusion 是 187.55 / 88.23，In-Context Frame Concat 是 161.67 / 74.64。只用 3D 关节位置而不用 6D 位姿表示则是 90.47 / 38.71——缺了朝向信息，生成结果里人的朝向会错。

anchor view 的 in-context 条件化。 anchor latent 沿帧维拼接：

Ttotal​=[zv(t)​; zs​]∈R(f′+fs​)×h⋅w×d,

再把位姿嵌入 zpose​∈R(f′+fs​)×1×d 空间广播后相加：Ttotal​←Ttotal​+zpose​。把视觉 token 与空间位姿耦合起来，模型才能区分位于不同位置的 anchor，并把生成的第一人称轨迹与正确的局部约束关联上。

局部化演化控制的注意力掩码。

M(q,kj​)={0,−∞,​if q∈zv​ or q∈zs(j)​,otherwise.​

即第 j 条演化描述只能被生成视频 token 和它自己的 anchor token 看到，从而在架构上保证不同 anchor 的动态指令互不干扰。

§ 7 — 实验设计与结论 ​

基线覆盖三个任务面。动作控制比 PlayerOne（官方代码不公开，作者用同一批数据在 Wan2.2 TI2V 5B 上重新实现，为公平同样排除手部）。静态场景一致性比 PlayerOne-Scene（给 PlayerOne 装上本文的 anchor 注入）与 Context-as-Memory 的两个变体（CaM-Ego 用本文的第一人称数据训练，CaM-UE 用官方 UE 数据）。动态演化因为没有同设置的前作，把演化 prompt 附加到静态基线的全局 prompt 上作为改造基线。

评测四个维度：动作精度用 MegaSaM 从生成视频反估相机轨迹后算 ATE / RTE / RRE（因为身体大部分不可见，只能通过视角控制间接量化）；场景一致性用 GIM 的匹配像素数、CLIP-V、PSNR / SSIM / LPIPS；动态演化用 VideoAlign 的文本对齐分；画质用 VBench。四个测试集：第一人称静态 100 条、UE（从 CineScene 筛的 100 条，初始帧与 anchor 无重叠）、真实拍摄（仅定性）、第一人称动态 100 条。

第三人称监督是必要的吗？ 是。消融显示去掉 Stage I 后 ATE 从 0.112 升到 0.125、RRE 从 3.187 升到 3.532；去掉头部位姿对齐 RRE 升到 3.806；Stage I 与 II 联合训练（而非先后）RRE 3.372，仍不如渐进训练。这组数据支持了论文的核心诊断——第一人称视频提供的动作监督确实不完整。

anchor 机制起作用吗？ 第一人称静态集上本方法 Mat.Pix 4493.4 / CLIP-V 0.885 / PSNR 16.06 / LPIPS 0.470，优于 CaM-Ego 的 4379.4 / 0.872 / 15.16 / 0.515 与 PlayerOne 的 PSNR 13.26。消融里去掉 anchor 位姿 Mat.Pix 掉到 4401.7，去掉 anchor RoPE 掉到 4395.2。anchor 数量从 1 增到 3，Mat.Pix 从 4074.94 单调升到 4233.59。

泛化到分布外场景？ UE 测试集上本方法 RRE 1.656 最优、Mat.Pix 4555.1 最优，但 CLIP-V 0.851 略低于 CaM-UE 的 0.852，VBench 0.769 略低于 CaM-Ego 的 0.770——不是全面碾压。

动态演化才是最大的领先。 第一人称动态集上 VideoAlign-TA 0.717，而 PlayerOne-Scene 0.449、CaM-Ego 0.385、CaM-UE 0.115。同时 PSNR 16.37 也最好。不过 RRE 1.346 略逊于 CaM-UE 的 1.230。

两个额外分析值得注意。 一是视野外演化：构造 anchor 里有人但初始第一人称视角看不到的情形，通过改变第一人称运动来控制转头时机——早转头时看到人还坐着（第 25 帧）随后站起，晚转头则直接看到已站起（第 60 帧）。二是场景连贯性（Fig. 12）：把 anchor 换成风格不匹配的图像，或同时翻转 anchor 位姿与人体位姿把世界镜像，生成结果都会变得不连贯。作者的解读是视频生成模型内部需要一个连续完整、几何自洽的世界表示。

§ 8 — Take-aways ​

5 句话版：AnchorWorld 提出 world-customizable embodied egocentric simulation 任务，同时提供具身动作控制与局部世界定制两种接口。针对第一人称视频里身体不可见导致动作监督稀疏的问题，它把动作条件写成"全身 SMPL-X 运动 + 相机视点"的投影形式，从而能先在大规模第三人称视频上预训练、再对齐到头部视点做第一人称适配。世界定制用 pose-associated anchor view 实现：RGB 图给外观、6-DoF 位姿给空间接地、演化 prompt 给时序变化，通过 in-context 拼接 + 位姿嵌入 + 带掩码的 cross-attention 注入。四阶段渐进训练（第三人称动作 → 第一人称动作 → 静态 anchor → 动态演化）在 Wan2.2 TI2V 5B 上完成。在场景一致性、相机精度与文本对齐上全面优于重新实现的 PlayerOne 与 Context-as-Memory 变体，动态场景的 VideoAlign-TA 0.717 vs 次优 0.449 差距最大。

3 句话版：第一人称拍不到自己的身体，所以全身动作控制学不好——用第三人称视频补这份监督，靠投影式条件统一两种视点。世界定制则是在指定 3D 位姿上钉一张图加一句演化描述。四阶段渐进训练，动态场景的文本对齐领先幅度最大。

1 句话版：缺失的动作监督在第三人称视频里，缺失的世界规格在带位姿的 anchor 图里。

§ 9 — 最脆弱的假设 ​

论文声称的"局部化"世界定制——每个 anchor 配自己的演化 prompt、用注意力掩码保证互不干扰——在实验中从未被真正验证过。

这不是外部推测。作者在附录 B 的局限里写得很清楚：受限于当前第一人称训练数据（通常只提供同一段人类活动的多个视角），他们的实现对所有 anchor 使用全局一致的演化描述，即 t1​=⋯=tn​，并且主要关注与人相关的活动而非多样的动态场景。

这意味着 §3.2 里那个精心设计的掩码 M(q,kj​) 在训练中从未受到过区分性压力：既然所有 tj​ 都相同，掩码限不限制局部性，模型看到的损失是一样的。VideoAlign-TA 0.717 这个领先数字，度量的实际上是"模型能否遵循一句全局的动态描述"，而不是"模型能否让 A 位置的灯亮起来的同时 B 位置的门关上"。

代价在于，"localized world-state customization"恰恰是论文相对 PlayerOne 与 Context-as-Memory 的主要 novelty 宣称之一。如果这个能力只在架构上存在而未在数据上被激活，那么 AnchorWorld 与"一个支持多参考图 + 一句全局 prompt 的场景一致视频模型"之间的差别，就比论文呈现的小得多。Fig. 8 展示了"同一 anchor 图换不同演化 prompt 得到不同状态变化"，但这仍是单 anchor 的实验，不能证明多 anchor 的独立控制。

§ 10 — 最小复现实验 ​

一周内可做，不需要跑完四阶段训练：

  • 用作者公开的模型（或复现 Stage III+IV），构造 50 组双 anchor 测试。每组给两个位于不同 3D 位置的 anchor，配互相冲突的演化 prompt（比如 anchor A："灯逐渐亮起"，anchor B："房间逐渐变暗"）。
  • 让第一人称运动依次扫过两个 anchor 覆盖的区域。
  • 测量：分别在扫到 A 和扫到 B 的帧区间上，用 VideoAlign 计算与 tA​、tB​ 的对齐分，得到一个 2×2 矩阵。
  • 判据：如果对角项（A 区间对 tA​、B 区间对 tB​）显著高于非对角项，说明掩码机制真的实现了局部控制，论文的架构主张成立；如果四项接近，或两个区间都更贴合其中某一条 prompt，则证实 §9 的担忧——局部化只存在于架构而未被训练激活。这个实验只需要推理，是检验论文最强宣称的最低成本方式。

§ 11 — 最强反例设计 ​

站在反对者立场，最有力的攻击是给出替代解释：anchor view 的作用主要是图像先验的检索与风格迁移，而非论文声称的 3D 位姿推理。

论文自己的 Fig. 12 提供了弹药。把 anchor 换成风格不匹配的图像会崩，把世界镜像（同时翻转 anchor 位姿与人体位姿，两者仍保持视野重叠）也会崩。作者把这解读为"模型内部需要连续自洽的世界表示"，但另一种同样自洽的解读是：模型高度依赖 anchor 图与初始第一人称帧之间的低层外观匹配，一旦外观不匹配就失去了唯一可靠的线索。

设计的实验很干净：保持 anchor 图像完全不变，只把它的 6-DoF 位姿 ci​ 在世界坐标系里平移 2 米（同时保持人体运动不变）。按论文的机制，anchor 图描述的应该是空间中另一个区域，模型在原区域应该不再使用这份先验，生成结果应显著不同。测量两组生成结果的 PSNR / LPIPS 差异，以及 Mat.Pix 相对 ground truth 的变化。

如果两组结果几乎相同（比如互相之间 PSNR 高于 25），那么位姿通道基本没起作用，Table 1 里相对 CaM-Ego 的提升就应该归因于"多了一张参考图"而非"空间接地"。论文的相关消融是"去掉 anchor 位姿"（Mat.Pix 从 4493.4 掉到 4401.7，降幅约 2%），这个降幅本身就小得可疑——它与"位姿通道贡献有限"这个替代解释是相容的。真正能区分两种解释的是上述位姿扰动实验，而论文没有做。Fig. 7 的"翻转位姿"实验方向是对的，但翻转会同时改变重叠与非重叠关系，混淆了两个因素。

§ 12 — Follow-up Research Idea ​

换个 framing：把 anchor view 从"作者在生成前写好的规格"变成"世界在被探索过程中不断被追加和修订的账本"。

驱动它的局限是显性的：论文自己承认专注于短视频片段，长时程探索需要实时自回归交互与长期记忆机制；同时所有 anchor 必须在生成前一次性给定，用户无法在 rollout 中途改主意。这两条限制同源——anchor 集合是静态的输入，不是动态的状态。

可借鉴的相邻领域工具是 SLAM 的关键帧管理与增量式地图构建。SLAM 系统在探索中持续插入关键帧、做回环检测、在发现不一致时全局优化。把这套机制搬到 anchor 表示上：agent 在第一人称漫游时，系统自动把生成出的高置信度画面提升为新的 anchor（连同其估计位姿写入账本）；当 agent 回到旧区域时，先检索账本里位姿邻近的 anchor 作为约束；若生成结果与账本冲突，触发一次局部修订而不是任其漂移。这样 anchor 从条件变成了可增可改的持久世界状态，长时程一致性问题就从"模型要记住多少"转化为"账本要维护多好"——后者是可检验、可调试、且不随 rollout 长度爆炸的。

第一个实验不需要改模型：在现有 AnchorWorld 上外挂一个最简账本。让 agent 走一条 60 秒的往返轨迹，前 30 秒每隔 5 秒把当前生成帧和 GVHMR 估计的位姿存进账本，后 30 秒返程时把账本里位姿最近的 3 个条目当作 anchor 喂进模型。对照组是原始设置（只用初始给定的 anchor）。测量返程段相对去程段同视角帧的 PSNR 与 GIM 匹配像素数。如果账本组显著更好，就证明 anchor 接口天然支持增量式使用，把它做成一等公民的持久状态是值得的下一步。
