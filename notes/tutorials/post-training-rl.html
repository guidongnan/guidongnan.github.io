第 0 章 导读：为什么视频生成需要"后训练"与"强化学习" ​

0.1 一句话概括 ​

视频生成大模型（如 Wan、HunyuanVideo、CogVideoX、Sora、Veo、Kling 等）在海量视频-文本对上做完预训练后，往往能"画得像视频"，但不一定符合人类想要的效果：可能物体运动僵硬、文本没对齐、画面闪烁抖动、物理不合理、人脸崩坏、指令没听懂。后训练（Post-training），尤其是基于人类/AI 反馈的强化学习（RLHF / RLAIF），就是在预训练之后，用相对少量的数据和算力，把模型"掰"到更符合人类偏好、更可控、质量更高的方向。

这条路线几乎完整复刻了大语言模型（LLM）"预训练 → SFT → RLHF"的范式，并在 2024 下半年到 2026 年迅速铺开。

0.2 类比：视频生成的"预训练 → 后训练"就像 LLM 的"GPT → ChatGPT" ​

阶段大语言模型 (LLM)视频生成模型
预训练海量文本上做 next-token 预测海量视频上做去噪 / 流匹配
监督微调 (SFT)高质量指令-回答对高质量精选视频 + 详细字幕（有时叫 "high-quality fine-tune"）
对齐 / RLRLHF、DPO、GRPO 对齐人类偏好用奖励模型 / 人类偏好，做 reward 反传、DPO、GRPO
蒸馏 / 加速蒸馏成小模型、少步推理少步 / 一步蒸馏（常与 RL 联合）

核心洞察：预训练学的是"世界长什么样"（分布覆盖、多样性）；后训练学的是"人类更喜欢哪一种"（偏好、质量、可控、安全）。二者目标不同，因此需要不同的损失与数据。

0.3 后训练能解决哪些"预训练解决不了"的问题 ​

  • 文本-视频对齐（Prompt Following）：预训练的字幕噪声大，模型经常"少画一个物体""数不对个数""动作错误"。
  • 视觉美学与画质：色彩、构图、清晰度、细节，人类偏好难以用 MSE/流匹配损失表达。
  • 运动质量与动态度（Motion Quality / Dynamic Degree）：预训练模型常"偷懒"生成近乎静止的视频来降低损失；后训练可以奖励"合理且丰富的运动"。
  • 时序一致性（Temporal Consistency）：闪烁、形变、物体忽大忽小。
  • 物理合理性（Physical Plausibility）：重力、碰撞、流体、刚体，预训练不显式建模。
  • 身份/主体一致性（ID / Subject Consistency）：人脸、角色、产品在整段视频中保持一致。
  • 安全与合规：抑制 NSFW、暴力、版权角色等。
  • 推理效率：少步采样后质量掉点，用 RL 补回质量。

第 1 章 基础：视频生成模型与后训练全景 ​

要理解视频 RL，必须先知道"被后训练的对象长什么样"。

1.1 三种主流视频生成范式 ​

(1) 扩散模型（Diffusion Models） ​

前向过程逐步加噪，把数据 x0​ 变成噪声 xT​≈N(0,I)；反向过程学习逐步去噪。训练目标（以 DDPM 记法）：

Ldiff​=Ex0​,ϵ,t​[∥ϵ−ϵθ​(xt​,t,c)∥2]

其中 c 是条件（文本、图像、姿态等）。视频扩散在图像扩散基础上加入时间维度（3D 卷积或时空注意力），并常在 VAE 隐空间里操作（Latent Video Diffusion）。

(2) 流匹配 / 整流流（Flow Matching / Rectified Flow） ​

当前主流大模型（Wan、HunyuanVideo、Flux、SD3、Stable Video 系）大多采用流匹配。它学习一个速度场 / 向量场 vθ​，把噪声分布沿直线（或近似直线）"流"到数据分布：

xt​=(1−t)x0​+tx1​,LFM​=Et,x0​,x1​​[∥vθ​(xt​,t,c)−(x1​−x0​)∥2]

（约定 t=0 为数据、t=1 为噪声，不同论文方向可能相反）。推理时用 ODE 求解器（Euler、Heun 等）沿速度场积分。这一点在后面非常关键：流匹配默认是确定性 ODE 采样，而策略梯度类 RL（GRPO）需要随机性来"探索"，所以要把 ODE 改写成等价 SDE——这是 Flow-GRPO / DanceGRPO 的核心技巧之一。

(3) 自回归 / 掩码生成（Autoregressive / Masked） ​

把视频离散化成 token（VQ）或按帧/块自回归预测（如 VideoPoet、NOVA、MAGI-1、CausVid、Self-Forcing 系）。这类模型和 LLM 的 RL（token 级策略梯度、GRPO）更"天然兼容"，但连续隐空间的自回归也在兴起。

DiT（Diffusion Transformer）是当下事实标准骨干：无论扩散还是流匹配，主干几乎都换成了 Transformer（时空 patch + 3D RoPE + 全/窗口注意力）。

1.2 代表性开源/商用视频基座（后训练的"底座"） ​

  • 开源可后训练：Wan / Wan2.1、HunyuanVideo、CogVideoX、Step-Video-T2V、Mochi 1、LTX-Video、Open-Sora / Open-Sora-Plan、SkyReels-V2、Cosmos（NVIDIA）、Seaweed-7B、MAGI-1、Waver。
  • 商用（多数闭源，但代表能力上限）：OpenAI Sora / Sora2、Google Veo 2 / Veo3、Kuaishou Kling、Runway Gen-3/4、Luma Dream Machine、字节 Seedance / Seedream。

后训练研究几乎都在开源基座上做（尤其 Wan2.1、HunyuanVideo、CogVideoX），因为需要访问权重、梯度和采样过程。

1.3 "后训练"到底包含哪些环节 ​

"后训练"是一个统称，通常包括：

  1. SFT / 高质量微调：用精选高质量视频（+ 精细重写字幕）继续训练，快速提审美与对齐。这是最"便宜"的后训练，很多"看起来质量暴涨"其实来自这一步。
  2. 奖励建模（Reward Modeling）：训练一个能给视频打分、模拟人类偏好的模型（VideoScore、VideoReward、LiFT-Critic 等），或直接用现成可微指标（CLIP、光流、美学分）。
  3. 对齐（Alignment）：核心的 RL / 偏好优化。三大流派（奖励反传、DPO、GRPO/策略梯度），第 2、6 章详解。
  4. 蒸馏与加速：把多步模型蒸成少步/一步（DMD、Consistency、对抗后训练 APT），常和 RL 联合以补偿质量损失。

本教程重点是 3（对齐/RL），同时覆盖 2、4、5 与其强相关的部分。

第 2 章 原理：把"采样"变成"可强化学习的决策过程" ​

这是全教程最重要的一章：把生成看成序贯决策，后面所有方法才有共同的坐标系。

2.1 关键视角：一次去噪/积分采样 = 一条决策轨迹（MDP） ​

回忆扩散/流匹配的推理：从纯噪声 xT​ 出发，一步步得到 xT−1​,…,x0​（最终视频）。把它看成一个马尔可夫决策过程（MDP）：

  • 状态 st​：当前带噪样本与时间步 (xt​,t)（以及条件 c）。
  • 动作 at​：模型这一步"去噪/移动"到 xt−1​。策略 πθ​(xt−1​∣xt​,c) 就是模型的去噪分布。
  • 状态转移：由采样器（DDPM/DDIM/SDE/ODE 求解器）决定。
  • 奖励 r：只有到最后 x0​（完整视频）才有奖励（终局奖励 / sparse reward），由奖励模型或指标给出 r(x0​,c)。
  • 目标：最大化期望奖励，同时用 KL 约束不要偏离预训练分布太远。

θmax​Ec∼D,x0​∼πθ​(⋅∣c)​[r(x0​,c)]−βEc​[KL(πθ​(⋅∣c)∥πref​(⋅∣c))]

这个"去噪即 MDP"的洞见来自 DDPO / DPOK（2023, 图像域），是所有后续视觉 RL 的思想源头。视频只是把 x 从图像张量换成"时空张量"，把奖励换成"视频奖励"。

2.2 为什么不能直接用监督损失去"提高质量" ​

因为"人类偏好 / 美学 / 运动好不好"这类目标：

  1. 不可微或难以写成解析损失：例如"这个视频的动作是否自然""是否符合物理"。
  2. 只在最终样本上定义：预训练损失是逐步逐像素的 MSE，而偏好是对整段视频的整体判断。
  3. 需要探索：好的输出可能不在预训练分布的高概率区，需要"试错 + 奖励"来发现。

于是要借用 RL / 偏好优化这套工具。

2.3 三大流派总览（先建立地图，再逐个深入） ​

流派需要奖励可微吗需要训练奖励模型吗需要采样探索吗显存/算力典型代表
① 奖励反传必须可微需要（可微 RM）否（用当前样本梯度）高（要沿采样链反传）ReFL, DRaFT, AlignProp, VADER, T2V-Turbo
② DPO 家族不需要不需要显式 RM（用偏好对）否（离线/半在线偏好对）中Diffusion-DPO, VideoDPO, DenseDPO, IPO
③ 策略梯度/GRPO不需要可微（黑盒奖励也行）需要奖励函数（可不可微都行）是（核心）中-高（要多次采样）DDPO, DPOK, Flow-GRPO, DanceGRPO

如何选？（先给结论，细节见第 6 章）

  • 奖励可微且想要样本效率高、收敛快 → 奖励反传（VADER 类）。但易 reward hacking / 过拟合奖励。
  • 手上有偏好对数据、想稳定、实现简单 → DPO 类。
  • 奖励是黑盒 / 不可微 / 多目标、想要上限更高、更像"真 RL" → GRPO 类（2025 年最火）。

2.4 流派①：奖励反向传播（Reward Backpropagation） ​

核心思想：既然奖励模型 rϕ​ 可微，那就把生成的视频 x0​ 喂给它得到分数，再把 ∇θ​rϕ​(x0​) 一路反传穿过整个采样链回到生成器参数 θ，直接做梯度上升。

θ←θ+η∇θ​rϕ​(x0​(θ,c))

  • ReFL / ImageReward（图像域先驱）：不反传整条链，而是在某个较晚时间步一步预测 x^0​ 后打分反传，省显存。
  • DRaFT / AlignProp（图像域）：沿采样链反传，用 梯度截断（只反传最后 K 步） + LoRA 降低显存。
  • VADER（Video Diffusion Alignment via Reward Gradient, 2024, 2407.08737）：把这套搬到视频。用各种可微奖励（图像美学、HPS、PickScore、视频文本对齐、目标检测等）反传，样本效率极高——几十到几百个 prompt 就能显著对齐。
  • T2V-Turbo / T2V-Turbo-v2（2405.18750 / 2410.05677）：把奖励反传融进一致性蒸馏（少步加速），一边加速一边用图像-文本、视频-文本奖励提质，是"蒸馏 + RL"联合的代表。

优点：样本效率最高、收敛最快。 缺点：

  1. 奖励必须可微；
  2. 显存大（要存采样链的计算图）——所以普遍用梯度截断 + LoRA；
  3. 最容易 reward hacking：模型会找到奖励模型的漏洞（如刷高 CLIP 分但画面崩坏），需早停、KL/正则、多奖励。

2.5 流派②：直接偏好优化（DPO 家族） ​

核心思想（来自 LLM 的 DPO）：不训练显式奖励模型，直接用成对偏好数据 (xw,xl)（对同一 prompt，xw 更受偏好、xl 更差），推导出一个只依赖策略与参考模型的闭式损失，让模型"抬高 winner、压低 loser"。

Diffusion-DPO 把 LLM DPO 推广到扩散，逐时间步近似，损失形如：

LDPO​=−Elogσ(β[(logπθ​(xw)−logπref​(xw))−(logπθ​(xl)−logπref​(xl))])

在扩散/流匹配里，logπ 用去噪/速度预测的误差差来近似（winner 的去噪误差应更小）。

  • Diffusion-DPO（图像域，2311.12908）：奠基。
  • VideoDPO（Omni-Preference Alignment for Video Diffusion, 2412.14167）：视频版 DPO，构造涵盖"视觉质量 + 文本对齐 + 运动"的综合偏好数据集，并做偏好分数加权。
  • DenseDPO（Fine-Grained Temporal Preference Optimization, 2506.03517，2025-06）：指出整段视频级偏好太"粗"，提出时间上更细粒度的偏好（哪几帧/哪段更好），用结构化去噪的视频对，缓解"静态偏置"，减少人工标注量。
  • IPO（Iterative Preference Optimization for T2V, 2502.02088）：把偏好优化做成迭代式（自我生成→打分→再优化），兼容点式（pointwise）与对式（pairwise）奖励。
  • 相关变体（逐个说明）：
    • MPO / 多样本比较（2410.12138）：用多样本同时比较（而非单一成对）来估计偏好，信号更稳。
    • SPO — Step-aware（分步偏好）（2406.04314）：把偏好对齐到每一步去噪表现。
    • D-Fusion（语义/视觉一致）（2505.22002）：用视觉一致的样本对做 DPO，聚焦真正的差异维度。
    • FocusDPO（2509.01181）：面向多主体个性化的动态聚焦偏好优化。
    • DreamBoothDPO（2505.20975）：把 DPO 用于主体定制（DreamBooth 式）生成，提升定制保真。

优点：无需显式 RM，训练稳定、实现相对简单，离线数据即可跑。 缺点：性能上限受偏好数据质量与覆盖度限制；纯离线易分布漂移，故常做"半在线/迭代"版本；对"数不清个数"这类硬约束提升有限。

2.6 流派③：策略梯度与 GRPO（2025 年的主角） ​

2.6.1 从 PPO 到 GRPO 的直觉 ​

经典策略梯度（REINFORCE / PPO）需要一个 value/critic 网络估计"基线"来降低方差。GRPO（Group Relative Policy Optimization） 由 DeepSeek 在 LLM 推理中提出，关键在于：

不训练 critic！ 对同一个 prompt，采样一组（group）G 个输出，用组内奖励的均值和方差做标准化当作"优势（advantage）"。

对第 i 个样本，优势为：

Ai​=std({r1​,…,rG​})ri​−mean({r1​,…,rG​})​

策略更新（带 PPO 式裁剪 + KL 正则）：

LGRPO​=−E[ min(ρi​Ai​, clip(ρi​,1−ϵ,1+ϵ)Ai​)]+βKL(πθ​∥πref​),ρi​=πθold​​(ai​)πθ​(ai​)​

为什么 GRPO 特别适合视觉生成？

  1. 生成模型本来就要采一组样本，天然契合"组内比较"。
  2. 不需要 critic（省一半模型、省显存），训练更轻。
  3. 奖励可以是任意黑盒（人类偏好模型、检测器计数、OCR、物理仿真校验……），不要求可微，灵活性极高。
  4. 与 LLM 的 RL 基础设施（同一套 GRPO）可复用。

2.6.2 关键难点：扩散/流匹配是"确定性"的，RL 需要"随机性" ​

策略梯度需要策略是随机分布（才能算 logπ、才能探索）。但：

  • DDIM / 流匹配 ODE 采样是确定性的（给定噪声就给定输出），没有可优化的"动作概率"。

解法（Flow-GRPO 的核心贡献）：把确定性 ODE 转换成等价的随机微分方程（SDE）——两者的边缘分布相同，但 SDE 每一步注入可控噪声，于是每一步的去噪就变成一个高斯策略 πθ​(xt−1​∣xt​)=N(μθ​,σt2​I)，可以算 logπ、可以做 GRPO。

  • Flow-GRPO（Training Flow Matching Models via Online RL, 2505.05470，图像域）：两大技术——(a) ODE→SDE 转换引入探索随机性；(b) 降噪步数缩减（denoising reduction）——训练时用更少步数采样以省时，评测时用完整步数，从而大幅加速在线 RL。在计数、文字渲染、空间关系等任务上大幅提升且几乎不牺牲画质。
  • DanceGRPO（Unleashing GRPO on Visual Generation, 2505.07818）：统一框架，把 GRPO 同时用于扩散 + 流匹配、文生图 + 文生视频，覆盖 SD、Flux、HunyuanVideo、SkyReels 等，兼容多种奖励（美学、HPS、CLIP、视频质量），是视频 GRPO 后训练的代表性开源工作，工程上验证了 GRPO 在视频上稳定可扩展。

2.6.3 GRPO 用于视频的额外考量 ​

  • 奖励稀疏且昂贵：一次要采一组视频，每个都要解码 + 奖励评估，成本高。→ 用少步采样、部分时间步优化、分支采样（BranchGRPO）复用前缀、KV/特征缓存等降本。
  • 时间维度：视频奖励可拆成"逐帧图像奖励 + 时序/运动奖励 + 文本对齐"，也可做逐段/逐帧优势（把 DenseDPO 的思路迁移到 GRPO）。
  • 稳定性：组内奖励标准化在方差很小时会放大噪声（除以极小 std）；Pref-GRPO 等提出用成对偏好胜率代替绝对奖励标准化，缓解"奖励尺度漂移 / reward hacking"。

2.7 三条主线的统一视角与选择决策树 ​

2.8 贯穿始终的三个"敌人" ​

  1. Reward Hacking（奖励作弊）：模型钻奖励模型漏洞，指标高但人看着差。对策：多奖励聚合、KL/正则、早停、成对偏好（Pref-GRPO）、奖励模型定期更新。
  2. 多样性坍缩（Diversity Collapse）：对齐后所有输出变得雷同（"模式坍缩"）。对策：KL 约束、显式多样性奖励、控制训练步数。
  3. 静态偏置（Static/Motion Collapse）：视频特有——为了刷高逐帧美学，模型倾向生成"几乎不动"的视频。对策：显式运动/动态度奖励、时序偏好（DenseDPO）、避免纯图像奖励主导。

后训练/RL 不是笼统地"变好"，而是针对具体能力设计奖励与数据。

3.1 任务全景图 ​

3.2 逐任务说明（含"用什么奖励"） ​

(1) 文本-视频对齐（Text-Video Alignment / Prompt Following） ​

  • 问题：漏物体、数错个数、动作/属性错配、空间关系错。
  • 奖励来源：CLIP/视频-文本相似度、VQA-式奖励（用 VLM 问"视频里有几只猫？"）、目标检测计数、OCR（文字渲染）、T2V-CompBench 分项。
  • 典型方法：Flow-GRPO（计数/空间/文字）、DanceGRPO、VideoDPO、VPO（通过 prompt 优化改善对齐与安全）。

(2) 视觉质量与美学（Quality & Aesthetics） ​

  • 奖励：美学模型（LAION-Aesthetic）、HPSv2、PickScore、ImageReward（逐帧）、MPS。
  • 注意：纯逐帧图像奖励会诱发静态偏置，必须搭配运动/时序奖励。

(3) 运动质量与动态度（Motion Quality & Dynamic Degree） ​

  • 问题：动作僵硬/抖动/物理错误；或反过来——为了降低损失而几乎静止。
  • 奖励：光流幅度（鼓励合理运动）、FVMD（Fréchet Video Motion Distance）、运动平滑度、VideoScore 的动态/运动分项、VideoJAM 式运动表征。
  • 典型：DanceGRPO（视频质量奖励）、Improving Dynamic Object Interactions with AI Feedback、Temporal Regularization（FluxFlow）。

(4) 时序一致性（Temporal Consistency） ​

  • 问题：闪烁、形变、忽大忽小、跨帧不连贯。
  • 奖励：帧间特征一致性、光流一致性、DINO/CLIP 跨帧相似度、DenseDPO 的时序细粒度偏好。

(5) 物理合理性（Physical Plausibility） ​

  • 问题：重力/碰撞/流体/穿模不合理，"看似像视频实则违反物理"。
  • 奖励/评测：PhyGenBench、Physics-IQ、VideoPhy、物理仿真校验、VLM 判物理。RL 可用"物理合规判别器"当奖励。
  • 前沿：把世界模型 / 物理先验作为奖励或约束（2025-2026 热点）。

(6) 身份与主体一致性（ID / Subject Consistency） ​

  • 问题：人脸/角色/产品在整段视频里"变脸"。
  • 奖励：人脸识别相似度（ArcFace）、主体匹配奖励、CLIP-I。
  • 典型：MagicID（Hybrid Preference Optimization）、ConsisID、Phantom、UMO（匹配奖励）、ID-Crafter（VLM-grounded 在线 RL 多主体）。

(7) 长视频与多镜头一致性（Long Video / Multi-shot） ​

  • 问题：长时漂移、跨镜头/跨段主体与风格不一致、误差累积。
  • 奖励/方法：InfLVG（用 GRPO 做推理期一致长视频）、误差回收（Stable Video Infinity）、历史引导。

(8) 图生视频首帧忠实（I2V Faithfulness） ​

  • 问题：I2V 生成偏离参考首帧、条件泄漏。
  • 奖励：与参考图的相似度、Conditional Image Leakage 修正。

(9) 可控生成（Controllable：相机/轨迹/姿态/布局） ​

  • 相机控制、轨迹控制、姿态驱动等本身多靠条件注入，但RL 可用来提升"控制精度"（控制信号被遵守的程度当奖励）。

(10) 安全与合规（Safety） ​

  • 抑制 NSFW/暴力/版权角色。用安全分类器当（负）奖励，或安全约束 DPO、概念擦除 + RL。

(11) 系统级：少步加速 + RL 补质量 ​

  • 一步/少步蒸馏（DMD、Consistency、对抗后训练 APT / Seaweed-APT）会掉质量；用 RL/奖励反传补回（T2V-Turbo 系、Flash-DMD 式"蒸馏 + 联合 RL"）。

3.3 一个统一的"多目标奖励"心智模型 ​

现实中一次后训练常同时要"对齐 + 美学 + 运动 + 一致"。通用做法是加权聚合：

r(x0​,c)=k∑​wk​r~k​(x0​,c)

其中每个 r~k​ 先做归一化/排名再加权（避免量纲不一致）。更稳健的做法是成对偏好聚合（Pref-GRPO）或多组优势（Multi-GRPO）；另一条不同的思路是把多个奖励当作条件写进预训练本身（MIRO，ICML 2026，图像域）。权重选择是工程核心：过度偏向某一项就会牺牲其他（典型：偏美学→静止；偏对齐→画质垮）。

4.2 奖励模型（Reward Model）——RL 的"打分器" ​

奖励模型分两大类：

(A) 可微、现成的通用奖励（用于奖励反传或作 GRPO 信号） ​

  • 图像域（逐帧用）：ImageReward（首个大规模文生图人类偏好）、HPS / HPSv2（Human Preference Score）、PickScore（Pick-a-Pic 偏好）、LAION-Aesthetic（美学预测器）、CLIP（图文相似度）。
  • 视频域：视频-文本相似度、光流/运动指标、时序一致性度量。

(B) 学习型视频偏好奖励模型（模拟人类打分） ​

奖励模型说明
VideoScore (2406.15252)在大规模人工细粒度标注上训练，模拟"视觉质量/时序/动态/文本对齐/事实性"多维人类反馈，可当自动指标与 RL 奖励。
VideoReward (2501.13918，Improving Video Generation with Human Feedback)面向视频的多维偏好奖励；同篇还提出 Flow-DPO / Flow-RWR / Flow-NRG 三种面向流匹配模型的对齐算法。注意时序：VideoDPO（2412.14167）早于本文，是它在附录 A 里与 VisionReward / OnlineVPO / LiFT 一并对比的并行工作。
LiFT-Critic（LiFT, 2412.04814）用人类反馈训练的"打分 + 给理由"的多模态 critic，用于 T2V 对齐。
VisionReward (2412.21059) / UnifiedReward (2503.05236)VisionReward 用分层评估 + 线性加权做可解释多维偏好（图/视频通用，偏好预测精度显著超 VideoScore）；UnifiedReward 是首个统一"理解 + 生成"的奖励模型，支持 pairwise 排名与 pointwise 打分，常配 Pref-GRPO / DPO 使用。
VLM-as-Reward（RLAIF）直接用 GPT-4V / Qwen-VL 等 VLM 当裁判打分或做成对偏好，省人力（如 ID-Crafter、AI-feedback 动态交互工作）。

(C) 可验证奖励（Verifiable / Rule-based Reward） ​

借鉴 LLM 的 RLVR 思路：用客观可判定的信号当奖励，不易被 hack：

  • 计数：目标检测器数个数是否等于 prompt。
  • 文字渲染：OCR 识别是否与要求一致。
  • 空间关系：检测框相对位置是否满足"A 在 B 左边"。
  • 物理：仿真/规则校验。

趋势（2025→2026）：从"单一学习型奖励"→"多奖励聚合 + 可验证奖励 + 成对偏好胜率"，以对抗 reward hacking。

4.3 如何"选/配"奖励（工程清单） ​

  1. 先明确任务（对齐？美学？运动？一致？）——见第 3 章。
  2. 每个子目标配 1-2 个奖励，优先"可验证 > 学习型偏好 > 通用可微指标"。
  3. 归一化后加权，或用成对偏好胜率（更稳）。
  4. 一定要留"守门奖励"：如画质/一致性下限，防止优化某项时其他项崩。
  5. 奖励与评测分离：训练用的奖励 ≠ 报告用的 benchmark，否则等于"考试作弊"。
  6. 定期人工抽检：肉眼看是不是真变好，抓 reward hacking。

5.1 需要哪些数据 ​

5.2 提示词（Prompt）数据 ​

  • 来源：真实用户 prompt（VidProM，百万级真实 prompt-gallery 数据集）、VBench / T2V-CompBench 类 benchmark prompt、LLM 扩写/构造（覆盖计数、空间、属性、动作等难例）。

  • Prompt 改写/优化：VPO、PromptEnhancer、VideoRepair 等把"用户短 prompt → 模型友好的详细 prompt"，本身就是一种后训练/对齐手段。

5.3 偏好数据（Preference Data） ​

  • 成对（pairwise）：同一 prompt 采 2+ 个视频，标"谁更好"。DPO/GRPO(Pref) 直接用。
  • 评分（pointwise）：给每个视频多维打分（VideoScore 训练数据即如此）。
  • 多维/全维（Omni）：VideoDPO 强调"视觉 + 对齐 + 运动"综合偏好，避免单一维度诱发偏置。
  • 时序细粒度：DenseDPO 提出"同源、仅局部不同"的视频对——用 SDEdit 式引导采样从同一条真实视频加不同噪声再去噪，造出运动结构对齐、只在局部细节上不同的两条视频；再把标注下沉到 1 秒片段逐段判胜负，让偏好信号定位到"哪一段更好"，标注更省更准。

第 6 章 方法：五大类后训练/RL 技术详解 ​

本章是"方法百科"。把第 2 章的三大流派细化为五大类（把"对抗后训练/蒸馏结合"和"推理期/提示期对齐"独立出来），每类讲清思想、公式要点、代表工作、优缺点、什么时候用。

6.1 类别一：奖励反向传播（Reward Backpropagation / Direct Reward Fine-tuning） ​

思想：奖励可微，直接把奖励梯度沿采样链回传给生成器。

关键工程技巧：

  • 梯度截断（truncated backprop）：只反传最后 K 步采样，省显存、防梯度爆炸（DRaFT-K）。
  • 单步 x^0​ 预测打分（ReFL）：在某时间步直接预测干净样本再打分，避免整链反传。
  • LoRA：只训练低秩增量，进一步省显存。
  • 早停 + KL：抑制 reward hacking。

代表工作：

  • ImageReward / ReFL（图像域，2304.05977）：首个大规模文生图人类偏好奖励模型，并提出 ReFL（Reward Feedback Learning）——在较晚时间步一步预测 x^0​ 再打分反传，奠定"奖励反馈学习"范式。
  • DRaFT（2309.17400）、AlignProp（2310.03739）：把奖励梯度沿采样链反传的两篇规范化工作，普遍用梯度截断 + LoRA 省显存（详见 7.1 ④）。
  • VADER（视频，2407.08737）：视频奖励反传，样本效率极高；支持图像美学/HPS/PickScore/视频文本对齐/目标检测等多种可微奖励。读数注意：论文表 1 每一列报告的就是被优化的那个奖励本身，除 100 份人评外没有独立于奖励的定量评价。
  • T2V-Turbo / v2（2405.18750 / 2410.05677）：一致性蒸馏（少步）中混入奖励反传，"又快又好"。
  • InstructVideo（2312.12490）：用图像奖励模型，通过"部分采样 + 编辑式微调"给视频扩散加人类反馈。

优点：收敛最快、样本最省。缺点：奖励须可微、显存大、最易 hack。适用：有好的可微奖励、算力有限想快速见效。

6.2 类别二：偏好优化（DPO 家族） ​

思想：用偏好对 (xw,xl) 直接优化，无需显式奖励模型（见 2.5 公式）。

视频域关键变体：

  • VideoDPO（2412.14167）：构建"视觉+对齐+运动"综合偏好，做偏好分数加权的 DPO；缓解单维度偏置。
  • DenseDPO（2506.03517，2025-06）：时序细粒度偏好 + 同源视频对，减少静态偏置、降低标注量。是 2025 下半年 DPO 方向的代表性进展。
  • IPO（2502.02088）：迭代式偏好优化，兼容 pointwise/pairwise，边生成边自我改进。
  • 相关（图像域，思路可直接搬到视频）——逐个说明：
    • Diffusion-DPO（2311.12908）：把 DPO 引入扩散的开山（详见 7.1 ③）。
    • MaPO — Margin-aware Preference Optimization（2406.06424）：无需参考模型的"边界感知"偏好优化，省掉一份参考模型的显存与前向。
    • SPO — Step-aware Preference Optimization（2406.04314）：让偏好与每一步去噪表现对齐，而非只看最终图，信号更密。
    • Diffusion-NPO — Negative Preference Optimization（GitHub）：专门学"负偏好（什么不要）"，与正偏好互补，改善对齐质量。
    • Diffusion-RPO — Relative Preference Optimization（2406.06382）：用相对偏好（跨样本相对比较）替代绝对成对，利用更充分。
    • Inversion-DPO（2507.11554）：借 DDIM 反演做精确、高效的 DPO 后训练。
    • D-Fusion（2505.22002）：构造视觉一致的偏好样本对，剔除无关差异干扰，让偏好聚焦在真正想改的属性上。
    • SmPO — Smoothed Preference Optimization（2506.02698）：用 ReNoise 反演做平滑偏好，兼容"人各有好"的多样偏好。
    • RankDPO / Scalable Ranked Preference Optimization（2410.18013）：用**排名（listwise）**偏好而非成对，且可规模化。
    • Diffusion-SDPO — Safeguarded DPO（2511.03317）：给 DPO 加安全护栏，优化偏好时不放大不安全内容（另见 7.3）。

优点：稳定、实现简单、可离线。缺点：上限受数据限、需构造大量偏好对、对硬约束（计数）提升有限。适用：有偏好数据、想稳、算力中等。

6.3 类别三：策略梯度 / GRPO（在线 RL） ​

思想：见 2.6。核心是组内相对优势 + 免 critic + ODE→SDE 引入探索。

流程（视频 GRPO 一次迭代）：

  1. 采一批 prompt，每个 prompt 用 SDE 采样器采 G 个视频（可少步以省时）。
  2. 每个视频用（多个）奖励打分，组内标准化得优势 Ai​。
  3. 计算逐时间步的 logπθ​，用裁剪目标 + KL 更新 θ（常 LoRA）。
  4. 周期性更新 πold​、参考模型。

代表工作：

  • Flow-GRPO（2505.05470，图像/流匹配奠基）：ODE→SDE + 降噪步数缩减。
  • DanceGRPO（2505.07818）：统一扩散/流匹配、图像/视频，多奖励，工程验证在 HunyuanVideo/SkyReels 等视频基座上稳定有效——视频 GRPO 的标杆开源工作。
  • InfLVG（2505.17574）：GRPO 用于长视频推理期一致性。
  • 图像域快速演进（正迁移到视频）：Pref-GRPO（成对偏好胜率，2508.20751）、BranchGRPO（分支采样提效，2509.06040）、DiffusionNFT（前向过程强化，2509.16117）、DGPO（Direct Group Preference，2510.08425）、G²RPO（granular，2510.01982）、TreeGRPO（2512.08153）、Multi-GRPO（2512.00743）。

优点：奖励可黑盒/多目标、上限高、真"在线探索"。缺点：采样成本高、需稳定化（除以小 std、reward hacking）、实现较重。适用：追求上限、有黑盒/可验证奖励、算力充足。

6.4 类别四：对抗后训练 + 蒸馏结合 RL（面向"少步/一步 + 高质量"） ​

背景：把多步模型蒸成 1~4 步会掉质量；用对抗/奖励信号在后训练里补回。

  • 对抗后训练（APT）/ Seaweed-APT（2501.08316）：用判别器做对抗后训练，实现一步高分辨率视频生成。
  • POSE（2508.21019）：分阶段一步对抗均衡，稳住一步视频训练；MagicDistillation（2503.13319）：弱到强蒸馏用于大规模人像少步合成；SwiftVideo（2508.06082）：轨迹-分布对齐的少步蒸馏；Flash-DMD（2511.20549）：DMD 蒸馏 + 联合 RL，少步且高保真（各篇详见 7.6）。
  • T2V-Turbo 系（2405.18750 / 2410.05677）：一致性蒸馏 + 奖励反传（同属 6.1 与 6.4 的交叉）。
  • TDM-R1（2603.07700）：用不可微（黑盒）奖励强化少步扩散，把 RL 用于加速后的质量恢复。

思路：判别器/奖励充当"质量守门 + 提升"，让加速不牺牲人类偏好。适用：实时/移动端、需要少步但不想掉质量。

6.5 类别五：推理期 / 提示期对齐（Training-free / Inference-time / Prompt-level） ​

不改（或少改）权重，在推理时或提示词层面对齐，成本极低、即插即用。

  • 推理期缩放/搜索（Inference-time Scaling / Search）：
    • Video-T1（Test-Time Scaling for Video, 2503.18942）：推理时用奖励引导的搜索（tree/beam）挑更好轨迹。
    • EvoSearch（2505.17618）：把图像/视频生成的推理期优化建模为进化搜索。
    • Diffusion Latent Beam Search（2501.19252）：latent 束搜索做 T2V 对齐。
    • VISTA（Test-Time Self-Improving Video Agent, 2510.15831）：智能体式自我改进。
  • 提示词优化（Prompt Optimization）：
    • VPO（2503.20491）：优化 prompt 以提升对齐、安全、无害。
    • PromptEnhancer（2509.04545）：用思维链（CoT）重写 prompt 来增强 T2I/T2V；Any2Caption（2503.24379）：把任意条件（图/轨迹/框）解读成 caption，以更好地控制生成；VideoRepair（2411.15115）：错位检测 + 局部再生修复视频（详见 7.7）。
  • 奖励引导采样（Reward-Guided Sampling）：无需训练，用奖励梯度/重要性采样在推理时把采样推向高奖励区——图像域代表：DAS — Alignment without Over-optimization（2501.05803，用序贯蒙特卡洛避免过优化）、Sampling Demon（2410.05760，训练自由的奖励引导采样）、FreeDoM（GitHub，训练自由的能量引导条件扩散），思路可迁移到视频。

优点：零/低训练成本、灵活、可与训练类叠加。缺点：推理更慢/更贵、上限有限、不改变模型本体能力。

7.1 奠基与"必读"：逐篇精读（2023–2025 上半年） ​

顺着读能看出整条脉络：图像域先跑通"去噪=MDP"，再逐步长出奖励模型、DPO、GRPO，最后迁移到视频。

图像域四块奠基石（视频方法的"母版"） ​

① DDPO — Training Diffusion Models with RL（2305.13301）

  • 问题：扩散模型只会最小化逐像素去噪 MSE，无法直接优化"人类觉得好不好、美不美、对不对"这类不可微、只在最终图上定义的目标。
  • 方法：首次把"逐步去噪"形式化成一个多步 MDP——状态 = (带噪图, 时间步)，动作 = 这一步去噪到下一状态，只有最终图才有奖励（终局稀疏奖励），然后用策略梯度（REINFORCE / 近似 PPO）直接最大化期望奖励。
  • 意义：整个视觉 RL 的思想源头。后面所有策略梯度/GRPO 工作（Flow-GRPO、DanceGRPO……）都站在"去噪=MDP"这一步上。配套开源代码 ddpo-pytorch 是入门这套形式化的最佳读物。

② DPOK（2305.16381）

  • 问题：纯策略梯度微调容易"跑飞"——偏离原模型、画质崩、多样性坍缩。
  • 方法：在 RL 微调目标里显式加 KL 正则（约束新策略别离预训练模型太远），结合奖励模型对文生图做在线 RL；与 DDPO 几乎同期、互为印证。
  • 意义：确立了"奖励 + KL 正则"这一直到今天仍是标配的稳定化范式——GRPO 目标里的 KL 项就是它的直系后代。

③ Diffusion-DPO（2311.12908）

  • 问题：RLHF 要先训奖励模型再做 RL，链路长、易 hack；能不能像 LLM 的 DPO 一样跳过显式奖励、直接用偏好对训练？
  • 方法：把语言模型的 DPO 推广到扩散——用成对偏好 (xw,xl)，在每个去噪时间步近似 logπ（用去噪误差之差代替），推出一个只依赖当前策略与参考模型的闭式损失，"抬高 winner、压低 loser"。
  • 意义：DPO 家族的开山，直接催生 VideoDPO、DenseDPO、IPO 等一整条视频偏好优化路线；因为无需在线采样，工程上最稳、最省。

④ AlignProp — Aligning T2I Diffusion with Reward Backpropagation（2310.03739）

  • 问题：策略梯度样本效率低；若奖励模型可微，为何不直接把奖励梯度传回生成器？
  • 方法：把最终图喂给可微奖励模型打分，再把 ∇θ​r 沿整条采样链反向传播到生成参数；用梯度截断（只反传最后若干步）+ LoRA 压显存。
  • 意义：奖励反传流派的规范化做法，是 VADER（视频版）的直接前身；样本效率极高，但也最容易 reward hacking，需早停/正则。

视频域奠基（把上面搬到时空张量） ​

⑤ InstructVideo（2312.12490）

  • 问题：视频扩散怎么用上"人类反馈"？逐帧奖励反传成本高、还易诱发画面静止。
  • 方法：复用图像奖励模型，通过"部分采样 + 编辑式微调"给视频扩散注入人类偏好——只在采样后段做奖励引导的微调，避免整段反传。
  • 意义：最早一批"给视频生成加人类反馈"的系统性工作之一，把 ReFL/奖励反馈从图像带进视频。

⑥ VADER — Video Diffusion Alignment via Reward Gradient（2407.08737）

  • 问题：视频对齐能不能像图像那样极省样本地做？
  • 方法：视频版奖励反传——支持一整套可微奖励（图像美学、HPS、PickScore、视频-文本对齐、目标检测等），沿采样链反传 + 梯度截断 + LoRA；几十到几百个 prompt 就能显著对齐（论文的训练规模是 2 张 A6000，平均约 12 小时；图 7 显示 12 GPU 小时内收敛）。
  • 意义：奖励反传在视频上的标杆，也是"想快速验证奖励是否合理"的首选工具；缺点仍是易 hack、显存大。这里的"显著对齐"要按论文口径读：表 1 报告的指标就是它优化的那个奖励，独立于奖励的评价全文只有 100 份人评。

⑦ VideoScore（2406.15252）

  • 问题：FVD/CLIP 与人类判断相关性弱，视频缺一个"像人一样打分"的奖励模型。
  • 方法：在大规模人工细粒度标注（视觉质量 / 时序一致 / 动态度 / 文本对齐 / 事实性等多维）上训练一个打分模型，可当自动评测指标，也可当 RL 奖励。
  • 意义：视频奖励建模的地基之一——没有好奖励，RL 就无从谈起；后续大量 GRPO/DPO 工作直接拿它当奖励信号。

⑧ T2V-Turbo-v2（2410.05677）

  • 问题：把视频模型蒸成少步会掉质量；能否一边加速一边提质？
  • 方法：在一致性蒸馏（少步）过程中融入奖励反传（图像-文本、视频-文本奖励）与精心设计的条件引导，把奖励信号"焊进"蒸馏。
  • 意义："蒸馏 + RL 联合"的代表，证明加速与对齐可以同框优化，启发后来 Flash-DMD、SwiftVideo 等少步+RL 工作。

⑨ VideoDPO（2412.14167）

  • 问题：单一维度偏好（只看画质）会诱发副作用（如只刷美学导致画面几乎静止）。
  • 方法：构建**"视觉质量 + 文本对齐 + 运动"三合一的全维（Omni）偏好数据集**，做偏好分数加权的 DPO。
  • 意义：视频 DPO 的代表作，把"多维度平衡"这一视频特有难题摆上台面，是理解"为什么视频偏好不能只看一维"的关键。

⑩ LiFT — Leveraging Human Feedback for T2V Alignment（2412.04814）

  • 问题：奖励只给一个分数，模型不知道"哪里不好、为什么"。
  • 方法：用人类反馈训练一个会"打分 + 给理由"的多模态 critic（LiFT-Critic），再用它指导 T2V 对齐。
  • 意义：把"可解释奖励"引入视频对齐，比纯标量奖励更抗 hacking、更利于诊断。

⑪ Seaweed-APT — Adversarial Post-Training（2501.08316）

  • 问题：多步视频扩散太慢，蒸成一步又掉质量。
  • 方法：用判别器做对抗后训练（APT），把模型逼成一步就能出高分辨率视频的生成器。
  • 意义："少步/一步 + 后训练"路线的标志性工作，判别器在这里既是"质量守门"也是"提升信号"，与 RL/奖励思路同源（对抗即一种隐式奖励）。

⑫ IPO — Iterative Preference Optimization for T2V（2502.02088）

  • 问题：纯离线 DPO 上限受数据限、且会分布漂移。
  • 方法：把偏好优化做成迭代闭环——自我生成 → 打分（兼容 pointwise/pairwise）→ 再优化，边生成边改进。
  • 意义：介于"离线 DPO"与"在线 GRPO"之间的实用折中，缓解数据瓶颈。

⑬ VPO — Aligning T2V via Prompt Optimization（2503.20491）

  • 问题：很多"对齐/安全"问题其实出在用户 prompt 太短/有歧义/含风险。
  • 方法：不改生成器权重，优化 prompt（改写成模型友好、对齐更好、更安全无害的版本）。
  • 意义：成本最低的一类对齐——推理期即插即用，可与训练类叠加。

⑭ MagicID — Hybrid Preference Optimization（2503.12689）

  • 问题：定制视频里人脸/角色**"变脸"**，且强行保 ID 会牺牲动态。
  • 方法：混合偏好优化——同时用"身份一致"与"动态保持"两类偏好信号，避免二者互相牺牲。
  • 意义：把偏好优化用于ID 一致这一具体、刚需的视频任务，示范了"任务专用奖励"的设计。

⑮ Video-T1 — Test-Time Scaling for Video（2503.18942）

  • 问题：不再训练，能否靠多花推理算力换更好视频？
  • 方法：推理时用奖励引导的搜索（树/束搜索）在多条采样轨迹里挑最优，把 LLM 的"test-time scaling"搬到视频。
  • 意义：开辟"推理期缩放"这一与训练正交的提升维度，成本可控、即插即用。

⑯ Flow-GRPO — Training Flow Matching via Online RL（2505.05470）

  • 问题：主流大模型是流匹配（确定性 ODE 采样），没有可优化的"动作概率"，GRPO 无从下手。
  • 方法：两大关键——(a) ODE→SDE 转换：把确定性采样改写成边缘分布等价的随机 SDE，每步变成高斯策略，于是能算 logπ、能探索；(b) 降噪步数缩减：训练用少步采样省时、评测用全步，大幅加速在线 RL。计数、文字渲染、空间关系等大涨且几乎不掉画质。
  • 意义：打通"流匹配 + 在线 GRPO"的钥匙，是 DanceGRPO 及后续几乎所有流匹配 GRPO 工作的技术前提。

⑰ DanceGRPO — Unleashing GRPO on Visual Generation（2505.07818）

  • 问题：GRPO 能否统一用于扩散 + 流匹配、图像 + 视频，并在真实大模型上稳定扩展？
  • 方法：一个统一框架，把 GRPO 接到 SD、Flux、HunyuanVideo、SkyReels 等多种底座，兼容美学/HPS/CLIP/视频质量等多奖励，工程上验证了稳定性与可扩展性。
  • 意义：视频 GRPO 后训练的标杆开源工作——它证明了"一套 GRPO 打通图像/视频"，是本领域从"图像域实验"迈向"视频域落地"的分水岭。

7.2 GRPO / 策略梯度类（2025 下半年爆发，多图像域→迁移视频） ​

2.6 讲了 GRPO 的原理，这里逐篇拆解它 2025 下半年的快速分化。一个心智框架：这些工作都在给 GRPO 打补丁，分别攻更稳、更省、更细、更专四个方向。

视频专用

  • InfLVG（2505.17574）——GRPO 攻长视频一致性。问题：长视频 rollout 会漂移、跨段主体/风格不一致。做法：把 GRPO 用在推理期，在线训练一个"该保留哪些历史 KV token"的上下文选择策略——给每个历史 token 打分后按 Plackett–Luce 不放回采样出 top-K，把上下文硬截断到固定长度；奖励是 ArcFace 人脸一致 + CLIP 提示对齐 + VLM 伪影判别三项之和。意义：少数把 GRPO 直接落到**视频特有难题（长时一致）**的工作。

方向一：更稳（抗 reward hacking / 抗尺度漂移）

  • Pref-GRPO（2508.20751）——用"成对偏好胜率"代替"绝对奖励标准化"。问题：GRPO 把组内奖励减均值除标准差当优势，当组内奖励都很接近时，除以极小 std 会放大噪声、诱发 reward hacking。做法：改成组内两两比较、用胜率当优势信号（谁赢的次数多谁优势高），奖励尺度漂移问题自然消失。意义：GRPO 稳定化的代表补丁，常与 UnifiedReward 等偏好奖励搭配。
  • GARDO — Reinforcing without Reward Hacking（2512.24138）——专治奖励作弊。问题：单一学习型奖励几乎必被钻空子。做法：在强化过程里引入抑制 hacking 的机制（约束/正则/多信号），在提升奖励的同时守住真实质量。意义：2026 年"如何让 RL 涨的是真质量而非假分数"这一核心命题的代表作。

方向二：更省（降低在线采样/反传成本）

  • BranchGRPO（2509.06040）——树状分支采样共享去噪前缀。问题：GRPO 每个 prompt 要独立采一组样本，去噪链很贵。做法：让同组样本共享前半段去噪前缀，在后段"分叉"成不同分支，一次前向摊到多个样本，大幅提效。意义：把"采样成本"这个 GRPO 最大痛点直接砍下来。
  • DiffusionNFT — Negative-aware Fine-Tuning（2509.16117）——免逐步 log-prob 的在线强化。问题：GRPO 要沿去噪链逐步算 logπ，实现重、易数值不稳。做法：把强化建到前向（加噪）过程上，用"正/负样本感知"的微调目标，绕开逐步重要性采样。意义：给"更轻量的在线 RL"提供了新范式。
  • TreeGRPO（2512.08153）——树优势（tree advantage）。做法：把一组 rollout 组织成树，用树结构上的相对比较得到更低方差的优势估计，兼顾提效与稳定。意义：BranchGRPO 思路在"优势估计"层面的延续。
  • MixGRPO / MixGRPO-Flash（2507.21802）——混合 ODE-SDE 的滑动窗口。问题：Flow-GRPO/DanceGRPO 要在所有去噪步上采样并优化，浪费严重。做法：只在一个滑动窗口内用 SDE 采样 + GRPO 优化、窗口外用 ODE 快速跳过，把随机性与梯度更新集中到少数关键步，窗口外还能上高阶求解器提速。意义：比 DanceGRPO 训练快约 50%（Flash 版快约 71%）且效果更好，是"更省"方向最实用的加速之一。

方向三：更细 / 多奖励（更精准的优势与目标）

  • G²RPO / Granular-GRPO（2510.01982）——更细粒度的奖励与优势。问题：把整张图/整段视频当一个奖励太粗。做法：在更细的粒度（区域/步/子目标）上算奖励与优势，让 RL 的信号更精准。意义：呼应视频里"逐段/逐帧优势"的需求。
  • Multi-GRPO（2512.00743）——多组优势 + 多奖励 + 树轨迹。做法：同时处理多个奖励、多组采样与树式轨迹，做多目标联合优化。意义：面向"一次后训练要同时对齐好几项"的现实需求。
  • DGPO — Direct Group Preference Optimization（2510.08425）——直接组偏好。做法：把"组内偏好"直接转成优化目标，免去逐步重要性采样，介于 DPO 的简洁与 GRPO 的在线之间。意义：又一条"轻量化在线偏好"的路子。
  • GDRO — Group-level Reward Post-training（2601.02036）——组级奖励适配扩散。做法：面向扩散/流匹配特点设计组级奖励的后训练目标。意义：2026 年 GRPO 家族继续"为生成模型量身定制"的代表。
  • Directly Aligning the Full Diffusion Trajectory with Fine-Grained Preference（2509.06942）——对齐整条去噪轨迹。问题：只对最终样本给偏好，中间步得不到监督。做法：把细粒度偏好信号铺到整条采样轨迹上，让每一步都朝偏好方向走。意义：把"过程奖励（process reward）"引入扩散对齐。

方向四：推理期 / 特殊架构

  • Inference-Time Alignment Control with RL Guidance（2508.21016）——推理期用 RL 引导控制"对齐强度"。做法：不改权重，在推理时用 RL 学到的引导信号，可调地控制对齐强弱。意义：把 RL 收益以"可控旋钮"形式放到推理期。
  • Co-GRPO（masked diffusion，2512.22288）——掩码扩散的协同 GRPO。做法：针对掩码/离散扩散这类生成范式设计协同优化的 GRPO。意义：GRPO 正在推广到连续扩散之外的生成范式。

注：以上偏图像/统一视觉生成的 GRPO 工作，其方法几乎都可直接用于视频（DanceGRPO 已证明统一框架可行），是理解"视频 GRPO 会怎么走"的重要风向标。

7.3 偏好优化 / DPO 类（含视频专用） ​

DPO 家族的共性是"无需显式奖励模型、用偏好对直接优化、训练稳"（原理见 2.5）。这一节的工作都在回答同一个问题：偏好信号怎么给得更准、更细、更安全。

  • DenseDPO — Fine-Grained Temporal Preference Optimization（2506.03517，2025-06，本节旗舰）

    • 问题：整段视频级偏好太"粗"——标注者说"A 比 B 好"，但模型不知道好在哪几帧；而且整段偏好里，"更好"往往来自"动得更少更稳"，反而强化了静态偏置。
    • 方法：两点关键——(1) 时序细粒度偏好：把偏好定位到视频的局部段落/帧，让监督信号知道"哪一段更好"；(2) 同源视频对：构造"仅在局部不同、其余相同"的成对视频（如同一视频不同去噪结果），使偏好聚焦于差异处、并大幅降低人工标注量。
    • 意义：2025 下半年 DPO 方向的代表作，直击视频 DPO 两大痛点（粗粒度 + 静态偏置），是"视频偏好该怎么标、怎么用"的范式更新。

  • Rethinking Direct Preference Optimization in Diffusion（2505.18736）

    • 问题：Diffusion-DPO 把 LLM 的 DPO 生搬到扩散，逐时间步近似其实有不少隐患（时间步加权、参考模型选择、损失尺度）。
    • 方法：系统重审扩散 DPO 的推导与实现细节，指出并修正若干近似偏差。
    • 意义：DPO"打地基"的工作，读它能避免很多实现踩坑。

  • DDSPO — Direct Diffusion Score Preference Optimization（2512.23426）

    • 问题：偏好只在最终样本上定义，去噪中间步缺监督。
    • 方法：用分步（stepwise）的策略对对比——在去噪轨迹的各步用 score/策略对做对比监督，把偏好信号铺到过程里。
    • 意义：DPO 版的"过程监督"，与 7.2 的"全轨迹对齐"异曲同工。

  • Ranking-based Preference Optimization（2510.18353）

    • 问题：二元偏好（谁好）信息量低，且难利用隐式的用户行为反馈（点击、停留、采纳）。
    • 方法：用排名（listwise/ranking）偏好代替成对，并从隐式用户反馈里学。
    • 意义：把推荐系统式的"隐式反馈 + 排名学习"引入生成对齐，更贴近真实产品数据。

  • Diffusion-SDPO — Safeguarded DPO（2511.03317）

    • 问题：优化偏好时可能顺带放大不安全内容，或为迎合偏好牺牲安全。
    • 方法：在 DPO 里加安全护栏（safeguard），让偏好优化与安全约束共存。
    • 意义：对齐与安全"同框"的代表，产品化必备视角。

  • Beyond Binary Preference（2601.04300）

    • 问题：一个"更好"把画质、对齐、运动、审美全糅在一起，模型学不清到底该改哪一维。
    • 方法：解耦属性——把偏好拆成多个细粒度维度分别对齐，避免"按下葫芦浮起瓢"。
    • 意义：与 VideoDPO 的"全维偏好"呼应，进一步走向"可解释、可分维"的偏好优化。

7.4 身份 / 主体 / 多主体一致性（用 RL/偏好增强） ​

这一节把抽象的"一致性"变成可打分的奖励（人脸相似度、主体匹配度），再用偏好/RL 去优化，是"任务专用奖励"的教学案例。

  • MagicID（2503.12689）——见 7.1 ⑭ 的精读。一句话：用混合偏好优化同时保"身份一致"与"动态丰富"，避免二者互相牺牲。它是本节的方法原型。
  • ID-Crafter（2511.00511）——VLM-grounded 在线 RL 做多主体视频。问题：一段视频里有多个人物/主体时，容易"张冠李戴"或某个主体崩坏。做法：用视觉语言模型（VLM）当裁判在线判断"每个主体是否正确、是否一致"，把这个判断当奖励做在线 RL（GRPO 式）。意义：RLAIF（AI 反馈）+ 多主体一致的代表，示范了"用 VLM 打分省人力"的在线范式。
  • MultiCrafter（2509.21953）——身份感知 RL 的多主体生成。做法：显式引入身份感知的奖励/约束，配合 RL 让多个主体各自保真。意义：与 ID-Crafter 同属"多主体一致 × RL"这条新兴小方向。
  • UMO（2509.06818，图像，思路可迁移）——用"匹配奖励"扩展到多身份一致。做法：把"生成主体与参考主体的匹配度"设计成奖励，扩展到多身份场景。意义：图像域的成熟做法，其"匹配即奖励"的思路可直接搬到视频。

7.5 运动 / 时序 / 物理 / 世界模型（RL 或反馈增强） ​

这一节针对视频最难、也最区别于图像的部分：运动、时序、物理。核心矛盾是——纯逐帧奖励会诱发"静止偏置"，必须专门给"动得对不对、动得真不真"打分。

  • Improving Dynamic Object Interactions with AI Feedback（2412.02617）——用 AI 反馈改善"动态物体交互"。问题：模型生成的物体交互（碰撞、抓取、接触）常常僵硬或不合理。做法：用 AI（VLM/判别器）对"交互是否自然合理"给反馈，作为训练信号去优化。意义：把反馈学习**聚焦到"交互动态"**这一具体弱项，而非笼统提质。
  • Temporal Regularization / FluxFlow（2503.15417）——时间正则增强运动。问题：视频模型倾向"偷懒"生成近乎静止的画面来降损失。做法：在训练中加入时间维度的正则/扰动，鼓励生成更丰富、更合理的运动。意义：一个轻量、通用、可与 RL 叠加的"抗静止"手段。
  • Inference-time Physics Alignment with Latent World Models（2601.10553，2026-01）——用"世界模型"当物理奖励。问题：视频"看着像"但常违反物理（重力、碰撞、守恒）。做法：推理时用一个潜在世界模型判断/引导生成是否符合物理规律，把"物理合理性"变成可对齐的信号。意义：2026 年最前沿的方向之一——把世界模型从"生成器"复用为"物理裁判"，预示"世界模型 × 物理奖励"的融合趋势。
  • DenseDPO（2506.03517）——见 7.3 精读。它的"时序细粒度偏好"本身就是缓解静态偏置、提升运动质量的关键武器，故也归入本节。

7.6 少步 / 蒸馏 + RL（加速与质量联合） ​

主题：把模型蒸成 1~4 步会掉质量，用对抗/奖励/RL 把质量补回来。

  • Seaweed-APT（2501.08316）——见 7.1 ⑪。对抗后训练（APT）实现一步高分辨率视频，是本节的范式起点。
  • POSE — Phased One-Step Adversarial Equilibrium（2508.21019）——分阶段的一步对抗。问题：一步对抗训练不稳、易崩。做法：把对抗过程分阶段推进，逐步逼近"一步生成"的均衡点，稳住训练。意义：让"一步视频"更可训、更可控。
  • SwiftVideo（2508.06082）——轨迹-分布对齐的少步生成。做法：通过对齐采样轨迹与目标分布来做少步蒸馏，兼顾一致性与画质。意义：少步蒸馏里"既要像又要稳"的一种解法。
  • Flash-DMD（2511.20549）——分布匹配蒸馏（DMD）+ 联合 RL。问题：DMD 少步生成质量仍有差距。做法：在 DMD 蒸馏的同时联合做 RL/奖励优化，少步且高保真。意义："蒸馏 + RL 联合"的 2025 末代表，延续 T2V-Turbo 的思路并做强。
  • TDM-R1（2603.07700）——用不可微奖励强化少步扩散。问题：加速后想再用 RL 提质，但奖励常不可微。做法：把 GRPO 式黑盒奖励用到少步（few-step）扩散上，恢复/提升加速后的质量。意义：把"策略梯度 RL"正式接到"少步模型"，是 2026 年"加速×RL"的新进展。
  • Adversarial Distribution Matching（2507.18569，ICCV'25 Highlight）——对抗分布匹配做蒸馏（图像/视频通用）。做法：用对抗目标做分布匹配式蒸馏，高效逼近教师分布。意义：少步蒸馏的一条主干技术路线，常被视频加速工作复用。

7.7 推理期 / 提示期 / 智能体式对齐 ​

主题：不改（或少改）权重，靠推理时搜索、提示词优化、或"生成-评估-再生成"的智能体闭环来对齐。成本低、见效快、可与训练类叠加。

  • Video-T1（2503.18942）——见 7.1 ⑮。测试时缩放：推理时用奖励引导搜索挑最优轨迹。
  • Diffusion Latent Beam Search（2501.19252）——在 latent 空间做束搜索对齐。做法：把去噪过程当搜索问题，在隐空间维护多条候选束（beam），按奖励扩展/剪枝，挑出与文本更对齐的结果。意义：把经典束搜索移植到视频扩散的推理期对齐。
  • EvoSearch（2505.17618）——把推理期优化建模成进化搜索（图像/视频通用）。做法：对生成的噪声/轨迹做变异 + 选择的进化式搜索，用奖励当适应度，逐代逼近高奖励样本。意义："test-time scaling"的一种强力实现，无需训练即可显著提质。
  • VPO（2503.20491）——见 7.1 ⑬。提示词优化：把用户 prompt 改写成对齐更好、更安全的版本。
  • VideoRepair（2411.15115）——错位检测 + 局部再生。问题：视频常"大体对、局部错"（漏了个物体、某区域不符）。做法：先用评估模块定位错位区域，再只对该区域局部再生修复，避免整段重采。意义：一种"诊断-修复"式的推理期对齐，精准且省算力。
  • VISTA（2510.15831）——测试时自我改进的视频智能体。做法：构建"生成 → 自我评估 → 反思 → 再生成"的智能体闭环，在推理时自动迭代变好。意义：Agent 化对齐的代表，把 LLM 智能体范式带进视频生成。
  • VideoAgent（2410.10076）——自我改进的视频生成。做法：用一个智能体反复生成-评估-修正，逐步提升输出。意义：与 VISTA 同属"生成-评估闭环"，是训练类方法的低成本互补。

7.8 奖励模型 / 评测（对齐的"指南针"，持续更新） ​

第 4 章的铁律：你优化什么，就得到什么。奖励模型决定 RL 往哪走，评测决定你能不能发现走歪了。

  • VideoScore（2406.15252）——见 7.1 ⑦。多维人类反馈奖励模型，既是自动指标又是 RL 奖励，是本领域最常被复用的视频奖励之一。
  • LiFT-Critic（2412.04814）——见 7.1 ⑩。会打分也会给理由的多模态 critic，比纯标量奖励更可解释、更抗 hacking。
  • VBench-2.0（2503.21755）——"内在忠实度"评测。问题：初代 VBench 主打画质/一致等表层维度，但模型越来越强后，瓶颈转向"是否真的符合常识、物理、人体结构"。做法：VBench-2.0 面向这些更深层、更接近真实世界的维度设计评测。意义：评测标准随模型进步而升级的典型，是判断"下一代视频模型强不强"的新标尺。
  • T2V-CompBench（2407.14505）——组合生成评测。专测"属性绑定、空间关系、数量、运动、交互"等组合能力——恰恰是 RL/对齐最想提升、也最容易量化成奖励的部分。意义：做"对齐类"后训练时，它既是评测也能反推奖励设计。
  • Stable Cinemetrics（2509.26555）——面向"专业级视频生成"的结构化评测。做法：建立更贴近影视工业的结构化评价体系（镜头、叙事、专业质量维度）。意义：把评测从"像不像视频"推向"够不够专业可用"。
  • LikePhys（2510.11512）——用"似然偏好"评测物理理解。做法：不靠人工打分，而是看模型对"符合物理 vs 违反物理"的样本给出的似然/偏好是否正确，以此衡量它是否真"懂物理"。意义：为"物理合理性"这一难量化维度提供了一把客观、可扩展的尺子，与 7.5 的物理对齐互为表里。

  • LoRA + 梯度检查点（gradient checkpointing）。
  • 少步采样训练（Flow-GRPO 降噪缩减）。
  • 部分时间步优化（只在部分去噪步算 loss）。
  • 分支/前缀复用采样（BranchGRPO）。
  • KV/特征缓存、稀疏注意力（SageAttention、Sparse-VideoGen 等）。
  • 低分辨率/短时长先训，再迁移。
  • 奖励模型批量推理、缓存解码结果。

  2. 任务：先做文本对齐 + 美学（奖励好拿：VideoScore + HPS 逐帧 + 运动守门）。
  3. 方法：VADER（论文规模：2×A6000 约 12 小时）验证奖励是否合理 → 再上 DanceGRPO 冲上限。

第 9 章 挑战、陷阱与未来方向 ​

9.1 尚未解决的核心挑战 ​

  1. Reward Hacking 系统性对策：单一学习型奖励几乎必被 hack。方向：可验证奖励（RLVR 式）、成对偏好胜率、多奖励博弈、奖励模型与策略共同演化、过程奖励（process reward）。
  2. 视频专属的"静态偏置"：如何在提升逐帧质量的同时不牺牲运动，仍无银弹。需要更好的运动/时序/物理奖励与逐段/逐帧优势。
  3. 奖励模型本身弱：视频奖励模型远不如 LLM 的成熟，跨模型/跨域泛化差、与人类相关性有限。更强的视频 RM 是瓶颈。
  4. 成本：视频采样 + 解码 + 奖励评估都贵，在线 RL 尤甚。需要更省的采样（少步、缓存、分支）与更省的 RL（免逐步 log-prob，如 DiffusionNFT）。
  5. 长视频 / 世界模型对齐：长时一致、可交互、物理正确的世界模型如何用 RL 对齐，是 2026 的大命题（Inference-time Physics Alignment、世界模型奖励等）。
  6. 多模态联合：视频 + 音频 + 相机 + 动作的联合后训练与统一奖励。
  7. 评测与训练的分离与可信：避免"优化 benchmark = 刷分"，需要更抗污染、更贴近人类的评测。

9.2 明确的趋势判断（2025→2026） ​

  • GRPO 成为视觉/视频对齐主力，并快速分化出"更稳（Pref-GRPO）、更省（BranchGRPO/DiffusionNFT）、更细（G²RPO/Multi/Tree）"三条支线。
  • 可验证奖励（RLVR）从 LLM 迁入视觉：计数、OCR、空间、物理仿真当奖励，天然抗 hacking。
  • 物理 / 世界模型奖励兴起：把"是否符合物理/世界规律"作为可学习或可验证的奖励。
  • 少步 + RL 深度融合：一步/少步生成 + RL/对抗后训练成为部署标配（实时视频）。
  • 统一模型的统一后训练：图像/视频/理解统一模型（如 UniVideo、Bagel 系）用一套 RL 同时对齐多任务。
  • Agent 化 / 测试时自改进：VISTA、VideoAgent 类"生成-评估-再生成"闭环，与训练类互补。
  • 偏好数据自动化（RLAIF）：VLM 当裁判 + 可验证信号，人类只做小规模校准与抽检。

9.3 给不同角色的建议 ​

  • 研究者：奖励建模、抗 hacking、运动/物理奖励、免逐步 log-prob 的高效 RL、视频过程奖励是高价值坑位。
  • 工程师：先 SFT + DPO 拿稳收益，再 GRPO 冲上限；把"评测/抽检/守门奖励"做成流水线。
  • 产品：推理期对齐（VPO/搜索）成本低见效快，可先上；训练类留给核心质量迭代。
