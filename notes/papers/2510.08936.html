RO-Bench: Large-scale robustness evaluation of MLLMs with text-driven counterfactual videos ​

项内容
arXiv2510.08936
提交日期2025-10-10
作者Zixi Yang, Jiapeng Li, Muxi Diao, Yinuo Jing, Kongming Liang
分类cs.AI, cs.CV
一句话把视频 caption 拆成物体属性/物体动作/背景/风格四个成分，用语言模型改写其中一项再驱动文本视频编辑模型生成反事实视频，配上自动生成的多选 QA，得到一个可以量化「原视频与编辑视频之间准确率落差」的鲁棒性测试集，并证明用同一条流水线造的反事实数据微调能把落差压下来。

§ 1 — 研究问题与重要性 ​

多模态大模型正在被推进内容审核、自动驾驶、实时监控这类高风险场景，而它们在受控数据上的表现与在被篡改内容上的表现之间可能存在巨大落差。作者指出这个落差基本没被系统探索过。

已有的 OOD 鲁棒性研究几乎全在静态图像上，视频域的鲁棒性测试又基本停留在加噪声或做画质损伤，绕开了视频真正的难点：时序动态与复杂的属性关系。噪声破坏的是低层信号，而现实中让模型失效的往往是「这个东西本来不该长成这样」——一个罕见的物体外观、一个不合常理的背景。作者把两个研究问题写在引言里：RQ1 是模型在反事实视频上表现如何、在理解被编辑内容时具体困难在哪；RQ2 是使用反事实视频会如何影响模型能力、能否反过来提升它们理解复杂视频的水平。

§ 2 — 前人工作与不足 ​

图像域的 OOD 基准已经比较成熟。OOD-CV 针对自然图像中单个 nuisance 因素的分布偏移建立了基准；LANCE 证明了用语言引导生成反事实图像来做压力测试是有价值的。作者的批评是这些努力集中在静态图像上，视频理解模型的评测因此留下空白。

视频域已有的鲁棒性工作（作者引用了大规模视频动作识别鲁棒性分析）多以噪声或 corruption 为主，这类扰动不触及视频里的时序动态与属性关系。换句话说，它们测的是「画质变差还能不能认出来」，而不是「内容变得反常还能不能理解」。

编辑工具这一侧，作者用到的资源来自 DAVIS、TGVE、MSR-VTT、BalanceCC 这些公开数据集与互联网视频，编辑模型则来自 CCEdit、Tune-A-Video 一类文本引导视频编辑工作。这些工作本身以生成质量为目标，没有被组织成评测协议，所以「用编辑视频做鲁棒性评测」这件事此前缺的不是生成能力，而是一条能保证编辑后题目仍然有唯一正确答案的流水线。

§ 3 — 重建作者的思考路径 ​

第一步是承认反事实视频不可能靠真实采集获得——按定义它们在世界上不存在。所以必须生成。

第二步是决定改什么。直接对视频做扰动会得到语义上说不清的结果，难以判定原题答案是否仍然成立。作者转而在文本上做改动：视频 caption 天然强调了重要视觉元素而忽略了无关细节，把 caption 拆成物体属性、物体动作、背景、风格四个结构化成分，改其中一个，就得到了一个语义明确、可控的反事实描述。然后把改过的 caption 连同原视频交给编辑模型，让它生成对应的新视频。

第三步是意识到生成质量不可控，所以需要先筛编辑模型。作者提出四个评估指标——Fantasy Level（FL）、Scene Complexity（SC）、Camera motion（CM）、Object Motion（OM）——先评一批编辑模型，按实验结果选出前三名再用于正式生成，最后再做一遍严格的人工筛选。这条链路的产出是 2.1k 条高质量视频-caption 对。

第四步是把视频变成可打分的题目。用 GPT-4o 按任务定义为每个视频生成问题，选项则分两种来源：动作识别、物体存在、物体识别这类任务的正确选项直接从 ground-truth caption 里抽；干扰项要求「既不平凡也不过难」，动作类任务的候选同时受动作与其主体约束，caption 任务则把原 caption 拆成属性、物体-动作、背景、风格、主体等成分再改动其中之一来造候选，最后打乱选项顺序。

§ 4 — 核心 Intuition ​

要测「模型是否真的看懂了画面」，最干净的办法是让画面变成模型没见过但人类一眼就懂的样子，同时保证题目答案仍然由画面唯一确定。文本驱动的视频编辑正好提供了这个杠杆：在 caption 的结构化成分上做单点改动，就能生成语义受控的分布外视频，而原本的问答格式一字不用改。

§ 5 — 具体方法与完整 Pipeline ​

流水线分四步（论文图 2）：收集高质量视频、用文本驱动方法生成反事实视频、按任务生成 QA 对、评测模型鲁棒性。

数据源。 公开数据集 DAVIS、TGVE、MSR-VTT、BalanceCC，加上互联网视频。数据覆盖四类主体（Human、Animal、Landscape、Object）与四类任务（Action Recognition、Object Recognition、Object Existence、Video Captioning）。

编辑 caption。 先用语言模型改写 caption。改动限制在四个关键视觉因素上：Object Attribute、Object Action、Background、Style。

编辑视频。 把改过的 caption 与原视频一起送入编辑模型。模型的选择由前述四个指标（FL/SC/CM/OM）的评测结果决定，取前三名，随后人工筛选，最终得到 2.1k 条高质量视频-caption 对。

生成 QA。 GPT-4o 先按任务定义为每个视频生成一个问题；选项按上文两种规则构造；物体存在类任务的选项固定为 yes / no / not sure。最终 RO-Bench 包含 8.6k 条多选 QA，覆盖 4 个视频理解任务。

训练集。 用同一条流水线另造了一份训练数据：332 个原视频、1328 条真实反事实视频样本、6640 条 QA 对。在其上微调 LLaVA-Next 得到 LLaVA-Next${\text{Ro}}$；作为对照，另用未编辑的视频数据训练同一模型得到 LLaVA-Next${\text{ori}}$。

一个具体例子。 一段原视频里一只棕色的狗在草地上奔跑，caption 的 Object Attribute 成分被改成「一只透明的玻璃质地的狗」，编辑模型据此生成新视频，原来的动作识别问题「视频中的动物在做什么」保持不变——答案仍然是奔跑，只有外观变成了训练分布里不存在的样子。模型如果依赖的是「棕色四足动物在草地上」这个统计模式而非动作本身，就会在这里翻车。

§ 7 — 实验设计与结论 ​

第一个问题：现有模型在反事实视频上掉多少（RQ1）。 Table 1 评测八个视频 MLLM，每个任务给出 Origin / Edit / Drop 三列。全表最后一行的 Overall 是 Origin 70.25、Edit 52.68、Drop −17.57。模型之间差异很大：VideoChat2（Mistral-7B）相对稳健，Overall 从 71.17 掉到 60.83，落差 −10.34；LLaVA-Next（Vicuna-7B）最敏感，从 69.98 掉到 43.41，落差 −26.56。VideoChatGPT 落差 −22.66，VideoChat −19.50，VideoLLaMA2 −16.08，mPLUG-Owl3 −18.56，Video-LLaVA −14.10，VideoLLaMA3 −12.73。

第二个问题：哪类任务、哪类编辑最致命。 按 Table 1 的任务列汇总，Action Recognition 的整体落差最大（Origin 66.90、Edit 42.91、Drop −23.99），Object Existence 最小（77.15 / 65.61 / −11.54），Captioning −18.82，Object Recognition −15.93。作者的解释是打断动态视觉线索会引发时序推理上的幻觉。按编辑因素比较（论文图 3），作者报告模型对物体变化的敏感度高于风格与背景，且背景与风格两者的影响接近；具体数值只在图中，本页不复述。

第三个问题：架构有没有系统性影响。 作者把八个模型按编码器分成两组（论文图 4）：使用冻结 CLIP ViT-L/14 的一组表现差于使用更大或经过微调的视频编码器的一组。Table 1 的分组标题也体现了这一划分。

第四个问题：反事实数据微调有没有用（RQ2）。 在 RO-Bench 上，LLaVA-Next${\text{Ro}}的Overall是Origin79.05、Edit74.23、Drop-4.83$，是全表落差最小的模型，好于原先最稳健的 VideoChat2（−10.34）。相对基线 LLaVA-Next 的 −26.56，落差缩小了 21.73 个百分点——这就是摘要里那个「21.73% 提升」的来源，它是落差指标的改善量，不是准确率的绝对提升；对应的 Edit 准确率提升是 43.41 → 74.23。对照组 LLaVA-Next${\text{ori}}（用未编辑视频训练）的Origin更高（77.34）但落差反而更大（-30.85$），说明单纯增加同分布训练数据不但没提升鲁棒性，还让它变差了。

第五个问题：这种微调会不会以牺牲通用能力为代价。 Table 2 在 MVBench 的 20 个任务上比较。LLaVA-Next 的平均分是 31.55，LLaVA-Next$_{\text{Ro}}是44.33，标注为+12.78$。同表里 GPT-4V 的平均分是 43.5，Video-ChatGPT 32.7，VideoChat 35.5，Video-LLaMA 34.1，mPLUG-OWL-V 29.7，Otter-V 26.8。作者据此说明反事实数据不仅补鲁棒性，还提升了通用视频理解能力，动作与物体相关任务提升尤为明显。

§ 8 — Take-aways ​

5 句版：反事实鲁棒性测试可以用「改 caption 的一个结构化成分再驱动视频编辑」低成本造出来，而且原题的问答格式一字不用改。八个视频 MLLM 在 RO-Bench 上整体落差 −17.57，动作识别最脆（−23.99），物体存在最稳（−11.54）。用同一条流水线造的 1328 条反事实样本微调 LLaVA-Next，把落差从 −26.56 压到 −4.83，同时 MVBench 20 任务平均分从 31.55 升到 44.33。关键对照是 LLaVA-Next$_{\text{ori}}：用等量未编辑数据训练不但没改善鲁棒性，落差反而扩大到-30.85$，说明起作用的是数据的反事实性质而不是数据量。整条流水线的可信度取决于「编辑后题目答案仍然唯一正确」，而这一步由自动流水线加人工筛选保证，论文没有报告这道人工筛选的一致性或通过率。

3 句版：RO-Bench 用文本驱动视频编辑造出动态 OOD 反事实测试集，量化模型在原视频与编辑视频之间的准确率落差。八个模型整体落差 −17.57，反事实微调把 LLaVA-Next 的落差压到 −4.83 并让 MVBench 均分从 31.55 升到 44.33。用等量未编辑数据训练的对照组落差反而扩大，这是全文最有说服力的一条证据。

1 句版：在 caption 的一个结构化成分上做单点改动再重新生成视频，就能得到一个既能暴露模型脆弱性、又能当训练数据用的反事实测试集。

§ 9 — 最脆弱的假设 ​

最要命的一条是：编辑后的视频仍然唯一地决定原题的正确答案。整个 Drop 指标的含义完全依赖这一点。如果编辑模型把「棕色的狗」改成透明玻璃质地时顺带破坏了奔跑动作的可辨识度，那么模型答错就不是鲁棒性问题，而是这道题在编辑后已经没有正确答案了。此时 Drop 度量的是生成质量而非模型能力，而所有排序结论都会随之失效。

论文为这条假设提供的证据是流程性的：先用 FL/SC/CM/OM 四个自定义指标筛选编辑模型、取前三名，再做「严格的人工筛选」保证视频质量，最终留下 2.1k 条视频-caption 对。这条链路是合理的，但它缺一个关键环节：论文没有报告人工筛选的标注者数量、一致性系数、通过率，也没有报告任何形式的人类在 RO-Bench 上的答题准确率。一个人类基线会直接钉死这条假设——如果人在编辑视频上的准确率与在原视频上基本持平，那么 −17.57 就确实归因于模型；如果人也掉，那么落差里有多少属于题目退化就无从分离。同样地，四个筛选指标 FL/SC/CM/OM 本身是作者自定义的自动指标，论文没有把它们对齐到人工判断上。这属于缺失证据而非反证，但它是全文最需要补的一格。

§ 10 — 最小复现实验 ​

一周内可做，不需要重跑编辑流水线。

  1. 从 RO-Bench 公开数据里随机抽 200 组「原视频 + 编辑视频 + 同一道题」。
  2. 招募 3 名标注者，在完全相同的题面下分别作答原视频版与编辑视频版（两版随机打散、间隔展示以避免记忆效应），记录逐题正确性与标注者间一致性。
  3. 计算人类的 Origin / Edit / Drop 三个数，与 Table 1 最后一行的 70.25 / 52.68 / −17.57 并列。
  4. 判据：若人类 Drop 在 ±3 个百分点内含零，则模型的 −17.57 可以干净地归因于鲁棒性缺陷，§9 的担忧被排除；若人类 Drop 明显为负（例如超过 −8），则模型落差中至少这一部分应归因于编辑导致的题目退化，Table 1 的全部 Drop 值需要按人类基线做偏移校正后再解读。
  5. 顺带记录人类判为「编辑后此题已无唯一答案」的比例，这个数直接量化了流水线的题目保真率。

§ 11 — 最强反例设计 ​

第一重攻击针对平凡基线的缺失。Table 2 的 MVBench 结果里，LLaVA-Next 的平均分是 31.55，Otter-V 是 26.8，mPLUG-OWL-V 是 29.7。MVBench 的题目多为四选一，随机猜测约为 25。也就是说表里有三个模型的成绩距离随机猜测不足 7 个百分点，而 LLaVA-Next$_{\text{Ro}}的44.33是从这样一个近随机的起点抬上来的。论文全表没有报告随机基线一行，读者无法在不自行查阅MVBench选项数的情况下判断+12.78$ 有多大。同样地，RO-Bench 的 Object Existence 任务只有 yes / no / not sure 三个选项，随机约 33，而 Table 1 里该任务的 Edit 列有模型落到 64.81，与随机的距离远小于与 Origin 的距离。任何引用这些数字的下游工作都应先补上随机基线。

第二重攻击针对同分布微调。LLaVA-Next${\text{Ro}}$ 的训练数据由与测试集完全相同的流水线生成：同一批编辑模型、同一个 GPT-4o 出题、同样的四个改动因素、同样的选项构造规则。它在 RO-Bench 上落差最小，这个结果无法区分「学会了识别反事实内容」与「学会了这条流水线的生成指纹」。一个可判定的对照是：换一族编辑模型（例如换成扩散架构完全不同的视频编辑器）与另一个出题模型重造一份 held-out 测试集，在其上重测 LLaVA-Next${\text{Ro}}。若落差回弹到接近基线的-26.56$，则收益主要来自流水线过拟合；若维持在个位数，则鲁棒性结论成立。Table 2 的 MVBench 结果是朝这个方向的证据（MVBench 与本流水线无关），但 MVBench 上的 44.33 仍低于同表 GPT-4V 的 43.5 之上仅 0.8，且 MVBench 测的是通用能力而非反事实鲁棒性，不能替代 held-out 反事实测试。

第三重是 Drop 指标本身的天花板效应。Drop 定义为 Origin 减 Edit，因此 Origin 越低可下降的空间越小。一个极端的平凡策略是让模型在所有条件下都输出同一个选项：Origin 与 Edit 都落到随机水平，Drop 趋近于零，鲁棒性看起来完美。Table 1 里没有任何一行是这种退化模型，但指标本身不排除它，所以 Drop 必须与 Edit 的绝对值并列报告才有意义。作者在文中确实同时给出了三列，这一点做得对；风险在于摘要只提「21.73% 提升」而没有说明它是落差改善量。

§ 12 — Follow-up Research Idea ​

驱动想法的局限是：这条流水线一次只改一个成分，因此它只能生成「单点反事实」。但真正让部署中的模型失效的往往是组合——一个罕见外观的物体、在一个罕见背景里、做一个罕见动作。摘要提到编辑覆盖了 Style、Object、Background 及其组合，而正文与两张表都是按单因素组织的，组合条件下的交互效应没有被拆开。

值得借鉴的相邻工具来自实验设计里的因子分析：把四个编辑因素当成四个二值因子，做一个 24 全因子设计，每个格子生成同等数量的视频，然后把模型准确率对主效应与交互项做方差分解。这与当前的「逐因素报告平均落差」是不同的分析对象——后者无法回答「物体与背景同时被改时的损失是否超过两者单独损失之和」。

第一个实验不需要新模型：在现有 2.1k 视频里选 200 个原视频，对每个都生成 16 种因子组合的编辑版本，共 3200 条视频，题目沿用原题。在其上评测 Table 1 里落差最大与最小的两个模型（LLaVA-Next 与 VideoChat2），对准确率做四因子方差分析。可检验的预测是：如果失效来自「统计模式被打断」，则交互项应显著为负（组合损失超过可加）；如果失效来自各因素独立地降低了某一类特征的可辨识度，则交互项应接近零。前者意味着鲁棒性训练必须覆盖组合而不是逐因素补数据，这会直接改写训练集的构造方式。
