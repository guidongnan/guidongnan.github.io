TimeSearch-R: Adaptive Temporal Search for Long-Form Video Understanding via Self-Verification Reinforcement Learning ​

项内容
arXiv2511.05489
提交日期2025-11-07
作者Junwen Pan, Qizhe Zhang, Rui Zhang, Ming Lu, Xin Wan, Yuan Zhang, Chang Liu, Qi She
分类cs.AI, cs.CV
一句话把时序搜索写成 text-video 交错的思维链并用 GRPO 端到端学，再补一个 CSV 环节——把 CoT 里搜到的帧抽出来让同一个策略模型只凭它们重答一遍，答对才发完整性奖励——以此在没有帧级标注的前提下监督中间搜索决策，防止 GRPO 退化成不搜索。

所属教程：长视频理解

本页依据 arxiv.org/e-print/2511.05489 的 LaTeX 源码（iclr2026_conference.tex 与 tables/*.tex）撰写，正文、表格与附录均已核验。论文为预印本，22 页 17 图，代码在 github.com/Time-Search/TimeSearch-R。

§ 1 — 研究问题与重要性 ​

时序搜索的目标是从几万帧里挑出回答问题所需的最小相关帧集。现有做法（VideoAgent、VideoTree、T*）都会逐步缩小搜索范围，但缩小的规则是人写的：先粗采样、再用检测器或 CLIP 打分、再放大。这类手工流程有两个后果——一是搜索策略没有被最终答案的梯度优化过，二是通常要挂一个外部大模型（GPT-4/GPT-4o）来做问题理解与打分。

论文的提法是把搜索直接写进模型的思维链：模型在 <think> 里推理，需要看细节时发出 <tool_call>，环境返回一段帧，接着继续想。这样搜索与回答共享同一个策略、同一个 RL 目标。

问题在于直接上 GRPO 会坏。GRPO 只奖励最终输出，中间的搜索决策完全无监督，于是出现两种失效（论文图 fig:challenges）：时序探索不足——模型漏掉关键帧却仍然蒙对，蒙对就被奖励；逻辑不一致——中间推理与最终答案自相矛盾。更极端的情况是训练崩塌：论文报告去掉 CSV 后，模型会逐渐减少搜索调用次数，到约第 300 步彻底不再搜索，完整性率趋于 0。这是一个很干净的负面结果——纯 outcome reward 会把工具使用直接优化掉。

§ 2 — 前人工作与不足 ​

静态采样这一族（Qwen2.5-VL、GPT-4o、Gemini-1.5-Pro）靠均匀采样加大帧数硬扛。表 tab:long_video_understanding 显示 Qwen2.5-VL-7B 用 768 帧在 VideoMME 上 65.1、MLVU 70.2、LongVideoBench 56.0，这是本文的基座与主要对照。

自适应时序搜索这一族靠外部模型驱动。VideoAgent 用 GPT-4 平均取 10.1 关键帧，VideoTree 用 GPT-4 取 128 帧，T* 用 GPT-4o 取 32 帧在 VideoMME 上 64.1。它们的共同点是流程手工设计、且依赖闭源模型，因此"搜索策略"从未被端到端学过。

纯文本推理的视频模型（Video-R1）把推理放在文本里，视觉输入仍是一次性给定的静态帧集，因此推理再长也改变不了看到了什么。

评测时序搜索本身需要帧级标注，成本高。已有工作（FrameVoyager、MDP3）退而用下游任务当代理指标，但它们只能从预先给定的候选帧池里选子集，不与视频环境交互。CSV 的设计动机正来自这里：用"只凭搜到的帧能否重答对"当作完整性的代理，既不需要标注，又不受候选池限制。

§ 3 — 重建作者的思考路径 ​

第一步是把公式写下来。整条推理链可以分解成

Pθ​(A,C∣V~,Q)=Temporal SearchPθ​(C∣V~,Q)​​⋅Answer PredictionPθ​(A∣C,V~,Q)​​.

只用 outcome reward，梯度只经过第二项有效地流动，第一项拿到的是被答案对错稀释后的信号。要修就必须给第一项一个直接的目标。

第二步是问：怎么在没有帧级标注的情况下判断"搜到的帧够不够"。作者给出的答案很朴素——如果这些帧真的足够，那么把推理过程全部扔掉、只拿这些帧重新问一遍，模型应该还能答对。这就是 CSV。

第三步是意识到这个判据必须被真值门控，否则它会奖励一致的错误：模型第一次答错、重答也错，两次一致，如果只看一致性就会拿到奖励。所以完整性奖励写成

Rc​=1[Acc(A,A∗)>0.5]⋅Acc(Ac​,A∗),

两个因子都用了 ground-truth 答案 A∗。这一点值得澄清：论文名为"self-verification"，指的是由同一个策略模型担任重答者，而不是"由模型自己判定对错"。奖励信号本身是有真值锚点的，因此不存在朴素意义上的自我确认偏差。

第四步是数据。RL 的一个常见坑是很多样本靠语言先验就能答对，此时一组 rollout 全对、组内 advantage 归零，梯度消失。作者据此设计了两级过滤：先删掉"只给 4 帧均匀采样就能答对"的样本（切掉语言捷径），再删掉"多次搜索、大量帧仍答不对"的样本（切掉噪声）。

§ 4 — 核心 Intuition ​

只奖励最终答案会让模型学会不搜索，因为不搜索也能靠语言先验和粗采样蒙对一部分，而搜索有成本无回报。要让搜索本身可被优化，就需要一个能单独衡量"搜到的东西够不够"的信号；而在没有帧级标注时，这个信号可以由模型自己制造——把搜来的帧单独拿出来重答一遍，答对说明证据充分。

§ 5 — 具体方法与完整 Pipeline ​

交互协议。给定视频 V 与问题 Q，先均匀采一份预览 V~。每一步策略模型生成 Tk​；若其中含 search 指令，模型必须同时给出时间边界 tsk​,tek​ 与文本查询 qk，环境执行

Vk​=search(V;tsk​,tek​,qk,F)={fk1​,…,fkF​}.

交错 CoT 记作 Ck​={(T1​,V1​),…,(Tk​,Vk​)}，直到模型给出 <answer> 或用完预算。实现上每次搜索至多取 8 帧、总共至多 8 次搜索。

帧检索的实现。环境侧用一个轻量 VLM（SigLIP-400M）在 [tsk​,tek​] 内计算帧间相似度以及与查询 qk 的相关度，再用 determinantal point process（DPP） 抽出信息量最大的 F 帧。DPP 的作用是同时兼顾相关性与多样性，避免取回 8 张几乎一样的帧。

CSV 环节。GRPO rollout 结束后，从 C 中把视频片段抽出来拼成动态帧集 Vc​；同一个策略模型被要求只用 Vc​（禁止再搜索）重答问题得到 Ac​。期望是 Pθ​(Ac​∣Vc​,Q)≈Pθ​(A∣C,V~,Q)。

奖励：R=Rc​+Rfmt​+Racc​。格式奖励是整条轨迹的二值判定，所有步骤都合规才给 1。准确率奖励在多选题上做选项字母精确匹配，在开放题上用 LLM-as-a-Judge 给二值分。

训练。两阶段。SFT 冷启用同一套数据构造流程，由 GPT-4o 生成交错推理过程与答案；训练时掩掉搜索返回的视频结果，强迫模型学会自己产出有意义的时间窗与查询，而不是照抄环境反馈。随后用 GRPO-CSV 做 RL。超参：Qwen2.5-VL-7B-Instruct 基座，AdamW，lr 1e-6，KL 系数 β=0.005，batch 4、每个 prompt 8 条 rollout，32 张 A100。

数据：Haystack-Ego4D、VideoMarathon、CinePile 三源混合，经两级过滤。

一个具体例子。一段长视频问"某个道具第一次出现在哪个房间"。预览帧看不到细节，模型在 <think> 里判断证据不足，发出 search，给出一个时间区间和查询词"道具特写"；环境用 SigLIP 在该区间内打分、DPP 抽 8 帧回填；模型继续推理并给出答案。训练时 CSV 会把这 8 帧单独拿出来再问一遍——如果模型这次答不对，说明它是靠预览帧或语言先验蒙对的，完整性奖励为零。

§ 6 — 核心数学推导 ​

值得展开的是完整性奖励的门控结构。设 a=Acc(A,A∗)∈{0,1}、ac​=Acc(Ac​,A∗)∈{0,1}，则

Rc​=1[a>0.5]⋅ac​=a⋅ac​.

四种组合的取值是：答对且重答对得 1；答对但重答错得 0（说明搜到的帧不足以支撑答案，原答案很可能来自预览帧或语言先验）；答错得 0（无论重答如何）。这个乘积形式同时抑制了两个 hack：一是"搜一堆无关帧但靠先验答对"（a=1,ac​=0，不给分），二是"搜得很准但整条推理走歪答错"（a=0，不给分）。

与之相对，若把完整性奖励改成纯一致性 1[Ac​=A]（不用真值），则"两次都错但错得一致"也会拿满分，模型可以通过把搜索结果做得毫无信息量、让两次回答都退化到同一个语言先验来刷分。论文选择用 A∗ 做双重锚点，正是为了堵这条路。

至于消融里 GRPO 崩塌的机制，可以这样理解：搜索动作会拉长轨迹、引入更多可能出错的格式步骤，而 outcome reward 下它的期望回报增量近似为零（模型不搜索也能靠预览蒙对相当一部分）。于是"不搜索"是一个回报不差而方差更小的策略，梯度自然把概率质量推过去。CSV 把 Rc​ 加进来后，不搜索意味着 Vc​ 为空、重答必然失败、Rc​≡0，"不搜索"这条路的回报被显式压低。这是我对论文观察到的崩塌现象的机制解释，属于基于证据的推断，论文本身只报告了现象。

§ 7 — 实验设计与结论 ​

问题一：时序搜索本身做得怎么样？ 表 tab:temporal_search（Haystack-LVBench，8 帧预算）。Temporal 三元组 P/R/F1：均匀采样 1.4 / 6.3 / 2.2，VideoAgent(GPT-4) 1.2 / 8.5 / 2.1，Retrieval-based(GPT-4o) 1.5 / 6.3 / 2.3，T*(GPT-4o) 1.6 / 7.1 / 2.5，TimeSearch-R 5.4 / 22.3 / 8.1。Visual F1：TimeSearch-R 69.2，此前最好的 VideoAgent 64.7。QA 准确率：TimeSearch-R 在 Haystack-LVBench 52.1、Haystack-Ego4D 53.5；T*(GPT-4o, 8 帧) 是 51.9 / 45.0；均匀采样用 Qwen2.5-VL-7B 是 33.7 / 32.0，用 GPT-4o 是 47.1 / 41.5。TimeSearch-R 自适应决定的平均关键帧数是 8.8。

这里必须把绝对水位说清楚：temporal F1 = 8.1 意味着挑出的时间位置绝大多数是错的，只是它比此前的 2.5 高了三倍多。整列的最高值都在个位数。

问题二：长视频理解上净赚多少？ 表 tab:long_video_understanding，TimeSearch-R-7B 与基座同为 768 帧输入。VideoMME short/medium/long/overall：76.8 / 67.1 / 56.0 / 66.6，基座 Qwen2.5-VL-7B 是 76.3 / 66.0 / 54.6 / 65.1，逐档增益 +0.5 / +1.1 / +1.4 / +1.5，随时长单调增大。MLVU 71.5 对 70.2（+1.3），LongVideoBench 60.1 对 56.0（+4.1）。相对 Video-R1-7B（768 帧）的 65.7 / 68.4 / 58.1，LongVideoBench 高 2.0。相对 T*（GPT-4o，32 帧）的 VideoMME 64.1 高 2.5。

另有一行很重要：Qwen2.5-VL-7B 直接用 CoT prompting 挂上搜索、不做训练，VideoMME 掉到 51.8、MLVU 58.9、LongVideoBench 49.1，全面低于什么都不做的基座。免训练地给模型一把工具反而是有害的。

问题三：SFT 与 RL 各自贡献多少？ 表 tab:ablation_grpo_csv（Haystack-LVBench 的 P/R/F1 与 VideoMME 的完整性/一致性/准确率）。Qwen2.5-VL + search：0.0 / 0.0 / 0.0，44.2 / 59.4 / 51.8——完全不会调用搜索。SFT 冷启后：7.4 / 11.6 / 7.8，60.5 / 69.2 / 59.2。GRPO（崩塌前）：5.2 / 18.8 / 7.4，57.2 / 69.3 / 65.1。GRPO-CSV 无准确率奖励：6.1 / 19.8 / 8.2，61.2 / 75.3 / 64.8。GRPO-CSV 带准确率奖励（完整方法）：5.4 / 22.3 / 8.1，60.2 / 71.8 / 66.6。

三条读得出来的结论：SFT 是搜索能力的来源（F1 从 0 到 7.8）；GRPO 在没有 CSV 时会把完整性从 60.5 压到 57.2、F1 从 7.8 压到 7.4，且训练最终崩塌；CSV 把完整性与一致性拉回来，加上准确率奖励后 QA 最高。但也要如实记下完整方法的 temporal F1（8.1）与完整性（60.2）都略低于"无准确率奖励"变体（8.2 / 61.2），作者自己的措辞是只用完整性奖励能拿到最好的完整性与一致性，但 QA 会降 0.3。

问题四：数据过滤有多重要？ 表 tab:ablation_dataset（VideoMME）。基座（第一行）General short/medium/long/overall = 76.3 / 66.0 / 54.6 / 65.1，Reasoning temporal/spatial/action/object = 51.4 / 76.8 / 56.8 / 59.5。Ego+Exo 无过滤：74.2 / 62.7 / 51.3 / 62.8，比基座还低 2.3 点。Ego+过滤：76.4 / 64.7 / 54.9 / 65.3。Ego+Exo+过滤：76.8 / 67.1 / 56.0 / 66.6。作者的解释是未过滤数据里存在语言偏置样本，导致组内 advantage 归零、训练效率与稳定性受损。注意 Reasoning 的 spatial 一列：基座 76.8 是全表最高，完整方法 75.0 反而略低。

问题五：效率代价。 表 tab:efficiency（Haystack-Ego4D，A100）：VideoAgent 34.9 秒、Retrieval-based 32.2 秒、T*（检测器版）11.1 秒、TimeSearch-R 13.4 秒。TimeSearch-R 的检索侧只用 SigLIP-400M 且不需要外部 question grounding 模型，但端到端延迟比 T* 高 2.3 秒。

§ 8 — Take-aways ​

5 句版：把时序搜索写进思维链后，纯 outcome reward 的 GRPO 会把搜索行为直接优化掉——论文报告约第 300 步模型彻底停止搜索、完整性率趋零，这是全文最有价值的负面结果。CSV 用"只拿搜到的帧重答一遍"当完整性代理，绕开了帧级标注，且用 Rc​=a⋅ac​ 的双真值门控同时堵住"蒙对"与"搜准但答错"两条捷径。两级数据过滤（删掉 4 帧就能答对的、删掉怎么搜都答不对的）是让 GRPO 不退化的前提，未过滤时 RL 训练后比基座还低 2.3 点。头条数字是 LongVideoBench 60.1（相对基座 +4.1、相对 Video-R1 +2.0），但 VideoMME 只 +1.5、MLVU 只 +1.3。时序搜索指标的绝对水位极低（F1 8.1，此前最好 2.5），"三倍提升"是在接近地板的区间里发生的。

3 句版：端到端学出来的时序搜索确实优于手工流程，但代价是必须补一个中间监督信号，否则 RL 会消灭工具使用。CSV 的巧妙之处在于用模型自己的重答能力代替帧级标注，同时用真值把这个代理锚住。净收益在需要长程检索的基准上明显（LongVideoBench +4.1），在通用基准上只有 1 点出头。

1 句版：给"搜到的帧够不够"造一个不需要标注的奖励，方法是把这些帧单独拿出来让模型重答一遍，答对才算数。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：temporal similarity 这个指标能够衡量"找到了正确的帧"，因此 F1 从 2.5 提到 8.1 意味着搜索能力有实质进步。

看整张表 tab:temporal_search 的 temporal F1 一列：均匀采样 2.2、VideoAgent 2.1、Retrieval-based 2.3、T* 2.5、TimeSearch-R 8.1，32 帧预算下的 T* 也只有 3.1。也就是说，除本文外的全部方法都挤在 2.1 到 3.1 这个区间里，而均匀采样的 2.2 就已经落在这个区间的中间。一个不做任何搜索的平凡基线与所有精心设计的搜索智能体在这个指标上无法区分，这本身就说明该指标在这个区间内几乎不携带信息。

与此同时，QA 准确率的差异却很大：同样用 8 帧、temporal F1 都是 2.2 的均匀采样，换成 Qwen2.5-VL-7B 得 33.7、换成 GPT-4o 得 47.1，差 13.4 点。帧完全相同、指标完全相同，答案质量差一倍。这直接说明在这个区间里，QA 表现主要由基座模型决定而非由帧集决定。

这为 8.1 提供了一个替代解释：它可能主要反映"TimeSearch-R 平均取了 8.8 帧且经过 DPP 去冗余"这类分布性质，而不是"找到了标注的关键时刻"。论文没有做能区分这两者的对照——比如把 TimeSearch-R 搜出来的帧交给 GPT-4o 回答，或者反过来把 T* 的帧交给训练后的 TimeSearch-R 回答。这类交叉替换实验是把"搜索质量"与"回答能力"分开的标准手段，在论文中不存在。

需要说明的是，这条批评不否定 QA 层面的结果：Haystack-Ego4D 上 53.5 对 T*(GPT-4o) 的 45.0 是实打实的。它质疑的是"时序搜索能力提升三倍"这个表述的证据强度。

§ 10 — 最小复现实验 ​

不需要复现 32 卡 RL 训练。一周内可做完的最小验证：

  1. 取论文开源的 TimeSearch-R-7B 与 T* 的公开实现，在 Haystack-LVBench 上各跑一遍，保存两者搜出的帧集（8 帧预算）。
  2. 做 2×2 交叉：{TimeSearch-R 帧集，T* 帧集，均匀 8 帧} × {TimeSearch-R-7B 作答，未训练的 Qwen2.5-VL-7B 作答}。
  3. 关键测量：每格的 QA 准确率，以及每格对应的 temporal F1（帧集决定，与作答模型无关）。
  4. 判据：若给定同一个作答模型时，三种帧集的 QA 准确率差异远小于给定同一帧集时两个作答模型的差异，则"增益主要来自回答能力而非搜索质量"成立，temporal F1 的三倍提升不能被解释为搜索能力的实质进步；反之则论文的归因站得住。
  5. 附加对照：加一个随机区间基线——随机取 8 个时间点、每点用 DPP 在小窗内选帧，凑够 8.8 帧的平均预算。若它的 temporal F1 也能达到 5 以上，则该指标在这个量级上主要由帧数与分散度决定。

§ 11 — 最强反例设计 ​

第一重攻击：主结果的净增益被 SFT 的损伤掩盖了。 表 tab:ablation_grpo_csv 显示 SFT 冷启后的 VideoMME 准确率是 59.2，而完全未经训练的基座是 65.1——SFT 让模型掉了 5.9 点。随后 GRPO-CSV 把它拉到 66.6。也就是说，整条训练管线相对基座的净收益只有 +1.5 点，而 RL 阶段 +7.4 点里的大部分是在修复 SFT 造成的退化。构造性的攻击是：跳过 SFT，直接用 GRPO-CSV 从基座开始训（论文声称 SFT 是"让 RL 更高效"的冷启，而非必需）。若跳过 SFT 后仍能到 66 附近，则 SFT 阶段是纯粹的绕路；若跳不到，则说明整个方法的能力上限受制于 GPT-4o 生成的 SFT 轨迹质量，而非 RL 本身。

第二重攻击：把 LongVideoBench 的 +4.1 与 VideoMME 的 +1.5 放在一起看。 同一个模型、同一批帧预算，在一个基准上涨 4.1、在另外两个上只涨 1.3 与 1.5。LongVideoBench 是四个基准里对"从长视频中检索细节信息"最敏感的一个，这与作者的机制解释一致，但也意味着方法的收益高度依赖基准的构造方式。更尖锐的构造是取 tab:ablation_dataset 里 Reasoning 的 spatial 一列——基座 76.8 是全表最高值，完整方法 75.0 反而低了 1.8 点。若把评测重心放在空间推理上，结论会反过来。论文没有讨论这个下降。

第三重攻击：效率论述在最强对手面前不成立。 论文强调 TimeSearch-R 不需要外部的 question grounding 模型（表 tab:efficiency 里它的该列是 --），检索侧只用 SigLIP-400M。但端到端延迟是 13.4 秒，高于 T*（检测器版）的 11.1 秒。硬件（A100）是写明的，这一点比很多同类工作规范；问题在于结论的方向——去掉外部模型并没有换来更快，只换来了更简单的部署。把这一列诚实地读出来，"效率优势"这个说法就只剩"不依赖闭源 API"了。

第四重攻击：没有种子重复。 全文表格都是单次运行。VideoMME 上 +1.5、MLVU 上 +1.3，以及消融里完整方法与"无准确率奖励"变体之间 F1 8.1 对 8.2、完整性 60.2 对 61.2 这样的差距，都在 RL 训练常见的种子波动量级内。论文用这些差距支撑"加入准确率奖励是必要的"这一结论，证据强度不足。

§ 12 — Follow-up Research Idea ​

驱动局限：CSV 用"重答对不对"这一个二值信号来概括"搜到的帧够不够"。这个信号极其稀疏——它把一整个帧集压成 1 bit，而且只在原答案已经正确时才被激活。结果是模型知道"这次搜索不够好"，但不知道缺的是哪一段。论文报告的 temporal precision 只有 5.4，说明模型确实经常搜回大量无关帧，而 CSV 无法告诉它该往哪个方向收。

新的 framing：把完整性验证从"重答一次"升级为留一法的反事实归因。具体做法是在 CSV 阶段做多次重答：把动态帧集 Vc​ 按搜索步骤切成若干子集，每次剔除一个子集重答，观察答案是否翻转。翻转说明该子集是必要证据，不翻转说明它是冗余。这样每一步搜索都能拿到一个属于自己的信用分，稀疏的 1 bit 被拆成了 per-step 的密集信号，而且仍然不需要任何帧级标注。这把 CSV 从"验证器"变成了"信用分配器"，正好补上论文里 precision 低而 recall 相对高（5.4 对 22.3）所暴露的问题——模型学会了广撒网，但没有被教会收网。

可借鉴的相邻工具：一是合作博弈里的 Shapley value 与其采样近似，它正是为"多个参与者对同一结果的贡献如何分摊"设计的，把每次搜索当作一个参与者可以直接套用；二是可解释性里的 leave-one-out / occlusion 归因；三是 RL 中的 hindsight credit assignment 与 counterfactual baseline（COMA），它们处理的正是多步动作共享单一终端奖励的情形。

第一个实验：在现有 TimeSearch-R checkpoint 上先不训练，只做离线分析——对一批已有轨迹计算每个搜索步的留一法翻转率，看它与该步帧集和标注关键时刻的 IoU 的相关性。若相关性显著，说明反事实翻转率是帧级标注的免费代理，可以直接当奖励用；随后用它替换 CSV 的二值完整性奖励重训，重点看 temporal precision 能否从 5.4 提上去而 recall 不掉。若 precision 能上去而 QA 不变，那就恰好证明了 §9 的怀疑——temporal 指标与 QA 是两件被混为一谈的事。
