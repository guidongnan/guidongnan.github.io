TempAct: Advancing Temporal Plausibility in Autoregressive Video Generation via Planner-Executor RL ​

项内容
arXiv2606.28016
提交日期2026-06-26
作者Jing Wang, Xiangxin Zhou, Jiajun Liang, Kaiqi Liu, Wanyuan Pang, Zhenyu Xie, Tianyu Pang, Xiaodan Liang
分类cs.CV
一句话用「LLM 规划器把全局指令拆成带时间跨度的分步 prompt + AR 视频执行器在自己生成的历史上兑现这些 prompt」的分层 RL，规划组内嵌执行组以分别做 plan 级与切换时刻级的 credit assignment。

所属教程：自回归视频生成

版本说明

本文基于 v2（2026-07-02 修订）全文撰写；v1 提交于 2026-06-26。abs 页与 v2 的标题在缩写上略有差异（v2 正文标题写作 "Planner-Executor Reinforcement Learning"），frontmatter 采用 abs 页的官方标题。

§ 1 — 研究问题与重要性 ​

把预训练视频扩散模型蒸成少步自回归（AR）生成器已经是低延迟流式生成的标准做法：模型不再一次性合成整段视频，而是逐 chunk 生成，用 attention state、KV cache 或 visual cache 携带因果视觉上下文。但这个 chunk-wise 形式带来一个此前没被清楚定义的问题——时序指令跟随变得歧义。

绝大多数 AR 生成器给每个 chunk 喂同一条全局 prompt。模型知道完整指令，却不知道当前这一块该兑现指令的哪一部分。论文用一个具体例子说明：指令要求狗先坐下、然后叼起球跑开，而单 prompt 的 Self-Forcing 基线在开头就画出「狗一边坐着一边叼着球」，把后期事件提前了。作者把这类失败命名为 temporal confusion：逐帧看都合理，但事件顺序在 chunk 之间坍缩或糊在一起。

这个问题重要，是因为它不是画质问题、也不是长程一致性问题，现有的评测（VBench、CLIP score、ImageReward、VideoAlign）对事件顺序与长程时序依赖都不敏感，所以它长期被指标掩盖。而对交互式与叙事性应用来说，事件顺序恰恰是最基本的可控性。

§ 2 — 前人工作与不足 ​

AR 视频生成侧：CausVid 用 video DMD 与 KV cache 把双向 DiT 转成因果生成器；Self-Forcing 用自回归 rollout 与视频级反馈缓解 exposure bias；后续工作管理上下文记忆以支撑更一致的长 rollout；LongLive 引入 KV-recache、streaming long tuning 与 frame-sink attention；Causal Forcing 用 AR 教师做 ODE 初始化再接 DMD 后训练，弥合双向教师与因果学生之间的架构 gap。这些方法都在给定一条文本条件下改进流式效率与 rollout 稳定性，没有处理「一条复杂指令内部该如何在时间上分配」。

生成模型 RL 侧：Flow-GRPO 与 DanceGRPO 通过 ODE-to-SDE 转换让 GRPO 式策略更新适用于扩散与 flow matching；后续工作改进采样方案、credit assignment、clipping 与正则化。更贴近的三篇是 AR-CoPO（chunk 级 forking 与局部对比更新）、Astrolabe（前向过程负样本感知微调 + 流式局部窗口更新）、KVPO（ODE-native GRPO + KV cache 语义探索 + 速度空间对比目标）。论文对它们的批评很精确：这些方法推进的是执行器级别的偏好对齐，但都不显式建模「复杂指令应当如何在时间上组织」，事件顺序与长程语义依赖仍处于欠定状态。

为什么 SFT 与蒸馏不够：SFT 在干净的 teacher-forced 历史上训练，推理时却要从不完美的 rollout 出发，存在 exposure bias；DMD 这类基于 rollout 的蒸馏能缩小这个 mismatch，但它优化的仍是低层去噪或教师分布匹配，不直接强制动作顺序或 prompt 切换的正确性。

§ 3 — 重建作者的思考路径 ​

第一步是从失败模式反推。既然全局 prompt 让模型不知道当前该做哪一步，最直接的修法是换成分步 prompt。作者显然试了——而且这一步真的把问题变得更糟（消融里从 0.325 掉到 0.248）。这是整篇论文最有信息量的负结果：难度被搬到了 prompt 切换时刻。AR 执行器在换 prompt 时会延续上一动作、把相邻步的语义糊在一起、或把前面的错误带到后面。

第二步是识别这里其实有两个耦合的子问题：先决定每个阶段该发生什么，再决定在自回归视觉历史下如何兑现这个阶段。只训执行器只能改善第二个，改不了一个含糊或时点不当的时间分解。

第三步是注意到 LLM 规划天然适合第一个子问题，但固定的预处理式 LLM 规划有个盲点：它不知道哪种分解对这个特定视频模型是可执行的。要让规划器学到「可执行性」，就必须从执行结果拿反馈——这就把问题推向 RL。

第四步是 credit assignment 的结构设计。如果只按最终视频打一个分，规划质量与执行质量的贡献无法分离。而 GRPO 家族的核心性质正是「同 prompt 内的相对比较提供低成本 baseline」，把它嵌套两层就自然得到：外层比不同的时间分解，内层在共享同一段视觉上下文的条件下比不同的延续。

§ 4 — 核心 Intuition ​

一条复杂的时序指令包含两个决策：什么时候该发生什么，以及在已经生成了一半的视频上怎么把它做出来。单 prompt 让模型两件事都猜；分步 prompt 只解决第一件却把第二件变难。让 LLM 去探索「视频模型真能执行的时间分解」，让视频模型在自己的历史上专门练「切换那一刻」，并且只在同一段共享上下文内部做相对比较——这样两级信用才互不污染。

§ 5 — 具体方法与完整 Pipeline ​

以生成 30 个 latent frame、L=6 的训练配置为例（J=⌈K/L⌉=5 步）：

  1. 规划器采样一组候选计划。 规划器 πϕ​（Qwen3-1.7B 初始化，LoRA rank 32 / alpha 64）对全局指令 c 采样 M=4 个候选计划 sm={s1​,…,sJ​}，覆盖不同的动作顺序、时间粒度与状态描述。每个 sj​ 既是分步分解也是 prompt 增强——把原指令切成带跨度的子目标，并为其分配的 latent 帧区间重写出明确的物体、动作与状态约束。
  2. prompt 平滑。 不用当前步的硬 prompt，而是 s~j​=Smooth(sj​,sj+1​)，让执行器同时看到当前与下一子目标。论文明确说这一步「经验上避免了硬切换造成的大幅性能下降」。
  3. 分层自回归采样。 对每个计划，执行器先生成共享上下文 x1:km​（k=min(jL,K)），每帧按其所属跨度的平滑 prompt 条件；然后从这同一段上下文出发采 N=8 条延续 {yk+1:Km,n​} 直到视频结束。于是每个 batch 产生 M×N=32 条视频。
  4. 两级奖励。 规划器侧：Qwen3-8B 作 LLM plan judge 打 plan-quality 分（考察对原指令的忠实度、事件覆盖、跨步时序连贯、避免幻觉），加上 Qwen3-VL-8B 对执行出的视频打 Temporal-Following 分（除时序顺序外还评物理一致性、视觉一致性、帧级与视频级的文视一致性），后者在该计划的 N 条延续上取平均。执行器侧：只在切换后的第一段跨度上算局部 step-following 分（Qwen3-VL-8B）与 PickScore 美学分。
  5. 两级优化。 组内相对优势 Aplanm​ 在 M 个计划上归一化，Aexecm,n​ 在共享同一计划与上下文的 N 条上归一化。规划器用 GSPO（序列级重要性比 ρϕm​=(πϕ​/πϕold​​)1/∣sm∣）更新，执行器用带 RatioNorm 的 Flow-GRPO 更新，且只更新切换后的第一个 chunk。两侧都加 KL 正则。
  6. 训练规模。 5,000 条由 GPT-5.2 生成的时序结构化指令；每条视频 117 帧（30 latent frame）；32 张 H20，batch size 16，每步约 800 秒，训 300–400 步。评测时改用 L=12、Simple Set 固定 3 步、Hard Set 固定 5 步。

§ 6 — 核心数学推导 ​

GRPO 的直觉。 对同一 prompt 采 G 条回答、用组内均值方差归一化得优势，从而免掉 critic：

Ai​=std({rj​})+ϵri​−mean({rj​})​

组内相对比较之所以是合法 baseline，是因为同组样本共享条件；这也正是 TempAct 嵌套结构的合法性来源——内层的 N 条延续共享同一段上下文与同一条新激活的 step prompt，外层的 M 个计划共享同一条全局指令。

为什么执行器只更新切换后的第一个 chunk。 论文给的理由是双重的。其一是策略梯度的合法性：组相对策略梯度要求样本在相同的条件状态下比较，而切换后第一个 chunk 内所有候选共享同一段前缀与同一条新 prompt；再往后的 chunk 是从各自不同的历史生成的，对应不同的策略输入，组内比较不再成立。其二是 credit assignment：切换那一刻正是新子目标的动作被决定的时刻，此处的执行误差会沿自回归链传播下去。执行器目标为

Lexec​(θ)=−E[N1​n∑​min(ρ^​θm,n​Aexecm,n​, clip(ρ^​θm,n​,1−ϵe​,1+ϵe​)Aexecm,n​)]

其中 ρ^​=RatioNorm(ρ) 来自 GRPO-Guard，用于纠正 flow matching RL 中重要性比在不同去噪时间步上的分布偏置（否则 clipping 约束会失效并导致过优化）。

规划器为什么用序列级比而非 token 级比。 ρϕm​ 对整条计划取几何平均，给整个 LLM plan 分配一个统一的更新权重，与「奖励只在执行完整个时间分解之后才拿到」这一事实匹配。用 token 级 PPO 比会把一个整体性的、延迟很久的奖励错误地摊派到单个 token。

§ 7 — 实验设计与结论 ​

基准。 作者自建 Temporal Order benchmark：Simple Set 100 条（1–2 个有序步骤）、Hard Set 100 条（3–4 个有序步骤及更复杂依赖）。判官用两个：Qwen3-VL-8B（与训练期奖励模型同族，in-domain）与 Gemini-3-Flash（训练中从未使用，out-of-domain）。

问题一：TempAct 有效吗？ 单 prompt 基线的平均 Temporal-Following Score：Self-Forcing 0.381、Casual Forcing 0.396、LongLive 0.424。分步 prompt 基线：Self-Forcing 0.400、LongLive 0.432。加 TempAct 后：Self-Forcing 0.400→0.462（+15.5%），LongLive 0.432→0.488（+13.0%）。

这里必须如实指出一个论文没有讨论的系统性差异：in-domain 判官上的相对增益普遍是 out-of-domain 判官的两倍左右。Self-Forcing 上，Qwen 判官的增益是 Simple +20.8% / Hard +24.9%，Gemini 判官只有 +10.9% / +9.7%；LongLive 上是 +23.6% / +12.1% vs +11.1% / +6.4%。论文的表述是「两个判官下增益一致，说明不是对训练期奖励模型的过拟合」，但倍数级的系统性差距恰恰是部分过拟合的特征——它只能说明增益不全来自过拟合，不能说明不存在过拟合。

问题二：画质代价如何？ Self-Forcing 上 VBench Total 从 80.07 到 79.99、Quality 82.89→82.71、Semantic 68.82→69.14、PickScore 均 20.6；LongLive 上 Total 79.55→79.97、Quality 82.10→82.61。论文称「几乎不变」。但需要把参照系放对：单 prompt 的 Self-Forcing VBench Total 是 81.20，切到分步 prompt 就掉到 80.07，TempAct 并没有把这 1.1 分补回来。也就是说整个分步 prompt 范式本身有固定的画质成本。

问题三：各组件各值多少？（表 2，Self-Forcing 骨干，Qwen 判官，Simple/Hard 平均）单 prompt 0.325；单 prompt + PE RL 0.326（几乎无提升，说明只改全局 prompt 无效）；分步 prompt 无平滑 0.248——显著低于单 prompt；加平滑 0.342；再加规划器 RL 0.362；再加执行器 RL 0.390；联合 0.418。这条链条信息量很大：从 0.248 到 0.342 的 0.094 全部来自 prompt smoothing 这个启发式，而完整的两级 RL 从 0.342 再拿到 0.076。换句话说，最大的单项增益来自一个不需要任何 RL 的技巧。

问题四：奖励怎么设计？ 执行器侧（表 5）：无执行器 RL 0.340；只用局部 Rstep​ 0.390（Simple 0.465 / Hard 0.314，PickScore 20.4）；Rstep​+Raes​ 同为 0.390（Simple 0.458 / Hard 0.321，PickScore 恢复到 20.6）；Rstep​+Rvideo​ 反降到 0.363；只用整段视频奖励 Rvideo​ 是 0.313，比完全不做执行器 RL 还差。规划器侧（表 4）：baseline Simple 0.414 / Hard 0.269；只用 Rvideo​ 为 0.428 / 0.313；加上 Rjudge​ 反而降到 0.420 / 0.304，只有 TA（文本对齐）从 −0.06 升到 −0.04。论文最终部署的正是这个在主指标上更差的配置，理由是 judge 起到了规范 plan 质量的作用。KL 消融（表 3）：βe​=0 时 0.375 / PickScore 20.2，5×10−4 时 0.390 / 20.6 最佳。

问题五：人类是否同意？ 每个骨干 100 条样本的 pairwise 偏好研究，TempAct 明显更受偏好（只有图 5，正文未给 win/tie/loss 具体数值）。判官与人的一致率：Gemini-3-Flash 81%、Qwen3-VL-8B 76%（VLM 分差在 ±0.03 内计为平局）。没有报告标注者人数与标注者间一致性。

§ 8 — Take-aways ​

5 句话版： (1) chunk-wise AR 生成让「指令的哪一部分该在当前块兑现」变得歧义，产生 temporal confusion。(2) 换成分步 prompt 会把难度搬到切换时刻，且单独使用时比全局 prompt 更差（0.248 vs 0.325），必须配合 prompt smoothing。(3) TempAct 用 LLM 规划器 + AR 执行器的分层 RL，执行组嵌套在规划组内，使 plan 级与切换时刻级的信用分离。(4) 执行器只在切换后第一个 chunk 上更新、只用局部 step-following 奖励；用整段视频奖励训执行器比不训还差。(5) 平均 Temporal-Following Score 在 Self-Forcing 上 0.400→0.462、LongLive 上 0.432→0.488，画质基本持平，但绝对值仍很低（Hard Set 最高 0.336）。

3 句话版： 时序指令跟随需要同时解决「怎么分解」与「怎么在自己的历史上兑现分解」，两者互补且必须分开做 credit assignment。分层组探索让规划级与切换级的比较各自在共享条件下进行，是这套方法能work的结构性原因。但最大的单项增益来自 prompt smoothing 这个非 RL 技巧，且 in-domain 判官上的增益约为 out-of-domain 的两倍。

1 句话版： 把「视频模型能执行什么样的时间分解」交给一个被执行结果奖励的 LLM 规划器，同时让视频模型只专门练 prompt 切换那一刻。

§ 9 — 最脆弱的假设 ​

最脆弱的是：Temporal-Following Score（一个 VLM 打的 0–1 分）能够作为事件顺序正确性的可靠代理，而且训练期奖励与评测期指标同源不会造成实质污染。

这个假设一旦不成立，核心贡献直接失效——因为整篇论文的主指标、规划器奖励、执行器奖励都是同一个协议（论文明说两个判官「遵循与 Rvideom​ 相同的评分协议」），训练期用的是 Qwen3-VL-8B，评测期 in-domain 判官仍是 Qwen3-VL-8B。

它在实践中可能不成立的理由有三条。其一，前面已经指出的倍数级 in/out-of-domain 增益差，是奖励模型特异性的直接证据。其二，绝对分数极低：Hard Set 上最好也只有 0.336，Simple Set 0.508，在 [0,1] 刻度上意味着大部分样本仍不满足时序要求；在这样一个远未饱和的区间里，0.03–0.06 的提升有多少是真实语义改善、有多少是判官偏好被拟合，很难区分。其三，训练集的 5,000 条指令与 200 条评测 prompt 都由同一套 GPT 生成流程产出，论文没有声明二者不相交，也没有说明构造时是否做过去重。

论文为此提供的证据是：out-of-domain 判官上仍有增益，以及 81% / 76% 的人机一致率。这是有分量的证据，但人机一致率的计算把 VLM 分差 ±0.03 内计为平局——而这个阈值与论文报告的多数增益幅度同量级，等于把最需要判别的边界样本排除在检验之外。缺的是：一致率在增益区间内的分层报告，以及标注者间一致性。

§ 10 — 最小复现实验 ​

一周内可做、不需要复现 32 卡 RL：

  • 目标：分离「prompt smoothing」与「两级 RL」的贡献，并检验奖励-指标同源的污染程度。
  • 实现：取公开的 Self-Forcing checkpoint，完全不训练，只做推理侧对照：(A) 单 prompt；(B) GPT 硬切分步 prompt；(C) 分步 prompt + smoothing；(D) 分步 prompt + smoothing + 用 Qwen3-VL-8B 做 best-of-8 重排（把奖励当推理时选择器，不更新参数）。
  • 评测：在自建的 200 条时序 prompt 上，用三个判官各打一遍——Qwen3-VL-8B、Gemini-3-Flash、以及一个第三方判官（如 InternVL 系列），同时收 50 条的人工 pairwise 偏好。
  • 判据：若 (C) 相对 (A) 的增益已接近论文报告的 TempAct 总增益，则大部分收益不需要 RL，论文的方法论价值被削弱；若 (D) 在 Qwen 判官上大涨而在另外两个判官上几乎不涨，则奖励-指标同源污染被坐实；若 (C)/(D) 的增益在三个判官与人工偏好上幅度一致，则支持论文的指标可靠性主张。

§ 11 — 最强反例设计 ​

站在反对者立场，最有力的攻击是提出一个替代解释：TempAct 的增益主要来自「每个 chunk 拿到了信息量更大、更具体的文本条件」，与规划器学到了「可执行性」无关。

支持这个替代解释的证据在论文自己的表里。第一，规划器的每个 sj​ 都做了 prompt enhancement——「用明确的物体、动作与状态约束重写子目标」。第二，表 4 显示，加了专门评估 plan 质量的 Rjudge​ 之后，Temporal-Following 反而下降（0.428/0.313 → 0.420/0.304）；如果规划器 RL 的价值在于学出更好的时间分解，那么一个直接评估分解质量的奖励不该让主指标变差。第三，表 2 里「单 prompt + PE RL」几乎无提升（0.325→0.326），而「分步 prompt + smoothing」无任何 RL 就到 0.342——分步这个结构本身、而不是它被优化过，才是主要变量。

设计这个反例的具体实验：加一个论文缺失的关键对照——冻结规划器的 prompt enhancement 能力，但随机化时间分配。具体做法是让同一个未经 RL 的 LLM 生成 J 条同样详细的子 prompt，然后把它们随机打乱后分配给各时间跨度（或按均匀但错位的跨度分配）。如果这个「同样具体、但时间顺序被破坏」的对照与 TempAct 的差距很小，那么增益来自 prompt 具体度而非时间分解；如果差距很大且接近 TempAct 相对 (C) 的全部增益，则论文的 framing 成立。

论文对此没有防御：全文没有任何打乱分步 prompt 顺序的对照实验，也没有报告规划器 RL 前后生成的计划在时间分配上究竟改变了什么（比如步长分布、动词顺序的编辑距离）。

§ 12 — Follow-up Research Idea ​

(a) 驱动的局限。 论文自陈的第一条限制是：规划器把 step prompt 分配到固定的时间跨度，对时长不同、执行难度不同的动作而言未必最优。这不是一个可以靠调 L 解决的超参问题——训练用 L=6、评测用 L=12 这一 train/test 不匹配本身就说明跨度是被外生指定的。第二条限制是规划器是开环的：它在生成开始前一次性给出全部分步，之后再也看不到视频实际长成什么样。

(b) 可借鉴的相邻工具。 语音与手语合成领域对「把符号序列对齐到连续时间轴」有成熟的处理：单调对齐搜索（monotonic alignment search）与 duration predictor（FastSpeech/Glow-TTS 一系）把「每个符号占多少帧」当作一个可学习的、在推理时由模型自己决定的隐变量，并用单调性约束保证顺序不被破坏。这与「事件必须按序发生但每个事件时长未知」的结构完全同构。

(c) 第一个实验。 把规划器的输出从「J 条固定跨度的 prompt」改成「J 条 prompt + 一个 duration 分布」，并让执行器在生成过程中用一个轻量的 VLM 状态检测器判断当前子目标是否已完成，据此触发向下一步的转移——即把固定跨度替换成由视觉状态触发的单调转移。第一个要验证的假设很具体：在 Hard Set 上，事件时长的方差越大，固定跨度相对状态触发的劣势应当越明显。实验设计为：按人工标注把 Hard Set 的 100 条 prompt 按「步骤时长不均衡程度」分成三档，比较固定跨度 TempAct 与状态触发版本在三档上的 Temporal-Following 差值。如果差值随不均衡程度单调扩大，就同时验证了 (i) 固定跨度确实是当前瓶颈，(ii) duration 建模是正确的解法方向。这个 framing 的价值在于：它把「时序合理性」从一个被 VLM 事后打分的模糊属性，转成一个有明确隐变量（每步时长）与明确结构约束（单调性）的建模问题，从而使问题可以在不依赖 VLM 判官的情况下被度量与优化。
