Head Forcing: Long Autoregressive Video Generation via Head Heterogeneity ​

项内容
arXiv2605.14487
提交日期2026-05-14
作者Jiahao Tian, Yiwei Wang, Gang Yu, Chi Zhang
分类cs.CV, cs.AI
一句话按注意力在「首帧 / 中段历史 / 当前块」三个时间桶上的占比，把 AR 视频 DiT 的 360 个 head 离线分成 local / anchor / memory 三类：前两类只留 4–7 帧 KV，把省下的预算给 memory 头配「快记忆 + 场景新颖度准入的情景记忆」，并逐头重编 RoPE 把相对位置压回预训练区间。

所属教程：自回归视频生成

§ 1 — 研究问题与重要性 ​

自回归视频扩散靠 KV cache 顺序生成，天然可扩展到长时程并支持实时流式合成。但两个问题随长度增长而恶化：误差累积带来色偏与细节丢失，有界 KV cache 丢弃早期上下文带来身份漂移与场景遗忘。

现有解法分两支。训练类（Rolling Forcing、LongLive、Self-Forcing++）靠把生成锚在初始帧上并周期性重跑 DMD，能做到分钟级一致性，但会因首帧偏置产生静态伪影；记忆机制类（MemFlow、Context as Memory、WorldPlay）需要复杂的架构改动。两者都有可观训练成本。训练无关类（Infinity-RoPE、Deep Forcing、StableWorld、Rolling Sink）通常用 attention sink 配合 RoPE 调整，但同样只依赖开头几帧的 sink 而丢弃中间上下文——这使得序列中途才出现的主体与场景无法被追踪，单 prompt 下输出趋于同质或静止，多 prompt 下转场不一致。

论文点出这两支共同忽略的一件事：所有 attention head 被一视同仁，而它们的功能角色不同，这个影响从未被系统检验过。

§ 2 — 前人工作与不足 ​

论文对基线的批评落在「均匀分配造成的根本性错配」：几乎不使用历史上下文的 head 拿到了过量预算，既浪费计算又引入噪声；真正需要长程证据的 head 反而拿不够。这个错配在长 rollout 中被放大，漂移累积与一致性退化随之加剧。

训练类方法（LongLive、Rolling Forcing）用 attention sink 加滑窗，Self-Forcing++ 用长流式微调扩展 DMD，代价是复杂改动与重训。训练无关类中，Deep Forcing 与 Rolling Sink 做基于 sink 的缓存稳定，Infinity-RoPE 与 LoL 在推理时改 RoPE，StableWorld 用动态帧驱逐减少累积误差。论文的判断是：它们都缺长期记忆机制，长时程一致性必然退化。

需要特别指出的是同期工作的重合。本文与 Pyramid Forcing（2605.13111，2026-05-13 提交，比本文早一天）在同一个骨干（Self Forcing）上做了几乎同一件事——把 attention head 分成三类并分配异构 KV cache 策略。两者的分类学不同且互不引用：Pyramid Forcing 的 Anchor / Wave / Veil 与本文的 memory / local / anchor 之间，Pyramid 的「Anchor（广泛长程）」对应本文的「memory」，Pyramid 的「Veil（首帧 + 邻近、对中段打负分）」对应本文的「anchor」，而 Pyramid 的「Wave（周期性）」在本文的分类里不存在。更关键的是方法论上的直接分歧：Pyramid Forcing 明确论证必须用 pre-softmax logits，因为 softmax 会把「主动抑制」的负极性压成正概率；本文用的恰恰是 post-softmax 的注意力占比。两篇论文得出了相容的定性结论，但对「该看哪个量」的答案相反。

§ 3 — 重建作者的思考路径 ​

第一步是把 profiling 做成可量化的东西而不是看图。做法是把注意力上下文切成三个时间桶——sink 桶（首帧）、middle 桶（中间历史帧）、current 桶（当前块），对每个 head 算各桶的注意力占比，并在多 prompt、多 AR 步、多去噪步上平均。散点图上三簇立刻分开。

第二步是验证功能而不只是描述模式，这一步是本文比单纯做可视化更扎实的地方。对被判为 local 的 head，把它们的历史 KV 全部删掉，其余不动，VBench 分数几乎不变（84.82/96.78/83.92 → 84.78/96.80/83.88，其中一项还略升）；而删掉等量非 local head 的 KV 会带来明显退化（81.58/95.82/80.74）。对被判为 anchor 的 head，只从它们的 cache 里移除 sink 帧会迅速质量崩坏，同样操作施加在其他 head 上则看不出退化。而且这种锚定行为绑定的是 sink 帧本身而非首个 cache 位置——把同一位置换成别的帧不会引出高注意力。论文把它归因于首帧的统计特殊性：它只编码初始图像、没有经过时间压缩，因此是一个稳定的长程参照。

第三步是资源重分配的直接推论：local 与 anchor 头既然不需要中段历史，就把预算省下来给 memory 头。

第四步是问 memory 头该拿什么。简单加大滑窗仍然会丢中间上下文。于是设计分层记忆：快记忆管紧邻的时序邻域，情景记忆存早期不同场景的代表帧。情景记忆该收什么？两条原则——存进去的 KV 要尽可能干净（误差累积少），要覆盖尚未被记忆表示的新场景。StableWorld 的已有结论是新场景对应的 KV 比同场景内反复条件于长历史的帧误差更小，于是场景新颖度同时满足这两条，成为准入判据。

§ 4 — 核心 Intuition ​

三类 head 要的历史长度差一个数量级：local 头只看当前块和紧邻一帧，anchor 头只认第一帧那个特殊参照，只有 memory 头真的在聚合全程上下文。给所有头发同一份 21 帧滑窗，等于对前两类灌噪声、对第三类断上下文。把前两类砍到 4 帧和 7 帧，省下的预算才够 memory 头维护一份「能记住中途出现的角色」的情景记忆。

§ 5 — 具体方法与完整 Pipeline ​

骨干是 Self Forcing（从 Wan2.1-T2V-1.3B 蒸馏的四步因果生成器，原生 5 秒、16 FPS、832×480）。DiT 有 L=30 层、每层 H=12 头、头维 d=128，共 360 个 head；每个 AR 步生成 f=3 个 latent 帧，空间分辨率 52×30（每帧 s=1560 token）；基线是固定窗口 W=21 帧加 sink 帧的 FIFO 缓存。

(1) 离线 profiling。20 条 prompt，各跑 30 秒 rollout（约 42 个 AR 步），从第 3 块开始随机采 3 个 AR 步，每步记录全部 4 个去噪时刻的逐头注意力图，算三桶占比。分类：首帧注意力占比进入 top αanchor​=25% 的判为 anchor 头（90 个）；在余下的 head 里按 current 桶占比取 top τlocal​=20% 判为 local 头（72 个，这些头的 pcurrent​ 通常大于 0.85）；其余 198 个为 memory 头。整个 profiling 约 1.2 GPU-hour（单张 A100-80GB），结果存成静态配置文件复用；论文称用 3–4 条 prompt 也够，约 10 分钟。

(2) 头级 KV cache 分配。local 头只留最近一帧加当前块（4 帧）。anchor 头留前三帧作为锚帧加上同样的局部 token（7 帧）——留三帧而不是一帧，是为了对分类边界上的误判更鲁棒。memory 头拿 Bepi​+Bfast​+f=5+3+3=11 帧：情景记忆 5 帧、快记忆 3 帧（FIFO 更新）、当前块 3 帧。

(3) 情景记忆的动态更新。某个块滑出快记忆窗口时，取它的第一帧作为候选（短块内相邻帧高度冗余）。用 key embedding 相似度衡量场景新颖度：对候选帧与每个情景条目的 key cache 沿 token 维均值池化得到紧凑表示，在所有层与 memory 头上求平均余弦相似度，取对所有条目的最大值作为新颖度分 δ(Kc​)；δ(Kc​)<τnovel​=0.95 才准入。准入决策在所有层上强制一致（同一帧要么各层都收、要么都不收），以保证语义连续性。论文每三个生成间隔更新一次情景记忆。

(4) prompt 引导的压缩。情景记忆满 Bepi​ 时不直接丢弃，而是把冗余条目压进一个专用的 summary 帧 S（放在情景记忆开头）。首次溢出时挑出成对余弦相似度最高的一对（这些相似度在新颖度计算里已经算过，零额外开销）压缩初始化 S；此后每次挑与邻近条目平均相似度最高的非 summary 条目并入 S。压缩在空间 token 粒度上做：把两者的 KV 沿 token 维拼成 2s 个 token，按每个 token 的 key 与当前文本 key 的平均余弦相似度打分，取 top-s 组成新的 S。这让 summary 帧随 prompt 演化偏向当前相关内容。

memory 头最终组装的 key 序列是 [KMepi​​,KMfast​​,K(3i−3)s:3is​]。

(5) 头级 RoPE 重编码。KV 写入 cache 时只施加空间维 RoPE，省略帧级时间编码——这对压缩后的 summary token 尤其重要，因为它们的 token 来自不同帧，空间语义应保留而时间位置应可自由重指派。每次缓存更新后，按头对组装好的 key 序列重编帧级索引：设头 h 的总缓存帧数为 Fi(h)​，则 Ki(h)​ 取 {0,…,Fi(h)​−1}，Qi(h)​ 取 {Fi(h)​−f,…,Fi(h)​−1}，空间分量不动。由于 Fi(h)​ 被各头的缓存容量上界（4 / 7 / 11），无论生成多长，所有时间相对位置都落在预训练区间内。

(6) 工程实现。把每个头当成一条独立序列，用一次 flash_attn_varlen_func 处理所有头；再用 Triton 融合核处理缓存滚动、情景记忆更新，以及「序列组装 + RoPE 重编码 + flat buffer 打包」三步。消融显示朴素的逐头 Python 循环只有 6.62 FPS，逐级优化后恢复到 15.81 FPS，与 Self Forcing 的 15.83 FPS 基本持平。

§ 6 — 核心数学推导 ​

论文的形式化很轻，核心是两条。

桶级注意力占比（式 3）。对当前块的注意力图 A=softmax(Qi​[Kpre​,Ki​]⊤/d​)∈R3s×3is，把 key 索引划成 sink 桶 [0,s)、middle 桶 [s,(3i−3)s)、current 桶 [(3i−3)s,3is)，则

pb​=3s1​m=1∑3s​n∈Ib​∑​Amn​

由于 softmax 在 key 维归一，psink​+pmiddle​+pcurrent​=1，三个占比构成单纯形上的一个点，这正是散点图能清晰分出三簇的原因。

场景新颖度（式 4）：

δ(Kc​)=j∈{1,…,Nepi​}max​∣Hmem​∣×L1​l=1∑L​h∈Hmem​∑​cossim(Kc(l,h)​,Kepi,j(l,h)​)

取 maxj​ 而非均值是对的：判断「是不是新场景」应该看它与最相似的那一条是否足够不同，而不是与整体的平均距离——后者会让一个与某条几乎重复的候选因为与其他条目差异大而被误判为新。

头级 RoPE 重编码（式 5）为 Qi(h)​:{Fi(h)​−f,…,Fi(h)​−1}、Ki(h)​:{0,…,Fi(h)​−1}。这个赋值把每个 query 对齐到其 key 序列的最后 f 帧，最大相对距离恰为 Fi(h)​−1。与 Infinity-RoPE 的全局统一重索引相比，本文的关键差别在于每类头的缓存构成不同（local 头 f+1 帧、anchor 头 2f+1 帧、memory 头 Bepi​+Bfast​+f 帧），统一重索引只能保证其中一种配置落在预训练区间内。

缓存预算核算（附录 I）。以 frame-slot ∑h​Ch​ 计（Ntotal​=360）：Self Forcing 360×21=7,560（244.2%），Deep Forcing 5,760（186.0%），LongLive 4,320（139.5%），Infinity-RoPE 2,880（93.0%），Head Forcing 72×4+90×7+198×11=3,096（100%）。这条核算相当有说服力——增益不可能来自「用了更多显存」。

§ 7 — 实验设计与结论 ​

单 prompt 长视频用 MovieGenBench 抽 100 条 prompt 生成 30 秒与 60 秒；多 prompt 交互按 LongLive 的做法设计 50 条六段式序列，每 10 秒切换一次，评 60 秒。

单 prompt（表 2）。60 秒上 Head Forcing 为 15.81 FPS / 动态度 41.37 / 运动平滑 98.67 / 时序闪烁 98.72 / 成像质量 69.27 / 美学 61.36 / 主体一致性 97.81 / 背景一致性 96.90。训练无关的两个对手全面落后：Deep Forcing 35.75/98.38/98.63/68.93/60.39/97.70/96.82，Infinity-RoPE 37.19/98.49/98.61/68.68/59.65/97.73/96.88。

但对训练类基线只能说互有胜负，需要如实指出。60 秒上 Rolling Forcing 的成像质量 70.09 与主体一致性 97.87 都高于 Head Forcing，LongLive 的运动平滑 98.75 与背景一致性 96.92 也更高，且 LongLive 的吞吐 19.03 FPS 明显更快。30 秒上同样：Head Forcing 的运动平滑 98.76 低于 LongLive 98.83 与 Rolling Forcing 98.80，时序闪烁 98.78 低于 LongLive 98.80，主体一致性 98.07 低于 Rolling Forcing 98.12，背景一致性 97.08 低于 LongLive 97.15。Head Forcing 稳定领先的是动态度（30 秒 42.14、60 秒 41.37，两个长度上都最高）与美学。

多 prompt（表 3）。Head Forcing 84.74 / 96.69 / 60.67，六段 CLIP 为 26.54 / 25.36 / 24.64 / 24.27 / 24.62 / 24.22。LongLive 84.83 / 96.05 / 60.29，CLIP 为 26.63 / 25.77 / 24.75 / 24.19 / 24.52 / 24.11。论文的说法是「在多次 prompt 切换之后取得更好的分段 CLIP」，与表相符——前三段 Head Forcing 都低于 LongLive，后三段反超（+0.08 / +0.10 / +0.11）。不过按表内数字算，LongLive 的六段 CLIP 均值是 25.00，略高于 Head Forcing 的 24.94（后者与消融表里的 24.95 一致）；同时 Quality Score 84.74 也低于 LongLive 的 84.83。也就是说本文在多 prompt 上真正稳定领先的是 Consistency Score（96.69 vs 96.05）与后段的 prompt 对齐，而不是均值。

组件消融（表 4，60 秒）。(A) 基线 31.92/98.42/97.62/67.33/83.52/95.74/CLIP 23.20 → (B) 只加头级分配 37.22/98.49/97.65/68.14/84.10/96.33/24.31 → (C) 再加分层记忆 39.09/98.54/97.73/68.93/84.34/96.51/24.61 → (D) 再加 RoPE 重编码 41.37/98.69/97.81/69.27/84.74/96.69/24.95。三块都有贡献，动态度上分别是 +5.30 / +1.87 / +2.28。

头级策略的关键对照（表 5，同等总预算）。这是本文比同期的 Pyramid Forcing 扎实的地方——它做了「随机分配」这条对照：把同样比例的 head 随机分成三类，结果是 32.21/98.29/97.38/67.92/83.55/95.88/23.55，几乎回到基线（31.92/…/23.20），远低于正确分类的 41.37/…/24.95。这直接排除了「增益只来自三档不同缓存长度的混合」这一替代解释。另外两条对照显示两类头的价值不对称：把 anchor 并进 memory（表中 Local Memory）掉到 34.28/24.12，把 local 并进 memory（Anchor Memory）只掉到 39.73/24.65——anchor 头的分离贡献远大于 local 头的分离。

情景记忆消融（表 6）。准入判据：均匀时间采样 37.42/…/24.59 对新颖度准入 41.37/…/24.95，差距明显。压缩策略：FIFO 驱逐 39.42/…/24.71、随机选 token 40.42/…/24.68、prompt 引导 41.37/…/24.95，差距小得多。附录 S3 还比较了新颖度度量：用 CLIP 相似度替代 key 余弦得到 41.42/98.62/97.80/69.33/84.68/96.73/24.98，在七项里有四项略优于本文的 key 余弦，论文的表述「on par」是准确的，key embedding 的优势在于零额外计算而非精度。

用户研究。单 prompt 60 秒（20 人 × 15 条 prompt，5 分 Likert）：Head Forcing 视觉质量 4.04 / 时序一致性 3.98 / 运动动态 3.67 / 均值 3.89；Rolling Forcing 4.12/3.71/2.34/3.39；LongLive 3.83/3.35/3.21/3.46。论文写「在三个准则上都取得最高均分」，但表中 Rolling Forcing 的视觉质量 4.12 高于 Head Forcing 的 4.04，这一句与表不符。多 prompt 研究里 Head Forcing 四项全胜（3.93/3.39/3.45/3.47 vs LongLive 3.78/3.08/3.09/3.28），不过论文称「优势在 prompt 对齐上最显著」，按正文给出的准则顺序算，最大差距其实在运动动态（+0.36）而非 prompt 遵循（+0.19）。

另有几处小的内部不一致：正文 §3.2 的叙述顺序是先选 local 头再选 anchor 头，附录 0.A.1 明确写的是先选 anchor 头、再在余下 head 里选 local 头；附录 0.A.1 说 profiling 用 30 秒 rollout，0.A.4 说「生成 20×10 秒视频」；表 5 的策略枚举里编号从 (1) 跳到 (3) 且 (4) 出现两次，漏了 Uniform Memory 的编号。表 S1（分类稳定性）的数值单元格在 HTML 中为空，只能引用正文文字——跨 AR 步的 core stability ratio 在三类上均高于 0.9，跨去噪步与跨 prompt 论文称「consistently high」但未给可复述的数字。

§ 8 — Take-aways ​

5 句话版：Head Forcing 把 AR 视频 DiT 的 360 个 attention head 按三个时间桶的注意力占比离线分成 local（72 个，缓存 4 帧）、anchor（90 个，7 帧）、memory（198 个，11 帧）。分类不只是描述性的——删掉 local 头的全部历史 KV 几乎不掉分，而删等量非 local 头会明显退化；只从 anchor 头移除 sink 帧会迅速崩坏，同样操作在其他头上无影响。省下的预算给 memory 头配分层记忆：FIFO 快记忆加上按场景新颖度准入、按 prompt 相关度压缩的情景记忆；再逐头重编 RoPE，使相对位置无论生成多长都落在预训练区间。全程免训练，总缓存只有 Self Forcing 的 41%，吞吐 15.81 FPS 基本持平，60 秒 VBench 动态度从 31.92 提到 41.37。最有说服力的证据是「随机分配同样比例的头」这条对照几乎回到基线（32.21 / CLIP 23.55），直接排除了「增益来自异构缓存长度本身」的替代解释。

3 句话版：注意力头对历史的需求相差一个数量级，把不需要历史的头砍到 4 帧，省下的预算才够给真正需要长程上下文的头维护一份情景记忆。情景记忆按场景新颖度准入、按当前 prompt 相关度压缩，这让中途出现的角色也能被记住，而不只是锚在第一帧。相对训练无关基线全面领先，相对训练类基线在动态度与美学上领先、在成像质量与部分一致性指标上仍有落后。

1 句话版：把 KV 预算从「所有头平分」改成「按头的功能角色分配」，再给长程头配一份会遗忘冗余、保留新场景的情景记忆，五秒模型就能稳定跑到分钟级。

§ 9 — 最脆弱的假设 ​

最脆弱的假设是：三桶占比这个后 softmax 的统计量，足以刻画一个 head 的功能角色。

这个假设的脆弱性有一个非常具体的外部证据——同期的 Pyramid Forcing 在同一个骨干上做同一件事，却明确论证必须用 pre-softmax logits，理由是 softmax 把值域压到 (0,1)，会将「query 与 key 夹角大于 90°、模型主动抑制该段历史」的负极性强行转成正的概率权重。若这个论证成立，本文的 pmiddle​ 就无法区分两种截然不同的 head：一种对中段历史真正无所谓（logit 接近 0），一种在主动抑制中段历史（logit 显著为负）。两者在 softmax 之后都表现为「中段占比小」，会被归入同一类。

后果并不抽象。本文的 anchor 头定义是「首帧注意力高」，而 Pyramid Forcing 的 Veil 头定义是「首帧与邻近帧高、对中段普遍打负分」——两者很可能指向同一批 head，但本文只用了首帧这一维，因此对 anchor 与 memory 的边界更模糊。论文自己在附录 0.A.3 里承认「少量 head 在 memory 与 anchor 的决策边界附近有波动」，并且在方法里为 anchor 头保留三帧而非一帧，理由正是「对分类边界上的潜在误判更鲁棒」。这两处都是该假设不够干净的直接痕迹。

论文为该假设提供的证据是相当强的：因果性的删除实验（删 local 头历史无影响 vs 删等量非 local 头明显退化；删 anchor 头 sink 帧崩坏 vs 删其他头 sink 无影响）、跨 AR 步/去噪步/prompt 的稳定性统计、以及在 LongLive 上复现出同样的三簇结构。缺的是与 pre-softmax 判据的直接对照——两套判据划分出的 head 集合重合度是多少，各自的下游分数差多少。这条对照现在有了现成的对手实现，做起来很便宜。

§ 10 — 最小复现实验 ​

不需要复现完整系统，一周内可做：

  • 模型与数据：Self Forcing 公开权重，MovieGenBench 抽 30 条 prompt，生成 60 秒。
  • 实现：只实现 profiling 与三档缓存分配（4 / 7 / 11 帧），跳过情景记忆（memory 头先用等长滑窗）——这对应论文表 4 的 (B) 行，是最便宜且贡献最大的一块。同时实现两套分类判据：本文的三桶后 softmax 占比，与 Pyramid Forcing 的 pre-softmax 符号率。
  • 测量：(a) 两套判据给出的 head 划分的重合率（按类别算 Jaccard）；(b) 两套划分在同一缓存配置下的 VBench 动态度与一致性；(c) 复现论文表 5 的 Random Allocation 对照作为噪声下界。
  • 判据：如果 (a) 的重合率很高（例如 anchor↔Veil 的 Jaccard > 0.8）且 (b) 的差距落在 (c) 给出的噪声范围内，说明 softmax 与否并不重要，两篇同期工作发现的是同一个稳健现象；如果重合率低而 (b) 差距显著，则「该看哪个量」这个问题是实质性的，本文的 §9 假设需要修正。

§ 11 — 最强反例设计 ​

最有力的攻击不是质疑分类本身（论文的删除实验相当扎实），而是质疑头级分配与情景记忆各自的功劳分配，以及动态度这个头号指标的含义。

第一条针对指标。Head Forcing 在两个长度上稳定领先的是 Dynamic Degree（60 秒 41.37 vs LongLive 40.29 vs Self Forcing 31.92），而它在运动平滑度、成像质量、主体/背景一致性上都不同程度地落后于训练类基线。VBench 的 Dynamic Degree 本质上是「运动幅度是否超过阈值」的比例，它与画面稳定性天然对立。论文的叙事是「基线因为均匀 attention sink 导致运动停滞，我们保住了运动丰富度」——这与数据相符，但同一组数据也支持一个更朴素的解释：Head Forcing 缩短了绝大多数头的历史窗口（总预算只有 Self Forcing 的 41%），历史约束一弱，画面自然更容易动起来，动态度上升而平滑度/一致性略降正是这一权衡的表现。要区分两种解释，需要一条论文没做的对照：把 Self Forcing 的均匀窗口从 21 帧统一压到约 8.6 帧（使总预算等于 3,096 frame-slot），看动态度是否也大幅上升。附录 I 的预算核算证明了「不是靠更多显存」，但没有排除「靠更少历史」。

第二条针对情景记忆的边际价值。表 4 显示分层记忆只贡献动态度 +1.87（37.22→39.09）与 CLIP +0.30（24.31→24.61），而表 5 显示「Anchor + Memory」（把 local 头并进 memory，即只有两类头）已经拿到 39.73 / 24.65——比带完整分层记忆的 (C) 行还高。这两处放在一起说明，情景记忆这套相当复杂的机制（新颖度准入、跨层一致准入、prompt 引导的 token 级压缩）所换来的增益，与「少分一类头」这种粗糙改动是同一量级。附录 S3 进一步显示把新颖度度量换成 CLIP 相似度，七项里四项略优。综合起来，最强的反例主张是：头级分配是真实且可复现的发现，分层记忆则是一个收益递减的复杂附加物。

可预测的失效场景，论文自己在附录 J 里点了名：超长序列（> 5 分钟）经过多轮压缩后，summary 帧会逐渐丢失早期场景的细粒度信息。可以把它做成系统实验：构造要求「第 1 分钟出现的角色在第 6 分钟原样再现」的 prompt 序列，用 DINOv2 度量身份一致性随再现间隔的衰减曲线，并与「不压缩、无限增长的情景记忆」这一 oracle 对照。若衰减在压缩轮次上呈现明显台阶，就定位到了 prompt 引导压缩的具体代价。

§ 12 — Follow-up Research Idea ​

驱动的局限：论文在附录 J 里承认，profiling 必须为每个新基座模型重跑一遍，「一个通用的、与架构无关的头分类规则，或者免 profiling 的方法」仍然是开放问题。更深一层的问题是，分类是静态的——一个 head 被判为 local 之后，无论生成的是静止风景还是快速切换的动作场面，它永远只拿 4 帧。而本文与 Pyramid Forcing 用不同判据得到相容结论这一事实本身暗示，头的角色可能不是由 prompt 或内容决定的，而是由架构与位置编码结构决定的。

新的 framing：如果角色真由结构决定，那就应该能从权重直接读出来，而不必生成任何视频。具体地，把问题重述为：给定一个 AR 视频 DiT 的 WQ​,WK​ 与 RoPE 配置，能否在不做前向的情况下预测每个 head 的时间依赖模式？一个可操作的切入点是分析 WQ⊤​WK​ 在 RoPE 旋转下的谱结构——注意力打分对相对帧距 t−s 的依赖完全由这个矩阵与旋转频率的耦合决定。这与「跑 20 条 prompt 再统计」是两种不同的东西：前者是模型的静态属性，后者是行为的采样估计。它同时给出免 profiling 的分类规则，并解释为什么两套采样判据会得出相容结论。

可借鉴的相邻工具：LLM 可解释性里已有成熟的「从 WQ​WK​ 的 QK-circuit 直接读出 head 功能」的分析框架（induction head 的识别最初就是这样做的）；位置编码分析里对 RoPE 频谱与有效上下文长度关系的研究，提供了把旋转频率与依赖距离联系起来的现成工具——Pyramid Forcing 把 Wave 头的周期 ≈6 追溯到 RoPE 最低频分量 θ0​=1 给出的 2π，正是这类分析的一个实例。

第一个实验：不需要生成任何视频。取 Self Forcing 与 LongLive 的权重，对每个 head 计算 WQ⊤​WK​ 在 RoPE 各频率子空间上的能量分布，得到一个纯静态的特征向量；用本文已公布的 profiling 分类作为标签，训一个极简分类器（逻辑回归即可）。如果留出层上的分类准确率显著高于随机，就证明头的角色可以从权重直接预测，profiling 这一步可以整个省掉；如果准确率接近随机，则角色是训练动力学与数据共同塑造的，静态规则不存在——这两种结果都直接回答了论文自己提出的开放问题。
