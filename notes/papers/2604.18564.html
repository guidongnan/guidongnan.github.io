MultiWorld: Scalable Multi-Agent Multi-View Video World Models ​

项内容
arXiv2604.18564
提交日期2026-04-20
作者Haoyu Wu, Jiwen Yu, Yingtian Zou, Xihui Liu
分类cs.CV
一句话用 RoPE 沿 agent 维打破动作对称性来区分"谁在动"，再用冻结 VGGT 把多视角观测压成一个 3D-aware 全局状态供各视角并行去噪，从而让智能体数与相机数都可变。

所属教程：世界模型

§ 1 — 研究问题与重要性 ​

现有 video world model 几乎都隐含一个假设：环境里只有一个 agent。协作机器人和多人游戏显然不满足这一点。多个 agent 同时动作，彼此的行为互相依赖；每个 agent 又从自己的视角观察同一个共享环境，于是模拟本身就要求跨视角的观测保持一致。论文把这个扩展拆成三个现有单智能体模型无法覆盖的挑战：多智能体可控性（要把每个动作绑定到对应的 agent 上并同步执行）、多视角一致性（不同视角的部分观测必须在几何上自洽）、框架可扩展性（真实环境的 agent 数和相机数是变的，不能假定固定配置）。

第三点是被前人系统性忽略的。COMBO 与并发的 Solaris 都假定固定 agent 数或预定义相机视角，这直接堵死了"两个机器人的任务训练出来的模型能不能用到四个机器人上"这类问题。而对机器人而言，一个能模拟失败轨迹的多智能体环境有直接价值——真机上采集碰撞和干涉数据既贵又危险。

§ 2 — 前人工作与不足 ​

交互式视频世界模型这条线已经很成熟：camera control（CameraCtrl、ViewCrafter）、action control（OASIS、MineWorld、The Matrix、WHAM）、物理一致性、长时程记忆（Context-as-Memory、WorldMem）、实时化（Self-Forcing、Causal Forcing）都有工作。但它们服务的都是单个玩家或单个机器人。

多智能体侧的三个直接对手各有明确缺陷。COMBO 的思路是先训若干单 agent 模型再把它们组合成多 agent 模型，论文指出这在根本上忽略了 agent 之间的交互——组合的是各自独立的动力学。MultiVerse 只模拟双人竞速游戏。并发工作 Solaris 在 Minecraft 上做了双人世界模型，数据集固定 agent 数与视角数，且做法是把两路观测沿序列维交错后过共享 self-attention；论文指出这条路因为计算和显存约束无法扩到更多视角。

至于多智能体规划领域（RoboFactory、SeqWM-MARL、TeamCraft、CausalMACE），它们依赖物理仿真器或游戏引擎，需要复杂的人工环境搭建，这正是 video world model 想要替代的东西。

§ 3 — 重建作者的思考路径 ​

从最朴素的做法出发：把 K 个 agent 的动作直接堆在一起送进一个 action encoder。作者观察到的失败是"identity ambiguity"——模型分不清 Agent 1 左移 + Agent 2 右移与反过来的情形，因为堆叠操作对 agent 维是对称的，网络没有任何信号来打破这个对称性。既然问题是对称性，那就需要一个能区分位置又能外推到任意数量的编码机制。RoPE 正好满足：它给的是相对位置，attention 里两个 agent 的内积只依赖下标差 n−m，因此训练时见过 2 个 agent 的模型在结构上能处理 4 个。

第二个观察是动作强度随时间变化，有的 agent 在动有的在停，等权处理会让模型忽略真正驱动环境变化的那一个。于是需要一个按内容自适应的加权。

多视角这一侧，最直接的两条路都不行：各视角独立生成没有任何跨视角信息；把多个视角拼成一张大图（Concat-View）在视角数增加时训练不可行，也无法处理可变视角数。要同时解决一致性和可扩展性，就得把"多视角观测"压缩成一个与视角数无关的定长表示。既然要求的是几何一致而不只是语义一致，这个压缩器应该本身就懂 3D——VGGT 作为端到端多图 3D 重建基础模型，其中间 latent 天然携带空间信息，且接受可变数量的输入图。

§ 4 — 核心 Intuition ​

两个对称性问题，两把钥匙。agent 维的排列对称性用 RoPE 打破，让动作 token 带上可外推的相对身份，再过一层 self-attention 显式建模 agent 之间的交互。视角维的组合爆炸用"共享全局状态"化解：不把多视角塞进同一个去噪序列，而是把它们编码成一个紧凑的 3D-aware 环境状态，每个视角各自作为单视角条件生成任务并行去噪，都锚定到这同一个状态上。一致性由共享的锚点保证，计算量与视角数解耦。

§ 5 — 具体方法与完整 Pipeline ​

以 RoboFactory 里三台机械臂堆方块为例。输入是三个（或任意 C 个）相机的初始帧，以及每帧的联合动作 ai​=(ai1​,…,aiK​)。

  • backbone。Wan2.2-5B，flow matching。把多视角模拟形式化为 C 个"图像-动作到视频"的生成问题，各视角并行合成，共享同一个全局环境状态。动作通过 cross-attention 注入，并施加逐帧因果 mask：第 i 帧的视频 token 只能 attend 到 {0,…,i} 的动作，防止未来信息泄漏并支撑自回归外推。
  • MACM。动作先被嵌成 latent token，按 agent 下标施加 RoPE 旋转得到 Agent Identity Embedding；随后一层 self-attention 建模 agent 间交互；再由一个 MLP 预测每个 action token 的自适应权重（Adaptive Action Weighting），加权求和成每帧一个统一的 action token。
  • GSE。多视角观测 O={Oc​}c=1C​ 送进冻结的 VGGT得到 Hvggt​∈RC×n×d，经 MLP 对齐到 DiT 维度后通过 cross-attention 注入。论文明确说明不显式重建点云，直接用 VGGT 的 latent，因为其中已经隐含 3D 空间信息。
  • 自回归。先生成所有视角的第一个 chunk，取各视角最后几帧回灌 GSE 更新全局状态，再生成下一个 chunk。
  • 数据。游戏侧从《It Takes Two》录了 500 小时真人对战，过滤后保留 100 小时（去掉过场动画、只保留左右分屏帧、剔除大幅相机运动和长时间静止段），2100 万帧以上，原始 2560×1440。两名玩家用键鼠和手柄，动作空间异构，处理办法是把两种动作拼成单个向量并把对方的分量置零，从而共用一个 encoder。机器人侧用 RoboFactory 的四个任务（击打、双臂堆叠、三臂堆叠、四臂传递），每个任务 1000 条成功 + 2000 条失败。失败轨迹不是随机动作生成的——早期实验发现纯随机会产生无意义 episode 并损害训练，最终做法是保留正确的操作步骤序列，在每步注入受控随机性，使失败"接近成功"。
  • 训练。81 帧，游戏 320×320、机器人 320×256，40000 步，学习率 5e-5，全局 batch 64，8 张 A800 约 4 天。

§ 6 — 核心数学推导 ​

flow matching 部分是标准的：xct​=(1−t)xc​+tϵ，目标速度 u=ϵ−xc​，网络 vθ​(xct​,t,a,o) 回归 u，采样时用 Euler 解概率流 ODE。

有意思的是 AIE。给定第 f 帧的动作 latent af​∈RK×D，对第 i 个 agent 施加旋转矩阵：

AIE(ai​,i)=RΘ,i​ai​

其中频率 θj​=b−2j/D，对每一对维度 (2j,2j+1) 做二维旋转。这样做的意义在 attention 内积上体现：

(Rm​am​)⊤(Rn​an​)=am⊤​Rm⊤​Rn​an​=am⊤​Rn−m​an​

即 agent m 与 agent n 的交互只依赖相对下标差。这一条同时给出了两件事：对称性被打破（Rn−m​=Rm−n​），以及身份编码可以外推到训练时未见的 agent 数。

base frequency b 的选取是一个容易被忽略但论文专门消融的点。LLM 里默认 b=10000，但 RoPE 的角度分离量级由 b 决定：当 b 很大时相邻下标之间的角度差极小，两个 agent 的嵌入几乎不可区分——这在序列长度上万时是合理设计，在 agent 数只有 2 到 4 时就完全失配。论文把 b 降到 20，使频率衰减速率与 agent 数量匹配。

§ 7 — 实验设计与结论 ​

评测指标分三类：视觉质量用 FVD/PSNR/SSIM/LPIPS；多视角一致性用重投影误差 RPE（用 DROID-SLAM 重建，计算共视 3D 点投影位置与观测像素位置的平均欧氏距离）；动作跟随用 VPT 式的 Inverse Dynamics Model（ResNet-50 + 时序层），离散动作报准确率，连续动作报 100×(1−MSE)。

比 baseline 好在哪？ 在双人游戏上，Standard（各视角独立）FVD 245、Action 88.4、RPE 0.75；Concat-View 为 215 / 89.1 / 0.74；COMBO 为 207 / 89.3 / 0.72；MultiWorld 为 179 / 89.8 / 0.67。值得注意 COMBO 在 PSNR（17.82）上其实略高于 MultiWorld（17.72），LPIPS 也更好（0.34 vs 0.35）——本文的优势集中在 FVD、动作跟随和几何一致性，而非逐像素保真度。

两个模块各贡献什么？ 逐步叠加的消融给出清晰分工：加 MACM 后 FVD 245→228、Action 88.4→89.7，但 RPE 反而从 0.75 微升到 0.76；再加 GSE 后 FVD 降到 179、RPE 降到 0.67。也就是说 MACM 买的是可控性，GSE 买的是跨视角几何一致性，两者正交。

GSE 的 backbone 必须懂 3D 吗？ 四组对照：无全局状态 FVD 228 / RPE 0.75；Wan VAE 编码各初始视角 256 / 0.71；DINOv2 语义特征 232 / 0.72；VGGT 179 / 0.67。Wan VAE 虽然与生成 backbone 的表示 gap 最小，FVD 反而最差，说明单纯提供"其他视角的像素信息"不够；DINOv2 的语义特征也只带来边际收益。只有显式建模多图之间 3D 关系的 VGGT 同时改善了视觉质量和一致性。

RoPE 的 base 真的重要吗？ b=104 时 FVD 234 / Action 89.2，b=20 时 228 / 89.7。差距不大但方向一致，符合"角度分离不足则身份不可辨"的解释。

AAW 有多大用？ 245→236（FVD）、88.4→88.6（Action）。这是全文最小的一个增益，可以推断该模块并非核心。

长时程与并行。 自回归生成可稳定到训练上下文的 2 倍，扩到 4 倍时质量损失很小。双视角下并行生成相对串行约 1.5 倍加速。

论文自陈的限制很坦率：规模仍小，大规模训练因算力未做。失败模式分析指出 agent 在画面中占比很小时形状会含糊，源于远处小物体的空间分辨率不足。

§ 8 — Take-aways ​

5 句话版：MultiWorld 把多智能体世界模型的难点归结为两种对称性/组合性问题。agent 维用 RoPE 施加相对身份编码打破排列对称，attention 内积只依赖下标差，因而可外推到任意 agent 数。视角维用冻结 VGGT 把可变数量的观测压成定长 3D-aware 全局状态，各视角作为独立的单视角生成任务并行去噪并共享这个锚点。消融显示两个模块分工明确：MACM 提升动作跟随、GSE 提升重投影一致性。数据侧贡献同样重要——100 小时《It Takes Two》真人数据与 RoboFactory 上"接近成功"的受控失败轨迹。

3 句话版：agent 身份用 RoPE 编码，因为它天然可外推且只依赖相对差。多视角一致性交给一个与视角数解耦的共享 3D 状态，而不是把视角塞进同一个序列。VGGT 优于 VAE 和 DINOv2，说明这个状态必须是几何的而非语义的。

1 句话版：把"多智能体多视角"重新表述为"打破 agent 对称性 + 共享定长几何状态"，可扩展性就成了架构的自然性质而非额外工程。

§ 9 — 最脆弱的假设 ​

最致命的假设是：冻结的 VGGT 在初始帧上提取的 latent，足以充当整段生成的全局环境状态。GSE 只吃各视角的观测帧，且在自回归里按 chunk 更新一次。这等价于假设"环境的全局几何在一个 chunk 内基本不变，且从当前可见视角能被充分观测到"。

它在什么时候不成立？第一，VGGT 是在真实多视图数据上训练的重建模型，输入换成模型自己生成的帧时其 latent 的可靠性没有被验证——这与 Lyra 2.0 面对的"深度估计跑在生成帧上"是同一类问题，但本文完全没有讨论。第二，agent 造成的环境改变（方块被移动、板子被推走）发生在 chunk 内部，而全局状态直到 chunk 结束才更新，期间各视角只能各自推断变化，一致性没有任何机制保障。第三，如果某个物体在所有视角里都被遮挡，全局状态里就不存在它的信息，"共享锚点"退化为共享的空白。

论文提供的证据是 GSE 消融（RPE 0.75→0.67）和补充材料里的定性展示（对向视角的阴影一致、雪地脚印在两个视角都持久）。这些支持"全局状态确实带来了跨视角耦合"，但不支持"它在长时程和强动态下依然可靠"。缺的关键证据是：RPE 随时间/chunk 数的曲线，以及 chunk 内部与 chunk 边界处一致性的对比。

§ 10 — 最小复现实验 ​

不需要复现 5B 训练和 100 小时游戏数据。选 RoboFactory 的双臂堆叠任务，用一个小得多的 DiT（或直接在开源的图像-动作到视频模型上加模块），只验证AIE 的外推性这一条最强 claim，因为它是可扩展性论证的支点。

  • 数据：RoboFactory 上采两组，2 agent 与 3 agent，各几百条 episode，视角数固定为 2 以隔离变量。
  • 训练：只用 2-agent 数据训练，AIE 的 base frequency 分别取 20 与 10000，另加一组用可学习的 agent embedding 表（不可外推）作对照。
  • 测试：在 3-agent 数据上零样本评测，指标只看 IDM 动作跟随准确率，按 agent 分别报告。
  • 判据：若 RoPE 版（b=20）在 3-agent 上的动作跟随显著高于可学习 embedding 版（后者对未见的第三个下标没有定义，只能退化处理），则支持"相对身份编码带来 agent 外推"。若两者相当，说明外推收益来自别处，可扩展性的 claim 需要重新归因。

再补一个极便宜的诊断：构造"镜像动作"测试集（Agent 1 左移 + Agent 2 右移，与完全反过来的一对），直接测模型能否区分。这是论文用来动机化 AIE 的具体失败模式，但正文并未给出针对它的专门实验。

§ 11 — 最强反例设计 ​

反对者最有力的攻击针对多视角一致性的度量本身。RPE 由 DROID-SLAM 在生成视频上重建后计算，它衡量的是"生成视频内部的几何自洽"，对跨视角是否描述同一个世界状态其实是间接的。一个模型完全可以让每个视角各自平滑自洽（低 RPE），却在语义上互相矛盾：视角 A 里方块被放上了，视角 B 里还没有。GSE 提供的是一个被压缩的全局条件，它可能主要在提升每个视角的几何稳定性，而不是在强制跨视角的状态同步。

设计验证：构造一个跨视角事件一致性测试。在 RoboFactory 里选择离散且可自动判定的事件（方块是否已被抓起、是否已放置到目标位、两臂是否发生碰撞），对每个生成视角独立跑一个事件分类器，然后计算各视角判定结果的一致率与相对真值的准确率。如果 MultiWorld 与 Standard baseline 在这个指标上差距远小于 RPE 上的差距（0.75 → 0.67），那么 GSE 的贡献就应被重新解释为"几何平滑"而非"状态同步"，而这正是替代解释。

第二类攻击指出可预测的失败条件：让一个 agent 在所有相机的视野之外操作（RoboFactory 里很容易构造，或在游戏里让一名玩家进入另一名玩家看不到的房间）。此时全局状态里没有该 agent 的信息，动作却仍被送入模型。预测是模型会产生"幽灵效应"——要么忽略该动作导致状态不同步，要么在可见视角里凭空画出不应出现的变化。论文的两个数据集（分屏合作游戏、桌面机械臂）恰好都保证了高视野重叠，回避了这个区域。

§ 12 — Follow-up Research Idea ​

驱动的局限：全局状态是从像素观测编码出来的，因此只能表示被看见的东西；而多智能体环境的本质是每个 agent 都只有部分观测，真正的世界状态从来不完全可见。

新 framing：把世界模型的全局状态从"多视角观测的编码"改造成"被动作序列持续修正的信念状态"，即引入部分可观测下的显式 belief update。可借鉴的相邻领域工具是 POMDP 里的滤波与 Dec-POMDP 里的联合信念：状态更新不只来自新观测（correction），也来自已知的联合动作（prediction）。具体做法是让全局状态 Ht​ 按 Ht​=f(Ht−1​,at−1​,{Oc​}visible​) 递推，其中 f 包含一个纯动作驱动的预测项——即便某个 agent 完全不可见，它的动作依然会改变全局状态。

这不是增量式改进，因为它改变了状态的语义：从"我看到了什么"变成"我相信世界是什么样"，并且天然给出了不可见 agent、遮挡物体和 chunk 内部变化的统一处理方式。它同时把世界模型和多智能体规划连了起来——belief state 正是 MARL 里 policy 的输入。

第一个实验：在 RoboFactory 上构造一个"部分可观测"变体，把相机摆位改成每个视角只能看到一部分工作区，保证至少一个 agent 在某些时段完全不可见。对比三个模型：本文的 GSE（观测驱动）、GSE + 动作驱动的递推预测项、以及一个只用动作不用观测的上界对照。度量指标用 §11 提出的跨视角事件一致性与动作跟随准确率，重点看"不可见时段"这一子集。如果递推版本在不可见时段显著更好而在全可见时段不掉点，就说明世界模型确实需要一个信念状态而不只是一个观测编码器。
