ConsisDrive: Identity-Preserving Driving World Models for Video Generation by Instance Mask ​

项内容
arXiv2602.03213
提交日期2026-02-03
作者Zhuoran Yang, Yanyong Zhang
分类cs.CV
一句话用 3D 框投影出的实例 mask 同时约束 attention 连边和去噪损失的作用区域，把驾驶视频生成里「公交车变卡车、黑车变红车」的身份漂移按住。

所属教程：世界模型

§ 1 — 研究问题与重要性 ​

驾驶世界模型作为数据引擎的价值，取决于生成视频能不能替真实采集分担训练负担。这里有一个被长期低估的失败模式：identity drift——同一个物体在帧间改变外观甚至类别。论文用三张图把它拆成三种具体形态：DriveDreamer2 里公交车逐渐变成卡车（类别漂移），MagicDrive-V2 里同一辆车的颜色在帧间跳变（外观漂移），以及小目标如行人被背景稀释成模糊团块（前景稀释）。

为什么这件事重要而不只是「不好看」：下游任务对实例级时序稳定性有硬需求。多目标跟踪要求同一物体的外观在时间上稳定，否则 ID switch 暴涨；视频式感知模型（如 StreamPETR）依赖跨帧的时序上下文；规划则依赖周围 agent 轨迹的连贯性来做运动预测。如果生成数据里的物体身份是漂的，用它训出来的模型学到的就是错误的时序先验。

§ 2 — 前人工作与不足 ​

街景生成这条线上，BEVGen 把语义编进 BEV layout，BEVControl 用两阶段流程保证跨视角一致性。它们能做到布局可控，但把 3D 信息投影成 2D layout 会丢几何细节，这个损失在视频里表现为时序不一致。DrivingDiffusion 用多阶段管线做多视角视频，代价是流程复杂。

论文对身份漂移给出的三条根因诊断是全文最有价值的部分，而且每一条都精确指向一个具体机制而非泛泛而谈：

第一，缺少显式的实例身份条件。DriveDreamer2 不注入类别这类实例特定条件，模型没有任何东西可以在长时段上锚定身份，语义就会缓慢漂移。

第二，attention 本身不是实例感知的。FLUX 的 MMDiT 在所有视觉 token 上做 3D full attention，不同实例的信息自由互串，导致 information leakage。MagicDrive-V2 虽然加了时序注意力提升帧间的全局连贯性，但缺少细粒度的实例级时序对齐，所以颜色仍会漂。这里的关键区分是：全局时序一致 ≠ 实例级时序一致。

第三，训练目标均匀作用于整帧。背景像素（天空、建筑）在数量上压倒前景，均匀监督造成 supervision dilution，模型没有动力去抠身份保持所需的细粒度特征，小目标首当其冲。

§ 3 — 重建作者的思考路径 ​

这条路径其实相当直接，前提全部来自这篇论文之前就存在的经验。

驾驶数据集本来就带 3D 框和 tracking ID，这是自动驾驶领域独有的便利——同一物体在不同帧的对应关系是已知的，不需要从像素里推。而扩散 transformer 的 attention mask 是一个现成的、零参数的连边控制接口，ControlNet 式的条件注入也早已成熟。

于是问题变成：既然我知道哪些 token 属于同一个实例，为什么要让模型自己从数据里学这件事？把 3D 框投到每一帧的像面，取角点凸包，栅格化成二值 mask，再插值到 latent 分辨率，就得到了 token 到实例的归属关系。有了这个归属，两件事立刻可做：限制 attention 只在同实例内连边；限制损失只在前景区域计算。

第二个念头是关于损失的：全部只算前景显然会毁掉背景（道路、高精地图区域）的生成质量。最省事的折中不是加权求和——那要调权重——而是按概率二选一，让期望自动成为两种目标的混合。

§ 4 — 核心 Intuition ​

模型之所以让公交车变成卡车，是因为在它的 attention 图里，公交车的 token 和卡车的 token、和背景的 token 之间没有任何结构性区别，一切都靠数据统计去隐式区分。ConsisDrive 的做法是把「哪些 token 是同一个东西」这件已知信息直接写死进 attention 的连边结构和损失的作用域，而不是指望模型从像素里重新发现它。约束一旦从软性偏好变成硬性 mask，身份就不再有漂移的自由度。

§ 5 — 具体方法与完整 Pipeline ​

底座是 OpenSora V2.0：Video DC-AE 做视频编码，T5XXL 和 CLIP-Large 做文本编码，MMDiT 做去噪主干。控制信号（3D 框投影、道路图、场景描述）经 ControlNet 注入——具体做法是复制 double-stream MMDiT 主干的前 19 个 base block 作为专用控制块，每个控制块把条件特征与对应 base block 的输出融合。

以 nuScenes 的一个片段为例，走一遍完整流程：

  • 构造实例身份条件。对视频中每个实例 i，取类别标签 ci​、tracking ID IDi​、框尺寸 si​=(dxi​,dyi​,dzi​)。ID 和尺寸过 Fourier 映射 γ(⋅)，类别过 CLIP-Large 文本编码器 τθ​(⋅)，拼接后过 MLP：

    gi​=MLP([τθ​(ci​),γ(si​),γ(IDi​)]),G={gi​}i=1n​.

  • 构造 token 到实例的归属。实例 i 的 8 个 3D 角点 Xi,c​ 用第 t 帧的相机参数 (Kt​,Rt​,Tt​) 投影，取凸包得到多边形 Pit​，栅格化成 BMi​∈{0,1}T×H×W，再三线性插值到 latent 分辨率得 BMi​。指示函数定义为 I(vk​)={i∣∃(x,y),BMi​(t,x,y)=1}。
  • Instance-Masked Attention。把 m=Tcomp​×Hcomp​×Wcomp​ 个视觉 token V 与 n 个实例条件 token G 拼接做 3D self-attention，用 mask 矩阵 M∈R(m+n)×(m+n) 控制有效连边，输出经门控加回主干（ω 是初始化为 0 的可学习标量）。
  • Instance-Masked Loss。用同一套指示函数构造二值损失 mask，按概率决定这一步用前景聚焦损失还是全局损失。
  • 训练配置。输入 16×256×448，64 张 A100。论文报告该方法可稳定生成 200 帧以上。

§ 6 — 核心数学推导 ​

方法的全部数学集中在两个 mask 的定义上，形式简单但语义值得掰开讲。

身份 mask。对视觉 token vk​ 与实例条件 token gi​：

Mk,m+i​=Mm+i,k​=−∞if i∈/I(vk​).

在 softmax 之前把 logit 置为 −∞，等价于把该连边的注意力权重强制为 0。它的作用是：每个视觉 token 只能看到自己所属实例的身份嵌入。这一条同时做了两件事——把类别与尺寸信息绑到正确的空间位置上（attribute binding），以及阻断实例之间的身份泄漏。

轨迹 mask。对两个视觉 token vk​,vj​：

Mk,j​=−∞if I(vk​)∩I(vj​)=∅.

注意这里用的是集合交为空，而不是相等——一个 token 可能落在多个重叠框内，只要有共同实例就允许连边。它的效果是让同一物体在不同帧的 token 互相可见，从而把颜色、纹理这类外观特征沿轨迹传播；不同实例之间则被严格切断。

融合用门控残差：

V=V+tanh(ω)V~[:m],

ω 初始化为 0 意味着训练初期这个模块是恒等映射，不会破坏预训练主干的先验，这是常见但重要的稳定性设计。

概率化掩码损失。记原始去噪损失为 L，前景掩码为 MLoss​(vk​)=1{I(vk​)=∅}，则 Lmask​=MLoss​⊙L。直接一直用它会让模型过拟合前景、毁掉道路和高精地图的生成质量，所以：

L~mask​={Lmask​,L,​p<αp≥α​

从期望上看，这等价于以 α 的比例把梯度预算分配给前景专注目标、1−α 分配给全局重建目标。相比直接加权求和，随机切换的好处是每一步的梯度方向是「纯」的，不会因两个目标在同一步里冲突而互相抵消——这一点论文没有明说，属于合理推断。

§ 7 — 实验设计与结论 ​

全部实验在 nuScenes 上，对比 BEVControl、DrivingDiffusion、DriveDreamer2、Panacea、MagicDrive-V2 等。

问题一：视觉与时序保真度如何？ FVD 降到 37.23、FID 3.88，优于表中所有对比方法，包括 InstaDrive（38.06 / 3.96）、UniScene（70.52 / 6.12）、UniMLVG（60.1 / 8.8）、DriveDreamer2（55.7 / 11.2）。作者把 FVD 的改善归因于 IMA 跨帧保住了实例属性。

问题二：生成的实例属性绑定对不对？ 这里的实验设计相当聪明：不去直接测「颜色对不对」，而是用感知任务当探针——因为准确的类别识别与尺寸定位本来就是感知的基本要求，所以感知性能直接反映生成内容与条件的对齐程度。只用生成数据训 StreamPETR，mAP 达到 31.5%，为真实 nuScenes 训练的 91.3%；对照 Panacea 是 22.5%（65.22%）。真实数据加生成数据一起训，NDS 达到 54.6，比只用真实数据提升 7.7 分，而 Panacea 的对应提升是 2.3 分。另外用预训练 StreamPETR 直接评测生成的验证集，ConsisDrive 的 NDS 相对性能 88.23%，高于 MagicDrive-V2 的 78.51% 和 Panacea 的 68.00%。

问题三：实例属性沿时间传播得好不好？ 用多目标跟踪当探针，因为 MOT 恰恰要求按一致属性跨帧追踪。用生成数据增广后重训 StreamPETR 跟踪器，在真实验证集上 IDS 降到 525，相比 Oracle 的 687 减少 162，也优于 InstaDrive 的 532 和 DriveDreamer2 的 593；AMOTA 0.498、AMOTP 1.350。

问题四：三个组件各自有多重要？ 消融的读法是「拿掉之后掉多少」：去掉身份 mask，NDS 掉 3.83 分，FVD 涨 3.66，IDS 增加 210；去掉轨迹 mask，FVD 暴涨 16.43，IDS 激增 549；去掉 IML，NDS 掉 4.53，IDS 增加 112。三组数字的分布本身就是证据——轨迹 mask 主要影响时序（FVD、IDS），身份 mask 与 IML 主要影响属性正确性（NDS）。定性上，去掉身份 mask 会让交通锥渲染成蹲着的行人，去掉轨迹 mask 会让车颜色漂移，与设计意图吻合。

§ 8 — Take-aways ​

5 句话版：ConsisDrive 把驾驶视频生成中的 identity drift 归因于三点——缺显式实例身份条件、attention 不区分实例、损失被背景稀释——并对每一点给出一个基于 3D 框投影 mask 的直接修补。Instance-Masked Attention 用身份 mask 把视觉 token 绑到自己实例的身份嵌入上，用轨迹 mask 让同一物体的跨帧 token 互相可见而切断异实例连边。Instance-Masked Loss 以概率 α 在前景聚焦损失与全局损失之间切换，避免前景过拟合毁掉背景。在 nuScenes 上取得 FVD 37.23、FID 3.88，纯生成数据训 StreamPETR 达到真实数据 91.3% 的 mAP，真实加生成使 NDS 提升 7.7 分，跟踪 IDS 相比 Oracle 减少 162。消融显示轨迹 mask 主导时序指标、身份 mask 与 IML 主导属性正确性。

3 句话版：驾驶数据自带 3D 框和 tracking ID，所以「哪些 token 是同一个物体」是已知信息，不该让模型从像素里重新学。把这个信息写进 attention mask 和损失 mask，身份漂移就失去了自由度。代价几乎为零（mask 无参数，融合门控初始化为 0），收益在感知与跟踪两个下游探针上都被量化验证。

1 句话版：把「同一个物体」这件已知的事写死进 attention 的连边和损失的作用域，公交车就不会中途变成卡车。

§ 9 — 最脆弱的假设 ​

最脆弱的假设是：3D 框凸包投影出的矩形化区域，能够充分近似实例的真实像素支撑集。整套方法的两个 mask 和一个损失全部由这个投影 mask 派生，如果它与真实物体轮廓的偏差足够大，三个组件会同时失效。

它在实践中不成立的场景是可预见的。第一是遮挡：两辆车前后重叠时，后车的框投影仍会覆盖被前车挡住的像素区域，于是后车的 token 集合里混入了实际属于前车的像素，轨迹 mask 会把前车的外观特征沿后车的轨迹传播——这恰恰是它想阻止的那种泄漏。论文的指示函数用集合交非空来允许多归属，某种程度上缓解了这个问题，但也削弱了「严格阻断」的强度。第二是非凸物体与铰接物体：行人、自行车骑手的框凸包里有大量背景像素。第三是 latent 分辨率：三线性插值到 latent 网格后，小目标可能只覆盖一两个 token，mask 的空间精度几乎丧失——而小目标恰恰是 IML 声称要救的对象。

论文提供的正面证据是端到端的下游指标（mAP、NDS、IDS）都改善了，以及行人生成质量的定性对比。但缺的是按遮挡程度和目标尺寸分层的结果：如果把 nuScenes 验证集按可见度属性分桶，ConsisDrive 相对基线的增益是否在重遮挡桶里消失甚至反转？这个实验会直接检验最脆弱的一环，论文里没有。以上属于基于证据的推断。

§ 10 — 最小复现实验 ​

一周内可做且不必训练完整视频扩散模型：把 IML 单独拎出来验证。取任意一个已开源的驾驶视频生成模型（或者退一步，取图像级的 layout-to-image 模型），冻结其余一切，只把去噪损失换成概率化的前景掩码损失，微调少量步数。掩码由 nuScenes 的 3D 框投影生成。

测量三个量：整体 FID、按目标尺寸分桶（小/中/大）的裁剪区域 FID、以及用预训练 StreamPETR 在生成验证集上的 mAP。支持论文的结果是：小目标桶的裁剪 FID 显著改善，整体 FID 不劣化，mAP 上升。反驳的结果是：小目标桶改善但整体 FID 明显变差，说明背景确实被牺牲了、概率切换的平衡并不像论文暗示的那样无痛；或者三项都基本不动，说明 IML 的增益依赖于 IMA 同时存在，不能独立成立。

顺带可以扫 α：如果性能在 α∈[0.2,0.8] 上几乎不变，说明这个超参不敏感（好消息）；如果只在某个窄区间有效，那论文没有报告 α 的具体取值就是一个可复现性隐患。

§ 11 — 最强反例设计 ​

站在反对者立场，最有力的攻击是提供一个替代解释：下游感知与跟踪的增益可能主要来自生成数据的分布覆盖与数量，而不是实例身份一致性本身。数据增广提升检测器性能是一个极其稳健的现象，几乎任何合理质量的合成数据加进去都会涨点。ConsisDrive 相对 Panacea 涨得更多，也可能只是因为它的整体画质更高（FID 3.88 对 16.96），而画质与身份一致性是高度相关的混淆变量。

设计这样一个实验来分离两者：构造一个「身份打乱」的对照数据集——用完整 ConsisDrive 生成视频，但在训练下游模型时，人为地把每条轨迹的 tracking ID 在时间上随机置换（保持每帧标注正确，只破坏跨帧关联）。如果用这份数据训出的检测器 mAP 与原版几乎一样，说明感知增益与身份一致性无关，只与单帧质量有关；只有 MOT 的 IDS 会变差。反过来，如果 mAP 也明显下降，则支持论文的归因。这个对照几乎零成本，却能把「画质好」和「身份稳」彻底分开。

另一类可预测的失败条件在 §9 已经提到：重遮挡场景。可以直接构造对抗性 layout——把多个同类不同色的车辆密集排布并互相遮挡，让它们的 3D 框投影大面积重叠。此时 I(vk​)∩I(vj​)=∅ 对几乎所有 token 对都成立，轨迹 mask 退化成全连接，方法自动失去约束力。这是可预测的、结构性的失败，不是随机噪声。

§ 12 — Follow-up Research Idea ​

驱动 idea 的局限是：整套方法的约束粒度被 3D 框这个粗糙的几何代理锁死了，而框在遮挡、非凸、小目标三种常见情形下都是糟糕的近似。

一个非增量的 re-framing 是：把实例归属从二值 mask 变成一个可学习的、随去噪步演化的软分配，并让这个分配本身受时序一致性约束。也就是说，不再问「这个 token 属于哪个框」，而是问「在当前去噪时刻，这个 token 应该有多大比例地听从哪个实例的身份」。粗去噪步时框级的粗分配足够，细去噪步时分配应当收敛到真实轮廓——这与扩散模型「先低频后高频」的生成顺序天然对齐。

可借鉴的相邻领域工具有三样。一是 slot attention 与 object-centric learning，它们已经把「无监督地把像素分配给对象槽位」做成了可微模块，这里可以用 3D 框作为槽位的初始化而非最终答案。二是全景分割里的 mask transformer（Mask2Former 一系），它们把 mask 预测本身写成注意力查询。三是最优传输——把 token 到实例的分配写成一个带边际约束的传输问题，1⊤ 行约束保证每个 token 的归属权重和为 1，列约束用框面积作为先验，Sinkhorn 迭代求解，整个过程可微。

第一个实验可以做得很轻：在训练好的 ConsisDrive 上冻结主干，只把硬 mask 换成由「框内先验 + 当前去噪特征相似度」组成的软权重，用 Sinkhorn 归一化，仅微调这一层。评测集专门构造成重遮挡场景（从 nuScenes 里按可见度属性筛选），主指标是该子集上的 IDS 与裁剪区域 FID。如果软分配在重遮挡子集上把 IDS 拉回到轻遮挡子集的水平，就证明了粒度而非机制才是当前的瓶颈，这会把整条「用先验 mask 约束生成」的研究线推向「让先验只做初始化、让模型自己精化归属」的新范式。
