HeadCast: Casting Attention Heads for Efficient Autoregressive Video Generation ​

项内容
arXiv2607.20125
提交日期2026-07-22
作者Jinliang Shen, Lianghao Su, Zheming Li, Kang He, ZiLiang Lai, Yanbing Jiang, Chengru Song
分类cs.CV, cs.LG
一句话在最大噪声步做一次性 head 分类，把注意力头分成 Sink / Dummy / Spatial / Global 四类并各配一条 KV 通路；Spatial 通路走固定尺寸网格，因此省下的比例随分辨率增长，同时保留 Global 头以避免激进淘汰造成的块边界闪烁。

所属教程：自回归视频生成

§ 1 — 研究问题与重要性 ​

自回归视频扩散逐块生成、用 KV cache 复用历史，这让长视频与流式生成成为可能，但 cache 随时间线性增长，注意力以 O(L2) 的代价迅速吃掉推理时间。滑窗能把增长掐住，可是高分辨率下窗内序列仍然很长——每帧贡献的 token 数随分辨率平方增长，720P 与 1080P 上注意力重新变成瓶颈。

激进地砍 cache 也不是出路：现有的训练无关方案用粗糙的启发式做淘汰，会丢掉某些头真正依赖的长程上下文，产生块边界处的帧间闪烁与结构漂移；基于训练的稀疏注意力方案则要重新训练。

论文提出的问题很干净：是不是每个注意力头都需要看完整历史？如果不是，它们各自需要什么？ 这个问题值得问，因为它把「压多少」这个一维旋钮换成了「谁压、怎么压」的分派问题，而后者有可能在同一速度点上换到高得多的保真度。

§ 2 — 前人工作与不足 ​

三条线交汇在这里。第一条是 AR 视频扩散本身：MAGI-1 逐块渐进去噪、CausVid 把双向 DiT 转成带 KV cache 的因果生成器、Self-Forcing 让模型条件在自己生成的帧上、Rolling Forcing 扩大扩散窗口、LongLive 用 KV re-cache 维持场景切换后的连续性。这些工作把步数压下去了（少步蒸馏），但每一步的注意力成本没动，HeadCast 与它们正交。

第二条是 LLM 的 KV cache 压缩：StreamingLLM 保留初始 token 的 sink，H2O 与 SnapKV 按注意力分数保留关键 token，DuoAttention 与 FastGen 按 head 分配不同预算。作者的批评是它们针对文本的一维结构，不利用视频的时空冗余。

第三条最接近：双向 DiT 的稀疏注意力（Sparse VideoGen 系列识别空间头与时间头）在 3D 全注意力下定义模式，无法直接迁到因果、动态增长的 AR 上下文；Light Forcing 做块级 coarse-to-fine top-k 但对所有头用同一套方案，Sparse Forcing 学原生稀疏注意力，两者都要额外训练。训练无关的一支里，最直接的对手是 Dummy Forcing：它把许多只有轻微时间稀疏性的头强行推进「只保留当前帧」的 dummy 模式，过度丢弃了它们依赖的长程上下文。同期还有 Forcing-KV，以及 Deep Forcing（目标是长程生成质量与稳定性而非分辨率扩展的加速）。

一个必须点出的同期关系：Head Forcing（2605.14487）同样利用注意力头的异质性，但用途是长时程外推（分层记忆 + head-wise RoPE 重编码把生成推到分钟级），而不是本文追求的随分辨率扩展的加速。更早的 Pyramid Forcing 也做过三类 head + 异构 KV cache。因此「head 异质性」这个观察本身在本文之前已经被独立发现过至少两次；HeadCast 的增量在于新增 Spatial 类型（把 Sparse VideoGen 的空间局部性搬到因果设定）并显式保留一个 Global 类型兜底。

§ 3 — 重建作者的思考路径 ​

从 Dummy Forcing 的失败模式出发：它已经证明有一部分头只需要最近一块，但把「不是明显长程」的头都归到这一类，代价是闪烁。那问题就变成——被误归类的那些头到底在看什么？

第一步是换观察坐标系。按帧聚合注意力分数，能看出两种极端的时间稀疏：全部压在第一块（Sink）与全部压在当前块（Dummy）。但对剩下的头，时间维上看不出结构。于是第二步把历史 KV 投回原始的二维空间网格再聚合，这才暴露出第三种模式：注意力集中在查询自身的局部空间邻域，但跨越全部历史帧。这类头在时间上不稀疏、在空间上极稀疏——恰好是 Dummy Forcing 的一维视角看不见的那一类。剩下真正需要完整上下文的，才是 Global。

第三步是可行性检验：分类要是每步都做就没有意义了。作者量化了稳定性——超过 90% 的头在不同自回归步上得到相同类别，跨去噪步与跨 prompt 也相似——于是一次性分类成立。

第四步是选在哪一步分类。直觉上应该在注意力反映结构偏好而非内容偏好的时刻，也就是最大噪声步 t=1000。这条直觉后来被消融证实，而且给出了机制解释：t 越低模型越关注局部高频细节，越来越多头表现出 Dummy 行为，真正需要全局历史的头被误路由到常数尺寸窗口。

第五步是工程妥协。分类时用的 Spatial 代理是每个 query 周围 (2r+1)×(2r+1) 的滑动邻域，但滑动窗口无法用 FlashAttention、只能走慢速的 FlexAttention 内核；部署时改成把每帧切成互不重叠的网格，得到一堆独立的稠密子矩阵，可以沿 batch 维堆起来交给 FlashAttention。作者明确称之为「同一局部性的硬件高效近似」。

§ 4 — 核心 Intuition ​

一个头的 KV 预算应该由它实际依赖的上下文形状决定，而不是由一个全局的稀疏率决定。视频里这个形状有三种极端（只要开头、只要最近、只要自己周围的一小片但要全历史）和一种兜底（什么都要），而且它主要由头本身的功能决定、几乎不随内容变化，所以可以一次性判定并永久固定。前人方法失效是因为它们只在时间轴上看稀疏性，于是把「时间上不稀疏但空间上极稀疏」的那类头误当成了长程头（保留全部，白花钱）或短程头（激进淘汰，闪烁）。

§ 5 — 具体方法与完整 Pipeline ​

以 Self-Forcing 生成一条 5 秒 720P 视频为例，共 360 个注意力头，每块 3 帧，滑窗为 4 块（1 个固定 sink 块 + 3 个滚动块）。

  1. Warm-up：前几个自回归步跑完整注意力，把上下文积累起来。
  2. Online Classification（cache 首次超过窗口 W 时触发，在最大噪声步 t=1000，只做一次）：对每个头算完整上下文下的参考输出 Oref(h)​，再算三种受限输出——Sink 代理（只看第一块）、Dummy 代理（只看当前块）、Spatial 代理（跨全部历史块但限制在 r=2 的 5×5 邻域内）。按逐 token 余弦相似度的均值判定，其中 Spatial 额外用一个保守的最坏情况分数。
  3. Heterogeneous Cache Management：把整块 KV cache 沿 head 维拆成三份。Sink-Dummy Cache 合并两类（Sink 头冻结初始块，Dummy 头用滚动覆盖只留最近块），两者的 KV 序列形状相同因而可以融进同一个注意力内核。Global Cache 保持标准滑窗布局（保留初始 sink token，淘汰窗外中间帧）。Spatial Cache 时间布局与 Global 相同，但靠下一阶段的空间掩码把有效计算压下去。
  4. Head-Specific Attention：每个自回归步按 head 维切分 query 分发到各自通路。Spatial 通路把每个 latent 帧切成互不重叠的 10×10 单元（边界余数向上取整），query 只与同一单元内跨窗口全部帧的 KV 交互，分解出的独立稠密子矩阵沿 batch 维堆叠后交给 FlashAttention。最后把各通路输出沿 head 维拼回。
  5. 超参：三个余弦阈值绑成同一个值 θs​=θd​=θsp​=0.95，空间分数阈值 θsc​=0.755，MSE 惩罚权重 γ=5。这一套在四个骨干与所有分辨率上原样使用，不做逐模型调参。
  6. 典型分派结果（t=1000，360 个头）：Sink 29.4、Dummy 136.3、Spatial 84.1、Global 110.2。

§ 6 — 核心数学推导 ​

分类判据。 给定该步的 query Q 与完整历史 (Kfull​,Vfull​)，参考输出为

Oref(h)​=Attention(Q(h),Kfull(h)​,Vfull(h)​),

对三种受限上下文 m∈{sink,dummy,spatial} 计算逐 token 余弦相似度的均值

cosm(h)​=Lq​1​t=1∑Lq​​cos(Om(h)​[t],Oref(h)​[t]).

这里的 intuition 是不去看注意力图长什么样，而直接看「把上下文砍掉之后，这个头的输出还是不是同一个向量」——判据定义在最终效果上，因此对注意力分布的形状不做任何假设。

为什么 Spatial 要用最坏情况分数。 均值余弦相似度可能在少数边界 token 上严重失败却仍然很高，而这些失败正是残留鬼影的来源。于是对 Spatial 额外用 5 百分位加 MSE 惩罚：

score(h)=P5​(cosspatial(h)​)−γ⋅MSE(Ospatial(h)​,Oref(h)​).

互斥决策层级。

C(h)=⎩⎨⎧​SinkDummySpatialGlobal​cossink(h)​≥θs​elif cosdummy(h)​≥θd​elif cosspatial(h)​≥θsp​ 且 score(h)≥θsc​otherwise​

优先级的顺序本身有后果：Dummy 排在 Spatial 之前，因此在低噪声步（局部性强）会有大量头被吸进 Dummy，这正是 t 消融观察到的现象。

为什么加速比随分辨率增长。 Spatial 通路的每个 query 只与固定尺寸网格（10×10）内的 token 交互，这个数目与分辨率无关；而每帧总 token 数随分辨率平方增长。因此 Spatial 头访问的历史 KV 比例随分辨率下降，省下的绝对计算量随之上升——这是全文加速比从 480P 的 1.02–1.08× 一路涨到 1080P 的 1.95× 的唯一机制来源。

§ 7 — 实验设计与结论 ​

问题一：在标准分辨率上，四类分派能否在不掉质量的前提下换到速度？ 设计是在 Self-Forcing、LongLive、Causal Forcing、Reward Forcing 四个骨干上，与各自的完整滑窗注意力和 Dummy Forcing 比较。5 秒用 VBench 标准 prompt，30 秒用 Self-Forcing++ 的 128 条 MovieGen prompt 跑 VBench-Long，全部用 Qwen2.5-7B-Instruct 改写 prompt，每条 prompt 5 个种子取平均。因为文生视频没有真值帧，作者用各模型自己的完整注意力输出作参考报告 PSNR/LPIPS。

答案分两半。保真度这一半站得住：三个 5 秒骨干上 HeadCast 的 PSNR 22–26 dB 对 Dummy Forcing 的 16–19 dB，LPIPS 低 3–4 倍（0.045–0.068 对 0.15–0.22），VBench Total 与完整注意力的差距不超过 0.15，附录 E 的块边界跳变指标显示 Dummy Forcing 在长片段上把边界跳变抬高最多 36%，而 HeadCast 与基线持平。

速度这一半必须如实说：480P 上加速几乎不存在（HeadCast 1.02–1.08×，Dummy Forcing 1.01–1.16×），作者也承认此时 cache 太小、注意力还不是瓶颈。更麻烦的是 LongLive（30 秒）这一行——Dummy Forcing 在 VBench Total（82.48 对 82.12）、FPS（18.63 对 17.29）与 Dynamic Degree（34.81 对 29.84）三项全面胜过 HeadCast，HeadCast 只赢 0.75 dB PSNR 与 LPIPS；而且 HeadCast 的 Total 82.12 还低于完整注意力的 82.26。Dynamic Degree 在 Causal Forcing 上更奇怪：两种加速方法都高于完整注意力基线（95.2 / 94.6 对 85.0），说明这个指标在此处并不指示保真。

另有一处算术需要指出：分类开销在 5 秒片段上是生成时间的 5–8%（30 秒上低于 1.5%），而 480P/5 秒的稳态加速只有 1.02–1.05×（约省 2–5% 时间）。由此可以推断，在 480P 短片段这一档，端到端的净收益很可能为零甚至为负；论文写「把它算进去几乎不改变结果」，这在 720P/1080P 成立，在 480P/5 秒不成立。

问题二：加速是否随分辨率扩展？ 这是全文最强的一组结果。Self-Forcing 5 秒从 720P 的 1.31× 到 1080P 的 1.46×；LongLive 30 秒（cache 更大）到 1.62× 与 1.95×；稳态 KV cache 在 Self-Forcing 上缩约 33%。但 Dummy Forcing 在每一个分辨率上都更快（720P 上 1.36× / 1.74×，1080P 上 1.63× / 2.16×），HeadCast 的主张始终是「同一速度区间内保真度高得多」，而不是更快。作者还主动解释了 LongLive 上 PSNR 只有 15.22 dB 的原因：30 秒 rollout 里稀疏化模型会与完整注意力轨迹分岔，这是参考型指标的性质而非质量损失，绝对质量由 VBench Total 佐证（720P 79.05 对 79.07，1080P 77.26 对 76.84）。

问题三：人类怎么看？ 2AFC 盲测给出一个诚实的结果：对 Dummy Forcing 是 90.9% 对 9.1% 的压倒性偏好，但对完整注意力是 39.6% 对 60.4%——人更喜欢完整注意力。作者的表述是「代价只是一个不大、常常不可察觉的质量边际」。主文没有给出参与者人数与比较次数（在附录 G）。

问题四：两类稀疏各值多少？（Self-Forcing 5 秒 720P）All-Global 基线 1.00× / VBench 83.78；只开 Spatial 1.19× / 25.04 dB / 83.76；只开 Sink+Dummy 1.04× / 27.99 dB / 83.82；完整 1.31× / 25.87 dB / 83.83。结论是 Spatial 是主要的速度杠杆也承担主要保真代价。但要注意一处非单调：完整 HeadCast 的 PSNR（25.87）反而高于只开 Spatial（25.04）——在既有稀疏上再加稀疏使保真度上升，说明这条轴的噪声底约在 1 dB 量级，Table 4 里小于 1 dB 的差异不宜作结论。

问题五：分类的时机与稳定性。 t 从 1000 降到 250，Dummy 头从 136.3 涨到 190.8、Global 头从 110.2 塌到 65.9，PSNR 从 25.87 单调降到 24.52，验证了在最大噪声步分类的选择。一次性分类的稳定性在三条轴上分别是 90.3%（自回归步）、85.8%（去噪步）、79.8%（文本 prompt）。

§ 8 — Take-aways ​

5 句话版：HeadCast 观察到预训练 AR 视频扩散模型的注意力头有四种稳定的异质结构偏好——Sink（锚在首块）、Dummy（只看当前块）、Spatial（跨全历史但只看自己周围的空间邻域）、Global（需要完整上下文），其中 Spatial 是只看时间轴的方法看不见的那一类。分类在最大噪声步做一次，判据不是注意力图的形状而是「砍掉上下文后输出向量还一不一样」的余弦相似度，Spatial 额外用 5 百分位加 MSE 惩罚的最坏情况分数。分类后把整块 KV cache 沿 head 维拆成 Sink-Dummy、Global、Spatial 三份，Spatial 通路用 10×10 互不重叠网格以便复用 FlashAttention，于是省下的比例随分辨率增长：720P 1.62×、1080P 1.95×。保真度是主要卖点——对各自完整注意力输出的 PSNR 比 Dummy Forcing 高 6–7 dB，LPIPS 低 3–4 倍，块边界跳变与基线持平，2AFC 里以 90.9% 胜过 Dummy Forcing。但 Dummy Forcing 在每个分辨率上都更快，480P/30 秒的 LongLive 上它在 VBench、FPS、Dynamic Degree 三项全胜，而人类在 2AFC 中仍以 60.4% 偏好完整注意力。

3 句话版：不同注意力头需要的上下文形状不同，而且这个形状主要由头本身决定、跨步跨内容基本稳定，所以可以一次判定、永久分派。加上一个「时间上不稀疏、空间上极稀疏」的新类别，并保留一类什么都看的兜底头，就能在与激进淘汰相近的速度点上换到高得多的帧级保真度。真正的收益只在高分辨率长上下文出现，480P 上加速比可能还抵不过一次性分类的开销。

1 句话版：先问每个头到底需要看什么，再决定给它留多少 cache。

§ 9 — 最脆弱的假设 ​

最致命的一条是：head 的原型在整段 rollout 中稳定，因此一次分类就够。

它的脆弱点集中在 prompt 这条轴上。作者报告的三个一致率是 90.3%（自回归步）、85.8%（去噪步）、79.8%（prompt）。前两条对本方法足够，因为一次 rollout 内自回归步与去噪步都会变；但 prompt 轴的 79.8% 意味着大约五分之一的头在换了文本条件之后会换类别。在单 prompt 的短视频生成里这不构成问题（分类就是在那条 prompt 下做的），但它恰好击中本文最重要的应用场景之一：LongLive 的卖点正是 rollout 中途切换 prompt 做长视频叙事，而 HeadCast 在整段 rollout 中沿用最初那次分类。

论文的数据也在这个方向上给出了不利信号：LongLive 是四个骨干里唯一一个 HeadCast 的 VBench Total 掉到基线以下的（82.12 对 82.26）、也是 Dynamic Degree 塌得最厉害的（29.84 对 35.59），同时它又是唯一一个 30 秒长上下文骨干。这两个混淆因素（prompt 切换与长上下文）在现有实验里没有被分开。

更进一步，这三个一致率度量的是类别是否相同，不是误分类的质量代价。一个从 Global 被误判成 Dummy 的头，与一个从 Sink 被误判成 Dummy 的头，代价差了一个数量级。论文缺的证据只有一条，而且很便宜：在 prompt 切换点强制重新分类（成本已知，30 秒片段上低于 1.5%），比较 PSNR 与 Dynamic Degree。若重分类把 LongLive 的 Total 拉回基线之上，那么「一次性」就该被改成「按 prompt 边界触发」。

§ 10 — 最小复现实验 ​

一周内可完成，不需要写 Spatial 的 FlashAttention 内核。

  • 实现范围：只实现分类器与 Sink / Dummy / Global 三条通路（Spatial 头暂时按 Global 处理）。这样跑不出加速，但可以完整测保真度，工作量约两天。
  • 骨干与数据：Self-Forcing 官方权重 5 秒 480P（便宜），以及 LongLive 30 秒（关键设定）。VBench 标准 prompt 子集 100 条，5 个种子。
  • 三组对照：(a) 论文的一次性分类；(b) 每个自回归步重新分类（上界）；(c) 随机分派——保持 Table 5 给出的类别配额（Sink 29 / Dummy 136 / Spatial 84 / Global 110）不变，但随机决定哪个头进哪一类。
  • 判据：若 (c) 与 (a) 的 PSNR 差距小于 1 dB（即 Table 4 暴露出的噪声底），则「head 身份」不是关键，起作用的只是各类的预算配比；若 (c) 明显崩坏，则分类判据得到独立支持。
  • 可直接引用的先例：Head Forcing 的表 5 已经做过同类随机分派对照（随机分配几乎回落到基线），结论支持 head 身份重要。但它的分类判据是 post-softmax 三桶占比，与本文的「受限上下文输出余弦相似度」不同，因此结论不能直接迁移——这也是本实验值得单独做一遍的原因。
  • 附加半天：在 LongLive 上比较「一次性分类」与「prompt 切换时重分类」，直接回答 §9。

§ 11 — 最强反例设计 ​

最强的攻击是提出一个把「四原型分类」整个抽掉的替代解释：HeadCast 的保真优势主要来自它给多少头留了完整上下文（Global 预算），而不是来自它挑对了哪些头。

论文自己的 Table 5 恰好为这条解释提供了最直接的支持。当分类时间步从 1000 降到 250，发生的事情是 Global 头从 110.2 塌到 65.9、Dummy 从 136.3 涨到 190.8，同时 PSNR 从 25.87 单调降到 24.52。作者把这解释成「分类质量变差」，但这组实验里同时变化的还有 Global 预算本身，两者完全共线，无法归因。

干净的判别实验只需要一行：把 Global 头数固定为 110，但随机挑选是哪 110 个（其余按同样配额随机分给三类），与真分类在同一速度点上比 PSNR。若差距小于 1 dB——也就是 Table 4 里「加了 Sink+Dummy 稀疏反而使 PSNR 从 25.04 升到 25.87」所暴露的噪声底——那么整套四原型判据（三个代理、5 百分位分数、MSE 惩罚、γ=5、两个阈值）就是可以省略的，方法退化成「保留约 30% 的头走全注意力、其余按空间网格稀疏化」。

第二条攻击针对方法的定位边界。HeadCast 在每个分辨率上都比 Dummy Forcing 慢，而它主张的补偿是保真度；但保真度用的是「与自家完整注意力输出的 PSNR」——一个越激进偏离参考就越低、与绝对质量不必然相关的量，作者自己在 §5.3 就用 LongLive 的例子论证过 PSNR 低不代表质量差。这就产生了一个内部张力：同一个指标在为 HeadCast 辩护时被解释为「不代表质量」，在攻击 Dummy Forcing 时被当作质量证据。要消解它，唯一可靠的裁决者是人类偏好，而 2AFC 只做了两两比较、且完整注意力仍以 60.4% 胜出。补一组「HeadCast 对 Dummy Forcing 对完整注意力」的三方排序研究，并报告参与者规模与显著性，是判定这套折中是否真的更优的必要实验。

§ 12 — Follow-up Research Idea ​

驱动它的局限：HeadCast 把 head 原型当成一个离线判定的静态标签去发现，但它其实是模型训练过程中偶然形成的产物——没有任何机制保证这些原型是干净的、稳定的或者比例合适的。79.8% 的跨 prompt 一致率、Table 5 里随时间步剧烈变化的类别计数、以及必须靠 5 百分位加 MSE 惩罚才能挡住边界鬼影，都是「在一个没有为稀疏化设计过的模型里挖稀疏性」这件事的固有摩擦。分类开销在 5 秒片段上甚至超过了它换来的加速。

新的 framing：不要在推理时发现原型，在蒸馏时把原型烧进模型。既然少步 AR 生成器本来就要经过一次 DMD / self-forcing 蒸馏，这一步天然是给每个头指定「你以后只需要这条通路」的机会。目标从「找出每个头需要什么」变成「决定每个头应该需要什么，并训练它接受这个约束」，稀疏结构因此是被设计出来的而不是被观测到的：预算可以按硬件最优配比分配，通路可以对齐 FlashAttention 的形状，推理时零分类开销、零跨 prompt 漂移。

可借鉴的相邻工具：MoE 的 router 与负载均衡损失提供了「把 token/head 分派给固定容量专家」的成熟机制，直接对应「给每类通路分配配额」；DuoAttention 已经证明可以用可学习的 gate 在微调中判定哪些是 retrieval head，把硬判定换成可微松弛；结构化剪枝里的 ℓ0​ / Gumbel-Softmax 门控提供了在训练中逐步硬化离散选择的标准做法；而本文的余弦判据可以直接当作初始化，避免从随机分派开始。

第一个实验：在 Self-Forcing 的蒸馏阶段给每个头加一个四路 Gumbel-Softmax 门控（初始化自 HeadCast 在 t=1000 的分类结果），损失为原蒸馏目标加一项按通路成本加权的预算惩罚，训练中逐步降温到硬分派。对照三组：原始 Self-Forcing、推理时 HeadCast、以及本方案。测量四项：720P/1080P 的端到端 FPS（含任何分类开销）、VBench Total、块边界跳变、以及跨 prompt 的稳定性（同一模型在 128 条不同 prompt 上是否还需要重分类，按定义答案是「不需要」，因此这一项直接消失）。判据是能否在同等 VBench 下把 1080P 的端到端加速从 1.95× 推到 2.5× 以上——如果能，说明「稀疏结构应当被训练而不是被发现」，训练无关这一约束虽然降低了使用门槛，但也把这条路线的天花板压在了模型偶然具备的那点异质性上。
