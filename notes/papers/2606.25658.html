Towards a Dynamic and Fixed-budget Memory Bank for Efficient Streaming Video Understanding ​

项内容
arXiv2606.25658
提交日期2026-06-24
作者Baiyang Song, Yuli Lin, Qiong Wu, Tao Chen, Jun Peng, Xiao Chen, Yiyi Zhou, Rongrong Ji
分类cs.CV
一句话在线维护一组正交的语义基向量来度量每个视觉 token 的"残差新颖度"，再用"新颖度 + 时间新近度"的加权分数在固定预算的 memory bank 里做淘汰，从而免训练地把流式视频压进定额显存。

所属教程：长视频理解

本页依据 arxiv.org/html/2606.25658v1 全文与 arxiv.org/e-print/2606.25658 的 TeX 源码撰写，方法名 CausalMem 与全部数字均在正文表格中核对过。

§ 1 — 研究问题与重要性 ​

流式视频理解和离线长视频理解是两个不同的约束条件下的问题，这一点常被混为一谈。离线设定下模型可以先看完整段视频再决定压缩什么，query 通常也已知；流式设定下两者都不成立。论文在 Introduction 里给了一个具体的量级：LLaVA-OneVision 处理一段两小时视频（1 FPS）需要应付超过 700k 个 visual token。token 数随时间线性增长这件事本身还不是最难的部分，更难的是压缩决策必须在不知道未来会发生什么、也不知道用户接下来会问什么的前提下做出。

这个约束直接废掉了两类主流做法。一类是基于全局冗余度的 token pruning / merging，它要求先看到整段视频才能算出哪些 token 冗余；另一类是 query-aware 的检索式方法，它要求 query 先于压缩到达。流式场景两个前提都没有。于是问题被重新表述成：能不能在严格因果（strictly causal，只依赖已观测帧）的条件下，维护一个大小固定的视觉记忆，使得它在任意时刻被提问都能给出好答案。固定预算不只是省显存的工程诉求，它是让流式系统的计算与存储开销与视频时长解耦的唯一办法。

§ 2 — 前人工作与不足 ​

论文在 Related Work 里把已有工作分成两条线。离线视频理解这一侧包括 RAG 式的帧检索（按 vision–text 相似度挑与 query 相关的帧）和 visual token 压缩（按全局内容或 query 相关性做 pruning / merging）。作者指出前者依赖 query 提前可得，后者依赖整段视频可访问，两个假设在流式下都不成立。

流式视频理解这一侧已有若干针对性设计。ReKV、StreamMem、LiveVLM 走 KV cache 压缩路线，直接压 visual token 产生的 key–value cache 以阻止显存无界增长；FluxMem 用 FIFO 把 token 组织成短、中、长期的分层记忆；StreamingTOM 把 LLM 之前的 token 压缩与 KV cache 量化组合起来；LiveVLM 与 StreamingTOM 还引入了 query 条件下的检索。作者对这一族的批评相当具体：它们的淘汰决策主要建立在已观测 token 内部的局部冗余上，或者需要 query 引导，因此难以刻画视频流的全局语义结构。

这个批评落在一个真实的机制差异上。如果只在当前 memory bank 内部两两比相似度来判断冗余，那么当记忆里已经堆满了同一类内容时，新来的相似 token 反而会显得"不冗余"（因为它和被淘汰掉的那些没法比），判断口径会随记忆状态漂移。论文后面的 q=0 消融正是冲着这个点设计的。

§ 3 — 重建作者的思考路径 ​

抛开本文的贡献，站在 2026 年初的位置上，可以按下面的顺序推出这个方法。

第一步是承认预算必须是硬的。只要记忆容量随帧数增长，无论增长得多慢，小时级的流都会把它撑爆。所以先把"固定预算 b"写死成约束，剩下的问题就变成一个纯粹的在线淘汰问题：每来一帧，往里塞 N 个 token，然后必须扔掉同样多的。

第二步是问"扔谁"。最省事的做法是 FIFO 或滑窗，但那等于宣布远期历史全部丢失。想保留信息就得有一个不依赖未来、不依赖 query 的重要性度量。已观测流的主成分语义是唯一符合条件的东西：它可以从历史里增量估计出来，且不需要看未来。

第三步是问"主成分怎么在线维护"。对第一帧做 SVD 拿一组右奇异向量当初始基，这是标准操作；后续帧只需要看它在现有基张成的子空间上投影后的残差——残差大说明这一帧带来了基描述不了的新语义，把残差正交化（QR）后追加进基里即可。基的容量也必须封顶，于是需要一个"哪些基向量最近一直在被用"的活跃度统计来决定保留谁。

第四步是发现只用"新颖度"排序在流式设定下会出问题：最近几秒发生的事情往往和当前 query 强相关，但它未必语义新颖。所以还要显式加一个时间新近度项，并允许两者的权重按设定（流式 / 离线）切换。四步合起来，CausalMem 的形状就完全定下来了。

§ 4 — 核心 Intuition ​

判断一个 visual token 值不值得留，不该拿它和记忆里的其它 token 比，而该拿它和已观测流的主成分子空间比：投影残差大的 token 携带了子空间描述不了的新语义。这个基是在线增量维护、容量封顶的，因此度量口径不随记忆内容漂移，也不需要看未来。再叠一个时间新近度项，就同时照顾了"信息量最大化"与"最近发生的事最可能被问"这两种互相冲突的需求。

§ 5 — 具体方法与完整 Pipeline ​

输入：逐帧到达的视频流，第 t 帧编码为 Xt​∈RN×d；某个时刻异步到达的问题 Q。 输出：仅基于当前 memory bank Mt​ 生成的答案。

整条 pipeline 分两条并行维护的状态。

（一）在线语义基 Bt​∈Rqt​×d。 第 1 帧做 compact SVD X1​≈U1​Σ1​W1⊤​，取右奇异向量的前 q1​ 行作为初始基。此后每来一帧：把 Xt​ 投影回 Bt−1​ 得到重构 X^t​=Xt​Bt−1⊤​Bt−1​，残差 Rt​=Xt​−X^t​；取残差范数最大（即最不冗余）的 top-m 个 token 作为候选，把它们的残差再投影掉一次 R^t​=Rtcand​(Id​−Bt−1⊤​Bt−1​)，做 QR 分解取出正交的新基向量拼接进去。附录 B 给了归纳法证明，这套更新保持 Bt​Bt⊤​=I 行正交。基的活跃度 st,j​ 用 EMA 更新，容量超过 q 时按活跃度保留最高的 q 个。

（二）动态 memory bank Mt​。 新帧 token 先无条件塞进去得到 Mt′​=[Mt−1​,Xt​]；一旦超过预算 b，对每个 token 计算它对当前基 Bt​ 的残差范数并做 min-max 归一化得到 e~i​，再算时间新近度 τ~i​=(ti​+1)/(t+1)，最后按 fi​=(1−α)e~i​+ατ~i​ 排序保留前 b 个，其余直接丢弃。

超参（Implementation 一节给出）：预算 b 在 LLaVA-OneVision 上取 12k、在 Qwen2.5-VL 上取 6k；基容量 q=64；每帧用于更新基的候选 token 数 m=8；EMA 系数 γ=0.9；平衡系数 α 在流式基准上取 0.8，离线评测时关掉时间项。流式基准统一 0.5 fps 采样。全部实验在 NVIDIA A800 上跑。

一个具体例子：一段一小时的第一人称厨房流。开头几分钟基向量增长很快，因为灶台、水槽、冰箱都是新语义；随后长时间的重复搅拌动作里，绝大多数 token 的残差都很小，fi​ 低，会被后面的新内容顶掉，只留下少数代表性 token；当镜头转到一个此前没出现过的储藏室时，那一帧的残差骤增，对应 token 几乎全部被写入并触发基更新。整个过程中记忆始终是 12k token。

§ 6 — 核心数学推导 ​

核心是"残差范数即新颖度"这一步。设 Bt−1​ 行正交，则 Pt−1​=Bt−1⊤​Bt−1​ 是投影到基张成子空间的正交投影算子。对 token Xt,i​，

et,i​=∥Rt,i​∥2​=∥Xt,i​(Id​−Pt−1​)∥2​.

由勾股关系 ∥Xt,i​∥22​=∥Xt,i​Pt−1​∥22​+et,i2​，所以 et,i​ 恰好度量了这个 token 中无法被已观测流的主成分解释的那部分能量。这是一个只依赖历史的量，因而满足严格因果性。

保留分数把它和时间项线性混合：

fi​=(1−α)e~i​+αt+1ti​+1​,e~i​=emax​−emin​+ϵei​−emin​​.

两项都被归一到 [0,1]，所以 α 是一个干净的插值系数。α=0 退化成纯信息最大化，α=1 退化成 FIFO 式滑窗——这一点很重要，因为它意味着"滑窗"是本方法参数空间里的一个端点，而消融表 4(d) 的 "only Temporal score" 一行正是在报这个端点的分数。

基的正交性由归纳法保证：B1​ 取自右奇异向量因而正交；假设 Bt−1​ 正交，R^t​ 已被投影出子空间之外，QR 得到的 Qˉ​t​ 行正交且与 Bt−1​ 的行张成空间正交，故拼接后仍正交。正交性是必要的：否则 Pt−1​ 不再是投影算子，残差范数的几何解释失效。

§ 7 — 实验设计与结论 ​

问题一：定额记忆在流式基准上能不能超过已有流式方法。 表 1 在 LLaVA-OneVision 基座上比较，OVO-Bench real-time 平均分：baseline 62.6，VisionZip 63.7，ReKV 57.3，LiveVLM 61.6，StreamingTOM 63.6，CausalMem 65.7；StreamingBench real-time 平均分：baseline 71.1，LiveVLM 72.9，StreamingTOM 70.1，CausalMem 74.3。摘要里的 "+3.2%" 对应的是 OVO-Bench 上相对 base 模型（62.6→65.7）的差，而相对最强流式对手 StreamingTOM 只有 +2.1；StreamingBench 上相对 StreamingTOM 是 +4.2、相对 LiveVLM 是 +1.4。教程摘要里存疑的"口径含糊"在这里得到确认：头条数字的参照系是 base 模型。

问题二：严格因果的流式压缩会不会在离线任务上吃亏。 表 2 让所有流式方法都在严格因果设定下评离线基准。CausalMem 在 VideoMME 60.0、MLVU 平均 70.9、LongVideoBench 57.0、LVBench 42.1，四项平均 57.5；StreamingTOM 对应 59.9 / – / 56.4 / 40.5，平均 56.2。作者强调的是相对 StreamingTOM 在 MLVU 上 +3.0、LVBench 上 +1.6。摘要里的 "+3.0%" 对应的是 MLVU 这一项，不是四项平均。

问题三：换基座还成立吗。 表 3 把 CausalMem 挂到 Qwen2.5-VL 上：OVO-Bench 67.8、StreamingBench 76.9，对应 Qwen2.5-VL 自身的 StreamingBench 73.9；同表里 TimeChat-Online 的 OVO-Bench 是 61.4，GPT-4o 是 64.5、Gemini 1.5 Pro 是 69.3。

问题四：每个部件贡献多少。 表 4 是四张小表。(a) 基容量 q：q=0（即用整个 memory bank 而非语义基来估冗余）时 StreamingBench 74.0 / OVO 65.3 / MLVU 68.9，q=64 时 74.3 / 65.7 / 70.9，q=512 反而降到 73.7 / 65.2 / 70.1。流式基准上去掉语义基几乎没有损失（74.0 vs 74.3），真正掉的是离线的 MLVU（-2.0）。(d) 保留分数：只用冗余分数时 MLVU 只有 60.2，只用时间分数时 StreamingBench 掉到 71.8，两者都用是 74.3 / 65.7 / 71.1。这两张表合起来讲了一个很清楚的故事——时间项撑起流式分数，冗余项撑起离线分数。

效率：图 3 报告 30 分钟视频 1 FPS 逐帧处理下的峰值显存与首 token 时延，CausalMem 两项都最低且随帧数增长最慢。硬件写明是 A800，这一点比很多同类工作规范。

§ 8 — Take-aways ​

5 句版：流式压缩的难点是压缩决策必须在不知未来、不知 query 的条件下做出，这废掉了全局冗余与 query 引导两类主流方法。CausalMem 用一组在线维护、容量封顶、行正交的语义基，把"新颖度"定义成 token 对该子空间的投影残差，得到一个严格因果且口径稳定的重要性度量。固定预算的淘汰由"新颖度 + 时间新近度"的线性混合驱动，α 的两个端点分别退化成纯信息最大化与滑窗。消融显示时间项负责流式分数、冗余项负责离线分数，去掉语义基在流式基准上几乎无损而在 MLVU 上掉 2.0 点。方法免训练、在两个基座上都成立，但头条的 +3.2 / +3.0 参照的是 base 模型或单个数据集，不是相对最强流式基线的平均增益。

3 句版：把 token 重要性定义成对在线语义基的投影残差，可以在严格因果下得到不随记忆内容漂移的冗余度量。配上时间新近度做定额淘汰，在 LLaVA-OneVision 上把 OVO-Bench 从 62.6 提到 65.7、StreamingBench 从 71.1 提到 74.3。语义基的收益主要体现在离线基准，流式基准上时间项才是主力。

1 句版：流式视频的记忆淘汰应该按"对已观测主成分子空间的残差"打分，而不是按记忆内部的两两相似度。

§ 9 — 最脆弱的假设 ​

最要命的一条是：主成分残差大 = 该 token 对未来任意问题更有价值。整个方法的重要性度量完全建立在这个等价上，但它是一个未经验证的替代目标。残差大的 token 也可能是噪声、运动模糊、镜头切换瞬间的过渡帧、字幕滚动、光照突变——这些恰恰是"语义上无法被历史主成分解释"却对问答毫无用处的内容。反过来，一个反复出现的关键人物在基已经学会它之后残差会持续走低，被系统判为高冗余，正好是流式问答最常问的对象。

论文为这条假设提供的证据是间接的。表 4(a) 显示去掉语义基后 MLVU 掉 2.0 点，这说明残差度量比"整库两两比"要好，但它没有说明残差度量比一个均匀采样的定额基线好——因为表 1 与表 2 里根本没有这个对照。表 4(d) 的 "only Temporal score" 是最接近的一行，它等价于纯滑窗（保留最近的 b 个 token），在 StreamingBench 上 71.8、MLVU 上 70.9；而完整方法是 74.3 / 71.1。也就是说在 MLVU 上，纯时间基线与完整方法只差 0.2 点。这属于缺失证据而非反证：论文没有给出"按时间均匀铺满预算"这个更强的平凡基线的分数。

另有一处需要指明：摘要与 Introduction 里 "20× 视觉 token 压缩比 / 约 82 MB 存储" 这组数字，我在 v1 全文的任何表格与图中都没有找到对应的测量条目（TeX 源码里也只在 abstract 与 intro 出现）。它可以由 12k token 预算与特征维度直接算出来，属于口径推导而非实测报告，读者不宜把它当成一条被验证过的实验结论。

§ 10 — 最小复现实验 ​

不需要复现全部基准，一周内可以做完下面这组对照，目标是把"语义基残差是否真的优于平凡的定额基线"这件事单独测出来。

  1. 取 LLaVA-OneVision 与 MLVU 的一个子集（例如 200 条 Multi-detail 与 Holistic 题），固定预算 $b=12$k、采样 0.5 fps，严格因果地喂帧。
  2. 实现四个变体，只改淘汰策略，其余完全一致：(a) 本文完整的 fi​；(b) α=1，即纯时间滑窗（对应表 4(d) 的 only Temporal）；(c) 均匀时间采样——把预算平均分配到已观测的所有帧上，每帧只保留固定数量的 token，新帧到达时对全体做重采样；(d) 随机淘汰——每次超预算时等概率丢弃。
  3. 测量：MLVU 准确率、峰值显存、首 token 时延；同时记录每个变体保留下来的 token 的帧覆盖分布（有多少帧至少留下 1 个 token）。
  4. 判据：若 (a) 显著高于 (c) 与 (d)，则残差度量的价值成立；若 (a) 与 (c) 差距在噪声内，则本文相对已有方法的增益更可能来自"定额 + 因果处理更多帧"这个框架本身，而不是语义基。变体 (c) 的帧覆盖分布还能直接回答一个诊断问题：CausalMem 是不是在偷偷退化成"只保留少数几帧的全部 token"。

§ 11 — 最强反例设计 ​

最强的攻击针对表 1 的对照口径。CausalMem 在 0.5 fps 下处理整段视频，而表 1 里的 LLaVA-OneVision baseline 一行写的是 Frames = 32。一段 10 分钟的视频在 0.5 fps 下是 300 帧，比 32 帧多了近一个数量级的视觉证据。也就是说 62.6 → 65.7 这个 +3.1 的差里，混杂了"看到更多帧"与"淘汰策略更好"两个完全不同的原因，论文没有把它们分开。构造反例的方法很直接：让 baseline 也在 0.5 fps 下均匀采样到同样的 12k token 预算再评一次。如果这条均匀采样基线就能拿到 65 附近，那么表 1 的头条增益就被"帧率"而非"记忆机制"解释掉了。这是视频理解领域反复出现的混淆，而本文缺的正是这个对照。

第二重攻击针对残差度量本身，可以做成一个可预测的失败构造。取一批视频，在中段插入 5–10 秒的强噪声片段（快速闪光、剧烈抖动、滚动字幕），这些片段的 token 对任何历史基都会产生极大残差，按 fi​ 排序必然优先占据预算；同时把问答的关键证据放在噪声片段之前的一段平稳画面里（它对已建立的基残差很低）。预测：CausalMem 在这批数据上的准确率会低于纯时间滑窗，因为滑窗至少不会主动把预算让给噪声。若该预测成立，则"残差 = 信息量"的等价在有噪声的真实流上不成立，而真实的第一人称流恰恰充满这类事件。

第三重是关于 q 的：表 4(a) 显示 q=512 比 q=64 更差。作者把它解释为"过大的基会吸收噪声"。但同一张表里 q=0 在流式基准上只掉 0.3。把 q=0、64、512 三点连起来看，语义基的收益窗口相当窄，且论文没有报告在不同视频长度下 q=64 是否仍是最优——一小时的流与五分钟的流，其主成分数目不该一样。

§ 12 — Follow-up Research Idea ​

驱动局限：本文的重要性度量是无监督且与任务无关的——残差范数不知道下游会被问什么。它之所以必须如此，是因为流式设定禁止 query 引导。但"不知道具体 query"不等于"对 query 分布一无所知"：任何一个流式基准的问题类型分布（OVO-Bench 的 OCR / ACR / ATR / STU / FPD / OJR 六类）都是可以离线统计的先验。

新 framing：把定额记忆的淘汰当成一个离线学出来的、在线执行的策略，而不是手工设计的打分函数。具体地，用离线数据训练一个轻量的写入策略 π(keep∣token,Bt​,t)，它的监督信号来自"事后回看"：对训练视频枚举其全部标注问题，用一个可以看到未来的 oracle 计算每个 token 对最终答对的边际贡献，把这个贡献作为标签蒸馏给只看历史的在线策略。这在结构上就是 imitation learning 里的 DAgger / privileged-teacher 范式，相邻领域（自动驾驶的 privileged distillation、机器人的 asymmetric actor-critic）有成熟工具可借。

第一个实验：不必训完整策略。先做 oracle 上界——在 MLVU 上允许淘汰器看到 query 与未来帧，用同样的 12k 预算贪心选 token，看准确率能到多少。如果 oracle 上界只比 CausalMem 高 1–2 点，说明手工分数已经接近这个预算下的信息论极限，后续投入应该转向增大有效预算（例如让 token 可合并而非只能丢弃）；如果高出 8–10 点，则说明"因果 + 无监督"这条路上还有很大空间，值得把策略学出来。这个实验一周内可做，且无论结果如何都能给整条记忆压缩线定一个明确的天花板。
