LearniBridge: Learnable Calibration of Feature Caching for Diffusion Models Acceleration ​

项内容
arXiv2606.26778
提交日期2026-06-25
作者Xuyue Huang, Zhe Chen, Wang Shen, Xiao-Ping Zhang
分类cs.CV, cs.LG
一句话跳步时不再用历史特征外推，而是把缓存下来的「最后一个 block 的输入」喂进一个用 3–5 条 prompt 训出来的 LoRA 增强末层，直接学出被跳过时间步的完整输出。

所属教程：加速与蒸馏

§ 1 — 研究问题与重要性 ​

特征缓存是扩散加速里最实用的一条路：不改模型、不重训、跨架构通用，靠复用相邻时间步的中间表示省掉计算。但它有一个共同的结构性弱点——所有方法都只用历史特征。DeepCache、FORA 直接复用；TeaCache 用输入差异预测输出变化；TaylorSeer 用多步历史做 Taylor 展开外推。历史外推的问题在高加速比下暴露得很彻底：缓存间隔一拉长，外推误差沿去噪轨迹累积，画面出现内容漂移、模糊、色彩异常。而 TaylorSeer 还额外要求特征轨迹是光滑可高阶微分的，这个假设并不总成立。

作者提出的问题很干净：这些缓存误差里是否存在可被学习的结构？ 如果「从缓存特征到真实特征」的修正量本身有低维结构，而且这个结构跨 prompt 一致，那么就可以用极少的样本离线学出一个校准器，把「外推」换成「学习到的映射」。这件事重要，是因为它把特征缓存从一个纯启发式的近似，变成了一个有明确训练目标的回归问题——而这恰恰是过去两年这条线上一直缺的东西。

§ 2 — 前人工作与不足 ​

DeepCache 面向 U-Net，跨多步复用特征；FORA 把模块级输出缓存搬到 DiT；DiTFastAttn 通过在空间、时间与条件分支上共享注意力输出降本；ToCa 引入动态特征更新缓解「特征老化」。这些方法的共同点是把复用当作零阶近似。

TeaCache 用一个标定过的多项式估计器，从输入差异预测输出变化，据此决定何时刷新缓存——它改进的是缓存调度，不是缓存内容。TaylorSeer 把范式从「复制」推进到「预测」，用 Taylor 级数外推，在长跳步下明显改善质量，是本文最主要的对手。EasyCache 是另一条基于误差阈值的自适应路线。

作者对这条线的判断是：为了实现简单，所有人都停在「用历史特征」这一步，而在高加速比下这必然导致误差累积。这个判断在实验里得到印证——表 3 显示在 WAN 2.1-1.3B 上，现有方法基本被限制在 3× 左右且质量退化明显（EasyCache 3.27× 时 PSNR 13.77，TaylorSeer 3.46× 时 14.84）。

§ 3 — 重建作者的思考路径 ​

如果把缓存误差当成一个需要修正的量，第一个问题就是「这个修正长什么样」。最省事的形式化是把它写成线性映射：对每个样本 i，定义跨时间步残差 et→t−k,il​=fl(xt−k,il​)−fl(xt,il​)，把 N 个样本堆成矩阵 E 与 X，寻找 ΔWl 使 E≈ΔWlX，最小二乘解是 ΔWl=EX†。

有了闭式解，自然的下一步是看它的谱。作者用 100 条 prompt 聚合出 Xtl​ 做 SVD，发现奇异值快速衰减——输入本身就是低秩的。既然 rank(ΔWl)≤rank(X†)=rank(X)，最优修正也必然低秩。低秩 + 无需改动骨干，答案几乎是被写在脸上的：LoRA。

第二个问题是「这个修正是不是每条 prompt 都要重学」。作者把 100 条 prompt 随机分成 20 个不相交的组，各自算出 ΔWl 并比较主子空间之间的夹角，发现夹角一致地小。于是结论是修正方向具有 prompt 无关的普适模式，可以用极少样本训一次到处用。

最后一个工程判断决定了收益上限：LoRA 加在哪里。如果加在每个 block 上，跳步时仍然要跑完整网络，省不下计算。作者的选择是只在最后一个 block 上加 LoRA，跳步时只执行这一个 block——缓存的是末层的输入，前面所有 block 全部跳过。这一步把「修正误差」和「跳过计算」合成了同一件事。

§ 4 — 核心 Intuition ​

缓存特征与真实特征之间的差距不是随机噪声，而是落在一个低维、且跨 prompt 共享的子空间里。既然如此，就没必要在推理时用历史去外推——可以离线用几条样本把这个修正方向学成一组低秩权重，推理时把缓存的末层输入喂进 LoRA 增强的末层，直接「跳」到被省略时间步的输出上。历史外推是在猜，学到的校准是在查。

§ 5 — 具体方法与完整 Pipeline ​

以 FLUX.1-dev、每 N=5 步做一次全计算为例。

训练阶段（离线，一次）：

  1. 预校准前向：取 3–5 条 prompt，跑完整的扩散轨迹，全部时间步都做全计算。对每个全计算步 t，记录最后一个 Transformer block 的输入 xtL​；对将在推理时被校准的时间步 t−k，记录其全计算输出 FL(xt−kL​)。
  2. LoRA 微调：冻结全部基础权重，只在末层 gL​ 的全部线性层上加低秩更新 ΔWQL​,ΔWKL​,ΔWVL​,ΔWOL​,ΔW1L​,ΔW2L​，最小化

LLearniBridge​=i∑​​F^L(xt,iL​)−FL(xt−k,iL​)​22​.

即：用时间步 t 的缓存输入，配上 LoRA，去逼近时间步 t−k 的全计算输出。

推理阶段：每 N 步做一次全计算并缓存 xtL​。对目标步 t−k，跳过 g1​,…,gL−1​，直接把缓存的 xtL​ 送进 LoRA 增强的末层得到 F^L(xtL​)。由于跳步时只跑一个 block，理论 FLOPs 约为 N1​+NN−1​⋅L1​，这解释了为什么 N=5 就能拿到约 4.4× 的 FLOPs 加速。

关键设计取舍是 LoRA 只加在末层：既最小化可训练参数与显存，又保证跳步时不需要执行任何额外模块，因此推理开销可忽略、可插拔。

§ 6 — 核心数学推导 ​

低秩论证及其边界。作者的链条是：ΔWl=Et→t−kl​(Xtl​)†，代入 X=UΣV⊤ 得 ΔWl=EVΣ+U⊤，于是

rank(ΔWl)≤rank((Xtl​)†)=rank(Xtl​)≤r.

这个不等式本身没有错，但它的证明力比论文暗示的弱得多。ΔW=EX† 是最小范数最小二乘解，其行空间被构造性地限制在 X 的主子空间内——也就是说，「解低秩」是伪逆这个求解方式的直接后果，而不是「真实需要的修正低秩」的证据。对于一个行空间之外的新输入（即测试时的 x 有分量落在校准集的零空间里），这个 ΔW 给出的修正恒为零。因此 (11) 式只能说明「在校准集张成的子空间内，低秩修正足够」，不能说明「低秩修正对新 prompt 足够」。

prompt 不变性的循环性。第二个实验把 100 条 prompt 分 20 组，各算 ΔWl 并比较主子空间夹角，得到「夹角一致地小」。但由上式，每个 ΔW 的行空间恰是对应 X 的主奇异向量张成的空间。而图 1 已经表明聚合的 Xtl​ 是低秩的——若各组的 X 共享同一个主输入子空间（这正是图 1 的含义），则各组 ΔW 的行空间在数学上必然接近。可以推断：第二个实验的结论在很大程度上被第一个实验蕴含，它验证的是「输入分布的主子空间跨 prompt 稳定」，而不是独立地验证「修正方向跨 prompt 稳定」。要给出独立证据，需要检查 ΔW 的列空间（输出侧）或直接做跨组的迁移测试（用 A 组学的 ΔW 去修正 B 组）。

线性分析与非线性实现的落差。以上全部推导针对单个线性层的残差 e=f(xt−k​)−f(xt​)。而实际实现是把 LoRA 装进整个末层 block（自注意力 + 交叉注意力 + MLP，含 softmax 与非线性激活），学习的是从 xtL​ 到 FL(xt−kL​) 的映射——一个非线性算子。低秩分析并不直接转移到这个设定，论文也未做形式化衔接。

§ 7 — 实验设计与结论 ​

设置：FLUX.1-dev（DrawBench 200 张图，ImageReward + CLIP），HunyuanVideo 与 WAN 2.1-1.3B（946 条 prompt × 5 样本 = 4730 条视频，VBench），另用 PSNR/SSIM/LPIPS 度量与原始输出的保真度。全部在 Ascend 910B 上生成。

问题一：图像生成上如何？ 表 1。N=5 档（4.36×）：IR 0.9590 / CLIP 0.8128 / PSNR 30.1525 / SSIM 0.7879，对比 TaylorSeer N=5,O=2（4.41×）的 0.9359 / 0.8164 / 29.8558 / 0.7625。IR 与重建指标全面领先，但 CLIP 一项 TaylorSeer 的 0.8164 更高，而正文写作「outperforms ToCa, TaylorSeer」。N=6 档（4.87×）：CLIP 0.8364，是全表最高——也高于未加速的原始模型 0.8102。一个加速方法在文本对齐上超过它逼近的目标，最合理的解读是 LoRA 校准改变了输出分布而非更忠实地近似它（或 CLIP 在该量级上区分度不足），这一点论文未讨论。N=8 档（6.17×）：IR 0.8308，高于 TaylorSeer N=8 的 0.8212。

这里有一组必须指出的编号不一致：摘要与结论声称在 FLUX 上达到 5.87×、在 HunyuanVideo 上达到 5.75×，但表 1 中 LearniBridge 的三行加速比是 4.36×/4.87×/6.17×，表 2 中是 3.75×/4.93×/6.15×，均不含 5.87× 与 5.75×；其中 5.87× 恰好是同表 ToCa（N=12）的加速比。正文另有两处对不上表：写「At a 4.98× speedup」而对应行是 4.87×，写「Even under aggressive acceleration at 5.87×…highest IR (0.8308)」而 0.8308 位于 6.17× 那一行。只有 WAN 2.1 的 4.10× 与表 3 一致。

问题二：视频生成上如何？ 表 2（HunyuanVideo，原始 VBench 80.93）：N=4（3.75×）VBench 80.84、PSNR 20.55、SSIM 0.7508、LPIPS 0.2314，优于同档 TaylorSeer（80.74 / 19.47 / 0.6686 / 0.3096）与 TeaCache。N=7（6.15×）VBench 79.51 > TaylorSeer N=7 的 79.14。但 N=5 档存在反例：LearniBridge VBench 79.93 低于 TaylorSeer N=5,O=1 的 80.13（后者 4.65× vs 前者 4.93×），而正文写「consistently maintains higher VBench scores…than TaylorSeer」。该档的 PSNR/SSIM/LPIPS 仍全面领先（18.80 / 0.7396 / 0.2349 vs 18.28 / 0.6121 / 0.3722）。

表 3（WAN 2.1-1.3B，原始 VBench 81.52）是全文最有说服力的一组：N=4（3.49×）VBench 81.21、PSNR 21.26、SSIM 0.8240、LPIPS 0.1824，相对 TeaCache δ=0.2（3.57×）的 80.04 / 18.24 / 0.6804 / 0.3002 是全面且大幅的领先；N=5（4.10×）VBench 80.51，比 TeaCache δ=0.3（3.98×）的 79.23 高 1.28——这正是摘要里那个「+1.28% VBench」的来源，可以核验。TaylorSeer 在 WAN 2.1 上表现很差（79.17 / PSNR 14.84），说明其高阶外推假设在该骨干上失效。

问题三：秩取多少？ 图 7(a)：PSNR 随 rank 上升在 r=64 处达峰。正文说超过后「收益递减」，而图注写「先升后降」，两处措辞不一致。

问题四：哪些线性层重要？ 图 7(b)：去掉 Wq​,Wk​,Wv​ 的 LoRA 只带来轻微退化；去掉输出投影 Wo​ 与 FFN 的 W1​,W2​ 退化明显。作者的结论是稠密特征变换比注意力路由对校准更关键——这与 LiveEdit 在缓存位置消融中得到的「FFN 表示步间相似度低」是同一现象的两个侧面。

问题五：需要多少校准样本？ 表 5：1 条 prompt PSNR 27.79，3 条 29.11，5 条 30.16，之后基本饱和（10 条 30.07，20 条 30.23，30 条 30.08）。注意 20 条虽然 PSNR 最高（30.2297），但 SSIM 0.7679 低于 5 条的 0.7799、LPIPS 0.2746 也更差——指标之间不一致，选 5 条是合理但非严格最优。表 4 显示 prompt 长度以中等（10–15 词）最好，过短（0–5 词）明显更差。

§ 8 — Take-aways ​

五句话版：特征缓存的误差不是随机的——把「从缓存输入到真实输出」的修正写成最小二乘问题后，其解被输入矩阵的低秩结构约束，且不同 prompt 组解出的主子空间夹角很小。据此 LearniBridge 只在 DiT 的最后一个 block 上挂 LoRA，跳步时跳过其余全部 block，把缓存的末层输入直接映射到被跳过时间步的全计算输出，训练只需 3–5 条 prompt。在 WAN 2.1-1.3B 上 3.49× 时 VBench 81.21（原始 81.52）、PSNR 21.26，相对 TeaCache 的 18.24 是显著跨越；4.10× 时 VBench 比同类高 1.28。消融显示 rank=64 足够、输出投影与 FFN 的适配器比 QKV 更关键、5 条校准 prompt 后性能饱和。需要打折的地方：摘要的 5.87×/5.75× 在表中找不到对应行，N=5 档在 HunyuanVideo 上 VBench 反低于 TaylorSeer，且 N=6 档的 CLIP 反超未加速原模型。

三句话版：把「用历史外推未来特征」换成「用学到的低秩映射直接生成未来特征」，是特征缓存这条线上一次范式转换，而且实现成本低到只需几条 prompt。它的效率来源其实是「跳步时只跑一个 block」，低秩校准是让这件事在质量上可行的前提。低秩论证本身有循环性——伪逆解天然低秩，跨 prompt 子空间一致在很大程度上是输入分布低秩的推论。

一句话版：缓存误差是可学习的，把它学成末层的一组 LoRA，就能在跳步时用 1/L 的计算换回接近全计算的输出。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：用 3–5 条 prompt 学出的校准，对任意新 prompt 都有效。整套方法的实用性完全押在这个泛化假设上，而支撑它的证据链有两个薄弱环节。

第一，如 §6 所述，「prompt 无关」的验证方式与低秩结论存在循环——最小二乘解的行空间被构造性地限制在校准输入的主子空间内，因此不同组的解自然共享子空间。这不是独立证据。

第二，也是更实际的：论文从未做过跨分布的泛化测试。表 5 变的是校准 prompt 的数量，表 4 变的是长度，两者都在同一分布内。真正需要的实验是：用 5 条风景类 prompt 训练，在人物、文字渲染、复杂构图等语义显著不同的 prompt 上测试。DrawBench 本身是覆盖多种类别的困难集，而校准只用了其中 5 条，两者的分布匹配程度未被检查。

这条假设一旦失效，失效方式是可预测的：新 prompt 的末层输入若在校准集的零空间上有显著分量，LoRA 给出的修正在这些方向上恒为零，退化为朴素的特征复用。N=6 档 CLIP 反超原模型（0.8364 vs 0.8102）也可以从这个角度重新解读——推测这是 LoRA 把输出往校准样本诱导的方向系统性偏移的结果，在某些指标上恰好表现为「更好」。缺失的关键证据只需一张表：按语义类别划分的留出集上，LearniBridge 与 TaylorSeer 的 PSNR 差距是否稳定。

另外，校准是绑定到 (模型,N,采样调度) 的——换加速比就要重训，而训练成本（时间、显存、需要跑多少条完整轨迹）全文未报告。

§ 10 — 最小复现实验 ​

不需要复现完整系统，泛化性可以直接测：

  • 数据：WAN 2.1-1.3B（1.3B 单卡可跑）。构造两个 prompt 集：校准集 5 条，全部取自同一语义类别（例如自然风景）；测试集 分四个类别各 25 条（风景、人物特写、多物体交互、含文字场景）。
  • 实现：按论文做法在末层加 LoRA（rank 64，全部六个线性层），N=4，用校准集训练；同时实现两个对照——(a) 不做校准的朴素末层复用（即 LoRA 置零），(b) TaylorSeer N=4。
  • 测量：在四个测试类别上分别报告与全计算输出的 PSNR/LPIPS 及 VBench 子项；另记录每条测试样本的末层输入在校准集主子空间上的能量占比 ρ=∥PS​x∥2/∥x∥2。
  • 判据：若 PSNR 与 ρ 呈强正相关，且 ρ 低的类别上 LearniBridge 退化到接近对照 (a)，则 §9 的失效机制被证实，且 ρ 可以直接用作部署时的「该不该走校准路径」的在线判据。若四类表现一致，说明 prompt 不变性确实成立，本文的结论比其证据更强。

这个实验单卡一周内可完成，且顺带产出一个实用的运行时安全阀。

§ 11 — 最强反例设计 ​

最有力的攻击是给出替代解释：LearniBridge 的增益可能主要来自「跳步时仍然执行了最后一个完整 block」，而不是 LoRA 校准。

论证如下。TaylorSeer、TeaCache、ToCa 在跳步时是纯外推/复用，不执行任何真实计算；LearniBridge 在跳步时执行了一个真实的、带交叉注意力（因而重新读取了文本条件）的 Transformer block。这本身就是一个非平凡的计算增量，足以解释文本对齐（CLIP、VBench semantic）与结构保真的改善。论文从未做过「末层全算但不加 LoRA」的对照——这正是分离两种解释的唯一关键控制组。图 7(b) 的模块消融只是逐个去掉 LoRA 适配器，从未把全部适配器归零。

第二条攻击针对指标的方向性。表 1 中 N=6 的 CLIP 0.8364 高于原始模型 0.8102，表 2/3 中 LearniBridge 的 PSNR/SSIM/LPIPS 优势远大于 VBench 优势（WAN 上 PSNR 21.26 vs TeaCache 18.24，而 VBench 只差 1.17）。这个模式与「LoRA 学到的是一个把输出往训练目标平均方向拉的算子」相符——它会强力改善与全计算输出的逐像素相似度（正是训练目标 ∥F^−F∥22​ 所优化的），而对语义类指标的改善有限。换言之，重建指标上的领先部分是训练目标与评测指标同源的结果。要证伪，需要报告一项与 L2​ 无关的指标（人类偏好或 VBench 逐子项），并检查优势是否等比例保留。

第三条：论文的加速比在延迟与 FLOPs 两个口径下并不总一致（例如表 3 中 TaylorSeer N=4 的延迟加速 3.46× 但 FLOPs 加速只有 2.94×），而全部实验都在 Ascend 910B 上完成。跨硬件的可复现性未被检验。

§ 12 — Follow-up Research Idea ​

把「学一个固定的低秩校准」推广成「学一个以跳步距离为条件的算子」，并让它自己决定何时该刷新缓存。

驱动这个方向的局限有两条。其一，当前每个 (t,t−k) 配对共享同一组 LoRA 权重，而跳 1 步与跳 4 步需要的修正强度显然不同；换一个 N 就要重训一次，部署时无法在线调节加速比。其二，缓存刷新的时机仍然由固定间隔 N 决定，而 TeaCache/EasyCache 这条线早已证明自适应调度有明显收益——但它们的调度器无法与校准器协同，因为二者对「误差」的定义不同。

可借鉴的相邻领域工具是超网络（hypernetwork）与条件适配器：让一个极小的网络以 (k,t)（以及可选的输入统计量）为输入，直接产出 LoRA 的低秩因子 A,B。这把「每个加速比一套权重」压成一套连续参数化的算子族，训练时把不同 k 混合采样即可。更进一步，同一个超网络可以顺带输出一个预测残差范数 ∥R−R∥ 的标量估计——这个估计天然就是刷新调度的判据：预测误差超阈值就强制全计算。这样校准与调度第一次被统一在同一个学习目标下，而不是两个互不知情的模块。

第一个实验不必端到端：在 FLUX 上固定骨干，训练一个以 k∈{1,…,7} 为条件的超网络产生末层 LoRA，与「为每个 N 单独训练一套 LoRA」在相同 N 下比较 PSNR。若条件化版本在各 N 上都不劣于专用版本，则加速比就变成了一个推理时可连续调节的旋钮——这对在线服务的价值远大于再多 0.5 个 dB。
