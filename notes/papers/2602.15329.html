EventMemAgent: Hierarchical Event-Centric Memory for Online Video Understanding with Adaptive Tool Use ​

项内容
arXiv2602.15329
提交日期2026-02-17
作者Siwei Wen, Zhangcheng Wang, Xingjian Zhang, Lei Huang, Wenjun Wu
分类cs.CV
一句话用灰度直方图相关系数在线切事件、事件内蓄水池采样填满固定短期缓冲、逐事件归档进长期记忆，再用 GRPO 把「什么时候去检索记忆、什么时候调 OCR/检测」这套工具策略训进模型本身。

所属教程：长视频理解

本页依据 arxiv.org/e-print/2602.15329 取回的 LaTeX 源码（main.tex 加 section/、tables/ 共 14 个 tex 文件）撰写。

§ 1 — 研究问题与重要性 ​

在线视频理解的约束和离线长视频不一样：模型只能看到提问时刻之前的内容，视频流原则上没有终点，而 MLLM 的上下文长度是固定的。这两者直接冲突。现有做法基本都是被动的——按某种规则不断往缓冲区里塞帧或塞摘要，然后在「保住长程上下文」与「保住细粒度细节」之间做一个静态的取舍。压缩得狠了细节没了，留得多了长程记不住。

本文的立论是：这个取舍之所以看着无解，是因为它被当成了一个纯粹的表示压缩问题。如果允许模型在需要的时候主动回去取，取舍就不必在写入时一次性做完。写入时保守压缩，读取时按需下钻，代价从「信息丢失」转成「延迟与调用成本」。这个方向本身是对的，值得注意的是论文最终并没有量化后一半代价。

§ 2 — 前人工作与不足 ​

论文对比的基线分四类：闭源 MLLM（GPT-4o、Gemini 1.5 Pro）、开源离线 MLLM（Qwen3-VL、InternVL-V2、LLaVA-Video、Qwen2-VL-72B 等，通过对提问时刻之前的片段做定 fps 或均匀采样来适配在线设定）、开源在线 MLLM（Flash-VStream、Dispider、VideoLLM-online、StreamForest、TimeChat-Online）、以及在线视频 agent（StreamAgent）。

从表里能读出前人的具体缺口。在线 MLLM 那一档在需要回溯历史的任务上垮得很明显：OVO-Bench 的 Backward Tracing 平均分，Flash-VStream 只有 27.38、Dispider 36.06、LongVU-7B 35.01，其中的 Hallucination Detection 一项 Dispider 是 4.3、LongVU 是 4.84。离线大模型靠 64 帧硬采样反而更稳（Qwen2-VL-72B 56.95），但它本质上不是流式方法。已有的 agent 路线（StreamAgent 总分 49.40）则显示光有工具不够。

§ 3 — 重建作者的思考路径 ​

第一个观察来自固定长度分段的失败模式：按每 30 秒切一段，切点会落在一个连续动作的中间，把一件事劈成两半，同时又把静止不动的长镜头切成许多几乎一样的段。这两件事分别造成语义割裂和冗余。所以分段应当跟着内容走。

第二个观察是，事件内部的冗余和事件之间的冗余性质不同。一个人站着不动拍了两分钟，这两分钟属于同一个事件，但里面绝大多数帧可以扔。问题是流式场景下事件何时结束事先不知道，不能等到结束再均匀抽。蓄水池采样正是为这种「总长未知的流上做等概率采样」设计的经典算法，直接搬过来即可。

第三个观察是，被挤出短期缓冲的事件不能直接丢。要归档就得决定归档成什么：只存 caption 会丢视觉证据，存全部帧又回到原问题。折中是存首帧作视觉锚点、存 caption 作语义索引、存 embedding 作检索键。

第四个观察是，有了记忆和工具，模型未必会用。这一步把问题推向 agentic RL：只用答案对错当 reward，让模型自己学会什么时候检索、什么时候调工具。

§ 4 — 核心 Intuition ​

在无界视频流上，固定长度的记忆分段会同时犯两个错——把一个连续动作切断，又把静止片段存很多遍。让边界跟着画面内容走，再在事件内部用蓄水池采样保证等概率覆盖，短期缓冲的每一帧就都花在刀刃上。剩下的长程细节不必强行留在上下文里，交给一个可被主动调用的检索接口，由 RL 训出来的策略决定何时下钻。

§ 5 — 具体方法与完整 Pipeline ​

输入：一路视频流，统一按 1 FPS 抽帧；一个在特定时间戳提出的问题。

短期记忆（STM）：固定容量 K 帧（实现中 K=32），组织成若干语义连贯的事件 Est​={E1​,…,Em​}，其中 Em​ 是正在累积的活跃事件，总帧数约束为 ∑i​ni​≤K。

在线事件切分：对新来的帧算归一化灰度直方图 ht​，与当前事件已有帧的平均直方图 hˉm​ 求 Pearson 相关系数 ρ，ρ<δ 就判定为边界（实现中 δ=0.2）。为了防止画面剧烈抖动导致碎片化，附录补充了一条硬约束：当前事件长度超过 8 帧才允许触发切分。

事件内蓄水池采样：当前事件帧数未超 K 时全部收进 STM；若 STM 总帧数超预算，按 FIFO 把最早的事件 E1​ 整体挤出去归档。当前事件累积帧数 n 超过 K 后，第 n 帧以概率 P=K/n 被接受并随机替换缓冲区里的一帧，保证每帧入选概率相等。

长期记忆（LTM）：被挤出的事件 Ei​ 归档为四元组 Ei′​={Iifirst​,ci​,ei​,Δi​}——首帧作视觉锚点，caption 由 Qwen3-VL-4B-Instruct 生成，embedding 由 Qwen3-Embedding-0.6B 提取，另加一份 Change Log 记录相邻事件之间的状态迁移。

工具集：Memory Search 支持时间检索（按时间区间过滤）与语义检索（query embedding 与事件 embedding 的余弦相似度，只返回相似度大于 0.3 的 top-3）；另有 OCR（DeepSeek-OCR）与目标检测（Grounding DINO），可作用于 LTM 的视觉锚点或 STM 的具体帧。

Agentic RL：走 ReAct 范式的多轮 thought–action–observation 轨迹，用 GRPO 优化，reward 只看最终答案对错的 0/1。骨干是 Qwen3-VL-8B-Instruct，训练数据是 10K 条由 VideoMarathon 标注的 MovieChat 样本，G=8，KL 系数设为 0，学习率 1e-6，global batch 64，1 个 epoch，在 8 张 80G A100 上完成。STM 的图像上还叠了帧号与时间戳以增强时空感知。

一个具体例子：问「刚才屏幕上出现的那个电话号码是多少」。STM 里如果还留着那段画面，agent 直接对相应帧调 OCR；如果已经被挤出，agent 先用语义检索在 LTM 里找到对应事件，拿到首帧锚点，再对锚点调 OCR。这两条路径正是训练前后行为差异最大的地方。

§ 6 — 核心数学推导 ​

事件边界判据用 Pearson 相关系数：

ρ(hˉm​,ht​)=σhˉm​​σht​​cov(hˉm​,ht​)​,

协方差与标准差都在直方图 bin 上计算，ρ<δ 触发切分。

蓄水池采样的核心是：当事件累积帧数为 n>K 时，第 n 帧以 P=K/n 被接受。这保证任意一帧最终留在缓冲区的概率都是 K/n，因此 Em​ 始终是这条长度未知的事件流的一个无偏均匀样本。

策略优化用 GRPO，对每个 query 采一组轨迹 {τ1​,…,τG​}，优化

JGRPO​(θ)=E[G1​∑i​min(ρi​Ai​, clip(ρi​,1−ϵ,1+ϵ)Ai​)],

其中 ρi​=πθ​(τi​∣q)/πθold​​(τi​∣q)，Ai​=(ri​−mean(r))/std(r)，ri​ 是二值的答案正确性。

§ 7 — 实验设计与结论 ​

问题一：在线基准上能到什么位置？ 表 1（OVO-Bench）里 EventMemAgent 用不超过 32 帧拿到总分 60.75，高于 GPT-4o 的 59.54（64 帧）、骨干 Qwen3-VL-8B 的 55.81（64 帧）、StreamForest-7B 的 55.57、StreamAgent 的 49.40。人类是 92.81。分项上 Real-Time Visual Perception 平均 68.29、Backward Tracing 58.03、Forward Active Responding 55.92。

这里有一处正文与表格的口径不一致值得记下来：正文写「Real-Time Visual Perception 相比现有开源方法最高值高出 4.27」，而同一张表里开源方法该项最高是 Qwen3-VL-8B 的 65.52，差值是 2.77；4.27 对应的是 LLaVA-OneVision-7B 的 64.02。Backward Tracing 的 +1.08 与 Forward 的 +1.1 分别对得上 Qwen2-VL-72B 的 56.95 与 LLaVA-Video-7B 的 54.82。三个分项各自挑了不同的参照对象。

问题二：流式实时理解呢？ 表 2（StreamingBench 实时理解部分）里本文 ALL 为 77.00，StreamForest 是 77.26，也就是并非该表最高分；论文正文的措辞是「highly competitive」而不是 SOTA，这一点是诚实的。分项上 CS 87.70、ATP 85.29、OP 83.92 领先，而 Counting 只有 48.70，明显低于 StreamForest 的 54.40。

问题三：层次事件记忆本身值多少？ 表 3 是把记忆换成每 30 秒固定切分、其余组件不变：OVO-Bench 从 60.75 掉到 60.16（−0.59），StreamingBench 从 77.00 掉到 76.80（−0.20）。

问题四：工具值多少？ 表 4（OVO-Bench）：去掉目标检测总分 56.87（−3.88），去掉 OCR 总分 57.88（−2.87）。有一个反直觉的细节：去掉 OCR 后 Real-Time Visual Perception 平均反而上升 0.51（68.29 → 68.80），两种消融的主要损失都落在 Forward Active Responding（−7.32 与 −5.89）。

问题五：RL 改变了什么？ 图 5 的统计显示训练前模型的工具调用策略两极分化，超过 96% 的样本要么一次工具都不调、要么循环调用直到超出最大轮数；训练后在回溯类问题上会主动调 Memory Search，在实时感知类问题上更多调 OCR 与检测。

§ 8 — Take-aways ​

5 句话版：在线视频理解的写入侧应当按内容切事件而不是按固定时长切；事件内部用蓄水池采样能在总长未知的前提下保持无偏覆盖；被挤出的事件归档成「首帧锚点 + caption + embedding + 变更日志」，把细节留在可检索的地方而不是上下文里；只用答案对错做 reward 的 agentic RL 能把「何时检索、何时调工具」这套策略训进模型，训练前的模型在这件事上几乎是全或无；但消融显示总分的贡献主要来自工具与 RL（去掉检测掉 3.88），事件式记忆本身只值 0.59。

3 句话版：事件切分加蓄水池采样构成写入侧，工具与 RL 构成读取侧，两者拼成一个 8B 规模、≤32 帧就能超过 GPT-4o（60.75 对 59.54）的在线 agent。真正撑起增益的是可主动调用的工具与把工具用法内化的 RL。给方法命名的那个层次事件记忆，在自家消融里的贡献接近噪声。

1 句话版：把在线视频的长程—细节取舍从「写入时压缩」改成「读取时按需下钻」，并用 RL 让模型自己学会什么时候下钻。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：灰度直方图的 Pearson 相关系数能够充当语义事件边界的代理。整套记忆结构——STM 的事件划分、蓄水池采样的作用域、LTM 的归档单元、语义检索的粒度——全部建立在这一个标量判据上。它是一个纯低层视觉信号，有两类系统性失效：同一场景内活动发生变化（还是那间厨房，人从洗菜换成切菜）时直方图几乎不动，边界不会触发，两件事被压进同一个事件，蓄水池采样会把它们混采；反过来，镜头摇移、灯光切换、字幕闪烁会让直方图剧烈变化，触发假边界。论文用「事件长度需超过 8 帧」这条硬约束来压制后一类，但对前一类没有任何机制。

论文为它提供的证据是表 3：换成 30 秒固定切分后掉 0.59 / 0.20。这个证据的方向是对的，强度却很弱，而且可以被反过来解读——如果内容自适应的事件边界真的在做实质性的语义组织，那么把它替换成完全无视内容的固定切分，损失不应该只有半个点。更可能的解释是：在 K=32 帧的预算下，无论怎么分段，最终留在缓冲区里的都是对全流的一个大致均匀的覆盖，分段方式只影响边缘情况。

§ 10 — 最小复现实验 ​

不需要训练，一周内可做：

  1. 在 OVO-Bench 上跑三种输入构造，全部用未经 RL 的 Qwen3-VL-8B-Instruct、全部限制为 32 帧、全部不给工具：（a）对提问时刻之前的片段做均匀采样；（b）本文的事件切分 + 蓄水池采样；（c）随机边界切分（事件数与 b 匹配）+ 蓄水池采样。
  2. 论文给出的参照点是 Qwen3-VL-8B 在 64 帧下的 55.81，以及完整系统的 60.75。32 帧均匀采样这个最直接的对照，论文没有报告，需要自己补。
  3. 判据：如果 (a)(b)(c) 三者落在同一个区间，说明写入侧的事件结构在这个预算下不起作用，全部增益归于工具与 RL；如果 (b) 明显高于 (a) 与 (c)，则事件切分确有价值，且表 3 的 0.59 低估了它。

§ 11 — 最强反例设计 ​

第一击打平凡基线的缺失。整篇论文没有报告以下任何一个对照：把视频流打乱帧顺序后送进同一套 pipeline；只保留提问时刻之前最后 32 帧（「只看最近」基线）；完全不给画面、只给问题和选项让 Qwen3-VL-8B 作答（语言先验基线）。OVO-Bench 与 StreamingBench 都是多选题，最后一项尤其关键——如果盲跑就能拿到 45–50，那么 55.81 到 60.75 这段差距的可解释空间会大幅收窄。Backward Tracing 里的 Hallucination Detection 一项各方法分数从 4.3 到 57.53 横跨极大，本身就提示这类子任务对答题偏置极其敏感。

第二击打效率叙述的空缺。论文的核心卖点是「主动」，而主动的代价就是延迟：每次 Memory Search 要跑 embedding 检索，每次 OCR/检测要跑一个额外模型，ReAct 多轮意味着多次 LLM 前向。全文只给了训练硬件（8×80G A100）与训练超参，没有给任何一个推理延迟、每样本工具调用次数的绝对值、或每题端到端耗时，而结论里却写着「achieves competitive performance with low hardware costs」。图 5(b) 画了工具调用次数的分布但没给数值。对一个声称面向在线流式场景的系统，这是最该给而没给的数字。

第三击针对表 4 的内部矛盾：去掉 OCR 之后 Real-Time Visual Perception 反而涨了 0.51，而 OVO-Bench 的 RTVP 里恰恰包含 OCR 子任务（该子任务 75.84 → 76.51 也是涨的）。这与「专用工具对捕捉文字等细粒度细节不可或缺」的叙述直接冲突。合理的替代解释是：工具消融改变的主要是 agent 的行为分布（可用动作变少、轨迹变短），而不是感知能力本身，两项消融损失都集中在 Forward Active Responding（−7.32 / −5.89）这个与 OCR、检测都关系最弱的类别上，正好支持这个解释。

§ 12 — Follow-up Research Idea ​

驱动局限：写入侧用的是一个无参数、无语义的低层信号，读取侧却是一个经过 RL 训练的高层策略。两者之间没有任何反馈——记忆怎么切、切得好不好，从来没有被下游的答对与否影响过。

可借鉴的邻域工具：认知科学里的 event segmentation theory 给了一个可操作的替代判据：事件边界出现在预测误差尖峰处。把它和序列建模里的 surprisal 结合，边界判据就从「画面变了多少」变成「模型对下一帧的预测被推翻了多少」，这天然对「同一场景内活动切换」敏感，而对镜头摇移不敏感——因为摇移是可预测的。

第一个实验：用骨干模型自身的视觉编码器做一个轻量的下一帧特征预测头，在流上逐帧计算 surprisal，取其局部峰值作为事件边界，其余组件完全不动，在 OVO-Bench 上与直方图判据对比。同时记录两种判据切出的事件数分布。如果 surprisal 版本在 Backward Tracing（最依赖 LTM 归档质量的一档）上明显更好，而在 Real-Time Visual Perception 上持平，就说明记忆分段的价值确实集中在长程检索而不是当下感知，也就为「把分段本身也纳入 RL 优化」提供了依据：把事件边界当成 agent 的一个可学动作，用同一个答案 reward 端到端地训它。
