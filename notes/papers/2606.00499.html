OptiWorld: Optimal Control for Video World Generation under Physical Constraints ​

项内容
arXiv2606.00499
提交日期2026-05-30
作者Yu Yuan, Jianhao Yuan, Xijun Wang, Daiqing Li, Liu He, Lu Ling, Stanley H. Chan
分类cs.CV
一句话在视频生成之前插一层经典最优控制：零样本抽出 3D 语义世界状态，把安全/效率/目标约束编码成黎曼度量与标量势，求测地线式最优路径，再把这条 3D 轨迹作为 tracking 条件喂给 DaS 渲染。

所属教程：物理感知视频生成

§ 1 — 研究问题与重要性 ​

视频生成模型正在变成一种可扩展形态的世界模型：给一张首帧加一个条件，就能合成逼真的未来。但它们只会生成看上去合理的运动，不会主动去控制或优化底层动力学。论文开篇的例子很具体：把一杯水从笔记本电脑的一侧移到另一侧，从起点到终点有无数条路径，其中不少能到达目标却是不安全的（从电脑正上方越过）、不平滑的（抖动）、或低效的（绕远、无谓抬升）。现有的物理感知视频生成方法（PhyT2V、WISA、VLIPP、Force Prompting）让运动更"可信"，但没有一个在多目标下优化运动。

这个缺口重要，是因为世界模型的下游用户是机器人与仿真，而这些场景关心的从来不是"这段视频是否物理上不违法"，而是"这段轨迹是否是我应该执行的那一条"。论文的判断是：现在缺的关键拼图不是完美的视觉，而是生成之前的主动世界理解与最优规划。3D 轨迹条件的视频生成器（LeviTor、Go-with-the-Flow、DaS、ATI、Perception-as-Control、MotionCanvas、MotionV2V）渲染能力已经足够强，但它们的运动信号来自预定义输入——这正是可以被最优控制填上的位置。

§ 2 — 前人工作与不足 ​

运动可控生成（CameraCtrl、MotionCtrl、Tora、Motion Prompting、LeviTor、DaS、ATI 等）通过相机位姿、轨迹、光流等额外条件提升可控性。它们做到的是"用户说什么就画什么"，做不到的是判断用户给的运动本身是否物理上可取——控制信号是外源的预定义输入，物理一致性问题原封不动。

物理感知生成分三条路。事后仿真（PhysGaussian、PhysMotion、Phys4DGen、AutoVFX）物理正确但受限于仿真器能表达的物体类型；仿真引导生成（PhysGen、PhysGen3D、MotionCraft、PhysAnimator）同理；学到的先验与评估器（GPT4Motion、VLIPP、WISA、PhyT2V、NewtonGen、VideoJAM）适用面广但只做"合理性"约束。最接近本文的是 VLIPP，它用 GPT-4o 生成粗粒度运动轨迹去引导扩散模型——但它是在施加合理性，而不是在多个目标（安全、平滑、效率）下显式优化动力学。

传统规划的路子是手工设计代价、跑 RRT/A* 一类图搜索、再用 MPC 风格数值优化器精化。这在状态空间与规则固定的领域（导航、目标跟踪）很成熟，但视频生成的起点是开放视觉场景：规划器必须把 3D 几何与任务相关的物理约束（目标可达、安全、平滑、效率）全部从像素里抽取或推断出来。把这些信号编码成彼此独立的规则会让建模脆弱且绑定特定场景，而直接把它们当作独立惩罚项优化则会得到高度非凸的目标。

§ 3 — 重建作者的思考路径 ​

第一步是把两种世界建模范式并排看。经典最优控制是显式的：观测模型 xt​=Ooc​(yt​) 把传感器读数变成规划状态，动力学 xt+1​=f(xt​,ut​) 描述状态如何在控制下演化，然后在终端代价与运行代价下求最优控制序列。它的强项是显式决策——按明确的目标与约束选择状态；它的短板是假定规划状态与动力学已经给定。

视频生成是隐式的：VAE 编码器把像素变成 visual token，DiT 在潜空间里演化它们。它的强项是场景泛化与视觉质量；它的短板是动力学被藏在生成器内部，不以带代价和约束的函数形式暴露出来，因此缺少最优控制的决策层。

两边的强弱正好互补，于是自然的做法是在它们之间插一个显式规划层：观测模型把像素与目标变成可规划的世界状态 W，动力学模型在渲染之前优化一条轨迹 τ。

第二步是解决"怎么在开放场景里规划"。既然独立惩罚项会导致非凸，那就换一个几何视角：黎曼流形提供了一种把世界信息转成连续几何的自然方式。在物体状态 q 处放一个正定度量 G(q)，穿过不安全区域的路径在度量意义下变长，即使它在欧氏意义下很短；再叠一个标量势 V(q)，目标变成盆地、危险与低效区变成山丘。于是规划变成"在场景诱导的几何里找最短路"，目标可达、安全、效率、平滑四件事被统一在同一个场景几何中。这一步是全文最关键的转换。

第三步是承认"理解"这一层不该自己训。MoGe-2 给度量深度与点图、SAM3 给开放词表分割、Qwen2.5-VL 给任务角色推理、SpatialTrackerV2 给稠密 3D 轨迹——全部零样本，因此不需要为每个物体类别、场景类型、任务设定重训一个世界理解模型。

§ 4 — 核心 Intuition ​

一个视觉再强的生成器也修不好一条糟糕的轨迹：引导路径若穿过危险区、抖动或绕远，生成的视频就会忠实地继承这些动力学。所以问题的关键在渲染之前。把场景的几何、语义风险与任务目标全部烤进一个黎曼度量和一个标量势里，规划就退化成"在这块地形上滚下去"——不安全的地方变陡变长，目标变成低谷，测地线自动同时满足四个本来彼此冲突的约束。

§ 5 — 具体方法与完整 Pipeline ​

以论文的核心例子"把装满水的杯子移到笔记本电脑另一侧"走一遍：

Stage 1 · 理解（零样本构建 3D 世界状态）。输入首帧 y0​ 与目标 g（一个用户点击的目标点 + 一句语言指令）。先缩放到固定工作分辨率，MoGe-2 估计度量深度、稠密 3D 点图与相机内参；SAM3 细化被选物体掩码与任务相关区域掩码；Qwen2.5-VL-3B-Instruct 读图与指令，给场景元素分配语义角色——可操作物体、支撑面、障碍、安全缓冲、安全危险源、目标。所有有效掩码像素通过点图升到 3D。输出是紧凑世界状态

W={P,S,A,T}

其中 P 是度量 3D 点世界，S 是语义区域，A 是任务属性（物体角色、语义风险），T 是可选的 3D 轨迹（仅视频动力学编辑用，由 SpatialTrackerV2 提供）。关键设计是同一个物体在不同任务下角色不同：笔记本电脑对一杯水是高危区域，对一个毛绒玩具则未必——这个判断由 VLM 给出。

Stage 2 · 规划（流形上的最优控制）。把 W 转成 3D 代价场，在体素图上跑 A* 得到全局可行的种子路径，再把种子重采样为连续曲线并在流形目标下精化，最后重采样成帧级轨迹 τ⋆：

W→3D cost fields→global seed path→γ⋆→τ⋆

视频动力学编辑时，把 Eq.(11) 的自主规划结果与源视频 3D 轨迹混合成新的种子路径再精化，从而在改善动力学的同时保住原视频的真实运动线索与任务意图。

Stage 3 · 生成（3D 感知渲染）。以首帧、文本 prompt 与帧级 tracking 控制为输入，用 Diffusion as Shader（DaS）渲染，30 步去噪。论文改造了 DaS 的桥接层：控制视频由度量 3D 点而非仅 2D 位移生成——被选物体掩码内的点接受规划出的刚体平移，支撑面与背景点保持静止，然后把所有 3D 点投回每帧像素渲成稠密 tracking 视频，使控制信号同时具备相机感知与深度感知。方法是 generator-agnostic 的，任何成熟的 3D 轨迹条件 I2V 模型都可以替换 DaS。

理解与规划两阶段在单张 A100-80GB 上约 2 分钟/场景，是纯离线推理流水线。

§ 7 — 实验设计与结论 ​

基准与指标。自建 OptiBench-I2V（60 张场景图，22 张来自 DROID 真实机器人操作、38 张自采日常场景，每例含首帧、被选物体、目标点、语言指令）与 OptiBench-V2V（30 段视频，20 段 DROID + 10 段自采）。运动质量从生成视频中提取前景 3D 轨迹后计算：目标可达用 Goal err.（终点到目标的 3D 距离）与 Track dev.（首帧对齐后与源运动的平均 3D 偏离），安全用 Viol.@succ.（在到达目标的那些视频中进入不安全区的比例），平滑用 Accel. 与 Jerk（3D 轨迹的二阶与三阶差分），效率用 Path len. 与 Energy。视频质量用 VBench 的 motion smoothness、background consistency、temporal flickering。

问题一：目标条件 I2V 上，加了最优控制层有多大差别？ 对比 HunyuanVideo-1.5、Wan2.2、Cosmos-Predict2.5（Image2World）、VLIPP。Goal err. / Viol.@succ. / Accel. / Jerk / Energy 依次为：HunyuanVideo-1.5 0.548 / 0.523 / 0.0118 / 0.0197 / 0.0576；Wan2.2 0.549 / 0.523 / 0.0172 / 0.0304 / 0.0860；Cosmos-Predict2.5 0.733 / 0.286 / 0.0104 / 0.0186 / 0.0398；VLIPP 0.331 / 0.511 / 0.0099 / 0.0176 / 0.0419；OptiWorld 0.310 / 0.260 / 0.0070 / 0.0116 / 0.0126。VBench 三项 OptiWorld 也最好（0.997 / 0.982 / 0.996）。

这里有两处需要如实指出。其一，OptiWorld 相对 VLIPP 的 Goal err. 优势（0.310 vs 0.331）远小于各自的标准差（附录表 6：0.310±0.317 vs 0.331±0.316），单看这一项不足以支撑"显著更好"；真正拉开差距的是 Energy（0.0126±0.0100 vs 0.0419±0.2171）与 Jerk，而且 OptiWorld 的方差小一个量级——一致性才是它最扎实的优势。其二，Cosmos-Predict2.5 的 Goal err. 最差（0.733）却拿到第二好的 Viol.@succ.（0.286）。由于 Viol.@succ. 只在"到达目标"的样本上统计，一个很少到达目标的模型其分母很小、路径也短，因此这个指标天然被成功率混杂（这是基于指标定义的推断，论文未讨论）。

问题二：视频动力学编辑能否在保持场景身份的前提下改善运动？ 对比源视频与 Wan2.1 FLF2V。Track dev. / Accel. / Jerk / Path len. / Energy：源视频 – / 0.0124 / 0.0205 / 0.647 / 0.0269；Wan2.1 FLF2V 0.123 / 0.0157 / 0.0266 / 0.733 / 0.0387；OptiWorld 0.113 / 0.0107 / 0.0181 / 0.524 / 0.0236。OptiWorld 是唯一在全部四项运动指标上都优于源视频的方法，且 VBench 不掉。

问题三：能否做反事实生成？ 只改规划器、固定理解与生成模块：换目标点得到不同轨迹；把安全约束权重置零则产生穿过危险区的路径。论文指出这可以为同一场景生成带定量标签（目标、安全违例、能量、平滑度）的多物理版本，用于训练或评估机器人策略。

问题四：哪个组件在起作用？ 规划诊断在渲染前的轨迹上算，视频诊断在生成视频上算。w/o Man.（用更平坦的欧氏目标替代约束诱导流形）Goal err. 从 0.304 升到 0.349；w/o Safe 的 Viol. 升到 0.589；w/o Eff. 的 Energy 升到 0.27；w/o Smooth 的 Accel./Jerk/Energy 升到 3.20 / 1.26 / 0.37（完整模型 2.40 / 0.86 / 0.22）；把 3D 引导换成投影到 2D 光流并用 Go-with-the-Flow 生成，视频端 Goal err./Viol./Energy 退化到 0.361 / 0.523 / 0.0518（完整 0.310 / 0.260 / 0.0126）。注：w/o VLM 一行的数值在 HTML 版本中未渲染出来，只能引用正文结论"移除 VLM 推理主要损害运动规律性"。

一个值得注意的量：规划阶段的 Goal err. 是 0.304，渲染后的视频是 0.310——渲染器只引入了 0.006 的额外误差，说明 DaS 对输入轨迹的跟随相当忠实。这既是优点，也是 §11 反例的切入点。

§ 8 — Take-aways ​

5 句话版：OptiWorld 在视频生成之前插入一层经典最优控制，把流水线拆成理解、规划、生成三段。理解阶段全部用零样本基础模型（MoGe-2 度量几何、SAM3 分割、Qwen2.5-VL 任务角色推理、SpatialTrackerV2 3D 轨迹）构建紧凑 3D 语义世界状态，因此不需要为每类物体重训。规划阶段的核心创新是把目标可达、安全、效率三类异质约束编码成黎曼度量 G(q) 与标量势 V(q)，把"避开危险"从硬约束改写成"那条路更长"，从而把高度非凸的多目标优化转成测地线式最短路问题，并用 A* 求种子 + 连续精化求解。生成阶段用改造过的 DaS，控制信号由度量 3D 点投影得到而非 2D 位移，因此同时具备相机与深度感知。在自建的 OptiBench-I2V / V2V 上，Goal err. 0.310、Viol.@succ. 0.260、Energy 0.0126 全面优于 HunyuanVideo-1.5、Wan2.2、Cosmos-Predict2.5 与 VLIPP，且方差小一个量级；但相对 VLIPP 的 Goal err. 优势（0.310 vs 0.331）落在标准差之内，真正稳固的收益在能量与平滑性上。

3 句话版：视频生成器缺的不是视觉能力而是决策层，因为再强的渲染器也修不好一条糟糕的引导轨迹。把场景几何与 VLM 推断的语义风险统一烤进一个黎曼度量和标量势，四类冲突约束就能在单一场景几何里被同时满足，规划退化为求测地线。整套流水线全部推理时完成、零训练，代价是每场景约 2 分钟，只能离线使用。

1 句话版：先规划再渲染——把最优控制当作视频世界模型缺失的那一层。

§ 9 — 最脆弱的假设 ​

最致命的假设是：被操作物体的期望动力学可以由"单帧构建的静态度量世界中、一个刚体平移轨迹"充分描述。这个假设同时施加了四重限制。世界状态由一张图经单目 MoGe-2 估计而来；被选物体接受刚体平移（论文明确写"Points inside the selected object mask receive the planned rigid translation"）；支撑面与背景点保持静止；而机械臂/手本身不在被规划对象之内。

这意味着任何涉及旋转、铰接、形变、场景反作用的任务，规划几何都无话可说。倒水、堆叠、插孔、开抽屉——这些是机器人操作里真正困难的部分，恰好全部落在假设之外。论文的两个基准（OptiBench-I2V 60 例、OptiBench-V2V 30 例）都是"把物体从 A 移到 B"这一类平移主导任务，因此基准的设计与假设的适用范围完全重合，这个假设在论文内部无法被证伪。

第二重脆弱在于"安全"的来源。ϕhaz​ 里的语义风险权重 r(q) 完全由 Qwen2.5-VL-3B-Instruct 给出——整个安全概念的可靠性上限就是这个 3B VLM 对"什么东西怕水/怕撞"的常识判断。论文承认移除 VLM 会损害运动规律性，但没有报告 VLM 角色标注本身的准确率，也没有做 VLM 尺寸的消融。如果 r(q) 有系统性错误（比如把电源插座判为无风险），Viol.@succ. 这个指标会一起错——因为不安全集合 Sunsafe​ 的定义与规划器的 ϕhaz​ 共享同一套 VLM 标注。评测与被评测对象共享同一个可能出错的组件，这是最需要独立标注来打破的循环。

§ 10 — 最小复现实验 ​

一周内可做，不需要复现理解模块或训练任何模型：

  • 数据：取 OptiBench-I2V 的 20 个场景（论文承诺公开数据与代码）。直接使用论文提供的世界状态（3D 点图、掩码、目标点、VLM 角色标注），跳过 MoGe-2/SAM3/Qwen2.5-VL。
  • 实现三个规划器：(a) 论文的完整流形规划器；(b) 只做直线插值再用三次样条平滑（无流形、无 VLM、无 A*）；(c) 欧氏空间中的直线 + 对障碍做固定半径绕行 + 样条平滑。
  • 统一渲染：三条轨迹全部通过同一个 DaS 配置（30 步）渲成视频。
  • 测量：视频端的 Goal err.、Viol.@succ.、Accel.、Jerk、Energy，各跑 3 个随机种子。

支持论文：(a) 在 Viol.@succ. 上显著优于 (b) 与 (c)（这是唯一真正需要语义风险场的指标），且 Energy 也明显更低。反驳：(c) 这个只用几何避障 + 样条平滑的朴素基线就能拿到与 (a) 相当的 Accel./Jerk/Energy——那说明流形形式化的贡献主要在于"给了一条平滑的路"，而这件事用一条样条就能做到，黎曼度量是不必要的复杂化。论文的消融（w/o Man. 只把 Goal err. 从 0.304 抬到 0.349）其实已经暗示了这个风险：去掉流形之后退化幅度并不大。

§ 11 — 最强反例设计 ​

最有力的攻击针对评测指标与优化目标的重合。OptiWorld 的规划器显式最小化路径长度、能量、加速度与曲率；渲染器（DaS）被证明对输入轨迹跟随极其忠实（规划端 Goal err. 0.304 → 视频端 0.310，只差 0.006）。而论文报告的运动质量指标恰好就是 Accel.、Jerk、Path len.、Energy。于是"OptiWorld 更平滑更省力"这个结论，在很大程度上可以被重述为"它优化了什么，DaS 就忠实地渲染了什么"——这几乎是同义反复，与场景理解、语义风险、流形几何都没有必然关系。

反例实验：把 HunyuanVideo-1.5 与 Wan2.2 生成视频中提取的 3D 轨迹取出来，做一次纯几何的平滑（比如三次 B 样条拟合 + 端点对齐到目标点），然后把平滑后的轨迹通过同一个 DaS 渲染。预测是：这条不含任何世界理解的流水线会在 Accel./Jerk/Energy 上逼近甚至达到 OptiWorld 的水平，因为这些指标只取决于输入轨迹的几何光滑度。若成立，OptiWorld 的真实独特贡献就只剩 Viol.@succ. 这一项——而这一项又受 §9 指出的循环依赖污染。

第二个替代解释针对视频动力学编辑任务的指标结构。Track dev. 度量的是"生成轨迹与源运动的偏离"，越低越好；但该任务的目的恰恰是改进源运动、也就是要偏离它。一个什么都不做、直接复制源视频的平凡基线，Track dev. 是 0，完胜 OptiWorld 的 0.113 与 FLF2V 的 0.123。这说明 Track dev. 与任务目标方向相反，只能读作"保真度约束"而非"性能"。论文把它列为 goal reaching 类指标，容易被误读为"OptiWorld 在目标可达上更好"。

第三个攻击点是 Viol.@succ. 的分母。该指标定义为

ViolationAmongSuccess=∑i​1[successi​]∑i​1[successi​]1[∃t, pi,t​∈Sunsafe​]​

分母是成功样本数。Cosmos-Predict2.5 的 Goal err. 是全场最差的 0.733，却拿到第二好的 Viol. 0.286，这个组合与"它很少成功、成功的那几例路径也很短"完全自洽。论文报告了各方法的 Goal err. 与 Viol.，但没有报告成功率本身，因此读者无法判断各方法的分母是否可比。补一列成功数就能证实或排除这个混杂，成本极低。

§ 12 — Follow-up Research Idea ​

驱动局限：OptiWorld 的规划几何是开环且一次性的——从单帧构建世界状态、规划一条完整轨迹、然后渲染。这意味着物理约束只在规划时被考虑，渲染过程中生成器实际画出了什么、场景如何响应，都不会反馈回规划器。这也是它只能处理刚体平移的根本原因：一旦场景会反应（水晃动、物体被碰倒、支撑面变形），开环轨迹就失效了。

新 framing：把最优控制层从"生成前的一次规划"改成"与去噪过程交织的闭环反馈控制"。核心想法不是"多规划几次"，而是把黎曼度量 G 与势 V 做成时变的：在扩散采样的每若干步，从当前部分去噪的 latent 里解码出场景的即时状态（哪些物体动了、有没有接触发生），据此更新代价场，再重新求解剩余轨迹。这把生成器从"被动执行者"变成了"被观测的被控对象"，也就把整个系统从开环最优控制推进到了 MPC（model predictive control）。关键在于：此时生成器本身就是那个未知的动力学 f，而扩散过程的中间态提供了状态观测——这是一个此前没有被使用的观测通道。

可借鉴的相邻领域工具：模型预测控制提供了滚动时域重规划的成熟框架；黎曼运动策略（RMPflow、Riemannian Motion Policies）提供了在流形上做实时反应式控制的形式化（论文已引用但只用了其静态形式）；扩散模型的 training-free guidance 提供了在采样过程中注入外部目标梯度的技术手段。

第一个实验：在 OptiBench-I2V 上构造一个开环必然失败的子集——目标路径上放置一个会被碰倒的轻质物体（如立着的纸杯），任务是把主物体移过去。开环 OptiWorld 的规划器只看首帧，不知道纸杯会倒，因此会规划一条从旁边擦过的路径；渲染出来纸杯倒下之后，后续轨迹已经不再安全。闭环变体则在纸杯开始倾倒的那一帧重新求解剩余路径。可证伪的预测是：在这个子集上，开环 Viol.@succ. 会显著高于其在原基准上的 0.260，而闭环变体能把它拉回来。如果开环在这个子集上表现依然良好，说明当前的视频生成器根本不会渲染出这类场景反作用——那么"场景会响应"这件事就还不是视频世界模型的真实约束，这个负结果同样重要，因为它会把物理感知视频生成的下一个瓶颈从"规划"重新指回"生成器本身能不能画出因果链"。
