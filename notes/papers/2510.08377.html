UniVideo: Unified Understanding, Generation, and Editing for Videos ​

项内容
arXiv2510.08377
提交日期2025-10-09（本页依据 v4，2026-07-03）
作者Cong Wei, Quande Liu, Zixuan Ye, Qiulin Wang, Xintao Wang, Pengfei Wan, Kun Gai, Wenhu Chen
分类cs.CV
一句话用冻结的 Qwen2.5-VL-7B 当统一多模态嵌入器、HunyuanVideo-13B 当生成器，靠一个 MLP connector 把两者接上，再用一套自然语言指令把 T2V/I2V/多 ID 生成/视频编辑联合训练，从而在无 mask 条件下做出可组合的视频编辑。

所属教程：后训练与强化学习

§ 1 — 研究问题与重要性 ​

统一多模态模型（一个模型同时做理解、生成、编辑）在图像域已经跑通：BAGEL、OmniGen2、Qwen-Image 这一类工作证明了用一个 MLLM 解析多模态指令、再驱动一个扩散生成器是可行的。视频域没有跟上，原因不只是算力。视频编辑的主流做法要求用户提供显式 mask 来圈出要改的区域，这在产品形态上是致命的：用户想说的是"把这个人换成参考图里的人"，而不是逐帧涂一遍轮廓。同时视频侧的每个能力都被做成了独立专家模型——VACE 做参考生成、UNIC 做上下文编辑、VideoPainter 做局部重绘、StyleMaster 做风格化——彼此不共享参数，也不能组合。

UniVideo 要回答的是：把这些能力塞进一个模型、用一套指令统一调度，是会互相打架还是会互相受益。这个问题的价值在于任务组合与零样本迁移：如果统一是有效的，那么"把这个 ID 删掉同时把另一个 ID 加进来并转成油画风格"这种训练时从未出现过的复合指令，应该能直接执行；图像编辑的海量数据也应该能把编辑能力免费迁移到视频域。

§ 2 — 前人工作与不足 ​

图像域统一模型（OmniGen2、BAGEL、Qwen-Image、MetaQueries、BLIP3-o）已经确立了"MLLM 解析 + 扩散生成"的双流范式，但它们的输入输出都停在图像。论文明确说自己是把这一设计推广到视频。

视频参考生成：VACE 是当时唯一开源的、能吃多参考图做上下文视频生成的模型。论文报告的问题是它在参考图数量增多（例如 4 张）时无法准确遵循指令。商用系统 Kling 1.6、Pika 2.2 也在这条赛道上。

视频编辑专家：UNIC、AnyV2V、VideoPainter 都能做换/删/加，但全部需要显式 mask 输入来定位编辑区域。这不是实现上的偷懒，而是因为在没有 mask 的情况下，模型必须自己从指令里推断编辑范围，这需要一个真正理解指令的组件——恰好是纯 DiT 缺的那一块。

任务特化设计：论文点名两类做法——给不同任务加 task-specific bias embedding（Ye 等），或者加 context adapter 模块（Jiang 等）。这类设计让模型可用，但每加一个任务就要加一套参数，天然无法组合。UniVideo 的立场是不做任何任务特化，靠位置编码让 MMDiT 自己区分条件 latent 与噪声 latent。

§ 3 — 重建作者的思考路径 ​

2025 年中的既有知识是：MLLM 的指令理解能力很强但会在联合训练生成任务时退化；扩散生成器的视觉保真度很高但对复杂指令理解很弱；把两者拼起来的关键在于用什么接口传递信息。

第一个判断：MLLM 必须冻结。如果为了生成任务去微调 MLLM，理解能力会掉，而理解能力恰好是无 mask 编辑的前提。冻结就意味着只能训练中间的 connector 与生成器。

第二个判断：光有语义不够。MLLM 的最后一层隐状态编码的是高层语义，把它送进 MMDiT 可以指导"生成什么"，但不足以保持身份和细节——这正是编辑任务最需要的。所以必须再开一条通路：把视觉信号用 VAE 编码后直接送进 MMDiT 的生成流。双流设计由此而来。作者在消融里验证了这一判断（见 §7）。

第三个判断：既然不做 task-specific 模块，MMDiT 就得靠别的机制区分"哪些 latent 是条件、哪些是要去噪的目标"。作者的做法是把各路视觉条件用 VAE 编码、pad 成统一形状、沿时间轴拼接，再用 3D 位置编码——保持每帧的空间索引不变，只递增时间维。论文说这比 Qwen2-VL 的 MRoPE 更有效，因为 MRoPE 在每引入一个新视觉输入时会把所有轴一起偏移。

§ 4 — 核心 Intuition ​

视频编辑真正缺的不是生成能力，而是"听懂人话并知道该动哪里"的能力。把一个冻结的 MLLM 当作统一的多模态嵌入器接到视频 DiT 前面，它的隐状态就成了一种比文本更稠密、比 mask 更灵活的条件；再用一条 VAE 旁路保住像素细节，模型就能在没有 mask 的情况下自己定位编辑区域。一旦所有任务都被写成同一种"多模态指令"，任务之间的边界就消失了，训练数据也可以跨模态共享——图像编辑数据能直接给视频编辑供能。

§ 5 — 具体方法与完整 Pipeline ​

架构：MLLM 用 Qwen2.5-VL-7B，全程冻结；MMDiT 用 HunyuanVideo-T2V-13B。原始 HunyuanVideo 自带的文本编码器被移除（正文 §3.1 说"两个 text encoder"，附录 E 说"还用 CLIP 作为 text encoder"，措辞不完全一致），改由 Qwen2.5-VL 充当统一的多模态嵌入器。取 MLLM 最后一层隐状态，经一个 4 倍扩展的 MLP connector 对齐到 MMDiT 的输入空间，喂进"理解流"；同时视觉信号经 VAE 编码后喂进"生成流"保细节。附录还提到已释出的 HunyuanVideo checkpoint 是 CFG 蒸馏过的，作者丢弃了其蒸馏 embedding 以简化训练。

任务统一方式：全部用自然语言指令描述，不加任何任务标识。T2V 时文本进 MLLM、噪声视频进 MMDiT；I2V 时图 + 文进 MLLM，图 + 噪声视频进 MMDiT；多 ID 生成与上下文编辑时，多张参考图与参考视频各自过 VAE、pad 到统一形状、沿时间轴拼接后做 self-attention。

三阶段训练：

  1. Connector 对齐：只训 MLP connector，MLLM 与 MMDiT 均冻结。数据是 T2I 与 T2V 的预训练样本，外加一个图像重建任务（只把图喂进 MLLM，让 MMDiT 用 MLLM 的视觉特征把图重建出来）。这一阶段结束后模型能按文本或图像条件生成图/视频。
  2. T2I/T2V 微调：MLLM 仍冻结，训 connector + MMDiT，用小规模高质量 T2I/T2V 样本。论文说这一阶段的目标是追平"用自带文本编码器的 MMDiT 底座"的水平——也就是先把换掉文本编码器造成的损失补回来。
  3. 多任务训练：加入多 ID 到视频、上下文视频编辑（ID 交换/新增/删除/风格迁移）、图像编辑、图生视频，与前两阶段任务一起训，仍只训 connector + MMDiT。

ID 数据构造（附录 G）：沿用 ConceptMaster 的流水线。先抽关键帧，用 Qwen2.5-VL-7B 标出主要主体（提示它忽略背景），用 Grounding DINO 在首帧拿主体框，过滤掉目标面积小于画面 10% 或大于 60% 的视频，再用 SAM2 拿分割 mask。为剔除跟踪不稳的轨迹，定义"可见性一致性分数"——mask 面积超过阈值的帧数除以轨迹总帧数——低于阈值的轨迹丢弃。最后对 mask 区域做视频 inpainting，把结果组成"输入-目标"对。

Generation with thinking：用户可以在画布上画参考图与故事分镜，或者直接在输入图上画标注箭头，MLLM 把这些视觉提示解析成结构化 plan 与 dense prompt token，MMDiT 直接吃这些 token 的 embedding。与 agent 化方案的差别是不调用下游多个生成器。

§ 6 — 核心数学推导 ​

本文无形式化数学推导，跳过。论文没有给出新的损失函数或理论结果，方法层面的全部内容是架构连接方式、条件拼接方式与三阶段训练课程；唯一带一点形式味道的是 3D 位置编码的构造规则（空间索引跨帧保持、只递增时间维），论文以文字而非公式给出。

§ 7 — 实验设计与结论 ​

问题一：换掉文本编码器、接上冻结 MLLM 之后，基础生成能力有没有掉？ 在 VBench 的 946 条 GPT-enhanced prompt 上评 T2V，UniVideo 得 83.48，HunyuanVideo 底座 83.24，Wan2.1 84.70。结论是与底座持平、未超过当时最强的 T2V 专家。

问题二：统一模型的理解能力如何？ 表 1 报 MMBench 83.5、MMMU 58.6、MM-Vet 66.6。这里必须读表注：论文明确说明，UniVideo 的理解结果是用它的 MLLM 底座 Qwen2.5-VL-7B 报的（沿用 BLIP3-o 与 MetaQueries 的惯例）。也就是说这三个数字衡量的是一个冻结的现成 MLLM，不是 UniVideo 训练带来的收益。把它与 BAGEL（85.0/55.3/67.2）这种理解与生成联合训练的模型并列在同一张表里比较，读者很容易误读成"统一训练没有损伤理解"，而实际论据只是"冻结的东西当然不会变"。

问题三：上下文视频生成能不能打过专家与商用系统？ 测试集自建，共 20 个 case（单 ID 与多 ID 各半），人评由至少 3 名标注员在 {0,0.5,1} 三档上给主体一致性 SC、指令遵循 PF、整体质量 VQ，自动指标取 VBench 的 smoothness 与 aesthetics。单参考下 UniVideo 得 SC 0.88 / PF 0.93 / VQ 0.95，Kling 1.6 得 0.68 / 0.95 / 0.88，VACE 得 0.31 / 0.65 / 0.42；多参考下 UniVideo 0.81 / 0.75 / 0.85，Kling 1.6 0.73 / 0.45 / 0.95。可以看到 UniVideo 在身份一致性上优势明显，但单参考的指令遵循不如 Kling 1.6，多参考的视频质量也不如。

问题四：无 mask 编辑能不能打过要 mask 的专家？ 表 5 分四个子任务。插入：UniVideo CLIP-I 0.693 / DINO-I 0.398 / CLIP-score 0.259，Pika 2.2 为 0.692 / 0.399 / 0.253，基本打平且略胜。交换：UniVideo 0.728 / 0.427 / 0.244 对 UNIC 0.725 / 0.429 / 0.242，同样是打平。删除：UniVideo PSNR 17.980，落后 VideoPainter 的 22.987、VACE 的 20.601、AnyV2V 的 19.504 与 UNIC 的 19.171，在六个方法里排倒数第二。风格化：CSD-Score 0.228 落后 StyleMaster 的 0.306，ArtFID 37.877 也差于 UNIC 的 36.198，只在 CLIP-score 与 aesthetic 上领先。论文正文写的是"superior or competitive performance across all metrics"，这个措辞与表 5 的删除与风格化两栏并不相符，应当按表读而不是按正文读。公平地说，UniVideo 是唯一不用 mask 的方法，在删除任务上落后是可以解释的；但"across all metrics"这句话本身站不住。

问题五：多任务与双流设计各自贡献多少？ 表 6 的人评消融。单 ID 上，单任务模型 PF/SC/VQ = 0.85/0.83/0.93，UniVideo = 0.93/0.88/0.95；多 ID 上单任务 0.75/0.79/0.73，UniVideo 0.75/0.81/0.85。多任务的收益存在但不大，作者自己也强调收益主要体现在编辑任务上（受益于大规模图像编辑数据）。真正剧烈的是第二个消融：只把视觉输入喂给 MLLM、不喂 MMDiT，主体一致性从 0.88 崩到 0.32（单 ID）、从 0.81 崩到 0.23（多 ID）。这个结果直接支撑了双流设计的必要性——MLLM 的语义隐状态不足以承载身份信息。

问题六：零样本泛化。 训练数据不含自由形式视频编辑（只有 ID 删/换/加与风格化），但模型能执行"换环境""改材质"这类未见指令，作者归因为从图像编辑数据迁移；模型也能执行未训练过的任务组合（同时删一个 ID 加一个 ID、编辑叠加风格迁移）。这部分只有定性结果，没有量化。

作者自陈的局限：有时不严格遵守编辑指令、过度编辑无关区域；受底座限制难以完整保持原视频的运动；自由形式视频编辑的成功率明显低于图像编辑。

§ 8 — Take-aways ​

5 句话版：UniVideo 用冻结的 Qwen2.5-VL-7B 替换 HunyuanVideo-13B 的文本编码器，靠一个 4 倍扩展的 MLP connector 接上，形成"理解流 + 生成流"的双流架构。所有任务写成同一种自然语言指令，分三阶段训练（只训 connector 与 MMDiT），不加任何任务特化模块。在自建的 20 case 测试集上，身份一致性显著优于 VACE 与 Kling 1.6，无 mask 编辑在插入与交换上与要 mask 的专家打平，但在删除与风格化上落后。最有说服力的证据是消融：把视觉输入只给 MLLM 不给 MMDiT，主体一致性从 0.88 掉到 0.32。零样本能执行未训练过的自由形式编辑与任务组合，但这部分只有定性展示。

3 句话版：把一个冻结 MLLM 当作视频 DiT 的统一多模态嵌入器，再用 VAE 旁路保住像素细节，就能在无 mask 条件下做指令驱动的视频编辑。多任务联合训练带来的主要红利是图像编辑数据向视频域的迁移，而不是各视频任务之间的互补。理解侧的分数来自冻结底座本身，不应算作统一训练的收益。

1 句话版：用"冻结 MLLM 做条件 + VAE 旁路保身份"的双流接法，把视频生成与编辑收进一个可组合的指令模型。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：在 20 个自建 case 上、由三名标注员在三档量表上打出的分差，能代表真实的能力排序。整篇论文关于"超越或持平任务专家与商用系统"的核心结论，主要靠表 4 与表 6 的人评撑着，而这两张表共享同一个 20 样本测试集与同一套 {0,0.5,1} 打分协议。

它可能不成立的理由很直接。20 个样本、三档离散量表，单个 case 的判定翻转就能让均值移动 0.025 到 0.05；表 4 里 UniVideo 与 Kling 1.6 在多个格子上的差距正是这个量级（多参考 SC 0.81 vs 0.73 只相当于约 3 个 case 的差别）。论文既没有报告标注员间一致性，也没有报告任何置信区间或显著性检验，更没有说明 20 个 case 是如何选出来的——附录只说从一个包含卡通与真实人物、动物、常见物体的 ID 池里"挑选并精心设计 prompt"，选择过程与最终模型的开发过程是否独立，无法判断。

论文为这条假设提供的证据是：每个样本至少 3 名标注员、协议沿用 Instruct-Imagen 与 OmniGen2。这只是说明协议是常规的，不解决样本量问题。要让结论稳固，最低限度需要把测试集扩到几百个 case，并报告 bootstrap 置信区间与标注员一致性。

§ 10 — 最小复现实验 ​

不需要复现整套 20B 级系统，一周内可以验证双流设计的必要性这条最核心的因果 claim，因为它是唯一有大幅度效应量的结果。

  • 数据：用公开的图像编辑数据集（如 ImgEdit）取 2,000 条"参考图 + 指令 + 目标图"三元组，任务限定为单 ID 交换。
  • 实现：在图像域而非视频域做，把 MMDiT 换成任意开源的小型 DiT（SD3-medium 级），MLLM 换成 Qwen2.5-VL-3B 并冻结。训三个 arm：(A) 双流，视觉信号同时进 MLLM 与 DiT 的 VAE 通路；(B) 单流，视觉只进 MLLM；(C) 单流，视觉只进 VAE 通路（即传统 DiT + 文本条件）。三者训练步数、batch、学习率完全一致。
  • 测量：在 200 条留出样本上算 DINO-I（身份保持）与 CLIP-score（指令遵循）。同时对其中 50 条做人工二元判定"身份是否保住"，用来校准 DINO-I 的判定阈值并报告这个校准结果。
  • 判定标准：若 A 的 DINO-I 显著高于 B（差距量级接近论文报告的 0.88 → 0.32 那种崩塌），支持"MLLM 隐状态不承载身份"这一机制解释；若 B 只是略低，说明论文的剧烈落差可能来自训练配置（例如 B 变体训练不足）而非架构本质。若 A ≈ C，则说明 MLLM 分支在单 ID 交换这类简单指令上没有增益，其价值只在复杂/组合指令上，这会缩小论文 claim 的适用范围。

§ 11 — 最强反例设计 ​

攻击一：补上缺失的平凡基线。 表 5 的四个编辑子任务都缺一个"什么都不做"的对照。删除任务用 PSNR 对着"删掉物体后的 GT 视频"打分——如果直接把输入视频原样输出，画面里绝大多数像素都是对的，PSNR 很可能落在 20 以上，也就是超过 UniVideo 的 17.980，接近甚至超过 VACE 的 20.601。同理，smoothness 指标上"原样输出"必然接近满分（表 5 里 Kling 1.6 的 0.993、0.995、0.998 已经在暗示这个指标区分度极低）。在没有报告这条平凡基线之前，删除任务的 PSNR 排名与所有 smoothness 列都不足以支持任何结论。 这是本文实验设计上最容易被抓住的漏洞。

攻击二：把"统一"的收益归因拆开。 论文把零样本自由形式编辑归因于"统一框架"，但真正的自变量可能只是"训练数据里加了大规模图像编辑数据"。反例实验：训一个任务特化的视频编辑模型，同样混入等量图像编辑数据，其他配置不变。如果它也获得了自由形式编辑能力，那么零样本泛化的功劳属于数据而非统一架构，论文的第三条贡献就被削掉大半。

攻击三：可预测的失败条件。 论文自陈"难以完整保持原视频的运动"。据此可以构造一个高运动强度的编辑测试集——快速移动的主体、剧烈相机运动、大幅形变——预测 UniVideo 在这类输入上的运动保持会明显劣于要 mask 的专家方法（后者的 mask 天然约束了非编辑区域不动）。若成立，说明无 mask 的代价不只是删除任务的 PSNR，而是一整类真实剪辑场景不可用。

§ 12 — Follow-up Research Idea ​

驱动的局限：本文的"统一"停在任务接口层面——所有任务共用一套指令语法与一个 checkpoint，但模型内部并没有被要求给出它对指令的理解。当它过度编辑无关区域时，我们无法知道它是"没听懂指令"还是"听懂了但生成器画歪了"。这两种失败需要完全不同的修法，而当前架构不可区分。

新的 framing：把 MLLM 分支从"隐式条件提供者"改造成显式可审计的编辑计划器。让 MLLM 在生成 dense prompt token 的同时，输出一份结构化编辑契约——要改的实体、要保持不变的实体、允许改变的属性维度（外观/材质/位置/运动）——并把这份契约同时作为条件送进 MMDiT 与作为约束送给一个独立的验证器。这样"过度编辑"就从一个模糊的质量问题变成一个可测量的契约违约事件。

可借鉴的相邻工具：程序合成里的契约式设计与运行时断言检查；视频目标分割与跟踪领域的实例级一致性度量（可以直接把 SAM2 + 跟踪拿来当验证器，而这套工具作者在数据构造里已经用上了，只是没用在评测侧）。

第一个实验：只做"ID 交换"一个任务。对 300 条测试样本，用 SAM2 在输入视频与输出视频上分别跟踪所有实体，定义"未指定实体的像素改变率"作为过度编辑的量化指标；先用 100 条人工标注校准这个自动指标与人眼判断的一致性并报告出来，再比较三个 arm：无契约的 UniVideo 复现、有契约但不做验证、有契约且在采样时用验证器做拒绝重采样。若契约 + 验证能在不损失指令遵循分的前提下把过度编辑率压下去，就说明把统一模型的中间理解显式化是一条比继续堆数据更划算的路径。
