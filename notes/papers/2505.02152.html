Interleave-VLA: Enhancing Robot Manipulation with Interleaved Image-Text Instructions ​

项内容
arXiv2505.02152
提交日期2025-05-04
作者Cunxin Fan, Xiaosong Jia, Yihang Sun, Yixiao Wang, Jianglan Wei, Ziyang Gong, Xiangyu Zhao, Masayoshi Tomizuka, Xue Yang, Junchi Yan, Mingyu Ding
分类cs.RO
一句话只给 VLA 的 tokenizer 加一对图像起止符，就能让它读「把[这张图]放进[那张图]」式的图文交错指令，用视觉 grounding 替代易产生注意力幻觉的文本描述。

所属教程：通用具身智能

§ 1 — 研究问题与重要性 ​

当前的通用机器人策略几乎清一色依赖纯文本指令。作者认为这正是泛化能力受限的根源。文本在很多场景里要么歧义、要么啰嗦：用户想说"把这个形状/颜色很特别的东西拿起来"，用语言精确描述反而困难；场景里有两个形状相似的玩具（恐龙和大象）时，"toy dinosaur"这个词并不能可靠地把注意力引到正确物体上。

论文要回答的问题是：能否让 VLA 直接消费图文交错的指令，并在物理世界中输出连续动作序列。这在数字世界已经是常识——现代 VLM 都能处理任意交错的图文序列——但 VLA 侧几乎空白，作者称本文是第一个既能理解交错图文指令、又能直接生成物理世界连续动作序列的机器人学习范式。

重要性有两层。技术上，它把 VLA 的输入灵活度提升到与 VLM 同级，纯文本 VLA 变成它的一个特例。实用上，它改变了人机交互的形态：用户可以截屏、丢一张网图、甚至现场画个草图来指挥机器人，不必再用文字精确描述目标。

§ 2 — 前人工作与不足 ​

交错 VLM 侧：从处理简单图文对（CLIP、LLaVA、BLIP-2、EVA）发展到处理任意交错序列（Qwen2.5-VL、Chameleon、InternVL、Mono-InternVL、BLIP-3、LLaVA-Interleave、Flamingo、Mantis），这类模型能利用新闻、博客等天然图文混排的网络语料，展现出更好的灵活性与跨任务迁移能力。但这些成果停留在数字世界。

VLA 侧：主流方法（OpenVLA、RT-1/RT-2、π0​、Gemini Robotics）处理单张或多张观测图像配纯文本指令，少数扩展到 3D 或语音模态。作者把这一类统称为 Text-VLA 范式。

最接近的工作是 VIMA：它确实探索了交错指令，但评测局限在仿真中的高层 2D 动作空间的视觉-语言规划任务。作者的批评很精确：VIMA 没有研究交错指令的两个更根本的问题——(1) 相对纯文本指令的优势到底在哪；(2) 能否应用到涉及低层机器人动作的真实场景。造成这一空白的原因也很实际：缺少真实世界的交错数据集，也缺少能处理这种输入的策略。这解释了为什么"交错指令"这个在 NLP/CV 里早已常见的想法在机器人上一直没被认真做——不是没人想到，而是数据不存在。

§ 3 — 重建作者的思考路径 ​

先看已有的失败模式。Text-VLA 在面对未见物体时经常抓错东西，这个现象人尽皆知，但为什么？作者做的第一件事是去看注意力：在 out-of-domain 场景下计算目标物体 token 相对于 tokenized 观测的注意力分数。这暴露出三种可归纳的失败：注意力偏置（焦点落到显著的干扰物而非目标）、注意力弥散（完全没有焦点，注意力薄薄铺满整个场景，反映模型的不确定）、注意力泄漏（正确识别了目标但焦点不收敛，溢出到无关背景）。

再追问这三种失败的来源，得到两条：语境歧义与训练分布偏置。前者的例子是指令说 "toy dinosaur"，场景里有形状相似的玩具大象，纯文本模型只能任意选一个。后者的例子极其具体：Text-VLA 把红牛罐误认成可乐罐，因为罕见词 "redbull" 被 BPE 切成 "red" + "bull"，模型过度关注 "red"，注意力被拉向训练中常见的红色可乐罐。这个例子很有说服力，因为它把失败一路追溯到了 tokenization 层面，而这不是靠加数据能修好的。

一旦把病因定位为"文本作为指代方式本身的缺陷"，解法就只剩一条：直接给一张图，指代问题就消失了。剩下的全是工程问题——没有交错数据集（那就自动造一个），VLA 不支持交错输入（那就在 tokenizer 里加分隔符）。

§ 4 — 核心 Intuition ​

纯文本指令的泛化失败不是因为模型不够大，而是因为词是一种有损且有偏的指代方式：罕见词会被 BPE 切碎从而把注意力引向错误的常见概念，相似物体无法用词区分。给一张目标物体的图片，指代就从"符号匹配"变成"视觉匹配"，注意力自然锁定。而实现这一点甚至不需要动模型架构——只要让 tokenizer 知道哪段 token 是图像。

§ 5 — 具体方法与完整 Pipeline ​

问题形式化：策略 πθ​ 在每步基于状态 st​=(It​,qt​,I) 采样动作 at​∼πθ​(⋅∣st​)，其中 It​ 是当前视觉观测，qt​ 是本体感受，I=(u1​,…,uM​) 是交错指令序列。当所有 uj​ 都是文本 token 时，退化为 Text-VLA。一个具体对照是：

  • 纯文本：<obs> Place [the blue spoon near microwave] into [silver pot on towel].
  • 交错图文：<obs> Place [image1 蓝勺图] into [image2 银锅图].

三个组件：

  • 适配：只改输入处理器。给 π0​ 的 tokenizer 词表加两个特殊 token <BOI>（图像开始）与 <EOI>（图像结束），输入构造成 <BOI> <image>1 … <image>256 <EOI> <text> <BOI> <image>257 … <EOI> <text> …，每个 <image> 是视觉编码器的一个 patch embedding。VLM 骨干（PaliGemma）本身没有原生交错支持，但这样也能用。作者还把同一套适配搬到 OpenVLA 上验证模型无关性。
  • 训练：用构造的大规模交错数据集训练，不改超参数、不改 flow matching 目标。SimplerEnv 上的配置是学习率 5e-5、全局 batch 1024、约 30 epoch，输入为单帧观测（无历史）+ 交错指令 token + 1 个本体 token + 4 个动作 token，4×H100 上训约两天。
  • 推理：同时支持纯文本与交错指令，交错图片可来自机器人相机截图、网络图片、手绘草图，作者还做了一个 GUI 方便交互。

数据集构造（三步自动流水线）：先用 Qwen2.5 从语言指令中抽取关键物体——相比 SpaCy 这类规则式 NLP 工具，LLM 无需针对每种指令格式定制规则，还能概括冗长指令；再用开放词表检测器 OWLv2 根据关键词从轨迹帧中定位并裁剪目标物体，准确率 82.6%；最后对 OWLv2 失败的困难样本，用 Qwen2.5-VL 验证检测结果，必要时提供关键点交给 SAM 做更精确的分割，整体准确率提升到 95.6%。作者在附录里给出了互补性分析：QwenVL+SAM 擅长开放世界物体（如绿色星星），但在杂乱或遮挡场景中不如 OWLv2；两者单独的错误率分别为 22.1% 与 17.4%，组合后降到 4.4%。最终数据集整合 Open X-Embodiment 中 11 个子集（RT-1 占 41.01%、Bridge 28.25%、BC-Z 20.34%、Language Table 7.81% 等），21 万条 episode、1300 万帧、3500 多个物体类别，并随机混入互联网图片提升指令多样性。

§ 6 — 核心数学推导 ​

本文的形式化很轻，核心是把 VLA 的条件从"图像 + 单条文本"推广到"图像 + 任意交错序列"：

at​∼πθ​(⋅∣st​),st​=(It​, qt​, I),I=(u1​,…,uM​)

每个 uj​ 取自文本词表 Vtext​ 或图像 token 空间；当 ∀j, uj​∈Vtext​ 时即为 Text-VLA。这个推广的意义不在数学复杂度，而在它明确了 Text-VLA 是 Interleave-VLA 的一个特例，因此不存在"要不要放弃文本"的取舍。

真正承载 intuition 的是 token 序列的构造。图像 token 与文本 token 在序列中的边界由 <BOI>/<EOI> 显式标记，其余一切——注意力机制、flow matching 动作生成目标、超参数——保持不变。这解释了为什么这个方法是模型无关的：它没有对 VLM 骨干做任何架构假设，只要求骨干能接受一段更长的、带边界标记的混合 token 序列。作者进一步把 OpenVLA 的 Prismatic 骨干换成原生支持交错格式的 InternVL2.5，发现更换骨干对性能影响可忽略（表 5：Prismatic 文本输入 L1 53.71，InternVL2.5 文本输入 45.29，而交错输入 83.14），这说明增益来自输入格式而非骨干的交错预训练。

§ 7 — 实验设计与结论 ​

问题一：仿真中相对 Text-VLA 如何？ 在 SimplerEnv-Bridge（WidowX 配置，兼容 BridgeData V2）上，除 4 个 in-domain 任务外，作者新增 10 个泛化任务，分为视觉泛化（未见环境/桌布/光照）与语义泛化（已知类别的新物体、全新类别）。结果（in-domain / 视觉 / 新物体 / 新类别 / OOD 平均）：RT-1-X 为 1.1 / 0.0 / 4.0 / 6.1 / 3.4；Octo 为 17.5 / 12.6 / 10.8 / 8.4 / 10.6；π0​（Text-VLA）为 69.2 / 71.4 / 30.2 / 21.0 / 40.9；Interleave-VLA(Partial)（交错训练、纯文本测试）为 71.9 / 69.9 / 35.1 / 27.5 / 44.2；Interleave-VLA(Full) 为 71.0 / 73.4 / 55.7 / 53.0 / 60.5。三点结论：in-domain 与 Text-VLA 持平，说明交错指令没有引入理解负担；Partial 版本已优于 Text-VLA，说明交错数据的多模态性本身就缓解了过拟合；Full 版本在语义 OOD 上达到 2 倍以上提升。逐任务看差距更极端——Redbull on Plate 从 π0​ 的 0.0 到 35.0，Tape Measure in Basket 从 1.0 到 53.0。

问题二：真机上是否成立？ FANUC LRMate 200iD/7L + SMC 夹爪，Lift 与 Pick&Place 两类任务，每个物体 20 条遥操作演示，每任务 12 次试验，同时报成功率与"抓对物体"的准确率。Lift 任务上 Interleave-VLA w/ PT 的平均成功/准确为 69.4% / 98.6%，π0​ w/ PT 为 36.1% / 70.8%，Interleave-VLA w/o PT 仅 2.8% / 30.6%。Pick&Place 上三者分别为 43.3% / 68.3%、38.3% / 61.7%、11.7% / 60%。两个结论：OOD 语义泛化上 2–3 倍提升；低数据 regime 下（每任务仅 60 条演示）预训练是必需的，且预训练数据里不包含 FANUC 机械臂却仍能有效跨具身迁移。

问题三：模型无关吗？ 把同一适配搬到架构与训练目标都不同的 OpenVLA 上，在 VIMA-Bench 的四个泛化层级评测。L1/L2/L3 上 Interleave-VLA 为 83.14 / 58.14 / 64.00，OpenVLA 为 53.71 / 23.00 / 23.86，超过 2 倍，且优于 VIMA-Gato、VIMA-Flamingo、VIMA-GPT，无需任何任务特定设计。作者说明排除了依赖历史记忆的任务，因为 Interleave-VLA 与常见 VLA 一样是一阶马尔可夫设定。

问题四：零样本能处理哪些指令形式？ 直接取 SimplerEnv 评测用的模型、不做任何额外微调，测试三类训练中从未见过的指令图像：用户现场截屏裁剪、互联网图片、手绘草图。表 3 报告的成功率大多在 58%–81%、准确率多为 86%–100%。手绘草图是完全新的输入风格，这一点尤其说明模型学到的是视觉匹配而非记忆。

问题五：数据里什么因素在驱动泛化？ 两个：模态多样性与指令图像多样性。前者由 Partial vs Text-VLA 的对照证明——架构完全相同，仅训练数据模态不同，in-domain 提升 +2.5、新物体提升 +5.7。后者由表 4 的消融给出：仅用互联网图片为 59.2（in-domain）/ 69.1（OOD），仅用任务特定裁剪图为 67.5 / 67.1，混合为 71.0 / 71.7——互联网图片缺乏任务相关性拖低 in-domain，裁剪图缺乏多样性拖低 OOD，混合两者互补。

§ 8 — Take-aways ​

5 句话版：Text-VLA 的泛化失败可归因于三类注意力幻觉（偏置、弥散、泄漏），根源是语境歧义与训练分布偏置，其中 "redbull" 被切成 "red"+"bull" 导致误认可乐罐是一个可追溯到 tokenization 的清晰例证。Interleave-VLA 只在 tokenizer 中加入 <BOI>/<EOI> 分隔符，不改架构、不改训练目标，就让 π0​ 与 OpenVLA 都能消费图文交错指令。配套的自动流水线（Qwen2.5 抽取关键词 → OWLv2 检测裁剪 → Qwen2.5-VL + SAM 校验）把 Open X-Embodiment 转成 21 万 episode、1300 万帧的交错数据集，准确率从 82.6% 提到 95.6%。SimplerEnv 上 OOD 语义泛化从 π0​ 的 21.0/30.2 提升到 53.0/55.7，真机 Lift 任务成功率 69.4% 对 36.1%，VIMA-Bench 上超过 OpenVLA 2 倍。零样本即可理解手绘草图、网络图片与用户截屏，表明学到的是视觉匹配而非记忆。

3 句话版：文本是一种有损且有偏的指代方式，图片不是。让 VLA 读交错图文只需要在 tokenizer 上加两个特殊 token。真正的门槛从来不是模型，而是不存在的交错机器人数据集。

1 句话版：用"这张图"替代"这个词"，把 VLA 的泛化瓶颈从语言歧义中解放出来。

§ 9 — 最脆弱的假设 ​

最脆弱的假设是：指令图像在部署时是廉价且可得的。整个范式的收益建立在用户能提供一张目标物体的图片上——但论文的所有评测中，指令图像要么由自动流水线从同一条轨迹的帧中裁剪得到（训练与 SimplerEnv 评测），要么由人现场截屏/画草图（零样本演示）。前者意味着构造指令时已经知道目标物体在哪，这在训练数据生成中没问题，但在真实部署中恰恰是任务的一部分。

这条假设一旦不成立，方法的实用价值就大幅缩水。设想一个移动机器人被要求"去厨房把我的杯子拿来"——目标物体不在当前视野内，用户手边也没有那只杯子的照片。此时交错指令要么退化为纯文本（回到 Text-VLA），要么需要一个额外的图像检索/生成环节，而后者会重新引入本文试图消除的歧义。

论文提供的证据是正面的：零样本实验显示模型能接受互联网图片与手绘草图，这大幅降低了"必须有目标物体实拍图"的门槛，成功率 58%–81%、准确率多在 86% 以上。但这些实验中的物体都是常见品类（茄子、胡萝卜、方块、勺子），画得出草图、搜得到网图。论文没有测试指令图像本身有歧义或质量差时会怎样——例如草图画得潦草、网图与实物颜色差异大、或截屏时框歪了。可以推断这类退化会直接传导为抓错物体，因为视觉匹配是唯一的指代通道，此时不再有文本作为冗余校验；但论文未做该实验，这属于推断。此外，limitations 中承认交错输入因图像 token 序列更长而增加计算开销，这对实时控制是实打实的代价。

§ 10 — 最小复现实验 ​

一周内可做、不需要训练任何 VLA 的验证，直接测最脆弱的那条假设——指令图像质量的退化曲线。

  • 素材：取 SimplerEnv 的 9 个 OOD 任务，对每个目标物体准备五档指令图像：(a) 同轨迹裁剪（论文默认），(b) 干净网图，(c) 手绘草图，(d) 加噪/低分辨率的截屏，(e) 框歪的裁剪（只框到物体一部分或带入干扰物）。
  • 实现：直接用论文公开的评测设置与 checkpoint（若不可得，则用一个开源交错 VLM 加轻量动作头做代理），不做任何微调。
  • 测量：每档的任务成功率与"抓对物体"准确率；同时记录目标物体 token 对观测的注意力峰值位置，判断失败是"没抓住"还是"抓错了"。
  • 判定：若 (a)–(c) 三档性能接近而 (d)、(e) 显著下降，说明方法对指令图像的语义正确性鲁棒但对框选质量敏感，实际部署需要配一个指令图像质检环节；若五档都平稳，则本文的可用性比论文自己声称的还要强。这个实验完全在推理侧，无需训练。

§ 11 — 最强反例设计 ​

最有力的攻击是给出一个替代解释：Interleave-VLA 的增益可能主要来自"指令图像相当于一次免费的开放词表检测"，而不是"交错格式带来了更好的多模态表征"。换言之，一个纯文本 VLA 只要在推理前先跑一次 OWLv2 定位目标物体、把 bounding box 作为额外输入（或直接把非目标区域涂暗），可能就能拿到大部分收益，而完全不需要交错训练与更长的 token 序列。

设计一个能区分的对照：训练一个 Text-VLA 变体，输入除原文本外额外接收一个由同一套 OWLv2 流水线生成的目标物体掩码或坐标 token（即把 Interleave-VLA 数据集里已经算好的检测结果以非交错形式喂进去），其余训练配置完全相同。若这个"检测增强的 Text-VLA"在 SimplerEnv OOD 上逼近 Interleave-VLA(Full) 的 60.5，那么本文的核心 claim 应被重述为"显式视觉定位有效"，而交错格式只是承载定位信息的一种较昂贵的形式；只有当交错版本仍显著领先，才说明格式本身带来了额外的表征收益。论文的 Partial 版本（交错训练、文本测试）确实优于 Text-VLA，这为"格式有独立贡献"提供了一些支持，但 Partial 与 Full 之间的巨大差距（44.2 vs 60.5）说明主要收益仍来自测试时的图像，而这正是上述替代解释的主战场。

一类可预测失败的场景：指令中出现的是关系或属性而非可框选的实体，例如"把最靠左的那个杯子拿起来"、"选温度最高的那杯"。这类指令没有对应的物体图像可裁——图片能指"哪个物体"，但指不了"哪种关系"。可以预期在这类任务上 Interleave-VLA 相对 Text-VLA 没有优势，甚至因为交错训练稀释了纯文本能力而略差。论文的全部 OOD 任务都是"指认某个物体"，这个盲区没有被测到。

§ 12 — Follow-up Research Idea ​

驱动它的局限：Interleave-VLA 把图像用作指代，但只用于输入侧。指令图像回答的是"操作哪个物体"，回答不了"要把它变成什么样"。而大量真实任务的目标是一个状态而非一个物体：叠成什么形状、摆成什么布局、拧到什么程度。论文自己在 limitations 中也提到未来可以让 VLA 支持交错输出（文本或图像）。

新的 framing：把交错从"指代通道"升级为"可协商的任务规格通道"。不是用户单向丢一张图，而是机器人在执行前先回画一张它理解的目标状态图给用户确认——把 VLA 的输出扩展为"动作 + 一张预期终局图像"，形成一个闭环的规格澄清协议。这解决的不是泛化问题而是规格歧义问题：用户不必一次把意图说清楚，可以看着机器人的理解来纠正。同时这张回画的图像天然是一个可解释性探针——它把模型内部的目标表征外化了，比注意力图更直接。

可借鉴的相邻领域工具：交互式语义解析中的"复述确认"范式（系统把理解回述给用户确认）提供了协议设计；图像编辑扩散模型提供了从当前观测生成目标状态图的能力；VLA 侧已有工作（CoT-VLA）证明自回归生成未来视觉目标再生成动作是可行的，可以直接复用其视觉预测头。

第一个实验：不需要真机。在 SimplerEnv 上给 Interleave-VLA 加一个轻量的目标图像预测头（用现有轨迹的最后一帧作为监督），只训这个头、冻结策略主体。然后构造一批故意歧义的指令（场景里有两个相似物体、或"把它放在旁边"这类方位模糊的表述），比较三种条件下的成功率：纯执行、执行前由人看回画图确认并在需要时替换指令图像、以及执行前由一个 VLM 自动扮演用户做确认。若"确认"条件的成功率显著高于纯执行，就证明规格澄清是一条独立于表征改进的收益来源，而这在纯输入侧的交错范式里是拿不到的。
