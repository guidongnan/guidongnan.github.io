Training Agents Inside of Scalable World Models ​

项内容
arXiv2509.24527
提交日期2025-09-29
作者Danijar Hafner, Wilson Yan, Timothy Lillicrap
分类cs.AI, cs.LG, cs.RO, stat.ML
一句话把 shortcut model 的步长条件嫁接到 diffusion forcing 的逐帧噪声上、并改用 x-prediction 参数化，训出每帧只需 4 次前向的实时 Minecraft 世界模型，再在其内部用 PMPO 做想象 RL，仅凭 2541 小时离线 contractor 数据把钻石成功率做到 0.7%。

所属教程：世界模型

§ 1 — 研究问题与重要性 ​

世界模型这条路线的承诺一直很清楚：从视频里学到关于世界的通用知识，然后在模型内部"想象"出经验来训练行为，从而不必真的去环境里试错。Dreamer 系列前三代已经把这套流程跑通了，但作者在摘要里点出一个卡了很久的瓶颈——以前的世界模型无法在复杂环境里准确预测物体交互。

这个瓶颈为什么致命：如果模型预测不准"我挥镐子砸向这块石头会发生什么"，那么在想象里训出来的策略就是在幻觉上优化，放回真实环境必然失效。Minecraft 恰好是把这个问题放大的环境——它的核心玩法就是物体交互（挖、合成、放置），而不是简单的移动与躲避。

论文进一步把任务设成"只用离线数据在 Minecraft 里挖到钻石"。这个设定不是为了刷分：作者明说它对齐的是机器人这类在线交互既不安全又缓慢的应用。任务本身要求从原始像素出发选出超过 20000 步的鼠标键盘动作序列，是一个极端长时序的信用分配问题。

§ 2 — 前人工作与不足 ​

引言把前人切成两支。一支是 Dreamer 3、DayDreamer、TD-MPC2、DIAMOND、MuZero、Muesli 这类世界模型 agent：在各自的窄环境里又快又准，但论文直说它们的架构缺乏拟合复杂真实世界分布的能力。另一支是 Genie 3、PlayerOne、Matrix 这类可控视频模型，建在 diffusion transformer 与 diffusion forcing 之上，能生成多样场景并支持简单交互，但仍然难以学到物体交互与游戏机制的精确物理，而且常常需要多张 GPU 才能实时模拟一个场景。后半句很关键：想象训练要在世界模型里滚成千上万步，一个多卡才能实时的模型在这条路线上根本用不起。

Minecraft 这条线上，§4.2 与 Oasis、Lucid-v1、MineWorld 逐一并排对比，方式是让人类玩家从同一张起始帧进入各个世界模型，用鼠标键盘真去完成任务。任务集覆盖挖坑、搭墙、砍树、放船并骑上去、把视线移开再移回来、与工作台和熔炉交互。图 5 的结论写得很具体：Dreamer 4 能让玩家真的把方块按正确形状摆出来，而前人模型画面退化、手持物品被换掉、并幻觉出玩家从未搭过的结构。作者还解释了为什么不能跟 Genie 3 直接比——Genie 3 只支持相机动作加一个通用的 interact 键，而 Minecraft 需要完整的鼠标键盘动作空间。

agent 这一侧，OpenAI 的 VPT 是标准离线基线：在 270K 小时用 IDM 反标注的 YouTube 视频上做行为克隆，再在早期游戏子集上微调。Dreamer 4 只用 VPT contractor 数据集的 2541 小时，论文说的少 100 倍数据指的正是这两个数字之比。这里有一处值得记住的细节：论文自己的现代 BC 基线——直接用 contractor 的真实动作而不是 IDM 标注——就已经超过了 VPT (finetuned)。也就是说 100× 这个对比里有相当一部分来自动作标签的来源，而不只是来自想象训练。

缺口于是有两层：世界模型侧，物体交互的准确性与实时性长期不可兼得；agent 侧，纯离线条件下没有方法能走完钻石这条链。

§ 3 — 重建作者的思考路径 ​

只用本文之前的知识，链条大致是这样长出来的。

第一个约束是速度。想象训练要求在世界模型里 rollout 成千上万步，如果每一步都要跑几十次扩散去噪，训练根本跑不动。所以"少步生成"不是锦上添花，而是想象训练的前提条件。而这几年扩散加速方向已经积累了成熟工具——一致性模型、shortcut model 这类允许用极少步（甚至一步）生成的目标函数。

第二个约束是自回归。世界模型必须能一帧一帧地对动作做响应，这正是 diffusion forcing 那套给序列里每一帧独立噪声水平的框架解决的问题。两条合起来就是 shortcut forcing：把 shortcut model 的步长条件与 bootstrap 目标嫁接到 diffusion forcing 的逐帧噪声上，推理时每帧只跑 K=4 次前向。

但真正不显然的是第三步。原版 shortcut model 让网络预测速度 v=x1​−x0​（v-prediction），整块生成图像或视频时很好用；论文发现它训练网络产出高频输出，逐帧滚长视频时这些细微误差会一路累积。于是改成让网络直接预测干净表示（x-prediction），bootstrap 项先换算到 v 空间算完再缩回 x 空间。论文明确把这个参数化选择说成是能做任意长度高质量 rollout 的原因，它也是 shortcut forcing 与现成 shortcut model 的实质分歧。

第四个约束是动作标注稀缺。互联网上有海量 Minecraft 视频但没有键鼠标签。论文的做法是把动作做成一个可以缺席的模态：每个动作分量被单独编码成 Sa​ 个 token 后求和，再加上一个 learned embedding；训练无标注视频时只用那个 learned embedding。同一个 transformer 因此既能吃有标签数据也能吃无标签数据，动作条件退化成一个薄接口而不是架构前提。这与 VPT 正好相反——VPT 用 IDM 给视频反推标签。

第五，既然模型准且快，就可以把 RL 完全搬进想象里。论文把这套流程叫 imagination training，图 1 展示了想象序列被解码回像素后的画面：破坏方块、使用工具、与工作台交互都被正确模拟。

§ 4 — 核心 Intuition ​

想象训练的瓶颈从来不是"能不能生成视频"，而是"生成得又准又快"：不准则策略在幻觉上优化，不快则 rollout 成本吃掉全部算力预算。Dreamer 4 用一个新目标（shortcut forcing）加高效架构同时拿下这两点——单卡实时交互，且物体交互的因果关系是对的。一旦世界模型可信，长时序信用分配就可以整个搬进模型内部完成，真实环境一次都不用碰。

§ 5 — 具体方法与完整 Pipeline ​

整个 agent 是一个 transformer，按 Algorithm 1 分三阶段训练。以从零挖到钻石为例走一遍。

Phase 1：世界模型预训练。 先训一个 causal tokenizer 把视频压成连续表示。编码器吃图像 patch token 加 learned latent token，latent 经一次低维线性投影和 tanh 挤过瓶颈，解码器再把 patch 读出来；时间维度上是因果的，因此既能做时序压缩又能逐帧解码。目标是重建，L=LMSE​+0.2LLPIPS​，同时按 p∼U(0,0.9) 随机丢掉输入 patch 做 masked autoencoding——论文说 MAE 训练提升了动力学模型生成视频的空间一致性。tokenizer 训完冻住。

接着在 token 序列上训动力学模型。每个时间步由 Sz​ 个空间 token、Sr​ 个 register token、一个承载信号水平与步长的 token 组成，与动作 token 交错排列。Minecraft 配置是 256 个空间 token、192 帧上下文、256 的 batch 长度。目标函数是 shortcut forcing（见 §6）。为了让模型也会无中生有地画起始帧，batch 里 30% 的视频被当作独立图像处理。

架构。 时间×空间的 2D transformer，注意力在时间上因果掩码。基础件是 pre-layer RMSNorm、RoPE、SwiGLU，稳定性靠 QKNorm 与 attention logit soft capping。提速靠三招：把稠密注意力拆成 space-only 与 time-only 的轴向注意力；时间注意力每 4 层才用一次；所有注意力上 GQA 压 KV cache。整体 2B 参数——tokenizer 400M、动力学 1.6B——在 256 到 1024 张 TPU-v5p 上以每设备 batch 1 加 FSDP 训练。

Phase 2：agent 微调。 往同一个 transformer 里插入 agent token 作为新模态，输入是任务 embedding，输出经小 MLP 头给出 policy 与 reward。关键约束是单向：agent token 可以 attend 到所有模态，但没有任何模态能 attend 回 agent token。论文说这是为了避免世界模型的因果混淆——未来预测只能被动作影响，不能被当前想做什么任务影响。policy 与 reward 用长度 L=8 的 multi-token prediction 训练，reward 头沿用 Dreamer 3 的 symexp twohot 输出。键盘动作表示成 23 个二元分布，鼠标动作是 121 类 categorical（沿用 VPT 的 foveated discretization）。任务与稀疏二元奖励直接由 VPT 数据集已有的 event 标注生成，共 20 个任务。数据配比是 50% 均匀采样序列加 50% 完成了某个任务的相关序列，行为克隆损失只加在相关那一半，动力学损失只加在均匀那一半——论文给的理由是避免乐观的生成。

Phase 3：想象训练。 新建 value 头，并把 policy 头复制一份冻住当 behavioral prior。只更新 policy 与 value 头，transformer 全程冻结。 想象 rollout 从数据集的 context 出发，每个 context 只起一条（换取数据多样性并省显存），表示从 flow 头采样、动作从 policy 头采样，再用 reward 头和 value 头标注。value 头用 TD 学 λ-return，γ=0.997；policy 头用 PMPO。所有损失项按各自的 RMS running estimate 归一化，这样一个 transformer 才带得动多模态多输出头。

推理与评估。 时间上自回归推进，每帧用 K=4 步、步长 d=1/4 生成，并把历史输入轻微加噪到 τctx​=0.1，让模型对自己生成里的小瑕疵更鲁棒。训好的策略放回真 Minecraft：60 分钟一局、空背包、随机世界，靠一条线性的任务提示序列引导它走完钻石链。

§ 6 — 核心数学推导 ​

底座是 flow matching。记信号水平 τ∈[0,1]，τ=0 是纯噪声、τ=1 是干净数据：

xτ​=(1−τ)x0​+τx1​,L(θ)=∥fθ​(xτ​,τ)−(x1​−x0​)∥2

推理时从噪声出发按 xτ+d​=xτ​+fθ​(xτ​,τ)d 走 K 步，步长 d=1/K。给数学基础弱的读者一句直观解释：网络学的是从当前含噪点指向干净数据的方向，小步走是安全的，大步走会因为路径弯曲而积累离散化误差。

shortcut model 的做法是让网络也把步长 d 当输入。最细的步长 dmin​=1/Kmax​ 用普通 flow matching 损失训；更大的步长用 bootstrap 损失，把连走两个 d/2 的复合结果（stop-gradient 之后）当成走一个 d 的监督目标。采样分布是

d∼1/U({1,2,4,8,…,Kmax​}),τ∼U({0,1/d,…,1−1/d})

因为网络学的是这一大步的终点在哪，推理时指定 d=1/K 就不再受离散化误差之苦。论文提到这类模型通常 2 到 4 步就能出高质量样本，普通扩散要 64 步以上。diffusion forcing 则给序列的每个时间步一个独立信号水平，于是同一次前向里每一帧既是去噪任务又是后续帧的历史 context。

shortcut forcing 是两者的合并，外加两处论文自己的改动。第一处是参数化。原版 shortcut model 用 v-prediction，论文指出它训练网络产出高频输出，逐帧滚长视频时误差会累积；因此改成让网络输出干净表示 z^1=fθ​(z~,τ,d,a)（x-prediction）。flow 项在 x 空间直接算，bootstrap 项先把网络输出换算回 v 空间求出 b′、b′′，再把损失按 (1−τ)2 缩回 x 空间：

b′=1−τfθ​(z~,τ,2d​,a)−zτ​​,z′=z~+b′2d​,b′′=1−(τ+2d​)fθ​(z′,τ+2d​,2d​,a)−z′​

L(θ)=⎩⎨⎧​​z^1−z1​22​,(1−τ)2​1−τz^1−z~​−sg(2b′+b′′​)​22​,​d=dmin​d>dmin​​

第二处是损失加权。论文的观察是：低信号水平那一端学习信号很少（flow matching 项退化成预测数据集均值），而 bootstrap 项因为目标确定反而更好优化。于是加一个随 τ 线性上升的 ramp 权重，把模型容量推向信息量大的一端：

w(τ)=0.9τ+0.1

这条公式看着朴素，但它精确表达了一个判断：世界模型的容量应该花在把接近干净的表示修对，而不是花在从纯噪声里想象。这与视频生成模型的常规取舍正好相反，因为世界模型的绝大多数前向发生在已有 context 的续写上。

想象训练侧的两个目标。 value 头学 λ-return，γ=0.997，ct​ 标记非终止：

Rtλ​=rt​+γct​((1−λ)vt​+λRt+1λ​),RTλ​=vT​

policy 头用 PMPO 而不是 Dreamer 3 的老目标。PMPO 只看优势的符号不看大小，把想象状态按 At​=Rtλ​−vt​ 分成正集 D+ 与负集 D− 分别取平均：

L(θ)=∣D−∣1−α​i∈D−∑​lnπθ​(ai​∣si​)−∣D+∣α​i∈D+∑​lnπθ​(ai​∣si​)+Nβ​i=1∑N​KL[πθ​(ai​∣si​)∥πprior​]

取 α=0.5 让正负集权重相等，β=0.3 给行为先验一个较弱的约束。忽略优势大小这一点在多任务里很实用：不同任务的回报量级不同，只看符号就不必再做回报或优势归一化。论文还指出与原版 PMPO 的一处差别——先验 KL 用了反向，为的是把策略更紧地约束在合理行为空间内。三项损失都以 nat 为单位，因此彼此的比例在实践中很鲁棒。

§ 7 — 实验设计与结论 ​

论文把实验组织成四问，主战场是 Minecraft，数据是 VPT contractor 数据集：2541 小时、360p、20 FPS 的鼠标键盘轨迹加 event 标注。

问题一：纯离线能不能走完钻石链？ 评测协议照搬 VPT——原始像素输入、低层鼠标键盘输出、合成必须走游戏内 UI。一局 60 分钟，空背包，随机生成的世界，成功率在 1000 局上统计。论文顺带给了一个有用的人类参照：有经验的玩家平均 20 分钟拿到钻石，对应 24000 步鼠标键盘动作。

对比的六个 agent 是 VPT (finetuned)、BC (notask)、BC、VLA (Gemma 3)、WM+BC、Imagination RL。结果链条很清楚：VPT (finetuned) 最远只到木棍，成功率 53%，它拿到的少量石头、铁矿和铁锭是靠苦力怕炸洞、战利品箱这类边缘情况蹭到的；换成直接用 contractor 动作训的现代 BC 基线就超过了 VPT；VLA (Gemma 3) 因为有预训练视觉语言模型打底，能推进到铁镐 11%；Dreamer 4 在石镐及之前的里程碑上成功率超过 90%，铁镐 29%，并在 0.7% 的局里拿到钻石。11% 到 29% 就是论文所说的几乎把 VLA 的铁镐成功率翻了三倍。

值得单独拎出来的是想象训练的收益结构：里程碑越难，imagination RL 相对行为克隆的提升越大。图 4 还报告了到达每个里程碑所需的时间，想象训练不只提高成功率，也让策略更快。

问题二：世界模型的物体交互到底准不准？ 设计是人类玩家进世界模型实操，与 Oasis、Lucid-v1、MineWorld 并排比。这个设计的巧妙之处在于用人类的反事实操作而不是固定测试集探测模型——固定测试集测不出模型在没见过的动作组合下会不会胡说。图 5 的判定是二元的：能不能把方块按正确形状摆出来。Dreamer 4 能，Oasis 和 Lucid 不能。

问题三：世界模型学到的表示是不是通用的？ 图 4 的答案是肯定的——拿世界模型的表示做行为克隆，效果好过用 Gemma 3 的通用表示，也好过从零训。论文的解读是视频预测隐式地学到了对决策有用的世界理解。这是一个漂亮的侧面证据：如果世界模型只是记住了像素分布，它的特征不该在决策任务上打赢一个用远多算力预训练过的视觉语言模型。

问题四与五：动作数据要多少、各组件各贡献多少？ 论文第 4 节列出了这两问（动作条件所需的数据量与泛化范围、目标函数与架构的消融），但我们取到的 arXiv HTML 渲染在 §4.2 之后截断，这两节及相关表格的具体数字不在可核验范围内，本文因此不复述任何相关数值。

§ 8 — Take-aways ​

五句话版：世界模型此前在复杂环境里预测不准物体交互，且往往要多卡才能实时，两条都堵死了想象训练。Dreamer 4 用 shortcut forcing——shortcut model 的步长条件、diffusion forcing 的逐帧噪声、x-prediction 参数化、w(τ)=0.9τ+0.1 的 ramp 权重——把每帧生成压到 4 次前向，配轴向注意力加 GQA 的 2B transformer 做到单卡实时。动作被做成可缺席的模态，无标注视频只用一个 learned embedding 就能参与训练。在同一个 transformer 里插入 agent token 学出 policy 与 reward，再冻住 transformer、只用 PMPO 更新 policy 与 value 头做想象 RL，Dreamer 4 成为第一个仅凭 2541 小时离线数据在 Minecraft 里拿到钻石的 agent——1000 局中 0.7%，铁镐 29%，石镐及之前超过 90%。同样协议下 VPT (finetuned) 最远只到木棍 53%，而它用了 270K 小时数据。

三句话版：把世界模型的速度写进目标函数与架构，使得实时交互与准确物体交互第一次同时成立。世界模型可信之后，长时序信用分配整个搬进想象中完成，真实环境一次不碰。里程碑越难，想象训练相对行为克隆的增量越大——这正是这套方法该有的收益形状。

一句话版：先把世界模型做到又快又准，再把强化学习完全搬进它内部，从而在不接触环境的前提下解决超长时序控制任务。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：世界模型在 agent 想象出来的、越来越偏离数据分布的轨迹上，依然保持准确。想象训练的整个价值都压在这里——RL 的本质就是不断去探索当前策略之外的行为，而这些行为按定义就不在离线数据里。

它在实践中为什么可能不成立：agent 会主动寻找模型预测出高回报的区域，而模型误差最大的地方往往正是数据覆盖最稀的地方，两者是同一批状态。这就是离线 RL 里经典的模型利用（model exploitation）问题。挖钻石这条链路（砍树 → 做工作台 → 做木镐 → 挖石 → 做石镐 → 挖铁 → 熔炼 → 做铁镐 → 下矿 → 挖钻石）任何一环上模型给出乐观的错误预测，策略都会学会去钻这个空子。

读过全文之后要修正一个印象：论文并非没有防守。它至少布了四道针对这条假设的闸门，其中一道写得非常直白——agent 微调阶段行为克隆损失只加在相关序列上，动力学损失只加在均匀采样序列上，以避免乐观的生成。也就是说作者明确担心用成功轨迹去训动力学会让世界模型学会把什么都画成成功。另外三道是：想象训练期间整个 transformer 冻结，只更新 policy 与 value 头，世界模型没有机会与策略共同漂移；PMPO 里对冻结 behavioral prior 的 KL 项（β=0.3，且刻意用反向 KL）把策略拴在数据支撑的行为空间内；推理时把历史 context 加噪到 τctx​=0.1，让模型对自己生成的小瑕疵不敏感。

最终证据是端到端的：策略被放回真实 Minecraft 跑 1000 局并确实拿到钻石。这基本排除了完全在幻觉里成功的可能。人类在世界模型里做反事实操作的对比实验，也是在直接探测模型的分布外行为质量。

仍然缺的证据。 论文没有给出想象轨迹随 rollout 长度增加而偏离真实动力学多少的定量刻画，也没有模型集成或显式的不确定性惩罚——上面四道闸门都是行为侧约束（别偏离数据太远），没有一道是认知侧的（在模型自己不确定的地方降权）。另一个可以放在一起读的数字是钻石成功率只有 0.7%：它与想象信号只在最难的里程碑上提供了边际帮助自洽，也与想象在长链条末端已经不太可信自洽，公开结果无法区分这两种解释。在噪声更大、数据更少的真实机器人场景里，这条假设能撑到哪一步仍然开放。

§ 10 — 最小复现实验 ​

不复现完整系统，一周内验证核心机制：

  • 环境：不用 Minecraft，用一个带物体交互的轻量环境，例如 MiniHack 或简化版 Crafter（有采集与合成链条，动作空间小）。
  • 实现：训两个小世界模型，架构与数据完全相同，只换生成目标——A 组标准 diffusion forcing（每帧多步去噪），B 组加上 shortcut 式的自洽性约束（网络额外接收步长 d，用两个 d/2 的复合结果监督一个 d 的预测）。
  • 测量：三个量——（a）单帧生成所需函数调用次数与 wall-clock；（b）给定同一段动作序列，rollout 20 / 50 / 100 步后与真实环境状态的偏差；（c）在两个模型里各用同样的 RL 算法训策略，放回真实环境测回报。
  • 判据：若 B 组在生成步数上降低一个数量级、而 (b) 的偏差不明显变差，就支持"少步生成不牺牲准确性"这一核心前提；若 (c) 上 B 组回报不低于 A 组，则想象训练确实从速度里获益。反过来，如果 B 组 rollout 偏差随步数明显更快发散，那么 shortcut 类目标与长时序想象训练之间就存在本文未讨论的张力。

§ 11 — 最强反例设计 ​

最有力的攻击是提供替代解释：挖钻石这条链路在 Minecraft 里是高度模式化的，人类玩家的做法几乎相同。因此 Dreamer 4 的成功可能主要来自离线数据里本来就包含大量完整的挖钻石轨迹、模型与策略共同把它记住并复现了，而不是在想象中做了真正的长时序规划。全文给这条攻击提供了额外弹药：论文自己承认现代 BC 基线（直接用 contractor 动作）已经超过 VPT (finetuned)，说明少 100 倍数据这个卖点里有一大块来自动作标签质量而非想象训练；而 20 个任务、一条线性提示序列、外加 50% 相关序列的数据配比，本身就是把钻石链的模式高效喂给策略的方式。

设计一个决定性实验：构造若干组合性新任务，其子技能都在数据里出现过但组合方式没有出现过，例如"先造船渡过一片水域，再在对岸挖钻石"或"在下界特定地形完成采集"。同时构造一组反事实初始条件（比如背包里已有铁镐但地表没有树）。如果 Dreamer 4 在这些任务上的成功率相对标准挖钻石任务大幅下滑，那么"在想象中训练长时序行为"的 claim 就要弱化成"在想象中复现数据中的长时序模式"。

一类可预测的失败场景：奖励模型必须在想象出来的画面上判断任务是否成功。当想象画面出现轻微伪影或不可能的物体组合时，奖励模型可能给出错误的高分，策略就会朝着"生成让奖励模型误判的画面"优化——这是 reward hacking 在想象训练里的特有形态。在奖励信号更稀疏、视觉更复杂的真实机器人场景里，这个失败模式预计会更严重。

§ 12 — Follow-up Research Idea ​

不要做"把 Dreamer 4 扩展到别的游戏"或"加大模型规模"，那是增量。

换一个 framing：把世界模型从"被优化的对象"变成"会自我暴露弱点的对手"。驱动它的局限正是 §9 说的——想象训练的准确性只在数据覆盖区可靠，而 RL 必然把策略推向覆盖之外，且目前看不到显式的不确定性处理机制。

可借鉴的相邻领域工具有两个方向。一是离线 RL 里成熟的悲观主义与不确定性惩罚（模型集成的分歧度作为惩罚项），二是对抗式课程生成（unsupervised environment design）：让一个"出题者"专门去搜索世界模型集成内部分歧最大的状态-动作区域，把这些区域作为主动查询的目标。在机器人这类离线场景里，这些查询可以被打包成一份"最值得真机采集的数据清单"，把稀缺的真实交互预算花在刀刃上。

第一个实验：在 Crafter 或同类环境里训练 K=5 个世界模型（不同随机种子），定义分歧度为各模型对同一 (s,a) 预测的下一状态之间的方差。跑三组：（A）标准想象训练；（B）想象训练加分歧度惩罚；（C）想象训练加分歧度惩罚，并允许额外采集固定预算（比如 1% 的原始数据量）的真实交互，采集点由分歧度最大的状态决定。评估真实环境回报与"策略被模型误差坑掉"的失败次数。如果 C 组用 1% 的额外交互就显著缩小与在线 RL 的差距，那么"纯离线"这个约束就应该被重新表述为"极少量、但选得极准的在线交互"——对机器人而言，这个改写比"完全不交互"更接近实际可行的范式。
