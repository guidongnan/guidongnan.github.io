Quant VideoGen: Auto-Regressive Long Video Generation via 2-Bit KV-Cache Quantization ​

项内容
arXiv2602.02958
提交日期2026-02-03
作者Haocheng Xi, Shuo Yang, Yilong Zhao, Muyang Li, Han Cai, Xingyang Li, Yujun Lin, Zhuoyang Zhang, Jintao Zhang, Xiuyu Li, Zhiying Xu, Jun Wu, Chenfeng Xu, Ion Stoica, Song Han, Kurt Keutzer
分类cs.LG
一句话先用 k-means 把 KV-cache 里语义相近的 token 分组、减掉组质心得到低幅值残差，再多级重复这个过程把残差逐层剥细，最后才做 2-bit 整数量化。

所属教程：自回归视频生成

版本说明

本文基于 arXiv v5（2026-05-05 修订）全文撰写；v1 提交于 2026-02-03，ICML 2026 接收。代码见 github.com/svg-project/Quant-VideoGen。本站论文索引里该条目写作「量化路线」，是中文描述而非编号错误。

§ 1 — 研究问题与重要性 ​

自回归视频扩散把「先算完整个窗口才能输出」变成了「算一块吐一块」，于是直播式生成、可交互控制、长时程世界模型才成为可能。代价是 KV-cache 必须常驻显存，且随历史线性增长。论文给的具体数字很有说服力：LongCat-Video 生成 5 秒 480p 视频约需 38K latent token，KV-cache 约 34 GB，而模型参数才 27 GB——缓存比权重还大，单张 RTX 5090 直接装不下。

真正让这件事从工程问题升级为研究问题的，是第二层观察：显存不只限制部署，还限制能力。现有系统之所以把上下文窗口写死（Self-Forcing 默认滚动 21 个 latent 帧，HY-WorldPlay 只留 20 帧），主要就是被显存逼的。而窗口一截断，模型的工作记忆就变小，身份漂移、布局重写、动作语义断裂随之而来。所以「压缩 KV-cache」在这里不是纯粹省钱，而是在同样的硬件上买回更长的有效上下文。

§ 2 — 前人工作与不足 ​

长视频这条线上，训练无关的长度外推（FreeNoise、FreeLong、RIFLEx）通过重排噪声或调整时间频率把预训练模型推到训练长度之外；扩散-因果混合（Diffusion Forcing、history-guided diffusion）稳定长 rollout；显式记忆机制（StreamingT2V、WorldMem、FramePack 系列）用外部结构存历史。论文对这一整片工作给了一句很准的批评：长时程生成不只是算法上的「记忆」问题，也是系统问题——硬件显存直接决定了算法记忆（即 KV-cache）能留多少。

KV-cache 量化在 LLM 服务里已经很成熟。KIVI 与 KVQuant 指出 key 与 value 的统计特性不同并针对重尾离群值设计免调优的低比特方案；QuaRot、RotateKV 用结构化旋转把激活分布抹平再量化；SKVQ、ZipCache、KVSink 走 token 异质路线，优先保住一小部分 token；PQCache、CommVQ 用学习码本做向量量化。论文的批评是精确的：这些方法都不显式利用视频特有的时空冗余，也没有针对视频 KV-cache 的数值特性设计。作者实测在 Self-Forcing 与 LongCat-Video 上 max∣K∣∼102、max∣V∣∼103，而且离群通道是随 token 变化的——对某些 token 是离群的通道，对另一些 token 不是。LLM 量化里常用的「固定若干离群通道单独处理」这类假设在这里直接失效。这解释了为什么该问题此前没被解决：不是没人想压，而是从 LLM 搬过来的工具在视频的激活统计上直接崩掉。

§ 3 — 重建作者的思考路径 ​

出发点是一个纯粹的量化算术事实：对称分组整数量化的尺度因子 SX​=max∣X∣/(2b−1−1)，期望误差正比于 SX​。所以降低量化误差只有一条路——把每个分组里的最大绝对值压下来。

LLM 那边的答案是旋转（QuaRot）或者挑离群通道特殊对待。但前面已经看到视频的离群通道随 token 漂移，通道级手段用不上。于是问题变成：还有别的方式定义「分组」吗？

这时视频自身的性质进来了。稀疏视频生成那条线（SparseVideoGen 系列）已经反复证明视频 latent 有强时空冗余：同一空间位置的相邻帧 token 高度相似，空间相邻的 patch 映射到的 latent 也高度相似。如果按语义相似度而非按空间位置分组，那么组内 token 的大数值很可能是共享的——它们本来就来自同一片场景内容。把组均值减掉，共享的大数值就被质心吸走了，剩下的残差幅值自然小。这是 Semantic-Aware Smoothing 的全部逻辑：不是抹平分布（旋转的思路），而是把分布的"直流分量"外移到一个额外存储的小张量里。

最后一步来自视频编解码的类比。可分级视频编码（SVC）是逐级细化的：先编粗结构，再一层层加细节。既然减一次质心能把幅值降一大截，那对残差再做一次同样的操作应该还能再降——只是收益递减。这就是 Progressive Residual Quantization，而级数 T 恰好成为一个连续调节「质量-压缩率」的旋钮。

§ 4 — 核心 Intuition ​

量化误差由分组内的最大值决定，而视频 KV-cache 的大值不是随机散布的——它们成片地出现在语义相近的 token 上。所以先用 k-means 把这些 token 聚到一起、把组质心减掉，大值就被搬进了一个体积很小的质心表，剩下的残差既小又均匀，2-bit 就够存。再把这个操作对残差重复几次，就是一个从粗到细的渐进编码器。

§ 5 — 具体方法与完整 Pipeline ​

以 HY-WorldPlay-8B 在 480p 下逐块生成为例（chunk = 12 帧）。

  1. 按 chunk 取 KV：一个 chunk 有 N=HWTc​ 个 token，写成 X∈RN×d，d 是 head 维度。压缩以 chunk 为单位做一次，不重复压缩，避免反复量化带来的漂移。
  2. 语义分组：在序列长度轴上跑 k-means，把 N 个 token 分成 C 组（实现取码本大小 K=256，正好让 assignment 用 uint8 存一个字节）。
  3. 减质心：Ri​=XGi​​−Ci​，输出残差 R、质心表 C、归属向量 π。
  4. 渐进细化：令 R(0)=X，对 t=1..T 反复执行第 2–3 步，每级都存下 C(t) 与 π(t)，中间残差丢弃。
  5. 量化并落盘：只对最后一级残差 R(T) 做 INT2/INT4 对称分组量化，scale 用 FP8 E4M3 存以降低元数据开销；key 采用 pre-RoPE 缓存（分布更好量化）。
  6. 反量化：从 XINT​ 解回后，从第 T 级到第 1 级逐级把质心加回去，X^(0) 即重建结果。作者写了融合 kernel，把全部级数的反量化与加质心合并成一次，中间结果留在寄存器里，不反复读全局内存。

两套预设：QVG 用 S=1 级、量化块大小 B=64（偏压缩率）；QVG-Pro 用 S=4 级、B=16（偏质量）。另有一个系统优化：用上一个 chunk 的归属结果初始化新 chunk 的 k-means，把聚类开销降低 3×。

§ 6 — 核心数学推导 ​

量化本身是标准的对称分组整数量化：

XINT​=⌊SX​XBF16​​⌉,SX​=2b−1−1max(∣XBF16​∣)​

对任意元素，舍入误差满足 ∣x−x^∣=SX​⋅RoundErr(x/SX​)≤SX​/2，在元素独立的假设下期望误差 E[∣x−x^∣]∝SX​。这条不等式是整篇论文的支点：它把「降低误差」等价地转换成「降低分组内最大绝对值」，方法设计从此只需围绕一个标量目标展开。对数学基础较弱的读者，可以这样理解 SX​：它就是「一格有多宽」，b 比特只能表示 2b 格，格子越宽，每个数落在格心的偏差越大；一个离群值把 max 撑大，整组数的格子就全被拉宽，哪怕其他数都很小。

Semantic-Aware Smoothing 写成 R,C,π=SA-Smoothing(X,C)，重建为

X^Gi​​=Ri​+Cπi​​

关键在于：maxi​∣Ri​∣ 只取决于组内的离散程度，而 max∣X∣ 取决于全局幅度。k-means 若能把大值 token 聚到一起，那部分幅度就整体转移到 C 上，而 C 是以全精度另存的、体积只有 C×d。换句话说这是一次显式的「均值-方差分离」：均值精确保留，只有方差部分被压到 2 比特。

渐进版本是同一算子的不动点式迭代：R(t),C(t),π(t)=SA-Smoothing(R(t−1),C)。每一级都在剩余残差上重新聚类，因此第一级捕捉粗粒度语义结构，后续级捕捉细粒度变化。代价是每多一级就多一份 C(t) 与 π(t)——这解释了为什么 QVG-Pro（4 级）的压缩率反而低于单级的 QVG。

§ 7 — 实验设计与结论 ​

问题一：2-bit 到底能不能用？ 在 LongCat-Video-13B（73 帧上下文、每次续 20 帧）、HY-WorldPlay-8B（chunk 12）、Self-Forcing-Wan-1.3B（chunk 16）上，用 MovieGen benchmark 的 prompt 套件、以 BF16 KV-cache 的输出为参照测 PSNR/SSIM/LPIPS，再用 VBench 测感知质量。INT2 下差距是压倒性的：LongCat 上 QVG 以 6.94× 压缩拿到 PSNR 28.716、VBench 四项 95.06/71.47/94.11/62.22（BF16 参照 96.22/72.72/95.51/64.83），而 RTN/KIVI/QuaRot 在 6.40× 压缩下 PSNR 只有 20.3–21.6，图像质量分掉到 38.10–59.60。HY-WorldPlay 上同样，QVG 7.05× 压缩、PSNR 29.174，VBench 几乎与 BF16 重合（97.98/73.87/97.90/69.80 对 97.92/74.33/97.90/69.85）。

这里必须如实指出一处比较口径问题：INT2 表里三个 baseline 的压缩率都是 6.40×，而 QVG-Pro 只有 4.97×/5.20×——它比被它击败的方法占用更多显存。多出来的空间正是 4 级质心表与归属向量。真正与 baseline 同档甚至更省的是单级的 QVG（6.94×/7.05×），它同样大幅领先。INT4 表里这个问题更明显：baseline 3.55×，QVG-Pro 只有 3.05×/3.15×。另外 INT4 档几乎没有区分度——HY-WorldPlay 上连朴素 RTN 的 VBench 都与 BF16 持平（美学分 70.13 甚至高于 BF16 的 69.85），说明这套 VBench 指标在 INT4 已经饱和，真正的战场只在 INT2。

问题二：长时程会不会崩？ 在 Self-Forcing 上每 50 帧测一次 Image Quality。附录把长度推到 1400 帧（约 90 秒）：BF16 从 74.33 一路降到 65.87，KIVI 从 67.57 崩到 35.85，QuaRot 从一开始就只有 48.33，而 QVG 是 74.36 → 69.52 → 67.23 → 67.28。最后一档 QVG（67.28）高于 BF16（65.87），论文只写「on-par」，未讨论这个反转。

问题三：两个组件各贡献多少？ Semantic-Aware Smoothing 单独把 key 的量化误差降低约 6.9×、value 约 2.6×（作者解释 value cache 比 key 更不规则）。Progressive Residual Quantization 的第一级贡献 5.83× MSE 下降，后续每级至少再降 1.10× 但收益递减。码本大小扫描显示 K 从 64 到 512，压缩率与重建质量单调对换（INT2 下 7.760×/4.832 到 7.307×/6.428），选 256 的理由是能塞进一个字节。量化块大小 16→64 同样是质量换压缩，64 综合最优、16 质量最好。

问题四：开销可接受吗？ 显存分解显示量化值占 ≥65%。端到端延迟开销：LongCat 2.1%、HY-World 1.5%、Self-Forcing 4.3%。这里论文内部数字不一致：摘要写「<4%」而 Self-Forcing 是 4.3%；附录表 4（Self-Forcing 不同 chunk 大小）称开销最高 3.3%；附录表 6（Self-Forcing，H100）又给出 43 s / 0.74 s = 1.7%。三处口径互不相同，论文未作说明。实用价值上最有分量的一条是：QVG 让 HY-WorldPlay-8B 首次能在单张 RTX 4090 上跑起来，相对 BF16 参照的 PSNR > 29。

§ 8 — Take-aways ​

5 句话版：自回归视频扩散的 KV-cache 已经超过模型权重本身（LongCat 5 秒 480p 约 34 GB vs 27 GB 参数），既卡部署也卡上下文长度进而卡长时程一致性；LLM 的 KV 量化方案搬过来会崩，因为视频激活的离群通道随 token 变化，通道级假设失效；QVG 改从时空冗余入手，用 k-means 按语义分组、减质心得到低幅值残差，把「大值」外移到体积很小的质心表；再把这个算子对残差迭代若干次实现从粗到细的渐进编码，级数即质量-压缩率旋钮；INT2 下 LongCat/HY-WorldPlay 分别达到 6.94×/7.05× 压缩、PSNR 28.7/29.2，远超 RTN/KIVI/QuaRot 的 20–25，延迟开销个位数百分比，并首次让 8B 世界模型跑进单张 4090。

3 句话版：量化误差正比于分组最大值，而视频 KV-cache 的大值成片出现在语义相近的 token 上。先聚类再减质心，把这部分幅度搬到全精度小张量里，剩下的残差 2 比特就够；迭代这个操作可连续换取更高质量。代价是质心与归属表本身占空间，所以高质量档（4 级）的压缩率反而低于 baseline。

1 句话版：把 KV-cache 的「均值」用全精度另存，只把「残差」压到 2 比特。

§ 9 — 最脆弱的假设 ​

最脆弱的是：latent 空间里的语义相似性，蕴含数值上离群模式的一致性。整个方法能成立，靠的是「组内 token 共享同一批大值，因此质心能把它们一并吸走」。但论文自己在 §3.2 观察到的恰恰是离群通道因 token 而异。方法实际上赌的是：这种 token 依赖性可以被 latent 相似度预测。如果一个 chunk 里存在语义相近但数值行为不同的 token——例如一个高速运动物体扫过静止背景，前后帧的同一 patch 在 latent 上仍然相似，但注意力投影的幅度已经变了——质心就吸不走这些值，残差里仍留着大 outlier，2 比特会把它抹平。

论文提供的证据是间接但真实的：key cache 的量化误差降低约 6.9×，value 只降 2.6×，作者自己给出的解释是 value cache「更不规则」。这个 2.6× 与 6.9× 的落差，正是上述假设在 value 上部分失效的直接读数。缺失的证据是把误差按内容类型分解——高运动 / 低运动、前景 / 背景各自的残差幅值分布。全文没有任何按视频内容切分的误差分析，因此无法判断失败会集中在什么场景。另外全部保真度指标（PSNR/SSIM/LPIPS）都是相对 BF16 输出测的，而非相对真值；这套口径能说明「与未量化模型一致」，说明不了「视觉上没坏」，只有 VBench 那四项承担后一职责。

§ 10 — 最小复现实验 ​

一周内可做，不需要写 CUDA kernel，纯 PyTorch 模拟即可。

  • 取 Self-Forcing-Wan-1.3B 公开权重，在 MovieGen prompt 里选 20 条，生成 200 帧并 dump 每层每 head 的 KV-cache（单块 40GB 卡足够）。
  • 实现三条压缩路径的离线模拟：朴素 per-group INT2、QuaRot 式旋转后 INT2、以及 QVG 的单级 SA-Smoothing + INT2（k-means 用 sklearn，K=256，B=64）。只需比对重建 MSE，不必接回模型。
  • 关键是加一个论文没有的对照：随机分组——保持组数与组大小完全一致，但归属向量随机生成后同样减组均值。这条基线的存储开销与 QVG 逐字节相同，唯一被破坏的是「组内语义一致」。
  • 判据：若 QVG 的 MSE 显著低于随机分组，则语义聚类确实在起作用；若两者接近，则增益主要来自「减去任意一个分组均值」这个去直流操作本身，与 k-means 无关。再把重建后的 KV 喂回模型跑 200 帧，看 VBench Image Quality 是否与 MSE 排序一致。

§ 11 — 最强反例设计 ​

反对者最强的一击是替代解释：QVG 在长时程上的优势，可能部分来自量化噪声起到的正则作用，而非「更忠实地保留了历史」。支持这个读法的是论文自己的附录表 2——在 1400 帧处 QVG 的 Image Quality 是 67.28，高于 BF16 参照的 65.87。如果 QVG 的目标真是逼近 BF16，那么超过 BF16 就不是好消息，而是说明这条曲线上「更像 BF16」与「看起来更好」已经分离。同一张表还显示 BF16 自己从 74.33 掉到 65.87，即全精度、全上下文也照样漂移——这直接削弱了引言里「显存是能力瓶颈」的因果叙事：上下文更长确实相关于更好的一致性，但显然不足以消除漂移。

第二条攻击针对比较口径。INT2 主表中 QVG-Pro 的压缩率（4.97×/5.20×）低于所有 baseline（6.40×），INT4 中同样（3.05×/3.15× 对 3.55×）。一个严格的对手会要求把 baseline 的量化块大小放宽到与 QVG-Pro 等显存的配置再比一次——论文写明 baseline 统一用 block size 16「以求公平」，但公平的口径应当是等压缩率而非等块大小。单级 QVG 不受这条批评影响，可它的 PSNR（28.7/29.2）比 QVG-Pro（30.4/31.6）低 1.7–2.4 dB，头条数字实际上来自那个不等压缩率的配置。

第三，可预测的失败场景很明确：k-means 是在单个 chunk 内做的，质心与归属都不跨 chunk 共享（只有初始化复用）。因此当一个 chunk 内部语义高度异质——快速转场、剧烈相机运动、多主体同时穿插——聚类质量下降，残差幅值回升。论文的 720p 实验其实已经露出一点端倪：同样 INT2、同样码本配置，QVG 的 PSNR 从 480p 的 28.716 降到 25.99，论文的措辞是「保持相同的误差界」，但近 3 dB 的下降更像是随每 chunk 帧数减少（分辨率升高导致每帧 token 变多，chunk 内帧数相应减少）而来的聚类退化。设计一个对照实验很直接：固定分辨率，人为构造「单场景」与「每 chunk 内含一次转场」两组 prompt，比较两者的残差幅值与 PSNR 差。

§ 12 — Follow-up Research Idea ​

驱动局限：QVG 把 KV-cache 当作一堆需要无差别保真的数字，压缩目标是重建 MSE。但注意力对 KV 的使用是高度不均匀的——多数 token 在后续几乎不被 query，少数 token 反复被引用。用统一比特宽度服务两类 token，本质上是在浪费预算。同时它与另一条正交路线（按重要性淘汰 KV，如同期的 salience 类工作）完全没有交互，两者都在独立地重新发现「有些 token 更重要」。

新 framing：把它从「压缩问题」重述为有损信道下的率-失真分配问题——给定总比特预算 B，为每个 token 分配比特数 bi​，最小化的不是重建误差，而是下游注意力输出的误差。这个目标把「淘汰」与「量化」统一成同一个变量的两端：bi​=0 就是淘汰，bi​=16 就是全精度保留，中间是各档量化。当前所有工作都只走两个极端。

可借鉴的相邻工具：率-失真优化在视频编解码里有成熟的拉格朗日框架（minD+λR），而「注意力输出误差」的敏感度可以用一阶展开近似为 ∥∂Attn/∂ki​∥ 的量级，这正是 LLM 量化里 GPTQ/AWQ 一系用来做敏感度加权的思路——只是它们用在权重上，没人用在视频 KV 的时间轴上。

第一个实验：在 Self-Forcing 上，先离线统计每个历史 token 在后续 n 个 chunk 中被 query 的累积注意力质量，据此把 token 分成三档，分别用 INT4 / INT2 / 直接丢弃，总显存与均匀 INT2 的 QVG 持平。测两件事：一是相对 BF16 的 PSNR，二是 700/1400 帧处的 VBench Image Quality。如果混合比特在同等显存下明显优于均匀 2 比特，就证明「均匀量化」本身是当前 Pareto 前沿的一个可去除的约束；如果不优于，那反而是个有价值的负结果——说明视频 KV 的重要性分布远比 LLM 平坦，而这恰好会解释为什么按语义分组的去直流操作能吃到这么大的收益。
