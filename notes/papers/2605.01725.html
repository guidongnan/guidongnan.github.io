Motion-Aware Caching for Efficient Autoregressive Video Generation ​

项内容
arXiv2605.01725
提交日期2026-05-03
作者Jing Xu, Yuexiao Ma, Xuzhe Zheng, Xing Wang, Shiwei Liu, Chenqian Yan, Xiawu Zheng, Rongrong Ji, Fei Chao, Songwei Liu
分类cs.CV, cs.AI
一句话把「块内相邻帧的 latent 差」证明成残差不稳定度的上界，用它给每个 token 分配不同的缓存更新频率，并先整块预热 K 步再切到 token 级稀疏重算。

所属教程：自回归视频生成

版本说明

本文基于 v2 全文（2026-05-14 修订）撰写，v1 提交于 2026-05-03。frontmatter 日期取 v1 提交日。

§ 1 — 研究问题与重要性 ​

自回归视频生成把长视频切成 chunk，靠 KV cache 把 attention 复杂度从二次降到线性，理论上支持无限长生成。但结构上的省不等于时间上的省：论文给出的实测是，在一张 A800 上以 batch size 1 用 SkyReels-V2 生成 7 秒 540×540 视频需要约 27 分钟，而 Table 1 里 SkyReels-V2 的 vanilla 延迟是 1540 秒。瓶颈在每个 chunk 内部仍要跑完整的迭代去噪。

feature caching 是这个场景下最直接的加速手段：扩散过程在相邻 timestep 之间高度冗余，把上一步算出的残差存下来复用，就能跳过若干次前向。问题是现有 cache 方法的粒度太粗。TeaCache 一类以整个 timestep 为原子单位，FlowCache 把这套东西搬到自回归上、以整个 chunk 为原子单位——要么全算要么全跳，没有中间状态。

这个粒度为什么不够，论文给了很具体的理由：视频里像素的动态差异极大。高运动区域需要更多去噪步才不会累积误差，静止背景则可以激进跳过。一个 chunk 里既有前者又有后者，二元决策必然是「在静态区浪费算力」和「在动态区损失质量」二选一。把粒度降到 token，是这一层里唯一还没被做过的事。

§ 2 — 前人工作与不足 ​

caching 加速被论文分成两支。layer-level 方法（FORA、Δ-DiT、BWCache 等）缓存中间特征图，代价是显存随模型深度线性增长；用 Taylor 展开做预测的 TaylorSeer 一类进一步放大了这个开销。step-level 方法（TeaCache、AdaCache、DiCache 等）只存残差，显存开销可以忽略，但预测精度不如 layer-level。这两类都是为标准 DiT（全序列联合去噪）设计的。

真正的直接对手是 FlowCache，论文承认它是第一个把 cache 迁移到自回归视频、并利用了 chunk 之间时间异质性的工作。FlowCache 的不足被论文说得很精确：它是二元的 chunk 级策略，整个 chunk 必须同时计算或同时跳过。这样做丢掉了两样东西——chunk 内部 token 级的时间冗余差异，以及同一 timestep 下不同帧之间的空间与内容差异。

后一点尤其容易被忽略，论文特意解释了为什么它在自回归设定里格外严重：video VAE 把若干原始帧压成一个 latent 帧，所以同一个 chunk 里不同 latent 帧对应原视频的不同时间段，内容演化本来就不同。以 chunk 为原子单位等于假设这几个时间段的更新需求一样，而这个假设没有任何依据。

§ 3 — 重建作者的思考路径 ​

出发点是一个可以直接算的问题：cache 复用到底错在哪里。把 flow matching 的 Euler 更新写开，复用残差与真实残差之差乘以步长，就是本步的局部误差。这一步不需要任何新概念，纯粹是把已有公式重排（论文的 Proposition 4.1）。

有了这个式子，最优缓存策略的形式立刻明确：只重算残差变化大的 token。但真实残差变化必须先做完前向才知道，这是个鸡生蛋问题。于是需要一个能在前向之前算出来的代理量。

代理量从哪找？扩散过程的残差是 velocity field 的函数，velocity field 又是 latent 的函数。如果残差场关于 latent 满足 Lipschitz 条件，那么 latent 上的差异就能控制残差上的差异。而 latent 上最便宜、最容易拿到的差异，就是同一 chunk 内相邻帧的差——它恰好也是「运动」的直接度量。这条链把「缓存误差」和「视频运动」连了起来。

然后是一个必要的现实检查：这个代理在整个去噪过程里都可靠吗？作者把缓存决策当成排序问题，用 NDCG 比较帧差排序与真实残差差排序，发现整体在 0.94 以上，但早期 timestep 波动明显。早期波动意味着语义布局尚未稳定，此时按 token 稀疏计算会破坏全局结构。既然如此，就先整块跑几步把结构立住，再切到细粒度。coarse-to-fine 的双阶段调度就是这么来的。

§ 4 — 核心 Intuition ​

cache 之所以出错，是因为复用的残差和真实残差不一样；而残差在什么地方变化剧烈，取决于画面在什么地方在动。所以不需要真的去算残差，用相邻帧的 latent 差就能提前知道哪些 token 必须重算、哪些可以躺在 cache 里。前人把整个 chunk 当成一个原子，等于强行让静止的背景和奔跑的主体共用一套更新频率。

§ 5 — 具体方法与完整 Pipeline ​

以 SkyReels-V2-1.3B 生成 540p、2 个 chunk、每 chunk 97 帧（24 FPS）为例。设第 i 个 chunk 在 timestep t 的 latent 为 Xti​∈RF×H×W×C。

  1. 算运动重要度。对 chunk 内第 f 帧，用上一 timestep（t+1）的输出 latent 算与前一帧的 L1 差作为重要度 Mt(i,f)​。chunk 的第 0 帧（i>0）与上一个 chunk 的最后一帧作差以保持跨块连续；整段视频的第 0 帧无参考，直接复用第 1 帧的重要度。
  2. 软映射成权重。对每一帧独立做 min-max 归一化（因为不同时刻的运动动态范围不同），再线性投到 [α,1] 得到权重 Wt(i,f)​。α 是地板值，保证静止背景的 token 仍以基准速率累积更新概率，不至于被永久冻结。默认 α=0.6。
  3. 重要度加权累积。先算 chunk 级的相对 L1 距离 Δchunk​(t) 作为整体更新预算，再按 token 权重分配到累加器 A。累加器超过阈值 τ 的 token 被选中计算，计算后累加器清零。
  4. 双阶段调度。Phase 1：前 K 次完整计算期间强制 chunk 级二元决策（整块算或整块跳），把全局结构立住；默认 K=6。Phase 2：切到 token 级稀疏模式，把 Mask[p]=1 的 token gather 成一个紧凑 batch 走前向，算完 scatter 回残差 cache Rcache​，未选中的 token 直接取缓存残差近似。

整套流程 training-free，依托模型原生的 KV cache 实现。实验在 A800 80GB 上用 PyTorch 完成。

§ 6 — 核心数学推导 ​

Proposition 4.1（残差不一致性原理）。在 flow matching 的 Euler 更新下，chunk i 在 timestep t−1 的局部近似误差为

ϵt−1i​=Δt⋅​Rt−1i​−Rti​​2​

其中残差定义为 Rti​=vθ​(Xti​,t,c)−Xti​，缓存复用时用 v~t−1i​≈Xt−1i​+Rti​ 代替真实前向。这个式子说明缓存的可靠性完全由残差的时间稳定性决定，与特征本身的大小无关——这是把决策变量从「特征差」换成「残差差」的依据。

Lemma 4.2（运动诱导的残差不稳定）。设 R(X,t) 是由 velocity field 导出的连续残差函数，假设残差场的时间梯度 ∇t​R 关于输入 latent X 满足 Lipschitz 条件，则

​Rt−1​(Xt−1(i,f)​)−Rt​(Xt(i,f)​)​2​≲C⋅​Xt(i,f)​−Xt(i,f−1)​​2​

左边是扩散时间方向上的残差变化，右边是视频时间方向上的相邻帧差。论文据此宣称帧差不只是启发式，而是残差不稳定度「有数学依据的上界」。

需要注意的是，这个不等式把两个方向的变化连了起来，而 Lipschitz 条件本身只保证「输入接近则梯度接近」。要让右边真的控制左边，还需要一个未被显式写出的桥梁：f 帧与 f−1 帧的 latent 差，能代表该 token 在扩散时间上走过的距离。这更像一个关于视频局部平稳性的额外假设，而非 Lipschitz 的推论（详见 §9，此处为基于证据的推断）。

具体实现上，权重与累积规则是

Wt(i,f)​=α+(1−α)⋅max(Mt(i,f)​)−min(Mt(i,f)​)+ϵMt(i,f)​−min(Mt(i,f)​)​,At​[p]=At+1​[p]+Wt​[p]⋅Δchunk​(t)

Maskt​[p]=I(At​[p]>τ)

高运动 token（W≈1）吸收全部更新量、快速累积到阈值；静止 token（W≈α）以 α 倍速率累积。当 α=1 时所有 token 权重相同、同步越过阈值，退化为 chunk 级的全算或全跳。

§ 7 — 实验设计与结论 ​

问题一：帧差真的能替代残差差吗？ 把缓存决策当排序问题，用帧差得到的 token 重要度排序去对比真实残差差得到的排序，NDCG 在各去噪 timestep 上稳定高于 0.94。论文据此认为代理有效。但论文没有给随机排序或均匀排序的 NDCG 参照，0.94 高不高无从判断（NDCG 天然偏高）。

问题二：细粒度能不能同时买到速度和质量？ 在 SkyReels-V2-1.3B（540p）与 MAGI-1-4.5B-distill（720p、7 chunk × 24 帧）上，与 TeaCache、FlowCache 对比 VBench-long、PSNR/SSIM/LPIPS 与 FLOPs/延迟。SkyReels-V2 上 MotionCache-slow 以 6.28× 加速拿到 VBench 82.84%、PSNR 23.46、LPIPS 0.0875，对比 FlowCache-slow 的 6.26×、82.70%、21.83、0.1417；MotionCache-fast 7.26×、82.75%。MAGI-1 上 MotionCache-slow 1.64× 拿到 77.25%（vanilla 77.26%），MotionCache-fast 2.07×、74.59%，而 FlowCache-fast 1.94× 已跌到 73.42%、TeaCache-fast 1.41× 跌到 68.81%。

几点必须如实指出。其一，摘要与 intro 引用的是不同配置：摘要的「6.28× 与 1.64×、VBench 仅降 1% 与 0.01%」来自两个 slow 配置，intro 贡献列表里的「7.26× 与 2.07×」来自 fast 配置，后者在 MAGI-1 上 VBench 掉了 2.67 个百分点。其二，PSNR/SSIM/LPIPS 衡量的是与 vanilla 输出的相似度，不是绝对画质，MotionCache 的主要优势正落在这三项上；唯一的绝对质量指标 VBench，在 SkyReels-V2 上四个加速配置全部挤在 82.38%–82.84% 区间内，区分度很小。其三，SkyReels-V2 上 MotionCache-slow 的 FLOPs 是 30 PFLOPs 对 vanilla 的 113（3.77×），墙钟加速却报到 6.28×；FlowCache 同样是 3.65× FLOPs 对 6.26× 加速，而 TeaCache 的 1.95× FLOPs 对 1.89× 加速是自洽的。这个不一致论文未解释。

问题三：两个超参各自贡献多少？ α 消融（Table 2，SkyReels-V2）：0.0 → PSNR 20.22/SSIM 0.7944/LPIPS 0.5853；0.2 → 21.82；0.4 → 22.90；0.6 → 23.46/0.9093/0.0875；0.8 → 23.42/0.9095/0.0862；1.0 → 23.44/0.9105/0.0866。K 消融（Table 3）：0 → 20.79/0.8636/0.1963；3 → 22.92；6 → 23.46；9 → 23.39；12 → 23.41；15 → 23.43。

这两张表的读法值得停一停。论文说 α=1 会「退化为 FlowCache」，但 α=1.0 的三项指标（23.44/0.9105/0.0866）与最优的 α=0.6 几乎逐位相同，SSIM 与 LPIPS 还略好；而 Table 1 里 FlowCache-slow 是 21.83/0.8733/0.1417。也就是说，在保留双阶段调度与累积器的前提下，把空间选择性完全关掉（α=1）几乎不损失任何质量。真正有害的是 α 太小（α=0 掉到 20.22）。同理 K 从 6 增到 15 质量全部持平，而 K=0 掉到 20.79。另外，Table 2 与 Table 3 都只报 PSNR/SSIM/LPIPS，没有延迟或 FLOPs 列，所以论文关于「α=0.6 在质量与效率之间最优」「更大的 K 提升边际而开销增加」的结论，无法从表内数据验证。

§ 8 — Take-aways ​

5 句话版：MotionCache 把自回归视频的 feature cache 从 chunk 级降到 token 级。理论上先证明缓存误差等于真假残差之差乘步长，再用 Lipschitz 假设把残差的时间不稳定度上界到 chunk 内相邻帧的 latent 差，于是「运动」成了免费的重要度代理。工程上是软映射权重 + 累加器 + 阈值掩码，加上前 K 步整块预热的 coarse-to-fine 调度。SkyReels-V2 上 6.28× 加速、VBench 82.84%，MAGI-1 上 1.64×、VBench 基本无损。但其自身消融显示，把空间选择性完全关闭（α=1）质量几乎不变，主要增益来自 α 地板与 K 步预热这两个「反选择性」的设计。

3 句话版：缓存出错的根源是残差在时间上不稳定，而不稳定的地方就是画面在动的地方，所以用帧差当代理可以在前向之前决定哪些 token 要重算。双阶段调度先立结构再抠细节，避开了代理在早期 timestep 失效的区间。加速数字漂亮，但消融表把「细粒度空间选择」这一核心卖点的边际贡献压到了接近零。

1 句话版：用相邻帧差当 token 级缓存的调度信号，能在自回归视频上做到 6× 级加速且 VBench 几乎不掉，只是其中多少功劳属于「运动感知」本身仍未被论文的消融证实。

§ 9 — 最脆弱的假设 ​

最脆弱的是 Lemma 4.2 那个跨方向的桥梁：扩散时间上的残差变化，可以被同一 timestep 下视频时间上的相邻帧差控制。

它脆弱在于两者度量的根本不是一回事。相邻帧差刻画的是「这个位置的画面内容在动」，残差的时间不稳定刻画的是「模型对这个位置的预测还在改主意」。二者在中后期去噪时确实高度相关（内容已定，剩下的修正主要发生在运动区），但在早期完全可以脱钩：一大片尚未确定语义的静止背景，帧差接近零，残差却在剧烈变化。

论文自己提供了这个失效的直接证据。§5.3 明确写道「NDCG 分数在早期 timestep 波动显著，表明语义基础尚未稳定，此阶段做选择性 token 前向会破坏一致的语义布局」——所以才需要 Phase 1。换句话说，Phase 1 的存在本身就是承认代理在那段区间不成立。而 K 消融给出了这个失效的代价：K=0（完全依赖运动代理）PSNR 20.79，K=6 是 23.46，差 2.67 dB。

更麻烦的是 α 消融把这条质疑推到了极端：α=0（完全信任运动代理、静态区永不强制更新）PSNR 20.22，是全表最差；α=1（完全不区分运动、所有 token 同权）23.44，与最优配置持平。如果 Lemma 4.2 描述的关系足够强，曲线不应该是这个形状。

论文缺的证据是：在固定延迟/FLOPs 预算下，把 motion 权重换成随机权重或均匀权重的对照。α 消融接近这个对照但缺了延迟列，所以无法区分「α=1 质量持平是因为它算得更多」还是「motion 权重本身没用」。

§ 10 — 最小复现实验 ​

不需要复现完整框架，一周内可做：

  • 数据与模型：SkyReels-V2-1.3B，VBench prompt 抽 50 条，覆盖高动态（人物运动、镜头平移）与低动态（静物、缓慢风景）两档。
  • 实现：只实现式 (9)–(13) 的重要度与累加器，不改模型；额外实现两个对照权重——uniform（W≡1，即 α=1）与 shuffled（把 W 在空间维上随机打乱，保持权重直方图不变）。
  • 测量：三种权重在同一实测延迟下（通过调 τ 对齐，而不是调 α）的 PSNR/SSIM/LPIPS（相对 vanilla）与 VBench；同时记录实际计算的 token 比例。
  • 判据：如果 motion 权重相对 shuffled 在同延迟下有稳定且超过运行间波动的优势，说明空间选择性确实 load-bearing；如果三者在同延迟下落在同一区间，则论文的核心机制被证伪，剩下的增益应归给 K 步预热与累加器阈值这两个与运动无关的部分。uniform 一路可以直接检验论文「α=1 退化为 FlowCache」的说法与 Table 1/Table 2 之间的落差。

§ 11 — 最强反例设计 ​

最有力的攻击是替代解释：MotionCache 相对 FlowCache 的增益，主要来自「把二元 chunk 跳过换成了一个更平滑的更新预算分配器」，而不是来自运动信息。

支撑这个解释的正是论文自己的 Table 2。α 从 0.6 升到 1.0，空间选择性被逐步抹平直到完全消失，PSNR/SSIM/LPIPS 三项全部持平（23.46/0.9093/0.0875 → 23.44/0.9105/0.0866）。同时 α=1.0 的分数远好于 Table 1 里的 FlowCache-slow（21.83/0.8733/0.1417）。两条放在一起，唯一自洽的读法是：把 MotionCache 的调度框架（累加器 + 阈值 + K 步预热）套在没有任何运动感知的配置上，就已经能拿到全部增益。运动图在定性可视化里确实与画面对得很齐（Figure 5），但「代理算得准」和「代理带来增益」是两件事。

可预测的失效场景有两类。其一是全局运动：镜头平移、推拉、旋转时几乎所有 token 的帧差都很大，min-max 归一化会把它们重新压回 [α,1] 的满量程，选择性随之失效，方法退化成一个昂贵的 chunk 级 cache。论文的归一化是逐帧独立做的，正好放大了这个问题——它保证了每一帧内部总有 token 被判为「最动」和「最静」，即使整帧动态几乎均匀。其二是低纹理高运动区域，例如晃动的纯色墙面或水面反光，latent 差小但语义演化快，会被系统性地长期缓存。

要把这两条做成实验：构造 30 条纯镜头运动（无物体运动）的 prompt 和 30 条低纹理动态 prompt，在与静态场景相同的 τ 下比较 MotionCache 与 α=1 变体的差距。如果差距在这两类上收敛到零甚至反转，替代解释成立。

§ 12 — Follow-up Research Idea ​

驱动的局限：本文的重要度是从已经生成出来的 latent 反推的（用 t+1 步的输出算帧差），本质上是滞后的、被动的。而且它是逐 token 独立决策，token 之间没有任何耦合，累加器一旦触发就重置，等于假设「重算一次就把这个位置的误差清零」——Proposition 4.1 里的误差是逐步累积并沿 chunk 传播的，这个假设并不成立。

新的 framing：把缓存调度从「每步独立的阈值判断」改写成一个预算受限的最优控制问题。给定一条 chunk 的总计算预算，决策变量是每个 token 在整条去噪轨迹上的更新时刻集合，目标是最小化 Proposition 4.1 给出的累计误差的传播上界。这与「谁更动」这一局部信号不同，它会自然给出「先密后疏」或「在结构突变处集中重算」这类非平凡的时间分配，而且能显式建模误差跨 timestep 的累积，而不是靠重置累加器把它抹掉。

可借鉴的相邻工具：LLM 推理里的 KV cache 驱逐策略已经从「按注意力分数贪心」走到了「带预算约束的子模最大化」；数值 ODE 求解里的自适应步长控制（嵌入式 Runge-Kutta 的误差估计与步长调整）提供了成熟的「用局部误差估计反推何时该多算一步」的框架。两者都可以直接搬到这里，且都自带预算或容差参数。

第一个实验：先在小规模上把「真值」拿到手——对若干条 prompt 完整跑一遍 vanilla，记录每个 token 每个 timestep 的真实残差差，然后用离线动态规划求出「给定 FLOPs 预算下的最优更新时刻表」。把这个 oracle 调度的质量作为上界，与 MotionCache、α=1 变体、随机调度一起放在同一预算下比较。oracle 与 MotionCache 的差距有多大，直接决定了这个方向值不值得做；oracle 与 α=1 的差距，则顺带回答了 §9 里「运动信息到底值多少」这个问题。
