Holo-World: Unified Camera, Object and Weather Control for Video World Model ​

项内容
arXiv2606.20083
提交日期2026-06-18（v1；最新版本 v3，2026-07-01）
作者Xiangchen Yin, Wenzhang Sun, Jiahui Yuan, Zijie Liu, Yinda Chen, Wei Li, Dachun Kai, Chunfeng Wang, Xiaoyan Sun
分类cs.CV
一句话只给一张首帧，同时听相机轨迹、物体控制与可选的天气指令：Unified Scene Adapter 在冻结的 Wan2.1 DiT 上挂两路残差分支，几何那一路恒开、天气那一路由开关 λs​ 控制；推理时再用嵌套式 Scene-Weather CFG 分别放大场景残差与天气残差。

所属教程：世界模型

本页依据 arxiv.org/html/2606.20083v3 的正文与附录写成（早先页面记载的「v1/v2/v3 的 HTML 均返回 404」是抓取瞬时失败造成的误判，实测 v3 可完整读取）。下文的模块名、公式、超参、数据划分与全部数字均取自该版本；表号沿用论文编号。

§ 1 — 研究问题与重要性 ​

视频世界模型这两年的目标正在从「生成一段合理的视频」收敛到一个更苛刻的设定：在可控的相机与物体运动下保住被观测到的那个世界，同时允许它的环境状态发生变化。前半句是一致性要求，后半句是可编辑性要求，两者天然冲突——保得越死，越改不动；改得越狠，越容易把世界改成另一个世界。

论文点出的现状是：这两类控制目前是相互隔离的。相机控制、物体控制各有各的方案，天气生成则通常依赖一段源视频或一个重建好的场景——也就是说，未来的结构在生成之前就已经被指定了。这是一个很关键的观察：video-to-video 的天气编辑之所以看起来效果不错，是因为它拿到了完整的源视频，时间演化、遮挡关系、物体轨迹全都是已知的，模型只需要改外观。

论文因此把设定收紧到首帧锚定的 source-to-state：模型只从单张图像出发，遵循显式的相机与物体控制，加上一条可选的天气指令，然后生成一段视频，要么保留源世界，要么把它迁移到目标天气状态。难度差异很实在：I2V 必须自己合成时间动力学，V2V 可以直接借用源视频的时间信息，作者在对比 Cosmos-Transfer2.5 与 Wan2.7-Edit 时专门声明了这一点。

§ 2 — 前人工作与不足 ​

论文的对比对象分成两条互不相交的线，全文里都点了名。

相机与物体控制线：Uni3C、GEN3C、VerseCrafter、NeoVerse。共同形态是把首帧做几何重建、沿目标轨迹重渲染，再把渲染结果当作条件去锚住生成。这条线已经做得相当好，Table 2 的控制误差就是证据：VerseCrafter 的 RotErr 低到 0.834，GEN3C 的 TransErr 是 1.156，Uni3C 的 ObjMC 是 7.771。它们的缺口在接口层面：条件通路里只有几何，环境状态根本没有对应的输入位；要换天气，只能在生成之后再串一个编辑模型，而串联意味着几何已经定稿、天气只能在像素上贴。

天气状态线：Wan2.7-Edit 与 Cosmos-Transfer2.5，两者都是 video-to-video。Table 3 显示它们在有源视频时的表现差距很大，Wan2.7-Edit 的 Weather Alignment 通过率 79.00、VLM 评分 61.92，Cosmos-Transfer2.5 只有 30.00 / 47.64。缺口在前提：这类方法要求一段已经把未来结构定死的源视频，时间演化、遮挡关系、物体轨迹全部是已知量，模型只需改外观。首帧锚定的设定下这个前提直接消失。

这两条线一直没被统一，可以推断（论文未显式声明）是因为它们对「未来几何由谁指定」给出了相反的答案：控制线交给显式渲染信号，编辑线交给源视频。要统一，同一套条件就得既承担几何指定又承担外观改写，而这两件事挤在一条通路里会互相污染——Table 4 的消融正好把这个污染量化了出来，见 §7。

§ 3 — 重建作者的思考路径 ​

只用这篇论文之前已有的背景，可以这样推：

第一步，注意到一个不对称。相机控制类方法喂给模型的是渲染出的几何缓冲（背景 RGB、法向、深度），描述的是结构；天气编辑改的是外观与粒子（雨丝、雪花、雾的散射、湿地面的反光）。同一条街在晴天和雨天几何完全一样，变的只是辐射与介质，所以这两层在物理上确实可分。

第二步，既然可分，就不应该共用一条注入通路。团队要在一个已经很强的文生视频底座上加控制，最省的做法是 ControlNet 式旁路：冻住底座，只训旁挂的 adapter。而如果旁路只有一条，几何条件与天气条件的梯度会打在同一组权重上；那就让旁路分两支，各自吃各自的条件，再各自加权注回主干。加权系数一旦存在，「有没有天气指令」就自然变成把其中一支乘 0 或乘 1 的开关。Unified Scene Adapter 就是这个形状。

第三步，classifier-free guidance 是控制强度的标准旋钮，但它作用在整个条件上。只用一个 scale，想把雨下大就得整体放大条件，而条件里同时装着相机与物体控制，代价是几何被过度锐化、运动被过度放大。既然分支已经分家，guidance 也该跟着分家：先算场景条件带来的残差，再算天气在场景条件之上额外带来的增量残差，两者用不同系数放大。

第四步，数据。这个设定要求同一个场景同时带相机控制、物体控制与天气监督，而真实视频里几乎不存在「同一段轨迹在四种天气下各拍一遍」。论文的解法是三源拼接：SpatialVID-HQ 提供真实池，Unreal Engine 渲染的开源配对天气视频提供仿真真值，剩下的 V2V 子集用自己从 Wan2.1-Fun-Control-14B 微调出来的 weather-transfer 模型再配合商用编辑模型合成。

§ 4 — 核心 Intuition ​

一个场景的骨架和它的天气是两层不同的东西：相机轨迹、渲染的几何缓冲与物体 bbox 钉住骨架，天气只改变这副骨架上的光照、介质与粒子。把它们接成两路可开关的残差分支，几何那一路恒开、天气那一路按需开，同一套权重就能同时服务「保住原世界」与「换天气」两个任务。推理时再把 guidance 拆成同构的两项，天气强度就能单独拧，而不会把几何条件一起拧紧。

§ 5 — 具体方法与完整 Pipeline ​

底座与可训参数。 底座是 Wan2.1-T2V-14B，VAE、text encoder 与 DiT 主干全部冻结，只训 Unified Scene Adapter。adapter 在 L={0,5,10,15,20,25} 这六层注入，每个 adapter 块与对应的 Wan 块同结构、并用它的权重初始化，但参数不共享。

两组条件。 世界分支吃 Cworld​={Rrgb​,Rdepth​,Rnormal​,Cbbox​}，即沿轨迹渲染出的 RGB、深度、法向加物体 bbox；状态分支吃 Cstate​={Rrgb​}，拿同一张渲染 RGB 当外观锚点。天气本身以一段独立的 weather prompt 进入模型，与描述场景的 scene prompt 分开。

一次具体运行。 给一张城市街景首帧、一条相机轨迹、几个要控的车辆 bbox，加上天气指令「rain」。系统先沿轨迹重渲染出三路 G-Buffer，连同 bbox 送进世界分支；渲染 RGB 同时送进状态分支；weather prompt 存在，于是开关 λs​ 置 1。两支的残差在六个注入层相加回主干，去噪 50 步后输出 81 帧 480×832 的雨中街景。不给 weather prompt 时 λs​=0，状态分支整支被乘没，同一套权重退化成纯的可控世界保持模型。

训练。 目标沿用 Wan 的 flow matching。8张 H200，81 帧 480×832，text length 512，batch size 1 配 gradient accumulation 2，lr 2×10−5，weight decay 0.03，共 3000 步。

推理。 81 帧、50 步，关掉 vanilla CFG，改用 SW-CFG，sscene​=1.0、sweather​=2.0。

数据与标注。 HoloStateData 分 Real 7571 / Simulation 3541 / V2V 3954，共 15066 条训练样本；benchmark 150 条，三个子集各 50。标注流水线：Qwen3-VL 写 scene prompt（明确要求排除天气描述）与 weather prompt（从 cloud / rain / snow / fog 的固定短语表里选），Grounded-SAM2 出 bbox，Depth Anything 与 UniDepth 出深度先验，MegaSaM 估相机参数，MoGe 出稠密深度与法向。Real 子集的真实池是 SpatialVID-HQ，Simulation 子集来自 Unreal Engine 渲染的开源配对天气视频。

§ 6 — 核心数学推导 ​

两个模块的公式都很短，但第二个公式里藏着一个恒等式，§11 的分析全靠它。

Unified Scene Adapter。 设 Fl​ 是第 l 个冻结的 Wan DiT 块，hlw​、hls​ 分别是世界分支与状态分支在该层的输出：

xl​=Fl​(xl−1​,c)+λw​hlw​+λs​hls​

论文把 λw​ 固定为 1，把 λs​ 设成二值开关：无 weather prompt 时 λs​=0，有天气 prompt 时 λs​=1。「两个子空间怎么切换」这个问题的答案就是这个乘法门控，没有 LoRA、没有掩码、没有路由。

Scene-Weather Decomposed CFG。 底座是 flow matching，所以被引导的量是速度场 v，不是 ϵ。每一步做三次前向：不给任何条件的 vempty​、只给场景条件的 vscene​、场景加天气都给的 vfull​，然后

Δscene​=vscene​−vempty​,Δweather​=vfull​−vscene​

v=vempty​+sscene​Δscene​+λs​sweather​Δweather​

这是嵌套式分解：天气的贡献被定义成「在同一副骨架上的增量」，所以放大 sweather​ 只会加强雨雪雾，不会把几何条件一起拧紧。

关键的推导在第三项前面那个 λs​。它与 §5 里门控 adapter 的是同一个开关，因此在不给天气指令的 Real 子集上，λs​=0，整项 sweather​Δweather​ 被乘没，于是

v∣λs​=0​=vempty​+sscene​Δscene​

与 sweather​ 无关。换句话说，「SW-CFG 不会损伤背景保真」在不给天气指令的样本上是一个构造性恒等式，不需要实验去验证。Table 5 里 w=2 与 w=4 的背景 PSNR / SSIM / LPIPS 三项逐位相同（都是 18.12 / 0.624 / 0.245），就是这个恒等式在数字上的直接后果。§11 会把这一点展开。

§ 7 — 实验设计与结论 ​

评测集 150 条，三个子集各 50。Real 侧用 VBench-I2V 八维、RotErr / TransErr / ObjMC 三项控制误差，以及只在有效静态区计算的背景 PSNR / SSIM / LPIPS。Weather 侧用 Weather Alignment（二值通过率）、VLM Evaluation（0–100）与盲配对 User Study。标注用的是 Qwen3-VL，评测则换成 GPT 模型，作者明说是为了避免继承标注模型的偏置。

问题一：加了天气接口，会不会把原本的控制精度拖下水？ Table 2（Real，RotErr / TransErr / ObjMC，越低越好）：Uni3C 3.036 / 1.228 / 7.771，GEN3C 3.063 / 1.156 / 8.078，VerseCrafter 0.834 / 1.197 / 7.002，NeoVerse 1.703 / 2.112 / 8.859，Holo-World 0.719 / 1.123 / 6.549。三项全最优。Table 1 的 VBench-I2V Overall：Uni3C 88.25、GEN3C 87.24、VerseCrafter 88.41、NeoVerse 88.00、Holo-World 89.05；I2V subject 99.43 与 I2V background 99.40 也是第一，但 subject consistency 只有 96.27，输给 GEN3C 的 96.79，dynamic degree 52.00。答案是没有拖下水。

问题二：只给首帧，能不能赢过拿到完整源视频的 V2V？ Table 3：Wan2.7-Edit WA 79.00 / VLM 61.92，Cosmos-Transfer2.5 WA 30.00 / VLM 47.64，Holo-World WA 86.00 / VLM 68.51。User Study 盲配对胜率 83.00%（对 Cosmos）与 62.00%（对 Wan2.7）。需要把话说清楚：这是跨输入设定的比较，作者自己也写了 I2V 必须自己合成时间动力学而 V2V 可以直接借用源视频，所以这个胜率不能被读成「天气建模能力更强」。

问题三：四个部件各自贡献多少？ Table 4 逐件累加（背景 PSNR / SSIM / LPIPS / WA / VLM）：什么都不加 13.20 / 0.552 / 0.320 / 51.00 / 51.60；+G-Buffer 15.34 / 0.577 / 0.329 / 62.00 / 55.20；+UniSA 16.36 / 0.598 / 0.308 / 58.00 / 58.53；+SW-CFG 18.12 / 0.624 / 0.245 / 86.00 / 68.51。这张表里有两个值得点名的不一致：其一，加 G-Buffer 后 LPIPS 从 0.320 恶化到 0.329，而正文的描述是三项保真指标都改善；其二，加 UniSA 后 Weather Alignment 从 62.00 掉到 58.00，这一点作者自己承认了，解释是结构分离会让模型对天气变得保守。

问题四：SW-CFG 的强度该取多少？ Table 5（同五项）：w/o CFG 18.12 / 0.624 / 0.245 / 51.00 / 55.68；Vanilla CFG 16.36 / 0.598 / 0.308 / 58.00 / 58.53；SW-CFG w=2 18.12 / 0.624 / 0.245 / 86.00 / 68.51；SW-CFG w=4 18.12 / 0.624 / 0.245 / 96.00 / 78.42。Vanilla CFG 把背景三项都弄差了，这坐实了「整体放大条件会伤及几何」的诊断。但 w=4 在所有已报告指标上都优于 w=2，论文仍选 w=2，给出的理由只有 Figure 6 的定性截图；能支撑这个 trade-off 的数字一个都没报。

代价在哪里。 附录 Table 7 报了 Weather 子集上 Holo-World 自己的控制误差：RotErr 1.681 / TransErr 1.745 / ObjMC 6.744，明显差于它在 Real 子集的 0.719 / 1.123 / 6.549。天气迁移确实以控制精度为代价，而这一栏没有任何 baseline 对照，无法判断这个退化幅度是否比对手小。

指标校准。 附录 A.5.6 报了一次人工校准：5 名标注者对 100 个 Weather 样本打分，与自动指标的 Pearson r 分别是 Weather Alignment 0.78、VLM Evaluation 0.66。前者可用，后者 0.66 的相关度偏弱，而 VLM 正是拉开与 Wan2.7-Edit 差距的主力指标之一。

§ 8 — Take-aways ​

5 句话版。 Holo-World 把相机控制、物体控制与天气状态迁移收进一个首帧锚定的 I2V 接口，底座是冻结的 Wan2.1-T2V-14B，只训一个在六层注入的 Unified Scene Adapter。该 adapter 挂两路残差，世界分支吃 G-Buffer 加 bbox 且权重恒为 1，状态分支吃渲染 RGB 且由二值开关 λs​ 控制。推理时用嵌套式 SW-CFG 分别放大场景残差与天气增量残差。在 15066 条三源拼接的 HoloStateData 上训 3000 步后，Real 子集的三项控制误差 0.719 / 1.123 / 6.549 全面超过 Uni3C、GEN3C、VerseCrafter、NeoVerse，Weather 子集的 WA 86.00 / VLM 68.51 高于两个 V2V 基线。代价是 Weather 子集上它自己的控制误差退化到 1.681 / 1.745 / 6.744，而且与 V2V 的对比跨了输入设定。

3 句话版。 天气编辑此前看起来简单，是因为它总能拿到一段已经指定了未来结构的源视频。把设定收紧到只有一张首帧，同一套条件就得既指定几何又改写外观。Holo-World 的答案是把它们做成两路可开关的残差，并让 guidance 跟着同构地拆成两项。

1 句话版。 保住一个世界和改变它的天气，应该是同一个模型里两个能单独拧的旋钮。

§ 9 — 最脆弱的假设 ​

最要命的一条：场景结构与天气状态可以被干净地因子化成两层，所以一个乘 1 的几何分支加一个乘 0/1 的天气分支就够了。

它在实践中为什么可能不成立：天气不只是加在几何上的一层外观。雨会让地面产生镜面反射，改变可见的几何线索；雾按深度衰减对比度，直接抹掉远处结构；雪会改变几何本身，积雪覆盖路缘、屋顶与树枝的轮廓。从晴天到雨雪的映射并不保持场景的几何等价类。一旦天气分支必须去修改结构，而世界分支的监督是「维持 G-Buffer 所指定的几何」，两者会在同一批像素上给出冲突的梯度。

论文自己的数字就把这个冲突拍在了桌上，这也是全文比 abstract 多出来的关键证据。Table 4 里加入 UniSA 后，背景保真三项全面变好（PSNR 15.34→16.36、SSIM 0.577→0.598、LPIPS 0.329→0.308），同时 Weather Alignment 从 62.00 掉到 58.00。这正是因子化假设失效时应当出现的形状：结构分支变强之后，天气就变弱了。作者自己的措辞是结构分离会让模型对天气变得保守。后续把 WA 拉回 86.00 靠的是 SW-CFG，也就是推理时把天气残差乘上 sweather​=2。这意味着因子化并没有在训练中自发地成立，它需要一个推理期的手动增益来补偿。

另一条证据在附录 Table 7：Weather 子集上的 RotErr / TransErr / ObjMC 是 1.681 / 1.745 / 6.744，对比 Real 子集的 0.719 / 1.123 / 6.549，旋转误差翻了一倍多。开了天气分支，几何服从度就下降；两个子空间并非互不干扰。缺什么证据：没有任何一张图把 sweather​ 从 0 扫到 4 同时画出天气强度与控制误差两条曲线，也没有把 Snow 这种会改写轮廓的天气与 Rain / Fog 分开统计。没有这两张图，因子化到底掉到什么程度无法判断。

§ 10 — 最小复现实验 ​

不复现整个系统，只补上论文没报的那两张图。代码与权重已公开，这个实验只需推理，一周结束。

  • 样本。 取 benchmark 的 Weather 子集 50 条，按目标天气分成 Snow / Rain / Fog / Cloud 四组。
  • 扫描。 固定 sscene​=1.0，把 sweather​ 从 0 扫到 6（至少覆盖论文用的 2 与报了数的 4），其余推理配置按论文：81 帧、50 步、关掉 vanilla CFG。
  • 测两条曲线。 天气强度用论文自己的 Weather Alignment；几何服从度用 RotErr / TransErr / ObjMC 三项，而不是背景 PSNR/SSIM/LPIPS——后者只在有效静态区计算，对相机轨迹漂移不敏感。
  • 判据。 把两条曲线画在同一张图上。若天气强度到达可接受水平之前控制误差就已明显上升，则两个分支并未真正解耦，SW-CFG 只是把耦合推后。附加检验：对 Snow 单独重跑，看它的控制误差曲线是否比 Rain / Fog 更早抬头——如果是，就定位到了「天气改变轮廓」这一具体失效模式。
  • 第二个问题，成本更低。 论文选了 w=2 而不是在所有报告指标上都更好的 w=4，理由只有一张定性图。把上面扫出来的样本做一次盲配对人工评估（同 §7 的 User Study 协议），看人类是否真的在 w=4 上看到了过饱和。这是论文欠的一个数字。

§ 11 — 最强反例设计 ​

拿到全文之后，最有力的攻击不再是猜测，而是 Table 5 里一个可以直接指出的构造性恒等式。

第一层：「SW-CFG 不伤背景」不是实验发现。 Table 5 里 SW-CFG w=2 与 w=4 的背景 PSNR / SSIM / LPIPS 逐位相同，都是 18.12 / 0.624 / 0.245，与 w/o CFG 那一行也逐位相同。原因已在 §6 推过：这三项只在 Real 子集上算，而 Real 子集不给 weather prompt，λs​=0，天气项整个被乘没。不管 sweather​ 取多少，这三个数字都必然不变。把一个恒等式写进消融表当成证据，读者会误以为论文验证了「加强天气不会损伤保真」，而真正能回答这个问题的量是 Weather 子集上的控制误差随 sweather​ 的变化，而它一次都没被扫过。

第二层：超参选择没有数字支撑。 同一张表里 w=4 的 WA 96.00 / VLM 78.42 全面厉害过 w=2 的 86.00 / 68.51，背景三项又因上述恒等式完全相同。按已报告的数字，w=4 严格支配 w=2，而论文选了 w=2，理由只有 Figure 6 的定性截图。反对者只需问一句：报一个你自己不用的、且在所有指标上更好的配置，是否意味着指标本身测不到你实际在意的那个退化？如果是，那 WA 与 VLM 就不应该被当成天气赛道的主指标。

第三层：跨设定胜率的替代解释。 赢过 Wan2.7-Edit 与 Cosmos-Transfer2.5 的那一栏，I2V 在「天气特征是否明显」这类指标上有结构性优势：它可以自己合成一段本来就适合下雨的运动与构图，V2V 却被源视频锁死。反例实验：把 Holo-World 拉到 V2V 的设定下比——给它源视频首帧加从源视频真值恢复的相机轨迹与物体 bbox，只在与源视频时序对齐度可比的样本子集上比天气指标。若优势在这个子集上消失，原结论的解释是设定差异。

还有一类可预测的失败场景：整套结构条件依赖从单张首帧重建出来的 G-Buffer。在首帧几何本身难以重建的场景（大面积天空与水面、强反射玻璃幕墙、夜间低纹理），Depth Anything / UniDepth / MoGe 给出的深度与法向会退化成噪声或空洞，世界分支失去锚点，而这些恰恰是天气效果最显著、最常被展示的场景。论文未按重建质量分层报告过任何指标，无法判断这一层退化有多大。

§ 12 — Follow-up Research Idea ​

把「天气」从一个离散的目标状态标签重新 framing 成一个连续的、有物理参数的环境状态，并让世界模型对它做插值与外推。

(a) 驱动它的局限。 当前的设定是从一个状态跳到另一个状态：给一条天气指令（Snow / Cloud / Fog / Rain），输出对应状态的视频。这意味着模型学到的是四个（或若干个）离散模式之间的映射，而不是环境状态本身的连续结构。真实世界里天气是渐变的——雨会从零星变密再转小，雾会随时间和深度变化，日落会连续改变色温。一个只会在离散标签之间跳转的模型，无法生成「雨渐渐下大」这种最基本的环境动力学，也无法把状态与时间耦合起来。这在世界模型的语境下是个硬伤：世界模型的定义性能力就是预测状态如何演化。

(b) 可借鉴的邻域工具。 大气散射的物理模型（如经典的雾成像模型 I=Jt+A(1−t)，透射率 t=e−βd 由散射系数 β 与深度 d 决定）与可微渲染。这套模型的好处是它给出了少数几个有物理意义的连续参数（散射系数、粒子密度、光源方向与色温），并且天然是深度相关的——而 Holo-World 恰好已经有 rendered depth 作为条件。把天气条件从文本标签换成这组连续参数，天气分支就不再是「贴粒子」，而是在给定深度下解一个成像方程；插值与外推自动获得意义，因为参数空间是连续的。这也顺带缓解了 §9 的因子化问题：散射对结构的影响通过深度显式地传递，不再需要天气分支去偷偷修改几何。

(c) 第一个实验长什么样。 先不做完整模型。取一批带深度真值的仿真数据（HoloStateData 的 Simulation 子集正好合适），用物理散射模型在连续变化的 β 下渲染同一段轨迹，得到一组只有天气参数不同的配对视频。用它训练/微调一个以 β 为连续条件的天气分支，然后测三件事：其一，在训练见过的 β 上，生成结果与物理渲染的一致性；其二，在未见过的中间 β 上插值是否平滑且物理合理；其三，在单个视频内部让 β 随时间变化（雨渐大），看模型能否生成连续的天气演化而不是突变。第三项是当前离散标签方案根本无法尝试的能力，也是把「可控天气生成」真正推进到「环境状态建模」的分界点。
