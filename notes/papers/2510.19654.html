From Forecasting to Planning: Policy World Model for Collaborative State-Action Prediction ​

项内容
arXiv2510.19654
提交日期2025-10-22
作者Zhida Zhao, Talas Fu, Yifan Wang, Lijun Wang, Huchuan Lu（大连理工大学）
分类cs.CV, cs.AI, cs.CL, cs.RO
备注NeurIPS 2025 Poster
一句话把 action-free 的未来帧预测当成规划前的"预期感知"中间推理步骤，让同一个自回归 Transformer 先生成未来状态再据此输出轨迹，从而把世界建模的知识真正传导进规划，单前视相机即达到多模态方法的 PDMS 水平。

所属教程：世界模型

§ 1 — 研究问题与重要性 ​

驾驶世界模型被寄予厚望，但论文指出它们的潜力"基本没被释放"。作者把现状分成两代，并指出两代都有同一个空缺。

第一代（AdrivER-I、GAIA-1、Vista、DrivingDojo、Drive-OccWorld）是解耦的：世界模型负责预测下一状态和奖励，规划要另找一个策略模型。世界模型在这个范式里只是数据引擎或仿真器。

第二代（DrivingGPT、Doe-1、VaViM）试图统一：在一个自回归模型里交替生成图像 token 和动作 token。但作者的批评很锋利——统一只发生在架构和预测形式上，两个任务仍然是独立进行的：世界建模那一路追求条件在动作上的高保真下一帧，规划那一路是从视觉观测到动作的端到端映射，中间没有显式的知识传递。

这个空缺为什么重要？因为它决定了"统一"这件事到底有没有意义。如果 Pθ​(未来帧∣历史) 和 Pθ​(动作∣历史) 只是共享参数而互不依赖，那么统一带来的只是参数效率，不是能力提升。作者要回答的正是这个问题：这种统一能否、以及如何真正让规划受益。

§ 2 — 前人工作与不足 ​

端到端驾驶：早期用 BEV 表示（ST-P3、UniAD），后来转向稠密 3D 占据（OccWorld）或稀疏 query（SparseDrive、SparseAD）。作者的批评是手工设计的中间表示会限制泛化。近期引入 LLM/MLLM 做场景推理。

生成式世界模型：BEVWorld 和 WoTE 在 BEV 潜空间操作；Drive-OccWorld 预测未来占据与规划模块交互。视频生成侧分两类——扩散式（DriveDreamer 做可控生成、Vista 做大规模条件合成、GLAD 做任意长度、DriveDreamer-2 与 Drive-WM 做多视角）和自回归式（GAIA-1/2 把帧、文本、动作统一进单一序列，InfinityDrive 与 DrivingWorld 延长视频）。对自回归这一支，作者给出了本文动机的关键批评：逐 token 预测计算昂贵，对效率敏感的下游任务不实用。这直接推向了后文的并行 token 生成设计。

统一理解与生成模型：Show-o、Chameleon、Transfusion 这类 UMM 把视觉理解与生成放进同一个自回归或扩散范式。本文的骨干正是从 Show-o 初始化的。

作者对既有工作的批评落点不在"做得不够好"，而在动作条件依赖这件事上：既有方法学世界模型都靠 action-conditioned 视频生成，这不仅依赖带动作标签的数据（限制可扩展性），更致命的是在动作被预测出来之前它什么都预测不了。你没法先想象再决策，因为想象本身要以决策为输入。这是一个逻辑顺序上的死锁，此前没人明确指出来。

§ 3 — 重建作者的思考路径 ​

设想你在做统一的驾驶世界模型 + 规划器。你按 DrivingGPT 的方式交替生成图像 token 和动作 token，训练收敛，指标也还行。然后你问自己一个问题：如果我把视频生成那一支的损失关掉，规划性能会掉吗？ 你试了，发现掉得不多。这说明世界建模的知识根本没传导到规划上。

你回头看为什么。因为在推理时，动作是直接从历史观测预测的：Pθ​(A∣D1:t​)。未来帧那一路虽然也在生成，但它是条件在动作上的——先有动作才有未来帧。所以未来帧永远出现在动作之后，规划器不可能利用它。

这时你想到人类司机怎么做：变道前会先在脑子里过一遍"如果我现在并进去，那辆车会在哪"。想象在决策之前。要复现这个顺序，未来帧生成必须是 action-free 的——不依赖动作，只依赖历史观测。这样它就可以排在动作 token 之前，成为动作预测的上下文。

于是你把序列排成 {D1:t​,Et​,Xt​,Dt+1:t+n​,A1:m​}：历史帧、导航指令与自车状态、文本描述、预测的未来帧、最后才是动作。action-free 还有一个副作用红利——预训练不再需要动作标签，可以直接吃 OpenDV-YouTube 那 1747 小时的无标注驾驶视频。

新问题随之而来：在动作前面塞十几帧未来帧，逐 token 自回归的延迟根本无法接受。但你注意到一件事——你要的未来帧不是给人看的，是给规划器当推理依据的，不需要照片级细节。那就把每帧压到极少的 token，少到可以一次并行生成整帧，把"next-token prediction"换成"next-frame prediction"。压缩靠一个双分支 tokenizer：高分辨率分支处理首帧提供上下文，低分辨率分支借助跨注意力从前者取信息，用 28 个 token 表示一帧。

最后一个坑：训练时你发现相邻帧之间高达 50% 的 token 不变，模型学会了"照抄上一帧"这个捷径。解法是给变化的 token 加权——Dynamic Focal Loss。

§ 4 — 核心 Intuition ​

世界模型要帮上规划，未来预测就必须发生在动作之前；而要发生在动作之前，它就必须是 action-free 的。 既有的统一模型全都把未来帧条件在动作上，于是想象永远排在决策之后，规划拿不到任何前瞻信息。把这个顺序倒过来，未来帧就变成了动作预测的多模态推理依据（rationale），世界知识才真正流进策略。代价是延迟，解法是把每帧压到 28 个 token 一次并行生成——因为规划需要的是场景动态的骨架，不是像素细节。

§ 5 — 具体方法与完整 Pipeline ​

Tokenizer（上下文引导的压缩与解码）。双分支编码器-解码器。高分辨率分支 Qh​ 用预训练的 Show-o tokenizer，处理 256×448 的首帧 I1​，产出 L=448 个 token，训练时冻结；它的编码器与解码器同时产出多尺度中间特征 Fe​、Fd​。低分辨率分支 Ql​ 是结构镜像 Qh​ 的可学习网络，处理 128×224 的所有帧，每帧压到 4×7=28 个 token（L′≪L）。两分支通过 cross-attention 横向连接（Ql​ 的多尺度特征作 query，Qh​ 的作 key/value），编码器在 8×14 分辨率处、解码器在 8×14 与 16×28 处施加。另加一个轻量 MLP 做 latent 序列长度的 4× 上下采样。两分支各有大小 8192 的码本，按标准 VQ-GAN 策略训练，用 L1 重建损失并对靠后的帧加大权重（因为它们与首帧差异更大、更难预测）。

Action-free 预训练。视频片段编成 {Z1​,D1:N​}，Z1​ 是首帧上下文 token，Dt​ 是第 t 帧的压缩 token。因为整帧 token 可以一次并行生成，自回归退化为逐帧：P(D1:N​;Z1​)=∏t=2N​Pθ​(Dt​∣D<t​;Z1​)。帧内用双向注意力建模空间关系，帧间保持因果。在 OpenDV-YouTube 上跑 3×105 步，同时混入 CC12M 图文描述与 FineWeb 纯文本任务防止灾难性遗忘，batch 比例 3:1:1，损失权重 1.0 / 0.5 / 0.5。

规划微调。走一遍具体例子。夜间路口，自车需直行。输入是过去 1 秒的帧 token D1:t​ 加导航指令与自车状态 Et​（自车状态经两层 SiLU MLP 投影；导航指令用三个可学习嵌入表示"直行/左转/右转"）。模型先自回归产出文本 token Xt​ 描述当前场景（"In this quiet nighttime driving situation, the vehicle should maintain a moderate speed and continue straight, adhering to lane discipline."），再产出未来帧 token Dt+1:t+n​，然后把 m 个可学习的动作 token 喂进去，让它们与前面文本和未来帧的潜表示交互，最后由轻量动作头解码成轨迹坐标 A1:m​。文本与未来帧用交叉熵监督，轨迹用 L1。

配置：从 Show-o 初始化。tokenizer 在 OpenDV-YouTube 上训 8×105 步，6 张 A800，lr 2×10−4，训完冻结。nuScenes 微调：1 秒历史 → 11 帧 + 3 秒 6 个 waypoint，16 epoch，2 张 A800，batch 8，lr 3×10−5。NAVSIM：2 秒历史 → 10 帧 + 4 秒 8 个 waypoint，20 epoch，batch 14；该数据集缺少部分预测所需帧，作者从原始 nuPlan 重采样补齐。全程只用前视相机，无数据增强。

§ 6 — 核心数学推导 ​

并行帧生成的因子分解。标准自回归视频模型对每个 token 做条件分解，序列长度是 N×L。本文因为 L′=28 足够小，把整帧当作一个生成单元：

P(D1:N​;Z1​)=t=2∏N​Pθ​(Dt​∣D<t​;Z1​)

帧内不再有自回归依赖，因此用双向注意力。这一步把 N×L′ 次串行前向压缩成 N 次——延迟的节省不是常数因子而是数量级。

Dynamic Focal Loss。作者观察到相邻帧间高达 50% 的 token 完全不变，模型因此倾向于预测静态 token，损害时序动态建模。定义逐 token 权重

ω(dti​,dt−1i​)=αI[dti​=dt−1i​]+βI[dti​=dt−1i​],α>β

LDFL​=−i=1∑L′​ω(dti​,dt−1i​)logPθ​(dti​∣D<t​;Z1​)

这与 Focal Loss 的思路同构但判据不同：Focal Loss 按"预测置信度"降权易样本，DFL 按"时序是否变化"降权静态 token。两者共同的假设是损失被大量平凡样本主导，只是"平凡"的定义换成了"和上一帧一样"。附录固定 α=1.0 扫 β，β=0.4 最优（FVD 67.13、L2 0.78、碰撞率 0.07）；β=0.1 时权重差距过大导致未来帧预测过拟合而规划任务尚未收敛；β≥1.0 时 α≤β 使机制失效，生成质量明显下降。（需要指出，正文图 2 的说明写的是 "with DFL enabled (α=0.1, β=0.4)"，这与 α>β 的条件和附录 α=1.0 的设定互相矛盾，推测是笔误。）

协同状态-动作预测。这是全文的形式化核心。既有解耦方法分别建 Pw​(Dt+1:t+n​∣D1:t​) 和 Pθ​(A1:m​∣D1:t​)；既有统一方法虽共享 θ，但两条路径仍是 Pθ​(Dt+1:t+n​∣D1:t​) 与 Pθ​(A1:m​∣D1:t​)，动作的条件集里没有未来帧。本文改成

Pθ​(Dt+1:t+n​∣D1:t​)⋅Pθ​(A1:m​∣D1:t+n​)→Pθ​(Dt+1:t+n​A1:m​∣D1:t​)

差别只在第二项的条件从 D1:t​ 变成 D1:t+n​——动作现在条件在包含预测未来在内的完整序列上。这一个下标的改动就是"collaborative"的全部含义：世界知识通过预测出的未来状态这一中间变量流向动作，形成因果与知识共享关系，而不只是参数共享。

§ 7 — 实验设计与结论 ​

问题一：规划性能如何？ nuScenes 上分"不用自车状态"和"用自车状态"两档（因为该数据集场景简单容易过度依赖自车状态）。不用自车状态时，PWM 的 L2 平均 0.78 米、碰撞率 0.07%；碰撞率优于 Drive-OccWorld（0.11%）与 LAW（0.19%），但 L2 明显不如它们（0.47 / 0.49）。用自车状态时 L2 0.41、碰撞率 0.04%，DiffusionDrive 是 0.57 / 0.08%。作者的措辞聚焦碰撞率，这是诚实的——L2 并非本方法的强项。NAVSIM 上 PDMS 88.1，与用相机 + LiDAR 的 DiffusionDrive 持平，明显超过所有纯相机方法（UniAD 83.4、LTF 83.8、PARA-Drive 84.0、LAW 84.6）以及同为单前视的 DrivingGPT（82.4），而 PWM 只用单个前视相机。分项上 NC 98.6、TTC 95.4、DAC 95.9、Comf. 100.0。

问题二：action-free 预训练贡献多少？ 消融显示不预训练时 FVD 826.15、L2 3.34、碰撞率 1.51%；预训练后 FVD 降到 239.13、L2 2.29、碰撞率 1.05%；全配置（预训练 + 两阶段 DFL）到 FVD 67.13、L2 0.78、碰撞率 0.07%。NAVSIM 上 PDMS 从 77.8 提到 88.1。

更有说服力的是数据量实验，它揭示了一个非单调现象：预训练数据用 0% 时，加上未来帧预测任务反而损害规划（L2 2.95 vs 不预测的 1.62）；用 50% 时两者接近（0.85 vs 0.88）；用 100% 时预测版反超（0.78 vs 0.80）。这条曲线的含义是：未来预测作为中间推理步骤，只有当预测本身足够准时才有正收益，否则就是在给动作头喂噪声。这是全文最有信息量的一个结果。

问题三：DFL 有效吗？ 单独在预训练或微调阶段用都有改善，且只在预训练用时的 LPIPS/PSNR 优于只在微调用，说明大规模视频上的时空建模更依赖这个机制。两阶段都用最好。OpenDV-YouTube 上单独评测 FVD 从 211.26 降到 118.07。

问题四：预测多少帧最合适？ 预测 0/5/10/15 帧时 NAVSIM PDMS 为 87.3 / 87.7 / 88.1 / 88.0，nuScenes 碰撞率 0.13 / 0.10 / 0.07 / 0.09。10 帧最优。作者的解释是：更短的时程捕捉不到足够动态，更长的时程预测质量下降甚至产生幻觉（单前视相机的感知本就受限）反而损害决策。延迟方面，相对零时程基线的额外开销分别是 +0.13 / +0.28 / +0.40 秒，token 预测本身约 40 FPS（不含像素解码）。

问题五：未来预测改变了什么样的规划行为？ NAVSIM 上呈现明确的权衡——不做未来预测时 EP（沿路线推进距离）更高；做未来预测时 NC、TTC、DAC 更高。作者据此推断未来帧预测诱导出更保守的规划策略，牺牲部分推进换取安全裕度。

问题六：文本生成任务有用吗？ 三种设定（无文本 / 场景描述 / 动作描述）在生成与规划指标上差异微小。作者如实报告"在我们的设定下效果有限"——这是一个负面结果的诚实披露，因为文本推理这条线在 MLLM 驾驶工作里通常被宣传为关键。

表征分析：把预测的未来帧潜表示做 UMAP 投影，尽管每个样本的未来是独立生成、条件在不同输入帧上，投影后的嵌入仍呈现平滑连贯的时序动态。作者据此论证模型学到了与具体视觉内容解耦的运动模式。

§ 8 — Take-aways ​

5 句话版：PWM 指出既有"统一世界模型 + 规划"工作的统一只停留在架构层面——未来帧条件在动作上，因而永远排在动作之后，规划拿不到任何前瞻信息。解法是让未来预测变成 action-free 的：序列排成"历史帧 → 指令与自车状态 → 文本 → 预测未来帧 → 动作 token"，动作的条件集因此包含了预测出的未来，世界知识才真正传导进策略。为控制延迟，用双分支上下文引导 tokenizer 把每帧压到 28 个 token，从而整帧并行生成，把 next-token prediction 换成 next-frame prediction。Dynamic Focal Loss 给时序变化的 token 加权，解决相邻帧 50% token 不变导致模型学会照抄上一帧的问题。仅用单前视相机，NAVSIM PDMS 88.1 追平相机 + LiDAR 的 DiffusionDrive，nuScenes 碰撞率降到 0.07%/0.04%，但 L2 距离并非强项；且数据量消融显示，预训练数据不足时未来预测反而损害规划。

3 句话版：世界模型要帮上规划，未来预测必须 action-free 从而排在动作之前，成为动作预测的多模态推理依据。极端 token 压缩（28 token/帧）让整帧并行生成，使这个额外的推理步骤在延迟上可承受。收益是安全性（碰撞率、TTC、DAC）而非位移精度，且依赖大规模无标注视频预训练——预训练不足时未来预测是负资产。

1 句话版：想象要排在决策之前才算数，而这要求想象不依赖决策。

§ 9 — 最脆弱的假设 ​

最致命的一条：28 个 token 的压缩表示保留了规划所需的全部决策相关信息。

这是整套设计的支点。整篇论文的效率论证、并行生成、乃至"未来预测可以作为中间推理步骤"这个可行性，全部押在"规划不需要照片级细节"这个判断上。如果压缩丢掉了关键信息，那么未来帧这个中间变量就成了信息瓶颈——它不但帮不上忙，还会把动作预测锁死在一个降质的场景表示上。

它为什么可能不成立？4×7 的空间网格意味着每个 token 覆盖原图约 32×32 像素的区域（对应 128×224 输入）。在这个粒度下，远处的行人、自行车、刹车灯、转向灯、交通信号灯的状态几乎不可能被稳定编码——而这些恰恰是驾驶决策里权重最高的信息。论文自己的实验其实给出了旁证：PWM 的强项全在碰撞类指标（NC、TTC、碰撞率），弱项在 L2 位移精度；碰撞类指标主要由大尺度障碍物的存在与否决定，正是低分辨率 token 还能表达的东西。

论文提供了什么证据？重建指标（LPIPS 0.22、PSNR 23.07）和下游规划指标。这些是间接的：重建指标由大面积的道路、天空、建筑主导，小目标的丢失对 PSNR 影响微乎其微。缺的实验很明确——按目标尺寸或类别分层，测量压缩重建对小目标（行人、骑行者、信号灯）的保真度，以及在含这些目标的场景子集上的规划表现。作者在结论里承认单视角输入在低能见度下鲁棒性受限，但没有触及 token 数量这个更根本的瓶颈。

§ 10 — 最小复现实验 ​

一周内可完成，不需要预训练任何大模型：

  • 数据：nuScenes 验证集前视图像，配合官方 3D 标注。
  • 实现：只复现 §5 的 tokenizer——冻结的高分辨率分支可直接用 Show-o 的开源 tokenizer；低分辨率分支只需一个镜像结构加 cross-attention 与 4× 下采样 MLP，在 nuScenes 上小规模训练即可（不需要 OpenDV-YouTube 的 8×105 步，验证性训练足够）。完全跳过世界模型与规划器。
  • 测量：把每帧编码成 28 个 token 再解码回像素，在重建图上跑一个现成的 2D 检测器（如 YOLO 或 Grounding-DINO），与原图上的检测结果对比。按目标像素面积分箱（<32²、32²–96²、>96²）报告召回率保持率；单独报告交通信号灯与行人类别。
  • 判定：若大目标召回保持在 90% 以上但小目标掉到 30% 以下，说明 §9 的信息瓶颈真实存在，PWM 的安全收益应被限定为"避让大型近距离障碍"，对涉及远处弱势道路使用者的场景无效；若各尺度召回都保持较好，则该假设得到独立支持，压缩率还有进一步压榨空间。

这个实验只训一个 tokenizer 分支，且判据直接对应决策相关信息而非像素保真度。

§ 11 — 最强反例设计 ​

站在反对者立场，最有力的攻击是给出对全部收益的替代解释：PWM 的提升来自 1747 小时 OpenDV-YouTube 的大规模视觉预训练，而非"协同状态-动作预测"这个结构创新。

论据链条如下。第一，消融表里预训练本身贡献了最大的一跳：无预训练 → 有预训练，nuScenes L2 从 3.34 到 2.29、NAVSIM PDMS 从 77.8 到 80.7；而所有对比方法（UniAD、VAD、DiffusionDrive、LAW）都没有在这个量级的额外视频数据上预训练过。第二，也是更致命的一条——论文自己的 Table 4 显示，预测 0 帧未来时 NAVSIM PDMS 已经是 87.3，而完整方法是 88.1。也就是说，在同样完成了 action-free 预训练之后，把整个"未来帧作为中间推理"的机制彻底关掉，只损失 0.8 分。这 0.8 分要和 +0.28 秒的额外延迟以及整套 tokenizer 的复杂度对比着看。第三，数据量消融进一步支持这个解释：0% 数据时未来预测损害规划（L2 2.95 vs 1.62），50% 时基本持平（0.85 vs 0.88），100% 时才微弱反超（0.78 vs 0.80）。这条曲线完全可以解读为"未来预测任务的价值主要是作为预训练的辅助目标（表征学习），而不是作为推理时的中间步骤"。

这也给出了可预测的失败条件：在预训练数据规模受限、或目标域与 OpenDV-YouTube 分布差异较大（夜间、恶劣天气、非城市道路）的场景下，未来预测这个中间步骤应当退化为净负担。

判决性实验：做一个"预训练时用未来帧预测目标、推理时关闭未来帧生成"的变体（即 Table 4 的 0 帧行，但明确作为独立方法评估），与完整 PWM 在同等推理延迟预算下比较。若在放开延迟预算给基线（例如允许它用更大的模型或多次采样集成）后两者持平，则"协同预测"的结构价值被证伪，收益应归因于预训练。

§ 12 — Follow-up Research Idea ​

驱动局限：PWM 的未来帧生成是单一确定性 rollout——给定历史，生成一条未来，然后据此规划。但驾驶的核心难点恰恰是未来的多模态性：前方那辆车可能变道也可能不变道，路口那个行人可能过街也可能停下。用一条采样出来的未来做决策，等价于对一个高度不确定的分布取了一个样本点然后当作确定性事实。论文自己的观察间接印证了这个问题：预测时程超过 10 帧后性能下降，作者归因于"预测质量下降甚至产生幻觉"——而所谓幻觉，很大程度上就是模型被迫在多模态分布上给出单峰答案的产物。

新的 framing：不要问"怎么把未来预测得更准"，而要问"怎么让规划器对未来的分歧本身作出反应"。也就是把中间推理步骤从"一条未来"改成"一组分歧的未来 + 它们的分歧结构"，让动作 token 不只是条件在预测帧上，而是条件在未来的不确定性几何上。这与"多次采样取平均"有本质区别：平均会抹掉分歧，而分歧恰恰是最有信息量的部分——两条未来在 2 秒后开始分叉，说明那个时刻有一个关键的交互事件。

可借鉴的相邻工具：轨迹预测领域已经把多模态当作一等公民，有成熟的机制处理这件事——多模态输出头配 winner-takes-all 训练避免模式坍塌、模式覆盖率（minADE-k）作为评价指标、以及基于分歧的场景难度度量。另一条可借鉴的线是不确定性感知的模型基强化学习（MOReL / MOPO 那一系），它们把模型分歧直接写进策略优化目标作为悲观惩罚。PWM 的架构对此非常友好：帧内已经是双向注意力的并行生成，采样 k 条未来只是把这一步做 k 次，在 28 token/帧的成本下几乎免费。

第一个实验：不改架构，只改推理。对 NAVSIM 的每个场景用不同随机种子采样 k=8 条未来 token 序列，计算它们在 token 空间的逐帧分歧度（例如逐位置的熵或成对汉明距离），得到一条"分歧随时间上升"的曲线。检验两件事：(a) 这条曲线的斜率是否与场景难度相关——具体地，与 PWM 自身规划失败（NC 或 TTC 扣分）的场景是否显著相关；(b) 分歧开始陡增的时刻，是否对应人类标注中的关键交互事件。若 (a) 成立，分歧度就是一个免费的、无需额外标注的失败预警信号，可以直接接进规划器做保守性调节；若 (b) 也成立，说明模型的分歧结构确实编码了语义上有意义的决策点，那么把它作为显式的中间推理表示就有充分理由。这个实验只需推理，不需要重训任何模块。
