Hi Robot: Open-Ended Instruction Following with Hierarchical Vision-Language-Action Models ​

项内容
arXiv2502.19417
提交日期2025-02-26
作者Lucy Xiaoyang Shi, Brian Ichter, Michael Equi, Liyiming Ke, Karl Pertsch, Quan Vuong, James Tanner, Anna Walling, Haohuan Wang, et al.（共 15 位，末位 Chelsea Finn）
分类cs.RO, cs.AI, cs.LG
一句话用一个 VLM 做高层策略，把复杂 prompt 与实时人类插话翻译成 π₀ 能执行的原子指令，训练数据由「反向想象」得到——给 VLM 一帧观测和已标注的技能标签，让它编出可能导致该技能的用户指令与机器人应答。

所属教程：通用具身智能

版本说明

本文提交于 2025-02-26，最新版本为 v2（2025-07-15），ICML 2025 接收，本解读基于 v2 全文。全文所有任务性能结果均以柱状图呈现，无任何数值表格，因此本文只引用图注中明确给出的数字，不复述任何柱高。

§ 1 — 研究问题与重要性 ​

语言条件模仿学习已经能处理原子指令——"把杯子拿起来"。但现实里的指令长这样："能给我做个素食三明治吗？我不要番茄。另外如果有火腿或烤牛肉，能不能再给我朋友单做一个？"这类 prompt 需要三层能力叠加：解析语言、把命令落到当前物理场景（哪个是番茄、哪盘还没吃完）、以及组合已有技能去完成一个没见过的任务组合。更难的是执行中途的反馈——"不是这样做，你得再低一点，不然一直会抓空"、"那不是垃圾"——这些必须被动态整合进正在进行的执行。

这件事值得做，因为它决定了机器人是"可编程设备"还是"可交互伙伴"。一个只能执行原子指令的策略，其可用性上限由预置技能表决定；而一个能被实时纠正的系统，用户可以在部署现场引导它完成训练时不存在的任务变体。

§ 2 — 前人工作与不足 ​

第一类是直接把 VLM 微调成动作模型的 VLA（RT-2、OpenVLA、π₀ 等）。它们的泛化与指令跟随都不错，但训练用的语言标注基本是简单命令，模型没见过复杂 prompt，也没见过中途插话。

第二类是把 LLM/VLM 当高层规划器、下接预定义技能（SayCan、Code as Policies、VoxPoser、MOKA 等）。它们能处理复杂命令并结合视觉观测，但下层技能的物理灵巧度有限，且大多不支持与人的实时语言交互。

第三类是专门做交互纠正的工作，论文逐一点名并给出精确的差异：OLAF 用 LLM 修改机器人轨迹，但不能基于机器人当前观测做情境化纠正、也无法实时应答；YAY Robot 能做情境化实时纠正，但只支持单一 prompt，且纠正种类被人工写的数据框死；RACER 也能做情境化纠正，但依赖物理仿真器构造恢复行为，本文只用真机演示、且演示中不含刻意加入的扰动或纠正。

真正的缺口是数据：训练一个能处理开放式 prompt 的高层模型，需要「复杂 prompt → 当下该做的原子动作」这种配对样本，而机器人演示里只有原子技能标签。

§ 3 — 重建作者的思考路径 ​

出发点是 Kahneman 的 System 1 / System 2 二分：快而自动的技能执行，与慢而审慎的推理。已有的 VLA 是纯 System 1，已有的 LLM 规划器是纯 System 2 但下接的 System 1 太弱。既然 π₀ 这类 VLA 已经能可靠执行原子指令，最直接的做法就是在它上面再放一个 VLM，用自然语言做两者之间的接口。

架构层面到此没有新意，难点全在训练数据。高层策略要学的映射是 (图像,复杂 prompt)↦原子指令。图像有了（演示里就有），原子指令也有了（演示切分后的技能标签）。缺的只有复杂 prompt——而它恰恰是最难人工采集的那一半，因为要覆盖开放式表达就得穷举语言变体。

关键的一步是把因果方向反过来。人工采集是"先给 prompt，再采符合它的演示"；论文改成"已有演示片段，让 VLM 反向想象出可能导致它的用户互动"。给一个先进 VLM 看当前观测 + 目标原子指令（"拿一片生菜"），让它编出一段合理的前情：用户可能说了"能给我加点生菜吗"，机器人可能回答"好的"。这样生成的 prompt 天然是情境化的（因为 VLM 看得见画面），也天然落在机器人能力范围内（因为目标指令来自真实演示）。

§ 4 — 核心 Intuition ​

复杂 prompt 的训练数据可以从答案倒推题目：机器人演示已经提供了"正确答案"（该做哪个原子动作）和"考场环境"（当前图像），只需要让一个大 VLM 编出一道能导致这个答案的题。这样合成出来的题既多样又不脱离机器人的真实能力边界——而直接让 VLM 自由生成任务，或让人穷举 prompt 变体，都做不到这两点兼得。

§ 5 — 具体方法与完整 Pipeline ​

以"清理餐桌"为例走一遍。

推理时：高层策略 phi(ℓ^t​∣It1​,…,Itn​,ℓt​) 吃基座相机与腕部相机图像、以及开放式 prompt ℓt​（"只收垃圾，别动盘子"），输出一条原子指令 ℓ^t​（"把纸杯放进垃圾桶"）。低层策略 plo(At​∣It1..n​,ℓ^t​,qt​) 是 π₀，吃同样的图像加关节状态，用 flow matching 输出连续动作 chunk。两者频率不同：低层高频出 chunk，高层每过一秒、或一旦有新的用户互动就重跑。高层可以在 ℓ^t​ 里附一段口头回应 ut​，经 TTS 播给用户后从传给低层的指令中剥掉。用户中途说"那不是垃圾"，立即触发高层重推理——因为高层同时看得见画面，它能把这句话 grounding 到手里正拿着的那个碗上，纯语言系统做不到这一点。

训练时：先遥操采演示 Ddemo​（只有粗粒度总目标标注），切成 1–3 秒的短技能得到 Dlabeled​，并从原始动作里启发式抽取基础运动原语（"把右臂往左移"）。再用大 VLM pgen 生成 Dsyn​：条件里不只有当前图像与目标技能 ℓ^t​，还包括该 episode 内此前所有技能标签 ℓ^0​,…,ℓ^t−1​，以保证多步任务中生成的用户命令前后连贯（已经放过生菜和番茄，接下来该请求的是别的配料）。prompt 设计上做了结构化的场景分类（negative task / situated correction / specific constraint）与应答分类（确认 / 澄清 / 错误处理），以保证互动类型的覆盖面。高层用交叉熵在 Dsyn​∪Dlabeled​ 上训，低层用 flow matching 在 Dlabeled​∪Ddemo​ 上训。

实现：高低层同用 PaliGemma-3B 起点，低层即 π₀（多一个 flow matching 动作专家）。AdamW，β=(0.9,0.95)，无 weight decay，梯度裁到 1，EMA 衰减 0.999，1000 步 warmup 后恒定 lr 1×10−5，batch 512。高层训练只需 8×H100 约 2 小时。语音用 Whisper large-v2 转写、Cartesia 合成。推理在 1–2 张 RTX 4090 上：低层单步 73 ms（板载）、高层单次解码 47 ms prefill + 13.2 ms decode（4090）或 17.3 + 5.7 ms（H100），配合 action chunking 可支撑 50 Hz 控制。

§ 6 — 核心数学推导 ​

本文无形式化数学推导，跳过。方法层面唯一的形式化是策略分解 p(At​∣ot​) 被拆成 phi(ℓ^t​∣⋅) 与 plo(At​∣ℓ^t​,⋅) 两个自回归/流匹配模型的串联，二者之间的接口是自然语言而非隐向量；论文没有为这一分解给出概率上的推导或界。

§ 7 — 实验设计与结论 ​

三个域：Table bussing（单臂 UR5e，收拾餐桌，需要区分可重复使用的塑料杯是餐具、纸杯是垃圾）、Sandwich making（双臂 ARX，最多六种配料 + 面包，处理易变形食材）、Grocery shopping（移动双臂 ARX，从货架取物放进篮子再放到桌上）。评测 prompt 包括"只收垃圾不收盘子"、"把所有偏黄的东西收走"、"做个素食三明治，我对腌黄瓜过敏"、"给我拿点甜的"，以及中途插话"这不是垃圾"、"剩下的别管了"、"我还想要个 KitKat"。

两个指标由对方法双盲的人类评估员打：Instruction Accuracy（高层预测的指令是否同时与用户命令和当前观测一致，按一次 trial 内正确预测占比算）与 Task Progress（正确放置的物体比例）。每方法每任务 20 次 trial。

对照组设计得很全：Expert human high level（人替代高层，用来标定低层策略的能力上限）、GPT-4o high-level（同样的分层结构但高层换成 GPT-4o，prompt 里按人工标注数据中最常见的技能标签排序给出可选动作，相当于 SayCan 的 VLM 加强版）、Flat VLA（纯 π₀，无高层无合成数据）、Flat VLA with synthetic data（把合成数据加进低层训练，用来把"分层"与"合成数据"两个因素分开）、Hi Robot without synthetic data（可视为 YAY Robot 的 VLM 版）。

结论：Hi Robot 在三个域上 IA 与 TP 都明显更高，图 5 图注给出的唯一数值是平均 IA 比 GPT-4o 高 40% 以上。GPT-4o 的典型失败是物理交互一开始就丢上下文，发出"pick up bermuda triangle"这类无意义指令，或把所有东西都叫 plate/spoon；也会在夹爪还占着时命令去抓新物体。Expert human high level 下低层几乎无失误，说明失败主要来自推理而非执行。去掉合成数据后，模型仍能与画面对齐，但会忽略用户约束（照样加腌黄瓜、无视"这不是垃圾"）。Flat VLA 即使吃了合成数据，也倾向退回默认行为（把所有东西都收走、把所有配料都加上），说明把推理单独拎出来对多步一致性有价值。

附录 C.4 自陈的失败模式很具体：高层缺记忆，长上下文推理吃力；低层会临时无视指令——离奶酪近时会去抓，尽管用户说了乳糖不耐（作者归因于训练数据偏向就近物体）；以及误差累积与掉落物体后的 OOD 恢复。

§ 8 — Take-aways ​

5 句话版：开放式 prompt 与实时反馈需要 System 2 式推理，而现有 VLA 只有 System 1。Hi Robot 在 π₀ 之上叠一个同架构的 VLM 高层，两者以自然语言为接口，高层每秒或每次用户插话时重跑。训练高层缺的是「复杂 prompt → 原子指令」配对，作者用反向想象补齐：给大 VLM 看观测 + 已知技能标签 + 该 episode 此前的技能序列，让它编出可能的用户互动。三个真机域上 IA 与 TP 均优于 GPT-4o 高层与扁平 VLA，图注称 IA 平均高 40% 以上。消融显示合成数据负责"听懂约束"、分层负责"多步一致性"，两者不可互相替代。

3 句话版：把复杂指令的推理与动作执行拆成两个同架构 VLM，用自然语言当接口。训练高层的数据靠"从答案倒推题目"合成，从而既多样又落在机器人真实能力内。真机三域上显著优于 GPT-4o 高层与扁平 π₀，但全部结果只有柱状图。

1 句话版：机器人演示已经给了正确答案和考场，让大模型去编题目，就能把开放式指令跟随的训练数据造出来。

§ 9 — 最脆弱的假设 ​

最致命的一条是：由 VLM 反向想象出的用户互动，与真实用户会说的话属于同一分布。整个高层策略的开放式能力完全来自 Dsyn​，而 Dsyn​ 是一个模型对"人可能会怎么说"的先验采样，不是人类语言的样本。

它在实践中为什么可能不成立？生成过程是条件在正确答案上的：VLM 知道下一步该拿生菜，才去编"能加点生菜吗"。这使得合成 prompt 系统性地偏向信息充分且与当前最优动作强对齐的表达。真实用户的插话则常常是欠指定的（"不对，另一个"）、延迟的（在错误已经发生两秒后才出声）、或与当前最优动作无关的（突然改主意）。更麻烦的是，pgen 和 phi 都是 VLM，二者共享大量语言先验——合成数据里"用户会怎么说"和高层"以为用户会怎么说"来自同一族分布，这种自洽不构成对真实分布的证据。

论文为它提供了什么证据？间接的：合成数据消融显示去掉它模型就无视约束，说明合成数据确实教会了模型某种东西；以及三个域的真机评测里由人类评估员给分，评测 prompt 由作者撰写。缺什么证据？没有独立用户群体撰写的 prompt 测试集。20 次 trial × 3 任务的评测 prompt 全部出自作者，与合成数据的设计者是同一批人，因此无法排除"评测 prompt 恰好落在合成分布内"。附录 A.1 明说场景类型与应答类型是按预设分类生成的，而评测用的插话（"这不是垃圾"、"剩下的别管了"）正好逐一对应 negative task / situated correction / specific constraint 这三类。

§ 10 — 最小复现实验 ​

一周内、不需要机器人：

  • 只复现高层策略的评测部分。收集三份 prompt 集：(A) 论文风格的、由熟悉系统的人撰写；(B) 由不了解机器人能力的外部人员针对同一批场景照片撰写；(C) 从 (B) 中筛出那些欠指定的（不足以唯一确定下一动作）。
  • 把三份 prompt 配同一批静态观测帧，请人标注"此刻正确的原子指令"，用 Instruction Accuracy 评一个自建的分层高层（PaliGemma-3B 在按 §5 方式合成的数据上微调）与 GPT-4o 基线。
  • 判据：若 (A) 与 (B) 的 IA 差距很小，支持"合成分布覆盖真实分布"；若差距显著（比如 20 个点以上），则论文的开放式能力主要是在自家 prompt 分布上验证的。(C) 上两个方法都应显著下降，若某方法不降，需要检查它是不是在忽略 prompt 直接按视觉默认行为输出。

§ 11 — 最强反例设计 ​

论文把优势归因于"分层 + 合成数据"。一个同样能解释全部数据的替代解释是：GPT-4o 基线被系统性地削弱了。它被要求从"人工标注数据中最常见的技能标签"排序出的列表里选，而 Hi Robot 的高层是在这些标签上直接微调过的——前者要在推理时用 in-context 的方式匹配一套它从未见过的技能命名习惯，后者把这套命名习惯烧进了权重。论文报告的 GPT-4o 典型失败（输出"pick up bermuda triangle"、把所有东西叫 plate）恰恰是标签空间不匹配的症状，而不一定是推理能力不足的症状。

干净的攻击实验：给 GPT-4o 同样的少样本示例（从 Dlabeled​ 里检索当前场景最相似的 k 帧及其技能标签放进上下文），并强制其输出被约束解码到合法技能标签集合内。如果这样处理后 GPT-4o 的 IA 大幅上升、与 Hi Robot 的差距从"40% 以上"缩到十几个点，那么本文的主张就要改写为"微调把技能词表烧进权重比 in-context 更高效"，而不是"需要合成互动数据来学推理"。

另一类可预测的失败在时间维度：高层固定每秒重跑一次，而低层的原子技能长 1–3 秒。这意味着同一个技能执行期间高层会重推理 1–3 次，每次都可能因为画面微小变化而输出不同指令，造成技能被中途打断；反过来，用户插话若发生在一次重推理的间隙末尾，最坏要等接近一秒才被响应。论文只报告了这个固定频率"效果不错"，没有做频率扫描，也没有报告指令抖动率。

§ 12 — Follow-up Research Idea ​

论文把高层与低层完全解耦：高层不知道低层的成功率，低层不知道自己被要求做的事有多难。作者自己在讨论里点了这一点，但给出的方向是"让高层意识到低层完成得如何"，这仍是把它当作反馈信号。

一个非增量的重构是把接口本身变成可协商的：让低层策略对高层指令输出一个"可执行性"信号，并允许高层据此改写指令而不是改变目标。

(a) 驱动它的局限：附录 C.4 自陈低层会"临时无视指令"（离奶酪近就去抓），这说明失败并非总是高层推理错，而是高层发出的指令落在低层能力分布的稀薄处。当前架构下这类失败对高层完全不可见，因为高层只看图像、看不见低层的动作分布。 (b) 可借鉴的邻域工具：语言模型解码里的受约束生成与拒绝采样。低层的 flow matching 动作专家在给定指令下会诱导一个动作分布，其条件熵/多峰性可以作为"这条指令在当前观测下是否明确"的代理量；高层则在若干候选指令上做一次 best-of-n，选熵最低的那条——这等于把 SayCan 的 affordance 打分从一个外挂的价值函数换成低层策略自身的不确定性。 (c) 第一个实验：不改任何训练，只在推理时让高层采样 4 条候选原子指令，用低层动作分布的散度给它们打分选一条。在 Table bussing 的"只收垃圾"设定上评 IA 与 TP，并单独统计"离目标物体近但被禁止触碰"这类样本的错误率。若这类错误显著下降而整体 TP 不降，说明低层的不确定性是可用的 affordance 信号，从而在不引入任何新监督的前提下把两个 System 耦合起来。
