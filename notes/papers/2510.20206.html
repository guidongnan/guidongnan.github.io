RAPO++: Cross-Stage Prompt Optimization for Text-to-Video Generation via Data Alignment and Test-Time Scaling ​

项内容
arXiv2510.20206
提交日期2025-10-23
作者Bingjie Gao, Qianli Ma, Xiaoxue Wu, Shuai Yang, Guanzhou Lan, Haonan Zhao, Jiaxuan Chen, Qingyang Liu, Yu Qiao, Xinyuan Chen, Yaohui Wang, Li Niu
分类cs.CV
一句话先用训练语料建的关系图把用户 prompt 拉回训练分布，再在推理时用 VLM/verifier/光流的多源反馈闭环迭代重写 prompt，最后把迭代出的 prompt 对回灌去微调重写器 LLM——三阶段全部不动生成主干。

所属教程：物理感知视频生成

版本说明

本文基于 v2（2026-05-14 修订）正文撰写。v2 是 CVPR 2025 会议版 RAPO 的期刊扩展，新增了 Stage 2 SSPO 与 Stage 3 LLM 微调。arXiv 页面标注该文与 arXiv:2504.11739 存在文字重叠。

§ 1 — 研究问题与重要性 ​

T2V 模型的一个尴尬事实是：同一个模型，喂不同写法的 prompt，输出质量可以差出一个档次。原因不神秘——训练语料里的 caption 有它固定的长度分布、句式结构和用词习惯，而真实用户输入往往只有七八个词、结构松散。推理时的输入分布和训练时对不上，模型的生成能力就发挥不出来。

论文把这个问题定义为训练-推理 prompt 分布错配，并主张它可以在不改动生成主干的前提下解决。这件事的价值是杠杆式的：T2V 主干动辄十几 B 参数、训练成本极高，而 prompt 层的改造几乎免费，且能横跨 UNet 系（LaVie）与 DiT 系（Latte、HunyuanVideo、CogVideoX、Wan2.1）通用。论文进一步把这套机制推到物理合理性上——在 SSPO 循环里插入光流评估器，让 prompt 优化直接服务于 PhyGenBench / VideoPhy 上的物理一致性。

§ 2 — 前人工作与不足 ​

T2I 侧的 prompt 优化已经成熟：Promptist（Hao et al., 2023）用强化学习训练一个 prompt 改写器去最大化美学奖励，PAE（Mo et al., 2024）动态调节每个词的权重与注入时间步，Tailored Visions（Chen et al., 2024）利用用户历史交互个性化改写。论文指出这些方法的共同问题是只管图像：已有研究表明它们对视频的时序维度（运动平滑度、闪烁）几乎没有帮助。

T2V 侧的现有做法主要是"让 LLM 把短 prompt 写长"（CogVideoX、Open-Sora 的 Prompt Refiner）或蒸馏一个轻量改写器（Movie Gen）。论文的批评很具体：这些方法model-specific，缺少可跨模型迁移的系统性策略；而且 LLM 自由发挥出来的长 prompt 往往过度堆砌细节与生僻词汇，反而离训练分布更远，造成 over-specification。论文在 Fig. 8 的 prompt 长度分布分析里给了这个批评的经验支撑。

那为什么不直接把 T2I 的 RLHF 配方搬到 T2V？论文解释了这个"X 为什么没被考虑"：RLHF 依赖大量 generator rollout 来估计奖励，而视频生成单次推理成本远高于图像，且奖励必须覆盖时序结构——把 PPO/GRPO 那一套照搬到 T2V 在算力上不现实。这正是本文选择"检索对齐 + 测试时反馈"而非"策略梯度"的原因。

§ 3 — 重建作者的思考路径 ​

只用 2024 年底已有的知识，推演路径大致如下。

先接受一个当时已被反复观察到的现象：长而详细的 prompt 通常比用户原始短句效果好。但如果只到这一步，做法就是"叫 GPT-4 扩写"，而这已经被试过且效果有限。于是必须问：长成什么样才有用？

这时一个关键的换位是：不要问"什么样的描述更丰富"，而问"训练集里的 caption 长什么样"。因为扩散模型学到的条件分布 p(v∣c) 只在训练 caption 的支撑集上被良好估计，落到支撑集外就是外推。这个视角一旦确立，"检索训练语料里的修饰词"和"用微调 LLM 把句子重排成训练格式"就都是自然推论——这就是 Stage 1（RAPO，CVPR 2025 会议版）。

再往下推：即使 prompt 落回了训练分布，它对这一条具体 prompt是不是最优仍然未知，因为不同 prompt 的失败模式不同（有的丢物体、有的抖动、有的物理不合理）。既然 RLHF 太贵，那就把"反馈"从训练时挪到推理时——生成一个视频、用 VLM 和一组 verifier 打分、把分数写回 prompt、再生成。这是 LLM 领域已经成熟的 reflection / test-time scaling 范式的迁移，也是 Stage 2。

最后一步是纯工程直觉：Stage 2 每条 prompt 都要跑好几轮推理，太贵；但它天然产出了大量 (ρu,ρb) 配对数据，正好可以拿去 instruction tuning，把迭代出来的模式固化进 LLM 参数——Stage 3。

§ 4 — 核心 Intuition ​

好 prompt 的标准不是"信息更多"，而是"更像模型训练时见过的句子"。所以第一步是把用户输入检索-重排回训练分布，而不是让 LLM 自由发挥地堆细节。第二步承认：分布对齐只解决共性问题，每条 prompt 的个性化缺陷得靠"生成一次、看一眼、改一次"的闭环反馈补，而这个闭环放在推理时比放在训练时便宜得多。第三步，闭环跑出来的改进不该被扔掉，它本身就是最好的微调数据。

§ 5 — 具体方法与完整 Pipeline ​

以论文自己的例子 "a woman representing a funeral" 走一遍。

Stage 1 · RAPO，三个模块：

  • Word Augmentation。先离线用 Mistral 从 Vimeo25M（2500 万文本-视频对）的每条训练 caption 中抽出 scene 及其 subject / action / atmosphere 三类修饰词，scene 作核心节点、修饰词作子节点，构成 relation graph G。论文从 Vimeo25M 中筛出约 2.1M 条有效句子。在线时用 all-MiniLM-L6-v2 把用户 prompt 编码，余弦相似度检索 top-k scene，再从这些 scene 挂的修饰词里取 top-k，通过 LLM 逐个合并进原句。例子中检索到 "a black suit"，合并结果是 "a woman dressed in a black suit representing a funeral"。
  • Sentence Refactoring。一个 LoRA 微调过的 LLaMA 3.1（Lr​）把增广后的句子重排成训练 caption 的长度与格式。训练数据约 86k 对，是反向构造的：拿真实训练 prompt ci​，用冻结 LLM 把它改写成"破坏格式但保语义"的 wi​，于是 (wi​,ci​) 就是天然的重排监督对。
  • Prompt Selection。另一个微调 LLM（Ld​，判别器）在重排结果 xr​ 和"直接叫 LLM 扩写"的朴素结果 xn​ 之间二选一。它的标签来自实际生成视频后按维度评测的胜负，训练数据是用 Mistral 生成的 7K caption，覆盖 VBench 全部维度。

Stage 2 · SSPO（测试时闭环）：RAPO 输出 ρir​ → T2V 模型生成视频 vi​ → 三路反馈：LLaVA-OneVision 检测 vi​ 与原始用户 prompt ρiu​ 的语义错位 M，一组 verifier 给出空间保真、时序连贯、语义对齐的综合分 S，可选的任务专用分支 O（物理场景下是光流预测，用于查动量传递与轨迹一致性）。三路信号写进 feedback memory 数据库，Qwen2.5-7B-Instruct 结合历史记录与当前反馈重写 prompt，进入下一轮。多轮候选用 average ranking 选出最优 ρib​。

Stage 3 · LLM 微调：用 Stage 2 产出的 {(ρiu​,ρib​)} 做 instruction tuning（LoRA，LLaMA 3.1，rank 64，batch 32，单卡 A100，每轮约 5 小时），让改写器在推理前就能直接给出高质量 prompt，降低测试时开销。

§ 6 — 核心数学推导 ​

论文的形式化很轻，但三处值得说清。

迭代式修饰词合并。检索到的 k 个修饰词不是一次性塞进去的，而是逐个融合：

xim+1​=f(xim​,pim​),m=0,1,…,k−1

其中 xi0​ 是原始 prompt，f 是由冻结 LLM 按 few-shot 模板实现的合并算子。为什么要逐个而非一次性？直觉是：LLM 在"把一个短语自然地嵌进一个句子"这种局部任务上远比"同时嵌入五个短语并保持句子通顺"可靠，逐步合并把一个高维组合问题拆成 k 个一维问题，每步都能保住原句语义。论文的消融也间接支持这点——把 GPT-4 抽出的修饰词一次性合并，效果低于逐步合并。

多 verifier 聚合。K 个 verifier 各给一分 sk​，聚合为

S(vi​)=K1​k=1∑K​sk​

这是最朴素的等权平均。对不熟悉的读者补一句背景：视频质量没有单一可信指标，CLIP 类分数管语义、光流类指标管运动、帧间特征距离管闪烁，任何单一指标都可以被针对性地"刷"高。平均是在没有先验权重信息时最保守的组合方式。

Average Ranking 选择。候选 prompt 不按聚合分数选，而是先在每个指标上排名，再取平均名次最低者。这是有意为之：分数的量纲和尺度在不同指标间不可比（一个是 0–1 的余弦相似度，一个是几十的 FVD），直接平均会被尺度大的指标主导；换成名次相当于做了一次秩变换，只保留序信息，从而降低单指标偏置。这是一个小但正确的设计。

需要指出：论文没有给出任何收敛性论证，SSPO 的迭代没有理论保证会单调改进，它靠的是经验上"每轮平均分上升"这一实验事实。

§ 7 — 实验设计与结论 ​

问题一：分布对齐真的比"扩写"更管用吗？ 设计：在 LaVie 与 Latte 上，把 RAPO 与 Naive / GPT-4 Refiner / Prompt Refiner / Promptist / PAE 五个基线在 VBench、T2V-CompBench、EvalCrafter 上对比。答案：管用，且差距集中在组合性维度。LaVie 的 VBench 总分 80.89% → RAPO 82.38% → RAPO++ 82.65%；Latte 77.03% → 79.97% → 80.75%。最戏剧性的是 multiple objects 维度：LaVie 从 37.71% 涨到 64.86%（RAPO）再到 71.89%（RAPO++），Latte 从 29.55% 到 52.78% 再到 55.38%。相比之下，GPT-4 Refiner 在 LaVie 上把总分拉低到 79.69%——这是论文那句"verbose descriptions lead to over-specification"最直接的证据。

问题二：为什么分布对齐有效？ 设计：统计训练集 caption、用户 prompt（VBench/EvalCrafter/T2V-CompBench 模拟）、各方法优化后 prompt 的词长分布。答案：RAPO 的分布最贴近训练集，其他方法明显偏长。这是全文最有说服力的机制性证据，把"有效"和"因为像训练数据"直接连了起来。

问题三：测试时迭代能推进到物理合理性吗？ 设计：在 HunyuanVideo、CogVideoX-5B、Wan2.1 上，把光流评估器接入 SSPO，在 PhyGenBench 与 VideoPhy 上跑四轮迭代。答案：能，且单调。PhyGenBench 上 HunyuanVideo 的物理一致性 PC 从 0.38 逐轮升到 0.57、语义对齐 SA 从 0.24 到 0.42；CogVideoX-5B 的 PC 0.34→0.53，Wan2.1 的 PC 0.40→0.50。VideoPhy 的 solid-solid 类别上 HunyuanVideo 的 PC 0.28→0.40、SA 0.41→0.65。三个模型、两个 benchmark、所有交互类型上趋势一致。

问题四：三个组件各自贡献多少？ VBench 上 RAPO 内部消融：只用 word augmentation 80.37%，只用 sentence refactoring 79.75%（低于原始 LaVie 的 80.89%，说明单独重排会掉分），两两组合 80.60%–81.75%，三者齐全 82.38%。T2V-CompBench 上 Stage 2/3 消融：都不用 0.620/0.232/0.483/0.760，只加 SSPO 0.629/0.236/0.542/0.778，只微调 LLM 0.659/0.253/0.552/0.835，两者都有 0.742/0.294/0.632/0.849。可以看出微调 LLM 的单独贡献大于 SSPO，两者叠加才有大幅跃升。

问题五：换 LLM 会崩吗？ GPT-4 82.38%、Mistral 82.25%、LLaMA 82.10%，差异极小，说明收益主要来自 relation graph 与流程设计，而非某个特定 LLM 的能力。

代价：几轮测试时迭代把推理时间推到单次的约 3 倍，换来 VBench 16 个维度平均 3.5%、T2V-CompBench 4 个维度平均 18.1% 的提升；LLaVA-OneVision 额外约 2GB 显存相对 T2V 主干可忽略。

已知失效：数量词。"five colorful parrots"、"three majestic giraffes" 这类明确计数的 prompt，生成帧数量对不上。论文归因于 T2V 模型把数值信息与整体语义混淆，以及 SSPO 缺少计数感知的细粒度反馈。

§ 8 — Take-aways ​

5 句话版：RAPO++ 主张 T2V 的 prompt 优化目标不是"写得更详细"，而是"落回训练分布"，为此用 Vimeo25M 建的 scene-modifier 关系图检索修饰词、用微调 LLM 重排句式、用判别器在重排版与朴素扩写版之间择优。第二阶段 SSPO 把 RLHF 那套反馈搬到推理时：生成视频、用 VLM 查语义错位、用 verifier 组打质量分、物理任务再加光流分，写进 memory 后让 LLM 反思重写，多轮候选用平均名次择优。第三阶段把 SSPO 产出的 prompt 对回灌去做 instruction tuning，把迭代能力固化进参数以省下测试时开销。实验覆盖 5 个 T2V 模型和 5 个 benchmark，VBench 总分在 LaVie 上 80.89%→82.65%，multiple objects 从 37.71% 冲到 71.89%，PhyGenBench 上四轮迭代把 HunyuanVideo 的物理一致性从 0.38 推到 0.57。代价是约 3 倍推理时间，且数量词生成依然失败。

3 句话版：把用户 prompt 检索-重排回训练语料的分布，再用推理时的多源反馈闭环逐轮改写，最后把改写结果回灌微调 LLM。全程不动生成主干，跨 UNet 与 DiT 架构通用。最有说服力的证据是 prompt 长度分布分析与组合性维度上的巨大增益。

1 句话版：让 prompt 说模型训练时听惯的话，再让模型自己看片子改台词。

§ 9 — 最脆弱的假设 ​

最致命的假设是：训练 prompt 的分布是可获取、且是正确的优化目标。

前半段的脆弱性是工程性的。整套 Stage 1 的地基是 Vimeo25M——它恰好是 LaVie 和 Latte 的训练集之一，所以关系图是"内部知识"。但 HunyuanVideo、CogVideoX、Wan2.1 的训练语料并不公开，论文却把同一套 RAPO 应用到它们身上。这意味着对这三个模型而言，"对齐训练分布"这一机制在原理上就不成立，收益只能来自别的东西（更可能是 Stage 2 的反馈闭环和 Stage 3 的微调）。论文没有为此做区分实验——它没有报告"RAPO 单独用在闭源语料模型上"的效果，因此无法排除在这些模型上 Stage 1 是无效甚至有害的。可以推断，论文在物理感知实验里只报告 SSPO 迭代曲线而未报告 Stage 1 的独立贡献，与这一点是一致的。

后半段的脆弱性更根本：训练分布是能力上界的近似，不是质量的定义。如果训练 caption 本身系统性地缺少某类描述（例如精确计数、精确的物理量），那么把 prompt 往这个分布上拉，等于把用户意图往模型的盲区里压。论文自己报告的数量词失败恰好是这个机制的直接后果——但论文把它归因于"T2V 模型混淆数值与语义"和"SSPO 缺计数反馈"，没有考虑另一种解释：是 RAPO 的分布对齐把数量信息稀释掉了。这是一个未被检验的替代解释。

§ 10 — 最小复现实验 ​

一周内可做、不需要复现三个阶段：

  1. 只做 Stage 1 的最小版。取 LaVie（有公开权重）与 Vimeo25M 的一个 100k 子集。用任意开源 LLM 抽 scene/modifier 建一个小关系图，跳过所有微调（refactoring 与 discriminator 都用冻结 LLM 的 few-shot 版本近似）。
  2. 构造三组 prompt：(a) VBench 原始 prompt；(b) 冻结 LLM 自由扩写；(c) 关系图检索 + few-shot 合并。
  3. 先测代理指标，不生成视频：用 sentence transformer 计算三组 prompt 与训练子集 caption 的分布距离（词长分布的 Wasserstein 距离 + 句向量的 MMD）。这一步几分钟就能跑完。
  4. 再抽小样本生成：每组各取 100 条 prompt，在 LaVie 上各生成 1 个视频，只测 VBench 的 multiple objects 与 spatial relationship 两个维度（论文提升最大的维度）。
  5. 判据：若 (c) 的分布距离显著小于 (b)，且 multiple objects 分数排序为 (c) > (a) ≥ (b)，则复现了论文的核心机制链条；若 (c) 分布更近但分数不占优，则说明"分布对齐 → 质量提升"这条因果链需要额外条件；若 (b) 也能提分，则论文对基线的批评被削弱。

关键设计是先测分布距离再测生成质量，因为前者几乎免费，能在花 GPU 之前就证伪或支持核心机制。

§ 11 — 最强反例设计 ​

最有力的攻击是给出一个替代解释：RAPO++ 的增益可能大部分来自"多次采样后择优"这个搜索行为，而与 prompt 内容的具体改进关系不大。

理由是 SSPO 的结构与 best-of-N 采样高度同构——它生成多个候选视频、用一组 verifier 打分、按平均名次选最好的一个。论文报告的推理开销约为单次的 3 倍，而 best-of-3 采样（保持 prompt 完全不变，只改随机种子，同样用 average ranking 选最优）的开销恰好也是 3 倍。这个对照实验论文没有做。若 best-of-N 能拿到 SSPO 大部分的增益，那么"反思式 prompt 重写"这一核心 claim 就被架空了，剩下的只是一个昂贵的采样器。

具体设计：固定 LaVie 与 VBench，对每条 prompt 跑三组——(i) 单次采样；(ii) RAPO prompt 不变 + best-of-4 随机种子采样 + average ranking；(iii) 完整 SSPO 四轮迭代。三组算力严格对齐。如果 (ii) 与 (iii) 的差距小于 (i) 与 (ii) 的差距，论文的贡献就主要是"承认了 test-time compute 有用"，而非"prompt 反思有用"。

第二个可预测的失败条件：当用户 prompt 本身就与训练分布相距很远、且这种偏离正是用户意图时（超现实构图、非常规物理、罕见概念组合），Stage 1 会主动把它拉回常见分布，等于系统性地破坏创意意图。论文展示的"熊猫当收银员"例子恰好落在这一区域，但那是被当作成功案例展示的；论文没有报告任何"优化后偏离用户原意"的失败率统计，而 SSPO 用来计算错位的参照物 M(ρiu​,vi​) 用的是原始 prompt，这至少说明作者意识到了漂移风险，却没有量化它。

§ 12 — Follow-up Research Idea ​

一个非增量的重构：不要优化 prompt，去优化条件嵌入本身，并把"训练分布"从一个统计目标换成一个可微的约束。

(a) 驱动的局限：RAPO++ 全程在离散文本空间里搜索，这带来两个硬伤——搜索靠 LLM 采样，不可微、样本效率低；而且文本是一个信息瓶颈，"落回训练分布"只能通过词长和句式这类粗糙的代理来近似。数量词失败就是这个瓶颈的典型症状：文本里的 "five" 在 CLIP 类编码器里几乎不携带可用的计数信号，无论怎么改写句子都改不出来。

(b) 可借鉴的相邻工具：来自表征学习的 energy-based / density-ratio 估计。在 T2V 模型的文本编码器输出空间上训一个轻量判别器，区分"训练 caption 的嵌入"与"用户 prompt 的嵌入"，其 logit 即为对数密度比 logpuser​(e)ptrain​(e)​。这给了一个可微的、连续的"像不像训练数据"的度量，可以直接在推理时对条件嵌入做梯度上升，而不必绕道文本。同时可以借鉴 textual inversion 的做法，把无法用词表达的约束（精确计数、特定物理量）编码成额外的可学习 token。

(c) 第一个实验：在 LaVie 上冻结全部权重，只在推理时对文本嵌入 e 做若干步 e←e+η∇e​logpuser​(e)ptrain​(e)​，与 RAPO 的文本级重排在同等算力下比较 VBench 总分与 multiple objects。若嵌入级优化能用远低于一次视频生成的代价达到相近增益，就说明"prompt 工程"其实是在用一个极低带宽的接口去做本该在嵌入空间做的事——这会把整个 prompt optimization 子领域重新定位成条件分布对齐问题，并顺带把它与相邻的 classifier guidance、textual inversion、reward-guided sampling 统一到同一框架下。
