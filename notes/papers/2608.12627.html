EgoCITE: Context-Augmented Indexing and Time-Aware Retrieval for Long-Horizon Egocentric Memory ​

所属教程：长视频理解

本页依据 arxiv.org/html/2608.12627v1（标注 12 Aug 2026）全文与 arxiv.org/e-print/2608.12627 的 TeX 源码（目录名为 latex_ke_revision，模板为 iclr2027_conference.tex）撰写。

§ 1 — 研究问题与重要性 ​

长时程第一人称记忆系统要把连续几天的音视频变成可检索的经历记录。这条流水线的标准形态有四段：感知与 caption 生成、记忆构建与索引、检索、推理与作答。绝大多数工作把创新放在第二段的结构上——向量库、知识图谱、语义记忆、视觉记忆，一个比一个复杂。本文的立论是：结构再花哨，如果被索引的内容本身是残缺的，agentic search 就不可能可靠；而检索环节若把时间当成被动元数据，问题里最强的那个信号就被浪费掉了。

两个瓶颈都被量化了。第一个：作者分析 WorldMM 与 LoCoMo，发现 WorldMM 抽出的实体里有 10% 含未解析的代词，LoCoMo 的记忆条目里有 17% 含未解析的原文引语。一条写着"Jake 说：好的"的记忆，脱离上下文就不知道他同意了什么，向量检索自然搜不到它。第二个：EgoLifeQA 有超过 76% 的问题、EgoMem 有 48% 的问题含时间意图；而在 EgoLifeQA 上，时间相关问题的准确率对 WorldMM 比时间无关问题低 9.8–10.3 个点、对 VideoRAG 低 13.3 个点。这两组数字把"索引质量"和"时间感知"从直觉变成了可测量的缺口。

§ 2 — 前人工作与不足 ​

EgoRAG 是 EgoLife 自带的基线，向量检索 + 递归式的时间聚合，其证据选择本质上是 recency-only 的。A-MEM 走 agentic memory 路线，用关键词与结构化记忆条目。VideoRAG 引入视觉记忆与图检索。WorldMM 用知识图谱把实体、事件组织起来，是本文的主要对照，也是本文的实现规范来源（30 分钟窗口、15 条记忆索引预算都对齐它）。

作者对这一族的批评落在同一个机制上：这些系统的索引都是从独立生成的短条目（单条 caption、单条语音转写）直接建的。caption 生成时模型只看到局部画面，语音转写更是完全没有视觉上下文，于是人称代词、省略、指代都留在原地。coreference resolution 单独做也不够，因为真实对话里还有大量省略与承前省略。在索引之前被丢掉的上下文，下游的 agentic search 永远拿不回来。

检索侧的批评同样具体。已有系统按语义相似度排序，时间只作为元数据附着。作者进一步指出把时间做进检索并不像"在 query 里加个时间戳"那么简单：句子 embedding 是为语义相似度优化的，不编码时序，追加时间表达并不能可靠召回；而"中午""早饭时候"这类表达指的是模糊区间，硬性时间过滤会把相关记忆整片切掉。

§ 3 — 重建作者的思考路径 ​

第一步是做诊断而不是先想方案。把已有系统的失败案例摊开看，会发现相当一部分失败与检索器本身无关——被检索的条目里根本没有足以定位它的信息。这一步把问题从"检索算法不够好"重新定义成"索引内容不够自足"。

第二步是问上下文从哪来。补上下文最便宜的来源就是时间上邻近的条目：前 5 分钟的 caption 与转写足以解析绝大多数代词与省略。于是"用局部窗口把每条 caption 改写成自足句子"成了一个纯粹的预处理步骤，不需要任何新模型。

第三步是问改写成什么形式。如果仍然写成自由文本，一条 caption 里往往混着一个短动作、一段持续活动、一句话和一整轮对话，而提问只针对其中一层。所以要沿两个轴切开：物理行为 vs 言语交互、细粒度 vs 粗粒度，正好得到动作 / 活动 / 话语 / 对话四个视图。

第四步是时间。既然 76% 的问题带时间意图，就必须让检索器显式产出一个时间区间；但区间估计一定有误差且表达本身模糊，所以不能硬切，用指数衰减做软权重是最直接的折中。最后一步是发现单个 agent 做不完：产出高召回候选与按"最后一次 / 通常"精确筛选是两种目标，前者要广撒网、后者要看全局，拆成 drafting 与 sampling 两个 agent 是自然解法。

§ 4 — 核心 Intuition ​

agentic 检索的上限由被索引的内容决定，不由检索算法决定；一条不自足的记忆条目在向量空间里没有可被命中的落点。补救办法不在检索时，而在构建时：用邻近上下文把每条记忆改写成一句不依赖上下文也能读懂的话。与此并列的是：记忆问题天生带时间意图，而句子 embedding 结构性地不编码时间，所以时间必须以一个乘在语义得分之外的显式项进入排序，并且要软（指数衰减）而非硬（区间过滤），因为人说的时间本来就是模糊的。

§ 5 — 具体方法与完整 Pipeline ​

四阶段，其中 Stage 2 与 3 是本文贡献。

Stage 1 感知：把第一人称视频与音频转成 dense visual caption 与语音转写，解析说话人身份，融合成多模态 caption 作为原始记忆条目。

Stage 2 上下文增强索引（EgoScheme + EgoIndex）。 EgoIndex 把经历沿两个轴切成四视图 V={\textscAction,\textscUtterance,\textscActivity,\textscConversation}，每条原子记忆索引 mi​ 带一个时间戳 τi​，全体记为 M=⋃v​Mv​={(τi​,mi​)}。 EgoScheme 给四个视图各定一份结构规范（表 1）：动作细分为 HOI（须有具名人物、具体物体、直接物理操作）、gesture（具名人物 + 有意义的表情动作）、movement（具名人物 + 抵达的具名目的地）；话语须有具名说话人、言语行为、以及代词与省略已解析的自足内容；活动须有即时目标、参与者、物体、地点；对话须有参与者与一个连贯话题。两条总原则是 human-centered（每条锚定到具体人）与 decoupled（每条只承载一个连贯语义）。当上下文不足以唯一解析时，EgoScheme 保留原表达而不编造细节。 抽取时，动作与话语用长度 T=5 分钟的滑动上下文（当前 caption 加前 5 分钟全部 caption），索引继承源 caption 的时间戳；活动与对话用 T′=30 分钟的不相交窗口（对齐 WorldMM），每条索引带一个时间区间 [tistart​,tiend​]，τi​=tistart​。此外还有一个 disentangling 步骤，把被 "and" / "while" 连起来的无关内容拆开；相邻窗口之间用句向量相似度找时间连续的索引并用一次额外的 LLM 调用合并。

Stage 3 时间感知检索（EgoRetrv）。 drafting agent 每轮产出结构化查询 Q={Qs​,Qv​,Qt​}：语义查询、视图指定、可选的时间查询。语义分 Si​=sim(f(Qs​),f(mi​))。时间查询 Qt​=[tstart​,tend​] 由 agent 从问题推断（"last time" + 参照时刻 DAY1 12:00 可能给出点估计 [DAY1 12:00,DAY1 12:00]，"this morning" 给出 [DAY1 06:00,DAY1 12:00]），并可随后续轮次的检索结果修正。最终按 Si​Ri​ 取 top-k 进入 index pool P，多轮累积。 sampling agent 读取 P 中带时间戳的索引，按时间排序，再按问题里的时间限定词做 curation：遇到"last / most recent"优先取最晚的并保留用于区分选项的相关条目；遇到"usually / habit"则跨多天选一组时间上分散的相关索引。

Stage 4 作答：response agent 拿到被 curate 过的原子索引，把时间戳映射回原始多模态 caption，读这些 caption 后给出多选答案。

默认配置：5 轮检索、15 条记忆索引预算（对齐 WorldMM），时间衰减 λ=0.99。硬件（附录 C.4）：小型 embedding 模型（Qwen3-Embedding-4B 文本、VLM2Vec 视觉）跑在单张 RTX 4090 + i5-13600KF + 128GB RAM 的本机上；Qwen3.6-27B-FP8 与 Gemma-4-31B 用 vLLM 部署在 4×RTX 6000 Pro 的云服务器上。

一个具体例子：问题是"我上次用螺丝刀是在哪天下午？"。drafting agent 产出 Qs​="用螺丝刀"、Qv​=Action、Qt​=最近一个下午的区间；语义检索命中若干条 HOI 索引（因为 EgoScheme 已经把"我用螺丝刀固定架子"写成了自足句，而不是原始 caption 里的"他把它拧上"）；时间衰减把三天前的那次压低；sampling agent 看到"上次"这个限定词，从池子里挑时间最晚的一条，并附带前后两条用于消歧。

§ 6 — 核心数学推导 ​

时间相关性打分是本文唯一的形式化部分。把所有时间戳映射到以小时为单位的连续时间轴上，给定时间查询 Qt​=[tstart​,tend​]，候选索引 mi​ 的时间分数为

Ri​=⎩⎨⎧​1,λtstart​−τi​,λτi​−tend​,​tstart​≤τi​≤tend​,τi​<tstart​,τi​>tend​,​0<λ<1.

最终排序分数是乘性的：score(mi​∣Qs​,Qv​,Qt​)=Si​Ri​，取 top-k 后并入 index pool。若 agent 没有给出 Qt​，则 Ri​≡1，退化成纯语义检索。

三点值得看清。其一，乘性而非加性：这意味着时间分数是一个乘性折扣，语义完全不相关的条目不会因为时间对得上而被拉进来，这与"时间是过滤器而非独立证据"的直觉一致。其二，指数衰减的尺度：λ=0.99、单位是小时，意味着偏离区间 24 小时的条目权重降到 0.9924≈0.79，偏离一周降到约 0.99168≈0.19。这个衰减非常缓和——它更像是给同分条目做时间倾向排序，而不是强过滤。其三，软衰减 vs 硬截断：硬截断会把区间外的全部丢弃，一旦 agent 的时间推断出错就无法挽回；软衰减让错误可恢复，代价是时间信号被稀释。作者用消融支持了这个取值（见 §7）。

§ 7 — 实验设计与结论 ​

问题一：相对长上下文 LLM agent 与已有 agentic memory 系统各差多少。 表 2 给出三个基准上的准确率与输入 token 数。EgoCITE-GPT 输入 32k token，EgoLifeQA 平均 63.8、EgoMem 平均 79.2、EgoR1-Bench 75.3；EgoCITE-Qwen 输入 34k，对应 61.5 / 79.9 / 73.0。长上下文对照：GPT-5.4 agent 输入 783k token，54.9 / 75.1 / 71.0；Gemini-3.1-Pro agent 输入 804k，60.2 / 78.3 / 72.7。agentic memory 对照：EgoRAG 34.3 / 59.5 / 49.5，A-MEM 42.9 / 58.8 / 52.0，VideoRAG 46.5 / 68.6 / 64.7，WorldMM-Qwen 46.4 / 74.8 / 66.3，WorldMM-GPT 49.6 / 68.1 / 64.0。摘要里的 "4.4–14.2%" 对应的是相对 agentic memory 基线的平均增益（EgoLifeQA 至少 14.2、EgoMem 至少 4.4、EgoR1 至少 9.0）；相对长上下文 agent 的增益要小得多（EgoLifeQA 3.6–8.9、EgoMem 0.9–4.1、EgoR1 2.6–4.7）。输入 token 少 23 倍这个数字出自同一张表。

问题二：涨的到底是检索还是作答。 表 3 报告 15 条索引预算下的检索命中率。EgoCITE-GPT 在 EgoLifeQA / EgoMem / EgoR1 上是 49.6 / 89.6 / 62.7，相对最强基线分别 +15.1 / +17.0 / +22.7；EgoCITE-Qwen 是 43.4 / 86.8 / 59.0。作为对比，WorldMM-GPT 是 34.5 / 66.9 / 40.0，VideoRAG 只有 2.0 / 17.4 / 6.0。附录里还报了 NearHits（检索到的索引落在真值证据 ±5 分钟内）：EgoCITE-GPT 69.4 / 90.8 / 70.3。命中率的提升幅度远大于准确率的提升幅度，说明改善确实发生在检索侧。

问题三：每个部件贡献多少。 表 10 在 EgoR1-Bench 上从 EgoRAG 式的 caption RAG 起逐步叠加：准确率 61.3 → 加 EgoIndex 69.7 → 再加 EgoScheme 71.3 → 再加 EgoRetrv 75.3；命中率 40.7 → 54.3 → 59.3 → 62.7。贡献最大的单项是 EgoIndex 的多视图组织（+8.4），而不是标题里排第一的上下文增强。另有一张多视图粒度消融：只用细粒度（动作 + 话语）69.7 / 55.7，只用粗粒度（活动 + 对话）73.3 / 59.3，四视图全用 75.3 / 62.7。

问题四：λ 怎么选。 表 11 在 EgoR1-Bench 的 100 题验证子集上扫 λ：从 0.97 涨到 0.99 时性能上升，在 0.99 达到准确率 81.0 / 命中率 67.0；继续到 0.995 两项都下降。

问题五：多轮检索值不值。 表 4 在 EgoLifeQA 上，1 轮 / 3 轮 / 5 轮的命中率是 36.5 / 48.6 / 49.6，平均准确率 58.7 / 62.6 / 63.8。5 轮相对 1 轮 +5.1 准确率，代价是 2 倍时延与 3.2 倍归一化成本。

问题六：36× 便宜从哪来。 5 轮变体相对 GPT-5.4 agent 准确率 +8.9、成本 36×、时延相当；相对 WorldMM 成本 2×、时延低 15 秒，原因是原子记忆索引检索把送进上下文的内容缩小了 5.7 倍。需要说明成本口径：Normalized Cost 是按 GPT-5.4 定价加权的 token 成本（短上下文模型输入 1×、输出 6×；长上下文模型输入 2×、输出 9×），EgoCITE 与 agentic memory 基线按短上下文计价，长上下文 agent 按长上下文计价。36× 里有一部分来自定价档位差异，而不是纯粹的 token 数差异。

问题七：记忆越长会不会崩，换掉人工 caption 还行吗。 图 4 报告 EgoLifeQA 上记忆跨度从 DAY1 增到 DAY7 的累积准确率：EgoCITE 从 DAY3 起始终最高，DAY1→DAY7 只掉 4.8%，而 GPT-5.4 agent 掉 11.9%。表 14 用 VLM 生成的 narration 替换 EgoLife 的人工 dense caption，Gemini-3-Flash 变体在 EgoLifeQA 上 60.3%，作者描述为"只有小幅下降"。

§ 8 — Take-aways ​

5 句版：agentic 记忆检索的上限由被索引内容的自足性决定，而不是由记忆结构的复杂度决定——WorldMM 有 10% 的实体带未解析代词，这些条目在向量空间里没有可命中的落点。用邻近 5 分钟的上下文把每条 caption 改写成自足句，并沿"物理行为 vs 言语交互 × 细 vs 粗"切成四视图，是一个不需要新模型的预处理级修复。记忆类问题里超过 76%（EgoLifeQA）带时间意图，而句子 embedding 结构性地不编码时间，所以时间必须以乘性的指数衰减项显式进入排序，且要软不要硬。消融显示贡献最大的单项是多视图索引（+8.4），上下文增强与时间检索各再加 1.6 与 4.0。"36× 更便宜"这个数字混合了 token 数差异与长/短上下文的定价档位差异，且只统计查询时成本，不含把七天视频转成 caption 与索引的一次性构建成本。

3 句版：把索引质量而不是索引结构当成长时程记忆的主要瓶颈，用局部上下文做自足化改写 + 四视图组织，把检索命中率在三个基准上提了 15.1 / 17.0 / 22.7 个点。检索时用 Si​⋅λ∣Δt∣ 把时间意图显式建进排序，λ=0.99（小时为单位）是一个非常缓和的软倾向。主结果建立在 EgoLife 的人工标注 dense caption 之上，换成 VLM narration 后 EgoLifeQA 从 63.8 掉到 60.3。

1 句版：检索不到往往不是检索器的错，是被索引的那句话本身缺了主语。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：记忆源是高质量的、已经把视觉内容说清楚了的文本。EgoCITE 的四个视图、上下文改写、时间衰减，全部作用在文本层；它从来没有直接看过像素。主结果里这份文本是 EgoLife 提供的人工标注 dense caption 加语音转写——作者在附录 B.1 与 C 里明确说明，这样做是为了与 WorldMM 等基线公平对比。

这条假设为什么可能不成立：真实部署里没有人工 caption，只有 VLM narration；而 VLM narration 的失败模式恰恰与 EgoScheme 依赖的能力冲突。EgoScheme 的规范要求"具名人物 + 具体物体 + 直接物理操作"，但 VLM 对第一人称视频里的人物身份识别本来就不稳；一旦 narration 里的人名错了或缺了，改写出来的原子索引会把错误固化进索引，而且比原始 caption 更自信、更像一句可信的事实。这属于错误放大而非错误传递。

论文为这条假设提供的证据是表 14：换成 Gemini-3-Flash narration 后 EgoLifeQA 准确率 60.3%，作者称"only a modest performance drop"。这个证据是部分的——它只在一个基准上换了感知源，没有报告换源后检索命中率的变化（而命中率才是本文机制的直接观测量），也没有分析错误类型是否从"检索不到"变成了"检索到但内容错"。作者自己在附录里也承认，EgoLifeQA 上 EgoCITE-GPT 与 EgoCITE-Qwen 分别有 11.3% 和 9.1% 的题是检索到了正确证据却答错，说明命中率与准确率之间还有一层没被本文机制覆盖的间隙。

§ 10 — 最小复现实验 ​

一周内可做，目标是把"上下文自足化"这一个变量单独测出来，不必复现整套四视图与双 agent。

  1. 取 EgoLifeQA 的一个子集（例如 300 题，含时间相关与时间无关各一半），用 EgoLife 自带的 dense caption 与转写作为记忆源。
  2. 建两个索引库，检索器完全相同（同一个句向量模型、同样 top-15、同样单轮）：(a) 原始 caption 直接入库；(b) 用一个开源 LLM 加 5 分钟上下文窗口把每条 caption 改写成自足句后入库。改写 prompt 直接照抄论文附录 G。
  3. 主要测量检索命中率（检索到的条目是否覆盖真值证据时间戳），次要测量准确率。
  4. 再加一个廉价对照 (c)：不做改写，只在每条 caption 前机械拼接前 5 分钟的原始 caption 文本再做 embedding。这条对照非常关键——它检验的是"改写"本身有价值，还是仅仅"embedding 时看到了更多上下文"就够了。
  5. 判据：若 (b) 显著高于 (a) 且显著高于 (c)，则 EgoScheme 的结构化改写有独立价值；若 (b) 与 (c) 接近，则本文这一半贡献可以被一行拼接代码替代。

§ 11 — 最强反例设计 ​

最强的攻击针对成本口径。"36× lower cost than long-context LLM agents"是本文最抢眼的数字，但它只统计查询时的 API token 成本。EgoCITE 的索引是离线建的：七天的多模态 caption 要经过 5 分钟滑窗的逐条 LLM 改写（动作 + 话语两个视图）、30 分钟窗口的分段（活动 + 对话两个视图）、disentangling、以及跨窗口合并的额外 LLM 调用。这几步的调用量与视频总长成正比，而且都用 GPT-5.4。构造反例的方法是把这部分算进去：设一天有 N 条 caption，索引构建的 LLM 调用次数约为 O(N)，而回答一道题的检索成本只涉及 15 条索引。给定 EgoLifeQA 的题量（时间感知子集就有 2223 题），需要摊多少道题才能把构建成本摊平，是一个可以直接算出来的数——如果这个盈亏点高于基准题量，那么在该基准的实际使用规模上 EgoCITE 并不比长上下文 agent 便宜。论文里我没有找到索引构建成本的任何报告，这个对照缺失。

第二重攻击针对平凡的时间基线。既然 76% 的 EgoLifeQA 问题带时间意图，而 EgoLifeQA 的时间关键词是可枚举的（附录 C.1 列了 "usually / often / never / morning / afternoon / DAY X / last" 等），那么存在一个极便宜的对照：规则式时间过滤 + 原始 caption 向量检索——用正则从问题里抽出 DAY X 或时段词，直接把候选限制在对应时间窗内，其余不变。这个基线不需要 agent、不需要四视图、不需要改写。如果它能吃掉 EgoRetrv 那 +4.0 的增益中的大部分，那么"必须把时间做成软衰减的学习式检索"这个论断就被削弱。论文对硬截断的批评是"对推理错误与语言歧义脆弱"，这是合理的先验，但没有给出实测对照。

第三重针对 λ 的实际作用力。λ=0.99、以小时为单位，意味着偏离一整天的条目权重仍有 0.79。在一个七天的记忆库里，这个衰减几乎不改变排序——它只在语义分极其接近时才起决定作用。表 11 的扫描区间只有 0.97 / 0.99 / 0.995 三点且在 100 题子集上做，跨度太窄，无法排除"Ri​ 的真实贡献很小、EgoRetrv 的 +4.0 主要来自 sampling agent 的 curation 而非时间衰减"这一替代解释。把 λ 扫到 0.9、0.8 并单独消融"去掉 Ri​ 但保留 sampling agent"，才能把这两者分开。

§ 12 — Follow-up Research Idea ​

驱动局限：本文把感知（Stage 1）当成一个已经完成的、不可回头的前置步骤。索引一旦建好，像素就再也不被访问了。这直接导致了作者自己观测到的那 11.3% 的失败——检索到了正确的时间点，但那一刻的 caption 里没写下回答问题所需的那个细节（螺丝刀是什么颜色、桌上有几个杯子）。这类失败在当前架构里原理上无法修复，因为信息在 caption 阶段就已经丢了，而 caption 是 query-agnostic 生成的。

新 framing：把感知从"一次性前置"改成索引负责定位、像素负责回答的两级架构——记忆索引不再试图承载答案，只承载"去哪一秒看"这个指针；一旦 sampling agent 锁定了证据时刻，就用原始视频帧做一次 query-conditioned 的重新观看。这把长时程记忆的目标函数从"记住所有可能被问的东西"（不可能）改成"记住足以定位的东西"（可行得多），并且天然解释了为什么本文的 NearHits（±5 分钟）比严格 Hit 高出十几个点：定位精度已经足够，缺的是回看。可借鉴的相邻工具是信息检索里的 retrieve-then-rerank 两阶段范式，以及流式视频理解里的 query-conditioned 帧检索（本教程 3.5 节讨论的那一族）。

第一个实验：不改索引构建，只改 Stage 4。取 EgoCITE-GPT 在 EgoLifeQA 上那 11.3% "检索对了但答错"的题，把 response agent 的输入从"时间戳映射回的 caption"换成"以该时间戳为中心的 ±30 秒原始视频帧 + 问题"，喂给一个视频 VLM 重答一次。测量这批题的准确率能恢复多少。如果能恢复过半，说明记忆系统的瓶颈已经从检索转移到了感知的 query-agnostic 性质上，整条研究线的重心应当随之转移；如果几乎不动，则说明这些题的失败在证据本身而非表示形式，本文的索引路线仍是主战场。这个实验只需要一次额外推理，一周内可完成。
