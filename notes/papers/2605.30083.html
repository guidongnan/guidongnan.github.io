Future Forcing: Future-aware Training-free KV Cache Policy for Autoregressive Video Generation ​

项内容
arXiv2605.30083
提交日期2026-05-28
作者Jiayi Luo, Qiyan Liu, Tengyang Wang, Junhao Liu, Jiayu Chen, Cong Wang, Hanxin Zhu, Chen Gao, Xiaobin Hu, Qingyun Sun, Zhibo Chen
分类cs.CV
一句话发现自回归视频模型的 pre-RoPE query 分布在整段生成里近似平稳,于是用历史 query 的均值加上未来位置的 RoPE 旋转造出"未来 query 代理",据此给 KV cache 打分淘汰,并在这个未来注意力剖面空间里把被淘汰的条目合并回保留项——全程免训练。

所属教程：自回归视频生成

§ 1 — 研究问题与重要性 ​

自回归视频扩散把长视频拆成一块块 latent 帧顺序生成,每块条件于之前生成的 token。为了不重复计算历史,系统必须缓存 key/value。但 KV cache 随生成长度线性增长,分钟级视频的显存开销很快压过模型本身,所以实际系统一律在固定预算下工作。预算一固定,淘汰谁就成了决定性问题:一旦丢掉了后续帧需要的 token,注意力对历史上下文的分布就被扭曲,而这个误差会顺着自回归链传下去,最终表现为主体身份漂移、场景闪烁、运动断裂。

已有的 KV cache 压缩方法都用当前或历史上下文导出的信号估计 token 重要性。这在语言模型里没什么问题——LLM 的 prompt 一旦给定,重要 token 大体稳定。但视频不一样:一个此刻在画面边缘、注意力很低的 token,可能三秒后随着镜头平移变成画面主体。用短时程信号做淘汰决策,系统性地偏向"现在有用"而非"将来有用",论文称之为 short-horizon bias。这篇工作的价值在于它指出这个偏差可以在不额外前向、不额外训练的情况下被纠正,前提是找到一个能预测未来 query 的量。

§ 2 — 前人工作与不足 ​

双向 DiT 视频模型(Sora、CogVideoX、HunyuanVideo、Wan、Open-Sora、LTX-Video、Step-Video-T2V)靠双向注意力联合去噪整段视频,质量高但天然离线:必须把所有时空 token 都去噪完才能解码第一帧,无法流式输出。自回归路线(CausVid、Self Forcing、Causal Forcing、Rolling Forcing、Reward Forcing、Sparse Forcing、LongLive、Context Forcing)解决了流式问题,但把 KV cache 的成本推到了台前。

cache 压缩在 LLM 侧有 Scissorhands、H2O、PyramidKV 等成熟方案。视频侧:Self Forcing 用 rolling KV cache;LongLive 组合 KV-recache、短窗注意力与 frame sink;PackCache、Dummy Forcing、FlowCache、TempCache、Quant VideoGen、PaFu-KV 分别探索 token 压紧、低比特量化与显著性淘汰;Relax Forcing、DeepForcing、Anchor Forcing、PackForcing 把历史组织成结构化记忆区。这些方法的共同缺口很具体:打分函数的输入全部来自已经发生的事。DeepForcing 用 deep sink 加参与式压缩,Reward Forcing 用奖励加权,都是历史统计。

唯一在方向上重叠的是 PaFu-KV,它也想引入未来感知,但走的是训练路线:用双向 teacher 提供过去与未来的显著性监督,再训一个轻量显著性头。这带来两个代价:需要 teacher 模型与额外微调,且只做淘汰不做合并。论文明确说明 PaFu-KV 未开源,因此未纳入直接比较——这是一个诚实但也削弱了对照强度的说明。

§ 3 — 重建作者的思考路径 ​

问题的死结很清楚:要知道未来 query 会关注谁,就得先有未来 query;但未来 query 要等未来帧生成出来才有,而那时淘汰早已发生。绕开死结只有两条路——用外部模型预测(PaFu-KV 走的路,要训练),或者找到一个可以从历史外推的不变量。

第二条路要求先问:query 到底为什么会随时间变化?在带 RoPE 的注意力里,实际参与打分的是旋转后的 q~​i​=R(pi​)qi​。这个量随位置连续变化是显然的——RoPE 就是这么设计的。但 RoPE 是一个正交变换,它不改变向量长度,只改变方向;真正携带内容信息的是旋转前的 qi​=WQ​hi​。于是自然的猜想是:观察到的"query 漂移"里,有多少是内容真的变了,有多少只是位置编码在转?

这是一个可以直接测的问题。把两组分布画出来看:固定 prompt 下,跨自回归步的 pre-RoPE query 分布 vs RoPE-modulated query 分布。作者报告的结果是前者明显更集中(附录 G 用归一化 Wasserstein 距离量化:pre-RoPE 平均 0.123σ,RoPE 后 1.176σ,差近一个数量级)。

一旦这个观察成立,方法就几乎自动写出来了:取最近 w 帧 pre-RoPE query 的均值作为"典型 query",对它施加未来位置 t+Δ 的 RoPE 旋转,就得到了未来 query 的代理,不需要生成任何未来帧。剩下的工程问题是 FlashAttention 不暴露逐 token 注意力权重,所以得自己写 kernel。

§ 4 — 核心 Intuition ​

自回归视频模型在固定 prompt 下"关心什么"其实一直没变,变的只是"从哪个位置去关心"。RoPE 把同一个语义查询方向映射到不同的时空配置,造成了逐步变化的局部注意力模式,但底下那个内容查询分布是稳的。既然稳,就可以把历史 query 的均值当作未来 query 的内容部分,只需补上未来位置的旋转——未来注意力于是变得可预测,淘汰决策也就不必再短视。

§ 5 — 具体方法与完整 Pipeline ​

以在 Self Forcing 骨干上生成 60 秒视频为例,KV 预算为 18 个 latent 帧。

  1. 收集历史 pre-RoPE query。 每层注意力在旋转前把 Qt​=Xt​WQ⊤​ 记下来,维持最近 w 帧的滑动均值 Qˉ​=w1​∑s=t−w+1t​Qs​。

  2. 构造未来 query 代理。 对每个前瞻步 Δ∈{1,…,Δmax​}(Δmax​=6),施加位置 t+Δ 的 RoPE 算子得到 Q~​t+Δ​=Rt+Δ​(Qˉ​)。这一步没有任何前向计算,只是旋转。

  3. 打分与淘汰。 对每个缓存 key K^j​ 算 logit s^t+Δ,j​=⟨Q~​t+Δ​,K^j​⟩/dh​​,softmax 归一化得 a^t+Δ,j​,与历史平均注意力线性混合(见 §6)。低于预算阈值的条目被标为淘汰集 E。

  4. 未来 query 剖面空间中的合并。 关键设计:不按 key 的欧氏距离合并,而是把所有 key 投影成"在各个未来 query 下的注意力剖面" K^t+Δ​=KQ~​t+Δ⊤​∈RN×Δmax​。每个被淘汰条目 j 找余弦最近的保留条目 i⋆(j),只有相似度 ≥τ=0.95 才准合并,否则直接丢弃。合并后的 key 保持 K~i​=Ki​ 不变(保持 RoPE 一致性),value 按未来注意力质量加权重算。

  5. 动态 RoPE 重索引。 每次淘汰后把幸存帧的时间轴位置重映射到紧邻当前生成位置的连续区间,只改时间通道、不动空间通道,保证相对时间距离落在模型训练过的分布内。

  6. 自定义 Triton kernel。 FlashAttention 不返回逐 token 权重,朴素 PyTorch 实现要显式物化 QK⊤。作者写了两遍扫描的 kernel:第一遍在 SRAM 里维护逐 query 的运行最大值与部分归一化和,写出 LSE;第二遍重算原始点积、套上已定型的归一化因子、立刻沿 query 维归约。工作集 O(BHQ+BH⌈Q/BQ​⌉T),避开了稠密的 O(BHQT) 矩阵。tile 尺寸 BQ​=BK​=128。

超参:λ=0.5、Δmax​=6、τ=0.95。cache 预算:Self/Causal Forcing 18 帧、Rolling Forcing 15 帧、Reward Forcing 9 帧。

§ 6 — 核心数学推导 ​

打分函数。 未来相关性与历史注意力的线性混合:

scorej​=λ⋅未来Δmax​1​Δ=1∑Δmax​​a^t+Δ,j​​​+(1−λ)⋅历史t1​s=1∑t​as,j​​​

λ=0.5 表示未来与历史等权。附录的超参分析显示,在 Self-Forcing 上把 λ 从 0.1 提到 0.9 会把 dynamic degree 从 53.00 拉到 65.67,同时 subject/background consistency 略降(97.60→97.57、96.57→96.37)——即 λ 实质上是一个动态性-一致性的旋钮。

合并规则。 被淘汰条目 j 的路由与合并:

i⋆(j)=argi∈Smax​cos(K^i​,K^j​),V~i​=Δmax​1​Δ=1∑Δmax​​a~t+Δ,i​a^t+Δ,i​Vi​+∑j∈E(i)​a^t+Δ,j​Vj​​

其中 a~t+Δ,i​=a^t+Δ,i​+∑j∈E(i)​a^t+Δ,j​ 是重归一化后的注意力质量。直觉是:注意力输出 O=∑j​aj​Vj​ 里每个条目的贡献是 query 相关的,两个 key 靠得近不代表在同一个 query 下拿到相似权重。在剖面空间做合并,直接最小化的是注意力输出的失真,而不是 KV 本身的重构误差。

Query 漂移上界(Theoretical Analysis 1)。 记相对漂移 ρpret→s​=∥Qs​−Qt​∥F​/∥Qt​∥F​、ρpostt→s​ 同理定义在旋转后,ϵ=∥Xs​−Xt​∥F​,Δp 为相对位置偏移,θ 为 RoPE 基频。则

ρpret→s​≤∥Qt​∥F​∥WQ​∥op​⋅ϵ​,ρpostt→s​≤2​sin2Δp⋅θ​​+∥Qt​∥F​∥WQ​∥op​⋅ϵ​

证明思路值得展开一下,因为它解释了为什么两者会分离。pre-RoPE 那侧很直接:Qs​−Qt​=(Xs​−Xt​)WQ⊤​,用 ∥AB∥F​≤∥A∥F​∥B∥op​ 即得。post-RoPE 那侧要拆成两项:加减 R(ps​)qt​ 后,一项是内容变化经正交旋转(范数不变,所以与 pre-RoPE 的界相同),另一项是同一个内容向量在两个位置下的旋转差。由于同一 token 在两帧里空间坐标不变,高度/宽度的 RoPE 块相消,只剩时间块;而每个 2×2 旋转块满足 ∥R2​(ps​θk​)−R2​(pt​θk​)∥op​=2∣sin2(ps​−pt​)θk​​∣。所以 post-RoPE 的界比 pre-RoPE 多出一个纯位置项,而标准 RoPE 的最低频 θ=10000−0=1,意味着这一项在 Δp 不小时是 O(1) 量级。

需要如实指出一个逻辑缺口:这是两个上界的比较。上界更大不蕴含实际漂移更大。这个命题只能说明"位置项可能很大",真正支撑主张的是图 2 与附录 G 的经验测量。论文把它称作 Theoretical Analysis 而非定理,措辞上是克制的,但正文里"provide a concise theoretical explanation"的说法仍然略强于证据。

§ 7 — 实验设计与结论 ​

问题一:超出训练时程时,未来感知淘汰是否真的更好? 现有 AR 模型训练时程是 5 秒,所以用 MovieGen prompt 在 VBench-Long 上评 30 秒与 60 秒。跨 Self/Reward/Rolling/Causal 四个骨干、每个骨干比 Native cache 与训练无关的 Deep Forcing。结论是多数指标上更好,最突出的是 subject consistency:Causal Forcing 60s 从 94.62 提到 96.11,恰好是摘要里 1.49 那个数字的来源。

必须如实指出三点。其一,dynamic degree 在两个骨干上明显下降:Causal Forcing 30s 从 97.14 掉到 88.16、60s 从 97.40 掉到 86.79;Rolling Forcing 30s 从 34.20 掉到 32.42、60s 从 34.20 掉到 31.43。论文的解释是高 dynamic degree 常来自"突兀的、非预期的场景跳变"而非有意义的运动,只提供了视觉与网页对照,没有定量证据。其二,overall consistency 并非全胜:Self Forcing 30s 上 Deep Forcing 23.91 高于 Future Forcing 23.60;Reward Forcing 30s 上 Native 23.94 也高于 23.61。其三,表 1 里 Rolling Forcing + Native 在 30s 与 60s 两行的 Dynamic Degree(34.20)与 Overall Consistency(23.25)逐位相同,两个不同时程给出两个完全一致的数,更像是复制错误而非真实结果。

问题二:在训练时程内,压缩本身损失多少? 5 秒生成,把 full cache 当参考,报 PSNR/SSIM/LPIPS 加 VBench。两个压缩率(28.57%、42.85%)、三个骨干上,Future Forcing 的重构保真度全面最优:例如 LongLive 在 42.85% 下 PSNR 24.035 / SSIM 0.842 / LPIPS 0.065,优于 Reward Forcing 的 23.313 / 0.824 / 0.075。这组实验的设计比长视频那组更干净,因为唯一变量就是 cache 策略。

问题三:两个模块各自贡献什么? w/o Score(换成 Sink + FIFO)与 w/o Merge(直接丢弃)。结论是未来感知淘汰对长视频贡献更大,合并对短视频保真更关键——这与两者的作用机理自洽:长时程的痛点是选错 token,短时程的痛点是丢掉的信息无处可去。

问题四:代价多少? A100 80GB 上,Future Forcing 与基线吞吐相当,Causal Forcing 下峰值显存最多降 1.8 GB。Triton kernel 在四个骨干上分别减少 6.0%/10.4%/6.6%/8.9% 推理时间。这里有一处内部不一致:附录写 Reward-Forcing 下"把峰值显存从 16.64GB 与 17.57GB 降到 16.71GB",但 16.71 > 16.64,相对 Naive 实际是略升。另外作者自己说明,Rolling-Forcing 设定下 Future Forcing 用的 KV 预算比基线更小,所以那部分显存优势有一部分是配置差异而非方法本身。

§ 8 — Take-aways ​

5 句话版。 自回归视频模型的 query 漂移主要来自 RoPE 的位置调制,底层 pre-RoPE query 分布在固定 prompt 下近似平稳(归一化 W1​ 分别为 0.123σ 与 1.176σ)。因此未来 query 可以用历史均值加未来位置旋转来代理,不需要任何前向或训练。据此打分把 KV 淘汰从"现在有用"改成"将来有用",并在未来注意力剖面空间做条件合并,让被淘汰的信息以最小输出失真的方式被吸收。长视频上 subject consistency 最多提升 1.49,短视频上重构保真度全面优于同类免训练方法。代价是需要自写 Triton kernel 拿到逐 token 注意力,以及在部分骨干上 dynamic degree 显著下降。

3 句话版。 Query 变的是位置不是内容,所以未来注意力可以外推。用外推出的未来 query 做淘汰与合并,免训练地纠正短时程偏差。长时程一致性提升明确,但动态性代价缺少定量支撑。

1 句话版。 把 RoPE 转过去,就能提前知道未来的 query 会看向哪里。

§ 9 — 最脆弱的假设 ​

最脆弱的一条:pre-RoPE query 分布"在固定 prompt 下"平稳,足以支撑对未来注意力的逐 token 预测。

先说它为什么可能不成立。这个平稳性是分布层面的:图 2 与表 8 测的是跨帧的 query 分布距离。但 s^t+Δ,j​ 是逐 token 内积,它需要的是具体那个 query 向量而非分布。取 w 帧均值 Qˉ​ 相当于用一阶矩替代整个分布——如果 query 分布是稳定的但方差不小(表 8 报的是 0.123σ,以 σ 为单位,说明它本来就是相对标准差的量),那么均值可能落在低密度区域,对应的注意力剖面就不代表任何实际 query。更麻烦的是,均值会系统性地抑制那些"少数 query 强烈关注某个 token"的情形,而这类稀有但关键的关注,恰恰是本文声称要保护的"早期不重要、后来变关键"的 token。

第二重风险:平稳性的前提是固定 prompt。整个流式长视频生成的价值主张之一就是 prompt 切换与交互(LongLive 的核心功能),而论文的实验全部在固定 prompt 下做。附录 H 补了三个高动态 prompt 的可视化,但那检验的是"场景剧烈变化",不是"prompt 变化"。

论文为这个假设提供的证据是:5 个骨干 × 2 个 query 维度 × 3 个 prompt 的分布可视化与 Wasserstein 距离,以及一个上界不等式。缺的是直接证据:未来 query 代理预测出的注意力排序,与真正生成出未来帧后的实际注意力排序,相关性有多高?这个量可以离线测(先正常生成完整视频,再回放对比),论文没有报。

§ 10 — 最小复现实验 ​

不需要复现 Triton kernel 或完整长视频评测。一周内可做的核心验证是量化代理的预测力。

  • 数据与模型。 开源 Self-Forcing checkpoint,20 条 MovieGen prompt,单卡 A100。
  • 实现。 关掉所有 cache 压缩,正常生成 30 秒视频并完整记录每层每步的 pre-RoPE query、旋转后 query、以及每个缓存 key 收到的实际注意力质量。这是纯 forward hook,一天可完成。
  • 测量。 对每个决策点 t 与前瞻 Δ∈{1,3,6,9},计算三个排序之间的 Spearman ρ:(i) 代理预测的 token 重要性排序 a^t+Δ,⋅​;(ii) 真实未来注意力排序 at+Δ,⋅​;(iii) 纯历史平均注意力排序(即 λ=0 的基线)。
  • 判据。 若 ρ(i,ii) 明显高于 ρ(iii,ii),方法的机制解释成立,且差值随 Δ 的衰减速度直接给出 Δmax​ 的合理取值;若两者接近,说明增益主要来自打分之外的部分(合并模块或动态 RoPE 重索引),论文的因果叙事需要修正。同时记录 Qˉ​ 到各帧 Qs​ 的距离分布,检验均值是否落在高密度区。

§ 11 — 最强反例设计 ​

替代解释:增益可能主要来自动态 RoPE 重索引,而非未来感知打分。 方法里有一步容易被当成实现细节:每次淘汰后把幸存帧的时间位置重映射到紧邻当前生成位置的连续区间。这一步本身就是一个已知的强 baseline——它保证相对时间距离始终落在训练分布内,是 Infinity-RoPE 一类方法的核心机制,论文自己引用 DeepForcing 与 Causal Forcing 说明这是"following"来的。而消融只做了 w/o Score 与 w/o Merge,从未做 w/o 动态 RoPE。也就是说,表 1 里 Native 与 Future Forcing 的差距同时包含了"更好的打分"与"更好的位置重编码"两个因素,无法分离。

这个替代解释还能解释一个否则很别扭的现象:Causal Forcing 上 dynamic degree 从 97 掉到 87。如果增益来自把相对位置强行压回训练分布,那么模型会更保守、更倾向复制近邻帧,动态性下降是可预测的副作用;而"更准确地保留了未来需要的 token"这一解释并不自然地预测动态性下降。

可预测的失效条件:Δmax​ 与重索引的相互作用。 代理是在绝对位置 t+Δ 上做旋转的,但重索引会把幸存 key 的时间位置改写。于是打分时假设的 query-key 相对距离,与实际生成时的相对距离并不一致。当淘汰比例高、重索引位移大时,这个失配会被放大。设计实验:固定 λ 与 τ,在 Δmax​∈{1,6,12} × 压缩率 ∈{28.57%,42.85%,14%} 的网格上测重构 PSNR。如果失配假设成立,应观察到在高压缩率下大 Δmax​ 反而变差的交互效应。附录 C.6 只在单一压缩率下扫了 Δmax​,报告"变化温和",不足以排除这一交互。

§ 12 — Follow-up Research Idea ​

(a) 驱动局限。 本文把"未来"建模成一个纯位置外推:内容部分被冻结成历史均值,只有 RoPE 在向前转。这在场景稳定时是好近似,但它按构造无法预测内容层面的未来——镜头即将摇向的新区域、即将进入画面的新主体。而这恰恰是长视频最需要提前保留证据的情形。当前设计只能保护"已经出现过、将来还会被同样地关注"的 token。

(b) 可借鉴的相邻领域工具。 值得连接的是缓存替换的竞争分析与在线学习中的专家算法。经典的 Belady 最优替换需要未来访问序列,不可实现;但 LeCaR 一类工作用多臂赌博机在多个替换策略之间在线加权,不需要预测未来、只需要观测每个策略的事后后悔。把这个框架搬过来:同时维护若干淘汰策略(FIFO、纯历史注意力、本文的未来代理、随机),每生成完一个 chunk 就用事后可得的真实注意力给每个策略打一个 regret,再用指数加权更新它们的混合系数。这把"预测未来"换成了"事后修正",绕开了 §9 的平稳性假设,而且天然适应 prompt 切换——切换后旧策略后悔骤增,权重会自动迁移。

(c) 第一个实验。 在 Self-Forcing 与 LongLive 两个骨干上,构造一个 prompt-switch 评测:每 10 秒切换一次 prompt,生成 60 秒。比较四条曲线随时间的 subject consistency 与切换点后 2 秒内的 CLIP-T:固定 Future Forcing、固定 FIFO、oracle(离线用真实未来注意力做淘汰,给出上界)、以及在线专家混合。关键观测量不是最终平均分,而是切换点附近的恢复速度与专家权重的时间轨迹。如果混合权重在切换后确实从"未来代理"迁移到"历史注意力"再迁回,就证实了平稳性假设是分段成立而非全局成立,这本身就是对本文观察的一个更精确的刻画。
