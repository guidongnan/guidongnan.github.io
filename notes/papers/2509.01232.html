FantasyHSI: Video-Generation-Centric 4D Human Synthesis In Any Scene through A Graph-based Multi-Agent Framework ​

项内容
arXiv2509.01232
提交日期2025-09-01
作者Lingzhou Mu, Qiang Wang, Fan Jiang, Mengchao Wang, Yaqi Fan, Mu Xu, Kai Zhang
分类cs.CV
一句话把人-场景交互建成动态有向图，用导航、规划、批判三个 VLM agent 分别产出关键节点、动作链和回溯纠偏，每条边由一个经 DPO 物理对齐的 I2V 模型生成视频再动捕回 3D，从而无需配对数据地做长程 4D 人体合成。

所属教程：物理感知视频生成

§ 1 — 研究问题与重要性 ​

人-场景交互（HSI）要生成的是「这个人在这个环境里会怎么动」。难点有两层：一层是长程高层任务——「去探索这座城堡」不是一个动作，而是一串带里程碑的行为；另一层是泛化——换一个没见过的房间、放一个没见过的物体，模型还得知道该绕开还是该坐上去。

现有方法卡在数据上。主流路线依赖成对的「动捕 + 场景」数据，采集成本极高且只覆盖特定环境，换个布局就失效。零样本路线（ZeroHSI、GenZI）借 VLM 或视频扩散模型的先验绕开配对数据，但只能做「坐下」「触摸」这类单一简单动作。再加一层要求：生成的动作必须物理可信，肢体形变、脚部滑移、穿模这些伪影一出现，结果就不能用。

§ 2 — 前人工作与不足 ​

早期工作（MDM、GMD、MLD）只建模孤立的人体运动，完全不看环境。随后 TRUMANS、LINGO、Sitcom-Crafter 等转向场景条件下的运动生成，用动作标签或文本描述提升可控性，但依赖稀缺的动作-场景配对数据，对新交互类型泛化差。论文的定性分析给出了具体的失败模式：TRUMANS 严重过拟合训练分布，遇到新物体时默认生成坐姿，且无法感知窗台高度，只会按标准椅子高度坐；LINGO 在未见环境里分不清表面边界，穿模严重；PedGen 能生成时序连贯的行走，但动作多样性极低，几乎没有真正的场景交互。

感知范围是另一个被低估的限制。论文指出 TRUMANS 与 LINGO 虽然用占据栅格检测障碍，但感知范围只有虚拟人周围约 1 米的点云盒子；周围物体的点云被这个范围截断，模型看不到物体的完整结构，语义信息大量丢失。因此遇到南瓜这类障碍时，LINGO 只会回头看一眼，TRUMANS 干脆生成不出合理动作。这不是「没考虑障碍」，而是感知表示本身决定了它们看不见完整的物体。

§ 3 — 重建作者的思考路径 ​

已有三条线索。第一，视频扩散模型在互联网规模数据上见过海量人类行为，包含爬梯子、扇鼻子这类高度抽象的动作，这些先验是任何 HSI 配对数据集都无法覆盖的。第二，VLM 能看懂俯视图、识别可通行区域与可交互物体，这正是占据栅格给不了的语义。第三，从视频抬回 3D 的动捕技术（WHAC 一类）已经足够可用，可以把生成的像素变回 SMPL-X 参数。

把三者串起来，一个自然的架构就是：VLM 负责看和规划，视频模型负责演，动捕负责把演的结果放回 3D 场景，再渲染成下一段的首帧，循环推进。但这条链路有一个致命缺陷——生成模型是随机的。让它「边走边看风景」，走多远、朝哪个方向只能大致控制；让它「困倦地伸个懒腰」，它可能顺手加一个哈欠。这些偏差会沿着链路累积，把虚拟人带离规划路线。于是必须再加一个环节：一个能评估偏差、回溯裁剪、纠正朝向的批判者。图结构正是为了让这种回溯有明确的对象——节点可以被剪掉，边可以被重生成。

§ 4 — 核心 Intuition ​

把长程人-场景交互写成一张有向图：节点是「人 + 场景」在某个时刻的 3D 状态，边是一个语义完整的动作单元。这样一来，规划变成在图上铺关键节点与动作链，生成变成实例化每一条边，而生成模型的随机性造成的漂移就变成了「图上多出了计划外的节点」——一个可以被检测、被剪枝、被回溯的具体对象，而不是弥散在长序列里的误差。

§ 5 — 具体方法与完整 Pipeline ​

以「在农场里探索并最终爬上屋顶」为例：

  1. 图初始化：节点 Nk​={Sk​,Hk​}，人体用 SMPL-X 表示，人体状态 H=F(R,T,θ,β)（旋转、平移、姿态、体型，F 为 SMPL-X 渲染函数）。节点分关键节点 K（里程碑，如「到达屋顶」）与非关键节点 U。
  2. 场景导航 agent：读入 3D 场景的若干俯视图，依次做语义分析、可通行空间识别、意图推断、可交互物体识别、子目标与路径规划，输出关键节点序列 K。
  3. 动作链规划 agent：把相邻关键节点之间的运动拆成一串自然语言描述的动作单元（每个约 3 秒内语义连贯的最小运动单元），在图中补入非关键节点与边。动作单元不是有限集合，可以是「打哈欠」这类复杂行为，也可以是「向后转」这类机械动作。
  4. 边实例化：渲染当前节点的人-场景快照作为首帧，以动作单元描述为 prompt，用物理增强后的 I2V 模型生成一段视频；再用动捕（WHAC）抽出 SMPL-X 序列，把逐帧运动变化施加到 3D 场景中的虚拟人上，状态从 Ni​ 更新到 Nj​；新节点渲染成下一段的首帧。相机固定，避免生成未观测区域的幻觉。
  5. 批判 agent：读若干渲染帧，评估朝向、与目标的距离、路线贴合度；从最后一帧开始时间回溯，找到最符合预期的最晚帧 i，把 i 之后的帧连同对应边和节点从图中剪掉；若朝向偏离，预测一个纠正转角并把旋转平滑分摊到剩余 i 帧；再为下一段设定最优相机视角（目标区域无遮挡、人物居中且尺度合适）；最后调整后续计划把人引回原路线。
  6. 物理增强：用 VEO、HunYuan-Video、Runway、Kling 生成样本，由专业标注者按指令跟随、运动伪影、肢体形变、场景不一致四个标准标出正负样本，共 10,000 对偏好数据，在 Wan2.1-I2V-14B 上做 DPO（8×A100 约 20 小时，lr 1e-5，β=5000）。推理 30 步、CFG 4.5，VLM agent 用 Gemini-2.5-Pro。

§ 6 — 核心数学推导 ​

状态转移被写成图上的加法：Hj​=Hi​+Ai,j​，即节点 Ni​ 中的人执行动作单元 Ai,j​ 后到达 Nj​。长时人体运动本是逐帧连续的，若把每一帧都设成节点，图会爆炸；因此只把动作单元的起止状态定义为节点，图的粒度与语言描述的粒度对齐。

物理对齐用 DiffusionDPO 形式的损失：

LDPO​=−E[logσ(−2β​(L(xw​,p)−L(xl​,p)))]

其中 xw​、xl​ 是同一 prompt p 下的正负样本，L(⋅,p) 是各自的扩散损失，β 是温度系数。直觉是：不要求模型去拟合某个「正确视频」，只要求它把正样本的似然抬到负样本之上。这对「物理可信」这类难以写成显式约束的目标特别合适——你说不清脚不该滑多少，但你能一眼看出哪段滑得更少。β=5000 这个取值相当大，意味着对偏好差异的惩罚很陡，可以推断作者希望模型强烈偏向正样本，代价可能是牺牲一部分生成多样性。

§ 7 — 实验设计与结论 ​

如何在没有公开 HSI 基准的情况下评测？ 论文指出 TRUMANS 只放出训练集、LINGO 未公开评测集，于是自建 SceneBench：20 个 3D 场景（10 室内 10 室外，来自 TRUMANS 与 Sketchfab），涵盖住宅、牛棚、健身房、草地、河岸、城市街道、乡村农场等，每个场景标注自然语言交互任务与起止位置，共 120 个「文本-场景-位置」测试实例。另设场景感知测试：从 SceneBench 取 15 个物体 + 从网络收集 15 个额外 3D 模型（含训练中未见的南瓜、石头），放在预规划路径上。

与 HSI 基线比如何？ 对比 TRUMANS、LINGO、PedGen，并为公平起见给基线提供真值轨迹或起止点（本文只需高层语言指令）。按论文表 1 的列序（P-Score、FS、CLIP-S、CLIP-Consistency、Diversity、POS、RDS，此列序与正文描述一致），本文为 0.020 / 0.102 / 0.31 / 0.9937 / 0.1911 / 0.063 / 0.3285，TRUMANS 0.083 / 0.156 / 0.19 / 0.9943 / 0.1703 / 0.126 / 0.1806，LINGO 0.085 / 0.148 / 0.20 / 0.9931 / 0.1510 / 0.133 / 0.1592，PedGen 0.063 / 0.199 / 0.17 / 0.9928 / 0.1102 / 0.119 / 0.1290。即穿模最低、脚滑最低、文本对齐最高、多样性最高、障碍穿模与反应差异两项均最优；CLIP-Consistency 略低于 TRUMANS。

三个 agent 各自有多重要？ 去掉多智能体（直接用视频模型生成复杂动作）CLIP-S 从 0.31 掉到 0.24；去掉批判 agent 掉到 0.23。定性上，没有多智能体时「跳上栅栏」生成不出来，有了动作链分解后模型先「双手撑石」再「起跳落地」才成功；没有批判 agent 时虚拟人偏离路线后无法回到目标位置。作者特别指出去掉批判 agent 后 Diversity 反而从 0.1911 微升到 0.1916，原因是那些本该被回溯剪掉的偏离片段被计入了——这是一个诚实的注解。

DPO 有用吗？ 与 SFT 和原始预训练模型对比：Ours 0.020 / 0.102 / 0.31，SFT 0.034 / 0.124 / 0.27，Baseline 0.051 / 0.149 / 0.23。穿模与脚滑随 Baseline → SFT → DPO 单调下降。

§ 8 — Take-aways ​

5 句版：HSI 的配对数据瓶颈可以用「视频模型出先验 + VLM 出规划 + 动捕回 3D」的组合绕开；把交互过程写成动态有向图，使生成模型的随机漂移变成可检测、可剪枝的具体对象；批判 agent 的时间回溯 + 朝向纠正是长程逻辑一致性的关键（去掉后 CLIP-S 从 0.31 降到 0.23）；物理可信度用 DPO 对齐比用显式约束更实际，穿模从 0.051 降到 0.020；VLM 读俯视图带来的语义感知范围远超占据栅格的 1 米点云盒，这解释了为何只有本文能对未见障碍做出跨越反应。

3 句版：用图结构给生成式随机性一个可回溯的载体，是这篇论文最可迁移的想法。动作链分解让「跳上栅栏」这类需要中间步骤的复杂动作变得可生成。DPO 把「物理可信」这个说不清的目标变成了可优化的偏好排序。

1 句版：把长程人-场景交互当成图搜索，让 VLM 规划、视频模型演出、批判者剪枝，随机性就从缺陷变成了可管理的分支。

§ 9 — 最脆弱的假设 ​

最关键的假设是：从生成视频动捕回来的 SMPL-X 运动，可以被当作虚拟人在 3D 场景中的真实状态转移。整条流水线是「渲染首帧 → 生成视频 → 动捕 → 更新 3D 状态 → 再渲染」的闭环，每一轮都要求动捕结果在几何上与场景对齐；一旦这一步有系统性偏差，误差会在每条边上累积，图上所有下游节点的状态都不再可信，长程一致性这个核心卖点直接失效。

它在实践中可能不成立的原因很具体：视频生成模型输出的是像素，不受场景几何约束；动捕从单目视频恢复的深度与绝对尺度本就欠定；而论文为了避免生成未观测区域的幻觉，采用固定相机，这意味着深度线索主要来自透视缩放，与 PEWM 那类工作遇到的问题同源——当运动方向接近垂直于成像平面时，尺度变化不足以稳健地推断位移。

论文提供的间接证据是穿模分数 P-Score 0.020 与障碍穿模 POS 0.063 都远低于基线，说明累积误差至少没有大到把人塞进墙里；批判 agent 的存在也构成一种误差抑制机制。但缺的是直接证据：没有报告动捕本身的重投影误差或绝对位置误差，也没有报告随动作链长度增长的位置漂移曲线。论文实验中长程任务的具体步数与漂移量都没有量化，「长程」到底能撑多久是未知的。

§ 10 — 最小复现实验 ​

一周内可做的最小验证，目标是检验「批判 agent 的回溯剪枝是长程一致性的主因」，不必复现 DPO 训练：

  • 数据：从 Sketchfab 取 5 个场景，人工设计 20 条长程指令（每条预期 6–10 个动作单元），标注起止位置。
  • 实现：用任意可调用的 VLM（Gemini/GPT-4o 一类）实现导航与规划 agent，视频生成直接用未经 DPO 的开源 Wan2.1-I2V，动捕用现成的单目 SMPL-X 方法。两个 arm——(a) 无批判 agent，(b) 有批判 agent（只实现「回溯到最匹配帧 + 剪枝 + 朝向纠正」三步）。
  • 测量：每执行完一个动作单元，记录虚拟人位置与规划路径的偏差；画出偏差随动作单元序号的增长曲线；同时记录任务终点是否到达。
  • 判据：若 (b) 的偏差曲线明显更平、终点到达率显著更高，则回溯机制的贡献成立；若两条曲线都在 6 个单元内发散，说明瓶颈在动捕的尺度恢复而非规划纠偏，论文的主要贡献点需要重新归因。

§ 11 — 最强反例设计 ​

替代解释：本文相对 TRUMANS/LINGO/PedGen 的优势可能主要来自基座模型的量级差异，而非图结构与多智能体设计。本文的动作先验来自 14B 的视频扩散模型 + Gemini-2.5-Pro，基线则是在有限配对数据上训练的专用运动模型。这是一次跨范式对比，不是受控对比。更公平的对照应当是：把同一个 DPO 后的视频模型 + 动捕链路直接跑长指令（即论文的 w/o multi-agents 设置），再与完整系统比——论文做了这个消融，CLIP-S 0.24 对 0.31，差距存在但不算悬殊；而 P-Score（0.022 对 0.020）与 FS（0.103 对 0.102）几乎完全相同，说明物理可信度这一项几乎全部来自 DPO，与多智能体架构无关。反对者可以据此主张：论文真正有效的是 DPO 后的视频先验，图与 agent 只贡献了任务完成度。

可预测的失败场景：动态环境。论文在 limitation 里承认，因缺少动态环境数据集，研究只在静态环境中进行。可以预期，当场景中有移动物体（另一个人走过、车经过、门被风吹动）时，「渲染快照作为首帧」这一机制会失效——快照只能反映规划时刻的场景状态，而生成过程中环境已经变了。另一个可预测的失败是实时性：作者指出扩散视频生成与 VLM agent 的推理速度构成计算瓶颈，无法用于实时交互，而每条边都要跑一次 30 步扩散 + 一次动捕 + 多次 VLM 调用，长程任务的端到端时间会线性累积。

§ 12 — Follow-up Research Idea ​

驱动局限：当前系统里，环境是只读的。批判 agent 能改人的轨迹与朝向，却不能改场景；动作单元只描述人做了什么，不描述世界因此变成了什么样。这使得整套框架只能处理「人在静态布景里活动」，而真实的人-场景交互本质是双向的——开门之后门是开的，推倒椅子之后椅子是倒的，后续所有规划都要基于新的场景状态。

新的 framing：把有向图的节点从「人的状态 + 静态场景」升级为「人的状态 + 可变场景状态」，把边从「人的动作」升级为「对世界的编辑操作」。也就是说，让规划 agent 输出的不只是动作描述，还包括这个动作对场景图的预期修改（哪个物体的位姿/开合状态会变），并让批判 agent 同时校验人的轨迹与场景的一致性。

可借鉴的相邻领域工具：机器人 TAMP 里的符号状态与算子前置/后置条件，已经形式化了「动作如何改变世界」；场景图生成与可动物体（articulated object）建模提供了把 3D 场景表示成可编辑结构的现成手段；视频编辑里的物体级一致性控制提供了让生成器遵守指定场景变化的机制。

第一个实验：构造一个必须改变场景状态的最小任务——「打开抽屉，把杯子放进去，再关上抽屉」。对比两种设置：(a) 场景静态，只靠视频生成隐式表现抽屉开合（本文）；(b) 显式维护抽屉的开合参数，每条边执行后更新场景 mesh 再渲染下一首帧。度量三点：关抽屉时杯子是否还在里面、抽屉开合状态在渲染帧与生成帧之间是否一致、第三条动作单元的首帧是否正确显示了打开的抽屉。若 (b) 明显更好，说明「场景可写」是这类框架的下一个必要条件，HSI 会从「人在场景里动」变成「人与场景互相改写」。
