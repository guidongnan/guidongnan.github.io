MineWorld: a Real-Time and Open-Source Interactive World Model on Minecraft ​

项内容
arXiv2504.08388
提交日期2025-04-11
作者Junliang Guo, Yang Ye, Tianyu He, Haoyu Wu, Yushu Jiang, Tim Pearce, Jiang Bian
分类cs.CV, cs.AI
一句话把游戏画面和动作各自离散化成 token 交错拼成一条序列做 next-token prediction，再用对角线并行解码把自回归采样提速 3 倍，让 Minecraft 世界模型跑到 4–7 FPS 的真实交互频率。

所属教程：世界模型

§ 1 — 研究问题与重要性 ​

世界模型要有用，必须能被实时操作。论文把这件事量化得很硬：StarCraft 职业选手的 APM（每分钟操作数）约 250–300，业余玩家约 50，作者自己测的业余玩家平均 150 APM。换算成帧率，世界模型要跟上业余玩家需要 >2 FPS，跟上职业选手需要 5 FPS。低于这个数，模型就不是"交互式世界模型"，而是"离线视频预测器"。

效率瓶颈在哪，论文说得具体：SoTA 视觉 tokenizer 把 16 帧编码成 4 万到 16 万个 token。自回归模型逐个吐 token，推理开销直接与这个数字成正比。第二个问题是可控性——世界模型的核心属性是"给不同动作要得到不同结果"，但当条件信号是文本、视频演示或机械臂位姿时，没有标准化指标能量化"生成结果有多符合输入信号"。

MineWorld 同时打这两个点：并行解码解决效率，基于逆动力学模型的分类指标解决可控性度量，并且把代码和权重全部开源。

§ 2 — 前人工作与不足 ​

论文的直接对照是 Oasis（Decart 等，2024），一个基于扩散的开源 Minecraft 世界模型。Oasis 已经能做到实时交互的演示效果，但论文指出关键前提：它需要更大的模型 + 专用芯片 + 不公开的推理引擎，这些资源公众无法获取。换句话说，Oasis 的实时性是系统工程换来的，不可复现。

在并行解码这条线上，Lformer 每次生成 L 形 token 块，但要求从头训练；ZipAR 利用相邻 token 依赖做图像并行解码，但只针对单张图像。论文指出视频场景的额外难度：跨帧的误差累积。图像里一个 token 猜错只影响当前图；视频里它会污染后续所有帧。这解释了为什么图像的并行解码方案不能直接搬过来——不是没人想到，是视频的误差传播特性让"训练—推理不一致"的代价被放大。

§ 3 — 重建作者的思考路径 ​

只用本文之前的既有知识：

第一步，VQ tokenizer + Transformer 做 next-token prediction 已经在图像（Taming Transformers）和视频（VideoPoet）上验证可行，且有明确的 scaling 行为。把动作也 tokenize 之后与画面交错，模型自然会同时学到"状态→状态"和"状态+动作→状态"的条件关系——这是一个几乎免费的设计，且顺带让同一个模型可以当 policy 用。

第二步，观察 VQ token 网格的结构。图像 token 在空间上是有序排布的，raster-scan 顺序下 xi,j​ 的下一个是 xi,j+1​。但 xi,j+1​ 和 xi+1,j​ 都只依赖 xi,j​ 附近的信息——它们之间的依赖弱。既然弱，为什么要串行等？这直接导出对角线波前式的并行调度。

第三步，任何并行解码都会造成训练（因果 mask）与推理（并行 mask）的分布不一致，导致质量下降。既然已经有预训练模型，最省事的修法是用与并行解码对齐的 attention mask 再微调一遍，而不是从头训练。

第四步，可控性怎么测。VPT 数据集自带动作标注，且 VPT 附带一个逆动力学模型（IDM），在按键预测上有 90.6% 的准确率。那么把 IDM 从生成的连续两帧里反推出动作，与输入的真值动作比对，就把"生成是否听话"变成了一个标准的分类问题——precision / recall / F1 直接可用。

§ 4 — 核心 Intuition ​

一帧游戏画面的 token 网格里，相邻行列的 token 之间依赖很弱：知道了左上角那个，右边和下边那个几乎可以同时定。所以不必按 raster-scan 一个一个等，可以让整条对角线一起走。理论加速比是 h+w−1h×w​——分辨率越高，串行的浪费越大，这个方法赚得越多。剩下的训练—推理不一致，用一次带并行 mask 的微调补回来。

§ 5 — 具体方法与完整 Pipeline ​

一个真实样例：玩家站在屋内，按下 forward 并向左转视角，模型要生成开门走出去的后续画面。

  • 视觉 tokenizer：VQ-VAE，从 aMUSEd 公开 checkpoint 初始化后在 Minecraft 数据上微调。空间压缩率 16×，码本 8192。原始 360×640 缩放到 224×384，切成 14×24 = 336 个 token 每帧。微调的收益是实打实的：重建 PSNR 从 25.91 → 29.24，SSIM 0.758 → 0.816，LPIPS 0.238 → 0.134，rFID 35.05 → 18.93。
  • 动作 tokenizer：连续的鼠标视角移动按 VPT 的方案离散成 11 个 bin（小幅度细、大幅度粗）；键盘动作按互斥关系归成 7 个互斥类（如 forward/backward 不可能同时发生），各占一个 token；再加 2 个相机角度 token 和 [aBOS] / [aEOS] 边界符，每个动作共 11 个 token。
  • 序列拼装：每对 (状态, 动作) = 336 + 11 = 347 token。16 对构成一个样本 ≈ 5.5k token。训练集 10M 个 16 帧片段（160M 帧），合计 55B token；验证/测试各 0.5k / 1k 片段。
  • Transformer：LLaMA 架构（RMSNorm + RoPE），三档规模 300M / 700M / 1.2B，词表 8192 + 70 = 8262。32 张 A100-40G 训 200k 步，AdamW + cosine 调度。训练目标就是标准的 next-token prediction，状态 token 和动作 token 一视同仁——这让同一个模型既能预测未来状态（world model），也能预测下一个动作（policy）。
  • 推理：对角线并行解码。生成了 xi,j​ 之后，下一步同时生成 xi,j+1​ 和 xi+1,j​。之后用并行 attention mask 微调预训练模型，补回质量损失。
  • 评测：把生成视频的相邻帧喂给 VPT 的 IDM 反推动作，与输入动作比 F1；相机角度比 L1。同时算 FVD / PSNR / LPIPS / SSIM。

§ 6 — 核心数学推导 ​

世界模型的建模目标：

p(xi+1​∣x<i​,ai​)

即给定历史状态和当前动作，预测下一状态。注意条件里同时有 x<i​ 和 ai​——它不是马尔可夫的，历史全部保留（在上下文窗口内）。

训练目标是把上式嵌进一条扁平序列的自回归分解：

fθ​(t)=i=1∏N​p(ti​∣t<i​)

这里 t 是状态 token 和动作 token 交错后的完整序列，N=n⋅c。这个写法的巧妙之处在于：因为动作 token 也在序列里被预测，模型隐式地同时学到了 p(ai+1​∣x<i+1​)——一个策略模型。世界模型和策略模型在这个形式下是同一个分解的不同切片。

并行解码的理论加速比：

r=h+w−1h×w​

推导直觉很简单：串行 raster-scan 要 h×w 步；对角线波前每步推进一条反对角线，h×w 的网格总共有 h+w−1 条反对角线。代入 MineWorld 的 h=14,w=24：r=336/37≈9.1。实测只有约 3 倍（300M 模型 2.00 → 5.91 FPS，1.2B 模型 0.89 → 3.01 FPS）。差距来自 KV cache 复用、显存带宽和批处理效率等系统开销，理论值是上界。

§ 7 — 实验设计与结论 ​

问题一：能不能达到实时？ 表 1 给出答案：300M 模型 5.91 FPS（≈354 APM，够职业选手），700M 3.18 FPS，1.2B 3.01 FPS（≈180 APM，够业余玩家）。Oasis 500M 为 2.58 FPS。三档模型都跨过了 2 FPS 的业余门槛。

问题二：比扩散基线好吗？ 全面胜出。以 1.2B 对 Oasis 500M：动作跟随 F1 0.73 vs 0.41，相机 L1 1.02 vs 2.60，FVD 227 vs 377，PSNR 15.69 vs 14.38，LPIPS 0.44 vs 0.53。可控性上的差距（F1 0.73 对 0.41）比画质差距大得多，这与论文"自回归 Transformer 可控性好"的动机吻合。

问题三：并行解码代价多大？ 表 2 是本文最诚实的一张表。1.2B 模型：纯自回归 0.89 FPS / F1 0.72 / PSNR 16.06 / FVD 203；并行 + 微调 3.01 FPS / F1 0.73 / PSNR 15.69 / FVD 227；并行不微调 F1 0.70 / PSNR 15.30 / FVD 258。三条结论：（a）3.4× 加速的代价是 FVD 从 203 涨到 227，PSNR 掉 0.37；（b）微调把 FVD 从 258 拉回 227，确实有效；（c）大模型对并行解码更鲁棒——300M 不微调时 F1 掉到 0.69，1.2B 掉到 0.70 但微调后能回到 0.73 甚至超过自回归的 0.72。

问题四：scaling 成立吗？ 300M → 1.2B，F1 从 0.70 → 0.73，FVD 从 246 → 227，PSNR 从 15.13 → 15.69。单调改善，但幅度不大，而 FPS 从 5.91 掉到 3.01。这是一个明确的质量—速度权衡曲线。

问题五：新指标可信吗？ 20 个测试片段、5 名有经验玩家、1–5 分打分，与 F1 算 Pearson 相关。论文称"significant positive correlation"，但 HTML 版的表 3 里 r 值与 p 值单元格为空，具体数值无法核验。

细分动作看（700M 模型）：forward-backward F1 0.782、left-right 0.771、jump 0.796 都不错，但 drop 只有 0.499——接近随机。论文归因于该动作更难学；可以推断真实原因是 VPT 数据里 drop 极其稀有，且它的视觉后果（物品掉出）在低分辨率下几乎不可见。

§ 8 — Take-aways ​

5 句话：MineWorld 把画面和动作分别离散化成 token 后交错拼成一条序列，用标准 next-token prediction 训练 LLaMA 架构的 Transformer，同时获得世界模型和策略模型两种能力。实时性瓶颈来自每帧 336 个 token 的串行解码，用对角线并行解码（理论加速 hw/(h+w−1)）把它压掉约 3 倍，代价是 FVD 从 203 升到 227。用并行 attention mask 微调可以把大部分质量损失补回来。可控性用 VPT 的逆动力学模型反推动作再算分类 F1 来度量，把"听不听话"变成可量化的问题，1.2B 模型达到 0.73，远高于扩散基线 Oasis 的 0.41。三档模型（300M/1.2B）分别跑到 5.91 / 3.01 FPS，跨过职业与业余玩家的 APM 门槛，且代码权重全部开源。

3 句话：token 网格里相邻行列的依赖很弱，所以自回归不必真的串行。可控性可以用逆动力学模型转化成分类问题来测量。开源 + 商用硬件下的实时性，比闭源 + 专用芯片下的实时性更有价值。

1 句话：让画面 token 沿对角线并肩走，世界模型就跟得上人的手速。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：VPT 的逆动力学模型能忠实地从生成帧中反推出动作。整个可控性评测体系——本文最重要的方法论贡献——完全建立在这上面。

它可能不成立的原因是分布偏移。IDM 是在真实 Minecraft 录像上训练的，论文引用的 90.6% 按键准确率也是在真实帧上测的。但评测时它面对的是 VQ-VAE 重建 + Transformer 生成的帧，这些帧带有码本量化伪影和生成模型特有的纹理。IDM 在这类输入上的准确率是多少，论文没有报告。更麻烦的是失败方向可能有偏：如果 IDM 对某类生成伪影系统性地误判为"无动作"，那么 F1 会低估所有生成模型；如果生成模型学到的画面恰好落在 IDM 决策边界的某一侧，F1 又会虚高。

论文提供的证据：20 个片段、5 名玩家的人类相关性研究，且相关系数数值在可获取的 HTML 版中缺失。缺什么证据：IDM 在真实帧与生成帧上的准确率对照。这是一个几乎零成本的实验（把 GT 帧和生成帧都过一遍 IDM 比准确率），却没有做。20 个样本的人类研究在统计功效上也偏弱。

§ 10 — 最小复现实验 ​

一周内可完成，目标是给上一节的假设定量：

  • 下载 VPT 的 IDM 和 MineWorld 的开源权重（论文声明代码与模型已发布）。
  • 从 VPT 测试集取 500 个 16 帧片段，得到三组视频：（a）GT 原始帧；（b）GT 帧经 MineWorld 的 VQ-VAE 编码再解码的重建帧；（c）MineWorld 以第一帧和真值动作序列生成的生成帧。
  • 对三组分别跑 IDM，与真值动作算同一套 macro F1 和相机 L1。
  • 判据：（a）组的 F1 是 IDM 的能力天花板。若（b）组相对（a）组下降超过 5 个点，说明仅 tokenizer 的量化伪影就已经严重干扰 IDM，那么论文报告的 0.73 里有相当一部分损失并非来自世界模型本身，可控性被系统性低估；若（b）≈（a）而（c）显著更低，则该指标干净可用，论文结论成立。

顺带可以扫一遍分辨率：把生成帧上采样或降采样后重测，验证 IDM 对分辨率是否敏感。

§ 11 — 最强反例设计 ​

站在反对者立场，最有力的攻击是给"MineWorld 学到了世界知识"一个替代解释：它可能主要学到了"视觉惯性 + 相机变换"，而不是环境的因果结构。

论文的定性证据里，最强的一个是"相机左摇再右摇，房子被正确重现"。但这可以被更弱的机制解释——16 帧上下文窗口内，房子从未真正离开过 KV cache，模型只需做一个近似的仿射外推。设计一个直接的反例实验：构造相机往返幅度分别为 8 帧、16 帧、24 帧、32 帧的测试序列（即物体离开视野的时长跨越上下文窗口边界），测量重现物体的 PSNR。预测：一旦往返跨度超过 16 对状态—动作（5.5k token 上限），重现能力会断崖式消失。论文自己在 limitations 里承认了这一点——"it is not guaranteed when the distance between game states exceeds this range"——但没有给出这条曲线。如果曲线在窗口边界处是断崖而非缓降，那么"MineWorld 学到了持久的世界状态"这一叙述就必须弱化为"MineWorld 在上下文窗口内做了正确的几何外推"。

第二条攻击针对 FPS 的口径。论文报告的 300M 模型 5.91 FPS 是在什么 batch size、什么上下文长度下测的，正文未明确。自回归模型的吞吐随 KV cache 长度增长而下降；如果 5.91 是在上下文接近空时测的，真实交互（上下文填满 5.5k token）下的稳态 FPS 会更低。让 FPS 随已生成帧数变成一条曲线而不是一个数，是检验"实时"这一 claim 的直接方式。

§ 12 — Follow-up Research Idea ​

驱动局限：MineWorld 的动作 token 是从游戏引擎里拿到的特权信息——键盘按键和鼠标增量，这只有在游戏环境里才免费可得。同时它的评测依赖 VPT 的 IDM，也只在 Minecraft 存在。两个依赖叠加，让这套方法论无法迁移到任何真实世界视频。而论文自己也把"无法泛化到互联网视频"列为首要 limitation。

新 framing：不要再假设动作词表是给定的，改问"能否让动作词表和世界模型在同一个 next-token prediction 目标下被联合发现"。具体地，把动作 token 从"引擎给的标签"改成"模型必须自己解释帧间变化的离散瓶颈变量"：在两帧之间插入一小段可学习的离散 latent，要求它足够窄以至于只能编码"发生了什么操作"，并同时被用作生成条件和被从帧对中反推。这样世界模型与逆动力学模型在训练中互为对偶，评测所需的 IDM 也随之免费得到——可控性指标不再需要外部标注器。

可借鉴的邻域工具：（a）Genie 的 latent action model 已经证明无标注视频里可以蒸馏出可控的离散动作空间；（b）语音领域的 self-supervised unit discovery（HuBERT / VQ-APC）处理的是同一类问题——从连续信号里发现离散、可组合的单元；（c）信息瓶颈理论提供了"latent 应该多窄"的原则性刻画。

第一个实验：在 VPT 数据上做一个可证伪的对照。训练两个同规模的 MineWorld（300M）：A 用真值动作 token，B 用自监督发现的离散 latent action（码本大小设为与真值动作空间同量级，如 64）。然后用 VPT 的 IDM 评测两者的可控性——注意 B 的 latent 与真值动作不同构，所以要先在小规模标注集上学一个 latent→真值动作的线性映射，再评 F1。判据：若 B 的 F1 达到 A 的 85% 以上，说明动作标注不是必需品，这条路可以直接推到互联网视频；若差距巨大，则说明 next-token prediction 目标本身不足以逼出有意义的动作空间，需要额外的结构约束（例如强制 latent 对时序可交换性的响应），这同样是明确的下一步。
