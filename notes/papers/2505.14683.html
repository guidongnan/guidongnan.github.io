Emerging Properties in Unified Multimodal Pretraining ​

项内容
arXiv2505.14683
提交日期2025-05-20（v2 2025-05-23，v3 2025-07-27；37 页 17 图）
作者Chaorui Deng, Deyao Zhu, Kunchang Li, Chenhui Gou, Feng Li, Zeyu Wang, Shu Zhong, Weihao Yu, Xiaonan Nie 等（ByteDance Seed）
分类cs.CV
一句话用 Mixture-of-Transformer-Experts 把理解专家与生成专家挂在同一条自注意力序列上（无 connector 瓶颈），在 5.1T token 的交错图文/视频/网页数据上预训练 7B 激活参数的 BAGEL，观察到编辑与"智能编辑"能力分别在 2.64T 与 3.61T token 处才追上来。

所属教程：后训练与强化学习

版本与取全文说明

本文按 v3（2025-07-27）全文撰写。取全文时踩到一个典型陷阱：该条目的 abs 页只挂了 View PDF 与 TeX Source、没有 HTML 入口，ar5iv 也不好用，但手工拼 arxiv.org/html/2505.14683v3 可以打开完整正文（380KB HTML）。另有两处小瑕疵：正文说 reasoning-augmented 数据分"四类"，实际只列了三类（T2I 生成、free-form 图像操作、conceptual edits）；§7.2 称"BAGEL 在 WISE 上超过除 GPT-4o 外的所有已有模型"，但 Tab. 6 里不开 CoT 的 BAGEL 是 0.52、低于 MetaQuery-XL 的 0.55，只有 Self-CoT 版本（0.70）成立。

§ 1 — 研究问题与重要性 ​

统一理解与生成这件事，闭源系统（GPT-4o 一类）已经展示了很强的能力，开源侧却始终差一截。差在哪，论文给了一个具体的架构诊断：开源统一模型普遍在理解模块与生成模块之间放了一个 connector 瓶颈。语言骨干先自回归地吐出一小组 latent token 当"语义条件"，再交给扩散模块画图。这种设计收敛快、数据省，在标准 benchmark 上也能跑出好看的分数，但它把整条 LLM 上下文压进了几十个 token。

作者的主张是：这个压缩与大模型的 scaling 哲学相冲突。真正想要的能力——多步推理后再编辑、跨图保持一致性、按世界知识补全场景——恰恰依赖长上下文里那些不会被总结进几十个 token 的细节。瓶颈会让这些能力永远无法从数据里长出来，而且你在 loss 曲线上看不出它被挡住了。

第二个更有意思的主张是关于评测的：这类能力现有 benchmark 测不出来。GenEval 测的是"图里有没有两个物体、颜色对不对"，GEdit-Bench 测的是常规编辑指令，它们都在模型早期就饱和了。如果只看这些数，会得出"统一模型早就训够了"的错误结论。

§ 2 — 前人工作与不足 ​

论文把设计空间干净地切成三条路线。

Quantized AR（Chameleon、Emu3、Janus 系、VILA-U、TokenFlow）：用离散视觉 tokenizer，文本和图像都走 next-token-prediction，能直接复用 LLM 基础设施。两个缺点：生成质量经验上不如扩散；自回归的串行性让推理延迟很高。表 5 里 Emu3-Gen 的 GenEval 是 0.66、Janus 是 0.61，确实低于扩散侧的 SD3-Medium 0.74。

External Diffuser（DreamLLM、SEED-X、MetaMorph、MetaQuery、LlamaFusion）：LLM/VLM 接一个外部扩散模块，中间靠轻量 adapter。收敛快、数据省，MetaQuery-XL 甚至在若干榜单上很有竞争力（GenEval 0.80、WISE 0.55、MMMU 58.6）。但它就是上面说的瓶颈路线，而且 MetaQuery 用的是冻结的 Qwen2.5-VL 骨干，理解侧根本不参与训练，适应性受限。

Integrated Transformer（Transfusion、Show-o、LlamaFusion、MetaMorph 部分工作）：在同一个 transformer 里同时跑自回归与扩散，全程无瓶颈，最适合 scaling。代价是训练算力需求显著更高——这正是它被少数人做的原因。

作者选第三条，理由不是"它现在分高"，而是"只有它在大规模训练下才有可能长出那些 benchmark 还测不到的能力"。这个论证是前瞻性的，所以本文必须自己造评测（IntelligentBench）来支撑它，而这一点后面会成为最大的方法论负担。

§ 3 — 重建作者的思考路径 ​

第一步是接受一个不受欢迎的结论：想要长上下文多模态推理，就不能压缩上下文。这直接排除了所有 connector 方案，也就接受了更高的训练成本。

第二步是问：无瓶颈的单塔里，理解和生成会不会打架。这是个可以实验回答的问题——在 1.5B Qwen2.5 上固定一切、只换 transformer 结构，比 Dense / MoE（只复制 FFN）/ MoT（复制全部参数）。三者 FLOPs 完全相同，MoE 与 MoT 只是把总参数量翻倍。结果 MoT 全面最好，生成侧差距最大。作者的解读是两个目标把模型往参数空间的不同区域推，给它们分配独立容量能缓解这个冲突。

第三步是数据。图文对能教基本的看图与画图，但教不了"多张图 + 中间文字"的连贯推理。所以必须自己造交错数据，而世界上最大的交错数据来源有两个：视频（时间上天然连续，帧间变化就是免费的监督）和网页（图文天然穿插，教程与百科最理想）。

第四步是承认现有 benchmark 不够。既然赌注押在"新能力会涌现"上，就必须有一个能测到它的尺子。于是有了 IntelligentBench——但这也意味着核心 claim 依赖一把作者自己造的尺子。

第五步是一个很具体的工程发现：直接把交错数据拿来训，图像与它周围文字的对齐很弱（网页里图片和上下文经常只是松散相关）。作者的解法是 caption-first——先给每张图生成一句简洁描述、插在图片之前，让模型在生成图之前先形成一个"概念草稿"。这是从"生成困难"倒推出来的数据设计。

§ 4 — 核心 Intuition ​

理解与生成之所以在统一模型里互相拖累，一半是优化问题（两个目标把参数往不同方向拉），一半是架构问题（connector 把上下文压掉了）。MoT 解决前者——同样的 FLOPs 下给两类 token 各自一套完整参数，只在自注意力处交汇；无瓶颈的共享注意力解决后者。两件事都做到之后，能力不是一起出现的，而是按复杂度排队出现：先是基础理解与生成，再是常规编辑，最后才是需要世界知识与多步推理的自由形态操作，而最后这一档要到 3.61T token 才追上来。

§ 5 — 具体方法与完整 Pipeline ​

架构。骨干 Qwen2.5（RMSNorm / SwiGLU / RoPE / GQA），额外加 QK-Norm 稳训练。视觉分两路：理解侧用 SigLIP2-so400m/14（384 分辨率初始化，position embedding 插值到最大 980×980，集成 NaViT 支持原生宽高比，两层 MLP 连到 LLM 维度）；生成侧用 FLUX 的 VAE（下采样 8、latent 通道 16，全程冻结），再过一个 2×2 patch embedding。扩散时间步不用 AdaLN，而是直接加到 VAE token 的初始 hidden state 上，架构更干净。ViT 与 VAE token 都先加 2D 位置编码再进 LLM。MoT 的路由是硬路由：生成专家只处理 VAE token，理解专家处理文本与 ViT token。

Generalized causal attention。每张图准备三套 token：noised VAE（加了扩散噪声，只用于 Rectified-Flow 训练，MSE loss 只在这套上算）、clean VAE（无噪声，作为后续图/文生成的条件）、ViT（SigLIP2 编码，统一交错生成与理解的输入格式，经验上还能提升交错生成质量）。规则是：后续 token 可以 attend 到前面图像的 clean VAE 与 ViT，但看不到 noised VAE。多图生成用 diffusion forcing（不同图独立噪声水平），并随机把连续若干张图分组、组内全注意力且共享噪声水平以增强一致性。实现用 PyTorch FlexAttention，比朴素 SDPA 快约 2 倍。推理时只缓存 clean VAE 与 ViT 的 KV，一张图生成完就把上下文里的 noised token 换成 clean 版本。交错推理的 CFG 靠随机丢弃实现，丢弃概率分别是文本 0.1、ViT 0.5、clean VAE 0.1。

数据（Tab. 1，合计约 5.1T token）：文本 400M 条 / 0.4T token；图文对理解 500M / 0.5T；图文对生成 1600M / 2.6T；交错理解 100M / 0.5T；交错生成-视频 45M / 0.7T；交错生成-网页 20M / 0.4T。

视频侧：公开在线视频 + Koala36M + MVImgNet2.0。做法是给相邻帧之间的视觉变化生成描述（物体运动、动作转换、场景切换），当作时序监督。大 VLM 太贵，于是从 Qwen2.5-VL-7B 蒸一个轻量 captioner，在少量高质量帧间样本上微调，并把 caption 长度截到 30 token 以抑制幻觉。每段平均采 4 帧，逐帧对生成描述，得到 45M 条时序对齐的交错序列。

网页侧：基于 OmniCorpus。两级过滤——先照 DeepSeekMath 的思路，让 LLM 标一小批文档，用这批标签训 fastText 分类器做大规模粗筛，再用 Qwen2.5-14B 精筛；然后一套规则过滤（Tab. 2）：URL 含 icon/widget 的图删掉；宽高在 [150, 20000] 且宽高比在 [1/2, 2]；清晰度算子去模糊图；OCR 文字超过 100 token 的文档式图片丢弃；CLIP 相似度去冗余；LLM 去页眉页脚；只保留含 3–8 张图的文档。再加 caption-first 策略与"图间文本超过 300 token 就用 LLM 摘要"，得到 20M 篇。

推理增强数据 50 万条：T2I 用人工写的模糊 query 起手，Qwen2.5-72B in-context 扩出 query-guidance 对与详细 prompt，FLUX.1-dev 出图，得到 (query, 推理轨迹, 图) 三元组；free-form 操作用 VLM 配 DeepSeek-R1 的推理范例生成轨迹，源-目标图对来自 OmniEdit 与交错视频数据；conceptual edits 用网页交错数据做三段式 VLM 流水线（选图对 → 生成问题 → 质量评估过滤）再生成推理解释。

训练四阶段（Tab. 3）。Alignment：只训 MLP connector，lr 1×10−3 余弦、5K 步、4.9B token、图像固定 378×378。PT：加 QK-Norm，除 VAE 外全部可训，lr 1×10−4 常数、200K 步、2.5T token、每 rank 序列 32–36K、上下文窗口 16K、生成分辨率 256–512、理解分辨率 224–980、timestep shift 1.0、EMA 0.9999。CT：提分辨率（生成 512–1024）与上下文（40K），并把交错数据的采样比从 0.25 提到 0.45，2.6T token，timestep shift 提到 4.0。SFT：lr 2.5×10−5、15K 步、72.7B token。全程 AdamW β=(0.9,0.95)，ϵ=1.0×10−15 用来压 loss spike，CE:MSE 损失权重 0.25:1，PT/CT/SFT 用常数学习率以便随时加数据继续训。

§ 6 — 核心数学推导 ​

本文无形式化数学推导，跳过。

论文是一份实证技术报告，正文没有任何编号公式。生成侧直接采用 Rectified Flow（引用 SD3 与 rectified flow 原文），文本侧是标准 next-token-prediction，两者用固定权重 CE:MSE =0.25:1 线性相加。唯一带数值的"设计推导"是 §4.1/4.2 那两组 1.5B 上的曲线：把生成数据采样比从 50%（1g1u）提到 80%（4g1u），MSE loss 有 0.4% 的绝对下降（作者称这对 rectified-flow 模型是可观的幅度），而 CE loss 没有一致规律，最大差距是第 14,000 步处 4g1u 与 2g1u 之间的 0.07；学习率上两个 loss 方向相反——大 lr 利于 MSE 收敛、小 lr 利于 CE，作者用损失权重而非分组学习率来调和。

§ 7 — 实验设计与结论 ​

能力是按顺序出现的（§6，Fig. 7）。作者用"达到峰值性能 85% 所需的 token 数"作指标：多模态理解 0.18T、GenEval 生成 0.68T、GEdit 常规编辑 2.64T、IntelligentBench 智能编辑 3.61T。差了整整一个数量级。智能编辑在后期从 15 涨到 45，翻了三倍。定性侧一致：文本渲染（正确拼出 "hello" 与 "BAGEL"）在 1.5T–4.5T 之间才出现；而在 3.5T token 之前，模型面对智能编辑任务的行为是"把输入图几乎原样复制出来"——作者称之为任务没理解时的 fallback 策略。另有一条消融很有价值：去掉 ViT token 对 GEdit-Bench 影响很小，但让 Intelligent Edit 掉 16%，说明语义视觉理解是复杂编辑的必需品。

理解（Tab. 4）：BAGEL 7B MoT 的 MME-P 1687 / MME-S 2388 / MMBench 85.0 / MMMU 55.3 / MM-Vet 67.2 / MathVista 73.1 / MMVP 69.3。相比同为 7B 的 Janus-Pro，MMMU 与 MM-Vet 分别高出 14.3 与 17.1。相比专用理解模型 Qwen2.5-VL-3B（MME-S 2157、MMBench 79.1、MathVista 62.3）也全面更好。但 MetaQuery-XL 的 MMMU 是 58.6，高于 BAGEL 的 55.3——论文没直接提这一项，转而指出 MetaQuery 用的是冻结骨干。

文生图（Tab. 5）：BAGEL 不用 rewriter 是 GenEval 0.82，用 LLM rewriter 是 0.88，都是表里最高。不过分项要看：BAGEL 在 Position（0.64）低于 Janus-Pro-7B 的 0.79 与 FLUX.1-dev 的 0.68，Color Attribution（0.63）低于 Janus-Pro 的 0.66 与 FLUX 的 0.65，Colors（0.88）低于 FLUX 的 0.93。它的总分优势主要来自 Counting（0.81 vs FLUX 0.75、Janus-Pro 0.59）与 Two Object（0.94）。

世界知识生成（Tab. 6，WISE）：BAGEL 0.52、BAGEL w/ Self-CoT 0.70、MetaQuery-XL 0.55、FLUX.1-dev 0.50、GPT-4o 0.80。不开 CoT 的 BAGEL 低于 MetaQuery-XL，正文那句"超过除 GPT-4o 外所有已有模型"只对 Self-CoT 版本成立。CoT 带来 +0.18 是全文最大的单项提升之一。

图像编辑（Tab. 7，GEdit-Bench，GPT-4.1 打分）：BAGEL 在 EN 上 G_SC 7.36 / G_PQ 6.83 / G_O 6.52，Step1X-Edit 是 7.09 / 6.76 / 6.70。也就是说 BAGEL 在语义一致性与感知质量两个分项上都赢，却在综合分 G_O 上输（CN 侧同样：6.50 vs 6.86）。论文的措辞"与领先的专用编辑模型 Step1X-Edit 具有竞争力"是准确的，但没有点明综合分是落后的。对 Gemini 2.0（6.32 / 5.36）则是明确领先。

智能编辑（Tab. 8，IntelligentBench）：GPT-4o 78.9、Gemini 2.0 57.6、BAGEL 44.9、BAGEL w/ Self-CoT 55.3、Step1X-Edit 14.9。这里有个必须读脚注才知道的口径：GPT-4o 只回答了 350 题里的 318 题，Gemini 2.0 回答了 349 题，被拒答的题目不计分。三个数字来自三个不同的子集，严格说不可直接比较。

思考带来的增益在三个基准上一致：WISE 0.52→0.70、IntelligentBench 44.9→55.3、RISEBench 6.1→11.9、KRIS-Bench 56.21→60.18。

世界建模（§7.5）：用 ParticleSfM 从交错视频里标相机轨迹做导航数据微调，模型能按指令生成动态数量的图完成导航、旋转与多帧生成，且只在真实街景上训练却能泛化到水墨画、卡通与电子游戏。这条是定性展示，没有量化。

失败案例（Fig. 17）也如实给了：特定 IP、复杂文字渲染、精细人体姿态、同时生成多个实例仍然困难；编辑侧交换物体位置或同时改大量实例会失败；这些场景下 GPT-4o 最稳。

§ 8 — Take-aways ​

5 句话版：开源统一模型的通病是理解与生成之间隔着一个 connector 瓶颈，把 LLM 上下文压进几十个 token，从而挡住了长上下文多模态推理这类能力；BAGEL 选无瓶颈的 Integrated Transformer 路线，并用 MoT（同 FLOPs、双倍参数、硬路由）解决理解与生成的优化冲突，1.5B 上的对照实验显示 MoT 优于 MoE 与 Dense；训练数据的重心是自造的交错语料——45M 条视频帧间变化描述与 20M 篇经两级过滤的网页文档，后者用 caption-first 把描述插在图前以缓解图文对齐弱的问题；能力按复杂度排队出现，理解 0.18T、生成 0.68T、常规编辑 2.64T、智能编辑 3.61T token，而 loss 曲线对此毫无提示；显式思考在四个推理型基准上一致有效（WISE 0.52→0.70），但核心的"涌现"证据依赖作者自造且由 GPT-4o 评判的 IntelligentBench。

3 句话版：把理解专家与生成专家挂在同一条自注意力序列上（无瓶颈 + MoT），在 5.1T token 交错数据上训 7B 激活参数，得到一个理解不输专用 VLM、GenEval 0.88、编辑接近 Step1X-Edit 的统一模型。最重要的观察是能力出现的顺序与时间尺度——智能编辑要到 3.61T token 才达到峰值的 85%，比理解晚了 20 倍。但这个结论完全建立在一把作者自造、GPT-4o 打分、且未与人类判断校准过的尺子上。

1 句话版：无瓶颈单塔 + MoT + 大规模交错数据，让统一多模态模型长出按复杂度排队出现的编辑与推理能力。

§ 9 — 最脆弱的假设 ​

最脆弱的假设是：IntelligentBench 的分数变化真的对应能力变化，而不是评判者偏好的变化。

全文的核心 claim（"复杂多模态推理是涌现的，且要到 3.61T token"）只有这一条证据链支撑，因为其余基准都在 0.68T 前就饱和了。而这条链上有三个未经检验的环节叠在一起：(1) 350 道题由作者自己出，覆盖面与难度分布无外部验证；(2) 评分由 GPT-4o-2024-11-20 完成，读四元组（问题图、问题文本、参考答案图、模型生成图）后按"请求满足度、视觉一致性、知识驱动的创造性"打 0–2 分；(3) GPT-4o 自己也是这张榜上的选手，且得分最高（78.9）。论文没有做任何评判者与人类的一致性校准，也没有报告人类之间的一致率作为上限。

论文自己意识到了风险，写了一句"评测指标可能无法线性反映模型真实能力，从而产生虚假的涌现迹象，尽管这不太可能"。但那个"不太可能"没有证据支撑——恰恰相反，已有文献（论文自己引的 Wei et al.）指出涌现现象常常是不连续评测指标造成的假象，而 IntelligentBench 用的正是 0/1/2 三档离散打分再求和归一，这是最典型的会制造阶跃的度量形式。

如果这个假设不成立，需要改写的是全文最重要的一段：能力"排队出现"可能只是"GPT-4o 评委在模型输出跨过某个视觉阈值后突然愿意给 1 分而不是 0 分"。而 §7.1–7.3 那些用公开基准得到的结论（理解、GenEval、GEdit）不受影响，它们是本文最稳的部分。

§ 10 — 最小复现实验 ​

一周、不需要训模型，目标是给 IntelligentBench 这把尺子做校准——这是论文缺的那一步，也是判断全文核心 claim 的前提。

  • 数据：BAGEL 已开源代码与 checkpoint，IntelligentBench 的 350 题也随论文发布。取全部 350 题，用开源的 BAGEL 与 BAGEL-1.5B 各生成一次输出，再加两个平凡基线：(a) 直接把输入图原样输出；(b) 输入图 + 一个与指令无关的随机编辑。
  • 实现：不训练，只做评测。用论文附录 Tab. 14 的原始 prompt 调 GPT-4o 打分，同时招 3 名标注者按同一套标准（请求满足度 / 视觉一致性 / 知识创造性）独立打 0–2 分。
  • 测量：(1) 四个系统（BAGEL-7B、BAGEL-1.5B、复制输入、随机编辑）的 GPT-4o 分与人评分；(2) GPT-4o 与人评的 Spearman 相关；(3) 标注者之间的一致率（作为可达上限）；(4) 复制输入这一平凡基线的绝对分数。
  • 判据：若"复制输入"能拿到 20 分以上，那么 Step1X-Edit 的 14.9 就落在噪声区间内，Tab. 8 里"BAGEL 领先 Step1X-Edit 30 分"这句话的分母需要重算；若 GPT-4o 与人评的 Spearman 低于 0.5，或低于人类之间的一致率太多，则 3.61T 那条涌现曲线不能作为能力证据。反过来，如果平凡基线得分接近 0 且评委与人高度一致，本文最核心的结论就获得了它现在缺的那块独立支撑。

§ 11 — 最强反例设计 ​

攻击一：复制输入是一个未被测量的强基线。 论文自己两次描述了这个策略：3.5T token 之前 BAGEL "倾向于把输入图原样复制、只做极小改动，这是任务没被完全理解时的 fallback"；Step1X-Edit 在 IntelligentBench 上失败也被归因为"输出与输入图高度相似"。既然它是一个被反复观察到的实际行为，就必须报告它的分数。在 GEdit-Bench 上这一点尤其严重——G_PQ 衡量的是感知质量，一张原封不动的输入图应当拿到接近满分，而 BAGEL 的 G_PQ 只有 6.83。没有这个下界，6.83 是好是坏无从判断。这是最有力也最便宜的攻击：跑一遍复制基线，如果它的 G_PQ 超过 6.83，这一列的意义就被推翻了。

攻击二：架构结论建立在 1.5B 上，从未在 7B 复现。 MoT 优于 MoE 与 Dense 这个决定了整个模型形态的结论，只有 1.5B、gen:und = 4:1、以 loss 为判据的一组曲线。数据采样比与学习率的结论也是同样的规格。论文自己在这一段留了余地——"至少在这里考察的 1.5B 规模上"——这句话很诚实，但读者需要知道：7B 的 BAGEL 从未与一个同 FLOPs 的 7B Dense 或 MoE 版本比过任何下游指标。而 MoT 把总参数翻到 14B，显存与部署成本翻倍。最强反例是：训一个 7B Dense 版（同 FLOPs、同数据、同步数）跑完 PT 阶段，比 GenEval 与 GEdit。如果差距很小，那么本文的头条能力更可能来自 5.1T 交错数据而非 MoT。

攻击三：一个可预测的失败条件。 交错生成数据的构造方式限定了模型学到什么。视频侧的 caption 被截到 30 token 以抑制幻觉，网页侧只保留 3–8 张图的文档、图间超过 300 token 的文本被 LLM 摘要压缩。这三条一起意味着：训练分布里几乎不存在"图与图之间隔着长篇论证"的样本。因此可以预测——当编辑指令需要一段长推理才能落到视觉变化上时（例如"把这张图改成符合这段 300 词物理描述的样子"），模型会退化，而这恰好是 IntelligentBench 声称在测的能力。检验方式：把 IntelligentBench 的题目按指令长度分箱，看 BAGEL 与 Self-CoT 版的得分曲线。如果得分随指令长度单调下降、且在 300 词附近有明显折点，那么"长上下文推理能力涌现"这个说法就要被限定为"短指令下的推理能力"。

§ 12 — Follow-up Research Idea ​

驱动局限：本文最重要的发现——不同能力在不同 token 量上追上来（0.18T / 0.68T / 2.64T / 3.61T）——目前只是一个事后观察。它是在训练结束后回头评测历史 checkpoint 才看到的，而 loss 曲线全程没有任何提示。这意味着一个 5T token 规模的预训练跑完之前，没人知道自己想要的能力会不会出现、还差多少。对一个动辄百万卡时的训练，这是最昂贵的一种不确定性。

新 framing：不去问"能力什么时候涌现"，而去问"能不能在能力出现之前就从模型内部读出它正在形成"。核心猜想是：智能编辑需要的是"把语言里的推理结论绑定到视觉 token 上"这个能力，而这种绑定应当在注意力模式里留下痕迹——具体说，在生成图像的 VAE token 回看前文文本 token 时，注意力质量的分布应当从"均匀地看整段"逐渐变成"集中在推理轨迹的关键结论句上"。这个量可以在任意一个 checkpoint 上、用几百条样本、几分钟算完，不需要跑评测、不需要 GPT-4o。而本文的架构恰好让它可测——无瓶颈的共享自注意力意味着这种跨模态绑定是直接可观测的，如果用了 connector 方案它就被压没了。

可借鉴的相邻领域工具：LLM 可解释性里的 induction head 研究提供了完整的方法论范式——Olsson 等人正是通过追踪特定注意力头的形成，把 in-context learning 的"涌现"还原成一个可以提前几个数量级观察到的、连续的内部现象。这里要做的是同一件事，只是把 induction head 换成"跨模态绑定头"。

第一个实验：取 BAGEL 已发布的历史 checkpoint 序列，在每个点上算两件事：(a) 前述的跨模态注意力集中度（用 IntelligentBench 训练分布外的 200 条推理样本）；(b) IntelligentBench 分数。判据是——如果 (a) 在 (b) 起飞之前若干 T token 就开始单调上升，那就找到了一个能力涌现的前兆信号，"涌现是不连续的"这个说法也会被降级为"评测指标是不连续的"，正好回答 §9 里那个未解决的问题。更实际的价值在于：有了这个信号，就可以在 1T token 处判断一次配方值不值得继续训下去，而不必赌满 5T。
