Think Only When Needed: Prompt-Authority Control for Selective Slow-Path Intervention in Vision-Language-Action Manipulation ​

项内容
arXiv2608.23224
提交日期2026-08-24（v1）
作者Zhiruo Zhou, Zelin Li, Xiwen Chen, Jiazhuo Li, Chenwei Wang, Huiming Chen, Xiaojun Zhu
分类cs.RO, cs.AI, cs.CV
一句话发现「往冻结 VLA 的指令后面追加检索文本」会把成功率从 92.47% 打到 3.00%（与追加内容的语义无关），据此把候选生成与「修改策略输入的权限」拆开：一条固定的文本级兼容性规则要么授权一条规范化紧凑指令，要么逐字节恢复原始 prompt。

所属教程：视觉语言动作模型 VLA

§ 1 — 研究问题与重要性 ​

现在的做法是给冻结 VLA 外挂各种测试期脚手架：规划器、记忆、验证器、steering 模块。它们的输出最终都要变成文字进入被执行的 prompt。论文点破的事实是：一旦这段文字进入执行 prompt，它就不再是「建议」，而是一次控制干预。

而这次干预的代价被严重低估了。在保持策略、初始状态、执行协议完全固定的对照下，把检索到的原始文本直接追加到指令后面，平均成功率从 92.47% 掉到 3.00%。更关键的是配对对照：在同样的 500 个状态上，语义正确的追加和长度匹配的无意义追加都是 0/500。两者语义天差地别却失败得一模一样，说明起决定作用的不是内容质量，而是指令形式变了。作者把这个现象命名为 prompt-form collapse。

作者对机制的假设是：OFT 微调让策略暴露在一个稳定的指令模板下，从未见过追加的检索 token；追加改变了序列长度、token 位置和指令边界。

这个问题重要，因为它把整个「测试期增强冻结 VLA」的研究方向置于一个此前没人量化过的风险之下。如果任何往 prompt 里写东西的做法都可能触发这种崩塌，那么该领域需要的不是更好的检索器，而是一个明确的权限边界。

§ 2 — 前人工作与不足 ​

冻结策略与推理期接口：PaLM-E、RT-1、RT-2 建立了可扩展的语言条件控制，Open X-Embodiment、Octo、OpenVLA 把跨数据集适配做大，连续与潜动作模型拓展了双臂、空间与开放世界控制，SmolVLA 探索了可部署性。这些工作重新设计的是策略、数据或动作表示；本文反过来冻住生成器，只管制外部文本如何穿过它已经理解的那个接口。

外部推理与快慢系统：SayCan、VoxPoser 通过 affordance 与空间价值图接地语言；ECoT、InstructVLA、VLS 把推理往动作方向推；快慢系统把语义计算与反应式计算分离。作者的批评是：这些系统让「提案到动作」的接口变得关键，但通常不把候选质量与一个显式、可记录的授权决定分开。这个区分对应决策论里的 value-of-computation 与带拒绝选项的选择性预测——一条慢路径值得被查询，不等于它的输出值得被服从。

策略边界上的可检查记忆：MemoryVLA 系列整合感知与情节历史，WorldVLA、VLA-JEPA 等用预测的视觉或潜动力学。相对于潜记忆，外部 capsule 的优势是可以在越过策略边界之前被检查和哈希。

语言生成之外的 prompt 脆弱性：语言模型对 prompt 语义可能不敏感、却对格式或优化后缀高度敏感。这些研究关心的是开环生成的输出质量；在闭环 VLA 里，跑题的文本直接条件化动作，prompt 脆弱性就变成了控制失效。

§ 3 — 重建作者的思考路径 ​

已知：(a) 检索增强能不重训就改善冻结策略；(b) LLM 对 prompt 格式的敏感度可能超过对语义的敏感度；(c) 运行时保障领域早有 Simplex 架构与 action shielding，核心思想是「学习控制器 + 一个总能退回去的安全兜底」。

从 (a) 出发做实验，撞上了 92.47→3.00 这个数字。这个数字太大了，大到必须先解释而不是先优化。于是做配对因子实验：把 prompt 形式（canonical vs appended）与语义（correct / wrong-object / wrong-target / meaningless）交叉。结果是形式解释一切。

有了这个诊断，(c) 的思路就自然接上：既然「改形式」本身就是高风险动作，那么就该像运行时保障那样，把改 prompt 的权限和产生候选的能力分成两件事。区别在于，这里不需要切换控制器——兜底就是逐字节恢复原来的 prompt，代价为零，且可以用 hash 验证。

最后一步是把「授权」做成可审计的：固定权重、固定规则、预先冻结、每条路由记录候选 ID、冲突原因、路由状态与最终 prompt 的 hash。

§ 4 — 核心 Intuition ​

检索文本一旦进入被执行的指令，它就是控制输入而不是参考资料，而冻结 VLA 对指令形式的敏感度远高于对指令语义的敏感度。因此正确的接口不是「让检索更准」，而是把「生成候选」与「有权改动策略输入」拆成两个决定：只有通过一条固定文本规则的候选，才能被渲染成一条规范化的紧凑指令；否则接口逐字节退回原始 prompt。拒绝的代价因此严格为零，接受的形式因此始终在分布内。

§ 5 — 具体方法与完整 Pipeline ​

以 LIBERO 指令 Place the black bowl on the plate. 为例。

Base 通路：固定渲染器 P 把原指令变成 base prompt，atbase​=πθ​(ot​,pbase​)，θ 全程冻结。接口初始化 u⋆=ℓ。

Compatibility-Reranked Capsule：冻结记忆库只有 48 条，存的是演示轨迹、不含任何评测 rollout，且评测期只读。用 CLIP 文本特征做最近邻检索取 K=5 个候选。每条记忆存任务描述、结构化 context、原始 plan、紧凑 hint；检索索引描述，解析与渲染只消费 context，原始 plan 与 hint 永远只是溯源字段、绝不进入执行文本。

一个冻结的纯文本解析器（从不读图像、机器人状态、动作历史或 benchmark 标签）从任务与每条 context 里抽出 object–target 对，用 Jaccard 重叠算 mobj​,mtgt​,mctx​，再按固定系数打分排序。系数 (αclip​,αobj​,αtgt​,αctx​,λobj​,λtgt​,η)=(1,2,1.5,0.8,0.6,0.4,0.01) 在评测前固定，不按结果拟合。

Top-2 Fail-Closed Cascade：硬检查器给出确定性的冲突原因集合，只有原因集合为空才算合格。先看 rank 1，被拒才看 rank 2，两个都不过就退回 Base。context 只影响软排序，不影响这条硬规则。

渲染：授权后用固定模板 put <object> <relation> <target> 渲染，上例解析为 put the black bowl on the plate；被拒则返回逐字节相同的原字符串，且不追加任何检索文本或拒绝提示。一次 rollout 只解析一次 prompt，之后不再查询慢路径。

三个可审计运行态：bypass（不检索直接执行 Base）、inspected-but-unauthorized（检查后仍执行 Base）、authorized（执行 capsule）。三个不变量：(I1) 拒绝时 prompt 边界零干扰；(I2) πθ​ 是唯一动作生成器；(I3) 检索后的检查预算与记忆规模无关（每 episode 最多 1 次检索、5 次打分、2 次检查、1 次渲染）。

§ 6 — 核心数学推导 ​

整套方法的数学就是一条授权规则，但它的每一项都对应一个可验证的性质。

兼容性打分（决定检查顺序，不决定授权）：

s(h,xℓ​)=αclip​sclip​+αobj​mobj​+αtgt​mtgt​+αctx​mctx​−λobj​robj​−λtgt​rtgt​−ηrankclip​(h)

其中 robj​=1[yobj​=∅∧mobj​=0] 是失配惩罚——候选提到了某个物体但与任务零重叠。最后一项 −ηrankclip​ 是确定性的平局裁决，保证排序可复现。

级联授权：

j⋆=min{j∈{1,2}:Gcomp​(h(j)​,ℓ)=1},u⋆={ucap​,ℓ,​g=1∧j⋆=∅,otherwise,​

g∈{0,1} 是慢路径调用位，always-on 评测下恒为 1。这个 { 是全文的核心：默认分支是原样返回 ℓ，也就是 fail-closed。任何检索、打分、检查环节出问题，系统退化成 Base 而不是退化成乱码。

任务签名：sig(u)=(cobj​(u),crel​(u),ctgt​(u))，逐分量比较（经确定性文本归一化与固定关系别名映射之后）。SigEq=1 是「授权后的指令没有改变任务」的可验证读数。

oracle 侧路由（只作为上界控制，不用于主结果）：gprior(m)​(z)=1[z∈Zallow(m)​]，慢路径覆盖率 ρslow​=N1​∑i​gi​，节省 Scall​=1−ρslow​。作者明确说明两个 manifest（five-suite 的 3/5 允许 → 省 40%，paired-3000 的 1500/1500 → 省 50%）分母不同、从不合并。

§ 7 — 实验设计与结论 ​

Q2（先看这个，它是全文的地基）：崩塌是形式问题还是语义问题？ 设计：500 个配对状态上的 2× 语义因子实验。答案（Table 3）：Base 499/500，逐字节恢复 499/500，正确的 canonical 指令 497/500，错物体的 canonical 497/500，错目标的 canonical 496/500；而正确的追加 0/500，无意义的追加也 0/500。三次固定调度重跑（每次 1,200 episode）给出 92.47% → 3.00%，重排序与 Top-2 fail-closed 都恢复到 91.08%。增大 K 既不加重也不缓解崩塌，说明检索深度不是操作变量。

Q1：在扰动 benchmark 上有多少净增益？ 设计：LIBERO-Plus 4×7（4 套件 × 7 扰动轴，28 格），每方法 10,030 个 episode，与同一冻结 OpenVLA-OFT 骨干配对。答案：69.46% → 73.07%（+3.61 点，+362 次成功，配对格 bootstrap 95% CI 1.89–5.45）。七轴里六轴改善，领先的是 Language +6.5 与 Robot +6.0，唯一下降的是纯图像的 Noise 轴；四个套件全部为正（Spatial 84.0→86.3、Object 65.8→69.5、Goal 62.9→68.1、Long 65.9→69.1）。

Q3：授权契约真的被遵守了吗？ 设计：两次审计。答案：1,200 状态审计中，重排序全部准入、1,100/1,200 保住任务签名；级联准入 1,000 个、其中 940 保住签名、其余 200 恢复 Base。900 路由审计中慢路径跑了 450 条（375 授权且 SigEq=1，75 检查后被拒），另 450 条 bypass，因此 525 条恢复出 hash 相同的 Base。作者明确解释了两次审计分母不同的原因。

Q4：能不能只在需要时思考？ 设计：oracle 路由与 oracle-free gate 对照。答案：3,000 配对状态上，benchmark 侧路由在保住完全相同的 2,826 次成功的同时把慢路径调用砍半，决策延迟 212.50 → 190.75 ms（−10.24%）。但在预注册的 24 开发 / 36 held-out 格划分上，学到的 gate 只授权 2/36 格、成绩等于 91.81% 的 Base；CLIP gate 授权 0/36；固定/随机等预算 gate 授权 32/36 却只有 90.14–90.97；form-aware 也只有 90.28。结论作者写得很直白：oracle 分析量化了可省的计算，但现有 gate 还不能识别该省哪些。

Q5：换骨干换实体还成立吗？ 设计：PiPER 机械臂 + 冻结 π0.5​，指令固定为 "Grasp the white object and place it upright in the green tray."，三种场景（无干扰、黄杯、红圆柱），每格 50 次、Base 与 TOWN-VLA 随机交错、人工判定直立保持两秒为成功。答案：79/150（52.7%）→ 118/150（78.7%），p=3.16×10−6（Fisher 精确检验），三个场景各 +22 至 +32。

另有一个限界实验值得单列：组合式语言探针里，Base 拿到 20/30，而去掉 drawer / cabinet / 相对位置从句的 canonical prompt 拿到 0/30。这直接量化了当前渲染器的适用边界。

§ 8 — Take-aways ​

5 句话版：往冻结 VLA 的执行指令后面追加检索文本会造成灾难性失败（92.47%→3.00%），且语义正确与长度匹配的无意义追加同为 0/500，说明起作用的是 prompt 形式而非内容；TOWN-VLA 把「产生候选」与「有权改 prompt」拆开，一条冻结的纯文本兼容规则要么授权一条 put <object> <relation> <target> 模板渲染的紧凑指令、要么逐字节恢复 Base；900 条路由审计里 525 条恢复出 hash 一致的 Base、375 条授权全部保住任务签名；LIBERO-Plus 匹配评测（每方法 10,030 episode）69.5%→73.1%，增益集中在 Language 与 Robot 轴，真机 PiPER 上 52.7%→78.7%；oracle 路由能在不掉成功率的前提下省一半慢路径调用，但所有 oracle-free gate 都还打不过「什么都不做」。

3 句话版：检索文本进入执行 prompt 的那一刻就成了控制干预，而冻结策略对指令形式比对指令语义敏感得多。把授权做成一条可哈希、可审计、失败即退回原 prompt 的固定规则，就能在零重训的前提下拿到稳定的正收益。什么时候该调用慢路径，仍然是未解决的标定问题。

1 句话版：提案不等于权限——冻结 VLA 的 prompt 边界应当像安全接口一样被显式管制。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：任务签名相等（SigEq=1）是一个足够的安全检查。整套授权契约的安全论证都建立在它上面，而它是一个纯文本判据——解析器从不读图像、机器人状态或动作历史。

论文自己的数据就在削弱它。Table 3 里，语义错误的 canonical prompt（错物体 497/500、错目标 496/500）与正确的 canonical prompt（497/500）表现完全一致。也就是说，在那个 500 状态 manifest 上，指令的语义内容对执行结果毫无影响——策略靠视觉就把任务做完了。这正是 InstructMove 所批评的那种「语言可有可无」的评测场景。

这带来两个后果。第一，签名检查在那批数据上没有任何可观测的保护作用：它保护的东西（任务语义不被改动）在那里根本不影响结果。第二，也是更严重的一条——如果在一个语言真正起作用的场景里，检索到的 context 恰好文本兼容（物体名与目标名都对得上）但指向场景中错误的实例（两个黑碗），SigEq 会照样给出 1 并授权。文本解析器原理上看不见实例歧义。

论文其实提供了这条边界的直接证据：组合式语言探针里 Base 20/30、去掉 drawer/cabinet/相对位置从句的 canonical prompt 0/30。渲染模板 put <object> <relation> <target> 只能表达单物体单目标的关系，一旦指令需要更丰富的关系结构，规范化本身就是有损的，而签名检查不会报警。作者把这一点写进了正文并明确说它「界定了当前渲染器的能力」，态度是诚实的，但这确实意味着授权契约的安全性只在 LIBERO 那种单物体单目标指令的窄区间内被验证过。

§ 10 — 最小复现实验 ​

一周，只需要一张卡和 LIBERO-Plus，不做真机。

论文最缺的对照组恰好也是最便宜的：canonicalize-only，零检索。

  1. 拿 OpenVLA-OFT 官方 checkpoint 与 LIBERO-Plus，先复现 Base（论文报 69.46%）。
  2. 实现一个只有 20 行的 arm：直接用冻结解析器把原指令 ℓ 抽成 (object, relation, target)，再用同一个模板 put <object> <relation> <target> 渲染。不检索、不打分、不检查、不用那 48 条记忆。
  3. 在完全相同的 28 格、相同的 episode 上跑这个 arm，与 Base 和完整 TOWN-VLA 三方比较，尤其看 Language 轴。
  4. 顺手记录三方的 prompt hash 分布，确认 canonicalize-only 与 TOWN-VLA 的 authorized 路由在多大比例上产生完全相同的字符串。

判据：若 canonicalize-only 拿到接近 73.07% 的成绩，那么 +3.61 点的增益应当归因于指令规范化这一件事，48 条记忆、CLIP 检索、七系数打分与 Top-2 级联在 LIBERO-Plus 上就都是可以删掉的部件，论文的标题应改为「规范化即防御」。论文在 Q3 里其实已经报过一个相近的观察——「task-only 与 retrieved canonical 两个 arm 共享全部 prompt hash 与结果」——但那只在 500 状态审计里做过，没有被带到 10,030 episode 的头条实验上。这一步就是把那个观察升级成结论。

§ 11 — 最强反例设计 ​

替代解释：TOWN-VLA 是一个 prompt 归一化器，检索管线是装饰。

除了 §10 的对照组，还有三条彼此独立的证据线指向这个解释，值得一并检验。

其一是增益的分布形状。七轴里最大的两项是 Language +6.5 与 Robot +6.0，而 Language 轴恰恰是把指令改写成同义变体的扰动轴。一个把任意措辞压回固定模板的归一化器，正好应该在这条轴上吃到最大收益。设计：把 +362 次新增成功按扰动轴归因，看是否 Language 轴独占大头；作者自己也把「路由级归因」列为重要的下一步。

其二是记忆规模。48 条记忆、CLIP top-5、七个手工系数，这套管线的信息量上限极低。设计：把记忆库随机砍到 12 条、6 条、1 条，看 LIBERO-Plus 成绩曲线。若 1 条记忆仍能拿到 73%，检索这一环就被证伪了。

其三是 Table 4(a) 自己的数字：Base 89.48、Strategy Capsule (Top-1) 90.64、+重排序 91.60、+fail-closed 91.32。加了 fail-closed 反而掉 0.28 点，作者诚实地把它折算成 2,500 个 episode 里的 7 次结果，并说明保留级联是为了「精确恢复」这个性质而非增量成绩。这等于承认整条管线里真正贡献分数的只有前两级，而前两级做的事本质上就是「换一个更规范的说法」。

第二个攻击点：真机实验是单任务、单操作者、人工判分。 150 次试验只有一条指令、一个物体、一个托盘，作者在 discussion 里明确把「受控的单任务、单操作者、人工评分」列为局限，并把更广泛的盲测列为自然延伸。这里可以补一个便宜且强力的对照：既然 §7 显示错物体的 canonical prompt 也能拿 497/500，那就在真机上加一组语义故意写错但形式规范的 prompt（如把 white 换成 blue）。若成功率仍在 78% 附近，就直接证明这个真机任务同样是「语言可有可无」的，+26.0 点应全部记在形式规范化名下。

第三点：与同组另一篇的基线重合。 同一批作者的 Pointing-VLA 用同样的 PiPER、同样冻结的 π0.5​、同样「抓白色物体直立放进绿托盘」的指令、同样三种干扰场景、同样每格 50 次，报出的 π0.5​ 基线也是 79/150 = 52.7%，但分场景是 20/26/33 而本文是 21/27/31。两个完全正交的干预分别报 +28.0 与 +26.0，读者不应把它们相加。做一次两干预同时开启的联合实验，是判断这个 52.7% 基线里有多少是共同的、任何合理干预都能吃到的余量的最直接办法。

§ 12 — Follow-up Research Idea ​

驱动局限：Q4 的结论是一个干净的阴性结果——oracle 路由证明有 50% 的慢路径调用可以省掉且不掉一分，但所有 oracle-free gate 都打不过「什么都不做」（学到的 gate 授权 2/36 格、成绩等于 Base；等预算 gate 反而掉 0.8–1.7 点）。作者把 admission 标定点名为下一个前沿。问题在于，现有 gate 全部是文本侧的：它们看不见机器人正在经历什么。而慢路径值不值得调用，本质上取决于当前 rollout 是否正在偏离——这是一个视觉与本体感觉的问题，不是文本相似度的问题。

新 framing：不要问「这条指令该不该被增强」，而问「这次 rollout 现在有多可能失败」，并把授权决定绑到这个失败概率上。这把 admission 从一个静态的文本分类问题，变成一个在线的、带校准要求的失败预测问题。可借鉴的相邻工具是共形预测（conformal prediction）——它能在有限样本下给出带覆盖率保证的拒绝集，正好匹配论文对「可审计、可预注册」的偏好；以及运行时保障里的可达性监控。

关键的方法论要求：这个失败预测器在被用来做授权决定之前，必须先被标定并把校准曲线写进论文。这恰好是论文里其余部分做得很好、而 gate 这一节缺失的一环——现有 gate 只报了它们的最终 SR，没有报它们的预测质量，因此无法判断失败是来自「预测不准」还是「预测准但阈值错」。

第一个实验：在 LIBERO-Plus 的 24 开发格上，用 rollout 前 k 步的策略内部量（动作 chunk 的方差、连续 chunk 之间的不一致度、视觉 token 的注意力熵）训练一个二分类器预测该 episode 是否失败，然后在 36 个 held-out 格上先画 reliability diagram。第一判据是校准本身：若预测器在 held-out 上不校准，就说明这条路也走不通，而这个阴性结果本身就有价值（它会告诉领域：冻结 VLA 的内部信号不足以自我诊断）。若校准良好，第二步才是把共形阈值接进 g，判据是能否在保住 91.81% Base 水平的同时把慢路径调用降到 60% 以下——那正好是 oracle 上界（50%）与当前最好 gate（100%）之间的中点。
