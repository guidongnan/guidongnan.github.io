M4World: A Multi-view Multimodal Driving World Model for Interactive Object Manipulation and Minute-long Streaming ​

项内容
arXiv2607.14005
提交日期2026-07-15
作者Ke Cheng, Hanqiao Ye, Lei Shi, Yahui Liu, Yunhan Shen, Jingtao Dong, Zhenke Wang, Wenxuan Ao, Weixiang Xu, Kaining Huang, Shuhan Shen（美团 / 中科院自动化所 / 北理工）
分类cs.CV, cs.RO
一句话把驾驶世界模型的物体条件从纯几何 3D 框扩成融合几何、类别、外观图像特征与文本属性的 object token，再用五阶段训练把双向视频先验蒸成 4 步因果学生，实现多相机加 LiDAR 的分钟级流式 rollout 中的物体级外观可控，并拿它给长尾感知造数据。

所属教程：世界模型

§ 1 — 研究问题与重要性 ​

自动驾驶的测试与数据扩充需要可控仿真来突破真实采集的成本与稀疏性限制。重建式仿真器（NeRF、3DGS 系）在观测覆盖的区域几何保真度很强，但它继承的是日志轨迹的支撑集，外推到未见视角、新遮挡或罕见场景组合时就退化。生成式世界模型放松了这个瓶颈，但作者指出仍有一道可控性缺口。

缺口具体在哪。当前实践里的物体条件基本是纯几何的——3D 包围框或占据栅格，用来指导场景构图与物体摆放，对单个物体的视觉属性几乎没有显式控制。这个能力对闭环仿真特别关键：构造一个有针对性的安全关键场景，不仅要把物体放在指定位姿，还要指定它长什么样。同时，现有长尾仿真流程往往只在合成的首帧里指定罕见 agent，之后交给 image-to-video 模型演化，于是 rollout 过程中对位姿、朝向与多智能体交互的显式控制就丢了。

除可控性外，闭环仿真还要求低延迟的长时稳定流式生成，而多数因果适配流程要么受 train-test exposure bias 困扰、要么推理延迟太高。

§ 2 — 前人工作与不足 ​

重建式世界模型沿两条表示（NeRF 与 3DGS）发展出动态 4D 建模的多种路线：用形变网络把时变观测映到标准空间、把时间戳作为额外输入、把场景分解成静态背景加独立运动物体模型以支持逐 agent 控制，以及用前馈框架跨场景学可泛化先验来避开逐场景优化。共同的天花板是传感器覆盖：未观测区域渲不出来，罕见场景条件泛化不了。

驾驶视频生成沿三个方向演进：一是在场景布局、天气、agent、ego 轨迹上引入结构化条件（DriveDreamer、GenAD、MagicDrive 一系）；二是通过显式 3D 几何、BEV 式控制或全景生成追求空间可控性与多视角一致（MagicDriveV2、Panacea、GAIA-2）；三是向大规模通用预测器与基础世界模型扩展（Cosmos、Vista）。近期系统已在把重建与生成融合（小米 EV 世界模型）、扩展实时闭环生成仿真（NVIDIA OmniDreams）、用自纠正蒸馏提升长时自回归稳定性（HorizonDrive）、以及做可控 ego-centric 多相机 rollout（X-World）。

实时交互视频世界模型这条线的工具是现成的：MAGI-1 做 chunk-wise 自回归渐进去噪；CausVid 用非对称蒸馏加 ODE 初始化把双向 DiT 转成少步因果生成器；Self-Forcing 让模型在训练时就吃自己的历史；Rolling Forcing 扩大扩散窗口；LongLive 刷新 KV cache 来在场景切换时保住视觉连续与 prompt 遵循。

本文的定位很清楚：这些工作各自解决了一半。可控性一侧停在几何层，流式一侧不带驾驶特有的多传感器与细粒度条件。M⁴World 要把两半合起来。

§ 3 — 重建作者的思考路径 ​

不用本文结论作前提，路径是这样的。

起点是一个产品侧的观察：长尾仿真在实际工作流里是逐个 case 定义的。工程师说的不是"给我更多罕见样本"，而是"给我一辆被树枝几乎完全遮住车身的运树卡车，从后视角看"。3D 框根本表达不了这个需求——框只说了那里有一辆卡车，说不了它长什么样。所以条件接口必须往上抬一层，抬到外观。

第二步是问怎么抬。既然骨干已经是 DiT 且用 cross-attention 注入异构条件，那么"再加一种条件"在架构上几乎是免费的：只要能把外观编码成 token。图像侧用 SigLIP-V2 抽外观特征，文本侧用 umT5 编码描述，与 3D 框的 Fourier 编码和类别 embedding 拼起来过一个 MLP，就得到一个既含几何布局又含细粒度外观语义的 object token。这一步的关键不是模型设计，而是意识到条件接口本身是可以被重新定义的。

第三步是数据。这类细粒度标注不可能人工标，但可以自动生成——用 3D 框把物体从视频里裁出来当作图像描述，再让 VLM 给每个裁片写一段关于外观、尺寸、状态的自然语言。标注管线的存在性决定了这个 idea 能不能规模化。

第四步是评测。FID/FVD 测的是分布真实性，测不了条件遵循。既然条件本身就是"图像 + 文本"，那评测就可以对称地用 VLM 来做：把生成结果按 3D 框投影裁片，问 VLM"这和参考图是同一个物体吗""这符合这段描述吗"。

第五步是长尾适配。基础模型在通用驾驶数据上训，罕见物体在数据里可能只有不到五个 clip，指望通用训练学会绑定是不现实的。逐 case 的 LoRA 微调 + 罕见/常见 50:50 平衡采样是自然的解法：上采样提供直接学习信号，混入常见数据防止漂离通用分布，LoRA 防止全参微调把多样性和通用可控性搞坏。

§ 4 — 核心 Intuition ​

驾驶仿真里真正稀缺的不是"多一些场景"，而是"这一个特定的、说得出长什么样的罕见场景"。把物体条件从 3D 框扩展成一个同时携带几何、类别、外观图像特征与文本属性的 token，条件接口就从"在哪"升级到"在哪 + 长什么样"，罕见 case 因此可以被逐个指定而不是等着被采到。而因为这个接口是 token 化的、走 cross-attention 的，它与"把双向视频先验蒸成 4 步因果学生"这条流式路线正交，可以在分钟级 rollout 中一直生效。

§ 5 — 具体方法与完整 Pipeline ​

以"造一批被树枝遮住车身的运树卡车数据"为例走完整链路：

条件与架构。 每帧条件集 Ct​={L,S,Pt​,Mt​,Ot​}，分全局（场景文本 prompt、传感器参数）与时变（ego 位姿、BEV 地图、物体属性）两类。编码方式各有讲究：场景文本走 umT5；相机内外参与 ego 位姿都表示成 3D 向量序列再做 Fourier embedding 加各自的 MLP；LiDAR 作为参考坐标系不需要几何参数化，用一个随机初始化的可学 token 代替；BEV 地图不走 ControlNet 式辅助分支（参数与计算开销大），而是用轻量 tokenizer 直接 patchify 展平。物体 token 融合四路信息——8 个角点的 Fourier 编码过 MLP、类别名的 pooled embedding、SigLIP-V2 抽的外观特征、umT5 编的文本描述——拼接后压成一个 token。

骨干是 DiT，每个 block 里 self-attention 管长程时空依赖，一路 cross-attention 注入控制 token，另一路 cross-attention 做跨视角聚合（沿用 MagicDriveV2）：某个目标视角的 latent token 会去 attend 所有视场重叠的视角，每 5 层插一次以平衡效果与效率。

LiDAR 的接法很省。 把每帧扫描投成 range map（128×1300，纵向 128 束、横向方位角采样），距离在 [0,100] 米内归一到 [−1,1]，resize 到与图像相同的空间分辨率，然后复用同一个 video VAE 编码——LiDAR 与视频被对齐进同一个 latent 空间，DiT 骨干可以直接并行生成两种模态。采样时对 LiDAR 用 APG 而非标准 CFG，因为 CFG 的过饱和在 range map 上会翻译成系统性的深度偏移，这对驾驶仿真不可接受。

五阶段训练： ① 双向 mid-training，用 rectified flow 目标做域迁移并扩展输入输出接口，混合 224×400／424×800／576×1024 三种分辨率、13 到 93 帧、最多 10 个视角，视觉先验稳定后再打开 LiDAR。② Teacher Forcing causal adaptation，给时间 attention 加因果 mask。③ Causal ODE 初始化出一个 4 步学生。④ Self-Forcing + 非对称 DMD，critic 每更新 5 次学生才更新 1 次（沿用 DMD2），并以 10% 概率混入真值 latent 上的监督去噪损失以稳训练、防模式坍缩。⑤ 迭代长视频微调：学生做 600 帧自 rollout，边生成边在每个新片段上微调、把已生成帧当因果上下文。因为控制信号本身就是时变的，每个 rollout step 都被训练成接收当前时间戳的控制 token，新注入的控制能自然生效，不需要 LongLive 那样的显式 KV-recache。

latent context refresh（推理时、免训练）：每块去噪完成后，把它最后一帧的 latent 送回网络作为下一块的额外上下文输入。这与纯 KV 缓存不同——缓存的 K/V 只由历史 token 算出并原样复用，而这个刷新上下文要与下一块的噪声 latent 一起参与 attention，K/V 必须重算。作用是缓解 chunk 边界的闪烁。

长尾适配： 对运树卡车这个 case，构造 50% 目标罕见 clip + 50% 普通 clip 的微调集，用 LoRA 训几百个 iteration，把罕见物体的视觉与文本 prompt 绑定到 object token 上，同时保住基础模型对位置、天气、光照的原有控制。

视觉参考条件变体： 三种——全视角首帧条件、单视角首帧条件、物体补全（给一段挖掉某物体的视频，按控制信号补回来）。实现统一：video VAE 把参考视觉信息编成 reference latent，空间与时间上扩展到与初始噪声 latent 同形，沿通道维拼接送进 DiT，再用任务专用的二值 mask 走同样的通道拼接。原有 control-token 通路完全不变。

§ 6 — 核心数学推导 ​

自回归形式化。 设 z1:T​ 为 latent 上下文，CT+1:T+W​ 为待生成 W 帧的控制信号，每个自回归步采样

z^T+1:T+W​∼pθ​(zT+1:T+W​∣z1:T​,CT+1:T+W​)

再把结果追加进上下文。得到的 latent chunk 解码成时间对齐的环视视频与同步的 LiDAR range map。

Rectified flow 目标。 干净 latent x0​ 与噪声 ϵ∼N(0,I) 之间线性插值 xt​=(1−t)ϵ+tx0​，t∼U(0,1)。这条直线传输路径上目标速度是常数且从噪声指向数据：v∗=x0​−ϵ。于是

Lrf​(θ)=Ex0​,ϵ,t​[∥vθ​(xt​,t;C)−(x0​−ϵ)∥22​]

直觉上，rectified flow 相比常规扩散的好处是速度场沿轨迹恒定，路径是直的，这让后续少步蒸馏更容易——4 步能走完的前提是路径本身不太弯。

Teacher Forcing 阶段换成因果 mask，把 xt​=(1−t)ϵ+tzT+1:T+W​ 的速度预测同时条件在控制信号与真值历史上：

Ltf​(θ)=E[∥vθ​(xt​,t;CT+1:T+W​,z1:T​)−(zT+1:T+W​−ϵ)∥22​]

Causal ODE 初始化。 教师在真值历史与未来控制下产出离线 ODE 轨迹，沿轨迹采若干中间噪声 latent，训学生 Gθ​ 一步映回干净目标：

Lode​(θ)=E[∥Gθ​(xt​,t;CT+1:T+W​,z1:T​)−zT+1:T+W​∥22​]

非对称 DMD。 目标写成反向 KL，其梯度用教师与学生 score 之差近似：

Ldmd​(θ)=Ez^,t,z^t​​[21​​z^−sg[z^−(sfake​(z^t​,t)−sreal​(z^t​,t))]​22​]

sg[⋅] 是停梯度。z^ 由学生自 rollout 生成再前向加噪成 z^t​；sreal​ 由冻结教师估计，sfake​ 由在线训练的 critic 估计。这里的工程要点值得记：因为 sfake​ 直接决定梯度方向，critic 估计不准会立刻产出不稳定或有偏的 DMD 梯度，所以 critic 要跟紧不断变化的学生分布——每次学生更新前 critic 更新 5 次。

§ 7 — 实验设计与结论 ​

问题一：加了细粒度物体条件会不会伤画质？ 与 MagicDriveV2 在同一数据集上训练后比 10 秒视频的 FID/FVD：41.7/346.1 → 34.8/288.7。作者的解读是细粒度物体条件反而提升了视觉质量。这个方向合理但只有一组对比，无法排除是骨干（Wan2.1）或训练配方差异带来的。

问题二：条件到底被遵循了多少？ 这是本文最有信息量的一张表，因为它同时给了 Oracle（直接评测真值测试视频，作为指标的经验上界）：

指标OracleMagicDriveV2M⁴World
天气76.775.476.6
时段83.079.180.9
物体存在性95.482.690.6
清晰度74.659.167.2
视觉保真87.013.462.7
文本保真75.411.659.1
跨视角一致93.378.984.5

视觉与文本保真的跃升（13.4 → 62.7、11.6 → 59.1）是预期内的——基线根本没有这两路条件，这更像是"有 vs 没有"而非"好 vs 更好"。真正有意思的是另外两点：一是天气控制已经贴到 Oracle（76.6 对 76.7），说明这一维基本饱和；二是Oracle 自身的分数并不高（文本保真只有 75.4，清晰度只有 74.6），说明这套 VLM judge 本身噪声不小，读表时要按相对值而非绝对值理解。跨视角一致从 78.9 提到 84.5，作者归因于细粒度条件的副作用——同一个 object token 被所有视角共享，等于给跨视角对齐加了一个语义锚。

问题三：4 步因果学生能撑多久、跑多快？ 60 秒、1024×567、10 FPS 的六视角 rollout 不出现灾难性漂移。吞吐上，六相机加一路同步 LiDAR、8 张 A100，1024×567 下 0.7 FPS，424×800 下 2.3 FPS，224×400 下 7 FPS。作者对训练配方做了定性消融：补充 Ldenoise​ 缓解背景退化，latent context refresh 减少 chunk 间闪烁。这部分没有量化表格。

问题四：造出来的数据对下游感知有用吗？ 选运树卡车这个 case——从后视角车身几乎被树枝完全遮住，外观与普通车辆差别极大，而在数十万小时日志里不到五个 clip。用少 clip 适配后的仿真器合成 500 段 10 秒 clip，混入 5 万段真实 clip 训 BEV 检测器，在含 99 个运树卡车标注框的测试集上评测：目标召回 1.0% → 69.7%，常规集 mAP 66.7% → 66.8%。常规集不掉这一点与增强的设计意图一致（混了 50% 普通数据、用 LoRA）。

问题五：不做微调能不能零样本造长尾？ 用视觉参考条件模型：拿图像编辑工具把首帧前视里的公交车换成水泥搅拌车或运树卡车，模型据此补全其余视角并按后续时变控制预测未来帧。这是定性展示。

§ 8 — Take-aways ​

5 句话版：驾驶仿真的长尾需求在实际工作流里是逐 case、按外观描述提出的，而现有世界模型的物体条件停在 3D 框这一几何层，表达不了"长什么样"。M⁴World 把 object token 扩成几何加类别加 SigLIP 外观特征加 umT5 文本描述的融合体，走 cross-attention 注入共享 DiT 骨干，同时用第二路 cross-attention 每 5 层做一次跨视角聚合。LiDAR 被投成 range map 并复用同一个 video VAE，从而与视频对齐进同一 latent 空间并行生成；采样时用 APG 替代 CFG，因为 CFG 的过饱和会在 range map 上变成系统性深度偏移。五阶段配方（双向 mid-training → teacher forcing → ODE 初始化 → Self-Forcing + 非对称 DMD → 长视频迭代微调）把双向先验蒸成 4 步因果学生，配 latent context refresh 撑起 60 秒六视角 rollout，8 卡 A100 上 424×800 达 2.3 FPS。逐 case 的 LoRA 少 clip 适配把这套接口变成可用的长尾数据引擎：500 段合成 clip 让运树卡车的检测召回从 1.0% 提到 69.7%，常规集 mAP 基本不动。

3 句话版：把"物体条件"从几何升级到几何加外观，罕见 case 就能被逐个指定而不是等着被采到。这个 token 化接口与少步因果蒸馏正交，因此细粒度控制能在分钟级 rollout 里一直有效。评测也对称地用 VLM 做，并且诚实地给出了 Oracle 上界。

1 句话版：仿真的长尾问题不缺"更多"，缺的是"指定得出来"。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：用少数几个真实 clip 微调出来的仿真器所合成的数据，对下游感知的增益能泛化到那些 clip 之外的同类实例。整篇文章最有分量的数字（召回 1.0% → 69.7%）完全押在这上面。

它可能不成立的理由很具体。作者自陈这个 case 在数十万小时数据里不到五个 clip，而 LoRA 微调集的 50% 就是从这些 clip 来的。测试集只有 99 个标注框——按驾驶数据的组织方式，99 个框极可能来自很少几个序列，而这些序列与微调用的那不到五个 clip 是否来自同一批日志、同一辆车、同一段路，论文没有说明。如果有重叠或高度相似，那么"仿真器学会了这个物体的外观 → 合成数据 → 检测器学会了这个外观 → 在同一外观上召回大涨"就构成了一条间接的信息泄漏路径：增益反映的是对特定实例的记忆，而非对"被树枝遮挡的卡车"这一类的泛化。真实部署中遇到的是另一辆卡车、另一种树、另一个角度，收益可能大幅缩水。

论文提供的证据是终点证据（召回涨了、常规 mAP 没掉）。缺的证据很明确：一个留出实例的划分——用一部分运树卡车 clip 做微调、另一部分完全不同来源的做测试；或者报告测试集的序列数与来源，说明它与微调集的关系。另外，69.7% 的召回是在多低的精度下取得的也没说，只报了 recall 而没报该类的 precision 或 AP，无法排除检测器学会了"看到树就报卡车"这种退化策略——常规集 mAP 不掉并不能排除它，因为常规集里未必有大量树木遮挡的负样本。

§ 10 — 最小复现实验 ​

不需要复现整套 5 阶段训练、聚焦检验 §9 的方案：

  • 数据：用公开数据集构造一个人造长尾类别。例如在 nuScenes 上把"施工车辆"（construction_vehicle，本身就是稀有类）当作目标，人为把训练集里该类的序列削到 3–5 条，模拟"长尾"。
  • 实现：不训世界模型。用任一现成的可控驾驶视频生成器（MagicDriveV2 开源版）或更简单的合成方式——把目标物体从那 3–5 条序列里按 3D 框裁出，粘贴到其他序列的对应几何位置并做光照协调——生成 500 段增强 clip。这一步的目的是复制"从极少真实实例出发扩增"的核心机制，而不是复制模型。
  • 划分：关键在这里。做两套测试集——(a) 与微调实例同源（来自同一批序列的其他帧），(b) 异源（来自完全不同的场景与实例，可以从 Waymo 或 Argoverse 里挑同类）。
  • 测量：在两套测试集上分别报该类的 recall 与 AP，以及常规集 mAP。
  • 判据：如果同源提升巨大而异源提升微弱，说明增益主要来自实例记忆，长尾数据引擎的价值需要重新评估；如果异源也有可观提升，则支持论文的主张。

这个实验单卡可完成，且给出的是论文最需要而恰好没给的那条证据。

§ 11 — 最强反例设计 ​

站在反对者立场，最有力的攻击针对评测的循环性。

论据链条：物体的文本描述是由 Qwen3-VL 在裁片上自动生成的；模型被训练成从这些描述生成对应外观；然后评测又用一个 VLM 去判断"生成的裁片是否匹配这段描述"。如果 judge 与 annotator 同源（论文明确说标注用 Qwen3-VL，评测只写"VLM judge"而未指明是否为不同模型），那么高分可以由一个平凡的机制解释——模型学会了复现该 VLM 的描述偏好，而不是学会了生成描述所指的视觉内容。VLM 的图像描述有强烈的模式化倾向（同类物体的描述高度模板化），一个只学会"看到 truck 类别就渲染成 VLM 典型描述的样子"的模型，在这套评测下会拿高分而在人眼看来毫无细粒度控制。

支持这个怀疑的间接证据就在表里：Oracle 的文本保真只有 75.4%——真实视频里真实物体与其自身的自动描述只有四分之三的时候被判为匹配。这说明 judge 与标注之间本来就有约 25% 的不一致率，指标的信噪比不高。

具体的反例实验有两个层次。第一层：换一个完全不同家族的 judge（比如 InternVL 或 GPT 系）重跑同一批生成结果，看 M⁴World 与基线的相对差距是否保持。如果差距明显收窄，评测的循环性成立。第二层，更强：做一个交叉条件测试——把物体 A 的文本描述配上物体 B 的 3D 框去生成，然后用人工评测（而非 VLM）判断生成的物体是否真的具有 A 描述的特征。这个设定破坏了"类别—描述"的统计关联，一个只学会类别到模板外观映射的模型会在这里失败，而真正做到了细粒度控制的模型不会。论文的全部控制性评测都在同分布条件下做，从未做过条件的交叉或反事实组合。

另一类可预测失败针对 LiDAR 分支。把 range map 当图像、复用为 RGB 设计的 video VAE，是一个有代价的近似：VAE 的感知损失与先验都是为自然图像的空间统计设计的，而 range map 的统计完全不同（阶跃边界、无纹理、深度不连续处的信息最关键）。可预测的失败是深度不连续处被平滑，即物体轮廓在 range map 上被抹圆。论文只报了 APG 解决了全局深度偏移，没有报任何 LiDAR 的定量指标（Chamfer 距离、深度误差、下游 LiDAR 检测性能）。攻击方式就是直接测：生成的 range map 解码回点云后，与真值点云比 Chamfer 距离，并在其上跑一个现成的 LiDAR 检测器看掉多少点。如果掉得厉害，"多模态"这个卖点就主要是视觉侧的。

§ 12 — Follow-up Research Idea ​

(a) 驱动它的局限：M⁴World 的整个控制接口是开环的。条件序列（ego 位姿、BEV 地图、逐帧物体属性）在 rollout 开始前就被完整指定，模型的任务是渲染出符合这些条件的观测。作者自己在结论里承认未来工作应当"在真正的闭环设定下评测，让学到的驾驶策略与生成环境交互"。这不只是评测缺失——它暴露了一个建模层面的空白：生成的其他 agent 不会对 ego 的行为做出反应。ego 突然刹车，前车不会看后视镜；ego 变道，旁车不会让。用这样的仿真器做闭环策略评测，得到的安全性数字会系统性偏乐观，因为环境从不针对你。

(b) 可借鉴的相邻工具：多智能体行为仿真（TrafficSim、CTG、SMART 这一脉）已经有成熟的反应式 agent 策略，能根据场景状态生成合乎博弈的轨迹；而本文的物体条件恰好是逐帧的 3D 框加属性——这正是行为仿真器的输出格式。两者的接口在结构上是天然对接的，只是至今被当成两个独立系统。

(c) 新的 framing：把驾驶世界模型从"条件渲染器"重构成渲染器与行为策略的耦合闭环。具体地，在每个自回归 chunk 边界插入一个轻量的反应式行为模块：它读入当前的场景状态（ego 位姿、各 agent 的框与属性、BEV 地图），输出下一 chunk 的物体条件，再交给 M⁴World 渲染。物体 token 里的外观与文本属性在这个循环里保持不变（保证身份一致），只有几何部分被行为模块更新。这样一来，安全关键场景就不再需要被逐帧脚本化——只需要指定 agent 的意图（"这辆车会切入"）与外观（"它是一辆被树枝遮挡的卡车"），剩下的交互由博弈自然涌现。这个 framing 还顺带解决了长尾脚本的可扩展性问题：脚本一条轨迹只能产出一个场景，指定一个意图能产出一族场景。

第一个实验：不改世界模型，只在推理循环里挂一个现成的反应式行为模型（比如在同一批数据上训的 SMART 类轨迹预测器，输入历史 agent 状态、输出下一 chunk 的框序列）。做三组对比——(a) 原始开环 rollout（条件全部来自真实日志），(b) 开环但 ego 轨迹被人为扰动（模拟策略与日志不同），(c) 闭环（ego 扰动 + 反应式 agent）。测量两件事：一是生成视频的物理合理性，用一个独立的碰撞检测器统计 (b) 中出现多少次"ego 与不反应的 agent 发生几何穿插"（这直接量化开环的失效程度）；二是在三组环境里评测同一个驾驶策略的碰撞率，看开环设定是否系统性地低估风险。如果 (b) 的穿插率显著高于 (a)、且 (c) 的策略碰撞率显著高于 (b)，那么"世界模型必须包含反应式 agent 才能用于闭环评测"就得到了量化支撑，这个方向的必要性也就成立了。
