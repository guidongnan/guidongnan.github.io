Orchestra-o1: Omnimodal Agent Orchestration ​

项内容
arXiv2606.13707
提交日期2026-06-10
作者Fan Zhang, Vireo Zhang, Shengju Qian, Haoxuan Li, Hao Wu, Jinyang Wu, Donghao Zhou, Zhihong Zhu, Zheng Lian, Xin Wang, Pheng-Ann Heng
分类cs.AI, cs.CL, cs.CV
一句话主 agent 只做编排：把全模态任务拆成带依赖图的子任务，按模态需求匹配后端与工具、把互相独立的那批并行派给 ReAct 子 agent，再用打在单步决策上的 DA-GRPO 把一个 8B 开源模型训成合格的编排者。

所属教程：智能体视频生成

§ 1 — 研究问题与重要性 ​

论文里那个 case study 最能说明问题：给一段音频（说 Mabon 秋分落在 9 月 23 日早上 7:49）和一张图（布拉格天文钟），问对应的 UTC 时间是多少。答案要同时用到音频里的本地时刻、图像里的地点、以及"布拉格 9 月执行 CEST（UTC+2）"这条外部知识，最后还要做一次算术，得到 05:49。人做这件事是自然的，agent 做起来要同时具备感知、长程推理、外部检索和代码执行。

论文给出的量化证据是：在 OmniGAIA 这个全模态 agent benchmark 上，最强的专有全模态模型 Gemini-3-Pro 也只有 62.5% 准确率。这个数字划出了问题的重要性——如果全模态智能只能靠继续把 omnimodal LLM（OLLM）做大来推进，代价曲线很陡；论文要论证的是「学会协调」是另一条独立的、更便宜的路。

§ 2 — 前人工作与不足 ​

论文把已有的全模态 agent 分成两类。native omnimodal agents（Qwen3-Omni、Ming-Flash-Omni、LongCat-Flash-Omni、Gemini 系列）直接把 OLLM 当 agent 后端挂上工具，同一个模型既感知又规划又调工具。它们的能力是真实的，但在长程推理、外部信息搜寻、代码执行和细粒度跨模态理解上仍然弱——62.5% 这个上限就是证据，开源侧最强的 OmniAtlas-Qwen3-30B-A3B 只有 20.8%。

orchestration-based agents 把感知与动作下放给子 agent，主 agent 只做高层决策。论文点名的最强开源基线是 AOrchestra，批评有两条：感知与动作工具集不完整；子 agent 工作流「相对刚性和线性」。这不是空泛的批评，表 1 里 AOrchestra-GPT-5 只有 40.0%，反而低于 Gemini-3-Pro 的 62.5%——编排框架做得不好，会把强主干的优势整个吃掉。至于 Kimi、Claude 这类闭源 agent swarm，藏在 API 后面，无法改造用于全模态研究。

§ 3 — 重建作者的思考路径 ​

在这篇论文之前，三件事已经成立：ReAct 式单 agent 的工具使用范式成熟；multi-agent swarm 在纯文本任务上已被验证有效；OLLM 在单一模态的子任务上其实够用，弱的是「同时扛感知和决策」。把这三条并排放，最自然的推论就是把感知从决策里剥出来。

剥出来之后立刻撞上两个工程事实。第一，不同子任务对模态的要求完全不同，把所有子任务都丢给最强最贵的后端是纯浪费——识别地标和转写音频显然不需要同一档模型。第二，很多子任务彼此独立（听音频与认地标互不依赖），线性排队浪费的是墙钟时间而不是精度。于是「显式依赖图 + 并行批次 + 后端/工具按需匹配」几乎是被逼出来的骨架。

训练侧的推理链条同样直接：如果奖励只看最终答案，每采一条 rollout 就要跑完整个多 agent 系统，既贵又稀疏。要让开源模型学会编排，就得把奖励打到单步决策上，用专家轨迹重建状态、离线打分。

§ 4 — 核心 Intuition ​

一个模型同时扛感知和决策，会在两边同时打折；把感知外包给专门的子 agent，主 agent 只负责「要什么证据、找谁要、够不够停」，两边都能各自做到最好。又因为子任务之间的依赖关系是显式且可预测的，互相独立的那些可以同时跑——准确率和延迟因此同向改善，而不是互相交换。

§ 5 — 具体方法与完整 Pipeline ​

沿用布拉格那个例子。主 agent 在第 t 轮观测状态 st​=(q,M,ct​,Ht​,B,T)，其中 ct​ 是压缩上下文、Ht​ 是结构化子任务历史、B 是可用后端池、T 是工具集，输出 delegate 或 complete。

  • 第一轮：主 agent 在未解子目标上诱导出依赖图。这里有两个互不依赖的节点——从音频抽事件/日期/本地时刻；从图像认地标与时区。两者都在 ready set 里，被打成一个并行批次，各自配好后端与工具子集（audio analysis / image analysis）。
  • 执行：每个子任务交给一个独立的 ReAct 式子 agent，环境克隆、最多 30 步，返回五元组（状态、答案、轨迹摘要、成本、延迟）。论文实测：音频子 agent 返回「equinox on the 23rd of September at 7:49 AM」，图像子 agent 返回「Prague Astronomical Clock / Europe/Prague」。
  • 聚合：结果 summarize 后并入 Ht+1​，再按 token 预算压缩成 Ct+1​，同时扣减成本预算。
  • 第二轮：时区换算依赖前两个结果，此刻才进入 ready set，派给 code execution 工具。
  • 停止：证据充分度 pθstop​(st​)>τstop​ 时输出 05:49 UTC。

工具生态固定为六个：image / audio / video analysis 三个感知工具，web search（Serper API）、page visit（Jina Reader API）、code execution 三个动作工具。主 agent 不直接调工具，只负责把工具子集分配给子 agent。

§ 6 — 核心数学推导 ​

后端选择把「能力匹配」和「花钱花时间」放进同一个打分里：

b∗(u)=argb∈Bmax​ 能力匹配⟨r(u),ϕb​⟩​​−λc​κb​ℓ(u)−λl​δb​

其中 r(u) 是子任务的模态需求向量、ϕb​ 是后端的能力向量、κb​ 与 δb​ 是单位成本与预期延迟。直觉：简单抽取和搜索路由到便宜模型，困难的全模态推理才动用强后端。

并行批次是一个带预算的选择问题：Pt​=argmaxP⊆Rt​​∑v∈P​Uθ​(v∣st​)，约束是 ∣P∣≤Kmax​ 且总成本不超当轮预算 Bt​。

命题 1给出并行的加速比，这是全文最实用的一个式子：

1≤St​=maxj​δt,j​+δtsync​∑j=1Kt​​δt,j​​≤Kt​

上界只在同步开销为 0 且所有子任务耗时相等时取到。它的实践含义是：只要有一个特别慢的子任务，加速比就退化到接近 1——并行的收益取决于子任务耗时是否均衡，而不只是数量。

命题 2用互信息链式法则论证编排优于原生：若主 agent 聚合证据不丢信息，且每个模态上专门化执行不劣于原生处理、至少一个严格更优，则 I(Y;Eorch​∣q)>I(Y;E0​∣q)，进而对数损失下的贝叶斯风险 Rlog​(Eorch​)<Rlog​(E0​)。这条命题的前提比结论强得多，读的时候要意识到它是把假设翻译成了结论。

DA-GRPO 用一个多维 rubric 奖励替代稀疏的最终答案奖励：

ri,j​=0.1rformat+0.1raction+0.2rtool+0.6rdecision

由 Claude-Haiku-4.5 一次调用打完四维（前两维二值，后两维分级归一到 [0,1]）。组内标准化得到相对优势 A^i,j​=Std({ri,k​})+ϵri,j​−Mean({ri,k​})​，再套 clip + KL 的 PPO 式目标。关键设计是专家决策只作参考而非唯一正解：只要拆解合理、有望解题，替代方案同样得分。

§ 7 — 实验设计与结论 ​

编排框架本身有用吗？ 控制主干和工具完全相同，把 ReAct-GPT-5 换成 Orchestra-o1-GPT-5，准确率从 53.9% 升到 72.8%。这排除了「增益来自 GPT-5」的解释。

比现有最强的强多少？ 72.8% vs Gemini-3-Pro 62.5%（+10.3）、vs AOrchestra-GPT-5 40.0%（+32.8）。按难度分解：easy/medium/hard 分别 80.3% / 75.0% / 56.4%，相对 AOrchestra 的增益是 35.2 / 35.0 / 24.3。

并行是省钱还是烧钱？ Orchestra-o1 用 341.6 的成本拿到 72.8%，AOrchestra 用 565.7 的成本只拿到 40.0%——更准且更便宜。

开源模型能学会编排吗？ Qwen3-8B 的阶梯很干净：ReAct 12.5% → 直接放进 Orchestra-o1 框架（不训练）26.3% → SFT 28.6% → vanilla GRPO 27.7% → DA-GRPO 30.0%，超过此前最好的开源结果 20.8%（OmniAtlas-Qwen3-30B-A3B，主干还大得多）。这里最反直觉的是 vanilla GRPO 反而低于 SFT：稀疏、弱对齐的强化学习信号对编排训练不够用，这正是 DA-GRPO 存在的理由。

§ 8 — Take-aways ​

5 句版：全模态任务的瓶颈不在单模型的感知能力，而在「同时感知和决策」；把两者解耦成主 agent 编排 + 专门子 agent 执行，同一主干能从 53.9% 提到 72.8%；编排要显式建模依赖图，独立子任务并行执行同时买到精度和延迟；训练开源编排者时，最终答案奖励太稀疏，把奖励打到单步决策上（DA-GRPO）才有效；一个 8B 主干在这套框架下能超过 30B 级别的开源全模态 agent。

3 句版：Orchestra-o1 把全模态 agent 拆成「编排 + 执行」两层，用依赖图调度并行子任务、按模态需求匹配后端与工具。它在 OmniGAIA 上把 SOTA 从 62.5% 推到 72.8%，同时比编排基线更便宜。DA-GRPO 用决策级 rubric 奖励替代稀疏结果奖励，让 Qwen3-8B 达到 30.0%。

1 句版：与其把全模态模型做大，不如教一个模型学会把活分给谁、怎么并行、什么时候停。

§ 9 — 最脆弱的假设 ​

命题 2 的假设 (i)——主 agent 在聚合子 agent 返回的证据时不丢失与答案相关的信息——是全文最承重也最可疑的一环。

现实中信息被压缩了两次：子 agent 返回的本来就是 summary（ωt,j​ 是「compact trace summary」），主 agent 还要再做一次上下文压缩以塞进 token 预算 Lctx​。每一次压缩都可能丢掉「当时看不出有用、后面才需要」的细节，而且这类丢失不可观测：主 agent 无从知道自己丢了什么，因此也无法通过补一轮 delegate 找回来。原生 OLLM 至少把所有模态放在同一个上下文里，不存在这道跨进程的信息瓶颈。

论文没有为这条假设提供直接证据（例如对比「完整轨迹 vs 摘要」的准确率），它提供的是端到端准确率高这一间接结果。如果假设不成立，编排相对 native OLLM 的理论优势就没有保障，只剩下经验优势——而经验优势可能来自 OmniGAIA 中那些「模态间弱耦合、天然可分解」的题目。

§ 10 — 最小复现实验 ​

不重建整套系统，只验证「编排结构」这一个变量。

  • 数据：OmniGAIA 的 hard 子集，30–50 题即可（这一档差距最大，信噪比最好）。
  • 实现：同一个 GPT-5 主干、同一套六工具，做两个版本。A：标准 ReAct 单 agent，工具全开。B：只加三件事——显式依赖图、ready set 并行派发、子 agent 独立上下文。不做任何训练，不加 DA-GRPO。
  • 测量：准确率、墙钟时间、token 成本。
  • 判据：论文自己的 harness 消融预测差距应在 15–20 个点量级（53.9 → 72.8）。若重现出的差距不足 5 个点，说明主要增益来自论文未充分披露的 prompt 工程而非编排结构本身；若差距成立但墙钟时间没降，说明命题 1 的均衡假设在真实子任务上不满足。

§ 11 — 最强反例设计 ​

构造一批证据强耦合的任务：答案取决于跨模态的精确时间对齐。例如「视频里说出『这个数字』那句话的瞬间，画面右下角显示的是多少」。

这类任务原理上无法被切成独立子任务。把音频和视频分派给两个子 agent 后，两边各自返回文本摘要，跨模态的精确时刻对齐信息在摘要阶段就已经蒸发了。可以预期 Orchestra-o1 在这类题上不但不优于 native OLLM，反而更差——后者至少在同一个上下文里同时看到两条流。

这个反例同时提供了两样东西：一个可预测的失败条件（模态间强耦合、需要细粒度对齐），以及对主结果的替代解释（OmniGAIA 上 +10.3 的增益可能主要由弱耦合可分解题目贡献）。验证成本很低：只需在 OmniGAIA 里按「是否需要跨模态对齐」重新分层，看增益是否集中在弱耦合层。

§ 12 — Follow-up Research Idea ​

驱动局限：DA-GRPO 只训主 agent，子 agent 后端在训练中固定（论文 Appendix C 自陈）。但更根本的问题是奖励的来源——rubric 由一个更强的模型按专家轨迹打分，本质是在模仿别人的决策分布，而不是在优化「这次该问什么」这个决策本身该优化的量。

新 framing：把 agent 编排当作带成本的实验设计问题。每个子任务是一次测量，主 agent 要选择使答案后验熵下降最快的测量序列。这把命题 2 里那个「事后正当化」的互信息，变成了「事前决策目标」。

可借鉴的邻域工具：贝叶斯实验设计与主动学习里的 expected information gain（EIG）准则，以及序贯决策里的 value of information 分析——它们恰好解决「在预算约束下选哪次测量」这个同构问题。

第一个实验：用一个小型代理模型对每个候选子任务估计 EIG，替换掉 rubric 里权重最大的 rdecision（0.6），训练 EIG-GRPO。在相同成本预算下画准确率-成本曲线，与 DA-GRPO 对比。若 EIG 版本在低预算区间更优，说明编排的正确目标是信息增益而非行为模仿；若在高预算区间才反超，说明 rubric 的价值主要是稳定早期训练。
