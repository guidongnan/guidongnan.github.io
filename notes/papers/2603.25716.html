Out of Sight but Not Out of Mind: Hybrid Memory for Dynamic Video World Models ​

项内容
arXiv2603.25716
提交日期2026-03-26
作者Kaijin Chen, Dingkang Liang, Xin Zhou, Yikang Ding, Xiaoqiang Liu, Pengfei Wan, Xiang Bai
分类cs.CV, cs.AI
一句话把历史 latent 压成时空 memory token，用 query-key 亲和度动态检索最相关的那几个 token，让离开画面又走回来的运动主体不再冻结、扭曲或消失。

所属教程：世界模型

§ 1 — 研究问题与重要性 ​

视频世界模型的记忆机制几乎都是围绕"静态画布"设计的：相机转开又转回来，模型要能把之前那面墙、那栋楼原样画回去。这个设定下的评测方式也很直白——回到相同 pose，看场景是否一致。

问题是真实世界不是画布。画面里有走路的人、跑动的狗，它们有自己的运动逻辑。当相机左摇再右摇，一个行人先离开视野再重新入画，模型该画什么？论文列出了当前方法的三种典型失败：主体冻结成雕像（保留了外观但丢了运动状态）、扭曲成畸形（检索到了错误的历史片段）、凭空消失（干脆没记住它存在过）。

作者把这个要求正式命名为 Hybrid Memory：模型要同时扮演两个角色——静态背景的精确档案管理员，和动态主体的持续追踪者。后者的难点在于，主体离开视野的那段时间里没有任何视觉证据，模型必须在 latent 空间里隐式外推它的运动，等它回来时位置和运动状态都要说得通。这不是锦上添花的细节，而是世界模型能否用于具身智能、自动驾驶这类有其他智能体存在的场景的前提。

§ 2 — 前人工作与不足 ​

近期记忆机制大致分检索与压缩两路。Context-as-Memory 用 FOV（视场）重叠来筛历史帧，VMem 用 surfel 索引的视图记忆，WorldMem 把 FOV 检索的外部记忆库和 Diffusion Forcing 结合用在 Minecraft 上，Memory Forcing 进一步引入时序记忆平衡探索与一致性，MemoryPack 沿 FramePack 思路做可更新的语义打包，RELIC 对上下文做均匀空间下采样压缩。这些方法在静态场景上确实有效。

论文指出它们共享同一个盲点，而且这个盲点是方法本身的假设带来的：FOV 重叠是纯几何量，它只回答"这一帧的相机看没看到过那块空间"，完全不包含"那块空间里的东西在动"这一信息。所以当一个主体在 out-of-view 期间移动了位置，几何检索会自信地取回一段空镜头——相机 pose 对得上，但主体早已不在那里。论文附录里给出了这个失败的直接可视化：FOV 方法只选到 re-entry 片段附近的最近 pose，检索回来的是空景，关键外观信息全丢。

另一个缺口在数据。互联网上带有"完整、无遮挡的离场—再入场事件"的视频极其稀少，评测无从下手。作者对比了几个现有数据集：Context-as-Memory 数据集只有静态场景；WorldScore 有部分动态元素但只有 3K 规模；Multi-Cam Video 有动态主体但只做原地动作；360°-Motion 有移动主体但相机静止、主体始终在视野内。Genie 3 展现了很强的动态一致性，但闭源、细节未公开，无法作为可复现基线。

§ 3 — 重建作者的思考路径 ​

顺着已有线索走一遍：静态记忆能用几何检索解决，是因为静态场景里"相机 pose"和"内容"是一一对应的——知道相机在哪，就知道该画什么。这个映射一旦引入独立运动的主体就断了：同一个 pose 在不同时刻对应完全不同的内容。

那自然的下一步是问：既然几何不够，还有什么可以作为检索的依据？注意力机制本身就是一种基于内容的检索——query 和 key 的内积衡量的正是特征层面的相关性，而不是坐标层面的重合。如果 denoising 的 query 里已经隐含了"我现在要画的这块区域和什么有关"的信息，那让它直接和历史 latent 算相似度，就有机会绕开"pose 对得上但内容对不上"的陷阱。

但直接在原始 latent 上做检索又有新麻烦：单帧 latent 里静态背景和主体特征高度耦合，且缺少跨帧的运动信息。要让检索单元携带"运动"，就得让它在时间维上有感受野——3D 卷积是最直接的做法。压缩本身还顺带解决了另一个问题：把全部历史 latent 塞进注意力既贵又吵，无关上下文会误导推理。

于是路径闭合：3D 卷积压出带运动语义的 memory token → 用内容亲和度而非几何重叠做 Top-K 检索 → 只把选中的 token 送进注意力。数据缺口则用 UE5 程序化渲染补，因为只有在引擎里才能把相机轨迹和主体轨迹显式解耦，从而"制造"足够密度的离场—再入场事件。

§ 4 — 核心 Intuition ​

几何告诉你相机看过哪里，但动的东西不会等在原地。要找回一个藏起来的主体，应该问"哪段历史特征跟我现在要画的内容最像"，而不是"哪段历史的相机 pose 跟现在最接近"。

把历史压成带时间感受野的 token，让 denoising query 用注意力打分自己挑，就把"记住一个位置"换成了"记住一段运动"。

§ 5 — 具体方法与完整 Pipeline ​

以一个具体样本为例：一段 UE5 渲染的街景，画面里一只长颈鹿沿预设路径走动，相机先向左平移把长颈鹿移出画面，再向右摇回来。模型收到 77 帧上下文 Xctx​ 和覆盖历史与未来的完整相机轨迹 P={Pctx​,Ptgt​}，要预测目标帧 Xtgt​。

  1. 编码与相机注入。causal 3D VAE 把上下文帧压成 latent（时间维下采样 4 倍）。相机轨迹 P={(Ri​,ti​)}i=1f​ 被展平拼接成 ccam​∈Rf×12，经 MLP 编码后在空间维广播、逐元素加到 DiT 输入特征上（沿用 ReCamMaster 的做法）。
  2. Memory Tokenization。历史 latent Zmem​ 过一个 kernel 为 2×4×4 的 3D 卷积 tokenizer，输出 M∈RC′×fmem′​×h×w。时间维的 kernel 是关键：它让每个 token 聚合多帧信息，从而携带长时程运动线索，而不只是某一瞬的外观快照。
  3. Dynamic Retrieval Attention（替换掉基础模型里的 3D self-attention）。目标 latent 投影成 query，memory token 投影成 Kmem​,Vmem​。对每个目标帧 i，先把 qi​ 空间池化到与 memory token 同分辨率，再和每个时间切片 kmem,j​ 算亲和度，Top-K 选出 K=10 个最相关的 token。
  4. 保留局部窗口。只用检索到的远程记忆会破坏局部去噪的稳定性，所以强制把当前帧邻域（窗口大小 5）的 key/value 拼进来，再做标准注意力。
  5. 输出。DiT 按 Flow Matching 预测速度场，去噪后的 latent 经 3D VAE 解码回像素。长颈鹿重新入画时，检索到的是包含它丰富外观细节的关键帧，而不是空镜头，所以身份和步态都能接上。

训练在 HM-World 上跑 10K iterations，32 张 GPU，总 batch size 32，基础模型是 Wan2.1-T2V-1.3B。

§ 6 — 核心数学推导 ​

Flow Matching 目标。给定视频 latent z0​ 与高斯噪声 z1​∼N(0,I)，训练时按时间 t∈[0,1] 线性插值得到 zt​，模型 u 预测真实速度 vt​=z0​−z1​：

Lθ​=Ez0​,z1​,t​∥u(zt​,t;θ)−vt​∥2

直觉上，模型学的不是"这一步该去掉多少噪声"，而是"从噪声到数据这条直线路径上，此刻的速度方向是什么"。线性插值让目标速度是常量 z0​−z1​，训练信号比曲线路径更干净。

相机注入。设进入 DiT 的特征为 Hin​，则

Hout​=Hin​+Ecam​(ccam​)

一个加法而非 cross-attention，因为相机是全局、低维、逐帧确定的条件，不需要模型去"挑选"。

时空亲和度。这是全文最核心的一个式子。q~​i​ 是池化后的 query，kmem,j​ 是第 j 个 memory token 的 key：

Si,j​=d1​y=1∑h​x=1∑w​⟨q~​i​(x,y),kmem,j​(x,y)⟩

⟨⋅,⋅⟩ 是通道维内积，d 是缩放因子。注意这里是逐空间位置对齐后再求和，不是全局池化后算一个标量——这样保留了"画面左上角和记忆里左上角是否匹配"这种空间结构信息。它是标准 attention logit 的一个空间对齐版本。

Top-K 筛选与最终注意力：

Ii​=TopK(Si​,K),Ksel​={kmem,j​∣j∈Ii​},Vsel​={vmem,j​∣j∈Ii​}

Attention(qi​,Ki′​,Vi′​)=Softmax(d​qi​(Ki′​)⊤​)Vi′​,Ki′​=[Ksel​,Kloc​], Vi′​=[Vsel​,Vloc​]

Top-K 把注意力从"对全部历史求和"变成"对少数几个 token 求和"，既降计算又降噪声；拼上局部窗口 Kloc​,Vloc​ 则保证近邻帧的连续性不被牺牲。

DSC 指标。用 YOLOv11 取主体框，CLIP 提特征，空间对齐与时间归一化后算余弦相似度：

DSCGT​=sim(Fpred​,Fgt​),DSCctx​=sim(Fpred​,Fctx​)

前者衡量与真值的一致性，后者衡量与历史上下文的一致性。分开两个指标是有道理的：一个跨域模型可能与 GT 差很多（域不同）但与自己的上下文很一致。

§ 7 — 实验设计与结论 ​

问题一：现有方法在动态主体上到底差多少？ 作者在 HM-World 上统一训练所有对比方法（baseline 是 Wan2.1-T2V-1.3B 加相机编码器，直接把上下文 latent 和噪声 latent 拼进 DiT）。结果显示 baseline PSNR 18.696、SSIM 0.517，DFoT（依赖邻近上下文窗口）反而更低到 17.693，Context-as-Memory（FOV 过滤）18.921。HyDRA 拿到 20.357/0.606/0.289，DSC${ctx}$ 0.827、DSC$$ 0.849，Subject Consistency 0.926、Background Consistency 0.932，全部指标领先。

问题二：这是不是只赢过学术小模型？ 作者额外做了 WorldPlay（商用模型）的 zero-shot 评测。WorldPlay 在 GT 参考指标上明显偏低（PSNR 14.855，DSC${GT}$ 0.832），作者归因于域分布差异和缺少针对性微调；但它在上下文参考指标上表现稳健（DSC$$ 0.822）。这个结果被用作双向论证：既说明大规模训练的模型确实有相当的 hybrid 一致性，也反过来支持 DSC 指标本身的合理性——一个域外但自洽的模型应该在 DSC$_{ctx}$ 上得分不低，事实正是如此。这一步比单纯堆数字更有说服力。

问题三：赢在哪个组件？ 三组消融给出了清晰的归因。tokenizer 的空间 kernel 从 4×4 换成 2×2 或 8×8，PSNR 只降 0.244 和 0.127，说明对空间尺度不敏感；但时间 kernel 降到 1（即取消时间交互）PSNR 掉 1.281、DSC$_{GT}$ 掉 0.014——时间感受野才是 tokenizer 的价值所在。检索 token 数从 5 增到 10 带来明显提升（19.309→20.357），再到 15 几乎持平，说明存在一个"够用即可"的区间。最关键的一组是检索方式对比：把亲和度换成 FOV 重叠，PSNR 19.776、Subject Consistency 0.908，均低于 dynamic affinity 的 20.357/0.926。附录还画出了 token 选择分布：FOV 方法因为依赖静态几何，整个推理过程选的是固定的那几个 token；亲和度方法在不同 timestep、不同 DiT 层会选不同 token。这直接支撑了 §4 的 intuition。

§ 8 — Take-aways ​

5 句话版：现有视频世界模型的记忆机制默认世界是静态画布，主体离场再入场时会冻结、扭曲或消失。论文提出 Hybrid Memory 范式，要求同时维持背景的空间一致性与主体的运动连续性。为此构建 HM-World，用 UE5 解耦相机与主体轨迹，渲染 59K 个含离场—再入场事件的片段。方法 HyDRA 用 3D 卷积把历史压成带运动语义的 memory token，再用时空亲和度做 Top-K 动态检索，替换掉原本的 3D self-attention。实验显示它全面超过 DFoT、Context-as-Memory 以及 zero-shot 的 WorldPlay，消融确认时间维 tokenization 和内容亲和度检索是两个真正起作用的设计。

3 句话版：静态几何检索找不回移动过的主体，因为相机 pose 对得上不代表内容还在那里。HyDRA 改用内容层面的时空亲和度检索压缩后的 memory token，把"记住一个位置"换成"记住一段运动"。配套的 HM-World 数据集第一次让这类能力可训练、可量化评测。

1 句话版：用基于特征亲和度的动态检索替代基于 FOV 重叠的几何检索，让视频世界模型记得住那些暂时看不见的运动主体。

§ 9 — 最脆弱的假设 ​

最要命的一个假设是：去噪 query 在检索发生时，已经携带了足够的"我要画的是那个主体"的语义信息。整个 Top-K 检索完全建立在 Si,j​ 这个内积上，而 qi​ 来自正在被去噪的 latent。在去噪早期，目标 latent 几乎全是噪声，query 里到底有多少可靠语义？如果早期检索选错了 token，后续步骤是否有能力纠正，论文没有给出直接证据（附录 Fig.10 显示不同 timestep 会选不同 token，这说明选择在变化，但没有说明早期的选择是否正确）。

这个假设失效的现实场景是可以预期的：当画面里有多个外观相似的主体时，特征亲和度本身就无法区分谁是谁——内积高只说明"像"，不说明"是同一个"。论文自己在 limitations 里承认，三个及以上主体或严重遮挡时性能会退化，这与上述分析吻合。作者提供的证据是"检索分布多样"和"最终指标更好"这类间接证据，缺的是检索正确率这一直接度量：在有 ground-truth 主体位置标注的情况下（HM-World 恰好有逐帧主体位置），完全可以统计"检索到的 token 是否真的包含目标主体"，但论文没有报这个数。

§ 10 — 最小复现实验 ​

一周内可做、且不需要复现整个训练流程的验证方案，目标是直接检验 §9 那个假设：

  • 数据：不必用全部 59K 片段。取 HM-World 测试集里主体单一、离场—再入场清晰的 100 个样本即可，这些样本自带逐帧主体位置和进出场时间戳。
  • 实现：加载作者开源的 HyDRA 权重（GitHub 已公开），在 Dynamic Retrieval Attention 里挂 hook，把每个 denoising step、每层 DiT 选中的 Top-K token 索引 dump 出来。由于 memory token 是多帧聚合的，用其源帧集合来判断"该 token 是否覆盖主体在场的帧"。
  • 测量：定义检索命中率 = 选中的 10 个 token 中至少包含一个"主体可见帧"的比例，按 denoising timestep 分箱统计。同时用同一批样本跑一次 FOV 重叠检索作为对照。
  • 判定：如果命中率在早期 timestep（t 接近纯噪声）就已经显著高于随机基线，说明 query 在高噪声下仍带有可用语义，假设成立；如果早期接近随机、后期才上升，那真正起作用的可能是局部窗口 Kloc​ 提供的连续性，而检索只是在后期锦上添花——这会大幅削弱论文的核心 claim。

§ 11 — 最强反例设计 ​

站在反对者立场，最有力的攻击是提出一个替代解释：HyDRA 的增益可能主要来自 memory tokenizer 带来的压缩与去噪，而不是来自"动态检索"这个机制本身。

理由是：3D 卷积 tokenizer 把原始 latent 压缩成少量 token，这个操作本身就过滤了大量无关上下文，而论文自己也说"直接注入全部 Zmem​ 会用无关噪声淹没模型"。那么一个公平的对照组应该是：保留 tokenizer，但把 Top-K 检索换成随机选 K 个 token 或直接用全部 token。论文的消融里有 FOV vs 亲和度（换了检索方式但都用 tokenizer）、有 kernel size（改了 tokenizer 但保留检索），却没有"有 tokenizer 无检索"这一组。缺了它，无法排除"tokenizer 干了大部分活"的解释。

进一步的可预测失败场景：把相机轨迹换成快速大幅旋转，使得主体离场时间远超 memory token 的时间感受野（kernel 时间维只有 2，即便叠加多层，覆盖的时长仍然有限）。此时"记住一段运动"退化为"记住一个瞬间"，外推距离超出模型能力，预期主体会回到冻结或漂移状态。论文的相机轨迹全部来自自己设计的 28 条，离场时长的分布未披露，无法排除这一区间被系统性回避。

§ 12 — Follow-up Research Idea ​

(a) 驱动它的局限：HyDRA 的记忆是"以帧为单位的隐式记忆"——token 仍然是画面切片的压缩，主体只是隐含在其中。这导致两个后果：外观相似的多主体无法区分（论文承认的失败模式），以及运动外推的时长受限于卷积感受野。根源在于，模型从来没有把"主体"当成一个可寻址的实体。

(b) 可借鉴的相邻领域工具：多目标跟踪（MOT）里的 tracking-by-query 范式（如 MOTR 系列）为每个目标维护一条持久 query，通过帧间传播保持身份，天然解决"谁是谁"；而物理引擎里的状态外推（恒速/恒加速模型）提供了在无观测期间推进实体状态的显式手段。同期的 ActionParty（arXiv:2604.02330）在游戏场景里已经验证了"为每个 subject 维护一个 state token 并用注意力掩码强制绑定"是可行的。

(c) 新 framing：把记忆从"检索历史画面"重构为"维护一组实体状态 + 按需渲染"。为场景中每个动态主体分配一条持久 entity query，它在主体可见时从视觉观测更新，在主体离场时按学到的运动先验自主推进（不再需要检索任何历史帧），重新入画时由 DiT 把这条 query 渲染回像素。这不是给 HyDRA 加模块，而是换掉它的记忆基元：从"帧的压缩"换成"实体的状态"。

第一个实验长这样：在 HM-World 的单主体子集上，训练一个只有两条 entity query（主体 + 背景）的变体，out-of-view 期间禁止任何历史帧参与注意力，只允许 entity query 自演化。若它在 DSC$_{GT}$ 上能追平 HyDRA，就证明显式实体状态足以替代帧检索；随后把主体数扩到 3–7 个并混入外观完全相同的主体，检验它能否解决 HyDRA 明确失败的那个区间。这个设计的好处是，第一步实验就能给出一个明确的二分答案。
