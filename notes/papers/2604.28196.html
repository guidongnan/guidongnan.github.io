HERMES++: Toward a Unified Driving World Model for 3D Scene Understanding and Generation ​

项内容
arXiv2604.28196
提交日期2026-04-30
作者Xin Zhou, Dingkang Liang, Xiwu Chen, Feiyang Tan, Dingyuan Zhang, Hengshuang Zhao, Xiang Bai
分类cs.CV
一句话用 BEV token 作为 LLM 与 3D 几何的公共载体，让 world queries 走一遍 LLM 吸收语义后经 Current-to-Future Link 生成未来 BEV，并在显式点云监督之外对 latent 加几何先验对齐，使同一个模型既能回答场景问题又能预测 3 秒后的点云。

所属教程：世界模型

§ 1 — 研究问题与重要性 ​

驾驶世界模型和驾驶 VLM 长成了两个互不相交的物种。前者（ViDAR、4D-Occ、DriveX、OccWorld）能预测场景怎么演化，但说不出场景里有什么、为什么会这样演化——你没法向它提问。后者（OmniDrive、DriveLM、DriveGPT4、ORION）能解释交通参与者、回答空间关系问题，但只理解当前状态，不具备预测几何演化的能力。

这个割裂在安全关键场景里是实质性的：避撞既需要当前上下文的理解，也需要对未来变化的预判。论文的主张是一个世界模型本该同时具备两者，而实现这一点要解决两个具体的技术问题。第一，需要一个既能承载多视角空间关系、又能被 token-based LLM 消费的 3D 表征。第二，需要一个真正的交互机制而非多任务特征共享——语义理解要能引导几何演化，几何预测要能给语言生成提供物理接地。

§ 2 — 前人工作与不足 ​

生成侧：ViDAR 用图像自监督预测未来点云，4D-Occ 把点云预测当作 4D occupancy 预测的代理任务，DriveX 做全景场景建模，OccWorld 用时空 transformer 做 occupancy 生成与规划。它们的共同缺陷是"能预测但不能解释"：可以给出貌似合理的未来状态，却没有内在机制去表达语义上下文或者驱动这一演化的因果因素。

理解侧：OmniDrive 用 Q-Former 把 3D 表征接进 VLM 并建了完整 benchmark，DriveLM 用场景图做结构化推理，ELM 针对具身场景做预训练。这些方法把 LLM 的角色限定在理解当前状态上，缺少预测未来几何演化的能力。而且论文指出一个具体的工程依赖：Omni-Q、ORION 这类用稀疏 query（Q-Former3D）抽取场景信息的做法，通常需要 3D 检测框、车道线之类的辅助监督来引导特征学习，以补偿稀疏观测捕获的几何上下文有限。

已有的统一尝试也不够。Doe-1 做闭环驾驶但主要是单视角生成，Epona 用自回归扩散解耦时序动态与视觉生成，FSDrive 提出视觉时空 CoT。论文的评价是这些方法大多在 2D 单视角上工作，或缺少与语义推理交织的稠密 3D 几何约束。

§ 3 — 重建作者的思考路径 ​

这是 ICCV 2025 会议版 Hermes 的扩展。会议版已经确立了主干思路，扩展版的四项新贡献恰好暴露了作者遇到的实际障碍。

起点是选表征。多视角图像 token 化后送进 LLM 是最直接的做法，但高分辨率多视角输入的 token 数会超出 LLM 的长度限制。BEV 是一个自然的答案：它天然融合多视角、消解遮挡与尺度歧义，且以规则网格形式存在，容易压缩成 token 序列。

接下来是怎么让"理解"真正影响"生成"，而不只是共享一个 backbone。作者的答案是让一组可学习的 world queries 直接进入 LLM 的输入序列。因果注意力使这些 query 能读到前面所有的 BEV token 和文本 token，同时 LLM 预训练里的世界知识会被注入这些 query。它们出来时就是携带了语义与因果先验的未来时刻表征。

会议版之后遇到的问题写在扩展贡献里：只用点云渲染损失监督，latent 会出现结构歧义。论文可视化了这个失败模式——沿相机投影线的射线状伪影，以及 ego 中心异常高的响应集中，把真正的场景几何淹没了。这直接推出了第二项贡献：在 latent 流形上额外施加几何先验对齐。另外两项（Textual Injection、Ego Modulation）分别针对"文本语义没有直接进入生成过程"和"自车运动与场景固有动态纠缠"这两个具体缺口。

§ 4 — 核心 Intuition ​

理解和几何预测不该抢同一份表征，而该共用同一个几何底座：BEV 既保留 3D 空间拓扑又能压成 LLM 可读的 token。把未来时刻的占位 query 直接塞进 LLM 的输入序列，它们就会在因果注意力下同时吸收当前观测的几何上下文和文本指令的语义，出来后已经是带世界知识的未来先验。至于渲染监督管不到的 latent 内部结构，用一个自监督点云重建网络当冻结教师做特征对齐补上。

§ 5 — 具体方法与完整 Pipeline ​

以一个 nuScenes 场景为例，输入是 7 路相机当前帧图像加一句用户指令，输出是文本回答加未来 0–3 秒的点云序列。

  • BEV tokenizer：OpenCLIP ConvNeXt-L 抽多尺度透视特征，经空间 cross-attention 转成 180×180、256 通道的 BEV 特征。因为原始 BEV token 数远超 LLM 长度限制，用带 stride 的卷积与池化把空间分辨率降 4 倍、通道扩 4 倍，展平后线性投影成 LBEV​ 个 LLM token。
  • world queries 构造：对压缩后的 BEV 特征做 adaptive max pooling 得到 n 个基础空间 query，把每个未来帧的 ego-motion 经 MLP 编码成运动 embedding 广播相加，再加可学习的帧序 embedding，拼成 Δt×n 个 query 投影到 LLM 隐藏维。
  • LLM 前向：BEV token、文本 token、world queries 拼成一个序列送进 InternVL2。文本侧走标准 next-token prediction 产生回答；world queries 在因果注意力下聚合前面所有内容，出来时携带了具体语义上下文与 LLM 的世界知识。
  • Current-to-Future Link：以 LLM 编码后的当前 BEV Bt​ 为初始输入，堆若干 block（默认 6 层，每层含 cross-attention、self-attention、FFN）。cross-attention 的 key/value 是 world queries 与池化后的文本 embedding 的拼接（Textual Injection）；self-attention 与 FFN 分支上施加由未来 ego-motion 生成的调制参数（Ego Modulation），把自车运动从场景固有动态里解耦出来。
  • BEV-to-Point Render：把 BEV 特征上采样并沿高度维展开成体素，3D 卷积细化后，对每条 LiDAR 射线采样、trilinear 插值取特征、浅层 MLP 预测 SDF 值，用 SDF 梯度导出的不透明度做体渲染得到深度，再转回 3D 坐标得到点云。这个 Render 在当前帧与所有未来帧之间共享。
  • 训练：三阶段渐进。先自监督训练几何特征提取器（稀疏 3D 卷积编码器 + Render 重建点云）然后冻结；再做视觉—语言对齐与精调（LLM 上用 LoRA），期间用一种拼接 caption 与未遮挡视角的 masking 增强把图文对扩到约 200K；最后接入 Current-to-Future Link 联合训练。

§ 7 — 实验设计与结论 ​

统一模型能不能打过专才？ 在 nuScenes / OmniDrive-nuScenes 上，生成侧用 3 秒 Chamfer Distance，理解侧用 METEOR / ROUGE / CIDEr。1.8B 版本 3 秒 CD 为 1.01，对比 ViDAR 的 1.73 降低 41.6%，比 DriveX 的 1.10 低 0.09；3.8B 版本进一步到 0.97。理解侧 1.8B 的 CIDEr 为 0.749，3.8B 为 0.772，而 Omni-L / OmniDrive-2D 分别是 0.732 / 0.671——关键是后者用了 3D 框与车道线的辅助监督，HERMES++ 没有。相对 ICCV 会议版（3 秒 CD 1.17、CIDEr 0.741），生成误差降低 13.7%。

BEV 真的比直接喂多视角 token 好吗？ 控制 token 数相同（2532）做对比。理解性能几乎持平（METEOR 差 0.001），但生成侧 BEV 把 3 秒 CD 降低约 32%。论文给出的解释是展平的图像 token 在 LLM 处理中发生空间结构坍塌，语义还在但几何恢复不出来。定性案例里多视角 baseline 被误导性的路面标线骗成预测左转，BEV 版本正确预测直行。

BEV 分辨率怎么选？ 从高分辨率特征下采样 4 倍最好（3 秒 CD 1.436，CIDEr 0.720）。直接学粗粒度 query 明显更差（2.012），说明压缩前先在高分辨率上捕获细节是不可替代的，直接粗查询造成的信息损失无法找回。下采样 8 倍则形成信息瓶颈（1.781，CIDEr 0.681）。

Joint Geometric Optimization 各部分贡献多少？ 只用显式约束 3 秒 CD 为 1.637；加 Lcos​ 降到 1.441，只加 Lgram​ 降到 1.544，两者都加 1.436。可视化显示只有显式约束时 latent 里有沿相机投影线的射线状伪影与 ego 中心的异常响应集中，加入隐式正则后这些被抑制，特征变得空间紧凑并贴合点云的固有几何。

Current-to-Future Link 的每个组件呢？ 完全去掉 Link（直接复制 Bt​ 加未来 ego 状态）灾难性失败：3 秒 CD 2.377，CIDEr 掉到 0.433。加 3 层 vanilla attention 的 Simple Link 立刻降到 1.542；加 Textual Injection 到 1.506；加 Ego Modulation 到 1.442；层数从 3 增到 6 到 1.436。

任务统一是互相帮忙还是互相拖累？ 单任务专才版本分别是生成 1.434、理解 CIDEr 0.726；"分离式统一"（共享 tokenizer 但无深度交互）反而更差（1.634 / 0.703）；完整版是 1.436 / 0.720。可以推断，统一带来的收益主要体现在"用一个模型达到与两个专才相当的水平"，而非在两项上都超过专才——论文自己的措辞也是"achieves performance comparable to specialized single-task models"。world queries 是否走 LLM 是关键：绕过 LLM 只到 1.526，走 LLM 到 1.436。

泛化性如何？ NuScenes-QA top-1 准确率 61.3%，超过相机 SOTA Omni-Q（59.2%）2.1 个百分点，也超过 LiDAR 专才 CenterPoint+MCAN（59.5%）。DriveLM leaderboard 最终得分 0.59，与挑战赛冠军 Team NVIDIA 持平，Accuracy 0.83 高于 Omni-Q 的 0.78。开环运动规划上，仅在 world queries 上接一个轻量 MLP 头，平均 L2 0.37 m、碰撞率 0.29%，碰撞率低于 ORION 0.08 个百分点。换 LLM 架构（Llama-3.2、Qwen3、InternVL2）都能工作，InternVL2 最好；模型规模从 0.8B 到 3.8B，3 秒预测误差改善 12.5%。

§ 8 — Take-aways ​

5 句话版：驾驶世界模型只会预测不会解释，驾驶 VLM 只会解释不会预测，HERMES++ 把两者放进一个框架。核心选择是 BEV：它同时保住多视角几何拓扑和 LLM 可消费的 token 形式，控制 token 数相同时比直接喂图像 token 的 3 秒 CD 好约 32%，因为展平的图像 token 在 LLM 里会发生空间结构坍塌。交互机制是让 world queries 进入 LLM 输入序列，靠因果注意力吸收 BEV 观测与文本指令的语义，再经 Current-to-Future Link 在文本 embedding 与 ego-motion 调制下生成未来 BEV，共享的 SDF 体渲染 Render 解码出点云。会议版只有点云渲染监督时 latent 会出现相机投影线方向的射线伪影与 ego 中心偏置，扩展版用冻结的自监督点云重建网络作教师，通过逐体素余弦与三视图 Gram 矩阵对齐把 latent 拉回几何流形，3 秒 CD 从 1.637 降到 1.436。最终 1.8B 模型在无任何检测或地图辅助监督的条件下，生成与理解两侧都优于对应的专才基线，并可迁移到 NuScenes-QA、DriveLM 与开环规划。

3 句话版：以 BEV 作为 LLM 与 3D 几何的公共载体，用穿过 LLM 的 world queries 把语义推理接到几何预测上。除了点云渲染监督，额外在 latent 上对齐冻结几何教师的特征，消掉了纯渲染监督造成的射线伪影。1.8B 模型不用辅助监督即在 3 秒点云预测与场景理解上同时超过专才基线。

1 句话版：让未来时刻的占位 query 亲自走一遍 LLM，语义就能真正流进几何预测——前提是底座换成 BEV，且 latent 本身也被几何先验约束住。

§ 9 — 最脆弱的假设 ​

最要命的一条是：压缩到 LLM token 长度的 BEV 特征仍保留了足够的几何细节，让 3 秒后的点云可以被准确解码。整个架构的合法性都建立在这个"压缩不致命"的前提上。

论文自己的消融恰好把这个假设的边界画出来了：下采样 4 倍能到 1.436，下采样 8 倍就退化到 1.781，直接学粗特征更差到 2.012。也就是说，方法工作在一个相当窄的压缩窗口里，而这个窗口的位置是由当前 LLM 的上下文长度决定的，不是由几何本身决定的。可以推断，若要提高 BEV 分辨率以覆盖更远距离或更小物体，token 数会立刻超出预算；若要延长预测时程，同样的 token 预算要承载更多不确定性。

论文提供的正面证据是定性案例里模型能从招牌上认出 "Shaw Foundation Alumni House" 并推断这是校园，说明压缩后仍有细粒度语义。但这是语义粒度的证据，不是几何粒度的证据——认出招牌文字与恢复远处车辆的精确 3D 位置是两回事。评测的 ROI 也限定在 x,y∈[−51.2m,51.2m]、z∈[−3m,5m]，超出这个范围的几何质量没有证据。

§ 10 — 最小复现实验 ​

不需要复现完整的三阶段训练。一周内可做的最小验证针对上面那个假设：

  1. 取一个现成的 BEVFormer 系列 encoder 加一个简单的体渲染 decoder，在 nuScenes 25% 训练数据上只训练"当前帧点云重建"这一项任务（跳过 LLM 与未来预测）。
  2. 扫描 BEV 下采样倍率（×2,×4,×8）与 BEV 网格分辨率，记录重建 Chamfer Distance 随 token 数的变化曲线。
  3. 判据：如果重建误差在 ×4 附近出现明显拐点，说明论文报的最优配置来自几何信息容量的内在限制，而非对 LLM 上下文长度的迁就；如果曲线是平滑单调的，那么"×4 最优"更可能是与 LLM token 预算的偶然匹配，换一个上下文更长的 LLM 结论就会变。

补一格更便宜的：只做 Joint Geometric Optimization 的消融。在同一个纯重建设定下开关 Lcos​ 与 Lgram​，看射线伪影是否复现。这一格不需要 LLM，且能直接检验论文最主要的扩展贡献是否依赖统一框架——如果在纯重建任务上就能复现同样的伪影抑制，那这项贡献与"统一世界模型"这个 framing 其实是正交的。

§ 11 — 最强反例设计 ​

论文把"生成任务帮助理解任务"当作统一框架的核心收益之一，但表 VI 的数据其实不支持这个方向的因果：单任务理解专才 CIDEr 0.726，联合训练后是 0.720，略有下降；生成侧单任务 1.434，联合后 1.436，基本持平。真正被证明的只有"分离式统一（1.634 / 0.703）比深度交互差"，也就是说，深度交互修好的是分离式统一自己造成的损失，而不是超越了两个独立专才。

据此设计最强反例：训练一个参数量相当的双专才系统（一个纯理解 VLM，一个纯生成模型），推理时简单地把理解模型的文本输出作为条件喂给生成模型，两者不共享任何参数。在同一 25% 数据设定下比较三者。如果这个朴素级联在 3 秒 CD 与 CIDEr 上都不输于 HERMES++，那么"统一"带来的就只有参数效率，而非论文声称的"语义引导几何演化、几何为语言提供物理接地"的协同。论文的 Textual Injection 消融（1.542 → 1.506）也支持这个反例的可能性：文本条件带来的增益只有 0.036，远小于 Ego Modulation 的 0.064 和 Link 本身的 0.835，暗示几何预测的主要驱动力是运动学而非语义。

另一类可预测的失败：world queries 由 max pooling 从 BEV 初始化，而 max pooling 在 BEV 网格上只保留最显著响应。在存在多个同等重要的动态目标（例如密集路口）时，n=4 个 query 能否分别承载它们是可疑的。论文的 query 数消融显示 n=1 到 n=8 之间 3 秒 CD 只在 1.419 到 1.436 之间波动，n=1 甚至略优于 n=4——这与"query 作为语义—几何桥梁"的叙事不太一致，更像是 query 主要起了一个全局条件向量的作用。用密集交通场景做分层评测（按场景内动态目标数分组报 CD）可以直接检验这一点。

§ 12 — Follow-up Research Idea ​

驱动局限：HERMES++ 的未来预测是一次性并行解码的——Δt 组 world queries 同时生成，Current-to-Future Link 一次前向输出 0 到 3 秒的所有 BEV。这意味着模型学到的是从当前观测到未来轨迹的一个确定性映射，没有任何机制表达"未来是多模态的"。而驾驶场景的本质困难恰恰在这里：前车可能刹车也可能加速，行人可能停也可能走。论文报的 Chamfer Distance 是对单一确定性预测的度量，这个指标会系统性地奖励输出所有可能未来的平均值。

新 framing：不要问"未来的几何长什么样"，而问"哪些未来是这段文本描述所允许的"。语言在这里有一个尚未被利用的独特能力——它是描述未来分布而非未来实例的天然接口。"前车可能突然变道"是一句合法的自然语言，但它不对应任何单一点云。可借鉴的相邻领域工具是条件生成里的 classifier-free guidance 与 RL 里的 counterfactual reasoning：把文本从"当前场景的描述"改造成"未来分支的选择器"，训练时用同一段历史配多条真实的后续轨迹（nuScenes 里可以通过对相似初始状态做检索来构造），让模型学会在不同文本条件下生成不同的未来。

第一个实验：在 nuScenes 上挑出初始 BEV 状态相近但后续 3 秒轨迹分歧显著的场景对，为每条轨迹自动生成一句区分性描述（如"前车减速"对"前车保持速度"）。训练一个只改条件方式的 HERMES++ 变体，评测两个新指标：给定正确描述时的 CD，以及给定错误描述时的 CD 上升幅度。如果后者接近零，说明当前架构里的 Textual Injection 实际上被几何路径旁路了，文本从未真正参与几何决策——这会把论文"语义引导几何演化"的核心 claim 从"已验证"降级为"待验证"，同时给出一条让语言在世界模型里承担实质角色的可行路径。
