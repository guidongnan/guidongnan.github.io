Diffusion-RPO: Aligning Diffusion Models through Relative Preference Optimization ​

项内容
arXiv2406.06382
提交日期2024-06-10（仅 v1，abs 页未标注会议接收信息）
作者Yi Gu, Zhendong Wang, Yueqin Yin, Yujia Xie, Mingyuan Zhou（UT Austin / Microsoft Azure AI）
分类cs.CV, cs.CL, cs.LG
一句话把 LLM 上的 RPO 搬到扩散模型：不只拿同 prompt 的 win-lose 对比较，而是用 CLIP 多模态嵌入距离给 mini-batch 里所有 win-lose 组合加权做对比，并另造一个用风格迁移数据算 FID 的"风格对齐"任务来替代昂贵且不可复现的人工评测。

所属教程：后训练与强化学习

版本与表格口径

本文按 v1（2024-06-10）HTML 全文撰写，该 arXiv 条目至今只有这一个版本。两处表格口径需要说明：(a) Table 1 与 Table 4 的列头在 HTML 渲染中为空，列序由正文文字"achieves 28.658 HPSV2 score and 23.208 Pick Score"与表内数值反查确定为 HPS / PickScore / Aesthetics / CLIP / ImageReward；(b) Table 2（风格对齐 FID）按模型分成左右两组、每组三种风格，但 HTML 渲染中未保留"哪一组是 SD1.5、哪一组是 SDXL"的表头，下文按"第一组 / 第二组"引用，不臆测对应关系。

§ 1 — 研究问题与重要性 ​

Diffusion-DPO 把 DPO 搬到文生图上，做法是拿同一个 prompt 下的一对图（一胜一负）做对比学习。这个设定有一个隐含的限制：只有共享同一个 prompt 的两张图才能互相比较。一个 batch 里如果有 M 对偏好数据，实际参与对比的只有 M 组，剩下的 M2−M 种跨 prompt 组合全部被浪费。

RPO（Yin et al. 2024）在 LLM 上指出了这一点：人的学习不只来自"同一个问题的对与错"，也来自"相似问题的失败"。它把 mini-batch 里所有 chosen-rejected 组合都纳入对比，按 prompt 相似度加权。本文要做的就是把这个想法搬到扩散模型上。

搬过来有两个具体的技术障碍。第一，最终图像的对数密度在扩散模型里是隐式的——πθ​(y0​∣x) 需要把所有中间步积分掉，实际不可算。第二，T2I 是多模态的：RPO 的加权靠的是 prompt 之间的文本嵌入相似度，而这里一条数据是"prompt + 图"，怎么度量两条多模态数据之间的距离没有现成答案。

论文还提出了第二个独立的问题：当前的偏好对齐评测本身不可靠。人工评测（Diffusion-DPO 用 Amazon Mechanical Turk）成本高且因偏好的主观性而难以复现；自动评测则有两个坑。其一，T2I 模型的预训练数据本来就是朝人类偏好筛过的，模型已经隐式对齐过了，所以偏好学习带来的分数变化幅度很小，很难判断一个算法是不是真的有效。其二，SFT 的表现完全取决于基座模型与偏好数据的相对质量——如果偏好数据的图比模型自己生成的好，SFT 会大幅涨分；反之会掉分。这让自动评测的结论不稳定。

§ 2 — 前人工作与不足 ​

RLHF 路线（DDPO、DRaFT、DPOK、AlignProp、ReFL）：先训 reward 模型再最大化 reward。论文的批评是两条：训一个真正反映人类偏好的 reward 模型既困难又昂贵；过度优化 reward 会导致明显的模型坍缩。

Diffusion-DPO：跳过显式 reward 模型，直接在偏好对上做对比。附录 B.2 完整复述了它的推导——在扩散路径上定义 reward R(x,y0:T​)，把 RLHF 目标写成最大化边缘化图像 reward 减去 KL 约束，经过近似后化简成一个关于去噪 MSE 差的形式。本文对它的批评落在一处：它被限制在共享同一 prompt 的图像对上。

RPO（Yin et al. 2024）：LLM 上的相对偏好优化，用 ωij​=ω~ij​/∑j′​ω~ij′​、ω~ij​=exp(−cos(f(xw,i​),f(xl,j​))/τ) 给 batch 内所有组合加权，f 是文本编码器。本文是它在扩散模型上的移植。

ORPO / Diffusion-ORPO：附录 C 讨论了另一条线——ORPO 把 SFT 项与 odds ratio 项合成一个损失，好处是不需要 SFT 预热、也不需要 reference model。HuggingFace 已经有把它扩展到图像偏好学习的实现，但那份实现用 DDPM 的去噪 MSE 做了一个粗糙的对数概率近似。

§ 3 — 重建作者的思考路径 ​

第一步是识别"为什么 Diffusion-DPO 只能比较同 prompt 的图"。答案在损失的形式里：DPO 的对数比 logπθ​(yw​∣x)/πref​(yw​∣x) 与 logπθ​(yl​∣x)/πref​(yl​∣x) 共享同一个条件 x，所以两项必须来自同一个 prompt。RPO 的破解方式是允许两项来自不同 prompt，但给这一组合配一个反映"这两个 prompt 有多相似"的权重。

第二步是处理隐式密度。既然 πθ​(y0​∣x) 不可算，那就不要在 t=0 上定义偏好，而在每一步转移上定义。用 r(ytw​∣yt+1w​)=βlogπθ​(ytw​∣yt+1w​)/πref​(ytw​∣yt+1w​) 作为逐步 reward，损失就只涉及单步转移概率，而单步转移在 DDPM 参数化下是高斯的、有闭式。

第三步是从离线数据里造出 yt​ 与 yt+1​。数据集给的只有 (y0w​,y0l​,x)。前向过程允许直接采任意时刻的 yt+1​；yt​ 则从后验 q(yt​∣yt+1​,y0​) 采，或者干脆用后验均值近似。

第四步是多模态权重。RPO 用文本编码器算 prompt 相似度，这里要同时考虑 prompt 与图。CLIP 恰好把两者投到同一空间，所以直接用 CLIP 编码 (y,x) 对。

第五步是评测。作者意识到在"模型已经隐式对齐过"的任务上做增量对比，信噪比太低，于是造了一个人为拉大领域差距的下游任务：风格对齐。刻意选择与 Pick-a-Pic V2 视觉上迥异的风格（梵高、素描、冬季），这样预训练与下游任务之间的差距足够大，方法之间的差异才显得出来，而且用 FID 度量、完全可复现。

§ 4 — 核心 Intuition ​

一个 mini-batch 里的 M 对偏好数据其实携带 M2 组可比信息，Diffusion-DPO 只用了对角线上那 M 组。跨 prompt 的对比并非无意义——一张"胜"图与另一个 prompt 下的"负"图之间的对比，能让模型学到超越具体内容的、关于色彩、光照与构图的普遍规律。要用上这些非对角信息，只需要给每一组配一个权重，衡量这两条多模态数据有多相关；CLIP 把 prompt 和图投到同一空间，正好提供了这个度量。

§ 5 — 具体方法与完整 Pipeline ​

逐步 reward 与逐步 RPO 损失。定义

r(ytw​∣yt+1w​)=βlogπref​(ytw​∣yt+1w​)πθ​(ytw​∣yt+1w​)​

第 t 步的损失是

LDiffusion-RPO,t​(θ)=ωi,j​logσ(βlogπref​(yt,iw​∣yt+1,iw​)πθ​(yt,iw​∣yt+1,iw​)​−βlogπref​(yt,jl​∣yt+1,jl​)πθ​(yt,jl​∣yt+1,jl​)​)

这里有一处与原始 RPO 的明确偏离，作者写在正文里：嵌入距离权重 ωi,j​ 被放在 logσ 之外，而 Yin et al. 是放在里面（见附录 B.3 的 RPO 原式，logσ(ωij​×β(⋯))）。理由只有一句"我们观察到这个修改后的形式经验表现更好"，论文没有提供任何消融来支撑这一句。这个差别不是形式上的：放在外面等于给每个组合的损失项加权（一个凸组合），放在里面等于缩放 logit（改变 sigmoid 的饱和位置）。

对所有时间步取期望，用常数的时间步重加权因子 λ(t)（沿用 DDPM 与 Diffusion-DPO 的做法），t∼U[1,T−1]。

多模态嵌入距离权重。给定两个"图-prompt"对 (y,x) 与 (y′,x′) 以及编码器 f，

ω~=exp(τ−cos(f(y,x),f(y′,x′))​),cos(a,b)=1−∥a∥2​∥b∥2​aTb​

注意这里的 cos(⋅,⋅) 被定义成余弦距离而非相似度。τ 越小，权重越集中在语义与视觉上非常接近的对上；τ 越大，权重越均匀。在成对偏好数据 D=(yw,yl,x) 与 batch 大小 M 下，构造 W~∈RM×M，ω~i,j​ 度量第 i 个胜对与第 j 个负对的接近程度，然后按行归一化使每行和为 1。对角元对应同 prompt 的偏好对，非对角元是 batch 内跨 prompt 的对比。

从离线数据造扩散链。前向过程给出 yt+1​=αˉt​​y0​+1−αˉt​​ϵt+1​，直接采。yt​ 从后验 q(yt​∣yt+1​,y0​) 采；为简化，作者用后验均值近似 yt​≈αt+1​​αt​​​(yt+1​−1−αˉt+1​​βt+1​​ϵt+1​)。代进 DDPM 的高斯参数化后，整个对数概率化简为一个 ϵ 预测的平方误差，最终损失变成

LDiffusion-RPO​(θ)=−E[ωi,j​logσ(−21​β(∥ϵθ​(yt+1,iw​,t)−ϵw∥22​−∥ϵref​(yt+1,iw​,t)−ϵw∥22​−(∥ϵθ​(yt+1,jl​,t)−ϵl∥22​−∥ϵref​(yt+1,jl​,t)−ϵl∥22​)))]

也就是四个去噪 MSE 的组合，实现上非常轻。

风格对齐数据集。三个数据集（Van Gogh、Sketch、Winter），每个 10,000 对，从 Pick-a-Pic V2 的子集构造。构造方式：对每一对图，随机挑一张标为 rejected，再用图像编辑模型做风格迁移——Sketch 与 Winter 用 Prompt Diffusion，Van Gogh 用 InstructPix2Pix——迁移后的新图标为 preferred。格式与 Pick-a-Pic V2 一致：(yw,yl,x)。作者还手工删掉了 Pick-a-Pic V2 里的不当 prompt，做了一个内容更安全的版本。

实现细节。基于 Diffusion-DPO 的代码库；CLIP 算多模态嵌入。人类偏好对齐用单阶段微调，SFT 与 RPO 各 2000 步；Diffusion-DPO 直接用官方 checkpoint。风格对齐既做单阶段，也做两阶段（先 SFT 再做偏好优化），后者的动机是 T2I 预训练与风格任务之间存在领域差距。全部实验 β=5000；SD1.5 用 AdamW、SDXL 用 AdaFactor；人类偏好对齐的 lr 为 β2000​⋅2.048×10−8；8 张 A100；SD1.5 每卡 batch 16、梯度累积 4，SDXL 每卡 batch 8、梯度累积 8。

§ 6 — 核心数学推导 ​

附录 A 的推导本身是标准的 DDPM 代数，值得展开的是它的一个结构性结论。

从逐步损失出发，把 πθ​(yt∗​∣yt+1∗​) 按 DDPM 的高斯形式写开。如果 yt∗​ 是从 q(yt∗​∣yt+1∗​,y0∗​) 真采出来的（含重参数噪声 ϵt∗​），对数概率是

logπθ​(yt∗​∣yt+1∗​)=−2βt+1​(1−αˉt​)αt+1​​αt​​​​ϵθ​(yt+1∗​,t+1)−ϵt+1∗​+σt+1​ϵt∗​​22​+const

如果改用后验均值近似（不注入 ϵt∗​），那一项就消失了：

logπθ​(E[yt∗​∣yt+1∗​,y0∗​]∣yt+1∗​)=−2βt+1​(1−αˉt​)αt+1​​αt​​​​ϵθ​(yt+1∗​,t+1)−ϵt+1∗​​22​+const

两者的差别是一项方差为 σt+12​ 的噪声。因为常数项 −2d​log2π−dlogσt+1​ 在 πθ​ 与 πref​ 之间相消，最终损失只剩 MSE 差——这就是为什么形式上它与 Diffusion-DPO 的损失几乎一样。Diffusion-RPO 与 Diffusion-DPO 的全部差别，归结为损失外面多了一个 ωi,j​、以及 i 与 j 被允许不相等。

作者还给了一个有意思的重新解读：这个损失与 conditional transport 同构。ωij​（行和为 1）可以看作"以第 i 个胜出对为起点、运输到第 j 个失败对的概率"，而经 logσ(⋅) 变换的 (i,j) 项是运输代价。于是整个目标变成：在 CLIP 隐空间里，最大化从胜出对运输到那些语义相关的失败对的代价，等价于压低采样出与胜出对语义接近的失败图的概率。作者明说这个视角可能允许进一步改进（修改运输概率与点对点代价的定义），但把它留给了未来工作。

§ 7 — 实验设计与结论 ​

问题一：人类偏好对齐上比 Diffusion-DPO 好吗？ Table 1（列序 HPS / PickScore / Aesthetics / CLIP / ImageReward）。

SDXL、HPSv2 测试 prompt：Base 27.900 / 22.694 / 6.135 / 0.375 / 0.808；SFT 27.555 / 22.069 / 5.847 / 0.373 / 0.692；DPO 28.082 / 23.159 / 6.139 / 0.383 / 1.049；RPO 28.658 / 23.208 / 6.163 / 0.383 / 1.046。SDXL、Parti-Prompt：Base 27.721 / 22.562 / 5.766 / 0.357 / 0.668；SFT 27.081 / 21.657 / 5.536 / 0.358 / 0.545；DPO 27.637 / 22.894 / 5.806 / 0.370 / 1.032；RPO 28.456 / 22.980 / 5.872 / 0.367 / 1.077。

诚实地读这两块：RPO 在 HPS、PickScore、Aesthetics 上稳定领先 DPO，但 CLIP 上从未赢过（一处打平 0.383、一处落后 0.370 vs 0.367），ImageReward 在 HPSv2 prompt 上也是 DPO 略高（1.049 vs 1.046）。另外 SFT 在 SDXL 上全面拉低性能，作者的解释是 Pick-a-Pic 的图（来自 SDXL-beta 与 Dreamlike）质量不如 SDXL-1.0 自己生成的。

SD1.5、HPSv2 prompt：Base 26.931 / 20.948 / 5.554 / 0.345 / 0.083；SFT 27.882 / 21.499 / 5.817 / 0.353 / 0.683；DPO 27.233 / 21.396 / 5.679 / 0.352 / 0.296；RPO 27.373 / 21.425 / 5.694 / 0.351 / 0.342。SD1.5、Parti-Prompt：Base 26.704 / 21.375 / 5.330 / 0.332 / 0.159；SFT 27.402 / 21.681 / 5.534 / 0.339 / 0.561；DPO 26.934 / 21.626 / 5.405 / 0.339 / 0.321；RPO 27.046 / 21.663 / 5.432 / 0.340 / 0.392。

这里最重要的事实是：在 SD1.5 上，普通 SFT 在全部五个指标上都打败了 RPO（27.882 vs 27.373、21.499 vs 21.425、5.817 vs 5.694、0.353 vs 0.351、0.683 vs 0.342）。作者没有掩盖这一点，并给出了与 SDXL 相反方向的同一解释：Pick-a-Pic 的图质量高于原始 SD1.5，所以直接监督微调就很有效。这个解释是自洽的，但它同时说明五个自动指标对"偏好学习算法好不好"这件事的分辨力有限——一个不做任何偏好建模的基线就能赢。

胜率评测（附录 D，每 prompt 生成 5 张取 reward 中位数）进一步印证：SD1.5 上 RPO 对 SFT 的胜率在 PickScore 上只有 32.22（HPSv2 prompt）与 33.58（Parti），也就是大比分落后；RPO 对 DPO 在 CLIP 上的胜率四处分别是 49.63 / 48.96 / 49.63 / 48.35，全部低于 50。SDXL 上 RPO 对 SFT 则大幅领先（PickScore 胜率 95.94 与 95.10）。

问题二：风格对齐上呢？ Table 2 报 FID（生成图 vs 训练集里的风格迁移图，用同一批训练 prompt 生成）。单阶段：SFT 第一组 15.34 / 20.56 / 16.31、第二组 28.15 / 16.41 / 21.74；DPO 第一组 91.8 / 34.67 / 63.43、第二组 152.35 / 137.07 / 99.37；RPO 第一组 42.24 / 29.36 / 33.29、第二组 97.57 / 59.75 / 85.54。两阶段：SFT+SFT 第一组 14.73 / 19.89 / 16.06、第二组 22.71 / 30.48 / 30.78；SFT+DPO 第一组 47.47 / 24.92 / 26.26、第二组 25.62 / 23.32 / 20.02；SFT+RPO 第一组 13.25 / 17.54 / 14.50、第二组 17.95 / 15.96 / 15.75。

结论分两层。单阶段下 SFT 压倒性地好（15.34 对 RPO 的 42.24 对 DPO 的 91.8），偏好学习方法在有大领域差距时根本跟不上；作者对此直言不讳。只有加了 SFT 预热之后，RPO 才在全部 6 个格子上最好。这实际上意味着风格对齐这个"新任务"验证的是"SFT 之后再做偏好优化"这个组合，而不是偏好优化本身。定性上作者指出 DPO 在 Van Gogh 上会学错风格（背景加过多绿色）、在 Winter 上被雪花淹没主体细节、在 Sketch 上生成不像铅笔素描的背景与黑块；SFT 学得到细节但学不好风格尤其是背景。

问题三：温度 τ 怎么选？ 消融（SD1.5 做人类偏好对齐、SFT-SD1.5 做 Van Gogh 风格对齐），五档 τ 由小到大：HPS 27.373 / 27.286 / 27.245 / 27.176 / 27.205；PickScore 21.425 / 21.448 / 21.417 / 21.366 / 21.421；Aesthetics 5.694 / 5.696 / 5.671 / 5.733 / 5.657；CLIP 0.351 / 0.352 / 0.353 / 0.353 / 0.352；ImageReward 0.342 / 0.335 / 0.320 / 0.270 / 0.316；风格对齐 FID 31.96 / 16.26 / 13.66 / 13.82 / 13.25。

这张表是全文信息量最大的一张。人类偏好那五行的全部变化幅度都很小：HPS 在 27.176–27.373 之间（0.197），PickScore 在 21.366–21.448 之间（0.082），Aesthetics 在 5.657–5.733 之间，CLIP 在 0.351–0.353 之间。而风格对齐 FID 从 31.96 变到 13.25，变化了 2.4 倍。更关键的是方向相反：论文为人类偏好选的 τ=0.01（最左一列）恰好是风格对齐里 FID 最差的那一档（31.96）。作者对此的解释是两个任务性质不同——人类偏好对齐需要低温度聚焦在相关的图-prompt 对上以改进 prompt 相关的细节；风格对齐的挑战是学到整体风格，任何一对偏好数据都携带风格信息，所以高温度下更均匀的权重更好。这个解释合理，但它同时说明没有一个 τ 能同时服务两个任务，方法必须逐任务调参。

问题四：能不能不要 reference model 与 SFT 预热？ 附录 C 提出 Diffusion-ORRPO（ORPO + RPO 加权）。SDXL 上 λ=0.2,τ=0.01 得到 28.660 HPSv2 与 22.827 PickScore，高于最好的 Diffusion-ORPO（λ=0.005）的 28.084 与 22.037。但要与正文对照着读：Diffusion-RPO 本身在同一测试集上是 28.658 / 23.208——ORRPO 的 HPSv2 只高 0.002，PickScore 反而低了 0.381。作者也报告了阴性结果：ORPO 与 ORRPO 都无法在没有 SFT 预热与 reference model 的情况下弥合风格对齐的领域差距，在部分 prompt 上成功、在另一些上失败。

§ 8 — Take-aways ​

5 句话版：Diffusion-DPO 只利用了 mini-batch 里对角线上的 M 组同 prompt 对比，浪费了 M2−M 组跨 prompt 信息。Diffusion-RPO 把 RPO 的相对偏好思想移植过来，用逐步 reward 绕开扩散模型隐式对数密度的问题，用 CLIP 编码的图-prompt 联合嵌入距离给所有组合加权（行归一化），最终损失化简成四个去噪 MSE 的组合，实现上几乎就是给 Diffusion-DPO 的损失加一个权重矩阵并放开下标。作者另提出"风格对齐"任务——用 Prompt Diffusion 与 InstructPix2Pix 对 Pick-a-Pic V2 的图做风格迁移构造 3×10,000 对偏好数据，用 FID 度量——以替代昂贵且不可复现的人工评测。在 SDXL 上 RPO 在 HPSv2、PickScore、Aesthetics 上稳定优于 Diffusion-DPO（HPSv2 benchmark 上 28.658 / 23.208 / 6.163），但在 CLIP 上从未领先；在 SD1.5 上普通 SFT 在全部五个指标上都优于 RPO。风格对齐必须先做 SFT 预热，RPO 才能在 6 个设定上全部最好；单阶段时 SFT 大幅领先所有偏好方法。

3 句话版：把偏好对比从"同 prompt 的一对"放开到"batch 内所有 win-lose 组合并按多模态相似度加权"，能在 SDXL 上稳定小幅超过 Diffusion-DPO。但方法的收益高度依赖温度 τ，而人类偏好对齐与风格对齐这两个任务需要的 τ 方向相反。更值得注意的是，在 SD1.5 与单阶段风格对齐这两个设定下，不做任何偏好建模的 SFT 就能赢过所有偏好优化方法。

1 句话版：给 Diffusion-DPO 的损失加一个 CLIP 相似度权重矩阵、放开跨 prompt 的对比，并用风格迁移数据的 FID 造一个可复现的对齐评测任务。

§ 9 — 最脆弱的假设 ​

失败代价最大的假设藏在评测这一半，而不是方法这一半："风格对齐"任务能作为图像偏好学习方法的可靠代理评测。

论文把它当作核心贡献之一（三个贡献里的第二条），并用它论证 RPO 优于 DPO（两阶段 6 个格子全胜）。但这个任务的构造方式让它测的东西与"偏好学习"关系不大。看构造流程：从 Pick-a-Pic V2 取一对图 → 随机挑一张标为 rejected → 用 Prompt Diffusion 或 InstructPix2Pix 把它风格迁移 → 迁移结果标为 preferred。于是：

第一，偏好标签里没有任何人类判断。"胜"仅仅意味着"被某个编辑模型处理过"。原始 Pick-a-Pic 的人类偏好标签被完全丢弃了（因为是随机挑一张作 rejected）。

第二，评测指标与训练目标同源。FID 是拿生成图去比"训练集里那些风格迁移图"，用的还是同一批训练 prompt。所以这个任务度量的是"模型多大程度上模仿了 InstructPix2Pix / Prompt Diffusion 在这批 prompt 上的输出分布"——本质上是一个蒸馏保真度的度量，不是偏好对齐的度量。

第三，SFT 在单阶段设定下大幅领先这件事，正是上面两点的直接推论：如果任务本质是模仿一个确定性编辑算子的输出，那么直接在输出上做监督微调当然最有效（第一组 15.34 vs RPO 42.24 vs DPO 91.8）。论文把这解释为"领域差距"，但更简约的解释是任务本身就是监督学习任务。

这个假设一旦不成立，"RPO 在风格对齐上优于 DPO"就不能推广为"RPO 在偏好对齐上优于 DPO"，而人类偏好那一半的证据又相当薄弱——SD1.5 上输给 SFT、CLIP 指标上从未赢过 DPO、SDXL 上的领先幅度在 0.05 到 0.8 之间且没有报告任何方差或多种子结果。

论文为风格对齐提供的最强辩护是它解决了人工评测的成本与可复现性问题，这一点是成立且有价值的。缺的证据是构造效度：没有做任何实验说明风格对齐 FID 的排名与人类偏好的排名相关。这个验证本可以很便宜地做——只要在同一批模型上同时报风格 FID 与一次小规模人工评测，看排名是否一致。

第二处脆弱是方法侧的：把权重 ωi,j​ 放在 logσ 之外这个偏离原始 RPO 的关键设计，论文只给了一句"经验上更好"，没有任何消融。而这个位置差别会改变损失的性质——放在外面是对损失项做凸组合，放在里面是缩放 logit。考虑到 RPO 在 SDXL 上相对 DPO 的优势本来就只有零点几个点，这个未被验证的设计选择可能承担了相当大一部分差异。

§ 10 — 最小复现实验 ​

一周内可做，目标是检验 §9 的第一个疑问——风格对齐 FID 到底测的是什么。

数据与模型：SD1.5；作者公开的三个风格对齐数据集（若未发布则按论文描述用 InstructPix2Pix 在 Pick-a-Pic V2 子集上自建 Van Gogh 一个风格即可，10,000 对）；Diffusion-DPO 的公开 checkpoint。

实现：训练四个模型，前三个复现论文（SFT、SFT+DPO、SFT+RPO），第四个是关键的平凡基线——直接把 preferred 图当作训练数据做标准的扩散微调，完全不看 rejected 图、不做任何成对建模。这就是"把它当纯粹的蒸馏任务来做"。

测量：四个模型在同一批训练 prompt 上生成图，算对 preferred 训练图的 FID；同时算一个留出 prompt 上的 FID（用一批没参与训练的 Pick-a-Pic prompt，风格迁移后作为参考）。

判据：如果那个"只用 preferred 图做蒸馏"的平凡基线在训练 prompt FID 上接近甚至超过 SFT+RPO 的 13.25，就说明这个任务不需要偏好信号，风格对齐作为偏好学习评测的构造效度不成立。留出 prompt 上的 FID 则回答另一个问题：这些方法学到的是可泛化的风格，还是对这批 prompt 的过拟合。论文只报了训练 prompt 上的 FID，这个留出评测是它缺失的最重要一环。

附带的低成本检验：把权重放在 logσ 内外各训一个 SD1.5 模型（其余完全相同），报五个自动指标。论文声称的经验优势如果在这个对照下消失，那么 RPO 相对 DPO 的领先就需要重新归因。

§ 11 — 最强反例设计 ​

最有力的攻击是给"跨 prompt 对比带来收益"提供一个不需要跨 prompt 的替代解释。

观察 §6 的推导结论：Diffusion-RPO 的损失就是 Diffusion-DPO 的损失外面乘一个行归一化的权重 ωi,j​、并放开下标 i=j。这意味着相对 DPO 有两处变化同时发生：(1) 引入了非对角项；(2) 即使只看对角项，每一项也被乘上了一个 ωi,i​，也就是同 prompt 的样本也被重新加权了。行归一化保证每行和为 1，所以 ωi,i​ 的大小取决于该样本与 batch 内其他样本的相似度分布——一个"独特"的样本会得到更大的自权重。这实际上是一种隐式的样本重加权/难例挖掘，完全不依赖跨 prompt 对比的任何"学到普遍规律"的机制。

区分实验：训练一个消融版本，只保留对角项但保留 ωi,i​ 加权（即把非对角权重强制置零后重新归一化会退化成 DPO，所以正确做法是保留原始归一化算出的 ωi,i​ 作为对角项系数、丢弃非对角项）。如果这个版本就能拿到 RPO 在 SDXL 上的大部分增益（28.658 中相对 DPO 的 28.082 那 0.576），那么"利用跨 prompt 信息"这个 framing 就是错的，真正起作用的是样本重加权。这个实验只需要改几行代码，而论文没有做——考虑到跨 prompt 对比是本文的全部立意，这是一个相当致命的缺口。

第二种攻击是可预测的失效条件。ω 的定义是 batch 内的行归一化，所以它依赖 batch 组成。论文的设定是 8 张 A100、SD1.5 每卡 batch 16、梯度累积 4——如果权重是在每卡的局部 batch 内计算的，那么 M=16，非对角项只有 240 个而且它们的内容取决于数据加载顺序。可以直接构造反例：把数据按 prompt 语义聚类后排序，让同一个 batch 里全是高度相似的 prompt；再构造另一个极端，让每个 batch 里的 prompt 尽可能不相似。如果两种排序下 RPO 的结果差异，超过它相对 DPO 的领先幅度（SDXL 上 0.05 到 0.8），那么论文报告的增益就落在实验配置噪声内。论文全文没有报告任何随机种子重复或方差，这个检验因此格外必要。

第三，一个针对整体叙事的直接质疑：论文摘要说 RPO "outperforms established methods such as Supervised Fine-Tuning and Diffusion-DPO"。但论文自己的 Table 1 显示，在 SD1.5 的两个 prompt 集上，SFT 在全部十个格子里都优于 RPO，附录 D 的胜率表里 RPO 对 SFT 的 PickScore 胜率只有 32.22 与 33.58。作者在正文里如实描述了这一现象并给了解释，但摘要的措辞与表格并不一致。任何引用这篇工作的人都应该把结论限定为"在 SDXL 上、以及在 SFT 预热后的风格对齐上"。

§ 12 — Follow-up Research Idea ​

驱动它的局限：本文最有价值的部分其实是它无意中暴露的那张温度消融表——同一个方法，同一个超参，两个任务需要的方向完全相反（人类偏好要 τ=0.01，风格对齐要最大的 τ，而 τ=0.01 恰好是风格 FID 最差的 31.96）。这不是一个调参问题，而是说明"用一个全局标量温度去控制整个 batch 的对比结构"这个设计本身太粗糙。同一个 batch 里不同的 (i,j) 组合，其有用性可能差别巨大：有些跨 prompt 对比携带风格信息，有些只是噪声。

新的 framing：把 ωi,j​ 从"一个由 CLIP 距离与全局温度决定的固定函数"变成一个被学习的、结构化的量。作者自己给出了通往这个方向的钥匙——§6 里那个 conditional transport 的解读：ωij​ 是运输概率，logσ(⋅) 是运输代价。他们明说"这个视角可能允许通过修改运输概率与点对点代价的定义来进一步改进，我们把它留给未来研究"。这个 follow-up 就是把这句话做实：不用手工设计的指数核，而是求解一个真正的熵正则化最优传输问题来得到 ω，其中传输代价由任务目标反向决定。这样 τ 从一个需要逐任务手调的全局常数，变成熵正则项的强度，而传输计划本身会自适应地在"聚焦相似对"与"均匀覆盖"之间找到位置。

可借鉴的相邻领域工具：Sinkhorn 算法能在 M×M 的代价矩阵上高效求熵正则化 OT，M 是 batch 大小（16 或 8），成本可以忽略。域适应领域的 prototype-oriented OT 框架（论文引用的 Tanwisuth et al.）已经给出了在深度网络里嵌入 OT 的成熟做法。此外，对比学习里的 hard negative mining 提供了另一条参照：如何在"太相似"（无梯度）与"太不同"（噪声）之间选择负例，已经有大量经验规律。

第一个实验长什么样：在 SD1.5 上做三方对比，全部用同一批 Pick-a-Pic V2 数据与同样的 2000 步预算：(a) 原始 Diffusion-RPO，τ 取论文的 0.01；(b) 原始 Diffusion-RPO，τ 取风格任务上最好的那一档；(c) Sinkhorn 版本，熵正则强度固定，不逐任务调。三个模型都在两个任务上同时评——人类偏好的五个自动指标，以及 Van Gogh 风格对齐 FID。判据很清晰：如果 (c) 能在两个任务上分别接近 (a) 和 (b) 各自的最好成绩，就证明自适应传输计划确实解决了"一个温度服务不了两个任务"的问题。必须报告的平凡基线是 (d)：把 ω 直接设成均匀分布（1/M），也就是完全不用 CLIP 相似度。考虑到论文温度消融里人类偏好那五行的总变化幅度只有 0.08 到 0.2，这个均匀基线很可能与 (a) 难分伯仲——如果真是这样，那么"多模态相似度加权"这个核心组件的价值就需要从头论证，而这本身就是一个值得发表的阴性结果。
