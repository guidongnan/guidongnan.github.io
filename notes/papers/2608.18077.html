Hydra-0: Action Flow for Generalist World Modeling and Control ​

项内容
arXiv2608.18077
提交日期2026-08-18（仅 v1；comments 只给了 project page）
作者Hongyu Li, Bowen Wen, Xinghao Zhu, Yixuan Wang, Yilun Du, Yunzhu Li, George Konidaris, Stan Birchfield, Soha Pouya, Chenran Li, Yan Chang（NVIDIA，部分作者兼 Brown / Columbia / Harvard）
分类cs.RO
一句话把机器人指令先在 Isaac Lab 里跑一遍控制器与物理，再用机器人几何与相机标定把可见表面点投影成图像平面轨迹（action flow），以这套像素级运动作为跨本体、跨任务、跨视频骨干的共享条件接口，并把同一接口反过来用：只给期望的物体流，让世界模型生成兼容的机器人运动。

所属教程：从视频生成到世界动作模型

§ 1 — 研究问题与重要性 ​

想要一个能给很多机器人共用的预测式模拟器，最直接的障碍是动作怎么表示。绝大多数动作条件视频模型直接吃机器人原生指令：关节空间指令把机器人结构编码进去了，末端空间指令在不同运动学的机器人上会产生完全不同的关节轨迹和可见连杆运动。两种表示都不指定"图像平面上会看到什么运动"，于是视频模型必须为每个本体重新学一遍"指令 → 视觉动力学"的映射。

结果是尽管数据体量已经很大（DROID、Open X-Embodiment 一类），可迁移的基础世界模型仍然稀缺：模型被绑在训练本体上，多本体联合训练与新部署环境的迁移都做不动。

Hydra-0 提出的答案是把动作表示搬到观测坐标系里。action flow 是一组可见机器人表面点或物体点在图像平面上的稀疏轨迹，同一套格式既能描述机械臂、夹爪，也能描述人手，不需要向视频模型暴露各自的原生动作空间。这个选择的价值在于它把异构训练数据（机器人遥操作、手持夹爪、第一人称人手视频）统一到一个接口上，同时保留了运动学约束——因为轨迹是从一条可执行指令经过控制器与物理仿真推出来的，不是凭空画的。

§ 2 — 前人工作与不足 ​

动作条件世界模型：Dreamer 一类学紧凑潜在动力学做规划，DINO-WM 预测预训练视觉特征以支持无像素重建的规划；视频生成式世界模型（Cosmos 2.5、Cosmos 3）合成可视检查的未来观测。这些方法的动作接口都是本体相关的，跨本体训练与迁移受限。

运动条件视频生成：Motion Prompting 用稀疏与稠密运动轨迹作为灵活的视频条件；ATI 通过高斯传播把用户指定轨迹注入视频潜变量；Wan-Move（论文称为最近的视觉条件先例）把首帧外观特征沿潜变量轨迹搬运，形成运动感知条件。相邻的二维条件还有 MIMIC 的参考驱动语义掩码、Mask2IV 的执行体与物体掩码轨迹、BridgeV2W 的指令导向本体掩码渲染、OSCAR 的二维运动骨架。

这一族证明了图像平面运动可以做共享视觉条件，但它们留下的缺口很具体：如何把这个共享视觉运动表示接回可执行的机器人指令。用户手画的轨迹不受任何运动学约束，也无法反过来解出动作。Hydra-0 的定位就在这个缺口上：训练时 action flow 可以直接从交互视频里恢复，部署时它从可执行指令经由 Isaac Lab 的控制器-物理 rollout、机器人几何与相机标定推出来，两端都成立。

§ 3 — 重建作者的思考路径 ​

先问一个诊断性问题：为什么动作条件视频模型换个机器人就失效？把因果链拆开会发现，视频模型真正需要知道的从来不是"关节 3 转了 0.2 弧度"，而是"图像里哪些像素会往哪走"。原生指令与这件事之间隔着一层本体相关的映射，这层映射必须被模型学出来，而它每换一个本体就变一次。

顺着这条，解决方案就浮现了：把这层映射从神经网络里搬到已知的几何计算里。机器人的 URDF 和相机标定是已知的，控制器和物理仿真是可跑的。给定一条候选指令，完全可以先在 Isaac Lab 里执行一遍拿到连杆变换序列，再把可见表面点投影到图像平面。这样视频模型收到的条件已经是本体无关的像素运动，不需要再学那层映射。

第二个问题是训练数据。大规模交互数据集常常没有 URDF 或相机标定（DROID 的物体掩码就拿不到）。这就要求同一个表示有第二条构造路径：用光流 tracker 恢复稠密图像平面轨迹与可见性标签，再用 grounded 掩码把轨迹切成"本体"和"被操作物体"两组。两条路径产出同一个 F，训练用视频路径、部署用几何路径。

第三个问题是训练时该喂哪一组轨迹。如果永远喂本体轨迹，模型学到的就只是"跟着机械臂动"；如果永远喂物体轨迹，模型学不到本体的运动学约束。作者的选择是随机采样四种条件模式（Embodiment / Object / All / None），这一步看起来只是数据增广，但它埋下了整篇文章最有意思的性质：因为模型见过"只给物体流"的条件，推理时就可以只给期望物体流，让模型反过来生成兼容的机器人运动。逆向模式不是另设计的模块，是同一接口的另一个用法。

§ 4 — 核心 Intuition ​

视频模型不关心关节角，它只需要知道图像里的哪些点会往哪走。既然机器人几何和相机标定都是已知的，就不该让神经网络去学"指令 → 像素运动"这层本已可算的映射——先用控制器加物理把指令跑一遍，把可见表面点投影成像素轨迹，再拿这套轨迹当条件。做完这一步，机械臂、夹爪和人手在接口上就没有区别了；而且因为条件既描述本体运动也能描述物体运动，把物体那一路单独喂进去，就能让模型倒推出"要让物体这样动，机器人得怎么动"。

§ 5 — 具体方法与完整 Pipeline ​

action flow 的定义。对 N 个跟踪点、H 步预测视界，点 n 在 t 时刻的图像位置记 xn,t​=(un,t​,vn,t​)、可见性记 mn,t​∈{0,1}，共享轨迹条件是 F={τn​}n=1N​，τn​={(xn,t​,mn,t​)}t=0H​。

几何路径（部署用）。在 o0​ 里可见的机器人表面上采点，Isaac Lab 执行候选指令得到状态与连杆变换序列，按

xn,t​=π(K[I3​  0]TCW​Tℓ(n)​(qt​)Xˉn​)

投影。可见性 mn,t​=1 只在投影点相机深度为正、落在图像内、且与渲染深度缓冲在小容差内一致时置位，用 3×3 邻域避免轮廓边界的误剔除。

视频路径（训练用）。用 AllTracker 在 128×128 查询网格上恢复稠密轨迹与可见性，再用 grounded 掩码（SAM 3 精修或文本提示）切成本体与被操作物体两组，不需要特权元数据。

四种条件模式。训练时每步从 {Embodiment, Object, All, None} 中采样一种，标准 I2V 概率是 (0.05,0.40,0.40,0.15)（None / Embodiment / Object / All 依次对应 0.05 / 0.40 / 0.40 / 0.15）。Embodiment 或 Object 模式采 1–128 条轨迹，All 模式在本体、物体与未归类场景轨迹的并集上采 256–1024 条。模式只决定哪些轨迹填进共享运动张量，不生成额外的学习 token。

运动条件的构造。沿用 ATI 的高斯传播与 Wan-Move 的首帧 VAE 特征复制：每条轨迹先在首帧潜变量上双线性采样得到源特征 hn​，再沿时间维按高斯权重传播到未来潜变量网格位置，

Mk​(p​)=n∈NK​(p​,k)∑​wn,k​(p​)hn​,wn,k​=mn,0​mn,k​exp(−β∥p​−xn,k​∥22​),

同时算一个 presence gate gk​=clip[0,1]​(∑n​wn,k​) 告诉骨干哪些位置带有轨迹传播来的外观。实现上 β=220，每个目标格取两条原始权重最大的轨迹。完整运动条件 Cmotion​=(M,g) 与噪声视频潜变量拼接后送进 DiT。

训练。冻结预训练视频骨干，只训 DiT patch embedding 与 q/k/v/o 注意力投影加两个 FFN 投影上的 rank-64 LoRA，用标准 flow-matching 目标。骨干覆盖 Cosmos 2.5、Wan2.2 I2V-A14B 与 TI2V-5B 三种，各自的条件注入适配器不同（Cosmos 用 17 通道侧输入加零初始化 patch 投影；A14B 走 I2V 视觉条件张量并在 MoE 切换点恢复原始条件；TI2V-5B 拼 49 通道侧输入并加宽 DiT 输入投影）。A14B 用 32 张 H100 训五天、40,000 步。

高效 rollout。用 LongLive-2.0 的自回归转换把潜变量序列切成时间块、用 KV cache 复用已生成上下文，Cmotion​ 一次性在整窗坐标里算好、按绝对块偏移切片，避免轨迹在块边界被重新锚定；再用 DMD2 蒸馏出四步学生。

训练语料。七个来源合计 178,187 个 episode、2,201.7 小时，过滤后 1,565,634 个 81 帧窗口（480p / 16 fps，窗口内不重叠）：DROID（单臂，223,075 窗口）、ABC-130k（双臂，1,048,681）、MolmoAct2（双臂，126,335）、EgoDex（人手，89,380）、Deform360（手持夹爪，60,315）、XVLA-Soft-Fold（双臂，17,772）、H1-Fold-Clothes（人形，76）。过滤规则是三条窗口级筛子：90 分位可见轨迹路径长度低于 480p 下 50 像素的静态窗口丢弃、本体轨迹低于同一阈值的冻结夹爪窗口丢弃、语言标注无可执行内容的 DROID episode 丢弃。IWS 任务只用于数据效率评测，不进训练语料。

§ 6 — 核心数学推导 ​

核心公式在 §5 已给全，这里补两处 intuition。

投影式为什么保住了运动学约束。Tℓ(n)​(qt​) 是连杆 ℓ(n) 在配置 qt​ 下的变换，而 qt​ 来自控制器与物理仿真对一条可执行指令的 rollout。这意味着 action flow 的取值空间不是"任意像素轨迹"，而是"该机器人在该相机下物理上能产生的像素轨迹"。这一点是 Hydra-0 与 ATI / Wan-Move 的根本差别：后者的用户手画轨迹可以违反运动学，前者不能。作者也标注了这套构造的敏感度——中等标定误差只是扰动二维运动条件而不改变目标视频，但大的投影误差会破坏空间对应关系。

presence gate 在做什么。Mk​ 是传播来的外观特征的加权和，权重是未归一化的高斯核。如果某个潜变量格附近没有任何有效轨迹，Mk​ 接近零；这时骨干无法区分"这里没有运动"和"这里没有条件"。gk​ 把保留下来的轨迹质量裁剪到 [0,1]，等于显式告诉模型"这个位置的视觉条件是否可信"。要求 mn,0​ 与 mn,k​ 同时为 1，则排除了源点或目标点不可见的轨迹——遮挡进来的时候这条约束很关键。

逆向模式的损失。世界动作模型只喂物体流 Fobj、不给夹爪流，让潜变量动力学去编码兼容的机器人运动，再用一个 action head 从干净的 DiT token 特征读出可执行指令：

LWAM​=Lflow​+λh​(Lact​+Lstate​+λv​Lvel​),

其中 Lact​、Lstate​ 是逐维归一化目标上的 masked Huber 损失，Lvel​ 是预测归一化动作一阶差分与目标一阶差分之间的 masked L1（只在相邻有效动作槽上算），λh​=λv​=0.1。作者强调配对 rollout 不必是专家演示，因为每条都把达成的机器人运动与产生它的动作关联起来了。

§ 7 — 实验设计与结论 ​

问题一：action flow 能不能跨视频骨干迁移？ 在五个留出集（XVLA-Soft-Fold、Deform360、DROID、MolmoAct2、ABC-130k）各 100 个验证 clip 上，用同样的 flow 构造、数据混合与预测视界训 Cosmos 2.5 与两个 Wan2.2 变体，指标是 PSNR、SSIM、物体与夹爪 EPE、FID、FVD 与 Gemma 4 31B 的 VLM 评分。Average 那一档的关键数字：Cosmos 2.5 基线（原生相对 6D 末端动作）PSNR 15.62 / 物体 EPE 13.23 / 夹爪 EPE 34.28 / FVD 405.8；同骨干换成 action flow 后 18.41 / 6.27 / 13.80 / 277.4；最好配置 Wan2.2 A14B 四步学生 21.84 / 5.27 / 3.29 / 155.9。

摘要的 90.4% / 60.2% 就出自最后一行对第一行：1−3.29/34.28=90.4%，1−5.27/13.23=60.2%。需要说清楚的是这是跨骨干的对比（Wan2.2 A14B 对 Cosmos 2.5 2B），真正控制变量的同骨干对比是 13.80 对 34.28（夹爪 EPE 降 59.7%）与 6.27 对 13.23（物体 EPE 降 52.6%）。两组数都在论文表里，但摘要选了前者。

另一处应当指出：零样本的 ATI 与 Wan-Move 在 Average 夹爪 EPE 上分别是 4.62 与 4.67，比经过多本体中训的 Ours (Cosmos 2.5 2B) 的 13.80 还好。也就是说在"视频是否跟随指定的夹爪轨迹"这一项上，一个通用轨迹条件视频模型零样本就压过了本文的 Cosmos 变体；本文的优势要到 Wan2.2 骨干上才建立起来。

问题二：多本体中训能省多少任务数据？ 六个 IWS 任务，按 1/2/4/20/40/60/80/100% 做种子固定的嵌套子集，所有方法用同一子集，0% 表示零样本。结论：0% 时 Ours (MT，多本体中训起点) 在全部六个任务上 LPIPS、物体 EPE、FVD 都优于 Ours (PT，直接从 Wan2.2 权重起)；100% 时 MT 在六个任务上 LPIPS 与 FVD 最低、flow EPE 在四个任务上最低。作者自己给了收敛性的保留意见：20%→100% 之间 MT 的逐任务变化至多 3.4% LPIPS、6.7% flow EPE、6.8% FVD，但 FVD 每个点只用 40 个 clip 估计、方差大，因此"早期饱和"只能算暗示而非严格收敛。

问题三：推理够不够快？ 单张 H100、bf16、batch 1、生成 81 帧 480×832。双向 teacher 20.92 s/clip（3.87 FPS），自回归 teacher 12.48 s（6.49 FPS，1.68×），四步学生 1.31 s（61.98 FPS，16.0×）。作者标注这是关掉 guidance 与 VAE 解码的 generation-only 数值，不是端到端加速比；而且测的是三块的短视界，24 潜变量的注意力上限没被触发。

问题四：能不能用它做开环策略评测？ RoboLab 上五个预训练策略（π0​、π0.5​、GR00T N1.7、Cosmos-3 Edge、Cosmos-3 Nano）× 六个任务 × 每对 10 次 rollout（300 episode）。从每条 rollout 的真实首帧出发，Hydra-0 收到从记录的末端轨迹导出的因果 action flow（策略不在生成观测上被再次查询，所以是开环重放）。生成成功率与环境成功率的 Pearson r=0.96、Spearman ρ=0.93、平均绝对误差 5.7 个百分点，按任务平均后能复现全部五个策略的参考排名。成功与否由一名对策略身份盲的人类评审判定。

问题五：逆向模式能不能真的控制机器人？ 只做了定性验证：一个柔性管弯折任务，从留出的人类演示里抽出物体流，只用这条流条件化 Hydra-0 生成兼容的机器人运动，再用训好的 action head 把潜变量 rollout 转成可执行动作，图 9 展示一次成功执行。论文明确称之为 proof-of-concept，没有成功率、没有基线、没有重复次数。

§ 8 — Take-aways ​

5 句话版：动作条件视频模型换本体就失效，根因是原生关节/末端指令不指定图像平面运动，模型必须为每个本体重学这层映射。Hydra-0 把这层映射搬到已知几何里：Isaac Lab 跑一遍控制器与物理拿到连杆变换，再把可见表面点投影成像素轨迹，得到既本体无关又受运动学约束的 action flow。训练时同一表示可以从视频用 tracker + grounded 掩码恢复，因此没有 URDF 与标定的数据集也能进语料（七个来源、2,201.7 小时、156 万个 81 帧窗口）。同骨干控制对比下，用 action flow 替换 Cosmos 2.5 的原生相对 6D 动作，在五个数据集上 PSNR、SSIM、夹爪 EPE、FID、FVD 全面变好；摘要的 90.4%/60.2% 则是最好配置（Wan2.2 A14B 四步）对 Cosmos 2.5 基线的跨骨干数字。同一接口反过来只喂物体流就能生成兼容的机器人运动，一个 action head 把潜特征映射成可执行动作，但这部分只有一个任务的定性演示。

3 句话版：把动作表示放进观测坐标系，异构数据就能共训，视频骨干就能替换。运动学约束靠"先仿真再投影"保住，因此这套像素轨迹始终对应一条可执行指令。正向做预测与开环策略评测（RoboLab r=0.96），反向做控制的证据还很薄。

1 句话版：跨本体的共享接口应该建在"能看到什么"上，而不是建在"机器人内部是什么结构"上。

§ 9 — 最脆弱的假设 ​

最脆弱的一条不在方法，而在主指标与方法之间的结构性重合：夹爪与物体 EPE 度量的是"生成视频里的跟踪点有没有沿着条件轨迹走"，而 action flow 就是那条条件轨迹。一个以轨迹为条件的模型在"是否跟随该轨迹"这项上占先，几乎是定义使然，而不是关于世界建模能力的证据。

这条重合让 90.4% 这个数字的解释力大打折扣。被比较的 Cosmos 2.5 基线吃的是相对 6D 末端动作，它的夹爪 EPE 是 34.28——考虑到同表里 ATI/Wan-Move 零样本只有 4.6，34.28 意味着这个基线在这项指标上基本处于失效状态。用一个在该指标上结构性失效的基线来算百分比降幅，得到的 90.4% 主要反映了指标与表示的匹配度。

论文缺少的是平凡基线。至少有两个必须报告却没有出现：其一，直接把 action flow 渲染到首帧上（不做任何生成），按定义就能拿到接近零的夹爪 EPE，这条能标出 EPE 的下界与它的信息量上限；其二，"复制首帧"作为静止基线，用来标出 PSNR/SSIM 的平凡水平——在 5 秒 81 帧的窗口上，静止基线的 PSNR 未必比 15.6 低多少，而这直接影响如何解读 15.62→21.84 的幅度。这两个基线都不需要训练，一天之内能补齐。

论文提供的能部分抵消这个问题的证据有三处：FVD 与 FID 度量分布质量而不度量轨迹跟随，Ours 在这两项上同样领先（Average FVD 405.8→155.9）；VLM 评分度量物理合理性、时间一致性、物体恒常性与运动真实感，作者诚实地写了这一项"结果不一"（Deform360 上 Ours Cosmos 2.5 2B 的 2.67 甚至低于零样本 Wan-Move 的 3.54）；以及 RoboLab 的 r=0.96 是在下游任务成功率上度量的，与 EPE 无关。这三处比 EPE 有说服力得多，但它们在摘要里的位置远不如 90.4% 显眼。

§ 10 — 最小复现实验 ​

一周内可做、不需要复现 40,000 步多本体中训，目标是把"EPE 增益里有多少来自表示匹配"量化出来。

  • 数据：只用 XVLA-Soft-Fold 与 Deform360 各 100 个验证 clip（论文用的同一批）。
  • 实现三个不训练的对照：(a) 静止基线——把首帧复制 81 遍；(b) 条件渲染基线——把 action flow 的轨迹点直接画到首帧上做前向 warp，不跑任何生成模型；(c) 现成的 ATI 或 Wan-Move 零样本 checkpoint（论文已给这一档，可作交叉校验）。
  • 测量：三者的 PSNR、SSIM、物体 EPE、夹爪 EPE、FID、FVD，与论文表 2 同口径。
  • 判据：若静止基线的 PSNR 已经在 15–18 区间，则 "Cosmos 2.5 基线 15.62 → Ours 21.84" 的实际增益空间要按静止基线重新标定；若条件渲染基线的夹爪 EPE 显著低于 3.29，说明 EPE 主要在测条件的可执行性而不是视频模型的质量，90.4% 需要改述。
  • 成本：纯推理与指标计算，无需训练。

这个实验直接检验的是指标的信息量，而不是方法的好坏——两个问题应该分开回答。

§ 11 — 最强反例设计 ​

第一条攻击针对 RoboLab 的 r=0.96。这个相关系数是在 30 个 policy-task 对（5 策略 × 6 任务）上算的，而任务之间的成功率差异通常远大于策略之间的差异。一个完全不看生成视频、只输出"该任务的平均成功率"的常数预测器，在这种结构下也能拿到很高的 Pearson r。要证伪或坐实这一点，实验很简单：逐任务计算策略之间的 Spearman 相关（去掉任务间方差），并报告一个"任务均值"基线的 r 与 MAE。如果去掉任务间方差后相关系数塌到 0.3–0.5，那么"生成模拟器能替代真实评测"这个主张要被大幅削弱——它能排任务的难度，未必能排策略的优劣。论文只报了"按任务平均后能复现五个策略的排名"，这是 5 个点上的排序，本身几乎没有统计功效。

第二条攻击针对逆向控制。全部证据是一个任务、一次演示、一张定性图。最强的反例是构造一类物体流不足以确定机器人运动的任务：任何存在多解逆运动学或多种抓取方式都能产生同一物体轨迹的场景（比如把一个对称杯子从 A 推到 B，从左推还是从右推产生同样的物体流，但一个会撞到旁边的障碍物）。在这类场景里，只给物体流的条件是欠定的，模型只能靠训练分布里的先验去猜，而这个先验一旦与新场景的障碍物布局冲突，就会稳定地失败。论文自己在 §6 报告的 "centimeter-scale grasp imprecision" 与 "grasp and contact state can be ambiguous in generated rollouts" 说明这条已经在最简单的任务上显形了。

第三条是一个替代解释：多本体中训的收益可能主要来自数据量与视觉多样性，与"action flow 是共享接口"无关。对照实验是把同一批 156 万窗口拿去做一次不带任何动作条件（None 模式占 100%）的视频中训，再在 IWS 上做同样的 0%–100% 数据效率曲线。如果这个无动作条件的中训模型在 0% 处也大幅优于 Ours (PT)，那么图 6 的迁移优势就有相当一部分与 action flow 无关。

§ 12 — Follow-up Research Idea ​

驱动局限：Hydra-0 的正向路径要求部署时有 URDF 与相机标定（论文在 §5.2 明说 "Forward deployment still derives action flow from robot geometry and camera calibration"），而它的训练路径已经证明这两样在训练时可以被 tracker 加 grounded 掩码替代。这个不对称是当前设计里最大的一块摩擦：一个宣称跨本体的接口，在新本体上部署时仍然需要该本体的完整几何模型。

新的 framing：把问题从"如何为已知机器人构造 action flow"改写为"如何让世界模型自己学出一台未知机器人的可见运动学"。给定一台完全没有 URDF、没有标定的新机器人的若干条自由运动视频（不需要任务、不需要成功、不需要遥操作专家），能否直接从视频里辨识出"指令 → 可见像素运动"的映射，从而把该本体接入同一接口？

可借鉴的相邻工具：视频里的关节物体辨识与自监督运动学发现（articulated object discovery）、以及机器人自标定文献里"用分割掩码与渲染掩码的一致性反解外参"的思路（DROID 的附录标定流程就是这个套路）。把两者结合，可以在不知道连杆结构的前提下，先从视频中聚类出刚性运动的像素群、再把每一群与指令通道做互信息对齐。

第一个实验：用 Hydra-0 已有的语料做留一本体实验。把 MolmoAct2 或 XVLA-Soft-Fold 整个从多本体中训里剔除，然后只给该本体的一小批"随机指令 + 视频"配对（不含任务标签），训一个轻量的可见运动学模块，输出"给定指令时哪些像素会怎么动"的预测；再把这个模块产出的 flow 当作条件喂给冻结的 Hydra-0，在该本体的留出集上测物体 EPE 与 FVD。对照是几何路径构造的 action flow（上界）与 Ours (PT) 零样本（下界）。如果学出来的运动学模块能把留出本体的表现推到几何路径的 80% 以上，那么"接入一台新机器人"的成本就从"提供 URDF 与标定"降到"提供几小时随机运动视频"，这是一个可以独立成篇的结论。
