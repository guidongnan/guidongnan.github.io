DataClaw0: Agentic Tailoring Multimodal Data from Raw Streams ​

项内容
arXiv2606.21337
提交日期2026-06-19
作者Cong Wan, Zeyu Guo, Zijian Cai, Jiangyang Li, SongLin Dong, Lin Peng, Xiangyang Luo, Zhiheng Ma, Yihong Gong
分类cs.LG, cs.AI
一句话先用确定性工具从原始多模态流里抽出「事实锚点」，再让强 VLM 在锚点上做意图条件的语义合成，用这批数据把 9B 模型训成一个能按下游意图裁剪数据的 agent。

所属教程：物理感知视频生成

§ 1 — 研究问题与重要性 ​

物理世界与数字世界每天产出海量原始多模态流：几小时的教程视频、具身智能体轨迹、网页与 GUI 操作日志。它们里面藏着密集的物理动态、流程知识和隐式决策逻辑，但没有任何显式监督信号。作者把这个障碍命名为「data entropy」——噪声大、冗余高、结构弱。

当前处理这些流的方式是被动的：启发式采样、粗粒度 captioning、或者直接让通用 VLM 生成问答对。对短而干净的输入这套够用，对长而嘈杂的流则会产出幻觉、碎片化、低信息密度的标注。作者的主张是把数据生产本身当成一种可学习的高阶能力，称为 Agentic Data Tailoring：给定一个高层用户意图或下游训练目标，裁剪 agent 主动过滤冗余、定位任务关键证据、重组成密集可验证的监督。

这件事的价值在于它改变了数据工程的成本结构。如果这种能力能被一个 9B 开源模型学会，那么数据生产就从「反复调用闭源 API」变成「本地可控、可审计、可微调的流水线」。作者把这个主张推到了它该被推的地方——用下游后训练效果当最终检验，而不是用标注质量的代理指标。

§ 2 — 前人工作与不足 ​

被动标注流水线（ShareGPT4V、SPHINX、MiniGPT-v2 这一支）已经支撑起早期的多模态 instruction tuning。它们的失效点很具体：面对需要时序推理、时空一致性、隐式物理理解的长流，直接 prompt 通用 VLM 会产出幻觉和碎片。这不是提示词写得不够好，而是模型在长流上缺少可靠的低层 grounding，必须自己同时完成「看到什么」和「组织成什么」两件事。

合成指令生成侧（Self-Instruct、WizardLM、Orca、LIMA、AlpaGasus）已经证明模型可以为自己造数据，但这些工作基本在纯文本上，且目标是通用指令而非意图条件的熵约减。Agentic AI 侧（ReAct、Toolformer、HuggingGPT、Reflexion、Voyager 以及 LangChain、AutoGPT 这类框架）证明了 agent 可以规划、调工具、反思修正，作者引用它们的意义是：agent 不仅能当执行器，也能当复杂数据生成流水线的组织者。

论文没有点名批评某个具体的数据流水线做错了什么，而是指出整类方法的共同结构缺陷：它们把「处理数据」当成固定的预处理，而不是一个可以被优化的策略。

§ 3 — 重建作者的思考路径 ​

起点是一个循环依赖：要训一个会精炼数据的模型，先得有高质量的精炼数据。作者把它叫作 data paradox。

打破循环的思路来自对失败模式的观察。直接让 VLM 标注长视频会幻觉，原因可以拆成两层——低层的事实（某帧里有什么物体、GUI 上点了哪里、动作在第几帧开始）VLM 其实经常搞错，而高层的逻辑串联（这一步为什么在那一步之后）恰恰是 VLM 相对强的地方。既然如此，就不该让同一个模型同时负责两层：低层交给确定性的轻量专家（元数据解析器、OCR、检测器、启发式规则），高层交给强 VLM，且强制它只在低层给出的锚点上做长程链接。这是典型的「自下而上抽取 + 自上而下合成」。

第二个观察是关于结构。下游要用的不是自由文本，而是严格符合某个 JSON schema 的样本。既然合规与否是可以用解析器确定性判定的，就不需要训练神经奖励模型——直接用规则奖励做 RL 即可，这同时绕开了长视频下奖励模型的显存开销。GRPO 恰好不需要 critic，与规则奖励天然匹配。

§ 4 — 核心 Intuition ​

VLM 在长多模态流上的幻觉来自它必须同时承担「感知细节」和「组织逻辑」两个负担。把感知的那一半外包给确定性工具，只留下组织逻辑给 VLM，幻觉就大幅下降，而且组织逻辑正是可以被蒸馏进小模型的部分。剩下的问题是让小模型输出严格合规——而合规是可判定的，所以用规则奖励做 RL 就够了，不需要奖励模型。

§ 5 — 具体方法与完整 Pipeline ​

以论文附录里的机器人案例说明。原始输入是一段机械臂在桌面操作的采样视频，用户意图是「构造一个 Predict Next Primary Subtask 训练样本」。

  • 锚点抽取（自下而上）：轻量专家集合扫描视频，产出四条锚点——object_state「一袋黄色珠子已被放入蓝碗」（证据帧 0–16）、object_presence「桌上还剩一个绿色方块」、robot_motion「机械臂在完成上一次放置后正在退回」、task_progress「上一子任务似已完成，应选择下一个物体」。每条锚点是三元组 (tk​,pk​,ck​)：时间戳、空间位置、局部语义。
  • 意图条件合成（自上而下）：强 VLM 在原始输入 + 锚点 + 领域意图的条件下写出结构化样本：question「机器人的下一个主要子任务是什么」、answer「拿起绿色方块」、cot 三句推理、input_video [0,16]。关键监督信号不是场景的表面描述，而是被时序证据与物体状态转移锚定的下一子任务推断。
  • 五领域覆盖：Daily Life、Education、Embodied AI、World Models/AIGC、GUI Agents。GUI 侧的构造更有意思——先用启发式判断一条轨迹是否真的包含多个子目标（指令里有没有「first / then」这类顺序标记、有没有跨应用跨页面、有没有对多个对象重复相同操作），再让 LLM 做细粒度分解，最后把片段打乱让模型推断正确顺序并重建原始任务。附录给的例子里，六个片段中只有三个（Excel 表格布局调整、表头录入含拼写错误 playerz、修正 E1 的拼写）属于同一任务，另外三个（Twitter/X Spaces、Trello 到期日、屏幕时间设置）是干扰项，模型必须识别出 B→A→C 的顺序并丢弃干扰。
  • 训练：以 Qwen3.5-9B 为基座。SFT 用 34K 条严格清洗的指令精炼数据训 1 个 epoch；随后 GRPO，格式奖励权重 0.7、锚点奖励权重 1.0、推理效率惩罚权重 0.3，学习率 4×10−6，8 张 A100。
  • 部署：DataClaw0-O 是跨领域联合训练的统一模型，DataClaw0-E 是按领域解耦的专家系统，推理时按场景路由。
  • 验证与落地：推理三段式——多模态摄入与意图解析、schema 约束解码、用事实锚点做事后 grounding 校验（交叉核对 UI 组件、空间坐标、时间戳、动作轨迹）。

§ 6 — 核心数学推导 ​

问题形式化。 输入原始流 Xraw​={x1​,…,xT​} 与意图 I，输出必须严格符合 schema Φ 的结构化资产 Ystruct​={y1​,…,yL​}，且 T≫L（这正是「熵约减」的形式表达）。优化目标带一个硬门：

θ∗=argθmax​(Xraw​,I,Ystruct​)∈D∑​logP(Ystruct​∣Xraw​,I;θ)⋅I(Ystruct​∈Φ)

指示函数把不合规样本的贡献直接归零，即先合规再谈内容。

规则奖励。 R(Y)=λ1​Rformat​(Y,Φ)+λ2​Ranchor​(Y,A)+λ3​Reff​(Y)。三项分别是：AST 或正则解析判定的 schema 合规、与抽取锚点的时空对齐、以及对冗长或过短 CoT 的惩罚。

锚点奖励的构造值得展开。预测轨迹与真值轨迹长度不同，先把离散帧索引归一化到标准区间并插值重采样到 K=50 个对齐点，算两者分布之间的 MAE 得到形变量 dshape​，再指数映射成相似度：

Ranchor​=exp(−τs​dshape​​),τs​=0.10

指数映射的作用是把「误差」变成有界的正奖励，温度 τs​ 给小的错位留容忍度：dshape​=0.1 时奖励约 0.368，dshape​=0.3 时降到约 0.05，惩罚随偏离迅速陡峭。

推理效率惩罚的相对化。 合适的 CoT 长度随样本复杂度变化，所以论文不设绝对阈值，而是在每个 GRPO rollout 组内取总奖励排前 50% 的样本的 CoT 长度当参考，显著偏离的被罚、接近的被小幅奖励。这是把「什么算合适长度」交给同组的高分样本自己定义。

GRPO。 组内标准化得到相对优势 A^(g)=(R(g)−μR​)/σR​，再用带裁剪与 KL 正则的目标更新：

J(θ)=E[G1​g=1∑G​(min(ρ(g)A^(g), clip(ρ(g),1−ϵ,1+ϵ)A^(g))−βDKL​(πθ​∥πref​))]

组内标准化替代 critic，正是 GRPO 相对 PPO 省显存的关键——处理长视频时省下的那份显存原本要给一个与策略同尺寸的奖励模型。

评测指标。 Stotal​=Gjson​⋅(0.20Sfield​+0.35Ssemantic​+0.45Straj​)，其中 Gjson​∈{0,1} 是 JSON 合法性硬门。字段分 Sfield​=0.7Cfield​+0.3(1−Rfield​) 同时奖励覆盖真值字段与惩罚多余字段；语义分是问题、答案、CoT 三处 embedding 余弦的加权（0.40/0.40/0.20）；轨迹分复用 exp(−dshape​/τs​)。三个权重把最大的份额（0.45）给了轨迹，说明作者认定时空定位才是这类数据的真正难点。

§ 7 — 实验设计与结论 ​

问题一：9B 模型能否逼近闭源标注器。 在 DataClaw0-val（200 条，五领域 + Fuzzy 子集）上，DataClaw0-E 的总体 Field 97.53、Semantic 74.94、Sequence 48.86。对照组：Gemini-3.1-Pro-Preview 98.12 / 73.85 / 58.50，GPT-4o 97.27 / 75.15 / 49.43，基座 Qwen3.5-9B 89.64 / 60.46 / 36.24。诚实的读法是：相对基座提升巨大（Sequence +12.6），但三项总体指标没有一项拿到第一——Field 输给 Gemini，Semantic 输给 GPT-4o，Sequence 明显输给 Gemini。论文的措辞是「comparable / competitive」，与表格一致。分领域看，DataClaw0-E 在 Embodied 的 Sequence（71.60，Gemini 67.97）与 Fuzzy 的 Sequence（50.31，Gemini 47.25）确实最优。

问题二：专家路由是否必要。 DataClaw0-E 在三项上全面超过 DataClaw0-O（97.53 vs 87.65、74.94 vs 62.46、48.86 vs 44.82）。附录给出的机制解释是任务干扰：Omni 模型的 scaling 曲线不是平滑对数线性，而是剧烈震荡——1/15 数据时总分 53.60，7/15 时跌到 47.23，12/15 时反弹到 57.84，随后再跌；Expert 组合稳定在 68.86。路由消融更极端：把 Embodied 任务交给 GUI 专家，Field 与 Semantic 直接归零；把 GUI 任务交给 Embodied 专家，Field 与 Sequence 归零。也就是说专家之间几乎没有交叉可用性。

问题三：GRPO 相对 SFT 贡献多少。 这是全文定量证据最弱的一处。奖励消融（在 10% SFT 初始化上做）：Minimal Init 82.50/36.79/45.40 → SFT Only 100.00/82.54/70.83 → GRPO 去掉 Ranchor​ 100.00/83.32/70.11 → GRPO 带 Ranchor​ 100.00/82.36/71.96。SFT 一步就把 Field 拉满、Semantic 从 36.79 拉到 82.54；GRPO 带锚点奖励相对 SFT 的净收益只有 Sequence +1.13，而 Semantic 反而从 82.54 掉到 82.36。去掉锚点奖励的变体 Semantic 最高（83.32）但 Sequence 最低（70.11），这一对比确实支持「锚点奖励管时空、不管语义」的分工，但整个 RL 阶段的边际贡献是一个百分点量级。

问题四：下游后训练是否真的更好。 三个任务在严格等量的数据预算下比较（同样的原始流、同样的过滤、等数量采样）。GUI 导航（Qwen3.5-4B）：零样本 12.4/1.2，自精炼 16.8/3.5，Gemini 39.5/14.2，DataClaw0 38.2/15.6。动作视频生成（Wan2.2-I2V-5B，200 条训练片段，480×832，81 帧，3 epoch）：零样本 FVD 385.2 / 一致性 68.4 / Contact mAP 18.5，Gemini 295.4/76.2/48.5，DataClaw0 288.6/75.8/51.2。时空 VQA（ReMoT）：零样本 28.3/9.8，Gemini 53.4/31.5，DataClaw0 52.1/33.2。规律是一致的：Gemini 在步级/部分正确指标上略优（GUI SSR、VQA Partial Acc），DataClaw0 在端到端指标上略优（GUI TSR、VQA Overall Acc、FVD、Contact mAP）。差距普遍在 1–3 个点，且没有报告方差或多次运行。

论文自曝的失败模式很有价值：daily-life 案例里构造的问答语义正确，但 CoT 把视频描述成「从工位走向床」而实际帧序（0→20）是反方向。作者称之为 temporal hallucination，归因于基座模型倾向按空间线索推出「合理的」事件流而非严格按时序。

§ 8 — Take-aways ​

5 句话版：原始多模态流的价值被「data entropy」锁住，被动标注流水线在长流上会产出幻觉与碎片。DataClaw0 把数据生产重构成意图条件的熵约减：确定性工具抽事实锚点负责低层 grounding，强 VLM 在锚点上做长程逻辑链接负责高层组织。用这批数据把 Qwen3.5-9B 训成裁剪 agent，SFT 之后再用纯规则奖励（schema 合规 + 轨迹形状对齐 + CoT 长度相对正则）做 GRPO，全程不需要神经奖励模型。领域解耦的专家版在自建基准上大幅超过基座并逼近闭源标注器，统一版则因任务干扰出现严重的 scaling 震荡。下游后训练在等量数据预算下与 Gemini 标注互有胜负，DataClaw0 在端到端指标上略优。

3 句话版：把长多模态流的标注拆成「确定性抽锚点」与「VLM 在锚点上合成」两层，从而绕开训练数据的鸡生蛋问题。9B 模型经 SFT + 规则奖励 GRPO 后成为可控的本地标注器，性能逼近闭源模型且专家路由是必需的。RL 阶段的边际增益只有一个百分点量级，主要工作由 SFT 与数据构造完成。

1 句话版：把 VLM 从「感知 + 组织」的双重负担里解放出来，只让它组织，数据合成的幻觉问题就大半解决了。

§ 9 — 最脆弱的假设 ​

最脆弱的是：DataClaw0-val 能独立地度量裁剪质量。 这个基准的参考输出与训练数据出自同一条构造流水线——同样的锚点抽取、同样的强 VLM 合成、同样的 schema。论文确实做了 source-disjoint 的隔离（val 用到的原始视频、GUI 会话、具身轨迹都被排除出 SFT 与 GRPO 池，还去掉了重复的任务模板与近似动作序列），但这只切断了内容泄漏，没有切断风格与格式的泄漏。

后果很具体。Ssemantic​ 是问题、答案、CoT 三处文本与参考的 embedding 余弦，而参考文本是教师 VLM 写的；DataClaw0 是在同一教师的输出上蒸馏出来的。于是「DataClaw0-E 的 Semantic 74.94 逼近 GPT-4o 的 75.15」这句话里，有多少是「裁剪得好」、有多少是「写得像教师」，无法从现有实验里分开。Sfield​ 更直接——schema 是构造流水线自己定的，SFT 数据里全是符合它的样本，Field 拉到 100.00 几乎是必然。

如果这个假设不成立，塌掉的是主表的全部结论（第 4.2 节），也就是「9B 模型逼近闭源标注器」这一条。不塌的是第 4.3 节的下游实验——那里的指标（FVD、Contact mAP、TSR、Overall Acc）由外部任务定义，与构造流水线无关。这正是作者把下游后训练称为 ultimate validation touchstone 的道理，只是下游那些差距太小（1–3 点、无方差）以至于承载不了主表塌掉后的全部论证负担。

§ 10 — 最小复现实验 ​

一周内可做，且不必训练 9B 模型：

  • 取 GUI 与 Embodied 两个领域各 100 条原始流。用论文的两阶段流水线造两版数据：版本 A 用完整流水线（锚点 + 强 VLM 合成），版本 B 只用强 VLM 直接合成、不给锚点。
  • 再造版本 C 作为关键对照：只用确定性工具产出的锚点，套一个固定模板直接填进 schema，完全不调用 VLM。
  • 三版数据各采等量样本，用同一套超参微调 Qwen2.5-VL-3B 这类小模型，在 GUI 步级成功率上评测。
  • 判定标准：若 A 显著优于 B（例如 SSR 相差 5 点以上），锚点机制得到支持；若 C 已经接近 A，则说明增益主要来自确定性工具的结构化，VLM 合成这一层的贡献被高估。

这个实验直接切开论文没有分离的两个变量（锚点 vs VLM 合成），而论文只做了「有没有锚点奖励」这一 RL 侧消融，从未做「有没有锚点输入」这一数据侧消融。

§ 11 — 最强反例设计 ​

从表格本身可以给出一个反例。看 Education 领域的 Sequence 分：基座 Qwen3.5-9B 是 24.75，DataClaw0-E 是 19.75，DataClaw0-O 是 17.41——两个训练后的版本都比基座差。AIGC 领域的 Sequence，DataClaw0-E 15.26，而 GPT-4o 46.95、Qwen3.6-plus 39.71、Gemini 33.14，差距是数量级的。也就是说这套训练在五个领域里至少有两个是失败的，而总体分之所以好看，靠的是 GUI（96.33）与 Embodied（71.60）两个领域把均值拉起来。这给「Agentic Data Tailoring 是一种通用可学习能力」提供了一个替代解释：学到的不是通用裁剪能力，而是两个结构性强、schema 固定的领域（GUI 动作序列、机器人轨迹）里的模板拟合，而这两个领域恰好是锚点抽取工具最可靠的地方。

具体反例实验：构造第六个领域，选一个锚点工具覆盖不到的场景（例如手术视频的器械-组织交互，或者体育比赛的战术回放），不给任何领域特定的确定性专家，只用通用检测器。按同样流程走一遍 SFT + GRPO，看 Sequence 分能否超过基座。可预测的失败模式是：在这个领域上 DataClaw0 的 Sequence 与基座持平甚至更差，与 Education/AIGC 的现象一致。若如此，论文的贡献应被重新表述为「一套把确定性工具的输出转成训练数据的高效模板」，而不是一种被模型内化的高阶能力。

另一条更省事的攻击针对表 1 本身：Claude-Sonnet-4-6 的 Daily 与 Education 三项分数完全相同（54.46/54.46 与 41.07/41.07），Gemini-3.1-Pro-Preview 也完全相同（54.51/54.51 与 51.48/51.48）。两个不同领域、不同题目上出现逐位相同的分数，指向表格填充时的复制错误。在这两行被订正之前，任何以「Gemini 在 Education 上强」为前提的比较都不可靠。

§ 12 — Follow-up Research Idea ​

驱动它的局限：论文自己在附录 F 点出，DataClaw0 只能在用户提供的原始流上做精炼、过滤、标注，无法从意图出发自主创造数据。这个限制比表面看起来更严重——精炼的上限被原始流里已经发生过的事情钉死了。机器人的失败恢复数据是靠把成功轨迹里的某一帧重复播放伪造出「卡住」来的（fault synthesis 分支），这说明作者已经意识到了缺口，但用的是像素级的伪造而非物理上真实的反事实。

新的 framing：不要把数据裁剪建模为「在已有流上做熵约减」，而建模为在可交互环境里做面向监督价值的主动探索。目标函数从「输出与参考的相似度」换成「这条被采集的轨迹能给下游模型带来多少梯度信息」——即把数据采集当成一个以下游模型学习收益为奖励的 RL 问题。这与当前设定的根本区别是：熵约减只能挑，主动探索可以造，尤其可以造出原始流里概率极低的长尾情形（真正的机械臂打滑、GUI 里的错误状态恢复）。

可借鉴的相邻工具：主动学习里的期望模型变化（expected model change）与影响函数给出了「一条样本值多少」的可计算代理；课程强化学习里的 teacher-student 设置提供了让采集策略与学习者共同演化的框架；具身仿真器（Habitat、GUI 沙箱、机器人仿真）提供了可反事实干预的环境，正好补上论文里用重复帧伪造失败的那一环。

第一个实验：在一个 GUI 沙箱里，让裁剪 agent 不再读日志而是自己操作，奖励定义为「用它采集的 N 条轨迹微调下游 Qwen3.5-4B 后，在留出任务集上的 TSR 提升」。对照组是本文的流水线在等量已有日志上裁剪出的 N 条。若主动采集组在同样 N 下 TSR 更高，尤其在长尾失败恢复类任务上更高，就说明「造数据」相对「挑数据」存在真实的上限差距，值得把整个 framing 换掉。
