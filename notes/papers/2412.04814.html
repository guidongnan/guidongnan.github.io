LiFT: Leveraging Human Feedback for Text-to-Video Model Alignment ​

项内容
arXiv2412.04814
提交日期2024-12-06（v3: 2025-03-05）
作者Yibin Wang, Zhiyu Tan, Junyan Wang, Xiaomeng Yang, Cheng Jin, Hao Li
分类cs.CV
一句话让标注者在打分之外写出「为什么打这个分」，用这份带 rationale 的 10K 数据训一个多模态奖励模型，再用它的分数做 reward-weighted likelihood 微调 T2V 模型。

所属教程：后训练与强化学习

§ 1 — 研究问题与重要性 ​

T2V 模型的失败模式已经从「生不出来」变成「生得出来但不是你要的」：伪影、语义没跟上 prompt、运动不自然。论文在 Introduction 里把这类问题的根源归到一句话上——人类偏好本质上是主观的，很难写成一个客观损失函数。这不是修辞。视频质量至少要同时管住单帧的清晰度与美感、帧间的连续性、以及与文本的语义对应，三者互相牵制，任何一个写成解析式目标都会牺牲另外两个。

于是问题变成：如何把人类判断本身变成一个可优化的信号。LiFT 的答案分三步——收集人类反馈、学一个奖励函数、用这个奖励函数微调生成模型。这个三段式在 LLM 与 T2I 上已经跑通，但视频这一环在当时是空白：作者在 Introduction 中明确写「利用基于视频的人类反馈来对齐 T2V 模型仍是一个未被探索的领域」。价值也因此直接：一旦这条链路成立，视频生成的质量上限就不再由预训练数据的平均质量决定，而是由标注预算与奖励模型的分辨力决定。

§ 2 — 前人工作与不足 ​

论文点名了两条路线。第一条是把图像奖励模型直接搬过来：InstructVideo、T2V-Turbo 这类工作把 HPS、CLIP 等图像侧偏好模型的反馈接进训练。它们能做的事是明确的——提升单帧的美感与图文相关性；不够的地方也同样明确：图像奖励模型在结构上就看不见帧与帧之间的东西，运动连续性、转场平滑度这些视频特有的维度它无法表达，因此对齐出来的模型仍然会生成"每帧都好看但动起来是错的"的视频。

第二条是训练视频质量评估模型，代表是 T2VQA 与 VideoScore：用人工标注的评分数据训一个模型，对视觉质量、时序一致性等维度分别打分。论文对它们的批评落在两点上。其一是可解释性缺失——这些模型只学"评分结果"，不学"评分理由"，于是只能拟合分数与像素统计之间的表层相关，捕捉不到人类评判中那些细粒度的、需要说明才成立的标准。其二更关键：它们停在了"评估"，没有走到"对齐"。有了打分器不等于有了训练信号，如何把一个不可微的视频评分接回扩散模型的梯度，是另一个问题。

为什么"评分理由"此前没被考虑？可以推断（论文未显式论证）是因为在图像时代，评分维度相对少、判据相对硬，纯回归就够用；到了视频，判据的组合爆炸让纯分数变成一个信息量极低的监督信号——同样是 2 分，可能因为闪烁、因为主体漂移、因为动作方向反了，回归损失对这三种情况一视同仁。

§ 3 — 重建作者的思考路径 ​

先看当时手上有什么。RLHF 在语言模型上已经是标准流程，其中「标注者不仅给偏好、还给理由」的做法（如 constitutional AI 一类的工作）已被证明能让奖励模型学到更结构化的判据。同时，多模态大模型（LMM）在 2024 年已经能对视频做描述与推理，具备"看视频并说出问题在哪"的能力。

再看视频侧的失败经验。图像奖励模型接进视频训练，收益停在单帧层面——这说明奖励信号的感受野决定了对齐的天花板。视频质量评估模型能覆盖时序维度，但它们的输出是几个标量，把一个高维的、多因子的判断压成几个数，压缩比太高。

把这两条线拼起来，一个自然的想法出现了：既然 LMM 本来就能生成文本，就不要强迫奖励模型只吐一个数——让它同时预测分数和理由。理由是分数的"中间推理"，用它做辅助监督，等价于给奖励模型一个信息量高得多的训练目标，也能在少量标注下学到更细的判据。剩下的问题是怎么把奖励接回生成模型。最省事的做法不是 policy gradient、也不是 DPO，而是最古老的一招：reward-weighted likelihood maximization——按奖励给样本加权做似然最大化。它不需要成对偏好，不需要在线采样与重要性采样，实现上就是在扩散损失前乘一个权重。

§ 4 — 核心 Intuition ​

人类给视频打的那个分，本身是被压缩过的信息；真正携带判据的是"为什么"。让奖励模型在预测分数的同时把理由也生成出来，就等于把标注者头脑里的评判过程当作监督信号的一部分喂进去，于是同样 10K 条标注能撑起一个分辨力更细的奖励函数。有了这个奖励函数之后，对齐这一步反而可以退回到最朴素的形式——按奖励加权做似然最大化，不需要任何强化学习机制。

§ 5 — 具体方法与完整 Pipeline ​

三阶段管线的真实构成如下。

阶段一：人类反馈收集（LiFT-HRA）。先造 prompt：建好 human / animal / place / action 四类选项表（Tab. 6 给了完整列表，里面甚至有一类叫 Imagine Place，例如“锅里的汽车”“云里的火车”），每条 prompt 随机抽 1–2 个主体、一个场景、一个动作，拼成短语后用 Qwen2 扩写成详细描述，再用 T2V 模型为每条 prompt 生多段视频。标注由 10 位本科/研究生专家完成，在网页 UI 上对三个维度各选一个等级并写下理由。等级只有 Good / Normal / Bad 三档，Tab. 3 与 Appendix A.3 给出了每个维度每个档位的具体判据。

数据清洗分三步，这一段设计比它看上去重要：粗筛（人工剔掉明显错标与不合规范的）→ 迭代细化（把数据一分为二，用前一半训一个初版奖励模型去标后一半，一致就保留、不一致交回人工裁定，再反过来重跑一次）→ 终极整合（用完全修正后的数据训最终奖励模型，去重新标注第一步被剔掉的数据并拉回数据集）。最终得到约 10K 条问答对，其中 9K 训练、剩下作测试集。数据分布上作者直接写了一句很诚实的话：大多数视频被评为 Bad，Good 次之，Normal 最少。另混入 1K 条来自 VIDGEN 的真实视频以接触真实分布。

阶段二：奖励函数学习（LiFT-Critic）。底座是 VILA-1.5 的 13B 与 40B 两个规模。视觉塔分别用 siglip-so400m-patch14-384（13B）与 InternViT-6B-448px-V1-2（40B），连同其 MLP projector 全部冻结，只微调 LLM 的线性层。LoRA 配置：13B 用 rank 128 / alpha 256 / batch 16，40B 用 rank 64 / alpha 128 / batch 8，都跑 20 个 epoch，AdamW 基础学习率 1e-5 配 cosine 调度与 3e-2 预热，8 张 H100。

关键设计是它不接回归头。分数被转成自然语言标签（"Good"/"Normal"/"Bad"），通过文本生成预测，而且每个答案选项都被用详细理由“扩充”过。作者的理由是两层：回归头捕捉不了人类判断里那些细微且主观的标准；而文本生成天然契合预训练 VLM 的强项。

推理时，LiFT-Critic 分三个维度各出一个词，再经一个映射函数 s 变成数值，取三维平均得到 rϕ​(x,z)。这个映射表在论文里写得很明确：Good = 0.9，Normal = 0.2，Bad = 0.05。注意它不是等距的——Good 与 Normal 之间隔着 0.7，而 Normal 与 Bad 只隔 0.15，相当于把"不够好"与"很差"归为一类。这个选择直接决定了微调时的样本权重分布，却没有被消融。

阶段三：T2V 对齐。用 CogVideoX-2B 生成 40K 条视频作为合成数据集 Dsyn​，另从 OpenVid 选约 20K 条真实 video-text 对作为 Dreal​。微调 CogVideoX-2B 的全部 transformer block（不是 LoRA）。论文给了两种奖励学习方式：reward-weighted learning（RWL，主方案）与 rejection sampling（RS，把权重化为硬阀值，只保留三维都是 Good 的样本）。作者对二者取舍的描述很具体：RS 轻量但因数据变少而有过拟合风险，RWL 贵但能用上所有样本。

另一个应用：同一套管线也被用到了 T2V-Turbo 上（Appendix B.4），说明它不依赖 CogVideoX 的特定结构。

§ 6 — 核心数学推导 ​

论文的形式化只有四个式子，但它们把整个方法定死了。

奖励模型的训练目标（式 1）。训练样本是三元组：多模态输入 M（视频 + 文本描述）、问题 Q、答案 A。目标是标准的自回归损失，但只施加在答案上：

L(ϕ)=−i=1∑N​logp(Ai​∣Q,M,A<i​;ϕ).

这条式子本身没什么新意，新意在 A 的内容：它不只是一个词，而是"等级 + 理由"。也就是说，理由不是辅助任务，它就在同一个 token 序列里，模型必须先把判据生成出来。

奖励聚合（式 2）：rϕ​(x,z)=∣D∣1​∑d∈D​s(rϕ,d​(x,z))，即三个维度等权平均。

RWL 对齐目标（式 3）。这是全文最值得看清楚的一式：

L(θ)=E(x,z)∼Dsyn​​[−rϕ​(x,z)logpθ​(x∣z)]+λ⋅E(x,z)∼Dreal​​[−logpθ​(x∣z)],λ=1.

第一项就是教科书式的 reward-weighted likelihood：不改损失形式，只改每个样本被重视的程度。第二项才是容易被忽略、却在消融里被证明必需的那一项：作者明确写它是一个正则项，因为合成视频本身就时序一致性差，只在合成数据上加权会把模型拉得更差；混入真实视频才能把它锚在真实的帧间动态上。Appendix B.7 的消融确认了这一点：去掉 Dreal​ 后，主体一致性、背景一致性、时序闪烁三项都明显下降。

RS 变体（式 4）：定义 rϕ​=1 当且仅当三维全为 Good，否则 rϕ​=0，于是第一项退化成在过滤后子集上的普通似然最大化。论文把 RS 明确定位为 RWL 的一个特例（权重函数退化为硬掩码）。

一个值得指出的缺口：论文没有 KL 正则项。作者在 Appendix D 的 Limitations 里自己把这列为不足，并指出 RLHF 可以在训练中在线采样并引入 KL 约束，从而缓解对特定奖励函数的过拟合。换句话说，防 reward hacking 的担子完全压在 Dreal​ 这一项上。

§ 7 — 实验设计与结论 ​

问题 1：奖励模型准不准，理由监督到底值多少？（Tab. 2，三维准确率与平均） GPT-4o-mini 60.42 / 64.33 / 68.26 / 64.34；GPT-4o 70.59 / 67.29 / 71.99 / 69.96；LiFT-Critic-13B w/o reason 80.27 / 77.48 / 82.72 / 80.15；40B w/o reason 84.55 / 88.01 / 88.62 / 87.06；LiFT-Critic-13B 85.61 / 88.92 / 88.51 / 87.68；LiFT-Critic-40B 90.23 / 94.89 / 95.53 / 93.55。两条结论都很硬：理由监督在 40B 上把平均准确率从 87.06 抬到 93.55（13B 上 80.15 → 87.68），而且 13B 带理由（87.68）已经超过 40B 不带理由（87.06）——理由这一维的价值大致相当于把模型放大三倍。另外 GPT-4o 只有 69.96，说明这类细粒度视频判据确实需要专门训练。

问题 2：奖励模型能否把 2B 推过 5B？（Tab. 1，VBench 16 项）这是论文的头条结论，但它成立的前提比摘要写的更窄。逐项对照 CogVideoX-2B / CogVideoX-5B / LiFT-13B / LiFT-40B：主体一致性 94.58 / 94.84 / 96.15 / 96.82；背景一致性 95.45 / 95.64 / 96.48 / 96.79；美学质量 61.94 / 63.13 / 63.24 / 63.72；成像质量 63.04 / 63.14 / 64.01 / 64.19；时序闪烁 96.94 / 97.19 / 98.10 / 98.20；运动平滑度 97.86 / 97.81 / 98.17 / 98.33；动态程度 60.22 / 62.78 / 61.89 / 62.85；人类动作 97.34 / 98.40 / 97.90 / 98.44；颜色 80.86 / 82.50 / 84.40 / 85.15；空间关系 61.78 / 55.94 / 64.66 / 66.04；场景 53.30 / 56.57 / 56.76 / 57.63；时序风格 24.19 / 25.12 / 24.83 / 25.23；整体一致性 27.34 / 27.84 / 27.23 / 27.93；物体类别 85.75 / 88.99 / 91.27 / 91.77；多物体 69.11 / 70.98 / 77.45 / 79.34；外观风格 24.67 / 24.70 / 24.86 / 25.92。

从这张表可以读出三件摘要不会告诉你的事。其一，"16 项全胜"只对 40B 奖励模型成立：13B 版本在人类动作、动态程度、时序风格、整体一致性四项上输给 CogVideoX-5B。其二，40B 版本的四项胜出幅度小于 0.15（动态程度 62.85 vs 62.78、人类动作 98.44 vs 98.40、时序风格 25.23 vs 25.12、整体一致性 27.93 vs 27.84），把它们计入"全胜"在统计上相当勉强。其三，真正拉开差距的是多物体（+8.36 相对 5B）与空间关系（+10.10），也就是组合语义那一类，这与三个奖励维度里"语义一致性"的定位是对得上的。

问题 3：会不会为了拿高分而牺牲运动？ 这是对 reward-weighted 微调最自然的质疑，而表里给了答案：动态程度从 2B 的 60.22 升到 40B 版的 62.85，没有塌缩。同时运动平滑度也从 97.86 升到 98.33。二者同向上升说明模型不是靠"少动"换的分。

问题 4：有没有独立于 VBench 的证据？ 有两条。一是 VideoScore 这个第三方评估模型（Tab. 4，VQ/TC/DD/TA/FC）：CogVideoX-2B 2.86 / 2.78 / 2.65 / 2.91 / 2.71，CogVideoX-5B 3.01 / 2.94 / 2.73 / 2.96 / 2.87，CogVideoX-2B-LiFT 3.18 / 2.99 / 2.96 / 3.04 / 2.90，五项全高于 5B。二是人类评测：120 条 prompt，把 LiFT 版分别与 2B、5B 做成对比较，评者可选更好或平局，报告获得正票的比例并标出取得多数共识（6 票中至少 3 票）的比例。此外作者还用 LiFT-Critic 复评三个模型的输出，称其排序与人评高度一致（Fig. 11）——这条要谨慎看，它是用自家奖励模型验证自家奖励模型对齐的结果。

问题 5：RS 与 RWL 谁更好？ Fig. 8 的雷达图显示 RS 显著优于 CogVideoX-2B、与 5B 竞争性持平，略逊于 RWL，但更轻量。

关于 prompt：Appendix B.1 明确写了评测 prompt 用 Qwen2.5-72B-Instruct 优化过，理由是 CogVideoX 本身就是用长 prompt 训的。这一点论文是披露了的，只是放在附录；引用"16 项全胜"时应当连带说明这个前提。

局限（作者自陈，Appendix D）：数据集只覆盖三个维度、四类文本类别、三档反馈；对齐只用 reward-weighted likelihood，没有在线采样与 KL 正则；作者自己认为 RLHF 可能带来进一步收益。

§ 8 — Take-aways ​

5 句话版。 LiFT 把 RLHF 的三段式（收数据、学奖励、对齐模型）第一次完整搬到 T2V 上，关键设计是让标注者在分数之外写出理由，并让奖励模型在同一个 token 序列里同时生成等级与理由。这一设计的收益被消融直接量化：40B 奖励模型的平均准确率从 87.06 升到 93.55，而 13B 带理由（87.68）已经超过 40B 不带理由。奖励维度拆成语义一致性、运动平滑度、视频保真度三项，分数映射为非等距的 Good=0.9 / Normal=0.2 / Bad=0.05。对齐用的是 reward-weighted likelihood 加上一项真实视频似然作正则，后者在消融里被证明是时序质量的必要项。头条结论“CogVideoX-2B 在 VBench 16 项上全胜 CogVideoX-5B”只对 40B 奖励模型成立，且其中四项胜出幅度不足 0.15，真正拉开差距的是多物体与空间关系这类组合语义。

3 句话版。 分数是被压缩过的人类判断，理由才是判据本身；把理由也当监督，它带来的增益相当于把奖励模型放大三倍。奖励拆成语义、运动、保真三维，补上了图像奖励模型的时序盲区。对齐用最简单的 reward-weighted likelihood，而担心的"为拿高分而少动"并未发生——动态程度从 60.22 升到了 62.85。

1 句话版。 让奖励模型学会"说出理由"，再用它的分数加权微调，小模型就能在偏好对齐上打赢大模型。

§ 9 — 最脆弱的假设 ​

最脆弱的是这一条：LiFT-Critic 给出的分数是人类偏好的可靠代理，因而可以直接当作优化目标。整条流水线的价值全部压在这个假设上——奖励函数一旦有系统性偏差，reward-weighted likelihood 会把这个偏差原封不动地放大成生成模型的行为倾向，而且比 DPO 更彻底，因为它没有成对比较带来的相对化保护。

它在实践中为什么可能不成立？奖励模型是在某一个 T2V 模型的输出分布上标注、训练的（Introduction 说明用于构造 LiFT-HRA 的视频由 T2V 模型生成）。一旦被对齐的模型在训练中漂移，生成分布就离开了奖励模型的训练域，此时分数的可信度没有任何保证——这正是后来 Dual-IPO（2502.02088，同为复旦/上海科学智能研究院团队）明确要解决的问题，那篇论文把"reward 必须随生成模型一起迭代"当作核心动机。

论文为它提供了什么证据？比只看摘要时多得多：奖励模型在 held-out 上的平均准确率 93.55%（Tab. 2），一个独立于 VBench 的第三方评估模型 VideoScore 上五项全高于 5B（Tab. 4），以及 120 条 prompt 的人类成对盲评。这三条合起来比只有 VBench 要结实得多。

但这些证据全部是在对齐完成后的模型输出上做的最终评价，没有一条回答过程中的问题：随着 pθ​ 在训练中漂移，rϕ​ 的准确率是否保持在 93.55%？ 93.55% 是在 LiFT-HRA 的 held-out 上算的，而那批视频来自对齐前的生成分布。论文全文没有在 CogVideoX-2B-LiFT 的输出上重新评测过奖励模型的准确率（Fig. 11 用的是 LiFT-Critic 对三个模型排序，不是准确率，且那正是“自己验自己”）。而由于目标里没有 KL 约束，漂移是无界的——作者在 Limitations 里自己也承认了这一点。这正是后来 Dual-IPO（2502.02088，同为复旦/上海科学智能研究院团队）明确要解决的问题，那篇论文把“reward 必须随生成模型一起迭代”当作核心动机。

§ 10 — 最小复现实验 ​

不要去重做“理由监督有没有用”——Tab. 2 的 w/o reason 两行已经回答了。该测的是 §9 指出的那个空白：奖励模型在分布漂移后还准不准。一周内可做，且不需重训任何模型：

  • 资源。 作者已公开 LiFT-HRA、LiFT-Critic 的 13B/40B LoRA 权重、以及 CogVideoX-2B-LiFT 权重。
  • 步骤。 用同一批 prompt（最好取自 LiFT-HRA 的 held-out）分别从 原始 CogVideoX-2B 与 CogVideoX-2B-LiFT 各生 300 条视频，混洗后交给三位标注者按论文 Appendix A.3 的同一套判据打 Good/Normal/Bad，得到两组真值。
  • 测量。 分别计算 LiFT-Critic-40B 在这两组上的三维准确率，并与论文报告的 93.55% 对比。同时统计奖励分布的偏移（对齐后被评为 Good 的比例应当上升，问题是人与模型上升幅度是否一致）。
  • 判据。 若对齐后组的准确率下降超过五个百分点，就直接证实了 §9 那条假设在迭代一轮之后就已经开始失效，“多跑几轮 RWL”这条路就不成立；若准确率基本持平，则该奖励模型可以支撑多轮迭代，这本身是一个对后续工作很有用的正面结论。
  • 加分项。 同一批 prompt 分别用 VBench 原始版与 Qwen2.5-72B 优化版各跑一遍，看“16 项全胜”在原始 prompt 下是否仍然成立——考虑到四项胜出幅度不足 0.15，这个检验很便宜也很必要。

§ 11 — 最强反例设计 ​

先说明一条已经被全文挡住的攻击，免得读者浪费时间：担心 reward-weighted likelihood 会让模型"少动以拿高分"是合理的，但 Tab. 1 显示动态程度从 60.22 升到 62.85、运动平滑度同时从 97.86 升到 98.33，两者同向上升，保守化没有发生。

还站得住的最强攻击是：给"16 项全胜"提供一个不需要 rationale、也不需要人类反馈的替代解释。设计：取同一个 CogVideoX-2B，用一组完全不含人类标注的自动指标合成奖励——把 VBench 的若干子指标线性组合成标量 rauto​——再做同样的 RWL 微调（含 Dreal​ 正则项），训练步数、数据量、prompt 集与 LiFT 严格对齐。如果 rauto​ 版本也能压过 CogVideoX-5B，那么论文的增益就可以被重新解释为"对着评测指标做加权微调"的必然结果。

这个反例指向一个可预测的失效条件：当奖励维度与评测维度同源时，提升是构造性的。LiFT 的三个维度与 VBench 的一级维度高度重合。要注意论文对此并非毫无防备：VideoScore 的五项与 120 条 prompt 的人类盲测都是与奖励维度不同源的证据。但这两条证据的分辨力都弱于 VBench 那张 16 项表——VideoScore 的差距在 0.1–0.3 分之间，人评只报了胜率比例。所以真正需要补的是把 rauto​ 这条对照做出来，让"人类反馈"的边际贡献被隔离。

第二条更便宜的攻击针对统计显著性：40B 版在四项上的优势不足 0.15，而 VBench 的这些指标本身有采样方差（每个维度只跑固定数量的 prompt）。跑 3–5 个随机种子并报告标准差，就足以判断"16 项全胜"是稳定结论还是一次好运。论文全文没有报告任何方差或多种子结果，这是一个便宜且必要的补充。

§ 12 — Follow-up Research Idea ​

(a) 什么局限驱动了它。 LiFT 的 rationale 只在训练奖励模型时被使用；到了对齐阶段，整条理由被压回一个标量权重，信息全部丢弃。这是一个明显的浪费——奖励模型明明知道"这条视频的问题是第 3 秒主体换了衣服"，但生成模型只收到一个"0.4"。

(b) 可借鉴哪个相邻领域的工具。 语言模型侧的 critique-and-revise / verbal reinforcement 路线：让 critic 输出自然语言的具体缺陷，再由一个编辑器按缺陷做定向修改，而不是把批评压成标量。视频侧已有的可控编辑与 inpainting 模型提供了"按指令做局部修改"的执行器。

(c) 新 framing。 把对齐从"按标量加权重训生成模型"改为"让 critique 直接可执行"：LiFT-Critic 输出结构化缺陷（维度 + 时间区间 + 空间区域 + 文字描述），由一个编辑模型在 latent 空间对被点名的时空区域做定向修正，修正后的视频再回到 critic 复评，形成闭环；生成模型本身只在闭环收敛后用"修正前 vs 修正后"这对样本做偏好学习。这样 rationale 的空间-时间定位信息被完整保留，而且天然抗 reward hacking——因为奖励不再是一个可以被整体拉高的标量，而是一组必须被逐条消除的具体指控。

第一个实验长什么样。 不训生成模型，只做推理期验证：取 CogVideoX-2B 的 200 条输出，让 LiFT-Critic 在带时间戳的 prompt 模板下给出结构化缺陷，用现成的视频编辑模型只改被点名的帧区间，然后做三方人类盲测（原始 / reward-weighted 微调版 / critique-编辑版）。若 critique-编辑版在"缺陷被消除"这一项上显著领先，同时 dynamic degree 不下降，说明把 rationale 保留到执行端是有价值的方向。
