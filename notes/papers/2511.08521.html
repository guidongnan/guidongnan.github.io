UniVA: Universal Video Agent towards Open-Source Next-Generation Video Generalist ​

项内容
arXiv2511.08521
提交日期2025-11-11
作者Zhengyang Liang, Daoan Zhang, Huichi Zhou, Rui Huang, Bobo Li, Yuechen Zhang, Shengqiong Wu, Xiaohan Wang, Jiebo Luo, Lizi Liao, Hao Fei
分类cs.CV
一句话用 Plan-Act 双 agent 加 MCP 工具服务器和全局/任务/用户三级 memory，把视频的理解、生成、编辑、分割统一成一条可依赖建模、可重规划的流水线。

所属教程：智能体视频生成

本页依据 arxiv.org/html/2511.08521v1 全文撰写（Technical Report，约 37 页）。

§ 1 — 研究问题与重要性 ​

视频领域的能力被切成互不相通的几块：理解模型答问题，生成模型出片子，编辑模型改片子，分割模型抠东西。真实创作请求几乎从来不落在单块里。"把这段素材里的人换成穿红衣服的，再接一段他走进雨里的镜头，最后配上字幕"这句话，需要理解、分割、编辑、生成按顺序协作，而且前一步的输出决定后一步的输入。

现有做法多是把 LLM 当作一次性路由器：解析意图、挑一个工具、返回结果。这种设计在单步任务上够用，在多步创作上会立刻暴露两个缺陷。第一是没有依赖建模，工具之间的输入输出约束（这个编辑必须在分割之后、必须用同一段 mask）只存在于 prompt 的自然语言里，不构成可检查的结构。第二是没有可回溯的状态，某一步失败之后整条链只能从头重来，用户上一轮说过的偏好也留不住。UniVA 把这两件事当成一等公民来做：计划是带依赖的结构化对象，执行状态与用户偏好写进分层 memory。

§ 2 — 前人工作与不足 ​

单体视频基座（生成侧的扩散/自回归大模型、理解侧的视频 MLLM）在各自任务上表现最好，但能力边界由训练目标定死。让一个 T2V 模型去"只改画面里的一个物体、其余像素不动"，它没有这个接口。

通用多模态 agent 框架已经把"LLM 调工具"这套跑通了，弱点在视频这一域特别突出：视频工具的调用代价远高于图像（一次生成动辄数十秒到数分钟），因此盲目试错的成本无法接受；同时视频任务的中间产物（mask 序列、关键帧、时间区间）结构复杂，仅靠文本传递容易丢失。

流水线式视频创作系统（分镜脚本加逐镜头生成）解决了长视频的组织问题，但流程是写死的，换一类请求就得重写编排逻辑，也不支持"理解一段已有视频再改它"这种反向流程。

UniVA 的定位是在开源栈上做一个能同时吃下这四类任务、且流程由 planner 动态生成的 agent。它付出的代价是整体质量被后端工具锁死，这一点在 §9 会展开。

§ 3 — 重建作者的思考路径 ​

从一个失败模式出发：让单个 LLM agent 一边想一边调工具，它会在长链条上逐渐忘掉最初的约束，并且在某一步失败后倾向于继续往下走而不是回头修计划。分开两个角色是很自然的应对——一个只负责把请求拆成带依赖的步骤并在失败时重规划，另一个只负责按步骤调工具并把中间产物落盘。

接着是工具接口问题。视频工具的输入输出不是纯文本，需要一个统一的协议来声明"我接受什么、返回什么"。MCP 这类工具服务器协议正好提供了这层抽象，让新工具接入不必改 agent 代码。

最后是记忆。创作是多轮的，用户会说"还是上一版那个风格"。把 memory 拆成三层是最小可用的划分：跨会话沉淀的全局知识、当前任务的执行状态与中间产物、属于这个用户的长期偏好。三层各有不同的写入与淘汰策略，混在一起会互相污染。

§ 4 — 核心 Intuition ​

多步视频创作真正难的地方是步骤之间的依赖，而不是单步的工具调用。把"规划"和"执行"拆成两个 agent，让计划成为可被检查、可被局部重写的结构化对象，失败就不再意味着整条链作废；把工具挂在统一协议后面，能力扩展就与编排逻辑解耦。

§ 5 — 具体方法与完整 Pipeline ​

架构：Plan agent 负责把用户请求分解成带依赖关系的步骤序列并在失败时重规划；Act agent 负责按步骤调用工具、管理中间产物。两者之间通过共享状态通信。工具以 MCP 服务器形式接入。Memory 分三级：global（跨任务的通用知识）、task（当前任务的执行状态与产物）、user（用户长期偏好）。

论文使用的具体配置：Planner 与 Act 均用 Claude-sonnet-4；视频生成用 Seedance-v4-480p；视频理解用 InternVL3-38B；视频编辑用 Runway Aleph；分割用 SAM-2 与 Sa2VA；图像侧用 FLUX-Kontext。

一个具体例子：请求是"把这段视频里的狗换成猫，然后再生成它跳上沙发的后续"。Plan agent 产出四步：(1) 用 Sa2VA 按文本定位并分割出狗的 mask 序列；(2) 把 mask 与原视频交给 Runway Aleph 做区域编辑；(3) 取编辑结果末帧作为条件，用 Seedance 生成后续镜头；(4) 拼接。步骤 3 显式依赖步骤 2 的输出帧，这条依赖被写进计划结构而不是留在 prompt 里。若步骤 1 的 mask 覆盖不全导致步骤 2 失败，Plan agent 只重写步骤 1–2，步骤 3 的规划保留。

UniVA-Bench：作者自建的评测集规模很小，需要如实记下。理解任务取 Video-MME 的 10 条视频、每条 10 个问题；Entities2Video 取 Opens2v-nexus 的 10 条；Video2Video 与 Editing 各取 SF20k 的 10 条；分割任务用 DAVIS2017 的 10 条拼接而成；规划探针 50 条。指标除常规的 CLIP/DINO/MLLM 打分外，另有三个针对计划质量的指标 wPED、DepCov、ReplanQ，论文给出了它们的计算式。

§ 6 — 核心数学推导 ​

系统本身没有定理或收敛性分析，形式化集中在 UniVA-Bench 的三个规划探针指标上：wPED、DepCov、ReplanQ 各有明确的计算公式。按其命名与论文对 Plan-Act 架构的描述，可以推断 DepCov 度量的是生成计划对参考计划中依赖关系的覆盖比例，wPED 是某种加权的计划编辑距离，ReplanQ 与失败后重规划的行为质量有关。我在正文可见部分没有确认到这三者各自的优劣方向（越大越好还是越小越好），因此下文只陈述数值本身，不据此下判断——这属于我未能核实的部分，不是论文的缺陷。

其余可形式化的只有生成侧常用的评测量：CLIP 相似度衡量文本与画面的对齐，DINO 特征相似度衡量帧间外观一致，MLLM 评分是模型打的主观分。三者的取值区间与语义完全不同，把它们并列成一行数字时很容易造成误读，§11 会用论文自己表里的一组数字说明这件事。

§ 7 — 实验设计与结论 ​

理解：UniVA 的准确率 0.76，对照 InternVL3-38B 0.75、Qwen2.5-VL-72B 0.74、Gemini2.5Pro 0.65、GPT-4o 0.52。UniVA 的后端理解工具就是 InternVL3-38B，0.76 对 0.75 的差距落在 100 个问题的量级上，只能说明编排层没有损害基础能力。

长文本转视频：UniVA 的 CLIP 0.2814、MLLM 3.333，两项都是最高。同一张表里 LTX-Video 的 DINO 高达 0.9392，而它的 MLLM 只有 1.125。

实体到视频：UniVA 输给了直接调用的 Seedance，0.2868/0.8796/1.789 对 0.3039/0.8800/2.700。作者没有回避这个结果。它说明当任务本身就是单个工具的原生能力时，套一层 agent 编排只会引入损耗。

视频到视频：UniVA 的 MLLM 4.068 最高，但 CLIP 与 DINO 并不领先。

编辑：UniVA 0.2280/0.7488/3.635，对照 Vace 0.2258/0.6808/3.484。分割：UniVA 0.3254/0.1680/0.2467，对照 SA2VA 0.2076/0.0972/0.1524，这一项的相对提升最大。

架构消融：Plan-Act 双 agent 与单 agent 相比，任务成功率 45.0% 对 20.0%，wPED 为 0.117 对 0.050。成功率翻倍是这篇报告最硬的结论；同时要指出 45% 的绝对值意味着一多半的多步请求仍然失败。wPED 两档数值的变化方向与成功率不一致，在我无法确定该指标优劣方向的前提下，它不能被当作 Plan-Act 收益的独立佐证。

§ 8 — Take-aways ​

5 句版：视频通用 agent 的核心工程量在依赖管理与状态保持，不在工具本身。Plan-Act 分离把成功率从 20.0% 提到 45.0%，这是全文最可靠的结论，也说明多步视频任务此时的天花板还很低。当任务是某个工具的原生能力时，agent 编排会带来净损失，Entities2Video 上输给 Seedance 就是实证。UniVA-Bench 每项仅约 10 条样本，所有百分点级的差距都不具备统计意义。同一张表里 LTX-Video 的 DINO 0.9392 配 MLLM 1.125，暴露出帧间特征相似度可以被近乎静止的视频刷满。

3 句版：把视频理解、生成、编辑、分割统一到 Plan-Act 双 agent 加 MCP 工具服务器之下，用三级 memory 支撑多轮创作。架构消融给出 45.0% 对 20.0% 的成功率提升，但绝对值仍低，且部分任务上不如直接调工具。自建 benchmark 规模极小，结论应按定性证据读。

1 句版：把计划做成带依赖的结构化对象、把工具放到统一协议后面，是当前开源视频 agent 最值得抄的两条设计。

§ 9 — 最脆弱的假设 ​

最脆弱的一条是：编排层的收益能够超过它引入的信息损耗与误差累积。UniVA 的每一步都通过文本与文件在异构工具之间传递意图，分割的 mask、编辑的结果、生成的条件帧都要跨越工具边界重新解释一次。这个假设一旦不成立，agent 就只是给单个强模型加了一层噪声。

论文自己提供了反向证据：Entities2Video 上 UniVA 全面输给它自己调用的 Seedance（0.2868/0.8796/1.789 对 0.3039/0.8800/2.700）。这恰好是那类"单工具原生能做"的任务，编排的收益为零而损耗为正。同时，成功率 45.0% 意味着链条越长失败越可能，与误差累积的预期一致。作者给出的正面证据集中在需要跨模态协作的任务（分割、编辑、多轮改写），这与"编排只在真正跨能力的任务上划算"这一解释同样相容。

这条脆弱性还有一个放大器：整个系统的上限由后端工具决定。表中的每一个数字都同时是"UniVA 的编排质量"和"Seedance/InternVL3/Runway Aleph 的质量"的函数，两者在现有实验设计下无法分离。

§ 10 — 最小复现实验 ​

一周内可做，且不需要复现全部工具栈：

  1. 只保留两个工具（一个分割、一个编辑），实现最小版 Plan-Act：Plan agent 输出带依赖的 JSON 步骤表，Act agent 执行并把产物路径写回。
  2. 造 60 条两步到四步的请求，人工标注每条的正确步骤序列与依赖边。
  3. 对照三个配置：单 agent 直接调工具、Plan-Act 无重规划、Plan-Act 带重规划。
  4. 测三个量：端到端成功率（人工判定）、依赖边覆盖率、失败后重规划的修复率。
  5. 判据：若 Plan-Act 无重规划相对单 agent 已有明显提升，则收益来自"计划结构化"；若提升主要出现在带重规划的配置，则收益来自"失败恢复"。这两种归因对后续系统设计的含义完全不同，而原文的消融只报了合并后的总效果。

§ 11 — 最强反例设计 ​

针对论文自己表里的一处裂缝设计攻击。长文本转视频一栏，LTX-Video 的 DINO 达到 0.9392，是全表最高，而它的 MLLM 只有 1.125，是全表接近最低。DINO 特征相似度衡量的是相邻帧外观是否一致，一段几乎不动的视频会把它刷到接近上界。这给出一个可执行的平凡基线：把 prompt 交给任意文生图模型出一张静态图，复制成 N 帧当作"视频"提交。这个基线的 DINO 应当逼近 1.0，超过表中所有方法，而它的运动量为零。

如果这个基线成立，结论是 DINO 一栏在长视频叙事评测里不能作为独立指标，必须配一个运动下界（例如光流幅度或帧间差分的最小阈值）做门控，否则表格会奖励退化解。这不否定 UniVA 的 CLIP 与 MLLM 结果，但它说明该表的三列不能被平等看待，而 Entities2Video 一栏里 UniVA 与 Seedance 的 DINO 几乎相同（0.8796 对 0.8800）也说明这一列在方法间的区分度很弱。

第二重攻击针对 benchmark 规模：每项 10 条视频的设置下，重跑三次不同随机种子的评测本身的波动可能就覆盖了方法间的差距。要求作者报告种子间方差，是对所有细微领先最直接的检验。

§ 12 — Follow-up Research Idea ​

驱动 idea 的局限是：现在无法把"编排质量"从"工具质量"里分离出来，所有分数都是两者的乘积。

可借鉴的工具来自程序分析与数据库查询优化：把 agent 的计划视为一个带类型的算子 DAG，为每个工具声明输入输出的类型与前置条件，然后引入一个工具能力模拟器——用可控退化的假工具（按给定概率返回错误 mask、按给定强度降低生成质量）替换真实后端。这样就能在固定编排逻辑的前提下扫描工具质量，画出"成功率对工具错误率"的曲线，把编排的鲁棒性单独测出来。

第一个实验：在最小 Plan-Act 系统上接入 3 个可控退化的假工具，让分割工具的 IoU 从 0.9 线性降到 0.4，测端到端成功率的下降斜率。斜率平缓说明重规划真的在吸收工具误差，陡峭则说明 agent 只是在传递错误。这条曲线一旦有了，"这个 agent 好在哪"才第一次可以脱离后端模型来回答。
